# R28：收敛导航协调，建立伙伴体验基线

日期：2026-10-01。状态：方案已补齐冻结前的四项选择与生命周期边界，实施尚未开始。

运行基线：本地 `56bd120`，对应公开整理版 `403a23f`。该基线的 R27、连续高度 M3 结论保留；本阶段不因方向评审而撤销旧证据，也不把旧通过数字当作 R28 结果。

入口：[D048](../decisions/0048-converge-recovery-by-risk-and-product-evidence.md)、[目标接口](../architecture/navigation-coordination-v1.md#17-r28-协调收敛目标尚未实施)、[验收口径](../acceptance/navigation-coordination-convergence.md)。职责与接口只维护在 architecture；阈值、样本和统计定义只维护在 acceptance。

## 1. 目标与范围

让已有移动能力在晚到、丢回执、改目标和有限外力下，通过同一个恢复入口继续工作。减少重复的等待和交接分支，保留安全约束，测量玩家实际能感受到的停顿和响应。

本阶段不新增游泳、攀爬、探索、载具或世界操作，不替换运动计算器、感知语义和寻路算法。增加一个受限的正式跟随探针，检验新任务能否只通过目标管理接入共享恢复规则。它只使用已知地形、合法获得的目标位置和已有移动能力；旧跟随器不计入本阶段结果。

改动依次进行。不得同时修改协调规则、路径评分和物理参数。每步保存可审查提交，列出删除的旧入口、保留的调用者和对应检查。

步骤编号保留，实际顺序改为：**R28-0 → R28-1 → R28-4 → R28-3 → 正式跟随探针 → 按数据决定 R28-2 → R28-5**。R28-1／4 通过后可以准备跟随目标管理；其正式验收必须覆盖 R28-3，不同时迁移三条执行链。

## 2. 实施前冻结

在运行任何候选版本前，保存基线提交、导出哈希、场景清单、种子、身体入口域、延迟列表、任务预算和风险约束。分组按场景与支持范围预先确定，不能把运行失败改成反例或排除样本。

现有 14 场、200 种子、192 组合、1000 序列和 256 异步组合继续作为历史比较及安全回归。R28 另建产品清单，避免把故意取消、预算注入和不可达场景混入可达任务成功率。

原有通过与失败归档、源码摘要、输入账本和身体轨迹保持原字节。记录比较口径，不能使用“结果在允许范围内”替代任务成功率。

## 3. 原六步交付与正式跟随探针

### R28-0：先取得可比较的数据

主要文件：`tests/sim/runner.py`、`event_sequences.py`、现有诊断、B10／B11／C1 实机脚本；新增一个薄的汇总脚本和一份产品清单，不另建模拟器。

交付：从正式链输出到达用时、停顿、响应、恢复次数、任务结果和安全违规；复用已有序列及实际应用记录。首版只汇总这些已有数据，不建立新的遥测框架。测量本身不能给 actor 补身份、许可或身体状态。以现有 B12／C1 移动目标场景验证指标能从正式控制链读取。

同时展开第 6 节的迁移清单：为每个停止后去向、等待开关、身份比较和严格动作的迟到处理登记源码位置、拥有者、接替接口、所属步骤和保留理由。主要目标是按拥有者拆分 `propose` 并删除重复决定；报告协调代码总量及技能层新增的协调逻辑，会话 2,000 行只作参考。跟随的输入、合法观察、结果和对抗清单也在此时确定，尚未接入的能力不填写通过数字。

行为不变的提交与主动改变行为的提交分别比较，分类取决于实际语义，不取决于步骤名称。冻结统计方法和“实质退步”数值；行为比较的样本规模按独立探索数据校准，不能直接把 1,500 对当作保证。具体方法只维护在验收第 5 节。

冻结本次改动影响哪些分层、普通地面的时间容差，以及两次查看的位置和最大样本数。统计模拟拟使用汇总脚本内的薄进程池；场景独立、固定测试时钟与注入，结果按任务对归档。先测本机代表场景的并行成本，不把三方短场景的计时写成本机性能。源码、配置与观察语义相同的基线可复用；真实墙钟与 Fabric 时序另测。

完成条件：三类既有产品场景与扰动均有基线数据；全部失败留在统计；指标覆盖不足单独报告；静态迁移清单和跟随探针范围完整；当前代码的规模、分支和状态映射保存。基线不达产品目标时照实登记，允许继续结构迁移，不能降低目标来宣布原能力通过。

### R28-1：收口偏离、停止和交接

主要文件：`navigation_handoff.py`、`execution_supervisor.py`、`navigation_session.py`、`route_body_controller.py`，以及 B11 调用入口。

先扩展现有交接协调器，把取消、改目标、执行偏离和依赖变化的“停止后去哪里”收进同一入口。监督者继续判断身体是否可交接。Session 只发送请求、消费结论，不再分别写停止后的规划、等待和终态。

`NavigationHandoffCoordinator` 的拟定公共接口见架构第 17.2 节；先保持现有 `NavigationSessionPort` 和报告枚举兼容。按第 17.6 节的目标状态映射区分任务是否活动、恢复、收尾或终结；规划与取证状态仍由对应 owner 报告。逐项迁移后才合并公开名称，不新增隐含布尔状态。

在同一共享迁移中实现通用到达策略：一次性任务默认到达即完成；持续目标任务到达后报告目标满足，任务仍活动并可修订。它属于任务请求，不读取“跟随”名称，不新增跟随专用状态。所需公共字段、拥有者和收尾条件见架构第 17.6／17.7 节。此项属于新增公共语义，单列验收，不能伪装成完全保持行为的搬代码。

将 `propose` 内的信息推进、规划结果消费、身体推进与恢复去向分别交还已有 owner；Session 保留明确的调用顺序、事件路由和报告组装。每次迁移一块行为，删除原决定分支，不把 785 行原样搬进另一个大方法。现有 driver 接替接口的复用由共同导航入口负责，技能层不各自维护收尾枚举。

完成条件：不同原因进入同一处理入口；非终结恢复中可更新目标，已接受结束请求的任务不复活；旧控制者只有在合法接管或安全释放后退出。覆盖空中改目标、业务终态后停止、在途输入和探边退出，以及目标满足后再次移动与取消。删除已迁移的 Session 局部分支，安全及产品对照均满足验收条件。

### R28-2：让可恢复移动直接使用当前观察

此步放到跟随探针之后。基线没有发现对应失败、异常停顿或重复停止检查时，登记“不需要行为修改”，保留既有控制。安全停止查询若存在两个重复实现，可在保持行为的提交中统一复用 `safe_ground_control.py`；不能为了完成步骤制造改动。

主要文件：`fixed_route.py`、`action_route_executor.py`、`safe_ground_control.py`、动作前置条件与监督者。

从宽阔、支撑完整的普通地面开始。输入晚到或回执缺失时，先依据当前身体及尚可能生效的输入判断下一步是否安全；安全则继续闭环，不自动让整个任务失败或重规划。

坑边、窄桥、未知支撑和已开始的空中动作继续走严格路径。普通行走的厘米级检查若实际不存在，不为减少数字制造“删除”。连续高度的离线证明先保留，只有在线预测确实覆盖高度、支撑、净空和尾迹后，才迁移其重复检查。

完成条件：若修改行为，按验收规定的足量配对比较检验晚到和轻推；否则保留“不需修改”的基线证据。安全预测和输入期限保留；原空中证明、落点门槛和伤害额度无退步。提交明确指出哪一处恢复或失败变成闭环继续，不删除动作内部必要的窗口处理。

### R28-3：简化异步失效与结果关联

主要文件：`async_work.py`、`navigation_owners.py`、`planning_coordinator.py`、`motion_worker.py`、`motion_coordination.py`。

由目标／请求拥有者维护计算世代，共享结果入口统一拒绝旧世代。保留作用范围和工作关联，同世代多个求解可以区分。当前事实与证明适用性仍由领域检查。

同一任务只修订目标位置时，不取消正在进行的计算，不递增计算世代。结果到达后由领域接纳入口核对当前目标完整要求、身体连接、依赖事实、规则、风险余额和命令窗口，形成绑定当前请求的候选实例。旧结果不能直接沿用旧执行许可；旧目标的否定结果不能终止新目标。

取消、新任务、世界切换、需要新状态锚点的重新计算及相关依据失效才撤销旧计算资格。已经起跳的执行器、已点击的放置确认和任务风险账本保留。首版不引入“小幅修订”阈值或任意路线截断。移动目标一直远离、导致结果始终不满足最新目标时，由正式跟随探针暴露；只有数据证明有必要，才单独设计按现有路线契约复用前段，并补验收。

完成条件：successor、世界切换、多工作同世代、旧否定结果和重复交付全部被正确处理；频繁修订不会反复取消计算，也不会把不适用的结果强行接纳。覆盖终点位置相同但终态或风险要求改变、身体入口改变及目标持续远离。身份检查只保留在明确边界，删去重复比较和已无消费者的退场状态；诊断仍可追溯实际开始、生效和终结。

### R28-4：统一无进展预算，结束重复等待

主要文件：`retry_ledger.py`、`navigation_handoff.py`、规划与信息拥有者；`motion_risk.py` 只调整调用，不重做账本。

一次恢复开始时计费一次；重复观察、旧回执和收尾中再次改目标不重复计费，也不补回预算。去掉仅用于流程选择的按原因计数，保留原因诊断。

任务总时长、恢复次数和无进展时间由同一个任务拥有者管理。等待记录按活动工作保留最少数量，有开始就有结束；已结束的历史放到有界诊断，不占活动额度。单动作确认期限、输入生效窗口和风险预留分别保留。

完成条件：频繁改目标、交替失败和任务接替不补回任务额度；重复通知不重复扣账；无进展有界。真实进展后仅重置连续无进展窗口，不重置任务总预算。每个等待拥有者退出后活动记录为零，分配上限不成为正常工作的失败来源。

### R28-5：整理契约、删旧路径并验收

主要文件：迁移涉及的公共边界、`NavigationSession`、正式 driver、模拟监视器和四类文档。

将环境变化、过期和偏离作为正常有类型结果处理。进程／后端边界的非法数据仍明确拒绝；程序错误保留原异常和现场，由唯一正式入口处理安全收尾。禁止为了降低异常数量吞错、反复重建 Runtime 或伪造安全释放。

建立旧 I1—I22 检查与新安全规则的映射。几何、输入、事实和资源检查分别保留；改了合法行为的旧用例要记录替代检查，不能大批删测试。每项旧分支在消费者迁移后删除。

完成条件：安全检查、按提交性质进行的产品比较、逆向破坏检查和受影响的 Fabric 对照通过；迁移清单逐项完成或有保留依据；正式跟随通过包含技能层的扩展检查。`propose` 按拥有者拆分，协调代码总量净减少，Session 不再自行处理各域等待与停止后去向。2,000 行是参考值，报告残留职责，不靠转发包装隐藏复杂度。

### 正式跟随探针：检验新任务如何接入

主要文件：现有 `mc2p/skills/navigation_session_driver.py`、目标契约、合法实体观察；拟新增薄的 `formal_follow_goal.py`／`formal_follow_driver.py` 及正式路径检查。拟定文件尚不存在。现有 `follow.py`／`follow_driver.py` 保留历史范围，不能让 RuleFollower 直接输出按键来冒充本探针。

目标管理把合法目标位置转为跟随区域，只提交目标、修订和有类型的结束请求。它可以消费任务结果并决定继续跟随或放弃；导航负责实际移动和恢复。使用持续目标的到达策略、Runtime 的唯一输入出口、世界与输入账本。跟随层不直接调用 successor／transfer、不判断何时释放身体，也不编排取消后的逐帧收尾；共享入口负责必要接替。

完成条件：正常追随、目标远离／横移、每 3／5／8 tick 修订、暂时丢失目标，以及修订与迟到、丢回执、外力、取消的组合都有正式链证据。记录会话和跟随层的代码、状态、等待及审查发现。Session 与监督者没有跟随专用分支，技能层没有复制共同接替、恢复或身体释放逻辑。具体产品要求和结果判定见验收第 6.1 节；首轮审查问题数量不单独代表质量。

## 4. 迁移和回滚

每步先补能区分旧行为与目标行为的正式路径检查，再改生产代码。旧缺陷要通过恢复错误规则验证监视器仍能发现。过渡期间每类状态只有一个权威拥有者，不长期双写。

每步有源码提交、基线／候选报告和导出哈希。出现安全退步时回到上一个通过步骤，保留失败记录；不覆盖用户数据或更换种子。一个步骤两轮整改后先报告原因，按 D048 决定继续修安全问题或登记非阻塞体验问题。

阶段整体的初始时间盒为 **10 个可验收工作批次，且首次开工后最多 10 个工作日**，先到者触发阶段复核；用户明确暂停的期间不计工作日。七个交付批次对应 0、1、4、3、跟随、可选 2、5，最多再投入三个整改批次。每批次从一项修改或基线交付到一次检查与审查结论结束，通过与未通过都计数，不能把失败批次改名后重新起算。R28-0 登记开工与复核日期；未结束的批次须报告等待原因，不把它藏在轮次之外。

事先声明的第二次统计查看属于同一个验收批次，不算整改。中途修改候选源码或规则则是新的修改／检查批次，不能合并旧样本。探索、校准和两次查看的运行成本都计入本阶段时间盒。

时间盒用尽且没有新决定时，默认冻结 R28，不自动延长整改；保留最新通过集成门槛、依赖完整的可用版本、未完成项和失败证据。各自通过的零散步骤不能随意拼成发布版本。安全问题或最低功能门槛未满足，R28 保持未完成；允许继续基于可用版本且不依赖未完成机制的新能力工作，正式跟随只有在其共享基础已通过时才继续。依赖未修复安全机制的能力不推进。延长整改或改变依赖范围先更新决定，不用“已到期”替代通过。

公共接口迁移同时检查 producer、consumer、脚本和导出。规划、动作、停止与信息的恢复入口逐项交接，不一次删完所有身份、窗口和状态。
