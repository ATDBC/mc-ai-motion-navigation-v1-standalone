# 连续高度完整矩阵实施计划

日期：2026-09-28

状态：M0 至 M2 已完成；M3 尚未运行；M4 已完成部分跨模块回归；完整矩阵尚未关闭

## 1. 要解决什么问题

现有证据能证明连续高度主链可用，但覆盖仍偏窄。真实 Fabric 只跑了连续半砖、四级下降和几种直接下落。它没有覆盖全部已授权形状、三个入口速度带，也没有按冻结种子重复随机迟到场景。

本阶段只补验收基础和已有能力的覆盖，不增加新的移动方式，也不放宽动作窗口、安全余量或伤害额度。

半砖及更矮形状不各自拥有一套动作。图规划只要确认相邻支撑面高差不超过普通步行范围，并且身体净空足够，就把它列为普通步行候选。随后由同一个 1.21 运动计算器检查真实支撑高度、碰撞外形、入口速度和完整扫掠结果。整格上升、孤立下落和可能造成伤害的下落仍保留独立动作，因为它们有不同的身体责任和风险规则。

## 2. 实施顺序

### M0：冻结清单和结果格式

- 小高差清单覆盖上下半砖、直楼梯上下、土径、地毯、三种积雪高度、单块下半砖和小高差后制动。
- 整格动作清单覆盖带速上一格、下一格，连续下降 2／4／8 级，以及直接下落 1／2／3／5 格。
- 入口速度固定为低、中、高三档；方向固定为东、南、西、北。
- 随机迟到使用清单里的固定种子，不在看到结果后改样本。
- 每个结果保存任务终态、首次表现、恢复次数、入口速度、路线动作、逐 tick 最低速度、参照用时、实际用时和安全违规。

### M1：正式路径组件矩阵

- 继续走 `Runtime → RuntimeNavigationDriver → NavigationSession → 规划／接纳／执行器` 正式调用链。
- 游戏只替换成现有 1.21 运动计算器和简化观察模型。
- 补齐土径、地毯、积雪和楼梯的真实碰撞外形；未知空间仍不能放行。
- 正常输入和随机迟到分开统计。支持范围内的可达任务失败必须留在分母中。

### M2：规划代价矩阵

- 复用现有 A* 与独立 Dijkstra 对照。
- 加入半砖、楼梯、土径和转弯，冻结至少 1,000 张小图。
- 单独报告代价一致性、展开数、规划耗时和缓存失效。

### M3：Fabric 矩阵

- 小高差每种形状覆盖四个方向，每个方向至少 5 次。
- 整格动作覆盖三个速度带；每种地形覆盖四个方向各 5 次。
- 真实游戏只运行组件矩阵已经关闭的组合。失败记录保留，不用重跑覆盖。
- 记录输入实际生效 tick、取证时间、动作执行时间、完整端到端时间和持续前进参照。

### M4：跨模块回归与阶段结论

- 重跑 B03、B07、B09、B10、C1-B、B11 和 B12-B 的正式入口。
- 分开报告组件、模拟和 Fabric。任何一层通过都不能替代下一层。
- 完整矩阵通过后，再判断 S5 是否可以关闭；192/200 的协调种子结果仍单独保留。

## 3. 不这样做

- 不把数百次组件随机试验塞进代表性 Fabric 脚本。
- 不为通过矩阵扩大输入生效窗口、探边期限或重试上限。
- 不把安全失败从正例分母删除。
- 不用简化碰撞外形冒充真实楼梯、积雪、地毯或土径。

## 4. 完成条件

- 机器清单在运行前冻结并带哈希；输出目录拒绝覆盖。
- 每类正例和反例都有明确终态，异常也能保存已经执行的 tick。
- 组件矩阵先关闭，Fabric 才开始对应组合。
- 指标和次数继续采用[连续高度地面移动验收](../acceptance/continuous-height-ground-movement.md)第 3 至第 7 节，不另设更容易通过的口径。

## 5. M1、M2 当前结果

组件闭环和规划对照都使用运行前冻结的清单。运行中没有根据结果修改种子、方向、速度带或地形。

| 矩阵 | 结果 |
|---|---:|
| 小高差，正常输入 | 1100/1100 完成 |
| 小高差，每条命令 20% 概率晚一帧 | 1100/1100 完成 |
| 整格动作，正常输入 | 900/900 完成 |
| 整格动作，每条命令 20% 概率晚一帧 | 867 完成，33 次有界安全失败，0 次安全违规 |
| 混合表面规划 | 1000/1000 与独立 Dijkstra 的最小整数 tick 代价一致 |

整格动作的 33 次安全失败没有从分母删除。其中一格下降 11 次、上一整格 3 次、直接下落 19 次。它们都在输入没有按证明生效后保留身体责任，并以 `input_lost` 或明确的求解不匹配结束。这个随机矩阵比正式门槛中的“首条命令固定晚一帧”更严格，因此这里只把它作为鲁棒性分布记录，不把 867/900 写成正式能力成功率。

矩阵还发现并修正了三处正式路径问题：

- 已经落到动作目标支撑面后，不再回到旧起点重复同一个升降动作；
- 某一帧没有新导航输入时，Runtime 会撤销旧的持久移动意图；
- 已提交命令仍可能迟到时，执行器继续持有身体，直到下一次观察或安全落地。

M3 仍需真实 Fabric 覆盖全部形状、方向和速度带。现有 12 场代表性 Fabric 结果不能替代这一步。

## 6. M4 当前结果

B03、B07、B09、C1-B 和 B11 的正式入口已经重跑并通过。B11 为 60/60 正例和 24/24 边界／反例通过。B10 的动作行为矩阵通过，但外层计时旁路没有记录一个完整 Runtime 回合，所以只保留行为结论，不把该批次写成完整计时验收。B12-B 尚未重跑。

完整 M4 仍需补 B12-B，并修复或重新采集 B10 计时证据。M3 全形状、全方向和全速度带 Fabric 矩阵依然是独立门槛。
