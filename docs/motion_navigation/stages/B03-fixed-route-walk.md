# B03：固定路线步行

日期：2026-09-18
状态：B03 已验收

## 要解决的问题

B03 要证明行走执行可以脱离搜索和探索独立工作。调用方给出一条固定路线，机器人负责沿路线连续行走，在终点停稳，并正确处理取消、输入确认丢失和输入断流。

## 本阶段范围

- 接收不可变的外部路线，不自行生成路点。
- 只支持已经校准的普通地面步行。
- 每个控制帧根据实际身体状态、路线前视和短时预测选择完整移动输入。
- 用统一扫掠和支撑查询检查候选。真实碰撞、支撑不足、未知和未支持材质是硬约束。
- 墙边与坑边余量只影响候选分数。越靠近边界，越倾向选择远离边界的动作；它不改变几何真值。
- 终点、取消和输入确认丢失都依据实际速度结束，不把松键当成已经停止。
- 正式实机实现与验收只使用独立 Fabric。

## 明确不做

- A*、后台规划进程和路线切换；
- 检查点、观察点和主动探索；
- 跳跃、冲刺、潜行、游泳和跨高度路线；
- 动态实体绕行和局部重接。

## 最小职责

固定路线控制器暂时集中实现 B03 所需的最小 M05、M08、M09 和 M12。它拥有路线进度、行走阶段和取消状态，但不写游戏输入。现有正式动作仲裁和 Fabric 客户端租约继续承担唯一输入出口与断流释放。

如果后续目标管理、局部跟踪或恢复出现独立状态与测试边界，再拆分文件。B03 不提前生成完整架构空壳。

## 完成条件

1. 固定路线的重复点、零长度路线和终点重合不会除零或错误启动。
2. 至少 100 组参数化闭环覆盖直线、转弯、不同视角和轻微横向偏移。
3. 已知固定路线不会在普通直线或宽转角的中间路点强制停稳。
4. 普通到点满足水平误差不超过 0.25 格、速度不超过 0.1 格／秒。
5. 取消经过实际制动并在停止后完成；输入确认丢失进入明确失败状态。
6. Fabric 输入租约断流后在已测包络内释放并停止，不会持续按键。
7. B03 的正式 Fabric 场景和性能写入验收记录；旧版相对耗时按 D007 的证据边界处理。

以上条件已经满足。正式实机在两个独立 JVM 中运行 50 条固定路线，S00、S01、S02、S03、S07 各 10 次。S02 使用真实两格高 L 形墙体；输入确认丢失使用真实客户端拒绝回执。取消和输入断流也分别通过。B04 后续已经完成，见 B04 阶段和验收记录。

2026-09-19 又补充了两类运动形状实测。第一类在世界方向保持直线时，让视角随路程顺时针转一圈再逆时针转回；第二类固定视角，分别向左、向右走半径 2、4、8 格的闭合圆。七条路线均在独立 Fabric 客户端中完成。它们补充验证视角和水平路线解耦、连续曲线路线跟踪及回到起点的能力，不改变 B03 的范围，也不提前引入路线搜索。
