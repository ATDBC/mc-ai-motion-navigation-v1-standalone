# 运动导航中层重构 M0—M1 方案

日期：2026-10-06。状态：M0 通过；M1 结构止损，不通过。保留经行为验证的动作查询迁移，M2—M5 未授权。

## 1. 目标

M0 先确保结构修改有可靠量尺。M1 只迁移受控下降，验证一种动作能否在不修改多个核心协调模块的前提下声明自己的规则。

本轮不追求一次完成全部重构，也不新增运动能力。M1 结束后再决定是否继续 M2。

## 2. 必须保持的行为

- S0-R 五组行为集合逐项不变：产品 2,000、协调 1,448、故障 16、跟随 10、世界变化 19；
- 唯一输入出口、观测确认、身体责任和 TEST_ORACLE 隔离不变；
- S0R-C-01 的等待落地与重锚继续由通用运动协调负责；
- 现有 `NavigationLifecycle` 继续作为唯一 Session 状态转移表；
- 不增加线程、进程、生产双轨开关、动态插件或新的长期状态 owner。

## 3. M0：收尾和量尺

M0 是一个批次。

### M0-1：记录决定和协作方式

- 采纳 D072；
- 更新 AGENTS.md 当前阶段；
- 本项目以后进入代码实施时，默认使用一个明确分工的子 agent。主线程负责方案、边界、复核和整合；只读分析和简单查询不因此创建子 agent。用户明确要求不用时例外。

### M0-2：恢复后台规划不阻塞控制的不变量检查

在 `tests/motion_nav/test_planner_worker.py` 增加两个确定性检查：

1. 规划计算不在控制进程执行；
2. 控制侧只使用非阻塞队列操作。

检查不得用墙钟决定通过。允许用有限轮询等待子进程返回，但断言只检查执行位置和队列 API。

必须做两项变异：

- 把规划计算临时放到控制侧，第一项检查失败；
- 把轮询临时改成阻塞读取，第二项检查失败。

### M0-3：删除三个死路径

目标：

- `NavigationSession._admit_async_event`；
- `NavigationSession._cell_fact_id`；
- `MotionRouteCoordinator._upcoming_air_index`。

每项先把函数体临时替换为断言，运行直接检查和路径集合；确认没有入口后再删除。不能一起删除后再推断其中每项都不可达。

### M0-4：建立不易被搬代码规避的结构量尺

新增 `scripts/navigation_design_metrics.py`，冻结到 `evidence/motion_navigation/redesign-m0/`。

量尺至少报告：

- 动作类型分支及所属问题类别；
- 每种动作在动作实现之外涉及的文件；
- Session 行数、方法数、长期字段和长方法；
- 驱动器中参与流程判断或写入的字符串状态，单纯报告映射另行统计；
- 两个协调器真正重复的作业生命周期职责；
- 协调模块的行数与依赖。

静态脚本必须同时报告未分类位置。它只排除具体动作实现文件，不能把整个 `actions/` 目录都当成盲区。字典映射、`match`、类型别名和类名字符串也要进入检查或由组件测试补足。

### M0-5：恢复场景时先检查是否提供新证据

先核对 seed 15、69、119 是否仍能进入 seed 163 和条件触发场景没有覆盖的路径。

- 有独立路径证据：加入正式回归；
- 没有独立路径证据：不增加历史种子，只在验收中记录原因。

不能用“以前存在过”代替当前覆盖价值。

### M0-6：提前核对两个驱动器边界

为下面两项增加直接检查并判断严重程度：

1. Runtime 仍为 READY 时，任务级失败是否只改变驱动器而没有同步 Session；
2. `_finish_control_unavailable` 在 Session 已有业务结论时是否仍保持终态和身体收尾一致。

若能造成状态分裂、终态后输入或无人负责身体，必须在 M0 单独修复后再冻结基线。否则登记到 M5，并保存证明它当前有界的检查。

### M0-7：冻结 M1 起点

在正式 Windows 环境运行：

- 直接相关检查；
- 完整运动导航正序和逆序；
- 五组行为集合一轮；
- 结构量尺。

只有测试工具或签名提取器发生变化时，五组集合才连续运行两次。M0 不改行为，不重新生成 Fabric 证据。

## 4. M1：用受控下降验证动作接口

M1 最多两个批次。实现按可回退的小提交推进。

### 4.1 文件和责任

建议建立：

```text
mc2p/motion_nav/actions/
  contracts.py          只放类型化契约，不引用具体动作类
  registry.py           固定类型映射和完整性检查
  controlled_drop.py    受控下降自己的规则
  existing.py           其余四种动作在 M1 需要的显式分类声明
```

如果实际导入关系表明更少文件更清楚，可以合并 `existing.py`，但不能把跨动作分支藏进一个被量尺整体排除的大文件。

`ActionSpec` 在 M1 只包含实际迁移需要的成员。暂不加入 M3 的复核接口，也不提前生成 M2—M5 空壳。

### 4.2 必须显式声明的内容

每个动作都要显式声明：

- `body_commitment`；
- `requires_verified_motion`；
- `expected_damage_points`；
- `stop_hold`；
- 是否需要后台求解。

受控下降另外实现：

- 前置条件和观察需求；
- 求解请求所需的动作几何；
- 控制器创建；
- 完成判定；
- 伤害何时已经承担。

缺失安全声明时，登记表必须拒绝启动。不能用宽松默认值补齐。

### 4.3 不属于动作的内容

下面逻辑不能迁入 `ControlledDropSpec`：

- `NEEDS_STATE` 时是否等待真实落地；
- 当前身体控制者是否继续负责；
- 结果是否属于当前世代、目标或请求；
- 重试、截止时间、接纳窗口和任务终态；
- 依赖变化后的重新规划。

动作接口可以返回类型化的“入口状态不足”，但通用协调器决定怎样安全收尾和重锚。

### 4.4 实施顺序

1. 先写契约测试，验证登记完整、缺少安全声明会失败；生产调用点暂不切换。
2. 在测试侧比较旧分支和新接口，覆盖五组集合中实际出现的所有受控下降实例。
3. 迁移风险与伤害。
4. 迁移前置条件与观察需求。
5. 迁移身体承诺和安全停止。
6. 迁移求解请求描述，但保留通用落地重锚。
7. 迁移执行器选择与完成判定，删除受控下降类型分支。
8. 加入一个仅用于契约验证的测试动作。它不得要求修改 Session 或执行监督者，用来证明扩展边界真的成立。
9. 删除测试中的旧逻辑副本，保留最小回归语料；补架构文档和量尺报告。

### 4.5 fail fast 检查顺序

每个小提交：

1. 新增或直接相关检查；
2. 受控下降、动作接续和 S0R-C-01 代表场景；
3. 结构量尺。

每个批次结束：

1. 完整运动导航正序、逆序；
2. 五组行为集合一轮；
3. Windows 性能检查。

M1 最终候选：

1. 五组集合连续两次逐项一致；
2. 完整检查全绿；
3. 结构量尺和扩展探针通过。

专项检查未稳定前不运行完整矩阵。

## 5. M1 通过门槛

必须同时满足：

| 项目 | 门槛 |
|---|---|
| 受控下降类型分支 | v2 量尺在具体动作实现之外 30 → 0；旧 21 只作三方旧口径对照 |
| 总动作类型分支 | v2 量尺 79 → 不高于 49，且没有用映射或字符串隐藏新增分支；旧 70 不与新口径混用 |
| Session 引用 | `navigation_session.py` 不再引用 `ControlledDropSegment` |
| 文件扩散 | 受控下降在具体动作实现之外最多出现在一个规划边转换文件 |
| Session | 至少减少 100 行；若没减少，M1 判定失败 |
| 总代码 | 运动导航生产代码净增不超过 300 行 |
| 专用接口 | 只服务受控下降的公共成员不超过一个 |
| 安全声明 | 五种动作全部显式声明；缺失声明的错误副本会被检查发现 |
| 通用恢复 | S0R-C-01 仍由通用协调拥有，seed 163 和条件触发场景通过 |
| 扩展探针 | 测试动作不修改 Session、执行监督者或规划协调器；生产改动不超过三个文件 |
| 行为 | 五组集合与 M0 索引逐项一致 |
| 性能 | 现行 Windows D058、D061 门槛不退步 |

正式 M0 结构起点为 Session 5,046 行、运动导航包 38,279 行。M1 的减少和净增均相对这一正式起点计算。量尺把动作记录、类型联合声明与运行时特判分开，不把声明本身算成外部行为特判。

行数、分支数或协调层占比不能单独关闭 M1。代码只是换目录、换写法或换名称时，量尺改善不成立。

## 6. 止损

发生任一情况就停止 M1：

- 两个批次用完仍有生产双轨；
- Session 没有缩小；
- 需要两个以上只服务受控下降的公共成员；
- 安全默认必须依靠宽松值才能接入；
- 扩展探针仍要修改 Session 或执行监督者；
- 性能门槛在两次局部调整后仍失败；
- 五组行为出现无法解释的变化。

停止时，只有行为一致、责任更清楚且量尺真实改善的提交可以保留。否则回退到 M0。

## 7. 后续但未获准实施的方向

- M2：迁移其余动作；
- M3：统一复核接口并交付终点接近；
- M4：共享异步作业协议，保留按负载隔离的 worker；
- M5：让现有 `NavigationLifecycle` 成为完整权威，并将驱动器状态改成枚举。

M0—M2 视为一次接口验证块；M3 必须带来产品增量。M4 和 M5 不得连续完成而没有新的产品交付。
