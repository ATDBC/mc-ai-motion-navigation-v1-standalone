# B12 审查整改实施计划

日期：2026-09-26
状态：已完成

## 1. 目标

本轮处理 B12 三方审查确认的问题，同时保留已经通过的能力和证据：

1. 交替出现的攻击失败也必须在有限次数内交给任务层决定；
2. 普通地面移动要按本帧最终采用的战斗视角计算，不能依靠固定 5° 容差掩盖旧朝向输入；
3. 用活动目标证明正式 `MovingMeleeDriver` 能在同一控制应用区间内移动并发生非零转头；
4. 从 Minecraft 1.21 客户端伤害包取得来源事实，区分机器人命中、其他实体伤害和环境伤害；
5. 修正 B12 的阶段状态、实机边界和公开证据，避免组件检查或确定性注入被写成实机结论。

本轮不增加绕圈、撤退、利用地形等战术评分。Jev 以后提供战术目标，导航继续负责安全抵达，战斗技能继续负责视角和攻击。

## 2. 实施顺序

### 第一步：冻结阶段状态和回归条件

- 新增设计决定，记录审查复现、当前证据缺口和本轮接口边界；
- 将 B12-B 标为“现有范围通过，持续瞄准移动待补实机证据”；
- 保留原 24 个 Fabric 正例和全部失败记录，不改写原成功率；
- 将“未交战目标在真实墙后”恢复为 Fabric 场景。确定性注入继续验证权限消费者，但不能代替真实遮挡。

### 第二步：给攻击任务增加总无进展上限

修改：

- `mc2p/skills/attack_evidence.py`
- `mc2p/skills/moving_melee_driver.py`
- 攻击证据、移动近战和离线重放测试

做法：

- 保留门禁拒绝、输入失败和确认超时各自的连续计数；
- 增加“自上次确认命中以来的失败总数”；
- 三类失败无论怎样交替都会增加总数；确认命中、正式更换目标或新任务会重新开始统计；
- 默认总上限为三类现有上限之和，即 6 次；
- 达到上限后返回新的有类型 `NEEDS_TASK_DECISION`，不封存 Runtime；
- 仲裁延后不算攻击失败，继续由任务期限约束。

验收：先增加“门禁拒绝与确认超时交替六次”的失败测试，再实施最小修正。单类连续失败仍返回原来的分类结果。

### 第三步：按最终战斗视角计算普通步行

修改：

- `mc2p/contracts/action_v1.py`
- `mc2p/runtime/arbiter_v1.py`
- `mc2p/skills/melee_strike_driver.py`
- `mc2p/skills/moving_melee_driver.py`
- `mc2p/skills/navigation_session_driver.py`
- `mc2p/motion_nav/navigation_session.py`
- `mc2p/motion_nav/action_route_executor.py`
- 对应契约、仲裁、导航和战斗组合测试

做法：

1. 战斗先产生本帧视角意图；
2. 正式导航驱动把这份视角作为普通 `WalkSegment` 的计算条件；
3. 地面控制器使用“当前观察朝向＋本帧视角增量”选择和验证移动键；
4. 移动意图记录它依赖的视角意图 ID；
5. 仲裁器只在同一份视角真正胜出时采用该移动；
6. 若另一份视角胜出，只压下本帧移动，Runtime 保持可用；
7. 台阶、上升、跨隙和下落不接受这项条件，继续使用各自动作证明。

首版仍保持普通步行的一 tick 授权。是否恢复更长租约由 C1-B 和长路线回归结果决定，不在同一修改中提前扩大。

验收：

- 四种地面移动在 8°～15° 本帧转头下按新朝向重新求解；
- 绑定视角落选时移动被明确压下；
- 空中和跨高度动作不能携带该绑定；
- 正式 `MovingMeleeDriver` 走到这条路径，不用测试脚本手工拼出另一套组合。

### 第四步：接入 Minecraft 1.21 伤害来源事实

修改：

- Fabric 伤害包 Mixin 和有界事件缓冲；
- Observation V3 客户端载荷、Python 契约与严格解码；
- 攻击证据分类与离线重放；
- Java 编译门禁、Python 契约测试和 Fabric 诊断场景。

伤害事件至少保存：

- 世界 tick；
- 受伤目标的已登记实体引用；
- 伤害类型；
- 造成伤害的实体是否为机器人玩家；
- 直接来源实体是否为机器人玩家；
- 能合法解析时的来源实体引用；
- 缓冲丢弃计数。

缓冲有固定上限。满载时丢弃最旧事件并报告数量，不能在游戏线程抛异常。换世界时清空，观察采样后只确认已经交付的事件。

只有“攻击命令已生效、目标一致、来源为机器人、时序位于本次确认窗口”同时成立，才提升为来源确认命中。现有命令关联证据保留为较弱等级；若伤害包明确指向其他来源，不能再由受伤动画把它提升为机器人命中。

先用 Fabric 验证玩家近战和环境伤害的实际字段，再关闭这项任务。协议映射存在不等于实机语义已经成立。

### 第五步：实机回归与证据整理

按下面顺序运行：

1. B12-B 活动目标专项：必须出现同一请求内连续生效的非零转头和非空移动；
2. C1-B：活动目标连续近战，检查停顿、路线进度和控制耗时；
3. B03 代表性长直线／转头路线：检查一 tick 普通步行授权没有造成断续；
4. B10 跨隙：确认视角条件没有进入空中动作；
5. 真实墙体遮挡下的未交战目标；
6. 伤害来源专项：机器人近战、环境伤害，以及条件允许时的其他实体伤害。

B12-B 的新实机通过至少要求：

- 正式 `MovingMeleeDriver` 运行；
- 活动目标与固定种子；
- 实际应用记录中存在同一请求、同一时间事件序列的非零转头和非空移动；视角钩子与运动钩子允许相邻一个客户端 tick；
- 没有墙体碰撞、坠落或路线走廊外偏离；
- 移动被压下时都有明确原因；
- 在线结果与离线重放一致。

### 第六步：文档与公开仓库

- 更新 B12 架构、阶段、验收和决定记录；
- B12-A 原始批次不整包上传，只制作经过清单校验的精简通过与失败证据；
- 公布 B12-B 活动目标和真实墙体遮挡的代表记录；
- 更新独立公开仓库的源码快照、哈希清单、README 和验证命令；
- 保留所有历史失败，不用新结果覆盖原始证据。

## 3. 模块边界

- Jev 决定战术目标，不产生逐 tick 按键；
- 战斗技能产生目标视角和攻击意图，不判断路线安全；
- 导航在最终视角条件下计算普通地面移动；
- 仲裁器只核对意图关系，不重新计算移动；
- Fabric 观察层保存伤害包事实，不判断战斗策略；
- 攻击证据层把命令、来源事件和后续观察关联成有等级的结论。

## 4. 完成条件

- 两个审查复现都成为自动回归并通过；
- B12-B 活动目标专项取得真实同帧移动与非零转头；
- C1-B 和代表性普通步行没有可见退化；
- 伤害来源在 Fabric 1.21 得到实机确认，错误来源不会授予机器人命中；
- 真实墙体遮挡场景通过；
- 所有新增结论都标明组件、确定性注入或 Fabric 证据来源；
- 项目检查、Java 门禁、公开快照校验和 `git diff --check` 通过。
