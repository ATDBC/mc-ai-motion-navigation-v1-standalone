# D107：D103 回归修复计划

日期：2026-10-14。状态：**已完成。** 决定见 [D107](../decisions/0107-repair-d103-regressions-before-new-motion-work.md)，正式结果见[验收](../acceptance/d103-regression-recovery.md)。

## 1. 范围

本阶段只恢复 D103 前已经成立的行为和测试能力：

1. 修复世界 section 在同语义观察下的重复重建；
2. 建立可定位、可超时、可生成报告的完整测试分片入口；
3. 定性并修复三方列出的 11 个失败模块；
4. 用现有 trace 检查 D103 性能回归与 B10 跨 tick 现象是否相关。

本阶段不优化摘要算法，不改变同步起始证明门槛，不生产 90 格局部快照，不修改 B10 带速入口，也不实施连续两跳。

## 2. R0：冻结失败基线

保存以下 Windows 基线：

- `test_r27_async_admission` 的失败类型和数量；
- F1 缩短场景的总用时、每 tick 用时、section 构造次数和深度校验占比；
- 11 个模块的预期失败清单；
- D106 直接检查的当前通过结果。

R0 只记录事实，不修改生产代码。

## 3. R1：分片测试入口

新增 `scripts/run_motion_nav_shards.py` 和对应测试。

运行器必须：

- 按文件名稳定枚举 `tests/motion_nav/test_*.py`；
- 每个模块启动独立 Python 进程；
- 支持单模块期限和可选模块过滤；
- 每个模块结束后立即输出一行进度；
- 原子写入 JSON 报告；
- 区分 `passed`、`failed`、`error`、`timeout` 和启动失败；
- 任一非通过结果使总命令返回非零。

测试先用临时小模块构造通过、失败和超时三种 RED 场景，再实现运行器。正式完整运行默认串行，避免并发影响性能测试。

## 4. R2：世界 section 增量修复

### 4.1 先写 RED

组件检查至少覆盖：

- 同一个方块以新时间戳、相同运动语义重复观察时，不重建不可变 section；
- evidence revision 和正式世界中的最新观察仍更新；
- 方块／空气身份、碰撞形状或移除发生变化时，section 必须重建；
- 旧依赖在语义变化后失效；
- 借出的快照保持不可变，旧快照不会被原地修改。

性能检查固定 F1 缩短场景，并报告 section 构造和整图校验次数。时间只作为 Windows 阶段门槛，结构计数才进入单元检查。

### 4.2 最小实现

先查清物理快照的消费者是否读取每格时间戳。只有不依赖最新时间戳时，才能复用原 section。需要证据时间的调用方改读 evidence owner，不把完整证据刷新重新塞进物理快照。

可信内部构造允许使用经过局部校验的路径，进程边界仍保留完整校验。不得同时改 snapshot lease、receiver 生命周期或 worker 协议。

### 4.3 验收

- 新组件检查通过；
- F1 缩短场景每 tick 不高于 40 ms；
- 安全结果、最终位置和来源释放与 R0 相同；
- D102／D106 快照与依赖检查保持通过。

## 5. R3：修复 11 个模块

按下面顺序处理，避免用测试改动遮住正式行为错误：

1. `test_r27_async_admission`、`test_async_gap_revalidation_delivery`、`test_motion_baseline_recovery`；
2. `test_motion_start_delivery`、`test_r28_persistent_budget_formal`；
3. `test_r28_planning_retry_successor`、`test_r28_reanchor_handoff`、`test_f2rec_r0_baseline`；
4. `test_navigation_design_metrics`、`test_navigation_product_delivery`、`test_public_repository_completeness`。

每一类先写或保留能表达正式行为的 RED，再做一个最小修正。生产代码与测试替身不能在同一个提交里同时改变同一项语义。

如果确认某条旧断言已经被 D102／D103 的正式决定取代，必须在验收文档中写出旧规则、新规则和依据，不能只更新期望值。

## 6. R4：完整分片与 trace 复核

1. 用新运行器完成整个 `tests/motion_nav`；
2. 失败、错误、超时为 0；
3. 正序和逆序各跑一次，检查顺序依赖；
4. 从已有 D103 前、D105、D106 trace 提取：
   - 相邻观察的 movement tick 差；
   - 控制帧时长；
   - `lease_exhausted` 或没有新请求的帧；
   - section 提交次数或可用的近似指标。

trace 缺少某个字段时要明确写成“无法判断”，不能用时间接近替代因果证明。

## 7. 止损规则

- 世界模型修正两轮后仍不能把 F1 缩短场景降到 40 ms/tick 以内，停止并重新设计物理快照投影；
- 同一正式行为修正两次后仍产生相邻生命周期回归，停止局部修补并检查 D103 异步管线边界；
- 分片完整测试发现清单外 P0/P1，先登记并判断是否属于 D103 回归；属于则纳入，不属于则停止扩大本阶段；
- 不因测试数量多而删除测试、放宽安全断言或延长到无界等待。
