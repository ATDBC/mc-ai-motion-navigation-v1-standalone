# F2-CV：封闭普通地面候选族的完整验证方案

日期：2026-10-08。状态：独立验证器通过，正式接线按止损规则撤出；阶段未通过。

**目标：** 完整验证普通地面的 `9 × 2` 封闭候选族，通过公共前缀、查询缓存和普通地面尾迹内核把成本控制在控制期限内。安全资格先完成，质量选择后进行。

**依据：** [D083](../decisions/0083-verify-the-closed-ground-candidate-family.md)、[D082](../decisions/0082-separate-safe-tail-from-completion.md)和 [F2-SC 失败记录](../acceptance/F2SC-safe-tail-and-completion.md)。

## 1. 当前事实

- F2-SC 的安全尾迹、completion 和逐 tick职责分离已经保留；
- F2S-C-04 normal 已完成；
- remaining9 为 `4/9` 完成、`5/9` 有界失败、零安全事件；
- F2SC-C-02 有一个稳定反例，terminal 进展仍只认路线弧长；
- F2SC-C-03 有四个稳定反例，九个候选需要完整复核而现有上限只检查三个；
- remaining42、大集合、D061 和 Fabric 尚未运行；
- F2-SC、F2-GP、F2-SG 和 F2-S 都没有因此关闭。

F2-SC 保持未通过。F2-CV 不回写它的历史结果，只在前置门槛通过后接着运行尚未执行的层级。

## 2. 修改范围

预计只修改：

- 普通地面候选生成与安全验证；
- 普通地面中性尾迹计算和正式 1.21 回退；
- `FixedRoute` 的候选验证调用与 typed 结果；
- terminal 进展监视器；
- 对应测试、证据和四类文档。

明确不改：

- completion 几何、目标区域和目标面；
- A*、PlannerWorker、Session 生命周期和重试；
- 严格动作证明、运动求解器协议和输入账本语义；
- 候选评分权重和动作种类；
- UNKNOWN、支撑、碰撞、危险接触和伤害门槛。

## 3. 批次 0：冻结 oracle、RED 和最坏微基准

先建立一个只用于测试的完整 oracle。它按固定顺序逐项运行正式 1.21 计算器，覆盖九种按键与一／两 tick许可，不使用快速内核、不按质量剪枝，也没有“三个候选”上限。

冻结这些行为：

1. 调换候选枚举顺序，安全集合完全相同；
2. 改变便宜评分，安全集合完全相同；
3. 删除任一方向或任一许可长度，oracle 差分失败；
4. `prefix0`、第一个 tick和第二个 tick分别可追溯；
5. 状态、支撑、碰撞、UNKNOWN、危险、姿态、模式和材质变化都会使依赖失效；
6. 预算耗尽与“不安全”“缺信息”“不支持”是不同结果；
7. 没有证明中性尾迹时，预算耗尽不能发送中性输入；
8. F2SC-C-02 的 completion 距离改善与路线弧长进展分开记录。

最坏微基准至少覆盖：

- 十八个声明候选都要分类；
- 所有方向候选都进入完整中性尾迹；
- 支撑边缘或碰撞边界迫使全部候选走逐 tick回退；
- 材质或状态事实进入依赖；
- 无可用候选和存在最后一个安全候选两种情况。

先记录当前实现的行为和耗时，不修改生产代码。RED 必须稳定复现四个 F2SC-C-03 反例和一个 F2SC-C-02 反例。

## 4. 批次 1：实现共享验证器

实现一个纯候选验证器，输入是当前正式身体状态、普通地面路线、完成区域、世界视图和冻结候选域。输出包含每个候选的安全资格、依赖、使用的验证路径和统计信息。

共享规则：

1. `prefix0` 只计算一次；
2. 九种按键的第一个 tick只计算一次，并由一／两 tick许可共用；
3. 两 tick许可从同一第一个 tick状态继续计算第二个 tick；
4. 相同状态的中性尾迹可以复用；
5. 所有格子、支撑、碰撞和材质查询使用同一个 `WorldQueryCache`；
6. 依赖取每个候选实际读取事实的并集，不登记未读取的整片世界。

验证器不得读取候选评分、场景 ID、reason 或历史胜者。候选输入顺序扰动后，每个候选的 typed 结果和依赖必须一致。

## 5. 批次 2：普通地面尾迹内核和复杂边界回退

普通地面尾迹内核只适用于：

- `STANDING + WALK`；
- 无碰撞命中；
- 支撑连续且已知；
- 姿态、运动模式和材质规则在尾迹中不变；
- 不靠近支撑、高度、危险接触或 UNKNOWN 边界。

内核逐项实现 Minecraft 1.21 的速度衰减和位置推进规则。测试用正式逐 tick计算器做差分，覆盖速度分档、四个主方向、斜向速度、普通材质和一／两 tick起始前缀。状态和停止位置必须落在冻结数值容差内，依赖集合必须一致。

复杂边界统一进入批量逐 tick回退。回退在一次调用中推进全部待验证状态，并共享 `WorldQueryCache`。不能为提升速度减少候选、缩短尾迹或忽略材质与状态依赖。

## 6. 批次 3：删除结果上限并接入 typed 预算结果

删除 `_full_candidates >= 3` 等结果上限。新的结构预算来自：

- 九种按键；
- 两种许可长度；
- 共用的 0／1／2 tick前缀；
- 现有中性尾迹 tick上限。

墙钟预算只产生 `BUDGET_EXHAUSTED`，不产生部分安全集合。正式调用方只能在完整验证结束后选择方向输入。

预算耗尽时：

- 已完整证明的中性尾迹安全，可以提交中性输入；
- 中性尾迹没有证明，不能提交新输入；
- 两种情况都要有界交回现有上层，不新增重试或等待。

先运行独立最坏微基准。Windows 生产验证门槛为 P95 `≤8 ms`、P99 `≤15 ms`、最大值 `<30 ms`。超限立即停止，保留纯验证器和证据，不接正式 `FixedRoute`。

## 7. 批次 4：单独修 terminal 历史进展

为当前 terminal 路线身份保存历史最佳：

- 当前身体到 completion 的距离；
- 中性停止点到 completion 的距离；
- 当前速度和预计停止速度；
- 当前处于接近、制动还是反向修正。

候选只要在冻结容差内改善其中已经声明的 terminal 进展事实，就可以获得进展资格。它不需要继续增加已走完的路线弧长。

目标修订、路线修订、terminal 段身份变化或业务终态会重置历史。该状态不参与硬安全，不改变候选评分，也不能延长停滞期限。

只先运行 F2SC-C-02 的稳定反例。失败时只修进展记录和重置条件；若需要调权重、completion 或候选，立即停止。

## 8. 批次 5：接入正式链并分层运行

微基准和 terminal 进展都通过后，按下面顺序接入：

1. 四个 F2SC-C-03 稳定反例；
2. remaining9；
3. 已恢复的 remaining42；
4. F2-SC 聚焦检查、F2-GP 原定向检查和严格动作负对照；
5. v9、v8、v7、F2、F2-R；
6. 五组行为、协调集合和完整 motion_nav 正序／逆序；
7. D061；
8. Fabric。

任一层失败立即停止，不运行后续大集合。前四项必须从 `no_safe_ground_candidate` 变成完成，或返回由完整候选族证明的 typed 失败；不能再因为验证顺序或名额耗尽失败。

## 9. Fabric 范围

至少覆盖：

- 四方向窄 completion；
- 九键中最后排序的候选才安全；
- 一 tick和两 tick许可各一个正例；
- 预算耗尽时中性已证明／未证明两种分支；
- 支撑边缘、墙边、材质变化和 UNKNOWN；
- terminal 超调后的反向修正；
- 晚到、丢失、目标修订、相关与无关世界变化；
- JumpGap 或 ControlledDrop 严格动作对照。

每帧记录完整候选数量、typed 分类、公共前缀数、内核与逐 tick数量、查询缓存命中、预算结果、获胜候选、实际输入窗口、terminal 历史进展和来源所有者。

## 10. 止损与关闭条件

出现以下任一情况立即停止：

- 最坏微基准超过 8／15／30 ms；
- 需要按候选顺序、评分或墙钟选择“先验证谁”；
- 需要增加候选、completion、评分权重或固定距离特判；
- 快速内核与正式逐 tick规则不一致；
- 预算耗尽时需要使用未完成证明的方向输入；
- 需要新增 Session 状态、等待或重试；
- 严格动作、UNKNOWN 或伤害门槛改变；
- 历史成功退步或产生新安全事件。

F2-CV 只有在独立 oracle、最坏微基准、五个稳定反例、remaining9／42、Windows 分层回归、D061 和 Fabric 全部通过后才能关闭。关闭只解除 F2SC-C-02／03；F2-SC 仍须按自己的剩余门槛签署。

## 11. 本轮实施与止损

本轮完成了独立的 `GroundCandidateVerifier`：

- 固定分类 `9 × 2` 候选；
- 共用 `prefix0`、九个首 tick、九个第二 tick 和 `WorldQueryCache`；
- 提供 `SAFE`、`UNSAFE`、`NEEDS_INFORMATION`、`UNSUPPORTED` 和 `BUDGET_EXHAUSTED`；
- 普通尾迹使用 1.21 规则内核，复杂边界回退正式逐 tick计算；
- 预算耗尽时不公开部分安全集合。

Windows 1000 样本／场景的最终微基准为 P95 `5.3708 ms`、P99 `5.3963 ms`、最大值 `5.7788 ms`，deadline miss 为 0。独立门槛通过。

正式链在 remaining9 停止。C02 允许安全修正后，在历史最佳不再改善时以 `fixed_route_stalled` 有界结束。四个 C03 场景中，一个完成，三个在完整候选分类后返回 `fixed_route_has_no_forward_control`。随后 remaining9 只有 `3/9` 完成，并使下面两个历史成功场景退步：

- `f2r/clutter/0.1/11/1/product`；
- `f2r/clutter/0.2/9/6/product`。

完整控制帧的代表最坏项为 P95 `7.1502 ms`、最大值 `9.8121 ms`。性能没有触发止损；行为退步触发止损。

根因是正式接线把完整中性尾迹留在 tracking corridor 内当作硬安全。普通地面可恢复移动只需保持身体安全，并允许下一帧从新观察继续修正。tracking corridor 应用于质量和偏离判断，不能直接否决所有离开走廊但仍安全的中性尾迹。

项目已经撤出 `FixedRoute` 正式接线，保留纯验证器、oracle、微基准和失败证据。remaining42、后续大集合、D061 与 Fabric 均未运行。F2-CV、F2-SC、F2-GP、F2-SG 和 F2-S 保持未通过。

后续不在 F2-CV 内继续增加 corridor 例外。[D084](../decisions/0084-separate-world-safety-and-route-fit.md) 与 [F2-WR](F2WR-world-safety-route-fit.md) 已单独冻结世界安全、路线适用性、真实偏离和短期 tail 依赖的边界。F2-WR 通过后，才能重新接入本阶段保留的验证器并继续未运行门槛。
