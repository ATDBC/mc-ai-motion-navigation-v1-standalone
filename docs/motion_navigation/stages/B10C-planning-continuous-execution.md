# B10-C：规划接纳、连续接续与在线执行

日期：2026-09-23
状态：完成；八行接续矩阵和 2026-09-23 三方审查整改均已完成组件与 Fabric 回归

## 目标

把已经通过验证的动作结果接入现有规划、路线接纳和唯一执行链，并在事前冻结的组合范围内消除仅因接口交接造成的无谓停稳。

## 范围

B10-C 首版只连接现有普通支持域：Walk、Sprint、Step、JumpUp、JumpGap 和 ControlledDrop。Crouch/Crawl 的现有单模式路线继续保留，但新的主动 Crawl 入口、攀爬、流体和特殊接触不在本阶段加入。

B10 首版只解决下面矩阵中明确列出的限定组合，不等于已经支持带速起跳或从正在高速奔跑的 Sprint 状态直接进入 JumpGap。B10-B 的跨隙动作内部可以使用 sprint 按键，但入口仍是 B09 冻结的低速范围。

## C0：冻结每种组合的控制依据

接入规划前，先为矩阵每一行登记：

| 项目 | 必须说明什么 |
|---|---|
| 控制来源 | 旧版已验证动作、新求解结果，或明确的组合控制方案 |
| 入口／出口 | 沿用旧范围，还是声明新增范围 |
| 计算依据 | 规则、输入投影、Profile 或求解器版本 |
| 前置证据 | 哪些既有证据可复用，哪些必须新增 |
| 交接条件 | 何种实际出口才能交给下一动作 |

迁移期间可以沿用旧动作。旧动作只证明停稳出口时，不能一边保持原终态，一边宣称已经实现非停稳接续；必须补充新的控制依据和证据，或继续把该组合标记为未支持。

## 状态和规划

- 具体状态、动作入口／出口范围和规划状态键分别表达。当前 `PlannerStateKey` 保存支撑面、模式、姿态和速度区间；现有动作不按来向改变资格，因此方向暂不进入键。
- 同一对支撑面之间允许保留动作类型或转换身份不同的多条边，不能按起终点覆盖。
- 方向会影响下一动作时，方向必须进入规划键、互不支配标签，或经过有代价的已验证转换。
- 前一动作的具体可实现出口必须满足后一动作入口。
- 新动作加入图时立即验证启发式；无法证明下界时先使用零启发式，并与独立 Dijkstra 比较。
- 资源按动作顺序累计。条件化资源结果不能被写成完整结果。

## 接纳和执行

- `RouteAdmitter` 核验当前入口、执行窗口、世界依赖、资源和恢复条件。
- `RouteAdmitter` 同时核验请求代次、目标 ID／修订、路线位置和候选修订。
- 有限变化可以复核短期部分；重求解和长路线验证返回后台。
- 跨隙命令搜索已经提供容量固定的后台进程入口。不同动作连接不会因为完成顺序而互相覆盖；队列满时由提交方收到明确背压。
- `MotionRouteCoordinator` 已把活动路线、后台求解、最新状态复核和 `ActionRouteExecutor` 接起来。`JumpGap` 默认要求已接纳证明；历史 B09 回归只能在明确测试入口关闭该要求。正式 Fabric 默认协调链为 10／10。
- 后台等待期间，首条命令可以在已验证启动窗口内按真实应用 tick 重新锚定；动作开始后，剩余命令仍逐 tick 精确确认。
- 后台结果晚到时，不能直接恢复旧授权。接纳器从最新状态重放原命令并重新验证整段轨迹；该过程不搜索新命令。
- 复用现有路线身份、进度、依赖和活动走廊。
- 执行器每次只提交已接纳短期方案的前段，并根据新观察更新锚点和剩余计划。
- 迟到、重复和旧会话结果不能接管输入。
- 现有 `MotorGateway` 继续是唯一写入者。

## 2026-09-23 审查整改

这轮没有扩大 B10 的能力范围，修正了原冻结范围内的实现漏洞：

- 相邻特殊形状不会再因代表点重合生成零时长动作；后台规划和动作求解异常会返回明确失败，协调器会发现工作进程死亡和请求过期；
- 客户端输入采样满 64 条时丢弃最旧样本并报告累计丢失数，Python 账本据此把缺口标为歧义，不再让游戏 tick 抛异常；
- 表面 A* 使用稳定的整数优先级和平手顺序，地面边按跨列数量计价；三种平地终点和一张 20×20 折返迷宫进入固定基准；
- `JumpGap` 先检查中间支撑，确定确有空隙后才做扫掠；动作求解只复制局部物理体积；
- 正式按需规划入口现在会保留同一对支撑面之间的多种合法动作，由搜索比较代价；`Step` 不再遮蔽 `ControlledDrop`；
- 同一状态和世界下的同因重验最多重试两次；空中动作缺少顶部快照时明确拒绝；跨隙候选逐 tick 保存松开输入仍可安全落地的证明。

本轮最终运行了 327 项运动导航测试、1 项原生 Java 输入缓冲测试和扩展后的表面规划基准。随后重新运行 Fabric：B04 的空地、高墙、悬浮墙和坑，B07 的台阶和代表形状，B09 的跨隙、下降、混合路线及中断，以及 B10 的稳定落地、落地转向和默认后台协调链全部通过。另有一条 10.5 秒空闲专项实测，确认 64 条输入采样缓冲满后会丢弃旧样本、报告缺口，并能继续接收和释放输入。

Fabric 正确性回归不替代组件层的后台进程死亡、超时和异常注入。表面规划性能仍以固定基准为准；B07、B09、B10 的本轮正确性回归同时运行，不能用其耗时替换原先单独运行的性能成绩。

## 首版接续矩阵

下表冻结 B10 首版必须声明的组合。具体场景参数以验收文档引用的唯一清单为准；该清单可以直接写在验收文档中，也可以使用机器可读配置，阶段文档不再复制一份。

| 组合 | 首版允许范围 | 需要证明什么 |
|---|---|---|
| Walk → Sprint | 普通直线支撑 | 加速不产生接口停顿，资源资格持续成立 |
| Walk → Step → Walk | B07 已支持台阶 | 跨步和退出连续，未支持高度正确拒绝 |
| 低速 Walk → JumpUp → Walk | B05 入口范围 | 正确起跳、落地和接续，不扩大旧能力 |
| 低速 Walk → JumpGap → Walk | B10-B 试点范围 | 求解结果可被规划、接纳和执行 |
| Walk → ControlledDrop → Walk | B09 相邻一格下降 | 离边、落地和接续不靠固定停稳 |
| Step → Step | 已支持的连续台阶 | 连续跨步不会每格重置路线或强制停车 |
| JumpGap 落地 → Walk 转弯 | 冻结入口速度和转向几何 | 落点由后续方向共同决定，超界时减速或拒绝 |
| Sprint → JumpUp | 仅当预测制动后进入 B05 范围 | 需要的减速真实发生，不把高速状态伪装成低速入口 |

这不是所有动作的两两组合表。新增组合必须先补一行入口、出口、时序和证据，再取得发布权限。

## 每个组合的三类证据

1. **连续正例**：允许条件下没有机械停顿。
2. **边界对照**：正确减速、调整、拒绝或返回缺条件；不强制所有组合制造“完全停稳”例子。
3. **扰动或中断**：在声明恢复范围内修正；超出范围时不错误完成、不扩大输入权限。

## 完成条件

- 接续矩阵中所有声明组合达到验收门槛；
- C0 登记完整，所有新增入口／出口都有对应控制依据和前置证据；
- 普通规划任务可以自动选择已发布动作，不使用未验证边；
- 后台阻塞、迟到结果和候选过期不会清空仍安全的执行前段；
- 控制帧不承担完整重求解；
- 没有仅为模块交接而出现的无谓停稳；
- 确实需要制动的场景保留制动，不把“连续”理解为始终全速；
- B03–B09 已发布范围继续通过回归。
