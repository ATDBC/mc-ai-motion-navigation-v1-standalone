# 连续动作控制器、离线表与增量证明实施计划

日期：2026-10-10。状态：M0 未通过，阶段已停止；M1—M4 未开始。

依据：[D097](../decisions/0097-use-controller-table-and-incremental-safety-proof.md)和[架构](../architecture/incremental-motion-proof-v1.md)。

## 1. 共同范围

- TP、D095 和 D096 保持结束状态，不回写旧结果。
- M0—M2 不修改 `mc2p`。
- 每个新行为先写 RED 并确认失败原因，再写最小实现。
- 每个阶段单独提交、复核和记录证据；未通过不进入下一阶段。
- 冻结矩阵包含 R2 的 22 个正例、6 个负例，以及只能由混合地面／起跳／空中输入完成的审查反例。

## 2. M0：Windows 可行性基线

新增仓库内测量入口，不能从三方 `reviews/` 目录导入代码。它固定输出：

- 控制器对冻结矩阵的结果、输入和 physics step；
- 有、无模板高度截断两种诊断；
- 已知输入完整扫描的 rollout、目标、扫描和停车尾迹成本；
- 逐边界证明的 step 上界估算；
- Windows 环境、预热规则、每轮耗时和确定性哈希。

至少预热三轮，再运行二十轮。墙钟只用于报告，不参与选择。

M0 通过条件：

- 22 个正例全部找到；有意义的负例分类正确；
- 混合动作元反例能够找到；
- 正式无模板高度截断口径下，正例最大值≤400 ms、负例耗尽最大值≤800 ms；带高度截断结果只作诊断；
- 估算的单次增量证明 P95≤10 ms，动作开始 rollout P95≤15 ms；
- 相同请求的结果、输入和计数不受 `PYTHONHASHSEED` 影响。

M0 只授权 M1，不签署增量证明性能。

实际结果中，混合动作元反例三次正式采集的最大耗时为 587.9 ms、591.2 ms 和 736.9 ms。其余门槛通过，但不能抵消这一项失败。M0 没有授权 M1，后续章节保留为未执行设计，不表示当前工作顺序。

## 3. M1：控制器和离线表

新增：

```text
experiments/motion_navigation/trajectory_proto/
  template_controller.py
  motion_table.py
scripts/measure_incremental_motion.py
tests/motion_nav/
  test_trajectory_proto_template_controller.py
  test_trajectory_proto_motion_table.py
config/motion-navigation/trajectory-motion-table-v1.json
```

控制器先覆盖转向、上一格和一至三格跨隙。起跳只允许在全部时序分支着地时触发。控制器不能读取墙钟或随机数。

入口分箱使用速度、横向偏移和朝向误差。每个分箱分别抽取中心、各面边界和角点，并用固定种子增加随机样本；另保留独立种子验证集。首版每个有效分箱训练样本不少于 200，验证样本不少于 200。

通过条件：

- 验证集成功率≥99%，失败全部有类型；
- 零错误安全许可；
- 表项保留入口→参数→出口关联；
- 序列化和哈希确定；表项数与字节数有上限；
- 规则或生成器身份变化时拒绝旧表；
- 直线跨隙在 A3／A5／A15 中保持相同输入；
- 不产生正式执行许可，不修改 `mc2p`。

只允许一次分箱细化。仍不通过则停止。

## 4. M2：真实增量证明

新增 `incremental_proof.py` 和直接测试。先把以下检查写成 RED：

- 去掉承诺时的落地证明；
- 把 UNKNOWN 当成 FREE；
- 只证明一条时序分支；
- 忽略在途输入或实际生效 tick；
- 使用过期锚点、目标代次、世界依赖或表版本；
- 超过任务伤害额度；
- 执行命令与锁定后缀不同。

实现后，冻结矩阵必须和完整扫描逐项一致地给出风险区间、承诺边界、恢复边界、依赖和结果分类。

Windows 正式性能至少采集 200 个动作开始和 1,000 个逐 tick 决定。单独报告证明和 rollout；完整控制路径仍使用 8／15／30 ms 门槛。

M2 只允许一次限定性能修正。仍不通过则停止并保留 B10 现状。

## 5. M3：隔离闭环与正式链适配

先在现有模拟正式调用链上运行，不直接进入 Fabric。正式代码只能增加薄适配器：

- ActionSpec 提供模板身份和入口／出口要求；
- MotionRouteCoordinator 持有计划和增量证明结果；
- ActionRouteExecutor 只消费通用许可和控制器；
- NavigationSession 不增加动作类型分支、等待或状态字段。

对照指标包括完成率、总 tick、非中性停顿、动作交界最低速度、重规划次数、伤害、输入晚到和完整控制耗时。安全指标零退步，停车次数必须低于现有 B10 对照。

## 6. M4：Fabric

覆盖四方向转弯后上一格、三个跨隙宽度、普通和首条晚一 tick、目标修订及依赖变化。只有实际应用账本证明的输入才计入结果。

M4 不通过时撤回正式适配器，保留 M0—M2 的实验和证据。
