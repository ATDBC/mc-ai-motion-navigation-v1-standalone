# B12 视觉空气部分可见修正计划

日期：2026-09-27

状态：直接缺陷和针对性实机回归已完成；专用外形复查与下行底部危险检查留待后续

## 1. 要解决什么问题

2026-09-26 的视觉空气实现要求候选整格的投影全部可见。这个规则与用户已经确认的观察语义不一致，也会让悬崖、坑、半砖和楼梯下方的必要空气永远无法从上层确认。

本轮要恢复以下语义：只要假想完整方块有一块有效区域真正露在当前视野中，而该格没有报告真实方块表面，机器人就可以形成视觉空气。隐藏的半砖等非完整方块可能造成误判；这种误判允许存在，并由后续视觉或接触纠正。

本轮同时处理审查发现的直接关联问题：未加载区块被当成空气、信息视角与原生可见性口径不同、正式路线不复查已知依赖、遮挡规则表遗漏，以及长时间移动后解码缓存失效。

## 2. 本轮不做什么

- 不恢复 profile 3 稀疏射线。
- 不读取视野外或被完全遮挡方块的隐藏类型。
- 不加入完整的未知区域探索和观察站位搜索。
- 不新增半格或八分块世界知识。标准下行先由“有效露出区域”解决；只有实测仍证明具体动作需要子格事实时，才另写决定。
- 不引入增量观察协议。现有性能证据尚未证明需要改变传输契约。
- 不修改移动物理、路径评分、战斗策略或动作仲裁。

## 3. 视觉空气的正式判定

一次空气候选必须经过以下顺序：

1. 确认世界会话和场景代次与本帧一致。
2. 确认候选所在区块已经加载，位置位于世界高度内。后续露出区域还要裁到眼睛周围 16 格内。
3. 把候选格当成一个假想完整方块，投影到当前相机视野。
4. 裁掉视野外区域，再减去更近的不透明表面。
5. 剩余投影面积达到约一个画面像素时，记为“有有效露出区域”。不要求八个角全部进入视野，也不要求整格轮廓全部可见。`1e-12` 只用于数值稳定，不能作为观察门槛。
6. 本帧若在同一格报告了真实方块表面、身体接触或当前交互目标，则返回方块事实，不返回空气。
7. 没有更强事实时，返回 `air_query` 视觉空气。

下面四种结果必须分开记录：

| 结果 | 含义 | 导航处理 |
|---|---|---|
| 视觉空气 | 有有效露出区域，且没有真实方块表面 | 可以写入世界知识并用于当前路线 |
| 视野外 | 当前相机没有覆盖目标区域 | 可以请求转头 |
| 超出范围 | 有投影露出，但露出区域全在 16 格外 | 转头无效；有界地结束等待 |
| 当前站位完全遮挡 | 目标投影被近处表面全部盖住 | 原地继续转头没有意义；有界地交给观察站位协调 |
| 未加载或场景无效 | 客户端没有合法世界数据 | 保持未知，等待有效观察，不得猜测 |

## 4. 事实优先级和纠正

同一格的优先顺序为：身体接触和当前交互事实、当前帧可见方块、已有的具体非完整方块事实、视觉空气。

视觉空气允许与隐藏世界不同。屏障、隐藏光源或被完全挡住实体部分的半砖，都可能先被认为是空气。机器人后来接触或看到实际方块时，必须在同一世界会话内覆盖旧空气事实。

普通的部分可见空气不能删除已经知道的半砖、楼梯等非完整方块。正式路线若依赖一个已知方块，应低频请求复查它：

- 完整方块的预期表面处于有效露出区域却消失，可以更新为空气；
- 非完整方块只有在它原来应当可见的外形确认消失时才能撤销；
- 由身体接触确认、视觉上不可见的方块不能被普通视觉空气反复覆盖。

这样既能发现别人挖掉的支撑，也不会让机器人反复撞同一面屏障墙。

## 5. 实施顺序

### 5.1 先固定错误行为和新语义

增加原生与 Python 回归，先证明当前整格规则在悬崖、半砖和 1×1 坑上失败。新正例包括：

- 假想方块只有一部分露出，同格没有表面，返回视觉空气；
- 实体部分被遮住的首次半砖可以暂时形成视觉空气；
- 已知半砖不会被它上方的空白覆盖；
- 完全墙后、视野外和未加载区块保持未知；
- 同格任一真实方块表面可见时，不返回空气。

### 5.2 修改原生判定和客户端门禁

把 `cell_fully_visible` 改为返回可见区域状态。复用现有多边形差集，只检查剩余面积是否大于稳定误差阈值。九点和八角可以继续用于快速拒绝明显无交集的候选，但不能再要求所有点都可见。

`SurfaceSensor` 在调用原生判定前检查候选区块已加载。原生结果分别携带“可见空气、视野外、超出范围、完全遮挡”；未加载由客户端直接拒绝。空气、方块和 16 格内实体继续使用同一相机和遮挡表。

### 5.3 统一信息视角和等待结果

信息视角不能再用格子中心是否落在 120° 内作为判断。它应读取与原生相同的候选状态：

- 视野外才转头；
- 有部分露出但尚未形成空气时，等待下一帧有效结果；
- 当前站位完全遮挡时返回明确原因；
- 超出范围时不转头，并在固定控制帧数内结束等待；
- 同一原因超过固定帧数仍无进展时，结束本次等待并交给上层，不能无限停住。

本轮不自动规划探边站位。后续观察站位协调可以读取“当前站位完全遮挡”，再决定是否走到边缘、潜行探身或选择其他观察点。

### 5.4 修正遮挡规则来源

在固定 Minecraft 1.21 客户端中枚举全部方块状态，记录渲染方式、不透明完整方块属性、碰撞形状和视觉外形。生成受版本控制的规则清单及哈希。手写策略只保留明确例外，并说明理由。

普通方块实体渲染的告示牌、旗帜、头颅等不能仅因 `BlockRenderType.INVISIBLE` 被当成没有视觉外形。屏障、光源和结构空位等人眼无法区分的隐藏状态仍可按视觉空气处理；接触和特殊效果继续纠正导航事实。

### 5.5 接入路线依赖复查

空气请求继续优先查询未知格。另给当前已接纳路线的关键支撑、头部空间和扫掠格一个低频复查配额。地图中与当前路线无关的已知格不主动重查。

复查产生变化时，只让受影响的路线段失效。不能因为任何视觉变化清空整张地图或立即全局重算。

### 5.6 修正长期解码缓存

当前按“含坐标的完整方块记录”缓存 4,096 项，满后不再更新。改为有界淘汰，或者把可复用部分改成不含坐标的方块几何键。先用 90 秒连续移动回放比较两种最小方案，再选择更快的一种。

缓存修改不能改变观察事实、时间戳或世界会话语义。

### 5.7 补齐独立小问题

- B10 滑行阶段缺失或晚到的输入样本不能默认为中性，应进入已有的输入不确定处理。
- 公开仓库补入验收入口引用的 `tests/test_segmented_trace.py`。
- 把 NumPy 写入当前版本锁定和公开安装说明。
- B10 除晚到率外，记录每条严格命令实际到达时距离最晚许可时刻还剩多少 tick 和毫秒。

### 5.8 恢复 B07 与 B09

- B09 夹具不能在平视下重复同一请求。缺失格返回“视野外”时，使用正式信息视角抬头，并在试次中逐格记录状态。
- B07 先记录每个失败帧的着地、速度、姿态、碰撞和实际输入生效 tick。失败记录必须在抛出异常前写盘。
- 在证据能区分退回半砖、冲过出口或侧向掉落之前，不放宽普通 Walk 的着地条件。
- 受控下降在离开边缘前增加近距离落点观察门槛。它属于动作接纳，不把“只看见上部”从通用视觉空气中删除。

## 6. 验收顺序

### 6.1 组件和原生门禁

- 固定种子的随机世界继续检查不能获得不可能取得的信息。
- 允许隐藏非完整方块造成视觉空气；报告数量，但不把它算成非法感知。
- 未加载、视野外和完全遮挡产生空气的次数必须为零。
- 当前帧看见真实方块却同时产生空气的次数必须为零。
- 对相同相机和场景，方块、空气和实体使用同一个遮挡规则版本。

原来的“与隐藏世界真值相比，视觉空气零误判”门禁废止。它会把允许的视觉错觉当成实现错误。

### 6.2 固定几何场景

至少覆盖：

- 一格悬崖下方；
- 下半砖和下楼梯；
- 地面 1×1 坑；
- 柱子后完全遮挡；
- 只有细小但稳定露出区域的候选；
- 首次遇到实体部分被遮住的半砖；
- 已经记住的半砖；
- 屏障接触纠正；
- 区块尚未到达；
- 已知支撑被合法移除。

下行场景不能通过测试夹具预先移动到特殊位置取得空气。

### 6.3 实机回归

1. B02：三态知识、未加载区块、接触纠正和世界会话。
2. B07：下半砖、下楼梯和已知形状保持。
3. B09：不预先观察的一格受控下降。
4. B10：跨隙和连续动作，补充命令许可余量。
5. B11、C1-B、C1-C、B12-B：只重跑实际依赖视觉空气、信息视角或缓存性能的场景。

每批同时保留成功和失败原始记录，不根据结果改变任务分组。

## 7. 性能门槛

- 自然地形热态表面计算 P95 继续不高于 8 ms。
- 128 个空气候选单独报告 P50、P95、P99 和最大值。
- 90 秒连续移动后，类型解码 P95 不得高于禁用缓存的基线。
- 控制帧继续使用已有 P95、P99 门槛；新增命令许可余量分布，不用控制往返均值代替。
- 若部分可见判定让空气计算明显变慢，先优化候选裁剪和共享多边形，不提前改成增量协议。

## 8. 完成条件

- D004 和 D035 的新语义已经落实到原生、客户端、Python 消费端和公开门禁。
- 标准下行不再因整格永远看不全而无限等待。
- 未加载、视野外和完全遮挡不会产生空气。
- 已知非完整方块与接触事实不会被弱视觉空气覆盖。
- 当前路线依赖发生合法变化后能够更新，且不会触发全图重算。
- 长时间移动不会因为缓存填满而退化到比无缓存更慢。
- B07、B09 和受影响的 B10—B12 场景完成新规则下的实机验收。
- 公开仓库包含实现、测试、版本依赖和代表证据，外部可以按 README 复核。
