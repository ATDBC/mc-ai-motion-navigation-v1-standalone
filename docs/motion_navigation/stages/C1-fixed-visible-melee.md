# C1：战斗纵切片

日期：2026-09-24
状态：C1-A、C1-B 与 C1-C 均已完成正式 Fabric 验收

## 目标

用一个固定、持续可见、关闭 AI 的敌人跑通第一条战斗闭环：接近、稳定瞄准、提交一次有目标身份的近战攻击，并根据后续正式观察确认命中。

这一步检查 B10 的公共链能否服务导航以外的任务。它不交付完整战斗系统。

## 现行分步

| 子阶段 | 内容 | 开始条件 |
|---|---|---|
| C1-A | 固定敌人，一次确认命中 | B10-C 及 D014 整改完成 |
| C1-B | 一只正常移动僵尸，重新接近和连续攻击 | C1-A 通过，并另行冻结死亡确认和交战记忆验收 |
| C1-C | 敌人还击，受击后的动作责任与路线恢复 | 已完成受控原版攻击、责任交接、恢复和重新锚定验收 |

## C1-A 完成记录

C1-A 已接通实体受击观察、有目标身份的单次攻击、客户端准星与距离核验、稳定瞄准、导航接近、取消和修订失效、异步完整记录及离线重放。正式 Fabric 批次完成 40／40 正例和 7／7 反例，证据见[验收记录](../acceptance/C1A-fixed-visible-melee.md)。

本阶段把起点固定为目标中心外 3.5 格。僵尸外形边缘仍在三格粗略近战范围之外，所以机器人必须先移动；同时该距离不需要未知区域探索。更远距离的战斗接近留给 C1-B 与移动目标一起验收。

C1-B 已按独立的[阶段记录](C1B-moving-target-melee.md)、[架构](../architecture/C1B-moving-target-melee-v1.md)和[验收结果](../acceptance/C1B-moving-target-melee.md)完成位置更新、交战记忆、生命、死亡确认、连续攻击、固定生物种子和移动目标验收。

C1-B 当前源码批次 `20260924T091651661550Z-34995f43` 通过 20／20 个移动追击正例和 10／10 个反例，并逐帧重放 3,145 次决策。共享核心修改后，C1-A 又以批次 `20260924T053939064824Z-40292978` 完成 40／40 个正例和 7／7 个反例回归。

C1-C 已完成共用外部运动处理链的首个正式来源。当前源码批次 `20260924T091041609545Z-d7c3c88b` 通过 20／20 个正例和 10／10 个反例；整帧控制 P95 为 5.7396 ms，受击到首个安全恢复输入实际应用的 P99 为 49.3256 ms。首版只正式覆盖僵尸伤害和击退、已知完整平地；实体挤压、活塞推动和复杂地形仍需分别补来源证据与验收。

## C1-A 范围

- 已知、平坦、封闭的测试场地；
- 固定石剑已经在主手；
- 一个关闭 AI、不能移动和还击的敌人；
- 初始目标持续处于合法视野内；
- 机器人从攻击范围外开始；
- 到达约 2.5 格的稳定站位后再瞄准和攻击；
- 规则决策，不使用学习模型；
- 保存完整正式观察流和各层因果记录。

不包含移动中攻击、连续攻击、击杀、敌人还击、多敌人、远程武器、食物、盾牌、装备切换、跳劈、未知探索或主动修改世界。

## 实施顺序

1. 扩展正式实体观察，保存客户端可见的受击动画状态；增加 `AttackEntityV1` 和客户端目标核验。
2. 建立最小战斗目标和 C1-A 阶段执行器，复用现有导航、视角仲裁和唯一输入出口。
3. 接入固定场景、种子／版本清单、完整观察流和六层因果记录。
4. 完成组件、Java 客户端和 Fabric 正反例，再进行正式重复验收。

每一步先写失败检查，再实施最小改动。不能为了 C1-A 提前建立完整武器、威胁场或战术框架。

## 完成条件

- C1-A 的正式成功和反例达到对应验收文档的门槛；
- 攻击绑定目标身份，准星指向其他实体时不会误攻；
- 攻击执行回执与命中确认分别记录；
- 目标取消和修订会让旧导航、瞄准和攻击请求失效；
- 完整记录可以离线重放局势评估、候选生成和选择；
- 失败可以定位到局势评估、候选覆盖、选择、技能执行、仲裁或运动层中的最早断点；
- B03–B10 已发布范围继续通过相关回归。

C1-B 实施时必须按独立架构和验收门槛补证据，不能把 C1-A 的固定目标结论直接外推到移动敌人。
