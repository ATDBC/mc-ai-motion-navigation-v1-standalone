# B05：最小跨高度动作

日期：2026-09-19
状态：已完成

## 实际交付

B05 已加入一个经过 Fabric 校准和验收的 `JumpUp`。它只处理相邻一格上升，不扩大到跨坑、下降或跑跳。

- `JumpUpProfile` 固定游戏版本、材质、入口速度、非对称起跳区域、参考轨迹、最长等待、落地区域和动作代价；
- 统一几何按 Minecraft 的实际碰撞顺序检查参考轨迹：每个 tick 先检查垂直移动，再检查水平移动；
- 已知图可同时包含多个脚底高度。Walk 只连接同高节点，JumpUp 只生成向上相邻一格的有向边；
- 快照顶部净空由能力显式声明。普通 Walk 不复制跳跃最高点所需的额外一格，JumpUp 快照声明额外一格；
- 后台进程能生成 Walk—JumpUp—Walk，路线接纳保留动作类型，动作段执行器分别调用 B03 与 JumpUp 控制器；
- 阶段由真实身体观测推进。一次跳跃脉冲、输入回执或 tick 计数都不能代替离地和落地；
- PREPARE、REQUEST_TAKEOFF、AIRBORNE、VERIFY_LANDING 四个阶段都已建立取消闭环。

最终 Profile 的入口速度上限为 `0.1 格/秒`。相对起点中心允许向后 `0.18` 格、向前 `0.01` 格、横向 `0.16` 格，并受半径 `0.18` 格约束。实测发现入口不能用一个对称圆形区域描述：角色稍微靠前且带有速度时，碰撞箱会先撞到高台侧面。因此保留非对称限制，而没有放宽落地判定。

## 要解决的问题

B04 只会在同一高度生成 Walk 路线。它已经证明后台规划、路线接纳和固定路线控制能够分开工作，但还没有证明系统可以加入一种具有独立前置条件、执行阶段和取消规则的新动作。

B05 只加入一种 `JumpUp`：角色从普通地面低速起跳，跳上水平方向相邻、顶面高一格的普通方块，然后继续 Walk。它用来检查现有世界知识、几何、规划、路线接纳、动作执行和唯一输入出口能否共同支持跨高度动作。

## 本阶段范围

1. 用独立 Fabric 实测校准低速 `JumpUp`。记录起跳输入、实际离地、逐 tick 位置和速度、最高点、落地、停止及输入应用回执。
2. 只支持站立姿态、普通草方块、四个水平正方向、上升一整格和一个已校准的低速入口范围。
3. 世界快照允许声明有限的脚底高度范围。它只复制该范围的支撑层、身体空间和 `JumpUp` 轨迹需要的顶部净空。
4. 普通 Walk 节点可以位于不同高度。Walk 边仍保持同高；`JumpUp` 是一种有独立类型、代价和依赖的有向边。
5. `JumpUp` 成立前必须确认起跳支撑、完整身体轨迹、顶部净空、目标支撑、落地区域和后续可恢复范围。未知、阻塞和未支持继续分别返回。
6. 后台规划可以生成 Walk—JumpUp—Walk。搜索结果仍只是候选，不能直接写输入。
7. 路线接纳把图边转换成有顺序的动作段。连续 Walk 仍交给 B03 控制器；`JumpUp` 交给新的阶段执行器。
8. 跳跃阶段必须由真实身体观测推进。提交跳跃键不等于已经离地，落到错误层高不等于完成。
9. 起跳前取消按地面动作制动；已经离地后取消进入“取消中”，继续执行已校准的安全落地方案，实际落地并停稳后才报告取消完成。
10. 正式实现与实机验收只使用独立 Fabric，并继续经过现有动作仲裁和客户端输入租约。

## 明确不做

- 不加入跨坑跳跃、向下跳、冲刺跳、潜行、连跳或跑酷；
- 不寻找最大跳距，也不把一次成功当作能力边界；
- 不支持半砖、楼梯、冰面、液体、梯子或其他未校准材质；
- 不接入未知探索、观察站位、动态实体绕行或局部修路；
- 不在 B05 同时加入对角寻路、路线平滑或连续空间最短路线；
- 不让 A* 根据地形名称猜测跳跃。规划只消费已经由能力查询确认的动作边。

## 固定动作定义

首个 `JumpUp` 满足下面的几何关系：

- 起点和终点的水平格相邻，`|dx| + |dz| = 1`；
- 终点脚底高度比起点高一格；
- 目标方块是经过校准的完整普通支撑面；
- 起跳时角色站立、接地，水平速度和相对位置处于实测允许范围；
- 起跳方向与平台方向一致，视角俯仰不改变水平动作语义；
- 动作成本使用实测的准备、离地、落地和进入后续 Walk 所需时间。

这些条件是首版能力声明。具体数值只从版本化 Profile 读取，不使用隐藏默认值。

## 状态与职责

`JumpUp` 执行器最少包含这些状态：

```text
PREPARE
  → REQUEST_TAKEOFF
  → AIRBORNE
  → VERIFY_LANDING
  → COMPLETE

PREPARE / REQUEST_TAKEOFF → CANCELLING → CANCELLED
AIRBORNE / VERIFY_LANDING → CANCELLING → CANCELLED（实际落地并停稳后）
任意活动状态 → FAILED / INPUT_LOST / UNSUPPORTED
```

- `PREPARE` 核对身体、入口速度、方向和最新几何，并把身体送入已校准起跳区。
- `REQUEST_TAKEOFF` 只提交有期限的跳跃输入，并等待输入回执和实际离地。
- `AIRBORNE` 按实测方案控制水平移动，不使用地面停车假设。
- `VERIFY_LANDING` 核对接地、目标层高、水平落地区域、支撑和速度。
- `COMPLETE` 只表示已经进入后续 Walk 可接受的入口状态。

动作阶段由执行器拥有。后台规划器不能推进动作阶段；B03 固定路线控制器也不承担空中控制。

## 已完成的实施顺序

### 1. 建立校准与反例

- 增加只读的 Fabric `JumpUp` 校准探针。
- 固定一格高草方块平台、起跳方向、自动跳关闭和非飞行状态。
- 采集不同起点偏移和低速入口下的真实轨迹。
- 同时采集未离地、输入被拒绝、碰顶和落地偏离反例。
- 从有效样本冻结入口范围、输入序列、轨迹误差包络、最长离地等待和最长落地等待。

### 2. 增加动作能力和几何查询

- 新建 `mc2p/motion_nav/jump_up.py`，保存 `JumpUpProfile`、动作边、查询结果和阶段执行器。
- 使用校准轨迹的相邻采样做连续扫掠，并按实测误差扩大身体包络。
- 起点和终点分别做支撑查询；空中采样不错误要求脚下持续有支撑。
- 缺少任一关键格时返回 `NEEDS_INFORMATION`，不生成可执行边。

### 3. 扩展有限三维快照和后台规划

- 把 `KnownMapBounds` 从单一 `feet_y` 改成明确的最小、最大脚底高度，并迁移 B04 调用方。
- 快照仍按格数分批复制。垂直范围增加后，单批预算语义不变。
- 图节点可以处于多个高度；Walk 只连同高相邻节点，`JumpUp` 只连已确认的一格上升节点。
- `RouteCandidate.segments` 保存动作类型。路线身份必须包含动作段，不能让相同节点序列下的不同动作得到同一身份。
- 用独立 Dijkstra 校验带 Walk 和 JumpUp 代价的 A*。启发式必须保持不高估；若首版无法证明，则对启用 JumpUp 的请求先使用零启发式。

### 4. 建立动作段路线和执行交接

- 新建最小的动作段路线与执行器，只支持 `WalkSegment` 和 `JumpUpSegment`。
- 路线接纳按动作边生成有序动作段。连续 Walk 继续合并，不能跨过 JumpUp 合并路线。
- Walk 段复用 B03 控制器。Walk 到 JumpUp 时必须进入跳跃允许的入口速度和起跳区；JumpUp 完成后才能把控制交给下一段 Walk。
- 当前走廊依赖包含即将执行的整个 JumpUp。相关几何变化会阻止起跳；无关远处变化不撤销当前动作。

### 5. 关闭取消、失联和失败分支

- 起跳输入得到拒绝回执时，不进入空中阶段。
- 限定时间内没有观察到离地时，动作明确失败，不无限重复跳跃。
- 空中收到取消或新目标时，保持当前动作身份，先完成可行落地，再结束或交接。
- 空中输入断流依赖客户端租约释放，并继续观察实际落地结果；不能立即报告停止或取消完成。
- 落在错误层、失去目标支撑或超过已校准时间时给出不同失败原因。

### 6. 闭环验收和回归

- 完成纯函数、参数化闭环、后台进程和路线接纳测试。
- 完成 Fabric 单动作、Walk—JumpUp—Walk、取消和反例测试。
- 重跑全部 `tests/motion_nav`，再跑 B03、B04 代表性实机场景，确认普通 Walk 没有退化。
- 更新验收文档为实际结果。没有真实运行证据时，B05 保持未完成。

## 完成条件

1. 校准报告明确入口速度、起跳区、控制序列、轨迹误差、时间界限和适用材质。
2. 声明范围内 100 次有效 `JumpUp` 全部到达正确层高；可避免碰撞、掉落和错误完成均为 0。
3. 低顶、未知净空、未知落地面、入口速度不满足、错误姿态和未支持材质均不启动动作。
4. 只有观察到实际离地才进入 `AIRBORNE`；只有目标层接地、支撑成立且身体进入后续入口状态才完成。
5. 起跳准备、请求起跳、空中和落地确认阶段的取消都有实机证据。空中取消不报告瞬间停止。
6. 后台可以生成并执行至少一条 Walk—JumpUp—Walk 路线；上下层目标不会因相同 XZ 被误判到达。
7. JumpUp 相关变化只影响相交的候选或当前动作，不让无关变化撤销安全 Walk。
8. 纯控制计算继续满足 P95 ≤8 ms、P99 ≤15 ms、最大值 <30 ms；后台搜索不阻塞控制线程。
9. B02、B03、B04 的正式测试继续通过。新增能力关闭时，规划结果与 B04 一致。

## 进入下一阶段的条件

B05 已满足本阶段条件，可以开始下一阶段的正式未知与观察协调。跨坑、下降、冲刺和连续多动作仍留在后续阶段，不因 B05 单个动作成功提前开放。
