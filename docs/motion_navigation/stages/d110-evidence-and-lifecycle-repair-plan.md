# D110 关闭证据链与生命周期修复计划

日期：2026-10-15。状态：**已完成已授权实现；唯一一次 B10 因原 30 ms 墙钟门槛停止。** 决定见 [D110](../decisions/0110-repair-close-diagnostics-and-measure-solver-tail.md)。

## 1. 范围

本阶段只做四件事：

1. 在调用线程抓取 `close_release` 诊断，并与 trace 记录一起进入异步队列；
2. 给 B10 求解补线程 CPU、垃圾回收和试次身份记录；
3. 修复 Linux settle 阶段的 fork 链逃逸，以及两处测试问题；
4. 完成检查后只运行一次 600 秒 B10。

不修改运动控制、路线、动作证明、输入窗口或伤害规则。

## 2. 实施顺序

### D110-1：关闭诊断

- 先写一个走真实 `Runtime.close()` 顺序的失败测试；
- 后端 `close()` 必须清空诊断；
- 修复后断言 close 诊断存在、数值正确，trace 和诊断记录数量一致；
- 为 `null` 诊断补明确错误测试。

### D110-2：求解测量

- 先冻结一个试次的原有结果和输入摘要；
- 增加 `solve_thread_cpu_ns`、每代 GC collection delta 和 `solve_gc_overlap`；
- 保留现有 `solve_time_ns` 和 30 ms 判定；
- 测量代码失败时不得影响求解和安全结果。

### D110-3：Linux 生命周期

- 先保留 `fork_during_cleanup` 的失败场景；
- settle 阶段改为直接强制结束身份匹配的已登记后代；
- 修正只有孤儿场景才要求收养的断言；
- 在关闭 stderr 副本后统计 fd。

### D110-4：回归和唯一一次 B10

- Windows 直接与相邻测试；
- 完整运动导航正序、逆序；
- 公开快照正序、逆序和 Java 门禁；
- 所有代码检查通过后，运行一次 600 秒 B10；
- 根据逐样本字段报告 30 ms 离群，D110 内不改门槛。

## 3. 止损条件

- 修复需要改变 Runtime 公共动作语义时停止；
- 新增测量改变候选、输入或轨迹时停止；
- 两轮限定修正后 close 诊断仍与 trace 错位时停止；
- Windows 检查未全绿时不运行 B10；
- B10 后不为了通过而修改门槛或再次运行。

## 4. 最终结果

- 关闭诊断、求解测量和 Windows 生命周期检查已完成；
- Windows 源树与公开快照正序、逆序全绿，Java 门禁与快照校验通过；
- 唯一一次 B10 的功能、安全、来源释放和时间归因通过；
- 142 个求解样本只有一个超过 30 ms，最大值为 39.2484 ms；
- 该样本与唯一一次二代垃圾回收重叠，但现有线程 CPU 计时粒度不足以证明因果；
- 本阶段按原门槛停止，不重跑 B10，不进入求解器优化；
- Linux settle 与 fd 的最终字节动态复核仍待 Linux 环境完成。
