# 连续高度地面移动整改计划

日期：2026-09-27

状态：H1 至 H6 已完成代码和组件闭环；整改后的代表性 Fabric 矩阵 12/12 通过，完整验收矩阵仍待运行

## 1. 要解决的问题

连续高度移动已经能在代表场景中运行，但复审发现现有结果依赖理想起点、理想输入时序和固定视角。主要问题有五类：

1. 地面证明按浮点路线点匹配。身体离格子中心几厘米，证明就无法接入。
2. 混合路线只尝试一次证明或改道。改道结果仍可能包含没有证明的小高差边。
3. 执行器逐帧回放旧输入。输入晚一帧、视角变化或入口速度变化时，不能根据当前身体状态修正。
4. 伤害额度按单次下落检查。整条路线可能累计超过任务允许值。
5. 多格下降尚未要求近距离看清落点底部，低矮危险可能藏在边缘下面。

## 2. 实施顺序

### H1：按规划节点绑定证明

- `GroundTraversalPlan` 保存所证明的表面节点序列。
- 接纳器用节点序列选择证明。
- 运行时从身体当前位置接入第一个规划节点时，不改写证明身份。
- `WalkSegment` 和 `FixedRouteController` 检查节点身份及路线后缀，不再要求运行路线与证明路线逐点完全相等。

完成条件：起点在支撑面内偏移 0.05 格和 0.12 格时，仍能接入同一份证明。

### H2：最终路线的每段小高差都要有证明

- 把连续 `Walk` 拆成若干最大连续段。
- 从当前真实状态开始的地面段可以直接生成证明。
- 暂时无法取得可靠入口状态的后续地面段，不得带着缺失证明进入接纳；规划器禁用对应边并有界重搜。
- 每次重搜后重新检查结果，直到路线不含未证明边、找到完整证明，或达到搜索期限。

完成条件：小高差后接一格下降的混合路线能够保留前段证明；规划结果不再出现“要求证明但证明列表为空”。

### H3：证明走廊内逐帧选键

- 离线证明负责给出可通行走廊、世界依赖、入口和出口范围。
- 执行器每帧从正式状态锚点出发，用 1.21 运动计算器评估九种地面方向输入。
- 评分考虑路线进度、横向偏差、终点制动余量和下一动作入口。
- 输入晚一帧时按当前状态重新选择，不继续按旧序号回放。
- 偏出已证明走廊、连续无进展或依赖变化时返回有类型的“需要重规划”。身体在空中时仍由当前动作负责落地。

完成条件：上下两个半砖在视角偏转 30°、每条输入晚一帧、20% 随机晚一帧时均能完成；不能完成时必须有界退出，不能一直 `RUNNING`。

### H4：整项任务累计伤害

- 规划资源中加入“剩余运动伤害额度”。
- 每条可能受伤的下落边消耗自己的保守预计伤害。
- 搜索、接纳和动作证明使用同一余额。
- 同一任务修改目标时保留已消耗额度；新任务才重新建立额度。
- 归因不确定时按保守预计值扣除。战斗伤害影响生命状态，但不冒充运动额度消耗。

完成条件：额度 2 点时，两次各 2 点的下落路线不能成立；额度 4 点时可以成立。

### H5：下落前确认落点底部

- 视觉空气正例附带观察距离和“露出区域是否到达格子下部”的事实。
- 多格下降在接纳前重新请求落点身体空间。
- 只有近距离、当前或仍在短有效期内、且下部露出的空气事实才满足门槛。
- 视野外、超出范围、完全遮挡和看见上部但没有看见下部必须分别返回。

第一版近距离上限定为 4.5 格。它来自现有边缘观察的几何复现；正式 Fabric 结果若证明过宽或过窄，再通过设计决定修改。

### H6：修正遮挡分类

- `potted_*` 不再被植物名称后缀误判为可透视。
- 普通花、树苗等仍按现有视觉外形处理。
- 用注册表枚举测试覆盖盆栽系列，避免继续增加零散名称分支。

## 3. 验收顺序

先运行组件闭环矩阵：

- 起点偏移；
- 连续上、下半砖；
- 小高差加空中动作；
- 视角偏转；
- 固定一帧迟到与冻结随机迟到；
- 入口速度扰动；
- 停滞与重规划；
- 累计伤害；
- 落点观察门槛；
- 盆栽遮挡。

组件矩阵通过后再运行 Fabric。实机至少记录：观察到控制提交、命令距最晚生效 tick 的余量、每段动作开始与结束 tick、重规划原因和最终落点。

## 4. 本轮不做

- 不引入通用轨迹优化器。
- 不把路径扩成任意角度平滑。
- 不用放宽静止动作入口来掩盖衔接问题。
- 不把“代表场景通过”写成完整速度带和全部方块形状已经验收。

## 5. 当前结果

- 起点在支撑面内偏移 0、0.05 和 0.12 格时，同一份节点证明都能接入。
- 小高差后接一格下降的混合路线保留前段地面证明；最终路线不会携带缺失证明的变化高度 Walk。
- 连续上、下半砖在固定一帧迟到、冻结种子的 20% 随机迟到、0° 至 90° 视角偏差和入口速度 0 至 3 格／秒下完成组件闭环。
- 额度 2 点时，两次各 2 点伤害的路线被拒绝；额度 4 点时允许，动作完成与重规划不会补回已消耗额度。
- 直接多格下降缺少近距离、较新且下部可见的落点证据时会返回缺信息；补齐正式视觉空气证据后才允许接纳。
- 盆栽不再因植物名称后缀被当成可透视状态。
- 落点被当前平台完全遮挡时，只有 `landing_visual_evidence_missing` 会触发潜行探边。普通遮挡仍有界等待，不会盲目前进。
- 探边后的蹲伏状态可以直接进入同一份受控下降证明，不会先走回格子中心。落地完成按证明中的落地区域、速度和姿态判断，不再要求命中单个预测坐标。
- 同方向连续两级及以上的一格下降会合成一段地面证明。孤立一格下降和直接多格下落仍走受控下降，不共享这项放行。

整改后批次 `20260927T150035189658Z-5d631809` 覆盖四个方向的连续小高差、四级连续下降和直接下落 1、2、3、5 格，12/12 通过。四级下降从上一批次的四个 `ControlledDropSegment`、51 tick，改为一个 `WalkSegment`、33 tick；同条件持续前进参照为 32 tick。5 格下落仍先探边，再用一个 `ControlledDropSegment` 落地，实际伤害 2 点，没有超过 2 点任务额度。

这次实测证明代表性主链可用，但没有覆盖全部速度带、授权形状和随机迟到重复次数，不能关闭第 3 节的完整矩阵。

## 6. 第二轮复审整改（2026-09-28）

第二轮复审确认 H1 至 H6 的主要目标已经实现。剩余问题集中在探边动作、重复重规划、后续地面段和会话级风险记账。本轮按下面顺序处理。

### H7：探边成为有明确所有者的动作

- 新增 `LandingEdgeProbe`，由它保存目标修订、落点格、开始观察序号、到达边缘的观察序号、期限和当前状态。
- `NavigationSession` 只持有一个探边动作，不再用 `_reason` 和布尔保持位决定是否潜行。
- 目标修订、取消、关闭、超时或接纳不再需要探边的路线时，探边立即结束并交出移动控制权。
- 普通观察仍要求证据在 4.5 格内、足够新且落点格下部可见。
- 探边可以替代 4.5 格距离限制，但证据必须在到达边缘以后取得，必须看到落点格下部，并且只能授权探边绑定的落点格。
- 正对边缘时平台会一直挡住落点下部，因此探边采用斜侧观察位。取得证据后先沿边缘横移到下落中心线，减速、松开潜行并恢复原视角，然后才允许路线接管。

### H8：输入失联和重复重规划有明确终点

- `INPUT_LOST` 在动作完成安全落地后直接成为会话失败终态，不再重新规划。
- `NEEDS_REPLAN` 按“原因、当前支撑面、世界几何修订”计数。
- 同一个键最多重新规划两次。第三次返回 `replan_retry_exhausted`。
- 目标修订、身体到达另一个支撑面或世界几何变化会形成新键，不继承旧次数。

### H9：后续地面段一次搜索完成

- 规划状态增加“仍在首个连续地面段”这一位。
- 普通 Walk 保留该状态；经过 Step、JumpUp、JumpGap 或 ControlledDrop 后清除。
- 状态清除后不再展开需要地面证明的 Walk 边，直接使用 Step 等已经存在的后备边。
- 保留首个地面段证明失败后的有限替代路线搜索，但不再为后续每条证明边反复运行完整 A*。

### H10：伤害额度按承诺动作记账

- 接纳路线时，用当前剩余额度重新核对所有受伤下落，不能继续使用请求发出时的旧余额。
- ControlledDrop 一旦离开起始支撑，立即按保守预计伤害记账。
- 随后的成功、取消、输入失联或失败不重复扣减，也不能撤销已经承诺的额度。

### H11：直接下落性能单独验收

- 先测探边动作改造后的 1、2、3、5 格下落分段耗时。
- 在不降低落点证据门槛的前提下，允许探边在远离边缘时正常前进，接近边缘后再保持潜行。
- 若 2 格以上下落仍不能满足“持续前进参照加 3 tick”，在决定记录中说明观察和探边成本，并按高度分别冻结新门槛，不能把退化隐藏在总用时里。

### H12：第二轮验收顺序

1. 先用第二轮复现脚本确认五个缺口全部关闭。
2. 运行 `tests/motion_nav` 全量检查。
3. 运行连续高度组件闭环矩阵，覆盖随机一帧迟到、视角偏差、入口速度、起点偏移和累计伤害。
4. 最后重跑完整 Fabric 矩阵，并分别报告移动、观察、探边和制动耗时。

## 7. 第二轮实机结果

正式 Fabric 批次 `20260928T001700926036Z-d3b4b17f` 使用固定种子 21001。12 个代表场景全部完成，计时归因覆盖 483 个正式观察，观察管线记录 482 帧；运行、诊断和清理均通过。

| 场景 | 结果 |
|---|---|
| 连续小高差 | 四个方向 26–27 tick；每条路线一个 `WalkSegment` |
| 连续四级下降 | 四个方向均为 33 tick；每条路线一个 `WalkSegment` |
| 直接下落 1 格 | 16 tick；一个 `ControlledDropSegment` |
| 直接下落 2／3／5 格 | 53／55／58 tick；各一个 `ControlledDropSegment`；5 格实际伤害 2 点 |

2 格以上的直接下落中，有 36 个控制帧用于取得落点下部证据、从斜侧观察位移到下落中心线、减速、松开潜行和恢复视角。动作安全通过，但没有满足“持续前进参照加 3 tick”的性能门槛。后续优化必须缩短探边过程，同时保留下部可见、稳定入口和伤害额度检查；本阶段不通过放宽安全条件来追求旧用时。

本批次是代表性矩阵。全部速度带、授权形状和随机迟到重复次数仍未关闭。

### 7.1 每帧落点复查结果

后续批次 `20260928T003309781397Z-fadf7e24` 继续使用固定种子 21001。12/12 完成，运行、计时归因、观察管线、清理和源码冻结检查均通过。

探边拥有者每帧复查绑定落点后，2、3、5 格下落的取证阶段从 36 帧降为 27 帧，端到端用时从 53／55／58 tick 降为 44／46／50 tick。对应 `ControlledDrop` 从首条已验证前进输入到确认落地为 14／16／20 tick；同条件旧批次参照为 18／21／24 tick。动作执行满足原性能门槛，首次遇到未知落点的取证成本另行报告。

第一次加速复查时，落点空气进入世界知识的帧早于探边完成，会话曾提前接纳路线并以 `ordinary_ground_state_lost` 失败。新增回归检查后，空气更新只有在探边完成生命周期后才能授权下落；实体方块更新仍可立即使旧候选失效。

本结果没有关闭全部速度带、授权形状和随机迟到重复次数。
