# 动作接口加固与驱动器生命周期方案

日期：2026-10-07。状态：已实施并通过本轮 Windows 验收。原冻结范围保留，历史 M1 未通过结论不变。

## 1. 目标

本轮只完成两件事：

1. 让使用新控制器的动作也能通过动作接口接入，不再修改执行器；
2. 让导航驱动器只用枚举状态，并通过一个入口写状态。

终点接近、统一复核和统一异步作业不在本轮实施。

## 2. 不改变的行为

- 五组行为集合与 M1 索引逐项一致；
- 受控下降的证据、伤害、落地责任和 NEEDS_STATE 重锚不变；
- Session、执行监督者、规划协调器和输入出口的 owner 不变；
- 不增加线程、进程、生产双轨开关或动态插件；
- Windows 是正式门槛，Linux 只作补充复核。

## 3. H1：修正量尺

现有 v2 量尺统计动作类名，但没有统计通过封闭枚举选择实现的代理分支。

量尺 v3 分开报告：

- `direct_action_dispatch`：直接按动作类判断；
- `proxy_implementation_dispatch`：根据 `ControllerFamily` 或其他封闭分类选择控制器、入口参数或求解实现；
- `capability_checks`：例如 `BodyCommitment`，只判断通用事实，不属于动作类型分支；
- `unclassified`：无法自动分类的位置。

基线预计有三个 `ControllerFamily.AIR` 代理分支和一个 `MotionSolveKind.JUMP_GAP` 求解策略分支。H2 必须消除三个控制器代理分支；剩余求解策略分支本轮只登记，不增加。

## 4. H2：控制器适配器

移除 `ControllerFamily`。动作规格改为可选的不可变 `ActionControllerAdapter`：

- `create`：创建并启动控制器；
- `entry_limits`：给前一段提供入口位置和速度限制；
- `interpret`：把该控制器的结果转换为执行器已有的统一动作结果。

受控下降和跨隙复用 AIR 适配器。Walk、JumpUp 和 Step 的旧路径暂不迁移；它们没有适配器时继续走原路径。

执行器判断“是否提供适配器”，不再比较封闭的控制器族枚举。以后新增新控制器，只需由动作实现提供新的适配器。

测试探针必须使用一种新的测试控制器和新的结果类型。它不能继承受控下降控制器，也不能要求修改：

- `action_route_executor.py`；
- `navigation_session.py`；
- `execution_supervisor.py`；
- `planning_coordinator.py`。

## 5. H3：解除反向依赖

新增两个小型低层模块：

1. `action_requirements.py`：保存动作前提结果、采集规格、采集许可和公开的 acquisition ID 构造函数；
2. `landing_evidence.py`：保存直接下降视觉证据判断和相关常量。

`actions/controlled_drop.py` 不得在运行时导入：

- `route_admission`；
- `action_preconditions`；
- 任何私有名称。

`action_preconditions.py` 继续作为当前动作边界的无状态入口，并从低层模块导入契约。为保持现有调用方稳定，它可以重新导出这些公开类型，但不能再拥有它们。

`route_admission.py`、`navigation_owners.py` 和 `planning_coordinator.py` 统一从 `landing_evidence.py` 读取视觉证据判断。

## 6. H4：驱动器枚举和单写入者

新增 `RuntimeNavigationDriverState`，覆盖现有状态：

- READY
- RUNNING
- STOPPING
- SUCCESS
- FAILED
- CANCELLED
- STOPPED
- INTERACTION_REQUIRED
- INTERACTION_SUSPENDED

`RuntimeNavigationDriver` 的生命周期状态只允许由一个私有入口写入。构造时的初值除外；其他方法不得直接给状态字段赋值。

Session 报告到驱动器状态的映射使用枚举。控制失效、交互暂停、恢复、取消、成功和身体收尾都通过同一入口。

`reason` 继续只用于报告，不能决定状态转移。对外需要字符串时使用枚举的 `.value`。

## 7. fail fast 顺序

每个小提交只运行直接检查：

1. 量尺错误副本；
2. 动作契约、执行器和新控制器探针；
3. 下降、跨隙、入口接续和重锚；
4. 驱动器 I/O 故障、取消、交互和身体收尾。

所有直接检查稳定后，再运行：

- 完整运动导航正序、逆序；
- 五组集合一轮并与 M1 round2 比较；
- D058 和 D061 Windows 性能检查。

本轮不改变真实输入依据，不新增 Fabric 结论。

## 8. 完成门槛

| 项目 | 门槛 |
|---|---|
| 控制器代理分支 | 3 → 0 |
| 直接动作分支 | 不高于 M1 的 42 |
| 求解策略代理分支 | 不高于 1，并明确登记 |
| 未分类位置 | 0 |
| 新控制器探针 | 不修改执行器、Session、监督者和规划协调器即可接入 |
| 下降规格依赖 | 不导入接纳、Session、协调模块或私有帮助函数 |
| 驱动器字符串状态 | 流程判断和写入 36 → 0 |
| 驱动器写入者 | 构造初值之外只有一个私有写入入口 |
| 行为 | 五组集合逐项一致；完整正逆全绿 |
| 性能 | D058、D061 现行门槛通过 |

Session 行数、协调层占比和生产总行数只报告，不作为通过门槛。

## 9. 止损

出现下列情况就停止扩大修改：

- 新控制器仍需修改执行器分支；
- 为解除循环依赖建立超过两个新的低层职责模块；
- 枚举迁移需要新建第二套 Session 生命周期；
- 任何五组行为签名变化；
- 两次局部性能调整后仍未通过现行门槛。

本轮完成后停止。下一步是单独设计终点接近，不自动开始产品实现。

## 10. 本轮结果

首轮采集来源为 `4f3bf8a`；最终复审修复与行为来源为 `069b24a`。执行器代理分支 3→0，直接分支保持 42，求解策略保留 1，未分类为 0。量尺将登记校验与实现选择分开，支持改名、私有名、属性链与 match/case；首次量尺基线保留，更正结果另存。

旧 AIR 同帧停止还有一次具体控制器类型判断，本轮一并交给适配器的停止操作。保护声明与停止能力不一致、适配器类型错误都会在登记时拒绝。独立控制器探针覆盖入口接续、执行、完成、输入失联及同帧停止。

Driver 自身流程字符串按 AST 实测为 29→0，原方案 36 是预估；构造之外写入方法为一个。最终复审补齐近战、Fabric 动态 expected 和故障输出消费者；内部比较使用枚举，保存字符串时使用 `.value`。全仓静态与两个近战模块全绿。Session 仍为 4,994 行。

首轮 Windows 完整正逆各 1547/1547；最终修复后重新采集，各 1568/1568。五组一轮与 M1 round2 全部逐项一致，产品仍为 1,718/2,000。D058 和 D061 首轮使用默认正式参数独立运行并通过；本轮因测量路径无语义改动沿用原来源，边界与哈希单独记录。原始失败、候选诊断和性能明细均保留，证据与命令见[验收](../acceptance/action-spec-hardening-driver-lifecycle.md)。

本轮结束。下一步只设计终点接近；统一复核和统一异步作业仍按 D073 的实际需求条件启动。
