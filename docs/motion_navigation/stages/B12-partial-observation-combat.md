# B12：战斗证据、部分观察与战斗运动

日期：2026-09-26
状态：B12-A、B12-B 均已完成

## 1. 阶段目标

B12 在现有 C1 战斗纵切片上处理更复杂的信息和移动条件。它复用 Runtime、交战记忆、导航会话和唯一输入出口，不建立第二套目标、地图或身体控制。

## 2. B12-A：证据和重试语义

进入部分观察前先修两项基础语义：

1. 攻击门禁拒绝、攻击已执行但命中未确认、输入失败和确认超时分别计数；
2. 一次命中确认成功后，只清除属于该次攻击尝试的未确认状态，不保留跨整场战斗的混合失败计数；
3. 生命下降、死亡和受伤动画先表示“目标受伤”。只有证据能绑定本次攻击命令时，才表示“机器人命中”；
4. 着火、药水、环境伤害、队友攻击或来源不明时，不用生命下降单独授予交战许可；
5. 计数达到上限后返回有类型任务结果，不直接封存 Runtime。

首版不要求精确计算每一点伤害来源。证据不足时返回“目标受伤，来源未确认”即可。

已确认的实现边界见 [B12 攻击证据与重试 V1](../architecture/B12-attack-evidence-v1.md)，验收范围见 [B12-A 验收计划](../acceptance/B12A-attack-evidence-retry.md)。

B12-A 按以下顺序实施：

1. 建立独立的攻击尝试编号、阶段、证据和终态；
2. 收紧生命下降、死亡与命令关联命中的关系；
3. 将门禁拒绝、输入失败和确认超时拆成独立统计与重试额度；
4. 用有类型任务结果替代攻击失败原因字符串对流程的控制；
5. 完成离线重放和固定 Fabric 验收；
6. 通过后再开始 B12-B。

六项均已完成。当前实现按单次攻击保存命令、回执和观察证据，能够离线重放结果，并把门禁拒绝、输入失败和确认超时分别计数。

目标修订和提交后取消现在拥有独立原始事件。世界会话更换必须先结束旧会话中的攻击尝试，再替换 Runtime；不能让旧目标的攻击证据进入新会话。

正式验收清单冻结为 40 个正例和 24 个边界／反例，世界种子为 `21001`。当前源码已完成 40 个 Fabric 正例；5 类、10 次游戏事实反例由 Fabric 覆盖；7 类、14 次控制链反例由确定性 Runtime 注入覆盖。两类结果分开统计，详情见 B12-A 验收记录。B12-A 已关闭。

D030 只拆分证据来源，没有减少试次或放宽判定。依赖 Minecraft 实体和客户端门禁的反例走 Fabric；仲裁、输入、会话和额度故障走确定性 Runtime 注入。

## 3. B12-B：部分观察和战斗运动

在 B12-A 通过后增加：

- 目标暂时离开视野、被遮挡或观察字段暂缺时，按交战记忆和信息有效期决定继续、重新观察或结束；
- 导航负责身体期望速度与安全路线，战斗负责目标视角和攻击时机；
- 前进、横移和后撤都可以在已验证条件内与战斗视角同时执行；
- 视角与动作条件不兼容时，明确减速、停步或拒绝组合，不能静默丢掉移动；
- 世界会话、目标身份、死亡、卸载和任务修订继续立即使旧授权失效。

首版边界见 [B12-B 部分观察与战斗移动 V1](../architecture/B12B-partial-observation-combat-motion-v1.md)，验收范围见 [B12-B 验收计划](../acceptance/B12B-partial-observation-combat-motion.md)，实施顺序见 [B12-B 实施计划](B12B-implementation-plan.md)。

B12-B 已完成组件、Fabric 和跨阶段回归。24 个四方向移动攻击正例、6 个游戏事实边界和 6 个确定性运行时注入全部通过。B10 的静止、转向、带速和默认协调跨隙批次也通过，证明普通地面许可没有扩展到空中动作。
