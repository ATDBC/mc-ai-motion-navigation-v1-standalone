# D111 B10 GC 归因与证据缓冲修正计划

日期：2026-10-15。决定见 [D111](../decisions/0111-remove-b10-observer-gc-distortion.md)。

当前状态：**FAILED／STOPPED**。D111-1 至 D111-4 已完成授权范围；唯一一次正式 B10 的 raw wall 最大值为 39.9605 ms，未过 `< 30 ms`。不再修正或重跑。

## 1. 目标

本阶段只修测试和测量装置，去掉 B10 探针自己长期保留对象树造成的 GC 扰动，并补充可以在 Windows 上使用的停顿区间证据。

## 2. 实施顺序

### D111-1：测试时序与历史证据

修改：

- `tests/motion_nav/test_d107_shard_runner.py`：由信号处理父进程写新子进程 PID；
- `tests/motion_nav/test_d102_action_handoff.py`：最多等待五个 receiver 周期，出现 `PreparedMotionJob` 后立即结束；
- `evidence/motion_navigation/d110-evidence-lifecycle-v1/published-production-semantic-hashes.json`：记录 `67f4f1d8` 的历史语义哈希；
- 对应公开完整性与导出清单。

门槛：两项测试原断言不放宽；Linux 专属结论仍以 Linux 运行结果为准。语义哈希可从 Git 对象独立重算。

### D111-2：字符串证据缓冲

修改 `scripts/b10_gap_solver_runtime.py` 和 `tests/test_b10_runtime_probe.py`：

- 缓冲内部保存 `strict_json_dumps()` 生成的字符串；
- `rows()` 和最终 flush 在控制试次结束后解析；
- 诊断本地列表也保存字符串；
- 增加输出字节、快照隔离、容量、溢出和 flush 失败回归。

门槛：旧实现和新实现写出的正常 JSONL 逐字节一致；试次、摘要和检查结果不变。

### D111-3：全程 GC 停顿区间

修改同一脚本和测试：

- 求解记录增加单调时钟开始、结束时刻；
- 专用回调记录完整 GC 区间；
- 所有求解结束后计算逐代重叠次数、重叠纳秒和扣除停顿后的诊断值；
- 现有 `solve_gc_collections_delta` 与线程 CPU 字段继续保留；
- 原始 `solve_time_ns.maximum < 30_000_000` 判定保持原样。

故障注入必须覆盖：其他线程触发 GC、结束回调晚于一次求解返回、未配对回调、测量代码异常、已有第三方 callback。

### D111-4：回归和唯一一次 B10

顺序：

1. Windows 直接与相邻检查；
2. 源树完整正序、逆序；
3. 独立公开快照正序、逆序、Java 和 `verify`；
4. 以上全部通过后，只运行一次 600 秒 B10；
5. 报告原始墙钟、GC 重叠停顿和扣除停顿后的诊断分布。

## 3. 判定

- 原始墙钟最大值 `< 30 ms`：D110-SOLVE-01 可以关闭；
- 原始墙钟仍超限：D111 停止，不因扣除 GC 后通过而改写结果；
- 功能、安全、来源、trace 或时间归因任一退步：立即停止；
- B10 后不修改门槛，也不为取得绿色结果再次运行。
