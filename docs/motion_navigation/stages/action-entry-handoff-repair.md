# 动作入口交接修复

日期：2026-10-09。状态：H0—H3 已完成。依据 [D092](../decisions/0092-revalidate-r2-and-repair-entry-handoff-within-existing-owners.md)。

## 交付行为

机器人先走一段、转弯后再上一格时，前段能主动满足下一入口的朝向。接近期间作废一个旧预计入口，不取消仍有效的地面路线。严格动作保持原证明、输入窗口和身体责任。

这次只补共同交接职责。完成后再评估更广的连续运动方案，不扩大求解域、速度域或运动方式。

## 批次 H0：固定 RED 和接口职责

从三方 `8ea820e` 提取复现输入，在 Windows 正式 Runtime → Driver → Session → Executor → Coordinator 链上复跑。冻结直线错朝向、转弯、短助跑、柱顶和负例清单，记录真实入口朝向、视角仲裁、活动作业和本地失败账本。测试不能按私有原因文案判断正确性。

允许改动：本阶段的场景、记录器与测试；更新 [动作衔接架构](../architecture/action-continuity-v1.md)的入口职责。此批不改生产行为。

## 批次 H1：当前执行器满足下一入口朝向

主要改动在 `action_route_executor.py`，必要时调整 `fixed_route.py` 对同一入口的读取。沿用现有 `ActionRouteDecision.look` 和 `movement_yaw_radians`。

- 下一入口没有 required yaw 时，行为保持原样。
- 下一入口有 required yaw 时，在前段最后约一格或已有入口接近区提出有界视角请求。位置条件直接读取路线与入口窗口，不按动作类型或场景判断。
- 视角与地面输入必须使用同一份朝向。已有正式链不能保证这一点时，先补该链的最小连接检查，不能假设发出 look 就已转头。
- 真实身体尚未满足 required yaw 时，不启动下一动作。视角失选后，当前路线仍负责安全接近或停止；沿用原准备／等待上限，不能另开等待计数。
- 保留配置中的原角度公差。JumpUp 的冻结公差仍为 2°。

不修改 Session 或规划器的状态、字段、作业类型。若正式链需要新增协调状态才能完成，停止并报告设计缺口。

## 批次 H2：旧预计入口作废，不计真实失败

主要改动在 `motion_coordination.py`，必要时只扩充已有 preparation 结果表达。

把“否定依据已变化”与“当前入口真实不可用”区分开。只有下一动作尚未开始、结果依据确已过期时，按 supersede 退场旧工作，不调用本地失败购买入口。现有 `_negative_basis_changed` 已产生事实判断，后续不再比较 reason 字符串。

在当前观察上重新核对必要条件得出的真实否定结果，不自动获得免计费资格。身体已进入入口后的真实求解失败，继续最多三次。只允许一个活动作业；所有工作按现有身份完成或取消。前段无进展时沿用原停滞和等待终态，不能每帧无限重求解。

## 批次 H3：签署交接行为

先跑少量代表场景：一个错朝向直线、一个 90° 转弯、一个短助跑、一个柱顶，以及三个负例。它们稳定后只扩本次冻结矩阵。

签署时运行完整正序／逆序、v7、F2 528、v8，以及 [验收清单](../acceptance/action-entry-handoff-repair.md)。旧成功退步为 0，所有严格输入都有负责人，工作和等待都有上界。生产耗时继续遵守 D058／D061；朝向准备只做常数次角度计算，完整运动求解仍在 worker。

Fabric 抽查四个方向的转弯后 JumpUp。每方向 normal、首条 late1 各一项，共八项；保留真实应用 tick、起跳前 yaw、落地和来源注销。若缺 Fabric 环境，只能签署组件修复，不能写成阶段完成。

每个生产批次使用一个实施子 agent，主 agent 复核边界和证据。每批最多两轮限定修正；新能力、清单外体验或性能余量不足登记到台账，不能顺手扩批。

## 实际交付

H0 在 `dfb74f9d` 的原代码副本上冻结了 80 项正式链正例：直线错朝向 8 项、90° 转弯 24 项、1／2／3 格短助跑 24 项、原 v9 柱顶 24 项。结果为 0／80，80 项都没有进入 JumpUp。旧结果保存在 `evidence/motion_navigation/action-entry-handoff-v1/h0-red/`，没有回写。

H1 只修改 `ActionRouteExecutor`。当前段为 Walk、下一段公开 `SegmentEntryWindow.required_yaw_radians`、身体进入原有前视距离后，执行器提出视角。地面按同一帧最终视角计算输入。本轮新增的朝向准备分支不检查下一动作类型；下一段没有入口视角时不改变原行为。执行器中原有的入口速度、位置等动作差异仍按既有职责处理。战斗或安全视角已胜出时，Walk 直接按该视角计算，本次路线不伪装成已经完成转头，严格动作仍等真实观察满足原公差。

H2 只修改 `MotionRouteCoordinator`。下一动作尚未开始、旧求解依据已经变化时，有类型的 `negative_stale` 结果只退场原工作，不增加真实失败次数。当前观察重新核对出的否定结果会清除这项资格，继续使用原三次上限。活动工作仍由原生命周期维护，没有增加 Session 字段、等待或作业类型。

H3 的 Windows 正例为 80／80。80 次起跳都有入口视角记录，最大误差为 0°；零伤害、零安全事件、零来源泄漏。v7、F2 528、v8 固定和 v8 杂乱的旧成功退步均为 0。Fabric 四方向 normal／首条严格输入晚一 tick 共 8／8；四次晚到都在证明允许的第二个 tick 实际生效，入口误差均为 0°，期限错过、伤害和违规均为 0。

本轮没有修改 Session、规划器、入口公差、求解域、速度域或动作证明。协调 smoke 中一个既有目标修订事件因提前转头由 tick 62 移到 tick 63；任务结果和安全事实不变，冻结清单已明确更新这个预期时刻。
