# B04：已知图规划与后台隔离

日期：2026-09-19
状态：已验收

## 要解决的问题

B03 已经证明控制器能够执行外部给定的普通地面路线。B04 要补上路线来源，并保证路线计算变慢或失败时不会卡住逐帧控制。

本阶段只处理完整已知范围。机器人从统一世界知识中建立普通地面 Walk 图，后台 A* 产生候选路线，控制线程核对候选身份和当前身体接入条件，再把接纳后的路线交给 B03 控制器。

## 本阶段范围

1. 用 B02 的支撑、净空和连续扫掠查询生成四邻接 Walk 图。端点可站但中间不可通过时不能建边。
2. 定义不可变的规划请求和候选结果。结果保留请求、目标、世界会话、规划起点、地图依赖和计算状态。
3. 首版 A* 只使用非负步行时间代价。用独立 Dijkstra 校验可达性和最短代价。
4. 规划运行在独立后台进程。控制线程提交请求和读取结果都必须有界、非阻塞；排队请求和结果只保留最新项。
5. 路线接纳单独检查目标版本、世界会话、变化依赖和当前身体能否接入。后台结果不能直接写输入。
6. 接纳路线拥有稳定身份、独立进度和有限可执行走廊。身体沿路线移动不能改变路线身份。
7. 已有安全前段足够时，后台阻塞 500 ms、返回旧结果或退出不能让控制循环无谓停车。
8. 正式实机仍只使用独立 Fabric，并复用 B03 动作仲裁、输入租约和固定路线控制器。

## 明确不做

- 不把未知区域当作可走，也不设置探索检查点或观察点；
- 不实现局部动态绕行、实体预测和路线机会评分；
- 不加入跳跃、冲刺、潜行、跨高度动作和多材质动力学；
- 不在首版引入 D* Lite、LPA*、共享内存或通用插件系统；
- 不因远处任意地图刷新就废弃当前安全走廊，也不为保留走廊而忽略其自身依赖变化。

## 实施顺序

1. 固定 Walk 节点、边、规划请求和候选结果的数据契约。
2. 实现已知图构建、A* 和独立 Dijkstra，对随机有限图交叉验证。
3. 实现后台进程、最新请求／结果槽及关闭、崩溃、迟到结果处理。
4. 实现路线接纳、稳定路线身份和短走廊，再接入 B03 固定路线控制器。
5. 完成确定性闭环、500 ms 阻塞注入和 Fabric 已知地图实测。

## 完成条件

1. 至少 1,000 个有限随机图中，A* 与独立 Dijkstra 的可达性一致，路径代价误差不超过 `1e-6 × max(1, reference_cost)`。
2. 已知墙、坑和悬浮结构不会产生非法 Walk 节点或边；未知导致明确的 `NO_KNOWN_ROUTE`，完整已知范围无路才允许报告 `NO_ROUTE_WITHIN_COMPLETE_SCOPE`。
3. 旧目标、旧世界和受相关变化影响的候选均不能接管当前路线。
4. 路线身份不随身体前进改变；短走廊变化只影响相交的执行承诺。
5. 后台阻塞 500 ms 时，至少两秒的已验证安全前段继续由 B03 控制，不新增中途零输入。
6. 后台崩溃、结果队列积压和迟到结果不会越过动作仲裁，也不会阻塞控制线程。
7. 完整已知的空地、墙、坑和悬浮结构 Fabric 场景按验收文档通过。

以上条件已经满足。控制侧按固定格数分批复制规划范围；若复制期间几何发生变化，整份快照作废并重新开始。最后一批不再整份复制已收集事实。后台进程在脱离实时世界所有者的快照上按需生成节点和边，再运行 A*。它不再要求控制线程先同步构造整张 Walk 图。

独立审查发现并关闭了结果槽竞争、快照末批重复制、未支持几何误报确定无路、运行入口未传递地图变化，以及接入检查与执行路线不一致五个问题。对应反例已进入正式测试。

10,000 个可站立节点的开放地图基准运行 20 次，首条路线 P95 为 49.676 ms，快照单批最大耗时为 1.987 ms。真实 Fabric 中，首次进程冷启动加规划为 319.508 ms，后续三次为 5.736～6.101 ms。空地、高墙、悬浮墙和坑四个场景全部到达并停稳。详细证据见对应验收文档。

B05 可以开始，但尚未实施。B05 只加入一个经校准的最小跨高度动作，不在同一阶段加入探索、动态实体绕行或完整跑酷。
