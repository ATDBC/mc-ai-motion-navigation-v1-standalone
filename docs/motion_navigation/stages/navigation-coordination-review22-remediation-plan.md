# 导航协调第二十二轮整改方案

日期：2026-09-30

状态：已完成。连续高度 M3 保持关闭；导航协调 S5 已重新关闭。

## 1. 要解决的问题

第二十二轮评审确认了三个 P1。它们都发生在旧动作尚未完全结束、新目标或新路线准备接管身体的时候：

1. 丢失一次输入回执后再改目标，旧输入长期处于“是否执行过无法确认”的状态，新路线永久等待交接；
2. 停止收尾期间，普通规划分支仍可能直接请求 `BEGIN_PLANNING`，触发非法状态转换；
3. 探边被目标修订打断时，取证等待没有结束。频繁改目标会填满等待账本。

三个问题共享同一个原因：导航知道任务状态和身体控制者，但没有统一管理动作留下的输入责任、等待记录和停止后的去向。各业务分支仍能分别开始规划、打开等待或判断输入责任。

本轮不增加移动能力，也不重写整个导航会话。目标是补齐三条共享规则，并把“改目标、停止、交接、重新规划”从会话的普通业务分支中收拢到一个所有者。

## 2. 范围与边界

本轮包括：

- 为历史输入歧义增加有界的交接判定；
- 让等待记录绑定创建它的动作，并随动作统一结束；
- 建立停止后的单一交接入口；
- 静态检查所有状态转换调用点和固定容量账本；
- 修正随机事件生成器，并把协调门槛扩大到至少 1000 个序列；
- 更新阶段、架构、验收、决定和缺陷台账。

本轮不包括：

- 扩展外力恢复能力；
- 改写规划算法、连续高度控制或动作求解器；
- 把整个 `NavigationSession` 一次拆完；
- 因本轮整改重新解释已经完成的 800 场连续高度证据。

## 3. 输入责任必须有出口

### 3.1 保留事实，不伪造结论

回执缺失时，输入记录继续保留 `AMBIGUOUS`。系统不能为了交接方便，把它改写成“已执行”或“未执行”。

交接判断改为返回有类型的评估结果。它至少区分：

- `IN_FLIGHT`：输入仍可能处于允许生效的窗口内；
- `AMBIGUOUS_WAITING`：窗口已过，但还没有足够新的身体状态支持安全收尾；
- `TRANSFERABLE_FROM_CURRENT_ANCHOR`：历史是否执行仍未知，但当前身体锚点已经晚于可能生效的最后一帧，当前控制者也证明可以从此状态安全释放；
- `UNRESOLVED_TIMEOUT`：在限定期限内仍不能形成可转移证据。

输入账本只保存观测事实。身体控制者根据当前动作、身体状态和责任评估决定是否可以释放。两者不能互相改写。

### 3.2 有界规则

历史歧义不再依赖“必须先有一条后续已确认命令”才能解除阻塞。满足以下条件时，可以从当前身体锚点继续收尾：

1. 锚点和输入记录属于同一个世界会话；
2. 锚点晚于该输入可能生效的最后一个运动 tick；
3. 没有更新的在途输入；
4. 当前身体控制者证明释放后的短期运动安全；
5. 交接证据绑定当前观察、当前控制者和当前世界会话。

若条件一直不成立，旧控制者在自己的收尾期限内继续负责身体。期限用尽后返回 `input_responsibility_unresolved`。任务可以失败或交给上层决定，但不能永久等待，也不能释放空中身体。

## 4. 动作拥有自己创建的等待

### 4.1 等待归属

每条等待记录增加稳定的 `owner_id`。`owner_id` 对应真实生命周期，例如：

```text
route/route-17/revision-4
probe/route-17/revision-4/action-3/acquisition-2
recovery/navigation-session-8
```

等待名称只描述用途，例如 `landing-evidence`、`information`、`safe-release`。用途不能代替所有者。

### 4.2 统一结束

账本提供“结束某个所有者的全部等待”。动作在以下任一情况发生时，都走同一个退场入口：

- 正常完成；
- 被新目标替换；
- 被取消；
- 超时；
- 明确失败；
- 会话关闭。

退场入口结束动作拥有的等待，并拒绝该动作之后到达的旧结果。各业务分支不再分别记住要调用哪个 `end_wait()`。

本轮同时静态检查风险记录、重试尝试和输入提交序列。每类固定容量记录都必须写明创建者、结束条件和满载行为。没有所有者的长期记录不能进入正式路径。

## 5. 停止后的去向只有一个入口

新增 `navigation_handoff.py`。该模块只负责目标修订与身体交接，不负责规划路线或执行移动。

它长期拥有：

- 当前待提交目标修订；
- 当前停止请求及其原因；
- 旧身体控制者身份；
- 交接期限；
- 已形成的交接证据；
- 停止后的目标状态：规划、等信息、失败、完成或取消。

流程固定为：

```text
保存完整的新目标修订
→ 请求旧控制者停止
→ 旧控制者继续负责身体
→ 清理旧动作拥有的等待和承诺
→ 形成当前帧交接证据
→ 原子提交新目标
→ 进入规划、等信息或终态
```

`NavigationSession._advance_planning()` 只推进已经进入 `PLANNING` 的请求。它不能决定如何离开 `STOPPING`。

普通代码不能在 `STOPPING` 中调用 `BEGIN_PLANNING` 或 `BEGIN_EXECUTION`。从 `STOPPING` 离开只能使用：

- `REPLAN_AFTER_HANDOFF`；
- `RESUME_EXECUTION_AFTER_HANDOFF`；
- 有类型的终态转换。

前两项必须携带当前帧的交接证据。

## 6. 测试与随机门槛

### 6.1 先冻结三个失败族

生产代码修改前，加入当前版本会失败的正式路径测试：

- 丢回执后 1 至 10 帧改目标或取消，覆盖两格下落、两级台地和 L 形走道；
- 所有可能在 `STOPPING` 状态触发规划的入口；
- 探边完成、替换、取消、失败和关闭后，等待账本均没有遗留该动作的记录。

### 6.2 修正生成器

随机事件生成器改为：

- 同类事件可以重复出现；
- 任务到达终态且身体控制权释放后停止派发事件；
- 根据当前场景和路线选择真实的落点支撑，不使用固定坐标；
- 覆盖两格下落、五格下落、L 形走道和两级台地；
- 保存种子、完整序列、最短反例和触发的不变量；
- 新的最短反例自动进入固定回归清单。

### 6.3 关闭条件

导航协调 S5 重新关闭前，必须同时满足：

1. 第二十二轮三个复现脚本全部通过；
2. 至少 1000 个固定随机序列没有不变量违规和永久等待；
3. 终态后没有活动等待、在途动作所有权或未处置的输入责任；
4. 所有输入歧义在期限内形成安全交接或有类型失败；
5. `STOPPING` 只能通过带交接证据的入口进入规划或执行；
6. 固定 14 场、冻结 200 种子和 192 个中断组合不退化；
7. 完整 `tests/motion_nav` 通过；
8. 连续高度 M3 的既有结论保持不变。

1000 个序列是本轮的最低门槛，不代表已经穷举所有事件组合。若运行中发现新反例，先缩减并加入固定清单，再重新运行完整门槛。

## 7. 实施顺序

1. 把三个 P1 和生成器缺陷写成失败测试；
2. 实现有界的输入责任评估；
3. 为等待记录增加动作所有权和统一退场；
4. 引入单一交接模块，清理 `STOPPING` 的普通规划和执行入口；
5. 对全部转换调用点和固定容量账本做静态清单；
6. 修正生成器并运行至少 1000 个序列；
7. 运行固定矩阵、种子扫描、中断矩阵和完整运动导航测试；
8. 更新四类文档，只有全部门槛通过后才重新关闭协调 S5。

每一步先运行失败检查，再实施最小修正。若同一共享规则连续三次仍产生同类缺陷，停止增加分支，重新检查所有权边界。

## 8. 完成结果

本轮按上述顺序实施，没有新增移动能力：

- 输入责任改为有类型评估。历史 `AMBIGUOUS` 事实不被改写；更新锚点越过可能生效窗口后，控制者仍要同时检查当前身体速度和预测尾段，才可交权。
- 等待记录带稳定 `owner_id`。动作完成、替换、取消、失败、超时或关闭时，统一结束该所有者的等待。
- `NavigationHandoffCoordinator` 统一保存待提交目标和停止后的去向。普通规划分支不能从 `STOPPING` 直接开始规划或执行。
- 随机门禁采用有放回抽样，覆盖四类场景与重复事件。外力只在导航仍有身体控制者时注入；更强的击退与受击恢复继续由 C1 的正式门槛验证。

最终本地证据：

| 检查 | 结果 |
|---|---|
| 固定 14 场 | 13 个任务成功、1 个有界安全失败、0 个意外 |
| 冻结 200 种子 | 198 个任务成功、2 个有界安全失败、0 个意外 |
| 中断与晚到矩阵 | 192/192 到达终态 |
| 固定随机事件序列 | 1000/1000 落在允许结果内；0 个不变量违规、永久等待和公开接口异常 |
| `tests/motion_nav` | 755/755 |
| 分段证据与 Java 门禁 | 15 项通过、1 项仅适用于 Windows 的符号链接检查跳过 |
| 公开真实证据 | 10 个归档、20,191,147 字节，通过 |

1000 个随机序列中，289 个任务成功，512 个有界失败，199 个有界取消。所有结果都保留在分母中。门禁额外发现并修正两类共享缺陷：当前身体仍在移动时不能只凭预测尾段释放；替换规划失败时，旧安全前段不能无限继续执行。

本轮没有新增 Fabric 批次。连续高度 M3 的既有实机结论没有被重新解释。
