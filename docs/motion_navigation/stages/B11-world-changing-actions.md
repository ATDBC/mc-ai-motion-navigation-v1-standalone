# B11：放置方块与有限搭桥

日期：2026-09-25
状态：冻结能力与复审整改均已通过

## 目标

在已知地形、明确授权和已有普通方块的条件下，让机器人通过原版交互放置方块，并在正式观察确认后继续规划。阶段性成果是：一条纯移动路线被一至三格已知缺口截断时，机器人能到达安全工作站位，逐块搭出道路，再走到目标。

## 冻结范围

- Minecraft Java 1.21、独立 Fabric；
- 生存模式；
- 主手预先放有 `minecraft:dirt`；
- 放置结果为普通完整 `minecraft:dirt` 方块；
- 全部支撑、目标空气和行走空间已知；
- 每次只放一块，连续最多三块；
- 不主动挖掘，不打开容器，不整理背包；
- 不做边走边放、跳搭、脚下搭柱或斜向速搭；
- 不接未知区域探索。

## 实施顺序

### B11-A：单方块事务

1. 固定放置请求、状态、失败类型和确认规则；
2. 复用 `InteractBlockV1` 和原版使用入口；
3. 提交前核对目标、物品和身体；
4. 根据新观察确认目标方块和库存变化；
5. 加入取消、超时、错误准星、错误物品和错误结果测试。

完成条件：不依赖导航，在固定安全站位能稳定完成一块放置；所有反例都不会误报成功或重复点击。

### B11-B：路线交互

1. 增加 `RequiredInteraction` 规划结果；
2. 先执行到工作站位的移动段；
3. 停稳后通过同一个 Runtime 输入出口把控制权交给放置事务；
4. 确认世界变化后，从真实状态重新规划；
5. 目标、依赖或会话变化时让旧要求失效。

完成条件：一格缺口场景可以自动走近、放置并继续到目标；未授权时仍明确无路。

### B11-C：有限搭桥

1. 将相同事务有界重复到最多三块；
2. 每块确认后才生成下一块；
3. 保存每次前置观察、操作回执、结果观察和路线修订；
4. 验证中途取消、失联、物品不足和世界变化。

完成条件：冻结的一至三格桥场景和全部反例通过，且已有 B03–C1 范围不退化。

## 完成结果

- 单方块事务、路线交互和最多三块的逐块搭桥已经接入正式 `Runtime`、仲裁器和 Fabric 原版使用入口；
- 工作站位位于被点击方块侧面以外，并保持潜行。这样既不会让身体覆盖目标格，也不会在边缘等待时掉落；
- 只有较晚的正式观察同时确认目标方块和生存库存减少，事务才完成；
- 60 个正例全部通过，共确认 90 次真实放置；20 个冻结反例全部得到预期结果；
- 首轮运动导航组件检查为 436／436，B11 与探针专项检查为 26／26；复审整改后，最新全套运动导航检查为 442／442，控制、战斗、B10／B11 探针与公开证据相关检查为 225／225，纯 Java 门禁为 2／2；
- 首轮跨阶段回归中，C1 移动近战通过；B10 跨隙与 C1 外力恢复暴露了既有时序边界。失败证据已保留，两者都没有进入 B11 交互路径，也没有出现放置驱动器抢占输入；
- 复审后修正了 B10 重复写图和后台进程启动时序、任务级搭桥额度、放置期间目标修订、准备期限，以及受击缺世界格时的来源归因；
- B10 完整复跑 `20260925T103445684561Z-9a2d62d9` 通过全部 150 个动作样本和 10 个协调试次；B11 完整复跑 `20260925T104441670754Z-64a4005e` 再次通过 60／60 正例和 20／20 反例。

## 不变量

- 只有 Runtime 的唯一输入出口可以操作玩家。
- 规划器不写 `WorldKnowledge`。
- 发送交互不等于放置成功。
- 未确认的方块不能成为支撑或路线节点。
- 取消不能让空中动作失去落地责任；本阶段地面放置不会接管已在执行的空中动作。
- 重试、候选数和连续放置数都有代码上限。
