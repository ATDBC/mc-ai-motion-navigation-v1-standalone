# 动作入口随机迟到小批次

日期：2026-10-09。状态：两轮限定修正完成；组件、正式模拟链和 Windows 完整检查通过。新增 Fabric 门槛未关闭，不作整体签署。依据 [D093](../decisions/0093-brake-within-entry-and-preserve-input-loss-cause.md)。

## 范围和顺序

1. 冻结 Windows RED、输入清单和固定种子。
2. 身体已处于下一入口接受的位置、姿态、朝向和支撑范围时，判断停下来是否能满足入口。可以时使用既有刹车，不再左右修正本来合格的偏差。
3. 末次严格动作失联后安全落地，却没有到达目标时，保留输入失联原因。
4. 先检查组件、八种子和关键 tick，再跑每族一百种子。外角两种初始朝向、转弯上跳和转弯下落是 H-01 完成正例；落点目标保留未完成结果，报告真实原因。
5. 定向稳定后运行 v7、F2 528、v8、v9、D058／D061和完整 Windows 正逆。最后抽查四方向 Fabric。

所有结果保存在 `evidence/motion_navigation/action-entry-late-hardening-v1/`。原 D092 的正常／首条晚一 tick 结论保持原范围。本批不补走安全落地后的最后半格，后续连续轨迹方案必须显式覆盖；原型止损后再回主线处理。

## 两轮上限

第一轮只修 H-01 与 H-02 分类。第二轮只处理这两处修正的直接回归。需要新状态所有者、求解方法或清单外能力时停止报告。八种子不能证明所有随机时序均能完成；一百种子完整报告成功、输入失联和真实求解失败，不能把安全有界失败算成功。

## 本批结果与停止点

H-01 四族八种子各 8／8，入口到实际离地的 41 次单次晚到均完成；四族各一百种子为 100、100、99、100 次完成，唯一未完成保持原求解失败。H-02 用已有 StopCause 透传因果、保持 FAILED 执行终态；16 个落点任务相对仅 H-01 的身体轨迹和窗口不变。v7、F2、v8、v9 旧成功退步为 0，Windows 正逆各 1681／1681。性能整体门槛通过，修订帧 8 ms 债务保留原始 false。

四方向 Fabric 的真实任务 4／4 完成，但只有南、西真正注入入口附近晚到。两条普通 Walk 晚到均超出现行精确授权窗口，原始门槛失败；东、北没有触发过窄的夹具条件。所有起跳速度为 0、yaw 误差 0°，零伤害、额外／严格窗口外和来源泄漏。未把失败改成通过，新增 Fabric 仍未签署。具体结果见[验收](../acceptance/action-entry-late-hardening.md)。

后续只保留三个明确输入：末次严格动作短落后如何接上目标；普通可恢复 Walk 的时序授权如何表达；入口晚到夹具怎样保证四方向都真正覆盖。它们不自动授权第三轮修正、轨迹原型或新阶段。
