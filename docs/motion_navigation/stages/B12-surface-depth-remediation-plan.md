# 表面深度合法空气与感知成本整改计划

> **执行要求：** 实施时使用 `superpowers:executing-plans` 逐项推进。除非用户再次明确授权，不使用子 agent。每个任务先补失败检查，再修改实现，并在任务通过后单独提交。

日期：2026-09-26

状态：已完成。任务 0—3、5、6 以及 B10—B12 的 profile 4 重验均已完成；任务 4 未达到启动条件，按计划保留现有保守重读。实现、文档、门禁和一份当前 profile 4 代表证据已经同步到公开独立仓库。

**目标：** 在 profile 4 表面深度主线上修复地下容量、遮挡分类、实体可见性和越权空气查询，同时量清观察成本，恢复 B10—B12 的当前视觉配置验收。

**做法：** 方块视觉、视觉空气和实体可见性共用一份表面投影与遮挡规则。先修会导致会话失败或产生非法事实的问题，再做不改变协议的性能优化；只有实测仍超预算，才引入增量传输。跨帧空气累积暂不实施。

**技术范围：** Minecraft 1.21、Fabric Loader 0.15.11、Fabric API 0.100.6+1.21、OpenJDK 21、Python 3.11、现有 C++17 表面深度核心和 Clipper2。

**依据：** [D004](../decisions/0004-lazy-positive-air-confirmation.md)、[D035](../decisions/0035-formal-surface-depth-only.md)、[当前架构](../architecture/mc_motion_navigation_architecture_v1.md)。

## 一、固定语义

本轮先固定下面六条，不在实现中临时改变：

1. 正式方块视觉只使用 profile 4，不恢复 profile 3，也不增加射线回退。
2. 空气请求返回“视觉上完整为空”的正例。它可以与屏障、光源方块等隐藏状态不同。
3. 单帧确认要求目标整格完全处于 120° 视野和 16 格范围内，整格投影没有被更近的不透明表面遮挡，并且本帧没有报告该格存在可见方块。
4. 身体接触和当前交互事实优先于视觉空气。同一帧发现实际方块时不得再输出空气正例；后来取得的新事实覆盖旧空气记忆。
5. 单帧只看见一部分时保持未知。本轮不合并不同时间的八分块。
6. “没有返回空气”只表示没有取得正例，不能据此推断这里存在方块。

## 三、审查重点

- 隐形但有碰撞的方块：远处可形成视觉空气；身体接触后必须立即成为实际方块事实。
- 动态世界变化：放置、挖除、活塞、区块加载和世界切换后，表面缓存不得继续输出旧几何。
- 非完整形状：楼梯、半砖、门、栅栏和含水形状不能因为只测中心点而误判整格为空。
- 材质规则：玻璃可透视；铁栏杆只允许从几何空隙看穿；浮冰、蓝冰和熔岩遮挡后方。
- 控制时限：复杂自然地形不能让观察和写入挤占 B10 的严格动作生效窗口。

**实施前隔离基准：** 使用当前 Release 原生库，在 4 格分区、17 格存储半径、16 格查询半径的实心岩层 1×2 隧道中，对两种策略分别运行 50 次缓存更新和 2,000 帧八方向／三俯仰角表面计算。两种策略得到的平均可见方块数相同。

| 指标 | 存储边缘全部保留 | 多读一格辅助邻居 | 差异 |
|---|---:|---:|---:|
| 打包方块 | 6,392 | 240 | 减少 96.2% |
| 16 格查询候选 | 198 | 198 | 相同 |
| 原生输入约占字节 | 594,456 | 22,320 | 减少 96.2% |
| `cache_update` P50 | 42.42 ms | 1.22 ms | 辅助邻居约快 34.6 倍 |
| 单帧 P50 | 0.421 ms | 0.353 ms | 辅助邻居约快 19% |
| 单帧 P95 | 0.729 ms | 0.658 ms | 辅助邻居约快 11% |

辅助邻居在完整刷新时需要额外读取 6,585 个格子。只比较原生更新时间，平均每个额外读取低于约 6.26 微秒时，辅助邻居就已经更快；实际实现还会减少 Java 缓冲区写入，因此这个临界值偏保守。正式选择还要由任务 0 在真实 Fabric 客户端测量额外读取耗时，不能用 Python 合成世界代替游戏内结论。

### 任务 2：冻结遮挡规则并统一实体判定

- 新增 `SurfaceVisibilityRules.java`

**规则：**

- 铁栏杆、栅栏、门、活板门按实际外形遮挡，空隙仍可看穿，不能因为属于 cutout 层就整体透明。

- 含水方块的实体部分按方块外形处理，水部分按水处理。
- 树叶按固定遮挡策略处理；未登记状态默认遮挡。
- `BlockRenderType.INVISIBLE` 不进入表面方块集合，也不遮挡；身体接触仍可发现其实际碰撞。

**固定场景：** 正前方空气确认；墙后、熔岩后、身后和部分可见格保持未知；玻璃后确认；屏障远处确认视觉空气，接触后改为实际方块；方块被挖除后更新为空。

**通过条件：** 128 格探测的原生计算 P95 目标不超过 1.5 ms；最终门槛以 Windows Fabric 中包含 JNI 和 Java 整理的实测为准。当前协议范围固定为 16 格。

### 任务 5：降低传输和重复写入成本

**第一步不改协议：**

- [x] `DeploymentObservationProbe` 不再把已经生成的观察 JSON 解析成树后重新序列化，改为安全地嵌入原始观察字节。
- [x] `NavigationObservationAdapter` 遇到内容相同的方块时跳过碰撞几何重建，但仍更新本帧可见集合、最后观察时间、来源和世界会话。
- [x] 用任务 0 的相同场景重测。

2026-09-27 的重测中，七场导航写入 P95 比任务 0 下降 33%～73%。实际可见方块 P95 最高为 644，没有达到 800 格的增量协议触发线。随后两个 B10 批次完成 300／300 个正例，40 个严格窗口命令帧没有晚到；控制往返 P95 分别为 48.786 ms 和 48.697 ms。第二个触发条件也未达到，因此不设计增量协议。

**只有满足任一条件时才设计增量协议：** 自然地形可见方块 P95 超过 800，或者完成上述两项后端到端控制往返 P95 仍不低于 50 ms。

增量协议必须另写决定记录，并包含全量基线、序列号、确认、丢帧恢复、世界会话重置、当前可见位置和变化记录。不能把“本帧没发送”解释成空气、不可见或已经删除。
