# B10-A：在线状态、输入投影与计算预算

日期：2026-09-21
状态：尚未开始

## 目标

为一个严格限定的跨隙试点建立完整数据链：从正式观察和已应用输入得到状态锚点，把合法命令逐 tick 投影为 B09-R 输入，并证明这条链在当前机器上有可用的计算预算。

B10-A 不实现自动输入搜索，不接入普通规划任务，也不取得真实输入控制权。

## 试点范围

首个试点沿用 `fabric-1_21-ordinary-gap-one-cell-b09-v1`，进一步冻结为：

- 起跳和落地支撑均为 `minecraft:grass_block` 的完整方块状态；
- 两个平台同高，中间是一格已知无支撑空隙；
- 首条连续证据使用 `+Z` 直线方向，运动途中不转向；
- 入口水平速度为 0～0.1 格／秒；
- 入口中心、前后、横向和 yaw 误差沿用该 Profile 的现有范围；
- 食物值至少为 7；没有会改变运动的装备、属性变化或状态效果；
- 自动跳关闭，环境身份继续使用 `fabric-1_21-motion-v1`；
- 落点、终端速度和恢复范围沿用该 Profile，不扩大为所有普通材质或任意方向。

这只是 B10-A 的首条证据链。B10-B 在宣布跨隙求解能力前扩展到四个正方向，并使用独立验证样本。

## 按能力维护证据

B10.0 不再作为“补完所有边界后才能继续”的总前置。每项能力维护自己的证据清单。某条规则分支一旦被试点实际使用，就必须在上线前补齐对应证据。

试点必需证据包括：

- 原始命令、采样后输入、运动前状态和运动后状态可以按 tick 对齐；
- 起跳、实际冲刺、前进／冲刺释放和落地状态连续；
- 低顶、未知途中净空、未知落地和过期输入正确拒绝；
- 输入丢失和取消保持 B09 已声明的空中恢复边界；
- 若求解候选使用“继续前进但释放冲刺”，先补齐冲刺单独释放的专项 Fabric 差分。

半砖、楼梯、地毯、积雪、Crouch/Crawl 连续转换等证据只有在能力范围实际使用对应规则时才成为前置条件。

## 交付

1. 正式状态锚点，包含世界会话、观察序号、运动 tick、tick 相位和已确认控制。
2. 有界输入应用账本，区分已应用、在途、过期和无法消除的歧义。
3. 合法命令到 `TickInput` 的逐 tick 投影；现有控制器仍是唯一输入拥有者。
4. 状态／预测有效范围与候选执行窗口的不同结构。
5. 试点规则的固定输入连续 Fabric 差分。
6. 1、20、60 tick 以及小批量候选的完整检查预算，分别报告冷启动、稳态和在线端到端时间。

## 反例

- 同一观察被重复推进两次；
- 相同位置和速度，但跳跃冷却或输入相位不同；
- Crouch 轴值被重复缩放；
- 命令已经应用但回执迟到；
- 命令错过请求生效窗口；
- 诊断开启和关闭改变正式行为；
- 候选可以计算，但执行窗口已经失效；
- 当前仍有多个可能状态，求解器只选择最有利分支。

## 完成条件

- 试点所用规则分支有连续、可追溯的命令—输入—状态证据；
- 正式 actor 不读取诊断 sidecar；
- 投影输入均可由真实命令链生成；
- 状态锚点和输入账本对迟到、重复和不确定输入给出有界结果；
- 完整检查预算支持一个限定能力进入后台求解开发；
- 现有 B03–B09 控制器没有被新链路改写。
