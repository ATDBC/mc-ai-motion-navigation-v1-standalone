# 导航协调强化计划

日期：2026-09-28

状态：H1 至 H7 的结构整改、统计复验和三项专项 Fabric 对照已完成，S4 已重新关闭；S5 因冻结扰动扫描中的任务失败和完整连续高度矩阵仍保持打开。在 S5 关闭前暂停新增运动、地形和战斗能力。

关联：[协调架构](../architecture/navigation-coordination-v1.md)、[原阶段计划](navigation-coordination-refactor-plan.md)、[验收](../acceptance/navigation-coordination-refactor.md)、[D040](../decisions/0040-reopen-navigation-coordination-gates.md)。

## 1. 要解决的问题

现有实现已经统一了身体控制权、重试账本、风险账本和动作前置检查。但 S4 只记录了事件，没有约束下一个任务状态。会话中的分支仍可以直接修改状态，导致失败或停止状态被后续帧复活。

同一轮复审还证明：

- 助跑后下一格的动作证明与真实入口错位；
- 目标修订会把正在执行的风险动作再次计入预算；
- 已释放的风险记录占用容量；
- 探边收尾持续制造新的在途指令；
- 下落前只检查落脚空间，没有确认支撑仍在；
- 验收把“结果属于登记范围”写成了“任务成功”。

## 2. 实施顺序

### H1：让任务状态表真正生效

交付结果：

1. 定义有类型的转移动作。转移表根据“当前状态＋转移动作”给出唯一下一状态。
2. `NavigationSession` 只能通过一个转移入口改变任务状态和对外原因。
3. `COMPLETE / CANCELLED / FAILED / CLOSED` 不得离开。`STOPPING` 只能进入终态，或通过明确的交接转移回到执行／规划。
4. 删除重复的会话级伤害累计状态；诊断直接读 `TaskRiskLedger`。
5. 静态门禁禁止在转移入口之外写入状态。

验收：状态×转移动作穷举测试通过；终态复活探针为 0；四个已批准的探边目标修订交接仍然成功。

### H2：在真实动作入口重新准备证明

交付结果：

1. 路线中的动作模板只说明允许的入口域。在首条不可逆指令前，使用当前正式锚点准备或重求解。
2. 动作尚未开始时的入口不匹配记为 `EXECUTION` 重试，不直接终止任务。
3. 未离地时的单帧晚到或仲裁丢失重新准备；已离地时由原控制者负责落地。
4. 释放身体前使用与探边一致的支撑余量和惯性检查。

验收：助跑 1／2／3／5 格 × 窄道／宽道 × 起点偏移 × 正常／固定晚 1 tick 的一格下降场景无新的无界结果。

### H3：收紧任务风险账本

交付结果：

1. 从未提交且已释放的记录立即移出活动集合。
2. 已结算记录只保留必要的任务汇总，不占未结算容量。
3. 目标修订中的替换路线从已承诺动作的出口开始，或等该动作安全结束后再规划，不重复预留同一落差。
4. 容量耗尽产生有类型的失败，不能被取证分支覆盖。

验收：同任务连续 100 次零伤害保留／释放不能填满账本；下落起始附近修订目标不会永久停在 `planning`。

### H4：收尾和失败分类

交付结果：

1. 探边进入稳定支撑后只发一次中性释放指令，等它实际生效；不再每帧重发潜行保持。
2. `recovery_unresolved` 在规定期限内交给父层决定，同时保留合法的身体保护，不伪装成已释放。
3. 动作无解返回 `motion_unsolvable`，不冒充用户取消。
4. 任务终态后，身体控制者必须在有界时间内完成收尾和来源释放。

验收：固定晚 1 tick 的受控下降不会永久停在 `stopping`；侧边落点有界返回真实失败类别。

### H5：动作开始前复查落点支撑

交付结果：

1. 同时检查落脚空间、支撑方块、支撑外形、区块加载状态和观察新鲜度。
2. 支撑证据不足时先取证，不能因为落脚格仍然是空间就放行。
3. 方块移除、区块未加载和非完整支撑分开报告。

验收：首条不可逆指令生效前移除落点支撑时不开始下落；指令生效后才发生的变化由原执行者继续负责落地。未改变地形的正例不增加无谓取证。

### H6：修正验收统计和监视器

交付结果：

1. 固定矩阵分开报告任务成功、有界安全失败和意外结果。
2. 种子扫描按场景和扰动率输出终态分布、首次成功率、带合法恢复成功率及恢复代价。
3. 删除对 `recovery_unresolved` 和“已进入终态但仍持有身体”的无限豁免。
4. 新增终态后来源释放期限、释放时支撑比例、活动风险记录容量和非法转移计数。

### H7：重走 S5

顺序是组件场景族、固定矩阵、冻结种子扫描、真实后台进程，最后才是 Fabric。Fabric 至少包含：

- 助跑后下一格台阶；
- 起跳前移除落点支撑；
- 固定晚 1 tick，或可等价验证命令时窗的客户端注入。

完整连续高度速度带、形状和随机晚到 Fabric 矩阵仍是独立跨阶段门槛，不因本计划自动关闭。

### 当前实施结果

H1 至 H6 已按顺序实现并分别提交：

- 状态只能通过转移表改变，终态复活探针 38 次运行均为 0；
- 已验证动作会在真实入口重新锚定，入口不匹配不再直接终止整个任务；
- 风险账本只用未结算责任占容量，目标修订不会重复预留同一次下落；
- 探边、输入失联和无法恢复都有有界终态，来源释放必须满足支撑条件；
- 下落前会重新检查落脚空间和支撑。支撑在首条不可逆指令前消失时会拒绝动作；指令已经生效后再移除支撑属于物理上无法撤回的变化；
- 固定矩阵和种子扫描已经分别统计任务成功、安全失败和意外结果。
