# F2-SP：目标选面性能修正方案

日期：2026-10-08。状态：已完成。F2-S 可以进入任务 4；v9、旧大集合和 Fabric 尚未运行。

**目标：** 保持目标选择、安全和生命周期语义不变，减少跟随目标修订帧里同步执行的目标列查询，使修正版 D061 重新满足正式控制期限。

**依据：** [D077](../decisions/0077-bound-goal-surface-selection-work.md)、[F2-S 方案](F2S-support-region-convergence-before-route-optimization.md)和 [F2-SP 验收](../acceptance/F2SP-goal-selection-performance-remediation.md)。

## 当前基线

非正式短 Windows 诊断连续接受 `77` 次目标修订。完整生产计算 P95 为 `8.8566 ms`。Navigation prepare、Follow update、Runtime 外壳和 Navigation adopt 的 P95 分别为 `5.0374/3.1117/0.6591/0.1304 ms`。

Follow update 内部的 `_surface_for_goal` 和精确区域选择 P95 分别为 `2.7117/1.1172 ms`。这些调用互相包含，不能相加。区域选择三类正式门槛已经通过；本轮只处理支撑面发现与精确查询之间的重复工作。

## 实施结果

- P0：冻结独立完整扫描参照、四方向、非完整表面、多高度、节点平手、相关 UNKNOWN、全不可行和错误副本。
- P1：支撑面发现、净空、支撑和精确区域查询共用一个 `WorldQueryCache`；错误世界和错误类型明确拒绝。
- P2：目标列按几何下界稳定排序。已知世界仍选择同一个 `SurfaceNodeId`；相关 UNKNOWN 阻塞，无关 UNKNOWN 不再拖住目标修订。
- P3：首轮短门槛 P95 为 `7.6401 ms`，失败证据保留。一次局部修正后，`77` 帧 P95 降到 `6.9638 ms`；区域 first/last/all unavailable 的 P95 分别为 `0.4460/3.5665/3.1538 ms`，全部通过。
- P4：唯一一次正式 D061 保留 `4096` 帧并通过。全部生产 P95/P99/max 为 `5.1705/5.3590/7.0193 ms`；目标修订层为 `7.0193/7.0193/7.0193 ms`；完整夹具最大值为 `28.4577 ms`。

没有新增 Session 状态、等待、重试、线程或后台作业。planner、动作和输入责任没有修改。

## fail-fast 顺序

### P0：冻结结果与错误副本

1. 保存冻结诊断场景的完整查询结果、`SurfaceNodeId`、missing、候选列顺序和查询次数。
2. 加入非完整表面、多个高度带、四方向、列乱序和等距节点场景。
3. 用测试侧完整查询作为参照。参照不使用待实现的提前结束逻辑。
4. 加入四类错误副本：缓存不复用、忽略缓存世界身份、过早结束、忽略可能更优的 UNKNOWN。
5. missing 的比较分两部分：已知世界下选择结果必须逐项相同；含 UNKNOWN 时按 D077 的“可能改变选择”规则冻结新结果。

P0 不修改生产代码。任何场景无法稳定复现时，先修夹具，不继续实施。

### P1：让支撑面查询接受单次缓存

1. 给 `query_support_surfaces()` 增加可选 `WorldQueryCache`。
2. owner、碰撞、净空和支撑查询都使用同一缓存。
3. 缓存世界身份不匹配时抛出契约错误。
4. 默认不传缓存时保持原接口和结果。
5. 运行支撑面、几何、F2-S 区域和错误副本检查。

P1 只减少重复读取，不改列枚举和选择顺序。结果或 missing 变化即停止。

### P2：按下界惰性发现目标列

1. 为每个目标列计算到目标中心的几何距离下界，并按下界、列坐标稳定排序。
2. 逐列调用 `query_support_surfaces()`；发现的支撑面仍按实际距离和 `SurfaceNodeId` 比较。
3. 只有当前最佳候选已经不可能被剩余列超过时才提前结束。
4. 等距时保留节点 ID 平手规则。无法证明平手不会改变结果时继续查询。
5. 可能更优的 UNKNOWN 进入 missing；已证明无关的远列不进入 missing。
6. 未找到可行候选时必须完整扫描，并汇总所有 missing。
7. 同一次 `_surface_for_goal()` 的列发现和精确区域查询共用一个缓存。

P2 不使用墙钟、列数上限或历史运行时间决定返回值。

### P3：短 Windows 门槛

先运行组件和短 Windows 对照，不运行 v9、旧大集合、Fabric 或正式 `4096`：

- 至少 `77` 个连续目标修订帧；
- 选择结果、节点和平手行为与完整查询一致；
- relevant missing 阻塞、irrelevant missing 不阻塞；
- 无可行场景完整扫描；
- 完整生产计算 P95 `≤ 7.2 ms`；
- 区域选择三类保持 P95 `≤ 4 ms`、P99 `≤ 6 ms`、最大值 `< 10 ms`。

任一门槛失败即停止。最多进行一轮针对明确根因的局部修正；仍失败就结束 F2-SP。

### P4：唯一一次正式 D061

P3 全部通过后，从干净提交运行一次修正版正式 D061 `4096` 帧。不得重复采集挑选结果。

要求：

- 总体生产计算 P95 `≤ 8 ms`、P99 `≤ 15 ms`、最大值 `< 30 ms`；
- 目标修订帧分层同样满足 `8/15/<30 ms`；
- 完整夹具最大值 `< 50 ms`；
- 区域选择继续满足 `4/6/<10 ms`；
- 原行为、安全、身份、GC、trace、pacing、deadline miss 和最小余量门槛全部通过。

正式 D061 失败时停止，不运行 F2-S 任务 4。

### P5：交回 F2-S

只有 P4 通过，才执行以下工作：

1. 在 F2-S 文档中记录 F2-SP 来源提交和证据哈希；
2. 把 F2-S 状态恢复为“可以进入任务 4”；
3. 按原 F2-S 顺序运行 v9、旧集合和 Fabric；
4. 不把性能优化写成新的产品能力。

## 完成条件

1. 完整查询与惰性查询在冻结已知世界中选择相同节点；
2. D063 的 missing 收紧有独立测试，UNKNOWN 没有取得通行权限；
3. 没有新增状态字段、后台工作、等待或重试；
4. 短门槛和唯一一次正式 D061 都通过；
5. 失败和未运行项目如实保留。

## 止损条件

- 需要改变目标、支撑面或完成区域选择结果；
- 需要按墙钟、候选上限或机器速度提前返回；
- 需要降低目标修订频率或放宽 `8/15/30`、`50`、`4/6/10 ms` 门槛；
- 需要修改生命周期、pending goal、planner、动作或输入责任；
- P3 一轮局部修正后仍不满足 `7.2 ms`。

触发止损后，F2-S 继续停在任务 3。后台或跨帧方案另写决定，不在本方案内实施。
