# 第二十四轮导航协调收口方案

状态：历史实施和门禁已完成；后续复审发现信息选择和依赖重试两个 P1，S5 已由 [D045](../decisions/0045-reopen-s5-for-planning-behavior-ownership.md) 再次打开。现行方案见 [R25](navigation-planning-coordinator-r25-plan.md)。

## 1. 要解决的问题

第二十三轮独立复审发现四个缺口：

1. 依赖变化拒绝路线后，状态变成 `PLANNING`，但没有任何工作可以推进。
2. 后台结果在调用方期限之后返回时仍可能被接纳。
3. 随机门禁把“尝试注入”误写成“已经生效”。
4. 快照找到足以判定范围不完整的未知格后，仍遍历并复制其余未知格。

## 2. 实施顺序

### R24-1：规划工作所有权

- 增加 I15：`PLANNING` 必须拥有快照构建或有效后台请求。
- 依赖变化拒绝候选时立即从当前身体状态重发请求。
- 旧请求、目标和世界不匹配的结果不能留下无工作规划状态。

完成条件：逐帧监视器能抓到人为制造的无工作规划状态；依赖变化后诊断立即显示新工作。

### R24-2：结果期限覆盖返回帧

- 在处理候选前检查调用方期限。
- 过期候选沿用 `planning_timeout` 和既有安全交接路径。
- 保留“worker 死亡”和“结果超时”两个不同原因。

完成条件：结果在期限后第一次轮询到时不能创建路线。

### R24-3：扰动统计按效果记账

- 后端分别记录派发和实际改变。
- 重复移除空方块只记派发。
- 仲裁只在导航移动确实被压下时记为应用。
- 随机门禁继续保留生成和跳过分母。

完成条件：单元测试能区分重复世界编辑，以及没有导航移动的仲裁帧。

### R24-4：未知格提前结束

- 扫描仍按稳定顺序保存未知事实。
- 整理阶段找到第一个会影响规划的未知格后立即结束。
- 返回这个格子作为下一轮信息请求，不生成整片未知位置元组。
- 若所有未知格都被完整支撑层遮住，仍按分片预算检查完并声明范围完整。

完成条件：大量直接相关未知格只检查到第一个；大量被遮住的未知格仍按预算分片完成。

### R24-5：复验

运行完整 `tests/motion_nav`、固定 14 场、冻结 200 种子、192 个中断组合、1000 个固定随机序列、分段证据、Java 门禁、公开证据和独立导出校验。

本轮没有改变真实运动和感知语义，不重跑 Fabric。若正式路径模拟出现新的移动结果，再决定是否补实机对照。

## 3. 关闭条件

- I15 没有违规；
- 过期候选无法接纳；
- 固定、种子、中断和随机门禁没有白名单外结果；
- 随机事件的生成、派发、应用和跳过数字含义与代码一致；
- 未知仍保持未知，信息请求可以逐轮推进；
- 文档和公开导出同步。

## 4. 完成结果

- 规划诊断增加 `planning_work_owned`，正式模拟增加 I15。依赖变化拒绝候选后立即创建下一代请求，不再留下空转的 `PLANNING`。
- 调用方期限在处理候选之前检查。测试中的迟到候选以 `planning_timeout` 结束，没有路线被接纳。
- 测试后端分别记录派发和实际生效。重复移除同一方块时，第二次只记派发；没有导航移动提案的仲裁帧也只记派发。
- 快照只返回第一个影响当前规划的未知格。被完整支撑遮住的未知格仍按 `maximum_cells` 分片检查；未返回的位置仍是未知。

本轮复验结果：直接相关四个模块 141/141，完整 `tests/motion_nav` 768/768；固定 14 场为 13 个任务成功、1 个有界安全失败；冻结 200 种子为 198 个任务成功、2 个有界安全失败；192 个中断与晚到组合全部到达终态；1000 个随机序列全部在冻结白名单内，仍为 289 个成功、512 个有界失败、199 个有界取消。

1000 个序列中，丢仲裁有 540 次生成，其中 363 次实际压下导航移动，16 次只派发但当帧没有导航移动可压下，161 次因任务提前结束而跳过。移除落点支撑有 556 次生成，其中 406 次实际改变世界，124 次派发时目标格已经为空，26 次跳过。其余扰动结果见验收文档。本轮没有改变 Fabric 侧运动与感知语义，因此没有新增实机批次。

分段证据和 Java 门禁为 16 项通过、1 项 Windows 权限相关的符号链接检查跳过；10 个公开真实证据归档通过。独立公开导出包含 679 个文件，哈希校验通过，并在导出目录内重跑直接相关四个模块 141/141。
