# 第二十三轮导航协调整改方案

状态：历史阶段已完成。第二十四轮复审后来发现规划工作所有权、过期结果、扰动应用统计和未知格收尾仍有缺口，现行修正见 [第二十四轮方案](navigation-coordination-review24-remediation-plan.md) 与 [D044](../decisions/0044-planning-work-ownership-and-truthful-perturbation-evidence.md)。

## 1. 要解决的问题

第二十二轮已经统一了输入责任、等待所有权和停止后的交接入口，但独立复审发现四个关闭条件仍不完整：

1. 会话进入失败、取消或关闭后，信息等待和恢复等待可能继续留在任务级 `RetryLedger` 中。后继会话复用同一账本时，会因为固定等待编号仍属于旧会话而触发内部契约失败。
2. 后台规划进程只要仍然存活，会话就可以无限等待结果。规划函数内部的时间预算不能处理“进程活着但结果永远不返回”。
3. 地图快照虽然分片复制格子，但完成帧仍一次性检查和排序全部未知格。大范围未知区域会把未分片工作重新带回控制线程。
4. 随机事件门禁把所有有界失败和取消都算作允许结果，而且只报告事件生成次数。内部契约失败可能被掩盖，生成次数也不能说明事件实际进入了正式调用链。

这些问题都属于现有职责边界没有完全落实，不需要增加新的协调框架。

## 2. 实施原则

### 2.1 只结束拥有者的等待

`RetryLedger` 继续保存任务级失败次数、进度和风险历史。会话退场时只结束以下活动等待：

- 当前会话拥有的信息等待；
- 当前会话拥有的恢复等待；
- 当前探边动作拥有的取证与恢复等待。

进入任务终态和最终关闭都调用同一退场方法。后继会话可以复用任务账本，但不能继承旧会话仍在活动的等待。

`NavigationDiagnostics` 公开活动等待的编号和拥有者。正式模拟监视器在任务终态检查：已经退场的会话不能仍拥有活动等待。

### 2.2 规划请求由调用方设置期限

`PlanningPipelineState` 保存当前已提交请求的身份、提交运动 tick 和单调时钟。请求得到匹配结果、被目标修订替换、会话退场或规划失败时清除这些字段。

当 worker 仍存活但超过请求期限没有返回匹配结果时：

- 当前请求代次失效；
- 后到结果不能重新接纳；
- 没有身体控制者时返回有类型的 `planning_timeout`；
- 有旧安全路线时，沿用现有交接流程让旧路线有界停止，再发布替换失败。

不新增线程，也不把每帧控制提交的 500 ms 截止时间当作规划请求期限。

### 2.3 快照整理继续服从格子预算

`KnownMapSnapshotBuilder.advance()` 的 `maximum_cells` 同时约束：

- 从世界视图复制格子；
- 判断未知格是否真正影响规划范围；
- 生成稳定顺序的缺失格列表。

构建器增加明确的整理阶段。一次调用最多处理 `maximum_cells` 个待整理位置；只有复制和整理全部完成后才返回 `COMPLETE`。整理期间世界几何发生变化仍返回 `STALE`，不能发布混合版本快照。

未知事实不能因为优化而变成空气。构建器可以只返回第一个会影响当前规划的未知格，供信息循环逐轮取得；其余位置在快照中仍保持未知。隐藏在完整支撑层下、确定不影响身体查询的未知格仍按现有规则排除。

### 2.4 随机门禁按实际结果验收

随机门禁分别记录：

- 生成次数；
- 进入运行时事件队列的次数；
- 满足触发条件并实际派发的次数；
- 因任务已终止、缺少控制者或场景不适用而未派发的次数；
- 对输入迟到、回执缺失、仲裁丢失、外力和世界变化，记录后端实际应用次数。

每个场景冻结允许的终态和原因。以下结果无条件视为门禁失败：

- 公开接口异常；
- `navigation_internal_contract_failure`；
- 不变量违规；
- 没有终态；
- 终态后仍有退场会话拥有的活动等待；
- 未列入该场景白名单的失败或取消原因。

有界失败仍可作为正确结果，但必须事先写入清单，不能运行后重新归类。

## 3. 实施顺序

### R23-1：等待生命周期

1. 先加入“范围外失败后创建 successor 并再次等待”的失败测试。
2. 加入终态活动等待监视器测试。
3. 实现统一等待退场方法，并从任务终态与最终关闭调用。
4. 重跑追击接续、探边和重试账本测试。

完成条件：旧会话退场后活动等待为空，任务级失败和风险历史仍保留；successor 可以正常创建自己的等待。

### R23-2：规划不响应期限

1. 用存活但永不返回结果的 worker 写失败测试。
2. 在 `PlanningPipelineState` 保存请求期限。
3. 超时通过现有规划失败和安全交接路径返回 `planning_timeout`。
4. 测试旧代次迟到结果不会复活请求。

完成条件：故障注入在冻结期限内到达有类型终态，没有释放仍在运动的身体。

### R23-3：快照整理分片

1. 写一个包含大量未知格的构建器测试，验证扫描结束后仍会返回若干次 `BUILDING`。
2. 将未知影响判断和结果排序改为分片整理。
3. 验证最终快照及缺失格与旧算法一致。

完成条件：每次 `advance()` 的格子扫描和未知影响判断都受预算约束；完成帧不再排序或重新判断全部未知格；路线语义不变。

### R23-4：随机门禁收紧

1. 给 `Result` 增加活动等待和事件派发／应用统计。
2. 让监视器检查终态活动等待。
3. 给清单增加允许结果类别和原因；内部契约失败必须失败。
4. 分开报告生成、派发、应用和跳过次数。

完成条件：审查发现的三个冻结种子会在修正前被门禁拒绝、修正后通过；人为注入内部契约失败必定使门禁失败。

### R23-5：全量复验与记录

依次运行：

1. 直接相关组件测试；
2. `tests/motion_nav` 全量检查；
3. 固定 14 场；
4. 冻结 200 种子；
5. 192 个中断与晚到组合；
6. 1000 个固定随机事件序列；
7. Java 输入门禁、分段证据、公开证据和独立导出检查。

本轮不改变运动物理、正式视觉和连续高度能力范围，因此不要求重跑 800 场 Fabric 矩阵。若修正触及真实输入或运动执行语义，再补对应 Fabric 对照。

## 4. S5 重新关闭条件

必须同时满足：

1. 失败、取消、关闭和 successor 接续后没有退场拥有者的活动等待；
2. 活着但不返回结果的规划 worker 能得到 `planning_timeout`；
3. 大范围未知快照的复制和整理都受分片预算限制；
4. 固定、种子、中断和随机门禁没有公开异常、内部契约失败、永久等待或不变量违规；
5. 随机门禁报告实际派发和应用覆盖，并只接受冻结白名单内的有界结果；
6. 文档、代码、测试和公开导出描述一致。

## 5. 完成结果

2026-09-30 完成实施和复验：

- 终态与关闭会结束当前会话、当前探边动作拥有的活动等待。任务级重试次数、进度和风险记录继续保留。模拟监视器会直接检查终态残留等待。
- `PlanningPipelineState` 保存请求提交 tick、墙钟和结果期限。活着但不返回结果的 worker 会得到 `planning_timeout`；迟到结果不能复活终态请求。
- 快照先按稳定顺序扫描，再按同一个 `maximum_cells` 预算判断未知格是否影响规划范围。扫描结束后可以继续返回 `BUILDING`，完成帧不再排序或重新判断全部未知格。
- 随机门禁为四种场景冻结了允许的“终态＋原因”。公开异常、内部契约失败、不变量违规和白名单外结果都会使命令以非零状态退出。
- 1000 个序列全部通过冻结白名单。结果仍为 289 个成功、512 个有界失败、199 个有界取消。事件统计现在区分生成、派发、应用和跳过。例如 884 次输入晚到中有 550 次实际应用，334 次因任务提前终止而跳过。

复验结果：直接相关组件 146/146，`tests/motion_nav` 762/762；固定 14 场为 13 个成功、1 个有界安全失败；冻结 200 种子为 198 个成功、2 个有界安全失败；192 个中断与晚到组合全部到达终态；1000 个随机序列没有白名单外结果。分段证据与 Java 门禁 16 项通过、1 项平台限定跳过；10 个公开证据归档通过；独立公开导出 677 个文件通过哈希校验。
