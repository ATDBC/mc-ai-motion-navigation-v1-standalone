# 空中转换 V1

日期：2026-09-19

适用阶段：B09

## 1. 要解决的问题

B05 的 `JumpUp` 只覆盖低速、相邻一格上升。B09 要在不破坏这条已验收能力的前提下，加入跨隙和受控下降，并让后台规划只使用已经通过几何与身体条件检查的动作边。

三类动作都经历离开支撑、空中移动和重新落地，因此共享轨迹扫掠、落地确认、取消和输入失联规则。它们的触发方式和适用地形不同，规划中仍保留独立类型：

- `JumpUp`：沿用 B05，不改已冻结的能力范围；
- `JumpGap`：主动起跳越过已知无支撑区域；
- `ControlledDrop`：不按跳跃键，从边缘进入已知的较低落地区域。

## 2. 状态归属

| 状态 | 唯一拥有者 | 说明 |
|---|---|---|
| 实际位置、速度、接地、姿态和碰撞 | Fabric 正式观测 | 输入请求不能代替实际状态 |
| 可用轨迹、入口范围、落地区域和时间界限 | 版本化动作 Profile | 只记录实测稳定范围 |
| 当前空中阶段 | 对应动作控制器 | 规划器不能推进执行阶段 |
| 动作边及其几何依赖 | 已知图规划器 | 只在能力查询为可行时生成 |
| 整条路线的动作顺序 | 动作路线执行器 | 不解释空中物理细节 |

## 3. 公共空中轨迹

`air_motion.py` 保存跨隙和下降共用的 Profile、轨迹查询和观察驱动控制器。Profile 使用相对于起点的三维参考点，并明确：

- 水平格距和目标高度差；
- 是否按跳跃键、是否请求冲刺；
- 入口速度、朝向，以及前、后、横向分别允许的偏移；
- 身体扫掠余量、离地等待和最长空中时间；
- 落地区域、允许层高误差、出口速度和恢复空间；
- 代价、风险标签和适用材质。

参考轨迹只描述已经校准的有限动作。系统不能按比例外推更远距离或更大落差。轨迹的每一小段都使用统一扫掠查询；起点、终点和恢复区域分别检查支撑与净空。未知关键格返回 `NEEDS_INFORMATION`，明确碰撞返回 `BLOCKED`，材质或关系超出 Profile 返回 `UNSUPPORTED`。

入口位置不是一个没有方向的圆。受控下降时，向边缘多站一点和离边缘远一点会产生不同结果。Profile 因此分别声明最大前向、后向和横向偏移。几何查询会从这些边界入口逐条扫掠，只有整个声明范围都安全时才生成动作边。

## 4. 执行阶段

```text
PREPARE
  → REQUEST_DEPARTURE
  → AIRBORNE
  → VERIFY_LANDING
  → COMPLETE
```

- `PREPARE` 核对世界会话、几何、身体、入口速度、位置和朝向。
- `REQUEST_DEPARTURE` 提交一次起跳请求，或持续向边缘移动，并等待实际离地。
- `AIRBORNE` 根据观察到的位移执行 Profile 声明的空中输入。
- `VERIFY_LANDING` 只在目标层接地、支撑成立、身体处于落地区域且速度满足出口条件时完成。

起跳前取消按地面停止处理。已经离地后，取消和输入失联都先执行可验证的安全落地。控制器不能在空中宣称瞬间停止。

空中进度从实际发出离地请求时的身体位置开始计算。它不能从支撑面中心计算，否则上一段路线留下的小偏移会提前或延后松键。目标落地区仍使用支撑面的世界坐标，并在落地后核对实际支撑和速度。

## 5. 规划和路线

支撑面图增加 `SurfaceJumpGapEdge` 和 `SurfaceControlledDropEdge`。每条边保存自己的 Profile、依赖、成本、入口和出口状态。后台只生成能力查询已经确认的边。

本阶段仍使用稳定入口。动作交接可以有必要的减速和准备；B10 才处理多动作带速连续接续。A* 的结果必须与独立 Dijkstra 对照。若新增动作使启发式无法证明为下界，则含这些动作的请求退回零启发式。

## 6. 风险边界

- 默认风险策略为 `no_expected_damage`；B09 不接受预计会受伤的下降。
- 不支持未知落地、未知轨迹净空、液体落地、特殊弹性地面或未经校准材质。
- 不支持对角跨隙、连续跑酷、攀爬、游泳、滑翔或主动改变世界。
- 一条边成立不代表整条路线必然成立。路线仍要累计时间、资源、风险和恢复条件。
- B09 不负责消除动作之间的停稳；这属于 B10。
