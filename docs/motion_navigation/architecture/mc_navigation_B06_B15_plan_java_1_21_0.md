# Minecraft Java 1.21.0：第二批运动／导航交付计划（B06–B15）

日期：2026-09-19
状态：已采用；B06、B07、B08、B09 已完成，B10–B15 仍是待实施计划。实际结果以各阶段的 `acceptance` 文档为准。
适用项目：Minecraft 常驻 2P AI 机器人。
阅读基线：`ATDBC/mc-ai-motion-navigation-v1-standalone`，公开提交 `fdad6e3a4cfed5934c5e744f6f4d7c6b3744c20b`；README 标注的来源提交为 `1114d84`。
设计依据：`docs/motion_navigation/architecture/mc_motion_navigation_architecture_v1.md`，以及 B02–B05 专项架构、阶段、验收与 D004/D006/D007/D008 决策。

**目标：** 先把已知地形中的移动能力扩展成可发布版本，再进入未知探索、观察站位协调。支持范围内不仅要能到达，还要能选择合适动作、连续接续并给出可核验的失败结论。

**架构：** 沿用世界知识、几何／预测、能力查询、后台规划、路线接纳、动作执行和唯一输入出口；按运动影响复用方块模型，按入口／出口状态连接动作。增加能力，不复制地图、目标、路线或输入系统。

**技术栈：** 保留当前 Python 运动核心与独立 Fabric 实机链路。沿用已经锁定并通过前序阶段的环境：Minecraft Java 1.21.0（工程版本标识 `1.21`）、Fabric Loader 0.15.11、Fabric API 0.100.6+1.21、Yarn 1.21+build.9、OpenJDK 21、Python 3.11。B06 核对实际运行工程与这些版本是否一致，并补齐客户端、服务端、mod 清单和配置哈希；不得重新选择版本或静默升级。

**执行方式：** 本文件是下一批交付包计划，不要求一次生成全部代码。逐包细化可独立验收的小任务，先反例、再最小实现、再回归；前一门槛不通过，不用后一层特判补救。实现可采用逐任务执行与独立审查，不依赖必须安装某个开发插件。

## 1. 本批范围与原规范的关系

原规范 P4 后先进入 P5 未知与观察，再进入 P6 动态变化和 P7 多移动方式；P9 扩展 Climb/Swim。本次按用户新目标调整**交付顺序**，不改变责任与权限：

`B01–B05 已完成 → B06–B15 已知环境多能力移动 → P5 未知探索／观察协调 → P6 动态变化与局部绕行 → P8 跟随等任务集成`。

其中 B06–B15 提前实施原 P7 和选定的 P9 内容，并进行只针对当前能力的规模与长时间验收。它不等于原 P5/P6/P8/P10 整体已经完成。[R1]

### 1.1 本批必须形成的能力

普通地面与常见非完整形状；Walk/Sprint/Crouch/Crawl；通过玩家自身合法动作进入和保持的低姿态通行；经校准的上升、跨隙、受控下降；带速动作接续；特殊地面与接触机制；Climb；水中移动与出入水；混合地形中的动作路线选择与效率验证。

“做全”指上述**冻结清单内**的能力、材质和必要组合做完整，不指原版一切可能机制的无限穷举。

### 1.2 本批不作为完成条件

未知探索、观察站位评分、动态实体避让、跟随与战斗；挖掘、搭桥、放置、主动开关门；活塞运输、坍塌预测等复杂动态设施；船、矿车、坐骑、鞘翅、创造飞行；末影珍珠、风弹、激流等消耗型道具或装备驱动位移；未经校准的药水／附魔组合；连续跨维度任务。

本批只实现玩家自身、不使用载具或消耗型道具、不主动改变世界的运动。排除项仍须被正确识别并返回 `UNSUPPORTED`、条件不足或所需交互，不能默认普通化。已存在且状态合法的开放门洞可以按实际几何通行；主动开门属于另一种授权动作。识别危险并绕开不计作“已经支持穿越危险”。

### 1.3 默认运行约束

普通玩家身体与现有感知权限；自动跳关闭；不使用飞行、位置写入、载具或道具位移替代动作。默认不允许预计伤害换路，不主动消耗物品，也不主动改变世界。对踩踏等运动诱发变化单独登记：进入可能触发受保护世界变化的区域前应按策略拒绝，不能以“只是走路”为由忽略副作用。

本批首先支持无运动增益／减益的普通身体配置；装备、属性和状态效果必须可观测并纳入能力适用条件。需要皮革靴等条件的能力由独立配置启用。未验证的状态组合关闭相关能力，不能自动切回普通物理。测试夹具可在试验前恢复初始健康、饥饿和装备，但正式计时后不得持续补充以掩盖资源消耗。

## 3. 方块分类与能力契约

### 3.1 多维分类，不建立一个互斥的材质总枚举

| 维度 | 保存或派生的信息 | 使用者 |
|---|---|---|
| 状态与身份 | 方块注册名、影响运动的状态属性、版本与已知来源 | 世界知识、分类器 |
| 几何 | 实际碰撞、支撑面、局部高度、形状所有者及依赖 | 几何与能力查询 |
| 地面动力学 | 经核验的滑移、速度、起跳参数及适用条件 | 运动预测 |
| 接触事件 | 进入体积、侧面接触、踩踏、落地等行为 | 接触模型与动作执行 |
| 介质与附着 | 流体种类／高度／流动条件、攀爬面及进入条件 | Swim/Climb |
| 危险与资源 | 伤害、呼吸、冻结、饥饿、装备要求、运动诱发变化 | 策略、能力与路线接纳 |

Minecraft 1.21 的版本对应接口将形状、滑移、速度／起跳倍率和接触方法分别表达；形状还存在实体上下文。因此不能仅按注册名、外观或一个摩擦值推断全部运动行为。[E2–E4]

### 3.2 “普通”等价类的判定

从固定版本方块注册表和方块状态出发，建立审查过的分类规则；运行时只把这些通用规则应用于合法已知的位置事实。允许共享一个普通地面模型，但需同时满足已验证参数、无未处理接触行为、几何可处理、当前身体条件匹配。

反射或扫描只能辅助发现回调和继承关系，不能证明所有自定义／继承行为等价。每个普通等价类必须有代表性实机替换测试。遇到未分类状态不能默认普通。

**全量登记不等于全量支持。** 分类报告分别记录：识别覆盖、几何覆盖、行为覆盖、可执行能力、参数适用域、反例与拒绝原因。B06 冻结原版注册表和本批必做族；B15 不允许把失败族临时移出清单以获得通过。

### 3.3 必须区分的结果

| 情况 | 处理原则 |
|---|---|
| 位置／相关状态缺证据 | `NEEDS_INFORMATION`，缺口继续保留 |
| 已知几何不通 | `BLOCKED` |
| 状态已知但相关机制未实现 | `UNSUPPORTED` |
| 机制支持但身体、资源或策略不满足 | 结构化原因区分条件不足／策略禁止；不伪装成地形堵死 |
| 搜索预算耗尽或候选尚未完成 | 沿用计算未完成／超时语义 |
| 有限已知模型中无路径 | 报告范围、能力集和离散化条件；不宣称真实世界绝对不可达 |

沿用既有类型体系，必要新增枚举先修改契约和消费者清单，不用 reason 字符串反向决定权限。

### 3.4 目标状态必须完整

导航目标不能只有一个坐标。每个目标至少声明位置点或区域、允许的支撑面或介质、允许姿态与运动模式、必要朝向、终端速度范围，以及允许使用的资源和风险。目标管理拥有这些要求；规划、路线接纳和动作执行读取同一份定义。

例如“到达水池边”可以要求站在指定区域的固体支撑面上并停稳；“到达水中观察位置”则可以允许 Swim 模式和非零速度。二者即使坐标相同，也不能被同一个二维到点条件提前完成。

### 3.5 新能力必须声明的信息

每种能力至少声明：版本化配置；可用身体／装备／环境条件；入口位置、姿态、模式、速度和方向集合；整段预测轨迹及其事实依赖；出口状态集合；误差包络；输入和执行阶段；取消／失联行为；终止与失败条件；预计时间、风险和资源变化。规划边引用这份动作转换定义，不能自己再猜一次能力条件。

动作转换契约在 B06 固定最小结构，后续能力只增加自己的参数和执行器。B06 不创建尚未使用的能力服务，也不提前实现 Swim、Climb 或完整动作库。

### 3.6 资源、几何和执行余量分开处理

饥饿、呼吸、预计伤害、冻结、装备耐久和状态效果等资源，既要检查单个动作，也要检查整条候选路线的累计变化。路线接纳再次使用当前身体资源核对；不能让每条边单独可行，却拼出整体必然失败的路线。

规划使用真实几何和能力边界。硬安全检查决定动作能否执行。墙边、坑边和实体附近的软缓冲只在局部控制中给已经安全的输入排序，用来吸收跟踪误差、惯性和临时扰动，不得把 0.45 格之类的执行偏好重新写成规划禁区。Walk、Sprint、Jump、Climb 和 Swim 分别声明自己的制动或安全退出范围。

方块运动分类沿用并迁移 `docs/superpowers/specs/2026-09-09-block-traversal-properties-design.md` 中已经确认的“几何 + 通用运动参数 + 可组合例外”规则。执行软缓冲沿用 `docs/superpowers/specs/2026-09-12-execution-only-safety-buffer-design.md` 的职责分工。旧文档保留为历史依据，当前接口和验收只写入本目录的新文档。

## 5. B06：版本冻结、共享契约、运动特征与普通类推广

**交付：** 核对固定环境身份，建立目标、动作转换和资源的最小共享契约，冻结分类清单和已知地图试验入口，并把经核验的普通材质映射到普通运动模型。

### B06.1 固定版本和试验来源

核对完整运行工程是否使用 Minecraft Java 1.21.0（工程标识 `1.21`）、Fabric Loader 0.15.11、Fabric API 0.100.6+1.21、Yarn 1.21+build.9、OpenJDK 21 和 Python 3.11。再导出客户端／服务端构建、mod 清单、协议、tick 设置、角色属性、自动跳设置、配置哈希和源码身份。环境不匹配时不加载旧校准配置，也不借 B06 重新选择依赖版本。

冻结三种独立的证据角色：组件夹具、Fabric 正式观测、测试真值。组件可以直接构造完整已知世界；Fabric 正式试验使用既有合法采集得到并可回放的预勘测知识。测试命令只能建立／重置场景，不能把隐藏世界或答案路径回灌规划器。预勘测成本与正式移动成绩分开，未经验证的区域继续未知。

保留 B05 旧 Profile 和原始运行证据；新配置使用新 ID，不能覆写参数后仍引用旧的成功率。

**验收：** 错版本、错配置哈希拒绝；相同合法观测但隐藏世界不同，决策在获得新证据前相同；缺失信息反例仍保留。预勘测只声明实际完整的有限区域，不声明全世界已知。

### B06.2 建立分类器和登记清单

导出 1.21 原版注册表与状态清单。按第 3 节建立审查规则，区分空碰撞非空气、普通完整块、部分形状、特殊行为、流体／攀爬、危险／条件对象。新增候选文件 `block_motion_traits.py`；世界坐标事实仍由 `world_model.py` 拥有。

先检查共享 Observation/Action 契约实际能提供什么，再登记需要新增的字段和消费者；不在 Python 层虚构饥饿、流向或装备默认值。

**验收：** 相同模型不同 ID 归入同类；相同 ID 不同运动状态可分流；未登记状态返回未支持；无碰撞危险块不等同空气。

### B06.3 推广普通地面模型

以草方块原配置为回归基线，选取经规则确认的石质、泥土、木板、玻璃等代表状态做替换试验；测试前确认这些代表确实属于冻结版本的目标等价类。校准组和独立验证组分开。

**验收：** 原固定路线与 JumpUp 在被推广配置的声明范围内通过；不重新拟合每个普通方块；模型误差仍处于冻结包络。新能力关闭时，B03–B05 原配置结果不变。

### B06.4 固定目标、动作转换与资源契约

建立最小的 `GoalState` 和 `MovementTransition` 契约。目标记录位置或区域、支撑／介质、姿态／模式、终端速度、必要朝向、资源与风险要求。动作转换记录入口状态类、整段轨迹与依赖、出口状态类、时间／风险／资源变化、取消与输入失联结果。

先让现有 Walk 和 JumpUp 适配这份契约，证明规划、路线接纳和执行器读取的是同一套条件。B10 只负责利用这些条件做连续交接，不再临时发明另一套动作协议。

资源契约同时提供单动作变化、沿路径的更新／恢复规则和前缀约束。搜索状态保留当前能力实际使用的资源标签；同一站位上，只有时间、入口状态和相关资源都不更差的前缀才能支配另一个前缀。不能只保留最快前缀，再到路线接纳阶段拒绝资源超限的最终候选。当前还没有呼吸、冻结等数据时，字段保持“未提供”并关闭依赖它的能力，不能用零值代替未知；尚未被当前能力使用的资源维度不提前加入搜索状态。

**验收：** 相同位置但目标支撑、姿态或终端速度不同，不会被错误合并；JumpUp 的出口只有落入下一段 Walk 的合法入口时才能交接；累积资源超限的组合路线被拒绝；同一站位的最快前缀资源不足、较慢前缀能够到达目标时，搜索仍能保留并找到后者；取消和输入失联都有结构化终态。

**主要落点：** `world_model.py`、`pre_floating_adapter.py`、`runtime_adapter.py`、`ground_motion.py`、`ground_calibration.py`、`action_route.py`、`route_admission.py`、`config/motion-navigation/`；新增 `block_motion_traits.py`、小型动作转换契约与对应测试。完整工程中 Fabric/契约的实际修改路径由 B06.1 导出，不伪造公开快照中不存在的文件。

## 6. B07：支撑面、非完整形状与台阶

**交付：** 半砖、楼梯、地毯、不同层数积雪、耕地／土径等代表形状；薄障碍、栅栏／墙、活板门和状态变化的正确几何。只在此启用已经匹配普通动力学的组合，含水／特殊接触组合等待相应能力。

### B07.1 修正跨格与上下文相关形状

移除“所有局部碰撞盒只能落在 0–1 内”的表达限制，但不直接取消校验：改为校验有限值、正体积、合法来源及版本允许的形状范围。扫掠查询必须纳入可能侵入当前空间的邻近形状所有者，记录所有者和依赖，处理区块边界及负坐标。

不能只扩大 AABB 接口而保留原来的候选格搜索。形状依赖邻接或实体条件时，只使用合法已知状态；缓存键包含影响结果的条件，不读取隐藏邻格补答案。

**反例：** 身体扫过上方一格，碰撞实际来自下面方块；栅栏连接状态变化；同一形状受实体上下文影响；相同几何重复观察不误撤销。

### B07.2 从实际表面生成站位

从碰撞形状提取支撑表面和连续可站立区域，保留真实非整数高度。站位身份使用稳定的表面身份、有限拓扑节点和必要模式；多个表面不得因相同 XZ 合并。离散节点用于表达连通关系和动作入口，不把玩家永久限制在格心或八个方向。不要把半砖高度 floor 成整数，也不要假定格心总是有效。

`query_support` 继续报告实际面积／比例；能力按身体、速度、风险判断是否够用。“面积大于零”不等于动作获准；支撑余量不应直接修改几何真值。

**反例：** 上下半砖、转角楼梯、窄表面、两个相同 XZ 不同高度目标、可站端点之间存在薄障碍。

### B07.3 建立小高度通行闭环

以固定版本实际台阶运动规则建立 StepUp/StepDown 或等价的地面高度转换，校准预测和失败范围。对超过已验证台阶能力的高度生成 JumpUp 请求，不用“碰到障碍就按跳跃”代替判断。

每个几何族必须最终形成“节点／边 → 接纳 → 实际执行”的小型路线，不能只验证碰撞函数。

本阶段若改变规划边或代价，必须同时证明当前启发式不会高估；无法证明时先使用零启发式，并与独立 Dijkstra 对照。启发式正确性不能拖到 B14 再补。

**验收：** 强制形状场景全部完成或正确拒绝；必要升降不靠瞬移；真实运动顺序与当前游戏版本一致；未知相关几何不能通行。原平地回归通过。

**主要落点：** `world_model.py`、`geometry.py`、`known_map_planner.py`、`route_admission.py`、`fixed_route.py`；按需新增 `support_surfaces.py`、`step_transition.py`，不新建另一套地图。

## 7. B08：地面速度、姿态与低通道

**交付：** Walk、Sprint、Crouch 的速度、制动与边缘行为；姿态变化的身体净空；Crawl 在已经合法进入后的保持、移动和退出。依赖水中进入的 Crawl 完整转换在 B13 交付。

### B08.1 观测和预测

接入实际冲刺状态、相关属性、饥饿／可冲刺条件和姿态，来源可追溯。分别校准加速、惯性、停止和输入延迟，不把 Sprint 仅实现成最高速度乘常数。共享地面控制逻辑，只在确实不同的行为处区分。

### B08.2 入口、取消和路径条件

开阔地选择可持续的速度；窄通道／坑边按空间与制动条件减速。Crouch 是潜行状态，涉及速度、身体和边缘规则；必须验证实际状态生效后才能使用这些能力。

Crawl 是独立的爬行状态，使用游戏实际的游泳姿态和净空规则，不是 Crouch 的更慢版本，也不是可以直接写入的姿态字段。B08 可以用明确声明“已经合法进入 Crawl”的固定路线前置状态，验证保持、移动和退出，但不能把测试夹具设置前置状态算作入口能力。它不自动开合活板门来制造入口，也不规划从普通站立直接进入低洞。水中合法进入 Crawl、穿过低通道并退出的完整转换在 B13 验收。

### B08.3 固定路线与模式切换验收

覆盖 Walk↔Sprint、Walk↔Crouch、Crawl 的保持／移动／退出、资源突然不满足、转动相机仍沿世界方向移动、不同速度取消、输入失联。Sprint 首次让资源影响选路，因此本阶段就要验证资源标签不会只保留最快前缀；加入强制反例：“同一站位的最快前缀无法继续冲刺，较慢前缀仍能完成目标”。缺少稳定条件时报告条件不足，不尝试无限切换模式。

**主要落点：** `runtime_adapter.py`、`ground_motion.py`、`fixed_route.py`、`action_route.py`、`action_route_executor.py`；新增模式配置与测试。共享动作出口和输入租约不变。

## 8. B09：参数化跳跃与受控下降

**交付：** 普通地面上的上升、跨隙、受控下降及有限组合。先验证动作覆盖和安全边界，B10 再完成带速连续性。

### B09.1 校准入口—轨迹—落地

对起点偏移、入口速度／方向、水平位移、目标高度、落地区域、顶部净空进行分层采样；保留边界失败，分离校准与验证样本。不能把 B05 单条轨迹缩放为任意距离或套到任意材质。

建立共享的空中预测／碰撞／落地组件，但上升、跨隙、下降可以保留不同的规划边类型和适用条件。配置记录实际证明的范围；不把单次极限跳成功当稳定能力。

### B09.2 能力边与执行

起跳、整段身体轨迹、目标支撑和落地后的恢复空间都要成立。受控下降同时检查水平速度、头部空间、累计下落状态和允许伤害；默认零伤害，不硬编码一个跨材质通用的安全落差。

后台只能生成已被能力查询确认的动作边。每个动作都完成固定路线验证、后台选路和实际执行验证，不能只手工指定动作成功。

同一条路线包含多个跳跃或下降时，要累计预计时间、饥饿、伤害风险和恢复条件。每条边分别成立，不代表整条路线的身体和资源条件必然成立。

新增这些边后立即核对启发式；无法证明现有下界对新动作仍成立时，对包含新动作的请求使用零启发式，并与独立 Dijkstra 对照。

### B09.3 取消和异常

复用观察驱动的阶段推进。起跳前允许地面取消；离地后先完成当前可验证的落地处理。覆盖未实际起跳、错误层着陆、落在目标区外、碰顶、输入拒绝、空中目标替换与失联；不能凭时间结束就宣称成功。

**主要落点：** `jump_up.py`、`action_route.py`、`action_route_executor.py`、`known_map_planner.py`、`route_admission.py`；按实际复用拆出 `air_motion.py`、`jump_gap.py`、`controlled_drop.py`。`jump-up-v1.json` 保留，新增配置另行命名。

## 9. B10：连续接续与执行走廊

**交付：** 普通复杂地形中不再为每个动作交接机械停稳。此包是第一个可发布中间里程碑，但不是全部第二批完成。

### B10.1 使用 B06 的有限状态类

本阶段直接使用 B06 已固定的入口位置区域、速度区间与方向、姿态／模式、出口集合和必需依赖。静止站位仍是合法状态；按 B08/B09 的实测结果增加有限的带速类别。不建立完整六维连续搜索，也不另建一套只供执行器使用的状态定义。

只有前一动作的可靠出口能进入下一动作的合法入口时，才允许接续；不兼容时规划可执行的调整／制动段并计入成本，不能到现场才无限校正。

### B10.2 执行交接

把现有只识别 Walk/JumpUp 的顺序执行器迁移到 B06 动作转换契约，各能力仍保留自己的执行阶段。顺序执行器只拥有段索引和交接，不复制底层阶段，也不解释具体方块或能力规则。

同帧交接可避免空输入，但必须保证：单次最终输入写入、有限的同帧推进次数、同一观测不会重复推进物理阶段、回执与实际输入相匹配、取消标记和异常不丢失、整帧耗时包括交接前后的全部计算。

路线接纳给执行器一段经过验证的短时执行走廊。局部跟踪器可以在走廊内连续修正位置、速度和朝向；只有走廊相关几何、身体条件或动作入口失效时才停止授权。折点已经满足时，删除折点本身，保留仍然有效的后续走廊。

### B10.3 组合场景

Sprint→Jump→Walk；Jump→转弯；连续高差；连续跨隙；落地空间不足必须提前减速；姿态转换；取消发生在交接边界。必须有至少一类“可带速完成、不需要中间停稳”的正式试验。

**验收：** 声明可连续的组合不增加交接空操作和无谓停稳；需要停稳的组合明确记录原因；静止与运动入口都保留覆盖。不得为了连续性扩大未经验证的能力范围。B10 里程碑可以包含已经处于 Crawl 后的移动和退出，但在 B13 完成水中合法入口前，不宣称支持从普通地面完整进入低通道。

**主要落点：** `action_route.py`、`action_route_executor.py`、`route_admission.py`、`fixed_route.py`、`known_map_planner.py`；扩展 B06 已建立的动作转换契约，不在 B10 新建第二份协议。

## 10. B11：特殊地面与接触机制

**交付：** 按机制逐组实施，不逐方块复制控制器。以下是必须在 B06 冻结的代表族，具体状态由 1.21 注册表／代码与实机核验决定：

| 子包 | 代表对象／机制 | 必测内容 |
|---|---|---|
| B11.1 滑移与减速 | 冰、浮冰、蓝冰；灵魂沙等条件相关减速面 | 制动、转向、从普通面进入和离开、脚下跨两种面 |
| B11.2 体积与侧面接触 | 蜘蛛网、蜂蜜等 | 进入／退出、竖直和水平影响、侧面与顶面区别、取消 |
| B11.3 落地响应 | 黏液块、床、蜂蜜等 | 弹性／抑制条件、二次离地、最终停稳、落地后动作接续 |
| B11.4 条件支撑与危险 | 细雪、危险接触方块及状态 | 装备条件；正常状态与危险状态；不满足条件时正确禁用 |

这里不预设这些对象仅具有表格中的一种影响；允许多个处理器共同参与，但其执行顺序须匹配固定版本。

**关键实现：** 预测每一步根据接触位置和模式更新参数。不能用起点材质覆盖整条轨迹，不能把多块接触的参数随意平均。空碰撞的危险仍参与安全检查。对稀有／未实现机制明确拒绝，不把无法识别的接触事件当无效果。

特殊地面改变制动距离和可恢复范围，但不改变职责边界：规划仍使用真实几何和能力可行性；硬检查使用当前模式的完整预测；软缓冲只给已经通过硬检查的控制输入排序。冰面上更早减速属于执行预测，不能通过给冰边附近的规划格子加任意惩罚来替代。

危险区域默认不允许以伤害换路。需要装备才能通过的状态使用独立条件配置；未知装备不是默认满足。掉落方块、脆弱支撑、压力板或其他运动诱发变化必须遵循已冻结策略；复杂动态变化不纳入本批通行保证。

**验收：** 每族的进入、内部运动、离开和动作接续分别测试；同类替换测试与跨类交界测试都通过。对水／攀爬组合等待 B12/B13 后再联合验收，不能提前声称组合支持。

**主要落点：** `block_motion_traits.py`、`world_model.py`、`geometry.py`、地面／空中预测；按需新增 `contact_effects.py`。规划器只消费能力查询，不散落判断具体方块名。

## 11. B12：攀爬及模式转换

**交付：** 按梯子、已登记可攀爬藤蔓族、脚手架分别验收；不得仅靠一个标签断言它们的进入与控制全部相同。

### B12.1 附着状态与预测

节点表达有效攀爬关系、进入方向和可维持状态，而不是伪造脚下支撑。采用独立预测，覆盖上、下、停留、离开及附着条件失效。

### B12.2 路线与进出

地面接近→进入攀爬→上／下移动→顶部或侧向退出→地面动作。退出动作验证身体净空与落地／站立区域；终点不能因为 XZ 相同就完成。

加入 Climb 边时同时核对搜索启发式。无法证明原下界仍不高估时，对含 Climb 的请求使用零启发式，并与独立 Dijkstra 对照。

### B12.3 取消／失联

按模式确定可维持的终态：经验证的附着停留或安全退出，不机械要求所有取消都必须落到普通地面。失联回退经唯一输入出口、具有期限；无法保证长期停留安全时如实终止，不宣称任意攀爬断网都安全。

**主要落点：** `runtime_adapter.py`、`block_motion_traits.py`、`known_map_planner.py`、`action_route.py`、`action_route_executor.py`；新增 `climb.py` 及对应配置／测试。

## 12. B13：水中移动、流动与出入水

**交付：** 静水、已声明范围内的流水和气泡柱、水面／水下运动、呼吸管理、合法出入水及含水形状的组合。

### B13.1 补全流体语义

从布尔 `fluid` 扩展为合法观测的流体类型、状态／高度及确定预测所需的信息。流体运动需要邻域或实际身体受流条件时，说明来源与适用域；缺信息不猜流向。

固体几何与流体影响分开：含水方块可以同时提供固体碰撞和局部液体，不能因为某格有水就全格当不可碰撞或整格未支持。

### B13.2 Swim 与模式边

为水面、水下、上浮、下潜和受流运动建立独立模型；进水／出水是明确的动作边。水中的有效状态不以脚下地面支撑为必要条件。已经知晓的上岸点／呼吸位置必须能进入搜索与资源验证。

气泡柱按上／下方向和终端危险分别验收。未实现或不满足零伤害策略的组合不能通行。熔岩只做危险识别与拒绝，不计作本批 Swim 能力。

加入 Swim、上浮、下潜和受流边时同时核对搜索启发式。无法证明原下界仍不高估时，对含这些边的请求使用零启发式，并与独立 Dijkstra 对照。

### B13.3 呼吸、取消和状态变化

读取实际呼吸与相关状态。验证到下一可靠呼吸点或安全退出点的保守时间预算及余量，不能只对每条小边独立判断后把整条路线错误拼长。呼吸等会改变可达性的资源必须进入路径标签或采用经过反例证明同样完整的方法；最终候选预算检查只能再次核对，不能替代搜索期间的资源状态。

取消先到可安全维持的水面／出水终态；失联时使用有期限的经验证回退，不保证长时间通信断开仍不溺水。水中按键与视角的耦合独立校准，不沿用“pitch 不影响水平 Walk”推断所有模式。

在本包补齐自然的水中低姿态→Crawl→低通道→退出关系；仍不通过直接写姿态或未经授权交互制造入口。强制反例覆盖同一水中位置的快速高耗氧前缀与较慢可完成前缀，确认资源标签不会丢掉后者。

**主要落点：** `world_model.py`、`runtime_adapter.py`、`geometry.py`、`known_map_planner.py`、动作段与接纳；新增 `fluid_motion.py`／`swim.py`，仅在责任确实独立时拆开。

## 13. B14：混合能力选路与效率

**交付：** 在已支持的图和动作上改善路线与真实完成时间，不重新设计整个导航框架。

### B14.1 代价与正确性

统一时间单位；起步、姿态调整、起跳、落地和接续时间计入成本且不重复计费。资源与危险限制先作为硬条件，不能靠较短路径抵消。

新增动作／模式后重新验证启发式。不能继续无条件沿用“四邻接等代价乘曼哈顿距离”。无法证明不高估时使用零启发式作为正确性基线，再引入已证明的下界。控制与规划的收益评分不得替代安全检查。

### B14.2 连续可行捷径与局部路线简化

全局搜索继续使用有限的支撑区域、拓扑节点和动作转换，保证状态规模可控；输出不能把玩家限制为四邻接或八方向折线。对同一支撑区域或一串普通地面边，尝试从当前连续位置直接连接更远的路段端点。连接必须经过统一扫掠、连续支撑、材质、速度和恢复空间验证。

局部跟踪器在已接纳的执行走廊中选择连续方向和速度，可以沿任意安全角度行走。路线简化后重新验证身体轨迹、速度、材质和停止／恢复空间；不能跨过动作边界、切穿拐角或删除事实依赖。

不承诺任意连续空间全局最短时间。报告的是声明的图和代价下最优，以及真实执行效率。

### B14.3 状态规模与预算

采用有限入口状态类、按需生成边和可证明不漏解的支配裁剪。优先复用已有全局路线；地图或身体更新先检查是否影响当前路线走廊，只有相关变化、目标改变、路线失效或出现显著更优路线时才修补或重算。快照、序列化、主线程接纳和局部控制均单独计时。保留后台阻塞／崩溃注入；仅因地图变大或搜索未完成不能撤销安全当前动作。

D* Lite、原生重写、完整 NavMesh 不作为本批必需项；只有基准证明对应瓶颈且不改变契约时再单独立项。

**验收：** 在同图同代价上与独立 Dijkstra 比较；另用独立构造的实际可达场景检查动作边生成遗漏。优化前后使用相同能力、地图、起终态和风险策略比较，保留所有失败。

**主要落点：** `known_map_planner.py`、`planner_worker.py`、`route_admission.py`、`fixed_route.py`、`scripts/benchmark_known_map_planner.py`。

## 14. B15：混合场景、规模与发布验收

**交付：** 已知环境移动发布候选、能力／材质矩阵、原始证据索引和性能报告，不仅是演示视频。

### 14.1 必须冻结的场景组

| 场景组 | 必须覆盖的问题 |
|---|---|
| 普通类替换 | 同几何、不同已确认等价材质 |
| 部分形状 | 半砖上下半、转角楼梯、雪层、薄障碍、跨格形状 |
| 姿态与速度 | 低顶进出、宽窄转角、资源约束、边缘制动 |
| 跳跃／下降 | 各方向和入口扰动、不同目标高度、低顶和错误落地 |
| 连续动作 | 跑—跳—走、落地转弯、多次高差、必要减速 |
| 材质交界 | 普通↔滑移、减速↔普通、落地效果和混合支撑 |
| 攀爬 | 进入、停留、上下、顶部与侧向离开、失去附着 |
| 水域 | 静水、流动、上浮、出水、呼吸不足、含水形状 |
| 混合长路线 | 至少一条包含地面、高差、特殊面、攀爬、水域的路线 |
| 失败与权限 | 不可行、未支持、信息不足、策略禁止和超时各有案例 |
| 生命周期 | 各模式取消、目标替换、输入拒绝、断流、旧世界结果 |
| 规模与持续 | 小／大地图、500 ms 后台阻塞、崩溃、30 分钟运行 |

### 14.2 数值门槛

以下是**拟采用的验收门槛**，不是新增能力的已测成绩。能力级试验延续原 P7/P9，规模试验借用 P10，但不据此宣布原 P10 全部完成。[R1]

| 指标 | 门槛／口径 |
|---|---|
| 强制有效场景 | 全部完成 |
| 每个独立校准的运动模型 | 至少 200 次有效／边界扰动闭环；另加明确不能执行的反例，分别计数。共享同一模型的材质别名不重复凑 200 次 |
| 材质等价类 | 分类清单全量检查；每个等价类选择代表材质做 Fabric 替换试验，并覆盖至少一个错误归类反例 |
| 随机有效组 | 成功率 ≥99%；所有失败保留；不能按运行结果把失败重标为无效 |
| 实机覆盖 | 核心矩阵必须有独立 Fabric 记录；纯 Python 参数化数量不得冒充实机次数。单元、闭环模拟、Fabric 数量分别报告 |
| 可避免安全违规 | 0；禁止穿墙、未知放行、未授权伤害和错误完成 |
| 地面最终到点 | 沿用水平误差 ≤0.25 格、速度 ≤0.1 格/秒及正确层高／支撑；同时必须在实际目标区内。窄区、攀爬、水域使用各自终态，不盲套此值 |
| 动作接续 | 预先声明可连续的组合无人工交接停顿；必要制动有原因记录 |
| 控制计算 | P95 ≤8 ms、P99 ≤15 ms、最大 <30 ms；整帧包含交接与安全复核 |
| 后台阻塞 | 注入 500 ms；当前有足够、已验证的可执行前段时，无新增无谓停车；无安全前段不要求继续 |
| 小图搜索正确性 | 至少 1,000 个有限随机动作图，与独立 Dijkstra 比较；代价误差 ≤`1e-6 × max(1, reference_cost)` |
| 综合随机导航 | 至少 1,000 次可复现的分层随机闭环任务，成功率 ≥99%；主要用于组合覆盖。Fabric 完成冻结的核心场景矩阵和独立运动模型抽样，实机／模拟分开统计 |
| 地图扩大十倍 | 静态远处规模变化下，本地控制 P95 增量 ≤`max(2 ms, 原P95×20%)`；初始载入单独测 |
| 持续运行 | 30 分钟，任务／日志／结果队列有界，无无限等待或无进展抖动 |

发布前冻结 Fabric 核心验收样本数和种子；“至少 200 次”适用于具有独立动力学或控制参数的运动模型，以 Fabric 有效／边界闭环为正式发布门槛，模拟只提供额外组合覆盖。普通石材、木板、玻璃等已证明共用同一模型的材质，通过分类清单、代表替换和反例验证覆盖，不为每个注册名重复运行 200 次。综合 1,000 次任务用于可复现的闭环组合覆盖，不要求全部在 Fabric 中重复；正式发布结论仍必须有对应的 Fabric 核心场景和代表抽样，且不能把同一次运行拆成多个成功任务。任务过重时可先发布 B10 的有限能力里程碑，但不能降低 B15 后再沿用原声明。

大批量试验开始前必须冻结单批磁盘配额、原始轨迹保留规则和自动清理规则。失败、边界样本、汇总指标与可复现元数据长期保留；可从这些数据重新生成的逐帧网页、重复截图、临时世界副本和中间渲染产物可以按规则清理。清理不得删除用户世界、唯一失败证据或发布清单引用的文件。

100% 强制通过和有限样本中的 ≥99% 是工程验收结果，不是任意真实地图上的数学成功保证。

### 14.3 不能混淆的效率指标

分别记录首次路线延迟、主线程计算、输入发送／应用延迟、真实游戏完成时间、无谓停车、必要减速、动作切换、资源消耗和重试。

旧三版没有公平基线的场景不计算速度提升；新旧能力不同的路线也不直接比较总耗时。冻结 B05 作为已支持范围回归，再在新增场景建立同能力、同权限、同起终态的优化前后对照。只有图中最短路证据不能证明真实运动最快。

## 15. 一直保留的架构约束

1. 单一 MotorGateway／动作出口；能力、规划器、诊断和测试夹具不能并行写玩家输入。
2. 世界事实只有一个拥有者。注册表规则可复用，具体位置知识仍遵守 D004；D003 的穿透诊断原型不重新启用为正式感知。
3. 路线是意图，执行许可绑定当前身体、当前能力／策略配置和相关局部事实。除世界依赖外，身体配置、能力版本与风险约束变化也要检查，不能只验几何哈希。
4. 按影响范围保留安全前段。相关变化停止授权，无关变化不重置路线；已经收到的变化不能因本批不做动态避让而忽略。
5. 已知不等于不变。具有未实现时变机制的场景不进入通行保证；输入中断、环境改变和资源变化仍有模式式失败／取消出口。
6. 地面停止、空中落地、攀爬维持和水中呼吸不是同一终态。失联回退必须有期限且可验证；不声称不可控长时间断网必定安全。
7. 每条边校验整个轨迹及恢复空间，不只验起终点。输入回执与实际状态不同；不能以发出动作判成功。
8. 正式实机只使用独立 Fabric。现有 CraftGround 共享契约适配继续做必要自动回归，不启动第二套实机验收。[R7]
9. 规划只使用真实几何、动作可行性和明确的路线成本。执行软缓冲不进入全局路径准入或边代价；它只在局部控制中处理误差和惯性。
10. 每个新增动作在加入规划图的同一阶段验证启发式和累计资源。不能等到 B14 才发现搜索会漏掉更优路线，或路线整体资源不足。

## 17. 每个小任务的固定交付方式

每个小任务只围绕一个可拒绝或接受的行为变化：

- 写清需求编号、输入、预期状态及能力边界。
- 增加失败反例并确认在修改前失败；不把缺依赖环境失败当业务反例。
- 修改最少的契约、消费者和实现；保留旧能力默认行为。
- 运行该反例、邻近边界、受影响组件回归和必要 Fabric 探针。
- 提交修改路径、接口差异、实际命令、逐项结果、失败原始证据和未验证范围。

现有完整工程中可沿用的组件命令：

```powershell
D:\Miniforge3\Scripts\conda.exe run --prefix D:\My_project\mc_ai\.venv --no-capture-output python -m unittest discover -s tests/motion_nav -p 'test_*.py' -v
```

该命令在独立源码快照中可能因缺少原工程依赖而不能运行；不得据此伪称已通过。新增阶段探针命令必须在实现后写入各自 acceptance 文档，不能把本计划中的新文件名当成现有 CLI。

**最先开始的实际任务是 B06.1：核对已经锁定的 1.21 环境、建立证据来源边界和旧能力回归。** 随后做 B06.2–B06.4，不先写 Swim、Climb 或完整新规划器。

## 18. 发布口径

B10 可以发布“已知普通复杂地形连续移动”里程碑：普通／常见部分形状、Walk/Sprint/Crouch、跳跃／下降、连续方向跟踪与动作接续。Crawl 可以报告已合法进入后的保持、移动和退出，但完整入口能力要等 B13 的水中转换通过后再发布。

B15 才发布第二批的“已知环境多能力移动”版本：在冻结材质／行为清单、身体条件、动作范围和风险策略内，对已知且可达的目标能够可靠、连贯、高效到达；不满足时返回真实原因。

不能使用“任意原版地形、任何位置均可到达”作为未经限定的承诺。需要道具、交互、世界修改、动态设施或未实现机制的目标，明确排除在本版本可达性保证之外。
