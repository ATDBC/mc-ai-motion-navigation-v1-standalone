# C1 战斗纵切片 V1

日期：2026-09-24
状态：C1-A、C1-B 与 C1-C 均已完成正式 Fabric 验收

## 1. 要解决的问题

B10 已把正式观察、状态锚点、规划、动作证明、路线接纳、输入回执和连续执行接成一条链。C1 用一个很小的近战任务检查共享观察、Runtime、仲裁、唯一输入出口和回执能否服务导航以外的目标。

C1 不追求完整战斗系统。它先证明机器人能够识别一个目标，使用现有平地导航进入攻击位置，复用视角控制对准目标，通过唯一输入出口发出一次合法攻击，并根据后续正式观察确认命中。C1-A 至 C1-C 的接近和追击仍使用旧 `PointGoalPolicy("D")`，没有验证战斗已经接入 B04–B10 的 `motion_nav` 规划和执行主线；该迁移由 C1-R 单独完成。

## 2. 分步范围

| 子阶段 | 交付内容 | 暂不包含什么 |
|---|---|---|
| C1-A | 已知平地中接近一个固定、持续可见、关闭 AI 的敌人，稳定瞄准并确认一次命中 | 移动中攻击、敌人还击、连续攻击、装备切换、食物、盾牌、跳劈和世界修改 |
| C1-B | 一只正常移动的僵尸；按冷却重新接近并连续攻击，直到合法确认目标死亡 | 多敌人、远程敌人、主动修改世界 |
| C1-C | 敌人可以还击；机器人受击后继续履行动作责任并恢复路线 | 完整威胁预测、复杂战术和学习策略 |

本文保留 C1 的共同边界和 C1-A 架构。C1-B 的增量设计见 [C1-B 移动目标连续近战](C1B-moving-target-melee-v1.md)。C1-C 的动作责任、外部运动和路线恢复见 [C1-C 外部运动与受击恢复](C1C-external-motion-recovery-v1.md)。

## 3. 采用的连接方式

战斗任务编排现有模块，不建立第二个游戏输入出口：

- 战斗任务拥有目标、目标修订、阶段和任务结果；
- 当前旧平地导航负责到达攻击站位；
- 现有视角控制和动作仲裁负责对准目标；
- 新的有类型近战操作通过现有唯一输入出口提交；
- 正式观察和输入回执共同确认执行结果。

攻击不进入地形路径图。地形图负责到达站位，攻击能力负责判断武器能否从当前状态作用于目标。

## 4. 状态归属

| 状态 | 唯一拥有者 | 其他模块怎样使用 |
|---|---|---|
| 世界方块、支撑面和路线依赖 | 现有世界知识层 | 导航和能力查询只读 |
| 当前身体状态和攻击冷却 | 正式观察层 | 战斗任务、导航和攻击检查只读 |
| 实体可见事实 | 正式实体观察 | 目标和战斗感知只读 |
| 当前战斗目标及修订 | 战斗任务 | 导航、瞄准和攻击请求绑定同一修订 |
| 当前导航路线 | 现有导航层 | 战斗任务只接收进度和终态 |
| 视角请求 | 现有视角控制／动作仲裁 | 战斗任务提交目标要求，不直接写 yaw/pitch |
| 最终输入和真实应用账本 | 唯一 `MotorGateway` | 所有技能只提交意图并读取回执 |
| C1 任务阶段 | C1 任务执行器 | 不复制地图、路线、视角或输入状态 |

## 5. 目标与交战记忆

### 5.1 目标身份

战斗目标至少绑定世界会话、任务目标 ID、目标修订和实体 `track_id`。目标取消、替换或修订后，旧导航请求、瞄准请求、攻击请求和等待确认状态全部失效。

实体暂时被遮挡不会让目标本身失效。能否使用某种攻击由该攻击能力判断。

### 5.2 两种位置来源

实体位置保留明确来源：

- `VISION`：机器人当前直接看见该实体；
- `ENGAGEMENT`：机器人曾直接看见该实体，并确认机器人对它造成过一次命中；首版据此采用“目标会按原版报复规则继续交战”的简化授权。

进入 `ENGAGEMENT` 后，只要客户端仍在收到该实体的权威位置更新，战斗层可以使用其准确位置，即使中间存在视觉遮挡。这是“交战后仍能根据生物行为持续掌握其位置”的简化规则，用来避免首版引入速度外推和不确定范围。

该规则受以下限制：

1. 从未直接看见的实体不能凭追踪事实建立目标；
2. 不适用于服务器上的任意玩家，只适用于机器人和任务明确登记的友方玩家；
3. 实体死亡、卸载、换维度、任务取消、目标修订或权威更新过期后，`ENGAGEMENT` 立即失效；首版没有直接观察“仇恨结束”事实；
4. 最后一次位置在更新过期后只能作为历史，不能继续宣称是当前位置；
5. 该位置不会揭示周围地形、其他实体或新的攻击权限。

C1-A 的敌人关闭 AI 且持续可见，因此只依赖 `VISION`。`ENGAGEMENT` 从 C1-B 起进入正式实机范围。

## 6. C1-A 阶段流程

```text
ACQUIRE_TARGET
  → APPROACHING
  → ALIGNING
  → WAITING_COOLDOWN
  → ATTACK_SUBMITTED
  → CONFIRMING_HIT
  → COMPLETE
```

1. 取得仍属于当前世界会话和目标修订的固定敌人。
2. 在已知平地上计算距目标约 2.5 格的稳定站位，并向现有导航层提交点目标。
3. 导航完成且身体稳定后，释放接近请求，提交对准目标的视角要求。
4. 正式准星目标必须是同一个 `track_id`，攻击冷却必须满足近战能力要求。
5. 提交一次 `AttackEntityV1`。
6. 客户端再次检查目标、距离、准星、界面和冷却，再调用普通客户端攻击。
7. 输入回执只确认攻击请求已经执行；后续实体观察确认同一目标进入受击动画后，任务才报告命中。

C1-A 不允许通过累计控制帧猜测已经命中。

## 7. 近战操作和命中确认

### 7.1 `AttackEntityV1`

首版新增一次性正式操作：

```text
AttackEntityV1(entity_ref)
```

客户端执行前核验：

- 当前准星命中实体；
- 当前实体 `track_id` 等于 `entity_ref`；
- 普通近战距离成立；
- 当前界面允许攻击；
- 攻击冷却满足当前能力要求；
- 请求和观察锚点仍有效。

任一条件失败都返回有类型的拒绝原因，不能改为攻击准星下的另一个实体。

目标修订由战斗任务在提交前核验，并绑定本次候选和意图。客户端不保存第二份任务目标状态。

### 7.2 命中证据

正式实体观察增加客户端可见的受击动画剩余 tick。一次 C1-A 命中必须同时满足：

1. `AttackEntityV1` 获得与请求严格关联的执行回执；
2. 在冻结的确认窗口内，同一 `track_id` 从未受击状态进入受击动画；
3. 世界会话、目标 ID 和目标修订没有变化。

固定竞技场内没有其他伤害来源，因此该变化足以确认 C1-A 命中。后续存在多个攻击来源时，这项信息只能证明目标受伤，不能单独证明伤害来自机器人。

不暴露目标血量来替代命中确认。

## 8. 遮挡与以后能力的接口

目标在墙后不构成永久禁止。每种能力声明自己的作用条件：

- C1-A 近战要求普通客户端射线能够命中目标；
- 将来的远程或穿透武器按自己的弹道、材料和厚度规则判断；
- 若任务允许改变世界，规划层可以组合“挖开合法位置 → 重新确认目标 → 接近或取得作用路径 → 攻击”。

因此，当前遮挡结果表达为“目标仍有效，但当前近战候选因作用路径阻挡而不可行”。战斗任务不能自行绕过 B11 的世界修改权限。

首版不建立通用武器插件框架。以后新增攻击方式时增加新的有类型能力及其条件，目标和交战记忆的语义保持不变。

## 9. 取消与失败

- 攻击提交前取消：撤销接近和瞄准，按现有地面规则释放输入，不攻击；
- 攻击已经提交：一次性攻击无法撤回，继续记录是否发生命中，但任务结果为“提交后取消”；
- 目标修订变化：旧请求全部失效，不能转而攻击当前准星下的其他实体；
- 导航无路、瞄准超时、冷却条件不成立、仲裁拒绝、客户端拒绝、回执缺失和命中确认超时分别报告；
- 攻击调用成功不能伪装成命中成功；
- 正式观察或关键记录存在缺口时，本次运行不能作为完整的成功证据。

## 10. 固定种子、记录和离线重放

每局保存世界种子、场景种子、决策平手种子、地图和出生条件、装备、游戏版本、代码提交及配置摘要。C1-B 以后使用事前冻结的种子集合，不能根据结果删除困难种子。

完整观察流按客户端运动 tick 保存一次。其他记录引用观察序号，不复制整份观察。每层记录自己的输入和输出，并用以下身份串联：

```text
run_id
observation_sequence_id
world_tick
target_id / target_revision
decision_generation
candidate_id
skill_execution_id
proof_id
intent_id
request_sequence_id
```

记录链为：

```text
正式观察
  → 局势评估
  → 候选集合及淘汰原因
  → 选中的候选
  → 技能计划与动作证明
  → 仲裁后的最终命令及各控制组来源
  → 真实输入应用、回执和运动结果
```

失败分析寻找最早出现的契约断点，分类为：

- 局势评估错误；
- 候选集合缺少正确选项；
- 存在正确候选但选择错误；
- 技能执行没有遵守动作证明；
- 仲裁拒绝、替换或组合命令后破坏了前提；
- 最终命令正确，但输入应用或运动层返回失败。

后续连锁失败不能覆盖更早的根因。

复用现有分段证据格式。完整观察通过有界、非阻塞的日志队列写出；队列满时记录缺口数量，不能阻塞控制。存在观察或关键因果记录缺口的运行可以保留为失败证据，但不能用于完整离线重放或正式成功率。

离线重放只验证上层逻辑：把已记录的正式观察按原序列交给局势评估、候选生成和规则选择，检查输出是否一致。它不声称仅靠观察流重演服务器物理或生物 AI。

## 11. 不变量

1. 战斗不建立第二份地图、身体状态、路线、视角状态或输入出口。
2. 目标身份和攻击资格分开表达；遮挡不删除目标。
3. `ENGAGEMENT` 只扩展已确认交战实体的位置来源，不扩展地形知识和攻击权限。
4. 攻击必须绑定实体身份，不能退化为无目标的通用点击。
5. 执行回执和命中证据分开表达。
6. 取消、目标修订和世界会话变化会让旧候选失效。
7. 记录不能参与或改变正式决策；日志阻塞不能阻塞控制。
8. C1-A 不主动修改世界，不切换物品，不使用消耗品，也不引入学习模型。
