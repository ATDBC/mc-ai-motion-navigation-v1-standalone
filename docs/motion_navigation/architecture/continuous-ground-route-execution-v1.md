# 连续地面路线执行 V1

日期：2026-10-07。状态：已实施，冻结范围已通过 Windows 组合、串行性能和 Fabric 正式验收。

## 1. 要解决的问题

搜索图继续使用支撑面的代表点。以后路线优化器会把搜索结果改成更短、更自然的连续折线，折线中的点通常不在格子中心。

实施前，`FixedRouteController` 已经能投影到任意坐标折线，但安全判断有三项粗限制：

- 快速预测只要碰到墙，就否决整组输入；
- 路线靠近支撑边缘时，只会提高风险或失败，不会使用原版潜行防坠；
- 最终位置用一个点和很小的容差表达，贴墙或位于边缘时经常无法停进目标。

本设计不改变中心点搜索。它补齐连续地面折线的执行能力，并把终点接近作为第一个实际用例。

## 2. 现有能力和边界

`FixedRoute` 已保存任意浮点坐标。`_RouteGeometry.project()` 已按连续折线计算进度和横向误差。因此首版不新增另一套路线、曲线或走廊类型。

现有 `maximum_cross_track_blocks` 继续定义普通路线走廊。路线优化器以后只需输出 `FixedRoute` 点列，并沿用同一套执行和安全判断。

本阶段不修改：

- 已知图搜索和中心点节点；
- Session、ExecutionSupervisor、Runtime 生命周期；
- 连续高度证明和严格空中动作；
- 未知探索、动态实体避让、疾跑路线优化。

## 3. 两级候选判断

普通开阔地继续使用现有平面快速预测。只有候选因为已知水平碰撞或支撑边界而失败时，才进入完整计算器复核。

完整复核读取正式 `StateAnchor.physics_state`，并用 `physics_1_21.step()` 推演：

1. 整个输入租约；
2. 松键后的完整停止尾迹；
3. 每个 tick 的真实碰撞后位置、速度、支撑和姿态。

每帧最多复核快速排序最靠前的三个候选。候选数量固定，不能用墙钟决定是否继续检查。每帧复用同一个 `WorldQueryCache`，不增加后台任务或长期缓存。

缺少正式物理状态时保留原结果，不能用推测状态放宽候选。

## 4. 墙面接触按结果判断

已知普通无害方块造成的水平碰撞，不再自动使候选失败。完整复核后同时满足以下条件才接受：

- 身体没有进入未知、危险、流体或未支持方块；
- 身体仍在路线走廊和声明高度范围内；
- 输入租约和停止尾迹都有足够支撑；
- 接触后沿路线取得正进展，或者最终进入终点站立区域；
- 停止尾迹不会把身体带出安全范围。

这条规则适用于整条普通地面路线。沿墙移动时，墙只裁掉横向位移，沿路线的位移可以继续。正面撞上中途墙且没有进展时，候选仍然失败并交回现有重规划入口。

接触后的状态必须来自计算器。不能把扫掠首次碰撞比例直接当成身体最终位置。

## 5. 路线段能力

潜行会改变输入和姿态，不能在所有靠边路线中自动启用。新增不可变的 `GroundRouteExecutionContract`，由 `FixedRoute` 可选持有：

```text
completion_region: GroundCompletionRegion | None
capability_intervals: tuple[GroundRouteCapabilityInterval, ...]
dependencies: tuple[BlockPos, ...]
rule/profile identity
```

首版能力只有 `SNEAK_EDGE_GUARD`。每个能力区间使用路线累计进度的起止值，不按场景名称或动作类型判断。

中心点搜索生成的普通中途路线不声明该能力。只有普通停止尾迹无法满足支撑要求、声明区间可被计算器证明时，路线接纳才为末段声明它。原目标内存在普通安全点时优先选该点。未来路线优化器若主动选择靠边路线，也可以使用同一契约。

契约依赖变化时，沿用现有路线失效和重规划规则。

## 6. 潜行防坠

当前进度进入 `SNEAK_EDGE_GUARD` 区间，且普通候选会失去支撑时，控制器才比较潜行候选。

潜行候选必须由计算器证明：

- 出现原版 `sneak_edge_clipped` 行为或等价的边缘裁剪结果；
- 每个 tick 保持已知支撑，没有下落和伤害；
- 身体仍沿路线取得进展；
- 松键尾迹安全。

离开能力区间或到达终点后，控制器停止请求潜行。若目标要求站立，控制器继续持有身体责任，等待正式观察确认允许的姿态。取消、目标变化、输入失联和外力继续走现有共同路径，不新增第二套生命周期。

能力授权使用当前身体在折线上的实际投影，不使用历史累计最大进度。离开区间后禁止带方向的潜行输入。若立即松开潜行的尾迹不安全，只能有界地保留中性潜行，先停住再释放；该过程单独记录 `OUTSIDE_STOPPING`／`OUTSIDE_RELEASING`，不能借它继续沿区间外移动。

## 7. 终点区域

新增不可变 `GroundCompletionRegion`。它表达原 `GoalState`、支撑面和身体净空共同允许的站立区域。首版只接受可准确表达的轴对齐矩形；不连续区域明确返回不支持，不能用外接矩形填补。

路线接纳按以下顺序选择参考点：

1. 将入射路线投影到完成区域，避免先去格心再折返；
2. 路径长度相同，选择边界余量更大的点；
3. 使用固定坐标顺序打破平手。

参考点只引导接近方向。完成判断使用整个区域，并继续检查原 `GoalState` 的模式、姿态、速度和朝向。终点逻辑不拥有另一套移动控制器。

`standable_region_in_goal` 返回区域与候选选择依赖；区域自身单独保存执行所需的支撑、净空及边界形状依赖。surface、ground-direct 和 local-direct 的最终普通 Walk 使用同一查询与契约构造，入口不改变完成语义。

活动路线用 `STANDABLE_REGION` recipe 复核区域依赖。它保存原支撑面、原目标范围、进入点、身体尺寸、支撑门槛与预期区域，由独立 `COMPLETION_REGION` owner 负责。变化后重查当前支撑面并重放同一查询；仅当范围、参考点、支撑高度与支撑面身份严格一致时继续，随后刷新依赖。区域改变按既有路线失效处理。点直连证明、原路线腿和原非 recipe 责任保持各自归属，不加修订号豁免。最多增加一个区域查询，仍共用每帧四个查询的预算。

## 8. 模块职责

| 模块 | 负责什么 |
|---|---|
| `support_surfaces.py` | 计算目标、支撑与净空的精确交集和依赖 |
| `ground_route_execution.py` | 保存完成区域、能力区间和纯判断结果 |
| `route_admission.py` | 为最终 Walk 绑定完成区域和需要潜行的进度区间 |
| `route_validation.py` | 重放区域与点直连各自的证明，保留原依赖和身份约束 |
| `fixed_route.py` | 跟踪任意坐标折线；快速失败时有限调用完整复核 |
| `safe_ground_control.py` | 用计算器验证输入租约、停止尾迹、碰撞后进展和潜行防坠 |
| `action_route_executor.py` | 传入正式物理状态；证明首次静止入口的中性启动余量，不解释墙面或边缘场景 |

Session、监督者和 Runtime 不增加本阶段专用分支。

### 首条普通 Walk 的启动窗口

启动窗口表示首条命令可以在哪个 tick 开始。实机验收发现，旧余量只适用于两点直线，正式搜索交付的多点折线会把晚一 tick 的首条命令记为窗口外输入。

现在只对首次静止普通 Walk 补一项证明。原候选已经验证输入租约和完整停止尾迹，再由现有计算器验证一 tick 中性前缀。正式预测状态必须匹配当前帧；前缀的位置、速度在 `1e-9` 内不变，姿态、碰撞、模式等其他字段逐项相等。效果或冷却变化、未知、失去支撑和不匹配状态都不给余量。前缀是一个单独的 physics step，不增加完整候选数量。

有组合视角时，使用状态锚点经过本帧已声明视角投影后的预测状态。移动仍依赖该视角胜出。视角失选时，移动和启动窗口一起被抑制，不能采用它的余量。

证明通过后，沿用 `MovementTickWindowV1` 表达最早下一 tick、最晚下下 tick。公共命令仍只生效一 tick，不扩大租约，也不改变空中动作的晚到证明。

## 9. 性能边界

- 无碰撞且支撑充足的普通路线逐项保持原快速路径；
- 完整复核每帧最多三个候选；
- 先按快速分数排序，再复核可能获胜的候选；
- 完整复核复用当前帧世界查询；
- 不增加全图查询、后台 rollout 或持久缓存；
- Windows 控制帧继续满足现行 P95 `≤ 8 ms`，并单独报告完整复核帧的 P50、P95、P99 和最大值。

如果完整复核连续两轮不能满足门槛，停止当前实现。可以先去掉重复查询，不能缩短安全尾迹或按机器速度改变候选。

## 10. 不变量

- 搜索代表点不是执行必须经过的点。
- 任意坐标路线仍受同一走廊、支撑、材质和未知边界约束。
- 墙面接触只有在碰撞后仍有路线进展或合法完成时成立。
- 中途正面撞墙不能因“安全接触”继续占有输入。
- 潜行只能在契约声明的进度区间启用。
- 未知、危险、流体和未支持材质不能成为停车墙或边缘依据。
- 完成区域不能扩大原 `GoalState`。
- 行为不依赖墙钟。
- 严格空中动作及其证明不因本阶段放宽。
