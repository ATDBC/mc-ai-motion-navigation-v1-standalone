# C1-C 外部运动与受击恢复 V1

日期：2026-09-24
状态：已实现；C1-C 正式验收与 C1-R R3 复测均通过

## 1. 要解决的问题

C1-B 屏蔽了僵尸造成的伤害和击退，只验证移动追击、连续攻击和死亡确认。C1-C 处理机器人身体被当前控制命令之外的力量改变以后，谁继续负责身体、哪些旧结果失效，以及怎样恢复路线。正常战斗回归与受击恢复验收分开：前者保留正常 AI，后者用受控时机调用原版攻击入口，避免安全的压制策略让恢复链永远得不到输入。

受击、实体挤压和活塞推动的来源不同，但都会造成同一个运动问题：实际位置或速度无法由已经应用的输入单独解释。因此，运动层使用一条共用的外部运动处理链。C1-C 首版只正式识别并实测僵尸攻击造成的伤害和击退。实体挤压、活塞推动和原因不明的运动偏差以后增加自己的证据与场景，不复制恢复控制器。

## 2. 现有能力与缺口

现有代码已经能够：

- 从正式观察取得玩家位置、速度、生命和接地状态；
- 用实际应用账本确认哪些输入真正进入游戏；
- 在动作入口状态不符时拒绝旧候选；
- 检测路线偏差、无进展和部分安全检查失败；
- 在空中取消后继续承担落地责任；
- 根据当前速度执行地面制动。

现有 `unsupported_motion` 表示游泳、攀爬、飞行、未支持姿态或未分类材质，不表示身体受到了外力。现有导航恢复处理路线拒绝和无进展，也不拥有外力事件。C1-C 补齐两项能力：形成可追溯的外部运动事件，以及在事件发生后串联动作失效、身体恢复和重新锚定。

## 3. 模块职责

| 状态或工作 | 唯一拥有者 | 说明 |
|---|---|---|
| 玩家生命、受击状态、位置、速度和接地事实 | 正式观察层 | 只保存客户端实际观察，不判断路线和任务 |
| 已经实际应用的输入 | Runtime 的 `InputApplicationLedger` | 读取唯一输入出口的提交与回执；记录实际生效、覆盖和歧义 |
| 预测外运动 | `MotionResidualTracker` | 从状态锚点、实际输入账本、世界快照和 B09-R 计算器得到 |
| 伤害与运动来源 | `DamageKnockbackDetector` | 分别保存伤害事实和运动残差；满足来源条件后只形成一个事件 |
| 当前恢复过程 | 外部运动恢复控制器 | 同一时刻最多一个，负责落地、制动和稳定确认 |
| 路线、动作证明和状态锚点 | 现有运动／导航层 | 按事件代次让受影响结果失效，并从新锚点继续 |
| 战斗目标、命中确认和任务终态 | C1-C 战斗任务 | 保留目标；不自行计算制动或写按键 |
| 最终移动、视角和攻击输入 | 现有仲裁与 `MotorGateway` | 不增加第二个输入出口 |

## 4. 正式观察与外部运动事件

### 4.1 玩家自身受击事实

正式玩家观察增加自身的受击动画剩余 tick。它与生命、位置、速度、接地状态使用同一个客户端采样边界。缺失、越界或来自旧世界会话的值按契约拒绝，不能补成零。

当前实现先分别取得伤害事实和运动残差，再判断来源。伤害事实在以下条件下建立：

1. 新观察属于同一世界会话，采样顺序严格前进；
2. 玩家自身受击动画从零进入正数，形成一次受击过程；
3. 生命与吸收心的合计值在该受击过程开始时或随后的同一受击过程中下降；
4. 该伤害事实尚未被当前检测器消费。

客户端可能先观察到受击动画，下一次正式观察才看到伤害量。检测器会在同一受击过程中保留受击前的生命与吸收心基线，等伤害量到达后只生成一个事实。受击动画归零后，这个基线失效，不能跨到下一次受击。

运动残差从上一状态锚点开始，按实际输入账本逐 tick 使用 B09-R 计算器推演，再与新观察比较位置、速度和接触状态。缺少输入回执时返回 `NEEDS_INPUT`；缺少所需世界格时返回 `NEEDS_WORLD`，并把这些格加入下一帧观察请求。残差查询优先于规划的大批量查询，避免伤害来源在等待期间超过可重放窗口。

`DAMAGE_KNOCKBACK` 只有在以下条件同时成立时产生：存在尚未消费的伤害事实；存在覆盖实际伤害 tick 的完整残差；该残差达到预测外运动门槛。着火、中毒或摔伤若没有运动残差，只保留伤害事实，不启动位移恢复。只有预测外运动而没有伤害来源时，报告 `UNATTRIBUTED_EXTERNAL_MOTION`，不能宣称为僵尸击退。

伤害事实可以早于完整残差到达。检测器会有界保存事实，直到残差覆盖伤害 tick；它不会拿伤害前或伤害后的无关偏差补作来源。残差最多回放 8 个运动 tick，超过窗口后明确重新锚定并报告输入不完整，不能无限追赶旧观察。

事件保存伤害前后的身体状态、生命与吸收心变化、观察序号、客户端运动 tick、残差区间和依赖的实际输入。速度和位移只描述运动影响；来源判断仍需要上面的事实组合。

### 4.2 扩展其他来源

以后可以增加：

- `ENTITY_PUSH`：实体接触证据和无法由输入解释的运动；
- `PISTON_PUSH`：相关方块变化、身体接触和无法由输入解释的运动；
- `UNATTRIBUTED_EXTERNAL_MOTION`：偏差成立，但没有足够证据确认来源。

新增来源只扩展事件生产者。恢复控制器仍读取实际身体状态、已知空间和恢复限制，不根据来源名称硬编码按键。

## 5. 责任交接和失效范围

外部运动事件在下一个有效控制机会进入处理。事件被观察前已经在途的输入按真实应用情况记录，不能倒写为未执行。事件被接纳以后：

1. 当前移动动作不再依据受击前连续状态产生新输入；
2. 受击前的动作证明、执行窗口和状态锚点失去执行资格；路线只撤销实际受影响的前段；
3. 已接纳的后台结果即使稍后到达，也因旧事件代次而被拒绝；
4. 当前战斗目标、交战记忆、已确认命中和世界知识继续保留；
5. 已提交的一次攻击继续等待回执和命中事实，但不能重复提交；
6. 尚未提交的瞄准和攻击资格失效，恢复后必须重新取得。

这次处理不能通过直接清空输入完成。若现有导航能够从新状态安全续行，它继续作为唯一移动责任方；否则原动作明确交出当前身体状态，专用恢复控制器再接管。空中不能为了恢复默认控制器而替换仍承担落地责任的动作。视角和一次性攻击结果仍按现有仲裁规则收尾。

## 6. 恢复流程

事件形成后，先判断现有导航责任方能否直接从新连续状态继续：

- 身体已经接地、当前位置有已知安全支撑，并且当前导航请求仍有效时，`NavigationSession` 重新读取真实状态。原导航责任方继续工作，下一次路线执行照常检查入口和局部安全，不要求先把速度降到零；
- 身体离地、支撑未知、导航契约已结束或当前位置没有合法支撑时，进入专用身体恢复；
- 直接续行只保留同一个任务和导航拥有者，不保留受击前已经失效的连续状态证明。后续动作仍需用新观察重新满足入口。

专用身体恢复状态依次为：

```text
CAPTURED
  → AIRBORNE_SETTLING / GROUND_BRAKING
  → STABILITY_CONFIRMING
  → REANCHORED
  → COMPLETE
```

- `CAPTURED`：封存事件、受影响的旧路线前段和当前实际身体状态；
- `AIRBORNE_SETTLING`：身体离地时提交中性水平移动，不使用受击前路线改变落点；
- `GROUND_BRAKING`：接地后复用普通地面模型，从实际速度计算有界制动；
- `STABILITY_CONFIRMING`：连续两个新客户端运动 tick 接地，且水平速度不高于现有点目标默认停止门槛 `0.03` 格／客户端 tick；
- `REANCHORED`：用最新正式观察和输入账本建立新状态锚点；
- `COMPLETE`：把控制权交回当前任务的导航或动作执行器。

一次专用恢复从首个事件起最多持续 40 个客户端运动 tick。恢复期间再次确认受击时，不并行创建第二个控制器；更新当前恢复所用的身体状态，并把新的受击计入任务恢复次数。该分支由确定性组件检查覆盖。实机重复受击在第一次恢复完成、受击动画清零后再次调用原版攻击入口，形成第二次独立恢复。单个任务最多接纳四次真实受击恢复。达到任一上限后报告 `external_motion_recovery_exhausted`，不能无限前后修正。

C1-C 已知完整平地允许中性空中输入。这个结论不能外推到坑边、悬崖、流体或活塞夹压。以后进入这些场景前，恢复控制器必须取得相应的已知空间和恢复包络。

## 7. 路线和战斗恢复

稳定后，战斗任务继续使用原目标 ID、目标修订和交战记忆。它读取目标的最新合法位置，重新建立当前攻击站位，并从新锚点提交局部导航请求。

攻击站位使用半径为 `0.25` 格的动态目标区域，并保留 `0.05` 格攻击余量。目标移动后，如果旧站位区域已经不能保证进入攻击距离，原终点立即失效。这样可避免路线在距离目标约 3 格处提前完成，随后反复等待攻击资格。

当前实现不会无条件丢弃整条路线。已接地且支撑安全时，同一个 `NavigationSession` 从新连续状态重新检查当前路线；入口仍成立的后缀可以继续使用。身体恢复或入口失效时，只撤销受影响的活动前段，并从当前位置请求必要的局部修复。世界知识和未受影响的后台地图保留，因此这不是重启整个任务或重建全图。

目标在恢复期间死亡时，任务进入死亡确认收尾，不重新接近。目标卸载、位置过期、目标修订、世界变化和任务取消继续按 C1-B 的有类型结果处理。

## 8. 记录

每次事件和恢复至少记录：

- 事件 ID、来源、世界会话、观察序号和运动 tick；
- 受击前后的生命、位置、速度和接地状态；
- 该区间内已知的实际应用输入；
- 被撤销的动作、路线和状态锚点代次；
- 每个恢复阶段、产生的移动意图及实际回执；
- 稳定确认、重新锚定和新路线请求；
- 恢复次数、耗时和最终结果；
- 战斗目标、攻击提交和命中确认是否在事件前后保持正确。

离线重放验证伤害归因、事件去重、失效范围、阶段选择和任务恢复。它使用实机日志里已经计算出的运动残差，不独立重演服务器击退物理。

正式记录直接保存父任务交出责任、恢复控制器每次状态决定、实际仲裁和输入回执。离线重放从真实观察重建外部运动事件，并重新运行恢复状态机。场景结束后的汇总行只用于统计，不能替代这些逐帧证据。

受击观察完成时间和输入实际应用时间使用同一个客户端单调时钟。租约和超时仍使用原始 JVM 时钟，两者职责分开。旧路线被打断时当场应用的中性移动已经属于恢复的第一步；随后专用恢复源接管不会让计时重新开始。

## 9. 不变量

1. 外部运动不会建立第二份身体状态、路线、世界知识或输入出口。
2. 受击证据、运动影响和恢复结果分别表达。
3. 无受击证据的运动偏差不能被宣称为僵尸击退；它只能形成未归因外力。
4. 现有导航安全续行时保持原责任方；需要专用恢复时，旧动作明确交出责任以后恢复控制器才接管。
5. 空中或尚未稳定时，任务不能直接恢复旧路线输入。
6. 已提交的一次攻击不会因受击而重复提交。
7. 外力使动作证明失效，不会自动删除战斗目标和交战记忆。
8. 每次恢复有明确期限，任务恢复次数有明确上限。
9. C1-C 的平地结论不能证明坑边、悬崖、活塞夹压或多实体挤压安全。
10. 战斗任务已经确认命中或死亡后，外部运动恢复不会把终态重新打开。
