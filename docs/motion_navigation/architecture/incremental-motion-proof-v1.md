# 连续动作控制器与增量安全证明 v1

状态：D097 设计，尚未接入正式 actor。

## 1. 数据流

```text
动作模板＋当前入口
        ↓
离线表选出最多三组参数
        ↓
确定性控制器生成具体输入计划
        ↓
计划建立：两支 rollout 与目标／出口检查
        ↓
每次提交前证明下一边界安全
        ↓
Runtime 仲裁与真实输入账本
        ↓
新观察重新锚定或继续已锁定后缀
```

表和控制器都不能发送输入。只有增量证明产生本 tick 的许可，Runtime 仍是唯一真实输入出口。

## 2. 主要对象

### `MotionTemplateParameters`

保存步态、起跳触发距离、空中模式和落地模式。它不保存身体状态。

### `MotionTemplateRow`

保存动作模板、入口子域、参数、候选承诺／恢复边界、出口范围及版本身份。入口、参数和出口保持同一行关联。

### `PreparedMotionPlan`

从实际入口生成的不可变计划。至少保存两支入口、共同输入、逐边界状态、候选风险区间、目标／出口要求和世界依赖。

### `IncrementalMotionPermit`

只授权一条具体命令及其生效窗口。保存本次使用的状态锚点、输入账本摘要、证明边界、必要停车尾迹和依赖。它不能被修改成另一条命令。

### `CommittedMotionSuffix`

越过承诺点前创建。保存直到恢复支撑为止的具体输入、两支预测、落地与停车证明。后续控制器不能重新选择这段输入。

## 3. 每 tick 行为

1. 用实际观察和输入账本构造当前锚点。
2. 检查计划、表项、目标代次和世界依赖是否仍有效。
3. 若处于承诺后缀，核对已经应用的输入并取下一条已证明命令。
4. 若未承诺，控制器可以从当前锚点重新生成剩余计划。
5. 证明提交下一条命令后的安全尾迹；需要进入风险区间时，先证明并锁定完整后缀。
6. 只有许可赢得仲裁时，Runtime 才登记对应生效窗口。
7. 下一观察到达后，以真实应用记录继续；缺回执、晚到或失选按现有动作责任规则处理。

## 4. 证明失败

| 结果 | 含义 | 处理 |
|---|---|---|
| `READY` | 当前命令和必要后缀已证明 | 可以提交 |
| `NEEDS_INFORMATION` | UNKNOWN 或缺少当前必要事实 | 不提交新命令，保留已有安全责任 |
| `STALE` | 锚点、输入、目标、依赖或版本已经变化 | 丢弃未生效计划，从当前观察重建 |
| `UNSAFE_TO_COMMIT` | 下一命令会失去安全收尾 | 执行已证明停车尾迹或有界失败 |
| `BUDGET_EXHAUSTED` | 固定计算预算用尽 | 不提交新命令，不能改写成不可达 |

## 5. 与完整扫描的关系

完整扫描继续用于离线表生成和验收。冻结输入和世界下，增量证明必须与完整扫描一致地识别：

- 最后可安全放弃边界；
- 首个承诺边界；
- 恢复安全支撑边界；
- 风险区间数量；
- 必要世界依赖；
- 两支时序是否均能完成。

一致不要求复制完整扫描的重复停车计算。它要求两种方法对安全含义得出相同结论。

## 6. 接入边界

M0—M2 只修改 `experiments/motion_navigation/trajectory_proto/`、对应测试、配置、文档和证据。M3 才允许新增正式适配器，并必须通过现有 ActionSpec、MotionRouteCoordinator、状态锚点和输入账本接入。NavigationSession 不增加动作专用状态或分支。
