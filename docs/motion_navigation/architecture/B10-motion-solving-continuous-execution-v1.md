# B10 动作求解与连续执行架构

日期：2026-09-21
状态：已采用的实施边界；尚未完成代码实现和正式验收

## 1. 要解决的问题

B09-R 已能计算“给定状态和给定输入之后会发生什么”，但它不会寻找输入，也不会授权真实执行。B10 要补齐这段连接：从正式观察得到可信的运动起点，搜索真实输入链能够产生的命令，验证完整轨迹，再把仍适用于当前状态的短期方案交给唯一输入出口。

B10 不重写 B09-R，不复制地图、身体状态、路线或输入出口。正式范围继续限定为已知地形、玩家自身、不使用载具或消耗型道具、不主动改变世界。未知探索、动态实体避让和跟随仍不属于本阶段。

## 2. 长期职责

| 责任 | 拥有者 | 不负责什么 |
|---|---|---|
| 世界方块、形状和会话事实 | 现有世界知识层 | 不保存第二份供求解器私用的地图 |
| 当前正式身体状态 | 现有观察／身体状态层 | 不接受诊断 sidecar 作为 actor 真值 |
| 给定状态和采样后输入的运动后果 | B09-R 计算器 | 不搜索命令，不决定是否值得执行 |
| 合法命令到逐 tick `TickInput` 的投影 | 输入投影边界 | 不写入游戏，不拥有按键租约 |
| 候选连接和已验证结果查找 | 动作可达性查询 | 查不到不能宣称现实绝对不可达 |
| 合法命令和时序搜索 | 动作求解器 | 不直接写按键，不自行实现物理 |
| 给定轨迹是否满足任务约束 | 轨迹验证器 | 不重新寻找另一条输入，不复制物理规则 |
| 候选现在是否仍可使用 | `RouteAdmitter` | 不求新解，不把版本相同当作充分条件 |
| 短时执行、阶段推进和反馈 | 现有动作执行层 | 不拥有全局路线，不绕过最终仲裁 |
| 真实输入写入、租约和失联回退 | 唯一 `MotorGateway` | 不接受第二个写入者 |

可达性、求解、验证和接纳按职责单向连接，但不要求每个组件只调用一次。求解器会逐 tick 交替调用输入投影、计算器和验证器；接纳器也可以使用同一个验证器复核已变化的短期部分。

## 3. 三种精度的状态

### 3.1 具体模拟状态

`PhysicsState` 表示某个确定 tick 边界上的具体身体状态，用于逐 tick 计算。它包含连续位置、速度、朝向、姿态、接触、必要内部状态和规则身份。

它不负责定义哪些状态可以在搜索中合并。

### 3.2 动作入口和出口范围

动作范围表达一个动作方案允许从哪些连续状态开始，以及执行特定命令后会到达哪些状态。文档中称为 `MotionStateEnvelope`；这是概念名称，不要求在 B10-A 立即建立同名通用类。

入口与出口必须保留关联：

```text
入口子域
  + 命令序列
  + 规则和世界依赖
  → 预测轨迹
  → 对应出口范围
```

不能分别合并入口和出口，再假设任意入口都能到达任意出口。若一个动作从平台偏左和偏右开始会产生不同落点，就应形成不同结果，或由同一结果中的条件关系明确区分。

### 3.3 规划状态键

`PlannerStateKey` 只保存本次搜索必须区分的有限信息。它可以包含支撑区域、模式、姿态、速度范围、方向类别、接触类别和当前能力实际依赖的内部状态。

同一个键只表示便于组织搜索，不自动表示其中所有具体状态可以互相替代。只要方向会改变下一动作是否可行，规划器就必须采用一种明确做法：

- 把方向纳入键；
- 在同一键下保留互不支配的方向标签；
- 或把不同状态都转换到一个已验证的共同入口，并计入时间和资源。

现有 `MovementStateClass` 继续作为已发布转换的粗粒度契约。B10 不向其中无条件塞入所有连续字段。只有确认一个字段长期属于共享粗分类时，才修改该公共类型。

## 4. 正式状态锚点和输入账本

### 4.1 状态锚点

在线预测必须从一个可追溯的正式状态开始。锚点至少绑定：

- 世界会话；
- 正式观察序号；
- 客户端玩家运动 tick；
- 该状态处于输入采样前、运动更新前或运动更新后的哪个边界；
- 最近已确认应用的控制序号及作用区间；
- 规则、状态 schema 和输入投影版本。

局部 rollout 的第 0 步表示“从该锚点开始模拟”，不冒充客户端真实 tick 0。

### 4.2 输入应用账本

未收到回执的输入不能直接当作未执行。每条在途记录至少保存：

- 命令内容和控制序号；
- 请求生效 tick 或窗口；
- 租约和到期条件；
- 已知应用信息与确认状态；
- 可用来消除歧义的后续观察。

首版只维护数量有上限的账本。若少量可能结果都能枚举，候选必须对所有仍可能的结果成立；若分支过多或差异过大，就等待新观察重新锚定，不建立无界的状态分支树。

### 4.3 两种期限

必须分开记录：

- **状态／预测有效范围**：在给定输入历史、世界依赖和不确定性下，可以继续推演到哪里；
- **候选执行窗口**：某条已经验证的方案最迟何时开始或继续执行仍满足约束。

预测有效不代表执行安全。世界变化、服务器纠正、输入历史不确定性或资源条件变化后，应按依赖重新核对候选。

## 5. 命令、输入和动作证明

### 5.1 求解真实命令

求解器搜索机器人能够实际提交的命令和时序，例如前进、冲刺、跳跃、释放、朝向变化及其生效窗口。它不能直接搜索任意连续轴值，再把模拟器专用 `TickInput` 当作真实按键。

输入投影按 tick 工作：

```text
命令 k + 预测状态 k + 输入相位
  → TickInput k
  → B09-R 计算状态 k+1
  → 再投影下一 tick
```

姿态缩放、实际运动 yaw、冲刺资格、释放语义和输入相位都在这条链中处理一次。不得提前用初始状态生成整段输入后忽略途中状态变化。

### 5.2 已验证动作结果

一个可供规划使用的结果至少绑定：

- 状态锚点或适用入口范围；
- 可发送的不可变命令序列；
- 同次计算得到的不可变 `TickInput` 轨迹；
- 完整预测轨迹、接触和姿态变化；
- 对应出口范围和必要恢复范围；
- 规则、输入投影和求解器身份；
- 世界依赖；
- 资源完整性和适用风险策略；
- 成本、计算预算结果和候选执行窗口。

三类记录必须来自同一次计算，不能分别修改。大轨迹可以通过不可变引用保存，规划节点不复制完整数组。

### 5.3 失败结果

至少区分：

- 已知条件明确冲突；
- 缺少世界事实；
- 缺少身体或资源条件；
- 规则尚未支持；
- 有候选但尚未求解；
- 搜索预算耗尽；
- 找到输入但轨迹不满足任务；
- 候选已经过期；
- 接纳时相关事实已经变化。

有限搜索没有找到解，不等于物理上绝对无解。

## 6. 求解、验证和接纳

### 6.1 可达性查询

先用支撑面、途中净空、已知能力边界和硬条件做便宜排除，再查找适用的已验证结果。地图中所有位置不做两两求解。

### 6.2 后台求解

重搜索复用现有后台隔离或一个明确有界的工作队列。请求和结果都采用“保留最新有效项”的有限结构。控制循环不等待完整求解。

优先减少重复工作：复用共同命令前缀、稳定世界查询、候选初值和仍有效的控制余段。只有实测证明必要时才增加新进程、共享内存或原生实现。

### 6.3 轨迹验证

验证器检查完整运动，而不是只检查终点：途中碰撞、支撑、姿态、落点、资源、恢复范围和任务出口都必须成立。`CalculationStatus.OK` 只说明计算完成，不能直接转换成动作许可。

### 6.4 路线接纳

`RouteAdmitter` 不求新解，但至少核验：

- 当前身体能否进入候选；
- 命令是否仍在执行窗口内；
- 世界、能力、规则和资源身份是否一致；
- 相关事实是否变化；
- 恢复条件是否仍成立。

有限变化可以调用同一验证器复核短期部分。需要重新搜索命令或重验整条长路线时，提交后台任务；不能把这项工作放入控制帧。

## 7. 资源范围

B10 不提前实现完整服务端饥饿时钟。它可以在已证明的动作数、持续时间、入口资源余量和条件化资源界内授权短路线。

路线短不是证据。若接近资格阈值、内部消耗可能改变动作资格，或发生未覆盖事件，依赖该资格的候选应返回条件不足或等待更新。每条边不能重复读取同一个初始食物值后宣称整条路线安全。

完整饥饿和呼吸同步在实际依赖它们的后续能力中交付。

## 8. 连续接续与执行

连续执行以事前冻结的接续矩阵为准，不要求所有动作两两组合。每个声明支持的组合都记录入口域、中间状态、出口、减速要求、时序和证据。

停稳是合法控制结果，但不是接口交接的默认动作。局部执行每次只发送当前已接纳方案的短期前段，然后根据新观察更新锚点、进度和剩余执行窗口。

偏差仍在已验证恢复范围内时，可以有限修正。超出范围时不宣称恢复成功；应停止扩大权限，保留安全回退并报告结构化结果。

## 9. 与 B11–B13 的关系

- B11 扩展接触和材质规则，继续使用同一计算器、求解器和动作证明结构。
- B12 增加攀爬模式和进出动作，不伪造脚下支撑。
- B13 的流体规则提供水体接触、浮沉、流动和呼吸条件；姿态规则仍由运动计算体系统一拥有。
- 水只是 Crawl 姿态转换的一种条件来源。流体模块不维护第二份 Crawl 状态。
- 每种 Crawl 入口仍需要固定版本的合法机制和证据。看到一格高通道不自动代表站立角色能够进入。

## 10. 不变量

1. 只有一个正式世界事实拥有者、一个正式身体状态拥有者和一个真实输入出口。
2. 诊断数据只用于对照，不进入正式 actor 决策。
3. 求解器输出真实命令；`TickInput` 是投影和计算产物。
4. 入口、命令、轨迹和出口保持关联。
5. 规划状态键的合并必须证明不会丢掉本阶段声明的可达路线。
6. 接纳可以复核旧解，不能在控制帧求新解。
7. 预测有效范围和候选执行窗口分别表达。
8. 安全、权限、缺信息、未支持和计算未完成保持不同结果。
9. B10 新路径未通过正式验收前，现有已发布控制器继续独占真实输入。
