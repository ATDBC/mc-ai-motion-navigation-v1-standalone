## 1. 目标、边界与当前基础

### 1.1 目标

构建无真实游戏副作用的版本化前向计算库：从一个明确的模拟状态出发，消费已经指定的控制序列，计算每个逻辑 tick 的状态、接触事件、模式变化、相关资源结果、世界依赖及不能继续计算的原因。

同一组完整输入在同一数值实现下应能重复得到相同结果；从中间状态保存、恢复和分支后，结果应与连续计算一致。

### 1.2 复用哪些已有内容

- `WorldKnowledge` 和世界会话：真实位置事实的唯一来源，不另建运行时地图。
- B07 几何所有者、碰撞盒、支撑表面和实际连续高度：作为只读计算输入。
- `BodyState`：已有位置、速度、姿态、实际冲刺／潜行、食物水平、饱和度、浸水和游戏模式等字段；不重复发明同义事实。[R3]
- 环境和材质分类：沿用现有 ID 和目录，增加规则／数值实现／支持范围身份。[R5]
- B05、B07、B08、B09 的轨迹与边界反例：用作回归来源，不将参考轨迹当成物理公式。[R1][R2]

当前 `ground_motion.py` 是参数化的水平预测，`AirMotionProfile` 主要保存有限参考轨迹和切换阈值。本次另建规则计算内核，并通过适配读取已有数据；不一开始删除旧模型，也不把旧模型统一改名后称为完整原版规则。[R2][R7]

### 1.3 本阶段的计算支持范围

| 范围 | 本阶段要求 |
|---|---|
| 普通已知、静态固体世界 | 支持；使用实际碰撞形状、所有者和方块状态 |
| 普通地面运动 | 起步、停止、前后与侧向输入、组合输入、朝向变化 |
| 基础三维运动 | 起跳、自由空中运动、离开支撑、碰顶、侧碰、重新落地 |
| B07 已声明形状与小台阶 | 逐项验证相应碰撞／迈步／下行规则，保留真实高度 |
| B08 地面模式 | Walk、Sprint、Crouch；已合法进入的 Crawl 保持和退出 |
| B09 三类动作的指定输入 | 同一计算内核演算 Up／Gap／Drop 场景，但不依赖动作名称选择固定曲线 |
| 普通身体条件与资源 | 当前资格判断必须准确；普通运动消耗的副模型按明确时钟和条件计算；不完整结果必须标明 |
| 特殊地面、液体、攀爬 | 预留状态和查询接入方式，具体规则仍由 B11–B13 实现 |
| 动态实体、活塞运输、载具、道具位移、复杂世界变化 | 不在本阶段计算保证范围；不能默认为无影响 |

这里的范围是**计算支持范围**，不是玩家获准执行的动作范围。

例如，一个输入序列导致碰墙：如果对应接触机制已经支持，计算器应正确算出接触与位移调整，而不是拒绝计算。某条下降轨迹可以计算，不意味着导航获准执行该下降。涉及尚未实现的伤害、特殊接触或世界变化时，应在对应边界停止或明确该结果分量不可用，不能声称已计算完整后果。

固定输入测试可以包含会失败、会碰撞、无法到达目标的序列；这类序列预测准确就是计算器测试通过，不应统计成导航事故。

## 2. 核心职责与未来接入

### 2.1 推荐实现方式

采用**轻量、无副作用的规则内核 + 正式观测适配 + 独立 Fabric 差分验证**。

不在真实玩家实体上试跑未来 tick 再回滚；不复制整个 Minecraft 世界；不为每种动作单独实现一份重力、碰撞和落地；不为未来能力提前建立庞大的插件框架。

物理规则以固定运行工程为依据。Yarn 文档可定位 `ClientPlayerEntity`、`LivingEntity`、`Entity` 和方块形状接口，但接口签名不能证明具体运算顺序或所有模组行为。本阶段第一项交付必须核对实际调用链。[E1–E4]

### 2.2 层次关系

```text
正式观测／独立测试记录
       ↓ 输入适配、相位对齐、状态与来源检查
只读计算状态 + 指定逐 tick 控制 + 只读已知世界 + 规则身份
       ↓
单 tick 计算 → 多 tick 演算 → 状态／事件／依赖／结果范围
       ↓
本阶段：差分、回归、吞吐基准、只读影子比较
后续：可达性查询、动作求解、安全检查、连续控制、训练采样
```

这是一个库的职责划分，不要求拆成多个服务或进程。

### 2.3 本阶段禁止反向依赖

计算内核不读取 `GoalState`、路线节点、`ActionRouteExecutor` 的阶段、风险政策、任务优先级或候选得分。也不调用 PlannerWorker、RouteAdmitter 或 MotorGateway。

物理后果依赖身体条件，但不依赖用户“想快一点”还是“想省食物”。相同状态与输入不能因任务目的不同而产生不同轨迹。

## 3. 必须先冻结的四类身份

### 3.1 运行环境身份

沿用当前环境：`1.21`、Fabric Loader `0.15.11`、Fabric API `0.100.6+1.21`、Yarn `1.21+build.9`、Java 21、Python 3.11，自动跳关闭，名义 `tick_seconds=0.05`。[R5]

补齐实际客户端／服务端／模组与配置哈希。不能只检查字符串 `1.21` 就认为物理完全一致。

### 3.2 规则与数值身份

新增规则实现 ID、状态 schema、输入 schema、几何查询契约及数值语义版本。逐项核对浮点类型转换、运算顺序、角度处理、碰撞轴处理及阈值；不通过改加速度来拟合输入延迟。

同一规则的数值实现发生实质变化时，旧缓存和差分报告不能自动继续适用。

### 3.3 计算支持范围身份

记录支持的材质／状态、姿态、身体属性、外部条件、输入种类和已验证预测长度。采用显式正向范围，范围外返回未支持，不默认套普通地面规则。

这里不记录“最大可跨几格”的动作授权；那属于后续可达性与能力验证。

### 3.4 执行时序身份

记录正式采样相位、按键应用相位、客户端运动 tick、服务端 tick 的对应证据、在途输入和回执语义。

硬件型号、耗时和延迟属于执行与性能报告，不进入运动公式。计算器可消费已确定的输入时间表；延迟估计与在线调度属于外层。

## 4. 输入契约：状态足够完整，但不强迫观测拥有未知信息

以下是拟新增语义，不是声称仓库已有实现。具体命名可贴合原工程，含义必须保持。

### 4.1 `PhysicsState`：一个固定相位的完整模拟状态

| 组成 | 内容要求 |
|---|---|
| 运动 | 连续位置、三维速度、朝向、姿态、实际身体尺寸 |
| 接触 | 实际接地和运动所需接触状态；不能只保存“节点可站立” |
| 输入相关内部状态 | 实际冲刺／潜行状态、当前输入持续状态、规则依赖的冷却与计时 |
| 身体条件 | 有效运动属性、游戏模式、当前支持的装备／效果条件 |
| 下落 | 累计下落与已发生接触等会影响后继计算的状态 |
| 资源上下文 | 当前食物／饱和度，以及资源副模型所需的已知内部状态、更新时钟与适用条件 |
| 身份与相位 | 世界会话、规则身份、逻辑步序号、状态采样边界 |

`PhysicsState` 是从真实状态投影出的**模拟副本**，不是另一份真实身体权威状态。内部可采用高效可变对象，但对调用者必须支持独立复制、无共享串扰和稳定序列化。

不要仅保存位置速度后宣称可以准确断点续算。`jumpingCooldown` 等内部状态可能决定后续相同输入的不同结果；具体字段以固定调用链审计为准。[E2]

### 4.2 不完整观测与精确模拟状态分开

真实观测可能不包含计算所需的全部字段。适配层对每个参与规则的值标注：直接观测、历史推导、条件假设或未获得。

原则：

- 缺失且会影响当前步骤的状态，返回 `NEEDS_STATE`，不写默认满饥饿、零冷却或无效果。
- 某项状态缺失但当前分支的结果与其无关，不必拒绝全部计算；记录该结论的适用条件。
- 本阶段不实现一般概率状态估计器。调用者可以显式构造多个假设状态，分别调用计算器。
- 多个假设的有限试算不是对整个连续不确定范围的保证。
- 仅用于规则诊断的内部真值可存在于离线证据，但必须与正式机器人可用输入区分；不能自动导入在线导航。

现有 `BodyState` 的默认值可继续用于旧测试兼容，但生产状态构建必须检查实际字段有效性，不能把 Python 默认值当成观测事实。[R3]

### 4.3 `TickInput`：已交付的控制，不是已成功的动作

输入表达该逻辑 tick 已交付给玩家输入处理链的前后、侧向、跳跃、冲刺、潜行和视角控制。它不直接指定速度、位置或强制姿态。

“冲刺键请求已交付”不等于“角色一定冲刺”；实际资格与切换由规则计算。对应版本有独立冲刺判定入口。[E1]

R0 必须冻结唯一输入边界：按键解码、方向符号、斜向归一化、视角应用、玩家模式判断各在边界哪一侧。内部可以有辅助函数，但公开接口不能在同一个字段里混用“原始按键”和“已经减速归一化后的速度系数”。特别检查现有桥接中的 strafe 符号与 yaw 约定。

控制序列每个 tick 都是完整的按键状态，包含显式释放。不得用“未给字段就沿用上一段”制造歧义。压缩段可表达同一完整输入持续 N tick，但运行时仍逐 tick 推进。

### 4.4 `PhysicsWorldView`：只读事实与形状查询

复用已有世界数据，用窄接口向计算内核提供：

- 所需位置的已知／未知状态与实际方块状态；
- 在当前预测身体上下文下的碰撞形状；
- 运动特征、形状所有者、相关版本和依赖；
- 本阶段支持的接触条件。

不在 `step` 内拉取新观测或读取 Minecraft 隐藏世界。预测姿态变化时，形状查询需要新的模拟上下文，不能永久缓存初始身体条件下的形状。[E4]

B07 已支持的向上跨格形状继续沿用其所有者查询范围。未支持的横向动态形状不能靠扩大一个随意的邻域默认为已解决。

只因无关地下格未知，不应推翻已经足以计算的已知接触；确实可能影响碰撞／接触的未知所有者也不能遗漏。需要哪些事实，由具体规则的真实读取决定，不扫描整张地图。

## 5. 计算接口与结果语义

### 5.1 两个主要接口

```text
step(state, tick_input, world_view, ruleset) -> StepResult

rollout(initial_state, input_sequence, world_view, ruleset,
        max_ticks, output_mode) -> RolloutResult
```

这是接口设计，不是已实现的 Python 代码。

`step` 在声明的起始相位到下一相同相位之间推进一个玩家运动逻辑步。`rollout` 只对外部给定序列反复调用同一单步逻辑，不生成输入、不选择动作、不发现目标。

### 5.2 `StepResult`

| 内容 | 语义 |
|---|---|
| 结果状态 | 是否成功算完本 tick；缺少什么或遇到什么未支持机制 |
| `next_state` | 下一相同相位的完整模拟状态，可继续推进 |
| 物理事件 | 碰撞、离地、落地、模式变化、输入请求未生效等 |
| 接触信息 | 接触对象、所有者和计算中真正使用的几何结果 |
| 运动过程 | 必要的 tick 内位移分段／接触顺序，不能只有两端坐标 |
| 资源结果 | 本阶段支持的实际资源计算或贡献量，并附完整／条件化／不可用标记 |
| 依赖 | 所读世界事实与条件；用于未来缓存和候选失效检查 |
| 假设与适用范围 | 精确给定值、条件假设、未实现分量和预测支持域 |

一个 tick 若因缺信息无法完整计算，保留原输入状态并报告原因，不返回伪装成完整下一状态的半成品。已算出的内部片段可作为诊断，不允许继续链接成确定轨迹。

### 5.3 `RolloutResult`

返回已完成 tick 数、逐 tick 状态／事件或指定摘要、最终状态、累计依赖、累计资源结果和停止原因。

`output_mode=full` 用于差分和可视化；`output_mode=summary` 可省去中间状态存储，但仍逐 tick 检查支持范围、接触和依赖。两种输出模式的最终状态与关键事件必须一致。

未达到请求长度的返回必须明确显示是缺状态、缺世界、未支持或预算停止。成功算完 30 tick 只意味着这些步骤已计算，既不是“动作成功”，也不是“完整动作已经结束”。

### 5.4 状态枚举不要借用导航许可语义

建议计算层使用：

| 状态 | 用途 |
|---|---|
| `OK` | 当前请求的计算步骤完整完成 |
| `NEEDS_STATE` | 缺少影响结果的身体／内部／权威状态 |
| `NEEDS_WORLD` | 缺少影响结果的世界事实 |
| `UNSUPPORTED` | 已知条件涉及尚未实现或验证的规则 |
| `INVALID_INPUT` | 数据契约矛盾、非有限数值、身份／相位不匹配等 |

运行器另报告 `BUDGET_EXHAUSTED` 或调用方要求的提前结束，不能把它映射为物理不可达。

**不在计算层返回 `FEASIBLE`、`SUCCEEDED`、`CANCELLED` 作为导航结论。** 撞到墙但完整算出响应，可以是 `OK + collision`。按下跳跃却因规则条件没有起跳，可以是 `OK + no_takeoff`。目标不相关，安全政策也不改变物理输出。

## 6. 规则计算必须与几何许可分开

### 6.1 规则来源和更新顺序

从固定完整工程核对输入处理、状态切换、运动积分、碰撞解析、迈步、落地、接触与相关内部计时的真实次序；给出源码方法、Mixin 修改、读写字段和输入／输出相位对应表。

本方案不凭经验编造完整原版 tick 次序。已有源码中的解释或单段回放也不能替代对完整调用链的核对。[E1–E3]

首版可按职责划分内部函数，但各函数执行顺序必须固定。特殊材质将来接入时按该顺序扩展，不能让注册插件的先后顺序意外决定物理结果。

### 6.2 碰撞是运动响应，不是统一失败

计算器使用实际身体碰撞体与真实形状，按版本规则计算允许位移和接触结果。正常落地、靠墙滑动、合法小台阶等应能够继续计算。

不能把导航为了安全增加的碰撞裕量写进物理规则；不能把“脚印至少 50% 支撑”的导航站位门槛当成玩家原版接地公式；不能把规划的 Step 动作阶段当成游戏物理实现。

安全包络、危险过滤、终态许可和可恢复性属于外层消费者。计算器返回所需事实，不对未来任务授权。

### 6.3 tick 内运动不能被一条端点连线代替

真实一步若经过碰撞轴解析或迈步候选选择，起止点之间的直线不一定等于实际身体运动过程。提供必要的内部位移／接触摘要，使后续验证器不会凭两个端点误判穿障碍或漏掉接触。

### 6.4 与动作 Profile 的关系

计算器没有 `JumpGap`、`JumpUp` 或 `ControlledDrop` 的特殊成功分支。它消费输入后自然产生对应轨迹；动作名称、目标落台和是否按预期完成由调用者判断。

旧 `reference_positions` 和松键阈值用于输入样本、回归比较和后续求解种子，不作为逐 tick 输出真值。新计算器也不自动扩大旧 Profile 的动作授权范围。

## 7. 饥饿、资源与客户端／服务端边界

### 7.1 本阶段必须做到的内容

读取／接受当前身体资格所需的真实条件，正确预测请求冲刺是否生效及模式变化。普通运动产生的消耗结果可以作为独立数值副模型接入，但不能套用路线里一个固定的 `ResourceChange` 来冒充原版资源演化。

对应的 `HungerManager` 不只有食物水平，还包括饱和度、消耗度和计时状态。[E5]

### 7.2 不能把服务器资源更新偷偷当作客户端运动的一部分

逐项记录资源状态由哪一侧维护、更新在哪个时钟、如何影响客户端已知资格。不能假定每运行一次客户端运动计算，就必然有一次同步的服务端资源更新或一次立即到达客户端的同步消息。

推荐分开两种能力：

| 能力 | 本阶段语义 |
|---|---|
| 运动计算 | 使用该时刻明确给出的、玩家侧可用的条件推进运动 |
| 资源副计算 | 在声明的资源更新序列、身体与环境条件下推进资源；结果可影响后续条件，但同步时序必须显式 |

资源状态、更新顺序和同步时间齐全时，可给出条件化完整预测；不足时，返回可计算的运动和资源贡献，并把资源预测标成不完整。如果这种不确定性已可能改变后续运动分支，则停止确定性后续或由外层分支计算。禁止一直假定饥饿充足直到完成任意长轨迹。

### 7.3 本阶段不做的资源工作

不实现路线级资源标签裁剪、是否值得冲刺的评分、自动进食、呼吸点规划、全部恢复／饥饿伤害／药水系统。

普通资源副模型的精确支持条件必须写入范围清单；缺少健康、难度、游戏规则或计时而无法判断的效果，不能默认不存在。也不能只为让结果好看，在正式记录中每 tick 重置食物。

### 7.4 与已有资源契约的兼容

原始消耗度等内部变量不等于“数值越大越有余量”的规划资源。计算器保留其真实语义；后续规划层负责映射为有证据的资源约束。

当前量和容量分开，恢复上限不默认等于任务开始时的余额。这个契约现在说清楚，但本阶段不修改搜索算法的支配关系。

## 8. 时间、跨机器和加速演算

### 8.1 三种时钟独立

玩家运动逻辑 tick、服务端 tick、进程单调时间分别记录。渲染帧不是物理步。`sequence_id` 也不默认等于经过的 tick 数。

`step` 每次显式调用推进一个模拟逻辑步；同一个输入状态被算两次，是两次独立分支演算，不改变真实时钟。真实观测去重由适配器处理，不能给无副作用函数加一个隐藏全局“已经算过”标志。

### 8.2 物理时间不随运行速度变化

项目对外仍使用格、模拟秒、格／模拟秒、弧度；内核可在单一转换边界使用原版格／tick等原生量，字段名和 schema 必须区分。

没有真实等待的循环可以快速算完很多步，每一步仍执行相同规则。加速时不修改 `tick_seconds=0.05` 来等于 CPU 实际耗时，也不把多 tick 合成一个大步后跳过碰撞和内部计时。

### 8.3 只做指定延迟的重放工具，不做在线调度器

本阶段测试工具可以输入明确的控制生效时间表，或注入固定的一／两 tick 延迟。先形成实际生效输入序列，再交给计算器。

不估计“最佳提前量”，不安排自动起跳，不下发未来按键队列，不替换客户端租约。真正的在线延迟适配与调度留到后续执行接入。

### 8.4 跨机器一致性

同一规则／数值实现、状态、世界和控制流，首先要求进程内重复、序列化恢复和不同演算拆分方式的确定性一致。

跨平台不预先承诺逐位相同：记录平台与数值实现，比较关键离散事件及事先冻结的数值容差。边界处的微小差异会改变接触分支时，必须作为真实差异报告，不用平均误差掩盖。

### 8.5 加速训练的交付边界

本阶段提供快速、无睡眠、多分支的计算能力和可重放数据。完整 Fabric 客户端／服务端同步步进、全游戏高速运行、多环境采样服务和训练算法都不是完成条件。

同一固定输入在实时节奏回放与无等待演算下应该有相同逻辑结果；真实游戏环境的加速等价性属于之后独立验收，不由纯计算器测试代替。

## 9. 现在必须预留、但不提前实现的后续接入能力

| 后续消费者 | 现在必须提供 | 本阶段不做 |
|---|---|---|
| 可达性查询 | 入口状态、全轨迹、接触、完整终态、依赖、计算支持范围 | 高差／距离可达表、判定所有动作组合 |
| 输入求解器 | 从同一状态廉价分支；指定输入的确定性结果；完整和摘要输出 | 搜索、候选生成、排序、最优切换点 |
| 连续接续 | 完整三维速度方向、姿态、接触、冷却、资源条件及中间状态 | 自动匹配动作入口／出口、联合优化 |
| 安全验证器 | 实际轨迹和接触分段、误差报告、依赖与缺口 | 风险准入、安全与收益权衡 |
| 在线控制 | 相位与输入语义、状态保存恢复、误差归因依据 | 滚动优化、真实阶段推进、MotorGateway 写入 |
| 缓存／后台批量 | 可序列化的状态和规则身份、只读世界、无串扰 | 复杂缓存驱逐、全图预计算、异步任务框架 |
| 特殊材质／Climb／Swim | 上下文相关形状查询、接触事件、明确模式与资源状态 | 空插件、未实现模式伪装可用 |
| 加速采样 | 无现实等待的 rollout、独立多分支、可复现输入 | 神经网络、奖励设计、训练调度、完整游戏加速 |

### 9.1 状态保存与恢复是必要交付

任意完整 tick 边界可保存，再以新的指定输入继续演算。保存对象包含所有会影响下一步的内部状态；不能仅从轨迹坐标恢复。

必须满足：`前 N 步 + 保存恢复 + 后 M 步` 与 `连续 N+M 步` 的结果一致。两个分支互不影响，调用顺序不影响结果。

### 9.2 身份和依赖

计算缓存的输入至少包含规则／数值 schema、完整初始状态、指定输入、所用世界事实及计算语义。依赖细化到足以区分几何、接触、材质和身体上下文变化。

本阶段不实现复杂缓存。也不因将来会做速度类别，就在计算内核中把连续速度提前取整成类别。近似缓存需另外验证，不能混入确定性参考计算。

### 9.3 结果量与性能

允许摘要输出和共享不可变世界快照，避免每个分支复制全地图。首版可以串行实现批量入口；能独立分支、能复现和能计时，比提前上 GPU 或原生重写重要。

预算控制放在 rollout 运行器边界。达到 tick／查询／外部时间预算时，在完整 tick 边界结束并返回有效前缀；不得半步修改状态后作为完整结果。物理单步函数不根据“已经耗时几毫秒”走不同物理分支。

## 10. 验证：证明计算正确，不证明路线会走

### 10.1 证据分层

| 层次 | 用途 | 不可冒充的结论 |
|---|---|---|
| 手工几何与状态夹具 | 契约、边界分支和简单确定规则检查 | 原版全部物理一致 |
| Fabric 单步差分 | 真状态＋该 tick 真正应用输入，对照下一同相位状态 | 长时开环准确 |
| Fabric 多步开环差分 | 真初始状态＋完整指定输入序列，无中途纠正 | 自动控制／导航成功 |
| 显式条件重放 | 提供外部同步或条件变化，定位资源／消息影响 | 不依赖未来信息的自由预测 |
| 旧控制器只读影子比较 | 旧控制继续写输入，新计算器只预测并记录 | 新计算器已经控制身体 |

多步开环不能每 tick 将真实位置、接地或速度重新灌入模拟；否则退化为单步误差检查。把未来资源更新等外部真值输入时，必须单列为“条件重放”，不能混入自由开环成绩。

### 10.2 保留集和输入真实性

校准、开发回放和保留验证按完整运行／场景 ID 分离，不能把同条轨迹切成两半后宣称独立泛化。

回执只表明输入链路某个事件，不自动等于该按键在所假定物理相位已经生效。缺失字段需要补采；不从输出轨迹反推按键，再将同一轨迹当独立验证。

来源为服务器内部的诊断字段或测试底图必须标记。正式只读影子模式仍只使用机器人合法可得信息；缺信息的结果单列，不借测试真值完成预测。

### 10.3 必测场景矩阵

| 组 | 给定输入或条件 | 需要验证的结果 |
|---|---|---|
| 空地 | 前后、侧向、斜向、转头、不同 pitch、松键 | 速度／位置、输入处理、惯性尾迹 |
| 内部状态 | 同位置速度但跳跃冷却／实际冲刺状态不同 | 正确产生不同后续，不遗漏状态 |
| 基础空中 | 指定 Up／Gap／Drop 输入，静止与带速初始状态 | 每 tick 轨迹、离地和落地相位，不要求成功到台 |
| 碰撞 | 撞墙、碰顶、接触后远离、转角、落地 | 正确接触响应，不把碰撞一概当计算失败 |
| 非完整形状 | 已支持半砖、楼梯踏面、地毯、雪层及跨格所有者 | 非整数高度、真实碰撞顺序和支撑 |
| 姿态 | Walk／Sprint／Crouch、合法 Crawl 保持与退出 | 实际尺寸和模式切换；低顶不能提前缩小身体 |
| 资源 | 冲刺资格成立／不成立；给定普通资源状态变化 | 实际运动模式与资源结果标签正确 |
| 知识边界 | 必需格未知、无关地下格未知、形状所有者未知 | 必要依赖不漏、无关缺口不造成任意失败 |
| 身份 | 旧世界、不同规则／schema、非法非有限值 | 明确拒绝，不静默兼容 |
| 演算方式 | 连续、分段恢复、输入压缩／展开、完整／摘要 | 相同输入有相同后果 |
| 多分支 | 从同状态分叉，交错调用或并行计算 | 无状态串扰 |
| 延迟重放 | 指定生效序列、漏观测、重复观测 | 时间表语义一致，不把晚到造成的偏差拟合成物理 |
| 计算终止 | max_ticks、查询预算、取消本次计算 | 返回完整有效前缀；不是动作取消或不可达 |
| 模型外 | 水、特殊接触、未知效果、受保护世界变化 | 明确未支持／缺条件，不普通化 |

负坐标、整数接触面、零水平速度和接触恰好位于阈值两侧必须单列。坐标平移和旋转的对照使用明确容差；不凭数学对称性假设不同浮点运算路径逐位一致。

### 10.4 精度与事件门槛

不能把“到点误差小于 0.25 格”用作物理计算器精度门槛。到点是任务验收，物理差分是逐 tick 计算验收。[R6]

沿用原规范的普通地面单步位置 P99 ≤0.05 格、6 步 P99 ≤0.15 格，仅作为最宽的历史基础上限，不把达到它们称为精确复现。新的规则计算应同时通过以下更细的门槛：

1. **精确相位的确定场景：** 接地、离地、碰撞分支、姿态和输入生效等关键事件分类一致；存在真实相位不确定性时，预先冻结允许窗口并单列结果，不事后平移时间轴消除误差。
2. **逐分支数值检查：** 有直接固定版本一步对照的规则，按运算精度误差检查，不使用宽松的整条路线容差掩盖公式／顺序错误。
3. **完整轨迹：** 报告位置／速度每轴误差、P50/P95/P99/最大值和首次分叉 tick；不能只报平均值或仅报终点。
4. **保留集边界：** 模型范围和误差报告由独立验证产生。用于未来动作许可时，还要小于目标轨迹的实际余量；本阶段不发放动作许可。

具体数值容差按来源精度、采样相位和目标规则族在 R0/R1 的测试规范中冻结，必须先于保留集运行，不能验收后调宽。公式分支已知有错时，即使误差暂时未超过基础上限，也不能通过对应规则验收。

### 10.5 样本量与统计

本阶段统计的是“真实指定输入序列的预测差分”，不是“自动动作成功率”。不以 200 次自动到达作为本阶段完成条件。

建议采用的初始最低样本要求：强制矩阵各组都有独立 Fabric 输入记录；地面与模式、碰撞与小台阶、普通空中三大类合计至少 200 条独立采集的指定输入序列，各大类不少于 40 条，四个主要运动方向、边界与模式转换均覆盖。验证集中保留至少 30% 的完整运行序列，不参与规则调整。相同记录切出的一万单步窗口可作样本数，但不能冒充一万独立运行。

这是本阶段新提议的数据门槛，不改写旧 B09 的统计，也不抵扣后续 B10/B15 的能力闭环发布门槛。已有轨迹只有字段／相位完整且满足分组要求，才可进入新差分集；不是因为曾成功就自动计入。

## 11. 性能、硬件与加速的验收

### 11.1 性能测什么

分别记录状态构建、单步计算、几何查询、完整 rollout、输出存储／序列化耗时。固定测试：1／6／20／60 tick；单分支以及 32／128 个彼此独立的已给定序列；空地、复杂静态形状、空中接触三种负载；冷热缓存分开。

报告参考机器、P50/P95/P99/最大值、有效 tick／秒、事实／碰撞盒读取量、内存峰值和超预算次数。预测长度是基准参数，不是固定的未来求解窗口。

### 11.2 本阶段与实时预算的关系

原规范的完整控制帧 P95 ≤8 ms、P99 ≤15 ms、最大 <30 ms 仍是未来控制集成预算，不是单个候选或一条离线 rollout 都可独占的额度。[R6]

B09-R 先建立可重复的吞吐基线、有界终止和开销构成，不在尚无求解器时声称整个未来闭环已经达到这些预算。也不能因为一条轨迹算得快，就推导每帧可以计算任意数量候选。

后续求解预算应按“候选数 × 平均展开 tick × 单步成本 + 适配／几何／安全开销”实测分配；性能不够时改变求解调度或实现，而不是改物理规则。

### 11.3 必须通过的一致性检查

同一保存输入在单进程重复、串行批量、分段恢复、无等待循环、人工加入等待的回放中，逻辑结果一致。不同机器的结果按冻结容差和离散事件核对；只有一台可用机器时报告跨机器验证未做，不拿单机不同负载冒充多硬件验证。

本阶段不要求已有完整游戏高倍速运行，也不把不同机器实时延迟都校准完作为完成前提。交付可携带到其他机器的重放包与比较工具，为后续部署提供验证入口。

## 12. 七个交付任务：按顺序推进

| 编号 | 本任务交付 | 首要反例／通过条件 |
|---|---|---|
| R0 | 规则调用链、输入相位、证据格式与保留集方案 | 输入可对应实际应用和后继状态；来源及缺失明示 |
| R1 | 完整模拟状态、唯一输入契约、只读世界适配 | 相同位置速度不同内部状态不可合并；序列化往返一致 |
| R2 | 普通运动和空中单 tick 规则 | 固定输入单步对照；起跳、松键、自由空中与冷却分支 |
| R3 | 接触解析、落地、已支持小台阶与形状 | 负坐标、碰顶、接触后离开、非整数高度；碰撞正常输出 |
| R4 | 地面模式、身体资格与普通资源结果 | 请求不等于实际模式；资源条件／权威时钟不完整时明确标记 |
| R5 | 多步演算、分支恢复、摘要、预算和快速重放 | 连续与恢复一致、分支无串扰、预算只返回完整前缀 |
| R6 | 独立差分、吞吐报告、只读影子比较与发布清单 | 支持范围真实、关键事件正确、不更改在线运动行为 |

每个任务都包括自身文档、反例和测试；不把 R1 当作一次生成所有未来状态类的空壳任务。内核首次可运行后，每新增一类规则立即做差分，不等到 R6 才发现整个模型不对。

### R0 实际第一项工作

使用 B09 原成功与边界场景，固定一条普通前进／松键序列和一条跨隙指定输入，记录完整相位。先回答“已有记录是否足以确定下一 tick 的输入和状态”。缺字段则在完整 Fabric 工程补采。

这个步骤不选择更好的输入，不修改路线，不调松键点。先建立能够发现预测错误的尺子。

## 14. 完成定义

B09-R 只有在以下条件同时成立时完成：

1. 版本、数值实现、输入相位和计算支持范围有明确身份与来源。
2. 给定完整状态和控制，可计算支持域内下一 tick 及连续多 tick 的结果。
3. 接触和模式变化根据规则产生；失败输入也能得到真实后果，不以导航许可替代计算。
4. 不依赖真实世界写入、求解器、目标、规划器或 MotorGateway。
5. 必要缺状态／缺世界／未支持／数据错误与预算终止分别表达，结果没有伪造完整性。
6. 单步、多步开环、分支恢复和条件重放分开验收，保留集未被反向用于调参。
7. 已给定输入的普通地面、形状、小台阶、地面模式和基础空中矩阵有实机差分依据。
8. 状态和世界无分支串扰，完整／摘要输出和无等待／加入等待的演算一致。
9. 资源结果如有条件或缺失，标记到结果分量，不把客户端／服务端时序混同。
10. 有性能报告、可携带重放包、原始失败索引和未验证项；旧在线控制行为及原验收范围保持不变。

**不要求：** 自动发现起跳点、最佳松键点、最大跳距、可达区域、完整路径、最优输入、连续无停顿导航，或者在任意机器上都满足未来求解器实时预算。

## 15. 对后续阶段的约束

后续“能力查询／求解专项”以本阶段产物为输入：先用范围或种子缩小候选，再给计算器不同输入序列，检查完整结果；它拥有搜索、代价、入口／出口兼容和是否执行的决定。

计算器只算给定输入，不建立可达性表。即使用户给出 100 条序列要求批量计算，也只是独立计算 100 条；选哪条不是它的职责。

B10 再加入连续接续、执行走廊、实时调度与滚动修正。B11–B13 增加特殊接触、Climb／Swim 和资源规则，不复制基础重力、碰撞和时钟系统。B14 优化求解和缓存；B15 验收完整导航。

本阶段为这些消费者保留接口，但不提前实现它们。若后续发现状态缺失影响物理，应修正计算契约并重新差分，而不是在求解器里再维护一套隐含物理。

## 16. 可交给开发 AI 的首批任务说明

> 基于当前 B09 已验收实现，开展 B09-R“逐 tick 运动计算器”阶段。先核对固定 1.21 工程的输入应用／观测相位、规则调用链和现有轨迹字段，建立可独立差分的证据入口。随后实现无副作用的完整状态、单 tick 与给定输入序列的多 tick 演算。
>
> 复用世界、几何和正式身体事实；保留旧控制器及其验收。计算器输出状态、事件、接触过程、资源结果的完整性、依赖和缺口，不接收任务目标、不选按键、不判断路线成功。单步与多步开环必须通过独立真实数据检查，不能用待测预测器或参考曲线生成独立真值。
>
> 每次只交付一个可验证机制。先完成 R0；不要开始求解器、动作范围搜索、A* 调整或在线控制替换。交付修改位置、真实运行命令、证据索引、误差／耗时报告和未验证项，不把文档状态或测试数量当成物理正确性的替代。
