# 运动证明依赖分层 v1

日期：2026-10-21。状态：**IMPLEMENTED／SIGNED**。源查询与证明汇总已按本规格实现并通过完整 Windows 发布门禁；actor 权限、Session、transport、Java 和观察路径未改。

依据：[D124](../decisions/0124-separate-broad-physics-reads-from-proof-dependencies.md)、[计划](../stages/d124-proof-dependency-projection-plan.md)、[验收](../acceptance/d124-proof-dependency-projection.md)。前序事实见 [D123 验收第 8—11 节](../acceptance/d123-proof-dependency-and-transport-loss.md#8-d123-0-只读实验结果)。

## 1. 要解决的问题

计算器为了避免漏掉向上伸出的碰撞形状，会多查下一层的形状所属格。这种宽查询合理，但被查询到不等于该格会影响当前安全结论。现行实现把两者混用，导致已知完整支撑下的隐藏格仍进入 proof，actor 随后被要求观察它们。

D124 要让每条查询说明实际依赖了哪些事实。它只改变依赖形成方式，不把未知格补成空气，不削弱真实碰撞、支撑、材料或伤害检查。

## 2. 三个集合

| 名称 | 表示什么 | 谁负责 |
|---|---|---|
| 宽查询候选格 `broad candidate cells` | 扫掠包围盒及可能伸入其中的形状 owner；owner 是碰撞形状所属的格子 | 几何查询计算；仅用于取数范围和诊断 |
| 安全必要依赖 `safety-essential proof dependencies` | 主轨迹、恢复、支撑、材料和伤害结论实际使用的事实，以及用于屏蔽其他读取的支撑事实 | 源查询返回，证明器合并并绑定版本 |
| actor 待观察事实 `actor-observable missing facts` | 必要依赖中尚未取得的事实；“待观察”不保证当前视点能看见 | 现有观察入口请求；缺失时保持有类型拒绝 |

世界事实仍由 `WorldModel` 单独拥有。查询只读这些事实，不能生成新的 `CellFact`。actor 待观察集合也不能反向改变证明依赖。

查询结果中的 `dependencies` 表示必要依赖。宽查询集合可以留在诊断中，不能再次整批并入 proof。`missing_cells` 必须属于必要依赖；必要依赖只能来自候选格及明确使用的屏障、表面或其他见证事实。未支持的必要事实继续返回 `UNSUPPORTED`，不能因为它已经 known 就算安全。

## 3. 必须在源查询处收窄

执行顺序固定为：生成候选范围 → 按本次查询用途核对几何与材料规则 → 返回必要事实和缺失事实 → 证明器合并 → 现有接纳门禁逐项核对。

禁止在 proof 序列化、摘要生成、依赖清单、观察门禁或结果展示中按坐标、层高、遮挡状态或方块名过滤。最终门禁不得另设“其实不用观察”的例外。若原查询仍依赖某格，门禁就必须检查该格。

同一个格子可以对碰撞无关，却对材料或 fallback 必要。只有所有实际使用它的查询都证明无关，才可以不进入联合依赖。

## 4. 首轮只证明完整方块屏障

已知完整方块覆盖下层空间是本轮唯一候选屏障。屏障必须来自合法已知事实，使用受支持、非流体的完整碰撞体；它的材质仍须通过既有规则检查。判定依据形状、查询范围和实际触发规则，不维护隐藏下层材料或固定坐标的放行名单。

仅因宽碰撞查询纳入、且被上方完整方块完全覆盖的下层 owner 不再读取。这个结论不依赖下层格当前是未知、空气、普通方块、流体或未支持形状，否则缓存仍会暗中依赖被省略格。身体或材料探测范围真正进入下层格时，查询照常读取该格，并继续对流体和未支持机制返回明确拒绝。

这条规则只证明冻结世界中的碰撞和接触，适用前提共有四项：下层格只是宽查询 owner；正上方是已知、非流体的完整方块；身体最低点位于该方块顶面或更高；执行期间屏障事实不变。原版活塞开始移动前会先完成 `PistonHandler.calculatePush()`，被推动的目标格随后替换成 `MOVING_PISTON`。`PistonBlockEntity` 的移动形状与推实体扫掠最高只到屏障顶面；水平蜂蜜拖动最高到下层格上方 `1.500001` 格，仍在屏障内部。身体不会进入这些查询盒。流体和材料回调只扫描收缩后的身体格，脚下速度与踩踏位置另取屏障格；完整方块也阻止下层流体向上流入屏障。活塞下一 tick 的推进属于世界变化或外力，沿现有偏离与失效路径处理，不由旧的冻结证明兜底。合成 `BlockGeometry.unsupported` 只用于验证查询和缓存没有偷偷读取下层格，不作为额外原版状态的证明。

每次省略下层 owner 前，都必须证明以下各项对当前用途成立：

1. 下层合法形状的可达范围不能绕过完整屏障改变当前查询。
2. 身体、分轴移动、step 候选及必要探测范围均满足该屏障证明的几何前提。
3. 下层事实不参与本次材料、支撑或伤害结论。
4. 屏障事实已经加入必要依赖，并沿用现有语义版本核对。

完整顶面并不自动等于本规格的完整方块屏障。上半砖、下半砖、楼梯、多盒拼接覆盖和带孔形状本轮都不推广。去掉屏障、改变形状或让身体进入下层空间后，相关下层依赖必须恢复；为 `UNKNOWN` 时返回 `NEEDS_WORLD` 或对应的 prepared 缺信息结果。

## 5. 按用途分别证明

| 查询用途 | 必须保留的判断 |
|---|---|
| 普通碰撞与 step | 分轴位移、碰撞事件、着地和全部 step 候选不变；保留 D119 的零高度候选语义 |
| 潜行防跌落、近地支撑 | 原版探测盒和输入削减结果不变；已知存在支撑不能冒充精确面积结论 |
| 支撑面积与支撑材料 | 有效面积、比例、支撑面和实际采用的材料不变；隐藏重复面不能凭空成为材料来源 |
| 姿态净空 | 身体变高后的完整碰撞查询仍可靠；没有对应证明就保留宽依赖 |
| 材料和流体作用 | 按真实触发位置核对身体内作用、脚下倍率、落地／踩踏作用和特殊接触；必要触发格未知或未支持时拒绝 |
| fallback 与 release witness | 尾段逐 tick 支撑、伤害及松键见证全部保留，不以主轨迹成功代替恢复证明 |

`_contacts_unmodeled_material()` 当前把碰撞依赖用于独立材料检查。D124 必须先查清原版触发位置与碰撞形状的关系，不能只删除这一检查，也不能把“没有碰撞”解释成“没有材料效果”。真正发生接触的特殊材料仍未获得普通运动支持。

## 6. 真实 1.21 状态与宽数据合同

`BlockGeometry` 当前允许 Y 到 2 的任意材料／形状组合。D123 的两格高蜂蜜块是该合同的有效边界反例，不是实际原版状态，也不能被删除或改写成错误实验。

D124-0 要用锁定的 Minecraft 1.21 原版代码、实际形状和触发调用点，建立本次省略规则的适用范围。代表样本只能验证论证，不能代替未知格全部可能状态的上界。必须说明哪些合法形状和材料机制已由通用规则覆盖，哪些仍未关闭。

`vanilla-block-registry-1_21.json` 只列方块 ID，`block-motion-traits-v1.json` 只登记移动效果。两者都不是完整的 `BlockState` 目录。`BlockState` 是包含朝向、连接、水浸等属性的方块状态；实际碰撞还可能受邻居和实体碰撞上下文影响。注册名已经登记、某种移动效果已经分类，都不能证明全部状态和上下文形状已经覆盖。

环境版本标签本身不能证明任意输入几何合法。已知异常形状、未支持机制和没有足够模型依据的输入，必须保持明确拒绝或原保守路径。不能把合成材料／形状当作真实原版事实，也不能为了排除合成反例而直接收紧全局 `BlockGeometry`、破坏历史载入。若不能在现有入口清楚区分本规则的适用范围，就停止，不以新布尔开关绕过合同。

适用范围由现有 `PhysicsWorldView.__init__()`／`from_snapshot()` 物理世界入口和源查询共同确认；在线与 prepared 查询使用同一份规则。省略只要求：该格不是直接占用格，并且其正上方是已知、非流体的完整方块。完整方块进入依赖。下层格本身不会为了决定能否省略而被读取。跨 section 的下层变化不会使缓存结论失真；屏障变化、身体进入下层或查询用途变化会恢复下层读取。

## 7. 证明汇总与版本

parent、successor、全部可执行 fallback、neutral release witness 和已有时序分支分别形成必要依赖，再取并集。不能只核后继或只核父主轨迹。

`prepared_motion_proof._support_fraction()` 当前会先把宽候选并入依赖；这条路径必须与在线 fallback 使用同一规则。原始取数范围、快照边界和 section 的保守有效性检查可以继续较宽，但不能因此重新要求 actor 观察已经证明无关的格。

屏障及其他必要事实继续使用 `WorldModel.dependency_versions()`／`dependency_changes()`。真实语义变化、owner 缺失和历史不完整照旧拒绝；纯观察时间戳刷新按 D116 既有规则处理。不得使用隐藏方块变化通知。

新证明重新生成依赖、版本和摘要；旧证明不重新贴标签。沿用既有 proof、registry、worker 和 owner 生命周期。宽读诊断不携带第二份完整证明，不增加新的常驻状态或消息管线。

适用范围还须沿现有身份链保持一致：`NavigationObservationAdapter.ingest()` 建立的世界会话 → 借用世界版本及 `seal_snapshot_version()` 生成的 `SnapshotIdentity` → `PreparedMotionRequest.snapshot_identity`／`PreparedMotionJob` → `prepare_fixed_motion()` 及 bundle／proof。D124-0 逐项核对会话、规则、世界版本、快照 digest、请求与快照身份、proof 所属请求及必要依赖版本。准备入口和 worker 校验不得把不匹配身份重新解释成同一模型；若适用前提无法由现有链携带和复核，就停止，不静默退化成只比版本字符串。

`0e6b0141` 修复的 parent-only 与 successor 完整安全 tail-only 依赖不能被本次收窄遗漏。它们的内容变化和变成 `UNKNOWN` 仍撤销准备资格；纯 stamp 刷新仍保持资格。源查询候选和行为必须与冻结的宽查询 reference 独立对照，预期集合和 tail-only 见证不能由同一个新依赖收集器反推。

## 8. 已知目标与交付边界

D123-0 南向下层候选 `(0,62,z)` 中，`z=-6…-1、1、6、7` 的 9 格是待证明屏蔽对象；`z=0、2、5` 在父恢复或后继中仍必要。其他方向使用对应旋转身份。任何一条 fallback 或 release 查询仍使用某格，就必须保留。

若恰好证明这 9 个下层格不再属于必要依赖，联合依赖预计从 67 变为 58。这是待验证结果，不是写死的通过数字。D123-1 的视觉遮挡 9 格不是同一集合，不能代替物理分类。

D124 不保证取得剩余 3 格的 actor 事实。它们未知时正式门禁继续拒绝。D003 的匿名穿墙几何不恢复，D004／D035 的合法观察规则不变；不实现视点规划，不进入 D123-2，不修改 Session、transport、Java 或生产动作能力。
