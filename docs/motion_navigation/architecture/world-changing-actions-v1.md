# 改变世界的动作架构 v1

日期：2026-09-25
状态：B11 实施基线

## 1. 要解决的问题

已知地形中有时不存在纯移动路线，但放置一个方块后路线会成立。B11 先支持普通完整方块的放置和有限搭桥，同时保持现有导航、观察和输入边界不变。

## 2. 职责

| 模块 | 负责什么 | 不负责什么 |
|---|---|---|
| 导航规划 | 找纯移动路线；无路时提出一个明确的 `RequiredInteraction` | 不直接写世界，不假定交互成功 |
| 放置事务 | 核对前置条件，产生一次交互意图，等待并判断结果 | 不寻找全局路线，不持有第二份地图 |
| 视角与站位 | 把机器人带到已知安全站位，并让准星稳定指向指定方块面 | 不决定该方块是否值得放 |
| Runtime 与仲裁器 | 保证每帧只有一个正式控制出口 | 不把提交动作当成成功 |
| Fabric 客户端 | 核对当前准星、距离和客户端状态，调用原版使用动作 | 不直接生成方块，不越过服务器规则 |
| WorldKnowledge | 接收后续正式观察中的真实方块事实 | 不接收规划器的假想方块 |

## 3. 有类型的交互要求

`RequiredInteraction` 至少保存所属规划请求、目标及修订、交互种类、目标格、支撑格和点击面、预期物品和方块、可执行站位、世界依赖、尝试次数和截止时间。

首版交互种类只有 `PLACE_BLOCK`。该对象表示“路线要继续，必须先完成这件事”，不表示操作已经获准或已经成功。

## 4. 一次放置事务

1. **准备**：当前世界会话、目标修订和依赖仍匹配；机器人位于已知安全站位。
2. **核对**：支撑格是已知实体方块，目标格是已知空气；目标格不会与玩家身体相交；主手是获准的方块；当前准星命中指定支撑面。搭桥站位在被点击侧面之外，并保持潜行，避免身体覆盖目标格或从边缘滑落。
3. **提交**：发送一次 `InteractBlockV1`。放置期间不同时提交移动。
4. **等待**：保存提交所依据的观察序号、主手物品数量和目标格事实。
5. **确认**：新的正式观察显示目标格是预期完整方块。生存模式还要确认对应物品数量减少一件。
6. **交接**：事务完成，旧路线候选失效；导航从当前身体状态和新世界事实重新规划。

`pending_confirmation` 只进入第 4 步。它不能直接完成事务。

## 5. 失败和重试

目标格仍是空气、变成其他方块、观察缺失、支撑或主手变化、客户端拒绝、超过确认期限、库存变化不一致或身体偏离安全站位，都不算成功。重试必须先取得新的交互观察并重新核对前置条件。同一原因最多重试两次。超过上限后返回有类型失败，不循环点击。

走位和瞄准从第一次准备观察起最多持续 120 次新观察。操作准备完成后，如果连续 20 次新观察都没有赢得操作仲裁，也返回明确失败。计数只随观察序号前进，不随同一帧内的函数调用增加。

## 6. 与导航的连接

规划器优先寻找不改变世界的路线。只有纯移动路线不存在、任务授权放置且候选满足冻结边界时，才允许返回 `RequiredInteraction`。

```text
走到工作站位 → 停稳并对准 → 放置一块 → 观察确认 → 从真实地图重算 → 继续走
```

交互完成前，规划器可以计算候选，但执行器不能越过交互点。导航到达工作站位后释放自己的有序输入源，由放置执行器通过同一个 Runtime 出口临时接管；事务结束后再把输入所有权交回导航。两个来源不会同时生效。交互失败后，原来的假想后半段全部作废。

Runtime 会在每个控制帧结束后更新共享世界知识。导航会话处理目标修订或恢复规划前，必须先吸收 Runtime 的最新正式观察，不能继续查询上一帧已经过期的不可变世界视图。

同一任务的目标位置可以修订，但不能重新发放方块额度。操作还没发出时，协调器撤销旧放置并立即采用新目标。操作已经发出时，旧事务继续负责确认结果；期间只合并保存最新修订。确认成功或世界依赖变化后，再把最新目标交给导航；其他终端失败仍结束当前任务，不能被新目标掩盖。任务取消仍会停止未提交的放置，已经发生的世界结果则由后续观察保留。

## 7. 有限搭桥

首版最多连续放置三块普通完整方块。每一块都是独立事务：上一块得到正式确认后，才能把它作为下一块的支撑。任一步取消、失联、观察不完整或依赖变化，都会停止继续放置，并让机器人留在已确认安全区域。

三块上限属于一次任务授权，不属于某个目标坐标或目标修订。新的独立任务通过新的导航会话取得自己的额度。

首版不包含边走边放、跳搭、脚下搭柱、斜向速搭、挖掘、开门、容器交互或消耗型特殊道具。

## 8. 长期扩展

以后增加挖掘、门、按钮或建筑任务时，扩展交互种类及其前置条件和确认器。导航仍只读取“是否可执行、完成后世界会怎样”的有类型结果，不能拥有物品操作和世界确认状态。

以后需要边移动边放置时，移动执行器继续拥有身体责任，放置能力只贡献视角和操作。仲裁器在同一控制帧中合成经过声明的兼容通道；组合输入改变运动轨迹时，必须重新验证受影响部分。B11 当前没有开放这项能力。
