# Minecraft 运动／导航模块：详细架构与分阶段验收规范

版本：1.0（设计基准）
日期：2026-09-18
适用项目：Minecraft 常驻 2P AI 机器人
状态：拟议架构和验收要求；不是已经实现、通过实测的系统。本文不修改现有仓库。

## 0. 核心决定与使用方法

**新建一条运动／导航主线，保留三个旧实现作参照，逐个迁移组件，不合并三个旧版的全部控制状态。** 保留现有游戏接入技术栈，不因本次设计切换到 Mineflayer、ROS 或其他框架。下面的模块名、接口名和目录都是新主线建议，不是声称仓库中已经存在。

**第一批工作不生成全部架构代码。** 实施必须依次完成三版参照固定、数据与几何统一、固定路线步行、已知图规划与后台隔离，再用一个小型跨高度动作验证扩展边界。前一阶段未通过时，不提前创建后续模块的复杂空壳，也不在后续层补条件掩盖基础问题。

现有公开仓库是三个不同来源的源码摘录／实验覆盖层，不含完整工程、世界、运行日志或回放。本文基于用户已描述的需求与该快照确定设计方向；B01 用本地封存运行补齐完整源码身份和运行证据，实际物理参数与输入生效时序仍须在后续阶段从完整运行工程导出并验证。[R1]

本模块接收“去哪里、使用哪些能力、允许多大风险”，输出可跟踪的执行结果；内部以结构化游戏状态为输入，最终控制移动、视角、跳跃、蹲伏、冲刺等玩家输入。LLM、Jev、任务规划和人格不进入每帧闭环，不拥有直接写入控制输入的权限。

全局目标保持三点：

1. **正确性**：不把未知空间当空气，不把地图计划当动作许可，不跨越未授权的能力／世界修改边界。
2. **连续性**：当前局部动作仍可验证时，不因远处规划未完成而无谓停车；必须停车时能说明原因。
3. **可扩展性**：三维场景扩展世界表示，跳跃等扩展移动能力，跟随等扩展目标管理，不为每个场景复制导航系统。

推荐阅读顺序：第 1–4 节确定边界和数据；第 5 节给出模块实现；第 6–8 节说明协作时序；第 9–12 节规定测试和实施；第 13–15 节指导 AI 交付、迁移和扩展。

**所有数值指标分为三类，不能混用：**

- 设计不变量：例如只有一个输入写入者，必须始终满足。
- 初始验收目标：例如控制计算 p99 ≤15 ms；是建议设立的门槛，不是已有成绩或行业统一标准。
- 实测配置：例如角色碰撞体、阻力、输入延迟、可跨间隙；必须从固定版本校准，不能照搬本文的示例数值。

## 1. 范围：这个模块做什么、不做什么

### 1.1 对外提供的能力

| 能力 | 含义 | 所属层 |
|---|---|---|
| 到点／到区域 | 到达满足位置、层高、支撑、必要朝向条件的状态 | 目标管理 |
| 跟随 | 持续维持与合法可见目标的关系，不是一次性到点 | 目标管理 |
| 暂停／取消／替换目标 | 按当前动作允许的方式停止或切换 | 会话与动作执行 |
| 步行、冲刺、蹲行 | 不同动力学与身体约束的移动配置 | 移动能力 |
| 上台阶、跳上、跨隙、受控下降 | 有前置条件、途中约束和完成条件的动作段 | 移动能力 |
| 局部绕行 | 在小范围已知安全空间内绕开障碍并接回原路线 | 局部规划 |
| 获取路线所需信息 | 转头或移动到已验证的观察站位 | 观察协调 |
| 卡住检测与有限恢复 | 判断是否无进展，执行可解释、有次数上限的恢复 | 执行监控 |
| 攀爬、游泳等后续能力 | 通过相同动作接口接入，但使用各自动力学和安全规则 | 后续移动能力 |

### 1.2 不归本模块独立决定的事

攻击谁、是否撤退、采集什么、建造什么、是否花费资源，属于上层任务／战术。导航只执行明确授权的目标和移动策略。

挖掘、放置、开关门等会改变世界或操作物品的动作，不默认藏进“寻路”。没有授权时，这些边不可用，而不是赋一个很大但有限的代价。需要时，导航输出 `RequiredInteraction`，交给拥有权限的交互／施工技能执行，收到实际世界变化后再继续。

载具、鞘翅、创造模式飞行可沿用会话和地图接口，但不承诺共用步行动力学。首版不得把未支持模式退化成普通步行继续执行。

### 1.3 三维世界不等于在全部空气体素里搜索

世界知识始终三维。步行搜索图初期只建立“可站立的支撑面／站位节点”，同一 `(x,z)` 可以有多个高度、多个支撑面。跳跃通过带动作类型的边连接这些节点。

早期图节点可使用：`(world_session_id, support_id, sample_id, pose_mode, entry_class)`。`entry_class` 初期仅为“已稳定站立”或有限的可接受速度区间；后续需要带速接续时扩展。不得假装位置相同就意味着动作起始条件相同。

这里借鉴了导航中规划、控制分责，以及目标与移动方式分离的思想，但实现仍针对你现有的 Minecraft 运行时。[R2][R3]

          ▼
M11 安全检查、动作仲裁、唯一 MotorGateway
          │ 最终输入与有期限的失联回退
          ▼
Minecraft 玩家身体
          │ 实际观测
          ▼
M01 观测接入与身体状态 ─────► M02 世界知识与变化日志
          │                         │
          └────────┬────────────────┘
                   ▼
           M03 几何与动力学查询
                   ▼
           M04 移动能力／动作原语库

M12 进度监控与恢复：读取实际结果，向会话／执行器发事件，不自行写输入。
M13 调度与诊断：控制执行预算和记录证据，不修改目标、路线或地图语义。

这 13 个编号是责任定位，不要求一次创建 13 个服务。固定路线阶段只需要其中的最小实现。简单模块可先是一个文件；只有出现独立状态与测试边界时再拆分。

| 编号 | 约束 | 关键测试 |
|---|---|---|

| I11 | 安全限制不是可被路径收益抵消的代价 | 禁止落差／禁止挖掘不能被更短路线选中 |
| I12 | 日志和计时不能改变导航决策 | 日志拥塞时仍执行同样控制；诊断只读 |

## 3. 最小数据契约：模块之间具体传什么

本节是接口规范，不是现成可运行代码。字段中的时间均明确单位，禁止不同进程单调时钟直接相减。

### 3.1 基础坐标、时间与版本

内部长度统一用“格”，速度用“格／秒”，加速度用“格／秒²”；角度统一用弧度，桥接层负责与游戏角度转换。游戏每 tick 的速度值必须按校准后的 tick 语义换算，不能把 `0.2 格/tick` 当 `0.2 格/秒`。

连续位置以脚底参考点表示，碰撞体由当前姿态提供。方块坐标采用 `floor`；楼层／支撑面由碰撞几何求得，不能普遍用 `round(y)-1` 推断。半砖、楼梯或下落中的角色尤其不能使用该简化。

区分三种时序：游戏 tick、控制进程单调时间、客户端采样／应用 tick。跨进程或 JVM/Python 通过 request ID、sequence ID 和采样／接收／应用标记关联；无法准确同步时保存时间区间，不拼接出虚假的精确延迟。

### 3.2 关键对象

| 对象 | 必须包含的内容 | 生命周期与含义 |
|---|---|---|
| `BodyState` | 世界会话、观测序号、位置、速度、yaw/pitch、姿态、包围盒、接地／碰撞、移动模式、状态修正、输入应用标记、时间 | M01 最新不可变身体状态 |
| `WorldSnapshot` | 只读查询接口、各类语义版本、支持面／碰撞／介质／实体／已知范围 | 当前地图视图；禁止每帧深复制整图 |
| `WorldDelta` | 变化区域及字段掩码：几何、支撑、介质／摩擦、危险、证据、实体、范围重置 | 有界日志，按变化实际内容更新 |
| `GoalSpec` | goal_id、revision、类型、目标坐标／实体、满足条件、可接受更新范围 | 身份不随每次小位移变化 |
| `NavigationRequest` | GoalSpec、允许能力、风险／资源约束、超时、优先级、取消策略 | M05 管理的一次导航会话 |
| `MotionPrimitive` | 类型、起始状态集合、目标状态集合、环境依赖、执行阶段、完成／失败／取消规则、代价模型 | 一个可组合的移动能力定义 |
| `RouteCandidate` | 搜索请求 ID、目标身份／版本、世界范围、起点锚定状态、动作段序列、代价、依赖、结果状态 | 后台结果，不能直接发输入 |
| `ActiveRoute` | 稳定 route_id、路线修订号、动作段、接纳时刻、独立进度游标 | 路线变化才变修订号 |
| `ExecutableCorridor` | 当前及前方短段的允许区域、起止进度、必要支撑／净空、停止或落地区域、局部依赖 | 比整条路线小的执行承诺范围 |
| `LocalTrajectory` | 时间索引状态、完整控制序列、扫掠空间、末端可恢复状态、依赖、截止时间 | 不是一个孤立“前视点” |
| `ObservationTask` | 缺口 ID、待知空间／属性、用途、最迟需要时间、可选站位／视线、尝试与结果 | M10 单一管理 |
| `ControlFrame` | 控制序号、世界会话、身体基准、apply_tick／有效期、完整输入包、动作阶段、回退策略 | M11 唯一接纳和发送 |
| `NavigationReport` | 当前状态、动作、进度、等待原因、相关空间、恢复结果、终止原因 | 向上反馈事实而非自评 |

### 3.3 对外接口

建议统一为：

```text
start(NavigationRequest) -> navigation_session_id
update_goal(navigation_session_id, GoalSpec) -> 更新接纳结果
cancel(navigation_session_id, cancel_mode) -> 取消接纳结果
poll(navigation_session_id) -> NavigationReport
```

`cancel` 的返回只确认“取消请求已接收”，不伪装成“角色已经停稳”。跟随是持续任务，满足距离要求后进入保持状态而不是一次性 SUCCEEDED。

### 3.4 动作段怎样接起来

规划中的相邻边需要有可实现的状态接续，不只是坐标相同。前一动作应能把身体送入后一动作的入口状态集合；若需要降速／转向准备，把它放入原语的 PREPARE 阶段并计入代价。两个状态集合存在一个交点，不代表任意一次实际落地都能直接开始下一动作。

运行时由 M09 检查实际身体是否进入下一入口集合。未进入时允许在已验证空间内调整；无法调整则重新接续或恢复。不能因为路线表中两段相邻，就跳过条件检查。

### 3.5 不能合并的版本

世界重置、几何变化、动力学材料变化、证据刷新、实体变化、目标变化、路线变化、身体变化分别有标识。`Dependency` 写明“关心哪片空间的哪些属性”，不是只比较一个全局 `map_version`。

例如，同一方块被重复看到可只更新证据；几何未变却变成更滑的材料，需要唤醒动力学依赖；实体靠近需要重验局部轨迹，但不是把静态墙重新建图。长期历史可支持路线意图；真正进入运动／落地区域前，证据必须满足 SensorProfile 与风险策略的有效范围和刷新要求。不要使用“所有地形永远可信”或“统一每隔固定短时间让整图失效”两种极端。

## 4. 地图与通行语义

### 4.1 知识状态与碰撞状态是两条轴

```text
知识状态：UNKNOWN / OBSERVED / STALE_OR_UNCERTAIN
几何状态：EMPTY / FULL / SHAPES / UNSUPPORTED
其他属性：流体、摩擦、危险、可交互性、证据来源与时间
```

已知的空碰撞体不一定是空气，更不等于安全地面；已知空气也不能提供脚下支撑。观察失效不会把曾经的墙直接删除成空气。实体离开视野也不能立即视为消失，要按轨迹和不确定区域处理。

三维地图明确区分自由、占据和未知，是成熟占据地图的基本做法；本项目并不因此需要引入 OctoMap 的八叉树或概率模型。[R4]

### 4.2 正式观测与测试全知必须隔离

B02 从新主线实际使用的完整运行配置导出 `SensorProfile`：距离、视场、遮挡规则、空空间成立条件、已处理覆盖范围、预算截断和世界加载范围。

**本设计不擅自把“视野内可知”扩展成全区块透视。** 正式图只收合法观测；测试全知地图通过 `TEST_ORACLE` 专用适配器进入，不得被正式启动配置加载。最终性能报告分开记账。

一个采样包必须声明 `processed_region`／`coverage_mask` 和 `complete`。即使传感器宣称某范围体积完整可知，也只能在确实处理完且保证完整的区域，将“省略的空值”解释为空；超时或截断的尾部仍未知。

如果数据来自稀疏射线，穿过某格的一条线不能无条件证明整个格子的碰撞体为空。对部分方块尤其要保存被确认的空间范围，或由合法适配器给出完整碰撞形状。

### 4.3 通行查询统一为类型结果

`validate_state`／`validate_transition` 返回：

- `FEASIBLE`：在声明的模型和证据范围内可执行。
- `BLOCKED`：存在明确障碍或不满足支撑／危险约束。
- `NEEDS_INFORMATION`：缺少必要信息，附具体空间和属性。
- `UNSUPPORTED`：能力、材质或模式尚未支持。

计算是否结束另用工作状态表达，不把“还没算完”混进物理通行状态。

节点和边都使用同一个几何／能力库。图搜索可以选探索目标，但不把待证实的边标成已经确认的执行路径。

## 5. 各模块的作用、关系与实现

### M01 观测接入与身体状态

**作用：把游戏真实发生的状态转成可信、时间含义明确的输入。** 输入是现有客户端／运行时采样；输出 `BodyState` 和经过权限过滤的地图／实体观测。

实现先复用现有桥接，不重做 Minecraft 客户端。统一字段、单位、坐标、版本以及本次已应用输入的标记。乱序旧观测可进入审计记录，但不能覆盖更新的身体状态。重复包不得重复推进动作状态机。

识别接地、空中、游泳、攀爬等模式；暂未支持的模式照实报告。死亡、重生、跨维度、重连和传送产生范围重置或重锚定事件。突发位置跳变首先标记 `STATE_DISCONTINUITY`，不把它解释成角色高速穿过中间道路。

游戏对象读取遵守原运行时线程约束。游戏线程只做必要采样与输入应用；重型 JSON 日志、整图比较、全局搜索不放在这里。

**失败处理：** 观测过期、缺失、输入确认丢失分别报告；交给 M11 选择当前模式下的有界回退。不能无限外推角色位置，也不能在同一个旧 tick 上连续发出多次新的动作阶段。

**关键测试：** 单位转换、负坐标、yaw 跨边界、重复／乱序包、延迟确认、暂停 tick、传送、死亡重生。

### M02 世界知识与变化日志

**作用：保存“已知什么”，而不是“希望哪里能走”。** 输入来自 M01；输出不可变地图视图与 `WorldDelta`，供 M03/M04/M06/M07/M08 查询。

初期采用稀疏体素／分块字典与简单空间索引即可。空格记录可以按 tile 压缩；碰撞形状统一存局部坐标或世界坐标并在接口写清，不混用。支持面由已知几何提取，同一水平列可保留多个表面。

更新按观测中的脏方块／区域进行，只变更实际字段变化的语义版本。静态几何、介质／动力学、危险、实体和证据分别维护。建立小型有界变化日志；消费者使用自己的游标。日志历史丢失时让该消费者重同步，不把整个导航都清空。

后台地图镜像通过 tile 快照和差分更新。初期 tile 粒度可以略粗，允许额外计算，但不能漏掉必要变化。只有测得粗粒度误触发明显时，才增加逐属性的倒排依赖索引。

热点局部区域更新优先；一帧海量远处变化可以排队分批处理。**但本地关键更新不完整时，不能声称本地地图已经是最新并继续授权。** 大量远处更新的处理延迟单独记录。

**失败处理：** 未加载、未观测、截断、陈旧各有状态；不能把数据没到当作空气。地图裁剪不得静默丢掉当前动作／落地区域的依赖。

**关键测试：** 悬浮结构、同列上下层、已知空气与未知、相同值刷新不重建几何、同形状材质变化、区块卸载和差分丢失。

### M03 几何与动力学服务

**作用：统一回答“身体放得下吗、走过去会撞吗、输入后会到哪、还能怎样停下来”。** 这是共享计算库，不拥有任务、路线或当前按键。

最小接口：

```text
body_shape(body_state) -> 当前姿态的碰撞体
query_support(body_state, world) -> 支撑结果与依赖
sweep(shape, trajectory, world) -> 连续路径的碰撞／缺失信息结果
predict(body_state, control_sequence, dynamics_profile) -> 状态轨迹及误差范围
recovery_envelope(body_state, recovery_policy, world) -> 有界制动／落地范围
```

几何先用 AABB 和现有碰撞盒，宽相位通过空间索引筛选，窄相位做扫掠相交。不能只查路径端点，也不能仅逐格中心采样。姿态不同采用不同碰撞体；支撑容差与净空容差区分，防止允许地面接触时也错误允许穿墙。

动力学不把 MC 当作瞬时可控的点：预测至少考虑速度、地面／空中模式、输入、姿态、材质与版本配置。内部可做确定性短时模拟或经过校准的模型。P1 用实际输入—状态对建立误差范围；复杂材质未验证前由能力配置禁用。

地面安全范围是“这一小段动作 + 之后可执行的制动轨迹 + 延迟和模型误差膨胀”。不把 `v²/(2a)` 当所有材质、所有模式的精确公式。若控制期间转向，预测必须使用实际 yaw 生效方式。

误差范围太大时，应降低速度、缩短承诺或禁用该动作，而不是不断加厚安全边界直到所有窄路都被封死。模型测试通过只说明测试范围内可信，不构成对任意外部服务器扰动的数学保证。

**关键测试：** 边界接触、角点擦过、薄碰撞体、低顶、部分支撑、不同初速度、滑行、转向与侧移组合、摩擦变化。

### M04 移动能力与动作原语库

**作用：把几何／物理能力变成可以被搜索和执行共同使用的“动作段”。** 输入是起始状态、候选目标、地图和能力配置；输出可用的带类型边及执行模板。

每种原语遵守同一契约：

```text
生成候选终点 → 检查起始状态集合 → 检查环境依赖
→ 给出目标状态集合与代价 → 创建执行阶段 → 定义成功／失败／取消
```

搜索只生成已启用的原语。每条边携带所需支撑、途中净空、落地／制动区域和材质依赖。`Walk` 与 `JumpGap` 共享基础几何，但不能共用“全程必须脚下有支撑”的规则。

| 原语 | 主要前置条件 | 成功条件 | 取消要点 |
|---|---|---|---|
| `Walk` | 支撑和净空已确认，速度在配置范围 | 进入下一动作的入口区域或终点集 | 使用当前地面制动策略 |
| `StepUp` | 台阶高度在经校准的自动上台阶范围，途中净空足够 | 到达更高支撑面 | 上台阶中按接触状态处理 |
| `JumpUp` | 起跳区、上方净空、落地面和入口速度满足条件 | 确认到达目标支撑面 | 起跳前可取消，空中转入落地／恢复 |
| `JumpGap` | 起跳及整段可达轨迹、落地和必要缓冲区已确认 | 落在目标状态集合 | 同上；不得只确认落点中心 |
| `ControlledDrop` | 落差、危险和损伤约束允许，落地区域已知 | 落地且风险结果满足约束 | 离边前／离边后分别处理 |
| `Climb` | 附着面与当前模式已验证 | 到目标高度并进入可接续状态 | 保持附着／进入已验证出口 |
| `Swim` | 流体、姿态、流速、呼吸预算在支持范围 | 到目标水域／上岸状态 | 不等同于地面松键停稳 |

蹲行和冲刺初期作为 Walk 等原语的动力学／姿态配置，避免无意义复制类别。一个原语不可支持所有起始速度：早期 JumpUp 可要求低速起跳；这项限制必须写进边，执行器不能临时发现不满足后再反复重选。

Baritone 的移动接口把动作状态推进和 `safeToCancel()` 分开；本设计借鉴“动作有阶段和安全取消条件”，不照搬其实现。[R5]

### M05 目标与导航会话

**作用：管理一次导航的目的、状态和生命周期。** 它不算几何、不写按键。输入是上层请求和运行事件；输出规划请求、执行指令和导航报告。

最初只实现 `PointGoal`、`RegionGoal`；随后加入 `FollowGoal`。每个目标有 `satisfied(body, observed_world)` 和更新策略。目标条件包括必要层高／支撑关系，不能只检查 XZ 半径。

会话状态建议为：

```text
IDLE → RUNNING ↔ WAITING_INFORMATION / WAITING_ROUTE / WAITING_DYNAMIC
              ↘ RECOVERING
RUNNING / WAITING / RECOVERING → CANCELLING → CANCELLED
RUNNING → SUCCEEDED（一次性目标）
任意活动状态 → FAILED / UNSUPPORTED（给出结构化原因）
```

跟随在满足关系时仍为 RUNNING，并以子状态 HOLDING 表示保持。观察站位是当前会话内的子目标，不替换原始任务身份。新玩家命令可替换目标；原任务产生的迟到规划结果不能再接管身体。

取消策略至少分 NORMAL 和 EMERGENCY。NORMAL 由 M09 报告可取消阶段；EMERGENCY 仍须选当前可行的风险最小动作，不承诺能让空中角色瞬间静止。若物理环境已无可行恢复，必须报告而非虚假成功。

**关键测试：** 同坐标不同楼层、重复提交、目标轻微变化、任务替换、取消过程中收到旧结果、跟随保持而非结束。

### M06 全局路线规划

**作用：在已有可用能力组成的图上，产生到目标或合理中间目标的路线候选。** 它只拥有搜索工作，不拥有当前执行路线。

首版使用 A*；小图用独立 Dijkstra 验证可达性和路径代价。代价先用非负预计执行时间，加明确的舒适／风险软代价；禁止能力、不可接受危险直接排除。启发式不能高估所用代价下的真实剩余代价；没把握时先用零启发式做正确性基线。

图按需生成邻接边，Walk 可从四邻接开始，验证后开放对角与连续捷径。转角捷径须检查完整扫掠和支撑，不因两端都可站而通过。Jump 等边由 M04 生成，不在 A* 内部堆地形 if/else。

搜索工作状态：`PENDING / COMPLETE / PARTIAL / NO_KNOWN_ROUTE / NO_ROUTE_WITHIN_COMPLETE_SCOPE / TIMEOUT / UNSUPPORTED`。其中 PARTIAL 只是有限结果，是否可执行由 M07 决定；不能把探索前缀当完整到达保证。

默认运行在独立后台进程。它可以分片 A*，但“分片计算”与“复用旧搜索结果的增量修补”不是一回事。后者在 P10 测得必要后再引入。D* Lite 的核心是复用前次搜索信息，不是单纯把 A* 放进生成器。[R6]

每个结果带世界范围、目标身份、目标版本、地图依赖、规划起点状态和请求 ID。迟到结果是否可采用，由 M07 与最新目标条件判断；不因身体移动几厘米就一概作废，也不忽略目标被替换。

固定目标可以考虑 D* Lite／LPA*；频繁移动目标必须单独验证策略，不能默认普通 D* Lite 已自动优化了目标移动。针对移动目标的增量搜索本身有专门研究。[R7]

**关键测试：** 小图穷举／随机对照、所有边条件、不可达与未知区分、预算耗尽、任务取消、旧结果乱序、局部新路口出现。

### M07 路线接纳、进度与可执行走廊

**作用：把后台“想走的路”转成当前能够消费的执行安排，并维护稳定进度。** 它是接纳路线的唯一拥有者。

候选接纳依次检查：世界／任务身份仍一致；能力配置没有失效；相关证据变化没有破坏待用前段；当前身体能安全接到路线的某个前方入口；接纳不会跳过未执行的动作要求。完整路线未全部验证时，只接纳可确认的前缀。控制线程的结果接纳也必须有预算：先检验有限前缀和元数据，远处整条路线的整理、复制、平滑不能偷偷放到本帧关键路径。

`route_id` 表示一条接纳路线的身份，`route_revision` 表示实际几何／动作变更，`progress` 单独记录。当前身体点不参与路线身份散列。进度投影只在当前段及有限前向窗口中寻找，使用层高、动作顺序和方向约束，避免跳到隔墙平行路段或楼上路段。进度通常单调；需要倒退时必须进入明确恢复分支并记录重锚定。

走廊不只是中心折线：它包括角色中心允许经过的区域、相关支撑面、必要净空，以及末端的停止／落地区域。第一版可用经过几何验证的小矩形／凸区域集合，不必一开始实现复杂多边形走廊。

依赖严格区分三个范围：整条路线、当前短走廊、本帧运动加恢复包络。走廊不能简单复用整条路线依赖。远处断路只缩短后续承诺／请求修补，不必取消眼前可执行段。

新路线较好但旧路线仍安全时，先在合法接续点切换。初始切换门槛可设为预计剩余时间改善同时超过 10% 和 0.5 秒；属于待校准的防抖配置，紧急阻塞不等待该门槛。

**关键测试：** 远处变化不撤销局部动作；同帧多类变化；相邻回头路；身体跨过路点；旧候选可接续；路线身份稳定；局部绕行只接回合法前方段。

### M08 局部运动规划与跟踪

**作用：基于当前身体状态，在短时窗内找出能执行、能接续、必要时能恢复的控制方案。** 它不仅选择一个目标点，还输出预测轨迹与完整控制包。

建议先做“前视跟踪 + 有限候选前向模拟”：

1. M07 给出当前进度和前方允许区域；沿路线自身切线和弧长选择前视目标。
2. 根据速度、拐角、制动边界决定允许的速度和方向。不能把身体偏离中心线误判成路线自身拐弯。
3. 地面初期枚举 9 种前后／侧移组合；加入视线选择后，最多检查少量兼容的 yaw 候选，例如 3×9，而非枚举任意长按键串。
4. 每种候选做有限短时预测，并附加制动／可接续验证。示例地面前向窗为 6 个 50 ms 控制间隔，但恢复包络不能被这个示例窗截断。
5. 先硬过滤碰撞、支撑、未知、能力和危险；再对进度、横向偏差、速度误差、输入切换与净空余量评分。
6. 只执行本次选定方案的第一个控制间隔，下帧依据新状态再规划。

候选模拟步骤之间也做扫掠检查，避免高速穿过薄障碍。控制与视角必须联合计算：先确定实际将执行的 yaw 变化，再把期望世界方向转为前后／侧移输入，并预测整个动作。不能先证明直行安全，发送前又独立转头改变方向。

局部绕行在 P6 增加：当中心线连接被阻断时，在有界、已知局部空间中做小图重接，生成短绕行折线，再交给同一跟踪器。局部绕行允许超出原中心线附近的窄区域，但必须另行验证新的空间，并接回正确的未来路线段。持续堵塞且局部无可行接续时，请求全局修补。

拐角平滑只在可验证扫掠体留在可行区时使用。狭窄直角处减速可以是正确行为，不要求“任何角度都不减速”。Nav2 的 Regulated Pure Pursuit 也将前视、曲率／障碍相关速度调节和前向碰撞检查结合使用；这里借鉴机制，不复用其轮式机器人参数。[R8]

**关键测试：** 小横向偏差、恰好到达末点、零长度段、自交／近邻路线、急转弯、低顶、有限候选均不可行、可局部绕行、视角改变后侧移保持世界方向。

### M09 动作执行器

**作用：知道“当前在做哪个动作的哪个阶段”，并根据真实反馈推进。** 它调用 M08 求动作，不能直接写输入。

通用阶段为 `PREPARE → EXECUTE → VERIFY → COMPLETE`，并可进入 `RECOVER / CANCELLING / FAILED`。不同原语细化子阶段，例如跳跃：

```text
接近起跳区 → 验证整段条件 → 对齐／调整速度 → 提交起跳
→ 确认已离地 → 空中修正 → 确认落地 → 交接下一动作
```

“按下跳跃”不能直接推进为“已经在空中”；如果实际没离地，要在有限观察窗口内判定输入未生效或起跳受阻，不不断重复起跳而不报告。

每个动作有起始状态集合和完成状态集合。Walk 接 Walk 时，可以穿过接续区域而不停车。Walk 接 Jump 时速度需要进入该 Jump 的允许区间。初版跨高度动作可以先低速起跳以验证接口，但不得把所有中间节点永久规定为停稳点。

每帧动作阶段结合当前身体、局部证据和输入应用标记更新。模型偏差过大时暂停常规阶段推进，触发 M12 重锚定／恢复；不能凭累计时间认定已经完成。

**关键测试：** 动作未实际执行、起跳失败、碰顶、空中改目标、落地误识别、连续 Walk 不停稳、走—跳—走接续。

### M10 观察任务与视线协调

**作用：解决会影响当前或即将执行动作的具体信息缺口，不追求无目的地看更多。** 读取 M04/M07/M08 产生的 `NEEDS_INFORMATION`；输出 ObservationTask、视线提议或已知安全的观察站位子目标。

优先尝试在当前动作仍安全的条件下转头观察；无法观察才规划到可达站位。路径沿途需要观察，不代表每个观察任务都必须停住。只有缺口进入动作必要空间或停止／落地准备范围时，才成为硬执行约束。

状态统一为 `QUEUED / ACTIVE / ANSWERED / OCCLUDED / UNOBSERVABLE / EXPIRED`。同一个缺口的空气请求、视角动作、候选等待不再由三套独立变量分别管理。

失败观察的重试需有理由：相关世界几何改变，或完成能改变可见性的站位／视线动作。单纯 yaw 跨过一个量化桶，不自动撤销旧拒绝。初期同一缺口与等价视点最多两次主动采样；仍不可见则换已验证站位或返回受限状态。

探索目标从“已知可达安全区域边缘，且可以获得有用信息的站位”产生。先用路程、朝向目标的进展、预计信息价值、重复尝试代价选取有限候选，不先实现复杂人格或全局信息最优策略。

可见障碍不意味着所有观察姿态都无效，但转头也不会穿透实体遮挡。若当前知识下没有可达观察站位，报告 `NEEDS_INFORMATION`，不要把它伪装成地图已证明无路。

**关键测试：** 悬浮墙下可见地板／未知头部、边走边看、转头看不到必须换位、视线轻抖不重复申请、同一事实刷新不反复探索、观察失败不会永久封死真实通路。

### M11 安全检查、仲裁与唯一输入出口

**作用：只让当前可接受的完整控制包进入游戏，并阻止冲突、过期与无界持续输入。** M08 提议动作，M09 提供动作阶段，M05 提供优先级；M11 对兼容组合做最终验证，MotorGateway 是唯一写入点。

外部战斗、交互、视线模块只能提交意图。仲裁不是把各自字段随意拼接：导航已验证的移动与战斗新要求的 yaw 组合后，必须按最终整体重新验证。某阶段确实需要独占跳跃／视角时通过可撤销租约表达，不靠各模块争写按键。

最终验证检查世界会话、控制序号、有效期、当前姿态／身体偏差、控制能力、相关新变化和运动／恢复包络。初筛可复用同一帧几何计算；最终检查只重验变化依赖，避免全图重算，但证据过期不能复用。

控制过期不只是把 `movement=0`：地面选择已验证的制动或释放策略；空中优先使用当前动作声明的有界落地／恢复策略。需要的失联回退在进入动作前交给 MotorGateway，不能指望已经失联的 Python 进程来完成看门狗。

Python 的提交接口与客户端的实际输入状态机属于同一个逻辑 MotorGateway；最终游戏按键只有客户端这一个状态机写入，过期回退也在这里串行执行。租约最长持续时间和回退步骤在固定运行时中验证。回退仍由同一个 MotorGateway 串行写入，不增加第二个执行控制器。失去感知后不能继续无限期沿旧方向飞奔；同时不能承诺在外部瞬间删除落地面时仍能安全落地。

**关键测试：** 多模块冲突、租约过期、乱序控制、世界切换、取消与实际停止区分、地面／空中断流、最终转向改变移动方向。

### M12 进度监控与恢复

**作用：区分正常慢行、主动等待和真正无进展，并采取有限、可解释的恢复。** 读取路线进度、实际位移、输入应用、碰撞与动作阶段；只发事件和恢复请求。

不能只用“离目标直线距离是否减少”检测进度，因为绕行可能暂时远离目标。Walk 用路线弧长／连接进度；Jump 用阶段与落地进度；Follow 用关系保持和更新状态。

初始地面卡住检测可设为：有推进意图且不在声明等待状态，1 秒内沿路线进度不足 0.1 格，则进入诊断。它是初始配置，慢动作／狭窄精确动作使用自身阈值。

恢复顺序：检查观测与实际输入 → 重算本地连接／前视 → 请求必要观察 → 有已知安全空间时小范围退让 → 请求全局修补 → 明确失败或请求上层介入。禁止通过清空未知／危险事实来“解卡”。

同一原因、同一相关地图版本下最多两次同类恢复；无新证据不能无限旋转和重试。每次恢复记录触发证据、动作、结束条件、结果和剩余次数。

**关键测试：** 合法绕远不误报、跟随保持不误报、规划等待不算控制卡住、被实体堵住有限等待、同原因无进展有界退出。

### M13 调度、快照交换与诊断

**作用：使前面模块在时间与算力上真正分离，并产生能定位问题的证据。** 不允许“后台”只是计时标签。

建议默认组织为：现有游戏桥接 + Python 控制进程 + 一个后台规划进程。固定路线阶段不启用规划进程。初期不做每个模块一个进程，也不以多线程数量作为分层完成标志。

控制进程拥有最新局部世界、会话、当前路线和执行状态。后台只有只读镜像与自己的搜索状态。用有界队列传差分，结果用最新有效候选槽接收；不允许过时结果排成长队后逐个接管。初期按 tile 复制即可，确有瓶颈再增加共享内存，不先做复杂无锁系统。

控制频率默认目标 20 Hz；它是项目设计目标，实际提交需对齐运行时可用 tick。服务器降速时，不对同一个旧状态盲目补发多帧动作。全局搜索按目标／可达性／依赖事件触发；控制周期绝不等待它返回。

详细日志放入有界环形缓冲区异步输出。队列满时保留关键失败和汇总，记录丢弃数量，不阻塞控制。完整计时从观测包就绪到最终控制提交，包括地图增量、上下文、候选、最终检查、序列化和诊断入队；客户端采样和输入应用延迟另列。阶段计时明确 inclusive／exclusive 口径，嵌套调用不能重复加和；未分类部分叫 unclassified，不记成“局部轨迹生成”。

**关键测试：** 后台阻塞 500 ms／崩溃，日志消费者阻塞，地图差分积压，控制进程重启，迟到规划结果，正常与压力负载下端到端时间分布。

## 6. 一帧如何运行，以及什么时候重规划

### 6.1 控制循环：先保障当前执行，再改善未来路线

```text
A. 接收合法最新观测，处理世界／身体重置事件。
B. 先应用会影响当前运动和恢复包络的地图变化，形成 FrameContext。
C. 接收目标更新与取消；推进当前动作的实际反馈状态。
D. 非阻塞读取后台结果；M07 检查是否可接纳，没有结果就保留当前路线。
E. 根据当前身体重建／复核短走廊，不扫描整条路线来决定本帧是否能走。
F. M09 给出当前动作阶段；M10 给出兼容的视线建议。
G. M08 生成有限候选轨迹；不足信息时输出具体缺口；无局部连接时请求重接。
H. M11 仲裁最终完整控制，复核新鲜度／安全范围，提交 MotorGateway。
I. 更新实际提交记录；M12/M13 入队诊断和后台请求。
```

后台进程独立更新其地图镜像、修补图和推进搜索。最终控制前不得同步调用一个可能超时的全局 `improve()`。若选择暂时使用单进程协作分片，必须验证每个不可抢占步骤的最坏耗时；在此前不宣称具备后台阻塞隔离能力。

没有路线时，执行模式相关的保持／恢复，不让主循环同步等待求路。已有路线的安全前缀耗尽时，允许按声明的停止边界减速；不能因为当前还能移动就冲进未知。

### 6.2 地图变化不是一个互斥类别

采用工作标志集合：

```text
need_local_revalidate
need_local_detour
need_corridor_rebuild
need_global_repair
new_route_opportunity
need_observation
scope_reset
```

同一帧可以同时置多项。处理优先级决定执行先后，不抹去后面的工作需求。

| 事件 | 当前动作 | 局部／走廊 | 全局规划 |
|---|---|---|---|
| 无关远处同值刷新 | 不撤销 | 通常无事 | 通常不唤醒 |
| 近处相同形状但摩擦改变 | 按动力学重验 | 必要时减速／缩短承诺 | 路线代价必要时后台更新 |
| 实体横穿当前区域 | 重验，允许等待／退让 | 尝试局部避让 | 短暂经过不重建静态图 |
| 远处采用路线新增墙 | 安全前缀可继续 | 更新停止／接续边界 | 请求修补 |
| 近处实体 + 远处新增墙 | 局部响应 | 局部处理 | 同时保留全局修补 |
| 原先未知区域变成可走捷径 | 保留当前安全动作 | 不强制重接 | 低优先级路线改善机会 |
| 下一个起跳／落地条件变坏 | 不开始新跳跃；空中进入恢复判断 | 按动作阶段处理 | 修补后续路线 |
| 世界／任务身份已变 | 撤销旧会话控制权限 | 重锚定或清理 | 旧结果拒绝 |

新可达区域即使不碰当前路线，也可能形成捷径／解除探索等待。因此除了“当前路线依赖命中”，还需要“新连接机会”的事件；它不应该强制停车。

### 6.3 走廊长度不是固定几个路点

必要条件为：在当前观测和延迟假设下，角色至少有完成这一步并进入可恢复状态的空间。

地面可用直观解释：已确认前方距离应覆盖当前动作距离、制动距离、输入／观测延迟带来的额外距离及误差余量。实际使用 M03 的轨迹预测，不以一条恒定加速度公式代替所有情形。

跳跃需要在起跳前确认整段关键空间和目标落地区域，包括速度误差导致的范围。空中不因为局部规划器只看 0.3 秒就忽略剩下的落地过程。

“安全前缀很短”不是强行持续移动的理由；应降低速度或停在已经验证的位置。安全余量同样不能无限膨胀，让原本能够行走的一格宽通道全部不可用。

## 7. 三个端到端例子

### 7.1 悬浮墙：看到地板，但身体空间不确定

M02 记录支撑已知、头部范围未知；M04 返回 NEEDS_INFORMATION，不能直接把该边放进已确认执行图。M06 可选择沿已知路线接近一个合法观察站位。M07 保留眼前已确认前段；M10 提前申请具体净空信息；M08 在还能安全前进时边走边配合观察。

若观察确认碰撞，M02 发布几何变化并由 M06 绕行；若确认净空，原请求结束并扩展走廊；若被遮挡，换已验证站位或报告知识不足，而不是每转头一次就重新选择同一个失败候选。

### 7.2 走—跳—走

M06 返回 Walk、JumpUp、Walk 三个动作段。M07 接纳前段，同时 M04/M03 检查 Jump 的入口速度、途中空间、落地和后续接续。M09 在合适时刻由接近转入起跳准备，按实际离地进入空中阶段，落地后进入下一段。

普通取消发生在起跳前，则停止开始新跳跃；发生在空中，则记录取消中并执行当前可行的落地／恢复。只有安全阶段到达后才报告 CANCELLED。若突发世界变化造成无安全轨迹，报告不可恢复风险，不能以取消成功掩盖。

### 7.3 跟随玩家转弯上楼

M05 持有同一个 FollowGoal。玩家小幅移动只更新目标关系，不清空路线。目标在楼上时，“同 XZ”不满足目标。M06 通过已启用的上升／跳跃能力找路，M08/M09 复用同样的执行链路。

玩家突然消失时，只使用合法最后已知状态与已允许的短时预测。不能继续读取隐藏实体精确位置。目标停住后机器人进入保持距离子状态；迟到路线结果不应让其重新冲向过时坐标。

## 8. 跟随、多模式与外部任务接口

### 8.1 跟随的初始策略

目标关系包括实体身份、期望间距区间、层高／可达关系、视线要求和丢失目标策略。初始示例：距离超过 3 格进入追随，降到 2 格内停止主动接近；过近时根据可用空间退让。这里 2/3 格是可配置的迟滞例子，不是对所有任务适用的默认正确值。

目标移动超过 0.75 格、进入新支撑区域、旧末端不再满足关系，或当前路线不可接续时，提交新的规划目标版本。后台请求合并成最新一项；小幅更新不销毁当前安全路线。

保持旧路线并非永远正确：目标大幅反向时应根据新的关系目标调整执行，不为了防抖一路走向旧位置。对比方案的改进阈值只用于仍可用路线之间的优化，不能掩盖任务目标已经不匹配。

跟随测试必须限制目标速度和动作在机器人已启用能力的可达范围内。玩家传送、飞行或持续快于机器人时，正确结果可以是 TARGET_LOST／TARGET_OUT_OF_CAPABILITY，而不是要求不可能的追上。

### 8.2 能力启用是显式配置

`CapabilityProfile` 指明允许的原语、材质、姿态、速度区间、最大风险、版本绑定和测试证据。P2 只启 Walk；P4 单独启一个 JumpUp；P7 才扩展组合。功能尚未通过验收，就不得因为“模型感觉可行”出现在正式搜索图里。

### 8.3 与战斗、施工、交互的关系

上层可给导航 RegionGoal、到交互距离的目标、避开某区域的硬约束，或给出世界修改授权。攻击、放置、挖掘意图和导航意图通过同一个身体仲裁；不在导航外再启动一个 WASD 控制器。

尚未实现多技能共享时，使用明确的单技能占用：外部技能等待导航安全取消／让出身体。后续再开放兼容视线与移动共享，不能一步跳到任意字段混合。

## 9. 测试体系：用什么证据说明真的完成

### 9.1 五层测试，不能互相替代

| 层级 | 方式 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| T1 纯函数／契约 | 几何、单位、状态、版本、动作边界的确定输入 | 边界和局部逻辑正确 | 实机完整闭环一定正确 |
| T2 性质／对照 | 随机小图对 Dijkstra，几何暴力参考，隐藏世界非干扰 | 关键不变量在大量组合下成立 | 分布外的绝对保证 |
| T3 记录回放 | 同一合法观测序列喂给决策模块 | 复现停顿和状态变化；解释同输入决策差异 | 改变动作后的真实后续世界 |
| T4 闭环模拟 | 简化物理中输入改变下一状态，故障注入 | 阶段接续与故障响应 | Minecraft 物理完全一致 |
| T5 游戏闭环 | 固定版本真实客户端／服务器、统一地图和起点 | 最终玩家实际行为与时序 | 未测版本／服务器配置的保证 |

不能让被测程序自己输出“safe=true”就当作安全证据。评估器独立检查实际轨迹、支撑、碰撞／伤害和预定义任务结果。测试真值可以读取完整地图，但绝不回流正式观测。

### 9.2 场景注册表

| ID | 场景 | 最重要的断言 |
|---|---|---|
| S00 | 空地直行与停止 | 输入真实生效、停止误差与滑行符合配置 |
| S01 | 直线小偏移、终点重合、重复路点 | 不除零、不回拉、不因 0.02 格偏移丢失前视 |
| S02 | 宽／窄 L 形走廊 | 不切墙；普通 Walk 接续不要求每点停稳 |
| S03 | U 形／近邻平行／自交路线 | 不跳到隔墙段；进度按正确顺序 |
| S04 | 地板可见、低顶或悬浮障碍 | 支撑与身体净空分别判定 |
| S05 | 坑、边缘、部分支撑 | Walk 不越坑；禁止能力不会被偷偷启用 |
| S06 | 同 XZ 上下层、桥与桥下 | 不混楼层、不穿层、不误判到达 |
| S07 | 对角角点、薄障碍、窄缝 | 检查扫掠体而非只看端点 |
| S08 | 合法观测下实体横穿／短暂消失 | 局部避让、有限等待、未知占用不过早清空 |
| S09 | 远处加墙、近处实体同时变化 | 两项工作都保留；眼前安全动作不无故取消 |
| S10 | 动态挖地／新增障碍 | 可恢复注入零违规；不可恢复注入诚实报告 |
| S11 | 后台慢 500 ms、乱序结果、崩溃 | 安全走廊够用时控制不受后台阻塞 |
| S12 | 已知无路／未知阻断／能力不足 | 返回不同状态，不互相伪装 |
| S13 | 起跳未发生、空中取消、落地失败 | 状态由真实观测推进，取消具有阶段语义 |
| S14 | 跟随抖动、拐弯、上楼、目标丢失 | 稳定目标身份、距离迟滞、丢失规则 |
| S15 | 几何相同但摩擦／危险改变 | 不忽略动力学变化，也不误当全图几何变化 |
| S16 | 遮挡、换观察站位、相同视点重试 | 观察请求唯一，有界重试，不永久拉黑未知 |
| S17 | 地图规模、日志拥塞、输入／观测断流 | 预算与看门狗真实有效 |
| S18 | 取消、传送、死亡、重连 | 旧会话／旧动作／旧结果绝不接管新身体 |
| S19 | 水域／攀爬／出水接续（扩展） | 独立模式条件、资源与取消策略 |

低顶和悬浮测试直接用世界坐标描述底面高度和厚度，例如“最低碰撞面位于脚底 + body_height −0.02”，不要只说“墙两格高”。这样不同 agent 才会构造同一种测试。

### 9.3 每次游戏运行保存什么

至少保存代码 commit、依赖锁定、游戏／模组／运行时版本、服务器设置、硬件／系统、物理与观测配置、地图快照／生成种子、起点、目标、实体脚本、随机种子、输入和实际采样、诊断版本、结论。

原始输入和身体轨迹优先保留；大量逐候选细节可在失败前后环形导出。游戏视频可辅助观察，但不代替结构化状态和计时。

### 9.4 无谓停顿不能由机器人自己随便解释掉

定义低速片段：活动导航过程中实际水平速度低于 0.1 格／秒、连续至少 0.15 秒的片段；跳跃／爬行等使用自己的进度指标。是否“无谓”，依据该场景预先声明的合法等待窗口及当时可用信息判断。

终点停车、跟随保持、必要观察、已承诺的起跳准备、动态堵塞可以是合法等待，但须有对应事实。仅输出 reason='safety' 不自动豁免。已知固定路线的空地／宽转角用例应没有中途低速；窄急转角则按预先定义的可执行速度曲线验收，不强求全速。

### 9.5 不可恢复扰动与安全保证边界

动态挖地有两种不同测试：

- 在可观测、且剩余响应距离大于校准恢复包络时挖地：要求不越过危险边界。
- 在角色已经无任何可行恢复动作时删除脚下／落地面：不要求物理上不可能的零坠落；要求立即识别、执行允许的最小风险动作、正确上报，且不伪装成功。

测试标签在运行前固定，不能失败后把原本可恢复场景重新归类为不可恢复。

## 10. 全局验收门槛（拟议初值）

这些门槛用于新主线，尚无实测成绩。首次产生新主线性能成绩前，要冻结参考机器、固定版本、观测规则和负载；改门槛要写决策记录，不能为了某次失败偷偷调整。

### 10.1 功能、安全与统计

| 项目 | 初始门槛 |
|---|---|
| 强制确定性回归 | 全部通过；不得因新增能力跳过旧场景 |
| 范围内安全事件 | 已定义为可避免的穿碰、误入危险、非预期坠落为 0 |
| 随机闭环验收 | 每能力集至少 200 次，覆盖多地图／起点／朝向；成功 ≥99%，所有失败有记录 |
| 未知语义 | 未获准执行穿越 UNKNOWN 的动作；相同合法观测下不依赖隐藏真值 |
| 输入冲突 | 第二写入者、过期输入接纳、旧会话恢复执行均为 0 |
| 结束准确性 | 普通到点：水平误差 ≤0.25 格、站位层／支撑满足条件、速度 ≤0.1 格／秒；精确站位单独更严格配置 |
| 顺滑步行 | S00 无中途低速；S02 宽转角无节点强制停稳；窄转角允许必要减速 |
| 横向误差 | 直线跟踪 p95 ≤ min(0.10 格，可用侧向余量的一半)，不得靠侵入碰撞空间达标 |
| 相对耗时 | 只有存在同权限、同路线、同能力且可启动的旧控制基线时，才比较完成时间中位数，初始门槛为不超过 1.15 倍；没有公平分母时按对应决策改用绝对门槛 |
| 回退／恢复 | 同原因同事实最多两次同类恢复，无无限循环；未支持能力有明确返回 |

“200 次中零事故”不是证明事故概率为零。报告要保留样本量、场景分层和失败，不把有限测试成功率直接宣称为所有世界的稳定成功率。重新运行多次同一地图也不能当作完全独立场景。

统计口径：成功率只统计预先声明可达、能力和感知条件允许的导航用例；不可达／未知不足／未支持用例分别验收返回是否正确，不通过大量正确拒绝来抬高到达成功率。超时、任务无端重置、模型没有完成动作都算失败。基础设施异常可以另列，但必须保留次数与原因，且不能把规划超预算或本模块崩溃移出失败分母。

P2/P4 的 100 次试验是早期中间闸门，不等于正式能力发布已经满足本节至少 200 次的统计门槛；P7/P10 发布时补齐相应样本和场景分层。

### 10.2 时序预算

参考控制周期 50 ms（20 Hz）。时钟停滞／服务器降 TPS 独立记录，不能用额外 CPU 循环伪装多次有效控制。

| 计时项 | 初始目标与解释 |
|---|---|
| 控制进程完整本帧时间 | p95 ≤8 ms、p99 ≤15 ms；名义测试最大 <30 ms；包括局部更新、控制、最终检查、序列化和诊断入队 |
| 本机采样到输入实际应用 | p99 ≤100 ms；覆盖桥接和 tick 对齐，不等同于远程服务器网络保证 |
| 控制硬期限 | 应在本帧 50 ms 期限内完成提交；名义 10 分钟测试期限失败为 0，超时必须记录并触发模式相关回退 |
| 初次规划（≤10,000 可站立节点基准） | p95 首条可用路线候选 ≤500 ms；2 秒未完成需报告 PENDING/TIMEOUT，不阻塞本帧控制 |
| 本地可恢复危险响应 | 在收到该变化后的下一个有效控制机会提交对应响应，最多一个控制周期；物理停止时间另按模型判断 |
| 后台阻塞注入 | 500 ms 搜索阻塞、且已确认走廊可支撑至少 2 秒动作／恢复时，不新增无谓停车，不错过控制硬期限 |
| 日志阻塞注入 | 日志消费者阻塞 5 秒，控制继续；丢日志明确计数，不静默假装证据完整 |

参考负载：单机器人、普通已校准地面、已知图不超过 10,000 个支撑节点、20 个以内近处实体、有限局部查询范围；具体地图窗口／碰撞候选上限最迟在 B03 实测前固定。更高负载单列压力档，不能用降低观测权限、去掉安全检查来冒充性能优化。

上述目标如在参考机器上暂时达不到，应先定位阶段耗时。允许通过设计评审调整目标，但调整后重新运行相同场景和全部安全门槛；不能把“改阈值”写成算法提速。

### 10.3 模型校准门槛

普通地面初值目标：单步位置预测 p99 误差 ≤0.05 格，6 步预测 p99 误差 ≤0.15 格。实际碰撞／恢复包络还要覆盖校准和验证集中的最坏误差加明确裕量。误差必须小于待执行空间容许余量；即使统计目标通过，也不能在比误差更窄的通道里宣称安全。

改变游戏版本、姿态、运动状态或关键材质后，该组能力应重新验证。模型偏差被触发时是能力／状态问题，不通过无界重试掩盖。

## 11. 实现顺序：每阶段交付、测试与验收

各阶段保留先前所有适用强制测试。只在明确改变需求契约时替换旧测试，并记录旧断言为什么不再适用；不能删除失败测试后宣布通过。

### P0：固定三版参照、运行边界和测试入口

**交付：** 固定三个用途不同的参照：悬浮墙实验前版本用于运动表现比较，重叠空气识别版用于知识语义和失败反例，当前分层版用于路线寿命与后台规划边界。每版同时记录公开摘录身份、完整实机源码树身份和已有封存运行。冻结 S00、S02、S04、S05 四类场景，并建立统一的输入、身体轨迹、分时钟计时和运行摘要格式。三版都不是新架构底座，也不从不同版本拼出一套控制器。

**不做：** 新寻路、新感知推断、所有旧代码的整理迁移。

**测试：** 逐文件核对三版公开源码摘录；用三版各一份已有封存实机证据验证统一导出。校验一次输入请求可以关联到真实应用与之后身体观测。控制进程和客户端采样分别计算耗时，不跨时钟相减。四类场景在后续产生公平新成绩时沿用同一身份；B01 不为凑齐矩阵重复运行游戏。

**验收：** 三版用途、源码指纹、报告和封存运行可以对应；公开快照可由固定命令完整核验；已有封存证据可只读导出统一格式。参照可以有已知失败，失败必须保留。跨 JVM/Python 时钟不能直接相减。B01 不宣布任何一版成为新主线，也不声称四类场景已有完整横向成绩。

### P1：三维知识、几何与短时动力学

**交付：** M01/M02/M03 最小实现，三维支持面与权限语义；普通地面物理模型；显式能力配置初版。尚不自动导航。

**不做：** 全局搜索、复杂探索、跳跃自动执行、未经验证的特殊材质。

**测试：** S04/S05/S06/S07/S15 的几何构型；至少 10,000 组有确定预期的随机小几何组合，与独立暴力参考比较。真实游戏对前进、侧移、停止、转向、组合输入分别采样，覆盖多个初速度／朝向，并把校准集与验证集分开。

**验收：** 所有知识语义与确定几何用例通过；同 XZ 多支撑面不混淆；未知不被推断为空气；相同事实刷新不触发几何变化；动力学达到第 10.3 节目标或显式收缩能力范围。模型外状态返回 UNSUPPORTED，不能偷用已校准地面参数。

### P2：固定路线步行执行闭环

**交付：** M08/M09/M11/M12 的 Walk 路径，最小 M05 会话；固定路点／区域直接喂给执行器；地面取消、看门狗、结束判断。这里不启用全局规划进程。

**不做：** 自动找路、主动探索、跨高度路线。

**测试：** S00/S01/S02/S03/S07：直线、宽窄拐角、不同朝向、0.02/0.05/0.10 格横向偏移、终点重合、连续重复路点。至少 100 次参数化固定路线闭环；每个关键确定场景至少 10 次真实游戏运行。另测取消、丢控制确认、地面输入断流。

**验收：** 强制用例全部到达；已定义为可避免的碰撞／越边为 0；S00 无途中低速；宽转角不在每个路点强制停稳；终点符合普通到点条件；轻偏移不回拉；无除零；地面取消按实测停止包络完成。存在公平固定路线旧控制基线时，完成时间中位数初值不超过 1.15 倍；B03 的基线缺口按 D007 处理。

**阶段价值：** 后续出现迷宫停顿时，先确认它是否属于已经被单独验证过的执行器，而不是把运动与找路混在一起调。

### P3：已知地图 A*、路线接纳与真正后台隔离

**交付：** M04 的 Walk 邻接、M06 的 A* 后台进程、M07 路线／走廊、M13 快照交换。用已知小图做定位基线，但仍通过同样通行查询。

**不做：** D* Lite、复杂观察站位评分、多动作路线。

**测试：** 至少 1,000 个有限随机图，A* 与 Dijkstra 比较可达性及未平滑路径代价，误差不超过 `1e-6 × max(1, reference_cost)`；端点可站但中途不通的边必须被拒绝。真实空地、高墙、坑、悬浮结构的完整已知图；另测 S11/S12/S18。

**验收：** 强制已知迷宫全部到达；完全已知范围内无路结论正确；部分结果不伪装完整路径。路线身份不因身体位移变；后台故意阻塞 500 ms 时，足够长安全前段上的运动不增加无谓停车。旧目标／旧世界结果不能接纳。达到初次规划和名义控制预算。

### P4：尽早验证一个跨高度动作

**交付：** 一个低速、普通地面的 JumpUp 或经物理校准可执行的上升原语；走—上升—走；上下层节点；阶段式取消。选哪一种具体上升动作由 P1 物理能力证据决定，不把一格高障碍默认当自动 StepUp。

**不做：** 连跳跑酷、最大距离跳跃、复杂下落、全部三维材质。

**测试：** S06/S13：正常起跳／落地 100 次，覆盖有限位置和速度扰动；低顶、未确认落地、入口速度不满足等拒绝用例；在起跳准备、刚离地、空中和落地确认阶段分别发取消／新目标。

**验收：** 声明范围内有效动作 100/100 完成；不满足条件的动作不启动；观察到实际离地才进入空中阶段；取消不伪装瞬间停止；目标层正确。加入该动作只扩展原语、执行器与必要图节点，不要求为它复制地图／任务／输入系统。

**阶段价值：** 在继续打磨平地之前，先证明框架没有把“任何时候可以松键停车”“位置决定全部状态”写死。

### P5：接入正式观测、净空缺口和观察协调

**交付：** M10、合法局部观测下的 M02/M04、必要探索子目标；单一 ObservationTask 生命周期；TEST_ORACLE 从机器人输入中关闭。

**不做：** 更改观测权限来提高成绩、复杂信息论最优探索、整套旧空气状态机移植。

**测试：** S04/S12/S16；相同合法观测下构造不同隐藏世界，检查到获得新证据前决策相同。地板可见但头部未知、可转头补全、完全遮挡需换位、无可达站位、重复证据、采样截断。选可在声明感知规则下解决的有限迷宫做至少 200 次参数化游戏闭环。

**验收：** 未确认体积不进入执行许可；不能看见的事实不泄漏；同缺口同等价视点最多两次主动采样；没有相关新信息不重新激活同一失败请求。眼前安全前段可继续时不因远处观察任务而停车。强制可解场景全通过，随机组成功 ≥99%；知识不足、无路、未支持返回不同状态。

### P6：动态变化、局部绕行与按需修补

**交付：** WorldDelta 多项工作标志、分范围依赖、短时实体占用、M08 小范围绕行／接回、局部无法解决后的全局请求。

**不做：** 把所有地图更新当全局重算理由；不为瞬时实体重建整张静态图。

**测试：** S08/S09/S10/S11/S15。每种变化既测只命中远处，也测命中当前执行／恢复范围；特别构造“近处实体 + 远处加墙”“新捷径不碰当前路线”。动态挖地分别测可恢复与不可恢复窗口。至少 200 次参数化扰动。

**验收：** 可恢复场景无违规；反应在收到变化后的下一个有效控制机会提交。无关变化不撤销局部动作；混合变化同时保留两类工作；局部有已知可行绕行时接回正确路线段；局部无路则有界等待或全局修补，不无限左右抖动。远处观察刷新不造成任务重启。

### P7：扩展多移动方式及接续

**交付：** 经独立校准的冲刺／蹲行、部分高度地形、JumpGap、ControlledDrop，以及它们与 Walk 的接续。按能力逐个启用，而非一次全部开放。

**不做：** 未测最大跳距、未授权伤害换路、未经校准的冰面／特殊效果等配置自动通用。

**测试：** 每种新能力至少 200 次有效／边界扰动闭环，另加明确不能执行的反例；走—跳—走、连续高度变化、落地后转角、跨模式取消、姿态改变后净空变化。最大边界距离在校准组与验证组分别测试，不用单次成功作为最大能力证明。

**验收：** 强制有效场景全部完成，随机组 ≥99%；所有不可行边拒绝；没有未授权坠落／伤害；中间 Walk 接续不强制停稳；每个动作完成后确实进入下一动作的入口状态集合。旧平地测试仍通过，未选能力保持不可用。

### P8：跟随、目标更新与外部身体占用

**交付：** FollowGoal、目标更新合并、迟滞保持、目标丢失策略；与外部视线／任务取消的明确仲裁。初期不同时接入完整战斗策略。

**测试：** S14/S18：玩家匀速、停走、反向、拐角、上楼、同 XZ 不同层、轻微目标抖动、短暂不可见、传送超范围。小范围已知地面和部分已知三维场景分组；至少 200 次参数化追随片段，另有 10 分钟持续场景。

**验收：** 目标小幅更新不清空当前安全路线；普通地面可追随条件下，启动稳定后至少 95% 时间落在测试配置的容差带。例如期望 2–3 格时可验收 1.5–3.5 格；该指标只用于预先声明可满足速度和空间条件的用例。不得持续顶撞目标。楼层错误不能判保持成功；目标超能力／不可见有明确状态；动态目标保持不产生反复 SUCCEEDED／重启。

### P9：额外移动模式按插件验证（扩展阶段）

**交付：** 按需要选 Climb 或 Swim，每次只接一种；模式识别、独立预测、资源约束、取消和进出模式的接续。载具／鞘翅／飞行独立立项，不自动算本阶段完成。

**测试：** S19；水流、呼吸不足、出水、附着面丢失、姿态变化、目标取消、状态跳变。每个声明支持的新模式至少 200 次有效／边界闭环，明确反例全部覆盖。

**验收：** 不复用地面停止假设；资源硬限制不被代价抵消；所有模式转换有明确观测证据；安全事件门槛和随机成功率与基础能力一致。未完成本阶段不影响 Walk/Jump 版本发布，但发布能力清单必须真实。

### P10：规模、长时间运行与旧版替换

**交付：** 完整新主线发布候选、支持能力／材质清单、性能报告和迁移开关。只有实测瓶颈需要时，才增加增量搜索、缓存倒排、原生优化或更复杂局部求解器。

**测试：** 全部适用 S00–S19；至少 1,000 次分层随机导航；30 分钟连续运行；地图扩大 10 倍、观测／日志负载、后台崩溃、输入延迟、重连。相同场景下与旧版比较，明确感知权限、路线、能力和风险是否一致。

**验收：** 强制测试全通过、随机 ≥99%、全部失败保留；可避免安全违规为 0。名义预算达标；地图静止、仅远处已知规模扩大 10 倍时，本地控制 p95 增量不超过 `max(2 ms, 原 p95 的20%)`，初始地图载入成本另测。30 分钟内存／任务／日志队列受已配置上限约束，无无限积压；不会因日志阻塞破坏控制。

D* Lite 等优化必须与同一图同一代价下的正确性基线对照；通过平均速度提升但引入安全回归不算完成。正式切换按能力范围，不在运行中静默轮流调用三个旧版兜底。

### 11.1 阶段依赖关系

```text
P0／B01 三版参照
  → P1 世界／几何／物理
  → P2 固定路线步行
  → P3 已知图规划与后台隔离
  → P4 最小跨高度验证
  → P5 正式未知与观察
  → P6 动态变化／局部绕行
  → P7 多动作组合
  → P8 跟随与任务交互
  → P10 集成发布

P7 之后按需求进入 P9 额外模式；P9 不阻塞只声明 Walk/Jump 的发布。
```

性能计时和必要优化贯穿每个阶段，P10 不是到最后才第一次查看卡顿。任何阶段如果依赖上一阶段未通过的能力，应先修基础问题，而不是在更上层补条件绕过。

### 13.2 第一批实际任务

第一批按下面五个交付包串行推进。这里的“交付包”是阶段门槛，不要求一次写完其中所有文件；每包仍拆成能独立验收的小任务。

| 顺序 | 交付包 | 本批交付 | 本批明确不做 | 通过条件 |
|---|---|---|---|---|
| B01 | 固定三版参照与统一比较口径 | 固定运动表现、知识语义、规划生命周期三种参照；冻结 S00 空地、S02 转角走廊、S04 悬浮墙、S05 坑边；把已有封存记录只读归一为输入、身体轨迹、分时钟计时和运行摘要 | 不选择新代码底座，不改变三版行为，不为补齐矩阵重跑游戏 | 三版公开摘录和完整实机身份可核验；四类场景身份固定；三版各一份真实记录通过统一导出，原始证据未改 |
| B02 | 统一数据和几何 | 明确时间单位、世界会话、三维支撑、未知与已知空空间；建立统一扫掠查询和普通地面短时预测 | 不加入自动搜索、探索或跳跃执行 | P1 的知识、几何、会话隔离和动力学校准门槛全部通过 |
| B03 | 固定路线步行 | 只接收外部给定路线；完成直行、转弯、停止、取消、输入失联和终点判断 | 不接 A*，不设置探索检查点，不加入跨高度动作 | P2 强制场景全部通过；有公平旧版基线时才比较相对耗时；运动错误能在执行层独立复现和定位 |
| B04 | 已知图规划与后台隔离 | 接入 A*、路线接纳、可执行走廊和真正独立的后台进程 | 不处理正式未知探索，不加入多种动作 | P3 通过；后台阻塞 500 ms 时，已有安全前段仍能继续执行 |
| B05 | 最小跨高度动作 | 只加入一个经校准的小型上升动作，验证动作前置条件、阶段推进、取消和 Walk 接续 | 不扩展成完整跑酷、连续跳跃或所有高度地形 | P4 通过；新增能力不要求复制地图、目标、规划或输入系统 |

必须先通过 B03，才能开始 B04；必须先证明 B04 的路线和后台边界成立，再用 B05 检查架构是否真的能够增加新移动能力。后续每个阶段按同样粒度拆任务。一个任务可以跨多个文件，但只能围绕一个可验收的行为或接口变化，不能同时改感知权限、评分算法和控制安全条件。

### 13.3 后续扩展应主要落在哪里

模块之间会互相提供数据，也会共同参与验收，但每类变化都必须有明确的主要落点：

| 变化 | 主要修改范围 | 可以影响但不应重新实现的范围 |
|---|---|---|
| 新增跟随 | M05 目标与导航会话；必要时增加目标更新策略 | M06/M07 消费更新后的目标，M08 继续跟踪已接纳路线 |
| 新增跳跃 | M04 移动能力、M09 动作阶段；M03 增加对应预测与扫掠能力 | M06 把新原语作为边使用，M11 复用统一安全检查和输入出口 |
| 新增地形或材质 | M02 世界知识、M03 几何／动力学、M04 能力判断 | 规划器通过统一通行查询得到结果，不在搜索内部增加散落的地形特判 |
| 更换寻路算法 | M06 后台规划内部 | M07 仍按相同候选契约接纳，M08/M09 不感知搜索算法名称 |
| 优化转弯 | M08 局部运动规划与跟踪；必要时校准 M03 动力学 | 不改变目标身份、全局路线语义或 MotorGateway 的唯一写入规则 |

如果一次功能必须同时修改上述大多数模块，应先检查接口是否缺少必要信息或职责是否放错位置。跨模块配合是正常的，重复建立一套目标、地图、路线或输入状态不是正常扩展。

### 13.4 给开发 AI 的任务契约

```text
需求编号与场景：例如 I07 / R-04 / S01
现象：可复现的输入与实际错误
本次改变：一个明确机制
读取：本规范相关模块、当前阶段、已有测试
允许修改：列出实际文件／接口
不得改变：感知权限、其他能力、终止条件等
失败复现：先运行指定反例，保留失败证据
实现：仅覆盖本任务所需行为
验证：原反例 + 邻近反例 + 全部受影响强制测试
交付：修改清单、实际命令、结果、未验证项、接口／文档变更
```

接口变更先改契约与消费者清单，再改实现。不能临时新增 `force_safe`、`ignore_unknown`、`legacy_mode` 等逃逸开关让测试通过，除非正式设计明确解释用途、范围和移除条件。

审查 AI 不只看实现者总结，应从需求和失败用例独立检查：是否改变了输入权限、是否把缺证据当障碍、是否把停止当成功、是否删了失败场景、是否把新状态分散到多个模块。

## 14. 从三个旧版本迁移的具体规则

悬浮墙实验前版本保留作固定路线运动表现参照；空气版的知识语义／反例转成测试；当前版的路线寿命、局部许可、后台工作分离思想保留。组件复用必须经过新接口和独立用例验证。

优先评估迁移：游戏接入、观测解码、输入适配、已有碰撞几何、普通地面运动测量、有效的转向／侧移控制、已有地图构造和轨迹采集工具。

不整体复制：旧的候选等待总状态、多个重叠观察生命周期、用 reason 字符串决定动作权限的调度、整个“路线／目的／动作”耦合对象。

新旧导航不同时写入身体。比较时可做离线影子决策，但只有被选择的控制器有 MotorGateway 租约。影子结果不影响真实地图知识或输入。

替换依据是“某能力范围全部通过验收”，不是新代码行数或组件测试总数。P3 通过可替换已知图 Walk；P5/P6 通过才声明正式部分观测动态步行；P7/P8 通过才开放对应动作／跟随。

## 15. 最容易再次走偏的地方

**把所有未来能力一次搭完。** 本规范先统一契约，未启用能力不创建复杂空壳，不为飞行提前构建完整六维搜索。

**把分层当成更多类和更多线程。** 真正分离需要不同状态归属、依赖范围和运行预算；后台必须接受阻塞／崩溃注入。

**把零碰撞当全部目标。** 必须同时验收到达、无谓停车、取消与有限失败；一直站着不算好导航。

**把局部轨迹当一个路点。** 必须包含时间、运动预测、必要空间和末端恢复条件；跟踪点只是其输入之一。

**把复杂算法当可维护性的来源。** 先用 A* 和有限候选验证语义；增量搜索与更复杂控制只替换其内部，不改外部权责。

**为了顺滑取消必要安全。** 同一个动作必须以最新身体、最终 yaw 和局部证据验证；未确认跳跃落地面不能靠更大评分奖励放行。

**把测试脚本里的真值带给正式机器人。** TEST_ORACLE 是诊断对照，不是感知能力提升；比较成绩必须注明权限。

**从失败后重新定义成功。** 地图、超时、合法等待窗口、不可恢复事件标签在运行前冻结，失败证据不能删除。
