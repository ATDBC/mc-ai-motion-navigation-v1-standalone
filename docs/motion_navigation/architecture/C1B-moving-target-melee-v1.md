# C1-B 移动目标连续近战 V1

日期：2026-09-24
状态：已实现，并完成正式 Fabric 验收

## 1. 要解决的问题

C1-A 已证明机器人能够接近固定目标、精确瞄准、提交一次攻击，并用后续观察确认命中。C1-B 要处理同一目标持续移动后的三个新问题：目标位置会变化，一次命中后任务仍要继续，目标死亡必须成为明确终态。

C1-B 仍是受限纵切片。它只处理已知平地中的一只普通成年僵尸，不处理多敌人、复杂战术、玩家受击恢复、远程攻击或主动修改世界。

## 2. 采用的结构

C1-B 把移动目标关系和近战攻击分开：

- 移动目标部分保存目标身份、当前位置来源、更新时间和期望距离，并决定何时更新导航目标；
- 导航继续使用现有世界知识、路线和控制链，不建立第二份地图；
- 单次近战部分复用 C1-A 的准星核验、客户端距离检查、一次性攻击、回执和命中确认；
- C1-B 任务执行器重复组合“追上目标”和“确认一次命中”，直到观察明确报告同一目标死亡。

C1-A 和 C1-B 共享一个不负责长距离导航的单次近战控制核心。C1-A 在它前面使用固定站位；C1-B 在它前面使用移动目标站位。这样不会把移动目标规则塞进已经验收的固定目标入口。

现有早期 `RuleFollower` 自己维护局部地图和路线，不作为 C1-B 底座。后续跟随羊、牛或玩家时，复用本文的移动目标关系和正式导航链。

## 3. 状态归属

| 状态 | 唯一拥有者 | 说明 |
|---|---|---|
| 当前目标、目标修订和任务终态 | C1-B 任务执行器 | 取消、替换和修订使旧请求失效 |
| 目标是否曾被直接看见 | 交战记忆 | 只由正式可见实体事实建立 |
| 交战许可及其依据 | 交战记忆 | 不由客户端实体查询自行授予 |
| 目标当前位置、生命和死亡事实 | 正式按需实体观察 | 只返回已登记的单个目标 |
| 当前动态站位 | 移动目标关系 | 不拥有地图和路线 |
| 当前接纳路线 | 现有导航层 | 小幅目标变化不自动清空路线 |
| 单次攻击阶段与命中确认 | 单次近战控制核心 | 不拥有长期目标和导航路线 |
| 最终输入及实际应用记录 | 唯一输入出口 | 导航和攻击都只能提交意图 |

## 4. 按需实体查询

`ObservationRequestV3` 增加有界的已登记实体查询。C1-B 首版最多查询一个已经存在的 `track_id`。请求不会按类型、距离或区域搜索隐藏实体。

查询结果至少包含：

- 世界会话、观察序号和客户端采样 tick；
- `track_id` 和实体类型；
- 相对位置、相对速度、碰撞箱、姿态和是否着地；
- 实体是否仍加载、是否死亡；
- 当前生命值和最大生命值；
- 本次事实的采样时间。

客户端只解析当前世界中已经分配过正式 `track_id` 的实体。实体从未直接出现过、身份不属于当前世界、已经卸载或请求超过数量上限时，返回有类型的缺失或拒绝结果。

原始查询结果不等于使用许可。交战记忆根据任务身份、直接观察历史和交战依据决定导航是否可以使用隐藏位置。

## 5. 位置来源和交战记忆

任务使用的目标位置带明确来源：

- `VISION`：当前正式观察直接看见同一 `track_id`；
- `ENGAGEMENT`：目标曾被直接看见，交战许可仍有效，而且按需实体位置仍新鲜。

C1-B 的交战许可使用冻结到 Minecraft 1.21 的规则证据：机器人在单玩家、单目标场景中确认自己命中一只普通僵尸后，该僵尸会按报复规则与机器人交战。证据类型记为 `RETALIATION_AFTER_CONFIRMED_HIT`。

这项许可只覆盖当前僵尸。它不能自动用于友方玩家的敌人，也不能推广到其他生物。以后支持“敌人仇恨友方玩家”时，需要增加相应的正式关系事实。

以下任一情况会撤销交战位置：

- 世界会话、任务目标或目标修订变化；
- 实体死亡或卸载；
- 按需位置更新超过冻结的新鲜期限；
- 正式观察出现身份冲突、时间倒退或记录缺口；
- 任务取消。

撤销后可以保留最后位置作为历史记录，但导航和攻击不能再把它当作当前位置。

`ENGAGEMENT` 只提供目标位置。普通近战仍要求当前准星、距离和作用路径成立，因此机器人知道墙后目标的位置时也不能隔墙攻击。

## 6. 目标生命

C1-B 允许读取当前已登记目标的准确生命值和最大生命值。该信息来自客户端同步的 `LivingEntity` 状态，并带观察序号和更新时间。

生命值只作为正式事实保存。本阶段不根据生命值选择进攻或撤退，也不实现伤害评分。以后策略可以比较“目标剩余生命上限”和“当前攻击能保证造成的最低伤害”。

生命值不能替代其他证据：

- 命中仍要求一次攻击回执和同一目标后续受击事实；
- 完成仍要求同一目标明确出现死亡状态；
- 生命更新过期后不能继续参与决策；
- 不能通过目标查询扫描其他隐藏实体的生命。

## 7. 移动目标和导航更新

移动目标关系根据目标位置计算一个合法攻击站位。目标每 tick 的微小位移不会直接重建路线。出现以下任一情况时才产生新的导航目标修订：

- 目标相对上次采用的位置移动超过 0.75 格；
- 目标进入新的支撑区域；
- 旧路线终点已经不能满足攻击距离；
- 当前路线不能安全接到新的站位。

新的目标修订只替换已经不再适用的路线部分。已接纳且仍安全的前段可以继续执行。后台规划仍按最新请求合并，旧结果不能重新接管身体。

若目标当前只由 `ENGAGEMENT` 提供位置，机器人可以先朝该位置转头。目标重新进入正式视野后，近战控制才能继续瞄准和攻击。

## 8. 执行流程

```text
ACQUIRE_VISIBLE_TARGET
  → PURSUING
  → STRIKE_READY
  → AIMING
  → ATTACK_SUBMITTED
  → CONFIRMING_HIT
  → RECOVERING_CADENCE
  → PURSUING / STRIKE_READY
  → CONFIRMING_DEATH
  → COMPLETE
```

1. 直接看见并绑定唯一普通成年僵尸。
2. 根据当前目标位置产生攻击站位，并由正式导航接近。
3. 进入近战范围后，导航释放输入，单次近战核心取得身体控制。
4. 精确瞄准、等待冷却、攻击一次并确认同一目标受击。
5. 首次确认命中后建立 C1-B 交战许可。
6. 等待受击动画清除和攻击冷却恢复，同时继续接收目标更新。
7. 目标离开范围时重新进入追击；仍在范围内时开始下一次攻击。
8. 只有同一目标明确出现死亡状态时完成任务。

导航和攻击不会同时拥有移动输入。目标在一次攻击准备过程中移出范围时，单次近战核心返回“需要重新接近”，由 C1-B 执行器接回任务，而不是把它误报为整项任务失败。

## 9. 固定种子和测试夹具

每个正式场景保存世界种子、场景种子、决策平手种子和僵尸 AI 随机种子。僵尸 AI 种子由测试夹具在服务端线程中、实体生成后的第一次 AI tick 前设置，并记录实际应用结果。应用失败或设置过晚时，场景不能进入正式样本。

固定种子只固定生物随机选择，不承诺网络和线程时序完全相同。每场仍保存完整观察流，并以实际观察离线重放上层决策。

僵尸保留正常 AI 和追逐。C1-B 测试夹具把它造成的伤害和击退影响归零，并验证机器人生命和外部速度没有变化。C1-C 再单独处理真实受击、外部冲量和恢复责任。

## 10. 取消和失败

- 取消时先撤销移动目标和未提交攻击；已经提交的一次攻击继续记录实际结果；
- 目标修订变化会让旧站位、路线、瞄准和攻击请求失效；
- 实体消失、卸载或更新过期报告目标丢失，不能报告击杀；
- 种子未应用属于夹具无效，不进入能力成功率；
- 有效可达任务超时仍保留在成功率分母中；
- 同一原因的重新接近、重新瞄准和攻击确认都有冻结上限；
- 关键观察或因果记录缺失时，运行可以保留为失败证据，但不能作为正式成功样本。

## 11. 不变量

1. C1-B 不建立第二份地图、路线、身体状态、视角状态或输入出口。
2. 移动目标位置、交战许可和攻击可行性分别表达。
3. 隐藏位置查询只针对已经登记的单个目标。
4. 精确生命只服务当前目标，不成为隐藏实体扫描接口。
5. 命中、生命值和死亡是三种不同证据。
6. 小幅目标变化不触发无条件全局重算。
7. C1-B 不处理玩家受击和外部击退。
8. 完整观察流和随机种子必须足以重放上层选择。

## 12. 实现结果与证据边界

C1-B 已按本文结构实现。正式入口使用一个 `MovingMeleeDriver` 组合现有导航驱动器与共享的单次攻击核心。按需实体事实、交战记忆、移动站位、攻击状态和输入应用记录仍由各自模块拥有，没有复制第二份地图或输入出口。

当前源码的正式批次 `20260924T091651661550Z-34995f43` 完成 20／20 个移动追击正例和 10／10 个有界反例。四个强制转开视角的正例都使用了新鲜 `ENGAGEMENT` 位置，并重新转回目标后继续攻击。全部正例至少确认四次命中、发生重新接近，并以同一目标明确死亡结束。整段控制计算 P95 为 5.7939 ms，P99 为 7.1828 ms。

正式重放从同一 trace 还原真实观察，并重新运行交战记忆、近战阶段和移动目标选择，共核对 3,145 次逐帧决策；“种子未应用”反例在场景开始前被拒绝，因此不进入决策重放。导航事件、攻击事件、仲裁和输入回执也保存在这条正式记录中。

这里的结论仍只覆盖受控平地和单只普通成年僵尸。服务端夹具隔离了僵尸造成的伤害和击退，因此没有验证真实受击后的动作责任，也没有验证多目标选择。
