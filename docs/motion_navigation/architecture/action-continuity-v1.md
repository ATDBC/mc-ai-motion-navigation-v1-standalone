# 动作衔接：用局部求解生成连续运动

日期：2026-10-02。状态：J1—J4 已实施，J5 已完成限定跨隙试点及受影响组件回归；全动作组合和长期运行门槛未关闭。依据[跨隙根因复查](../acceptance/current-navigation-visual-demo.md#跨隙根因复查2026-10-02)和 [D052](../decisions/0052-share-action-entry-and-preserve-verification-limits.md)。沿用现有求解器、控制器和监督者，不扩大运动能力、感知权限、伤害额度或 R28 时间盒。

后续只读审查确认：实际接口仍有单块正常出口、后继要求不完整、首个合法候选即返回和内部地面段停稳等限制。第 11 节是 [D053](../decisions/0053-separate-safe-landing-continuation-and-motion-quality.md) 的目标接口，尚未实现；当前试点通过不代表运动已经达到效率和连续性要求。

## 1. 要达到的行为

机器人应根据后面的地形和任务要求调整位置、速度、方向和姿态。允许带速通过，就连续通过；需要低速、转向或换姿态，就提前调整。任务终点要求停住时仍要停住。

主线是三个结果：减少合法衔接中的无谓停顿；偏离时继续有人负责身体；计算赶上真实输入期限。动作类别、文件数量和测试数量都不能代替这三个结果。

“下一段入口”是下一动作接受的身体状态范围。例如，跳跃可以接受朝北移动、站立、速度不超过声明上限且有足够起跳支撑的身体。这个范围与搜索使用的方块中心是两件事。

入口是各能力必须守住的条件，不是要求身体先到一个参考点停车。局部求解应同时考虑短距离接近、跨越和落地后的去向，从计算结果中找到连续输入；不逐项编写 Walk→Jump、Jump→Walk 等专用衔接规则。

保持三个层次：全局路线选通道；局部求解选短输入序列；在线控制根据实际观察执行和修正。图上两条边相连，不自动代表实际运动连续可行。

## 2. 全局路线与局部求解怎样配合

全局规划沿用已有支撑图、路线依赖和按需更新。它提供要经过的通道、必要能力和后续方向，不每帧搜索所有按键、速度和朝向。

局部求解读取真实 `PhysicsState` 和输入应用账本，在这条通道附近计算短输入序列。现有状态已经包含速度、姿态、朝向、跳跃冷却、资源及运动属性；不能把“物理确定”扩大为任意材质、效果和外力都已有精确模型。未知世界或未支持规则继续明确返回缺信息或未支持。

一个局部候选可以覆盖“继续行走若干 tick、起跳、落地后继续行走”。求解目标包含下一段需要的位置、速度和方向，不只要求落在某个方块上。动作名称继续用于能力、前置条件和责任报告，不规定每段都从静止开始、以静止结束。

短输入模板可以复用；把模板放到当前入口和当前世界中推演后，才得到可执行依据。首版扩展现有模板搜索，不预建覆盖全部地形、速度和姿态的离线动作库，也不替换成全局状态格搜索。搜索状态只保留影响后续可行性的区别；归入同一个速度或方向档，不自动证明状态可以互换。

滚动预测是每次根据新观察修正后面一小段运动。安全可恢复的地面继续使用现有闭环选键；严格段只能使用已验证命令或已验证修正。有效候选和全局路线继续复用，不因每个新观察全量重算。安全检查发生在越过危险边界之前：坑边步行的停止尾迹会掉下去时，也需要严格依据。

首个试点只用已验证普通材质的完整支撑面、同高一格跨隙、现有带速入口和落地后直行。它检验“前段—跨越—后段”的真实调用链，不同时加入途中转向、疾跑跨隙或新运动方式。

## 3. 复用哪些数据

| 数据 | 拥有者与用途 |
|---|---|
| `SegmentEntryWindow` | 下一动作提供位置、高度、速度、运动方向、姿态、模式和必要视角；继续只表达身体入口 |
| `ActionPreconditionResult` | 动作前置条件提供当前支撑、事实、落点证据与资格；缺信息和需要探边继续分开 |
| `VerifiedMotionResult` | 求解器保存本次具体入口、真实命令、输入投影、轨迹、出口和验证条件；复核不得改写条件 |
| `CandidateExecutionWindow` | 候选最早、最晚可以生效的运动 tick；与计算期限、动作长度、安全恢复期限分开 |
| 输入账本与状态锚点 | Runtime 提供实际生效历史和当前身体；预测未来的状态不能冒充已确认观察 |
| 任务重试／风险账本 | 延续原任务的等待、重试、伤害承诺与结算；切段、改目标或重求解不补回余额 |

预测前缀要关联原真实锚点、预计应用 tick、命令和视角。后台从该锚点推演前缀，在线再用实际应用和身体观察核对。预测出的未来入口不能包装成已经确认的未来锚点，也不能据此提前授权起跳。扩展候选记录复用现有不可变结果和工作身份，不另存一份权威身体状态。

入口域、具体候选入口和当前身体必须区分。原 B09 的格心、低速入口只约束它自己的校准动作。B10 求出的具体入口应指导对应前段；不能只更新速度上限，却继续强迫身体停到旧参考点。候选入口仍须处于声明的能力域和起始支撑范围内；扩大域先补证据。

同一入口范围内的不同状态不自动共用同一套空中命令。只有原证明覆盖的状态或起始变体可以直接使用；其他状态必须重新验证。

带速入口的速度、方向和姿态限制从下一能力绑定的同一份策略读取。不要让执行器从一份配置取 3 格／秒、求解器从另一份配置取不同上限。历史固定轨迹 Profile 与在线求解策略可以保留各自的支持域，但必须显式区分；原候选绑定的策略不能在复核时偷偷换成当前默认策略。

## 4. 谁决定衔接

| 模块 | 负责什么 | 不负责什么 |
|---|---|---|
| 后台规划 | 给出通道、能力顺序、依赖和候选入口域 | 不搜索每帧按键，不把预测入口当成当前许可 |
| 现有运动 worker／求解器 | 从具体身体状态推演有限短输入序列，覆盖接近、跨越和后续需求；验证严格段及恢复 | 不更新任务、写真实输入或接管身体 |
| `MotionRouteCoordinator` | 提前准备候选、消费后台结果、选择仍适用的入口与起始变体 | 不自行求解另一套按键，不另建停止状态机 |
| `FixedRouteController`／当前动作控制器 | 用当前观察选短期输入，使身体进入下一入口；必要时安全减速 | 不按下一动作的类型自行改变验证门槛 |
| `ActionRouteExecutor` | 决定同一路线的段顺序，核对段入口并完成内部交接 | 不拥有第二份目标、世界、输入账本或任务额度 |
| `ExecutionSupervisor` | 处理换路线、探边、取消等身体控制权交接 | 不逐段重新实现每种动作的启动规则 |
| Runtime／唯一输入出口 | 仲裁并登记实际发送、应用窗口和回执 | 不用候选准备完成冒充输入已生效 |

同一路线切段时，`RouteControl` 仍是身体负责人。内部运动控制器可替换，但不新建导航任务。换路线或交给探边时才走监督者的身体交接协议。两层共用入口、输入责任和证据检查，不重复求解或各开等待。

逐步把现有动作类型分支中“入口声明和控制器创建”交还对应能力。前一控制器只消费下一入口和准备结果，不增加 Walk→每个新动作的专用规则。首版复用现有能力，不建立通用插件框架。

## 5. 正常衔接的顺序

1. 读取下一动作的入口和前置条件，同时检查当前动作能够怎样安全继续或停止。
2. 根据当前选中的短期输入预测未来入口。视角和按键使用同一份输入投影，不能用按前进的预测来指导一条松键命令。
3. 在时间仍充足时，把真实锚点、条件性的接近前缀、后续要求和局部快照送入现有后台求解。后台比较有限候选，前一动作继续负责身体。
4. 收到结果后，先检查身份、依赖、资格和执行窗口；可适用的起始变体只做轻量核对。
5. 身体真正进入入口且下一动作就绪时，生成下一动作的首条意图。没有这些条件，不提前把身体交出去。
6. 首条意图赢得仲裁并进入应用账本后，下一内部执行器承担在途输入和后续身体责任。动作进度仍由实际应用和观察确认；后续根据真实状态复用或修正候选，不能整段盲目回放。

在提交前创建下一控制器只是准备，不表示交接完成。仲裁未选中、窗口过期或输入被拒绝时，原路线负责人继续处理身体；不能留下无人负责的一帧，也不能反复重建任务刷新等待额度。

首条严格命令已经提交、尚未确认生效时，即使身体还在地面，也按在途严格动作保留责任。此时取消或改目标不能把执行器退回普通步行并丢掉可能即将生效的起跳。若命令后来被明确拒绝，再按最新身体状态退出准备。

### 5.1 提前多久准备

取消固定“离入口 0.20 格才计算”作为唯一触发条件。协调器复用局部跟踪的短期预测，判断预计进入入口的时间是否接近准备提前量。

提前量覆盖本机后台往返、观察与应用年龄、已声明的一帧迟到，并保留裕量。首个试点只预测一个优先入口和少量起始变体；上限与冷／热交付样本在实现前冻结。预测前缀不是多 tick 输入授权，各 tick 仍经过正常仲裁。

只有实际前缀、视角和依赖保持适用时，才复用预测。它们超出证明范围时，按共同偏离入口从当前观察准备。目标修订后的计算复用遵守 R28-3，不自行增加“小幅修订”阈值；当前目标的执行资格仍须重新核对。普通新观察本身不要求重新求解。

首版在当前获选地面输入上预测最多 4 tick，只取一个可适用入口，后台仍最多检查 12 个基础跨隙模板。局部控制用有期限的 `GroundHandoffTarget` 参考该前缀；每次提案仍检查当前支撑、碰撞和完整停止尾迹。前缀结束后只可提出经检查的中性输入，等待沿用原 20 tick／1 秒计算期限。取消、失联和风险检查先于该参考；它不拥有身体，也不授予起跳许可。

工作进程尚未热启动或来不及交付时，应在可安全停止的位置等待。不能为了避免停顿把未完成方案当作可执行结果。复用现有运动进程、收件箱和队列，不为每个边界另开进程。

### 5.2 减速应该由什么决定

减速只为满足下一动作的入口、方向、空间、资源或安全停止要求。抵达图上的参考点、前一段即将结束、后台尚未给结果，均不能独立成为“必须停稳”的规则。

没准备好时仍可能需要制动：继续走将无法在当前已知支撑上安全停住，就必须选择经过验证的减速、潜行或保持动作。能安全继续且正在按计划进入入口时，保留合适速度。

依据应是实际选中输入的短期结果、下一入口和可停止尾迹。不要只删除原制动条件，也不要把所有中性输入当作安全。

## 6. 既有能力的适用边界

下表用于说明能力范围和验收覆盖，不是生产代码中的两两衔接规则表。共同入口、局部求解和实际出口承担衔接；旧低速能力保留为后备。

| 组合 | 正常做法 | 必须保留的边界 |
|---|---|---|
| Walk→Walk、连续小高差 | 已有连续地面段继续闭环跟踪；在安全走廊内保持运动 | 小高差证明和短时离地的既有支持范围不扩大 |
| Walk↔Sprint | 在前进方向和资格成立时切模式；前段按下一入口收尾 | 不能仅因允许疾跑就忽略朝向、饥饿或速度上限；普通自动转身另做 |
| Walk↔Crouch、合法预置 Crawl | 核对姿态、净空及身体尺寸；下一段使用真实观察到的姿态 | 不凭发送潜行键假定换姿态完成；主动进入 Crawl 仍未交付 |
| Walk→Step | 先尝试已有经过证明的普通迈步；必须使用独立 Step 时按其真实入口收尾 | 旧 Step 只允许低速时仍须必要减速，不能直接放宽参数 |
| Walk→JumpGap／JumpUp | 提前求解具体起跳入口，保留可接受的速度和方向，首条起跳直接接续 | 保留起跳支撑、顶部空间、资格、输入窗口和中断恢复证明 |
| Walk→ControlledDrop | 按当前落点证据、任务余额和入口准备下落；同向阶梯优先保留已有连续 Walk | 下部可见、观察新鲜与临离边支撑检查不被提前求解绕过 |
| Jump／Drop→Walk、转弯 | 用真实落地状态和下一入口判断；满足时继续走，转弯则按需要提前减速 | 不能只按预计落地 tick 切换；出口受前段真实入口与命令影响 |
| 严格动作→下一严格动作 | 在前段已验证出口上准备下一动作，再以真实出口核对 | 不声明所有跳跃两两组合；只发布有证据的组合 |
| Route↔探边 | 前置条件创建获取动作，监督者交接身体；完成后重查动作与求解入口 | 探边过程中位置和姿态变化，原候选不能未经核对继续用 |
| 移动→放置／攻击 | 放置沿用 B11 的安全站位与确认；攻击沿用已有同帧仲裁 | 本方案不发布移动中放置；空中自造地形需另声明预计世界变化 |
| 任意动作→任务终点／取消 | 终点满足任务的速度、姿态和支撑要求；取消先撤销新动作资格，再继续收尾 | 任务结束不等于空中、在途输入或已点击操作的责任结束 |

运动和视角仍分职责：普通步行可按获胜战斗视角重投影；严格动作使用声明的路线视角。视角未按证明预计的方式生效时不能发送仍标作已验证的移动，不依靠提交先后决定权限。

## 7. 证明中的时间必须保持同一含义

需要分别表达四个量：

- 后台计算期限：结果必须何时交付。
- 动作 rollout 上限：最多模拟多少 tick 来寻找正常完成。
- 安全恢复期限：从某个中断状态起，最多多久应回到声明的安全状态。
- 候选执行窗口：真实输入最早、最晚何时开始仍适用。

首个修正保留原能力的数值：跨隙原请求 20 tick、一格上升 40 tick、受控下降 80 tick 不因命令缩短而缩减恢复证据。本次不是给所有动作统一设置 20 tick。

在现有求解请求和 `VerifiedMotionResult` 中显式保留 `recovery_horizon_ticks`，由发布能力提供。原 `max_ticks` 继续限制正常搜索；迁移时将原请求值显式写为恢复期限，保持原验证语义。派生 delayed-start 变体和复核读取同一字段，不能用 `len(commands)` 推导。命令长度仍决定重放多少条命令，不决定中断恢复还能计算多久。

入口、落点、资源、恢复条件和这份期限共同属于不可变验证条件。旧证明未保存该字段时，不能假装已完整保存；重新生成，或仅按明确冻结的原版本来源转换，不能统一补一个任意默认值。

恢复轨迹需要的世界事实也属于依赖。局部快照应覆盖正常轨迹及声明的恢复分支；缺少事实返回缺信息，不能把缺失空间当空气。修改输入或真实入口超出证明范围时，重新验证受影响的剩余动作和接续条件。

### 7.1 准备、交付与首条输入的共同时间线

本节依据 [D055](../decisions/0055-preserve-start-slack-after-background-delivery.md)，是已经接入的共同入口契约，实机验收仍须单独判定。验收第 12、13 节既有结果不据此扩大。

设真实源观察的运动 tick 为 `t`，已选择的准备前缀长度为 `H`。后台先预测这 `H` 个地面输入，再证明动作在 `t + H + 1` 和 `t + H + 2` 两种时刻启动。两条分支均需验证动作、出口、伤害和中断恢复；后一条不是只修改时间字段。

首版普通等待先使用一 tick 的安全准备，复用原本就在发生的后台等待，不额外规定必须停稳。已有提前接近的前缀继续使用。较晚交付需要重新准备时，令已观察到的往返为 `L` tick，准备目标长度取 `min(4, max(1, L))`，已有安全前缀足够时直接保留。实际前缀仍须可安全执行；无法在该范围准备就沿用原有界结果，不自动扩大上限。往返从工作请求的真实源锚点计算，不能从预报的未来入口计算。一次冷启动超过范围时，可在原预算内重新准备；新结果仍须独立满足交付保证，不能以估计长度代替检查。

新候选第一次取得执行资格时，令当前真实观察 tick 为 `n`，最早发送时刻为 `n + 1`。本次支持首条输入晚一 tick 的能力，要求 `proof.latest_start_tick - (n + 1) >= 1`，同时核对所选启动分支、真实准备输入和当前身体。结果早到就保留在现有收件箱中，等真实观察到入口；余量不足则返回现有 `REVALIDATION_REQUIRED`，在原预算内重新准备和后台复核，不将它报告成物理不支持。

这项要求针对新候选的首次交付。已经获准的候选可以消费原来发布的迟到分支；首条已在途或动作已开始后，不重新要求每帧都剩一 tick，也不能重置起始窗口。后续有效按键和中性滑行仍使用原执行规则。

准备输入由现有路线身体拥有者提出。它仍需满足当前支撑、净空、姿态及停止安全，通过唯一仲裁出口实际发送，并由正式输入账本确认。准备输入不是严格动作第一条命令，不能据此假记动作启动、承诺落差伤害或创建第二个身体拥有者。后台返回的准备轨迹只供核对，不成为新的真实观察。

普通等待、提前接近和后台复核消费同一准备记录。普通等待的准备提案由现有路线拥有者送入正式仲裁与输入账本；提前接近继续使用 `FixedRouteController` 的交接输入。`GapMotionSolveJob` 的求解和复核都消费同一种前缀。不能只填字段或删除禁止条件，必须同时接通实际输入和纯计算消费。

长期状态继续由原拥有者维护：协调器管理计算请求及安排，路线执行器负责准备输入和身体，求解器只产生证明，接纳器核对适用性，Runtime 维护真实应用账本，监督者决定身体是否可交出。准备记录复用现有工作与候选身份，不另建第二套任务状态。

协调器只保存最近一次实际交付的工作身份和用时，供下一次准备安排使用。第一次看到结果时就记录用时，结果早到后在收件箱中等待入口的时间不计作后台耗时。这项测量不授予动作权限，也不新增等待或重试上限。

延迟估计只接受成功完成的完整 `SOLVE` 作业。`REVALIDATE` 和快速必要条件结果的工作量不同，不能用来缩短或扩大下一次完整求解的准备。两处结果读取入口调用同一个采样函数；每个工作身份最多采样一次。快速结果仍照常进入接纳、对齐和失败处理，只是不作为完整求解的耗时样本。

核对准备期间的视角输入时，按真实应用时间判断。一个只授权一 tick、已经确认在源观察之前应用的视角输入，属于该源观察已经包含的历史，不能仅因旧允许窗口与未来前缀重叠而拒绝。尚未确认的输入，以及实际在前缀期间应用的输入，继续按原条件核对。

后续输入失联后，如果身体仍在起始支撑高度，已经低速，并且完整停止尾迹在已知支撑上安全，可以直接从当前位置重新求证。不能证明安全时，继续走原退回和收尾路径。当前位置可准备，不代表旧命令可以直接重放；新候选仍须由 worker 验证、由当前观察和真实账本接纳。

后台复核接口为：

```python
revalidate_air_transition(
    proof, anchor, world, execution_window,
    *, entry_prefix: tuple[MotionCommandTick, ...] = (),
) -> SolveResult
```

它仍只重放旧动作命令，不重新搜索。前缀的预测与 `solve_prepared_air_transition` 共用纯计算步骤，保存真实源锚点、准备输入和未来入口。`motion_worker._execute_job` 对求解与复核都实际消费前缀；证明保留原规则、动作命令、出口、风险和恢复期限，并合并准备与恢复需要的世界依赖。局部快照必须覆盖这些格子，缺失仍返回缺信息。

取消、目标变化、世界变化、准备输入落选或姿态／视角不符时，沿用原工作身份、接纳和停止规则。失效的是未执行计算；在途输入、空中身体和已发生操作继续由原拥有者负责。不得在 Session、技能或 worker 中增加私有等待、重试或交接状态。

## 8. 逐帧控制怎样避免重算

控制线程保留：当前身体和输入责任、即时前置条件、候选身份、相关依赖、任务余额、起始窗口、已验证起始变体的状态核对，以及一次局部跟踪。

完整求解和包含全部中断分支的重验证留在现有运动 worker。过期候选需要重验证时，提交有类型的复核工作，沿用同一队列、工作身份、收件箱和重试账本；不在 `RouteAdmitter` 内同步做几百次物理 step。

当前 tick 变了，不自动代表整个证明失效。先选择对应生效 tick 的 `start_variant`，核对当前真实状态、已经应用的前缀和该变体是否一致。只能使用已验证变体；不能把普通 `SegmentEntryWindow` 内的任意状态都当作已证明。

当前实现核对完整物理条件，位置、速度与朝向只容许 `1e-7` 的数值误差。旧的 0.05 格入口跟踪公差不再作为启动证明。前缀采样必须逐 tick 存在且与记录匹配；期间可能生效的非零转头使旧前缀不适用。初始意图未获选时，可以选下一已发布变体，不能记录假应用；严格命令即使转角为零也提交明确路线视角，复用现有仲裁约束。

收件箱可保留早到结果，等实际观察到入口再接纳。接纳时只比较证明依赖在提交快照与当前世界中的事实，不只看本帧变化列表，不扫描整张世界。需要复杂复核时，提交同一 worker 的 `REVALIDATE` 工作：重放旧命令、保留原规则与恢复期限，并绑定新的真实锚点；原接近前缀不再作为新观察发布。

快路径允许的数值公差必须有误差依据；扩大位置、速度或方向范围需要证明覆盖该范围。不能为提高命中率把现有近似比较的容差直接当作安全证明。匹配不上就后台重验证，当前动作安全继续或有界等待。

首版只维持一个即将执行的优先候选，最多准备当前和紧邻后继动作；不同连接不能按“最新到达”互相覆盖。复用已有计算结果和局部快照，不新增无上限动作库、全世界缓存或多分支状态树。

首个连续跨隙试点沿用最多 12 个基础候选及原一帧启动迟到范围。接近前缀的变化也计入候选上限，不能每项各给 12 个再相乘。候选顺序和计算量上限在比较前冻结；墙钟期限继续保护在线交付，算不完如实报告，不能改选目标或冒充已证明不支持。

视角也影响运动。首版只使用已有路线视角及合法投影，不搜索任意角度序列。普通自动转身以后单独验证；战斗视角胜出时，地面输入按同一视角计算，严格命令仍须满足自身声明。

名义轨迹和首条命令晚一 tick 是首版明确的启动验证范围，不代表覆盖每条命令任意晚到。支持的中途迟到、缺回执和仲裁中断要单独列出；不可恢复的候选拒绝，超出范围时由原控制者按已有契约收尾。不能把两条轨迹当作全部抖动的安全证明。

普通帧不重放整条路线；只检查相关变化，不因远处新观察重建全局路径。严格动作复核也不重复拷贝整张世界。采样与性能门槛只维护在 R28 验收第 12 节。

## 9. 变化和中断统一处理

| 当前情况 | 处理 |
|---|---|
| 身体在轨，下一动作就绪 | 核对即时条件，在合法窗口内交接 |
| 身体在轨，下一动作准备中／缺信息 | 前段安全继续；即将越过可停止边界时选择安全保持，并使用原等待预算 |
| 候选不再适用，身体仍可恢复 | 停止旧计算，从当前观察准备；通过 R28 共同恢复入口决定后续 |
| 已离地或有严格动作输入在途 | 原动作负责人继续负责；新目标撤销旧计划的资格，不撤销身体责任 |
| 暂缺锚点或回执、仍有身体观察 | 不发送无法授权的新严格命令；按已有收尾契约保留责任和等待期限，不把证据暂缺当作释放或 Runtime 必须重建 |
| 相关地形、资源或输入历史变化 | 只失效受影响的证据；无关变化不撤销全部路线 |
| 额度耗尽、取消、连接不可用 | 按既有生命周期、账本和失联规则收尾；不能以换动作实例绕过上限 |

原因字段只用于报告。等待、准备、拒绝与控制权都使用现有有类型结果；不再用 `goal_braking` 或其他文案决定阶段。尚未完成的 R28 共同恢复和持续预算按原计划实施，本设计不把它们写成已经可用。

## 10. 实施原则与大局检查

先修验证条件一致性及快路径／后台复核，再用一个连续跨隙试点验证局部求解的收益。试点同时核对候选覆盖接近与落地后运动、真实输入与预测一致、取消仍有人负责。代表检查稳定后才扩大到既有升降能力；不为覆盖表一次改完全部控制器。

每项删除原重复判断。控制线程超预算或出现安全反例就停止扩大验收。没有安全影响的体验缺口先登记，在当前范围内按统计门槛判断；不能为少一帧停顿不断增加协调状态或新一轮全矩阵。

每个可验收步骤结束只回答四件事：玩家的完成、停顿和响应是否改善；安全与输入期限是否成立；重复决定是否实际减少；是否仍在原时间盒和范围内。没有改善先归因，不靠增加模板、等待分支和检查数量宣布成功。局部优化不能取代 R28 的共享恢复、任务预算、异步失效和正式跟随主线。

学习是后续可选项。只有搜索成本或动作风格确有需求时，才评估用学习推荐候选或排序；最终是否合法仍由现有规则和验证判断。本方案不安排训练，也不把学习作为连续运动的前提。

不引入新物理模型，不生成所有动作两两组合的适配器。规划、控制和测试分别按自身职责检查同一契约。具体顺序在 R28 阶段第 8 节，验收在第 12 节。

## 11. 共同出口与择优接口

2026-10-02：本节的共同需求、有限直线跨隙候选及连续高度接非格心尾段已接入。拐角提前松键和墙接触仍按独立批次处理；不声明全面混模式或任意空中接续。

### 11.1 三项判断分别表达

| 判断 | 使用什么事实 | 不应附加什么限制 |
|---|---|---|
| 确实落地且安全 | 实际／预测着地、足底支撑、净空、材质、伤害与当前世界 | 身体必须位于图的目的单格内 |
| 正常运动可以交给下一段 | 上述安全事实，加后继接受的位置、速度、方向、姿态、模式和路线进度 | 所有内部段都先停稳，或统一只多走一帧 |
| 中断后可以安全收尾 | 该时刻的输入责任、原恢复期限、剩余输入策略及经过的真实空间 | 必须回到正常完成区，或把正常落地误当输入账本已清晰 |

首版保持当前能力已声明的支撑要求和原中断检查。连续普通地面的多个支撑面可以共同构成允许出口，但需要逐轨迹查询真实支撑和净空。支撑比例由几何和能力判断，不因图上的单块边界改变；未验证的更少支撑比例不能在本次顺手开放。相邻面的大包围矩形可能包含坑或内凹空白，不能直接作为授权。

恢复检查已补齐：正常最终出口也要计算松键后的尾迹，逐分支检查未知空间、支撑高度及伤害。审查复现了“低速但继续漂移后离地”的 helper 反例；这不是已复现的完整求解发布漏洞。原 R tick 内达到着地低速的期限不变，达到后继续证明被动漂移到真实水平零速度，总推演最多 2R。新增推演不延长动作窗口，也不授权新的输入。连续高度的带速出口同样保存完整停止轨迹及依赖。

### 11.2 一份后续要求，多个消费者

`segment_entry.py` 已增加不可变的 `MotionContinuationRequirement`，复用 `SegmentEntryWindow`，不增加状态所有者。当前字段是正常入口、恢复入口、后继模式、后继路线 ID 和原地面最小支撑比例。恢复入口只提供几何必要条件；失联后仍要查询当前世界的净空和足底支撑，不能把正常窄出口用作唯一恢复位置。

首次扩域限于后继普通 Walk 的第一条同高直线，最多四格，并在真实拐角或终点前留出 0.4 格。连续共线的搜索点不是拐角。其他模式或后继证明段保持原入口规则。接口后续可以表达：

- 本次路线用途：继续通过、进入下一已支持动作，或满足任务终态。
- 有界的后续路线区间及其中实际可查的支撑关系；保留节点顺序，不扫描整张地图。
- 下一段的入口条件、模式／姿态策略与必要视角；最终段直接使用真实任务要求。
- 用于候选比较的同一下游位置或路段，以及明确的需求版本。

这里的位置区间是允许的范围，比较位置也不强迫经过某个格心。求解器保存实际落地状态、正常出口和所用需求；任务候选再绑定请求、目标、动作位置和需求版本。新入口、需求或依赖超出证明时，仍走已有后台复核／重新求解。

需求身份由现有路线／候选修订与不可变内容确定，不再增加独立计数器或生命周期。

共同需求必须进入请求转换、worker 序列化、名义及迟到分支验证、接纳、执行结束与失联后的观察确认。扩大正常出口时同步覆盖新增的支撑、净空和恢复依赖。`end_surface` 继续用于通道组织，不能另在恢复确认中保留一套单块成功条件。

后继控制器从实际出口接续，并取得已走过的合法路线进度。只搜索本次有界区间，核对局部连接；不能越过未完成的严格动作、拐角障碍或未验证证明段。正常交接与失联后的确认共用这份几何事实，输入责任仍由原账本单独判断。

### 11.3 准备输入由当前控制器认可

现有 `GroundHandoffTarget` 应引用完整输入及其视角／模式条件。普通地面和连续高度分支都明确回答能否消费；不能消费时，协调器不继续按另一组按键预测入口。模式缩放和姿态按实际投影处理，实际采样继续逐 tick 核对。

连续高度证明也使用后续要求生成出口。旧证明要求停稳时先重新证明带速出口，不能单独删除控制器的停稳检查。任务终点、取消和旧低速能力需要停住时，继续完成必要停止。

### 11.4 有限候选中择优

先用有界候选表达当前支持的不同合法输入，包括按需持续前进、松键或制动。疾跑按钮是一个可选输入条件；入口速度域、饥饿资格与其他原条件不因此放宽。新模板要取得新的轨迹、迟到和恢复证据。

直线跨隙先对最多十二个名义轨迹排序。排序使用“已用 tick 加到同一下游截面的剩余距离／后继速度上界”作为局部用时估计，再比较反向和空输入。该估计不等于完整后继控制用时；正式链仍按相同实际目标统计总用时。候选中两项持续前进替换两项旧模板，数量没有相乘；后输入最多十九 tick，但正常总预测仍是二十 tick。

排序后的候选必须完成启动迟到、每个释放点和最终停止尾迹证明。后继要求低速时，落地后先用计算器预测前进输入；若超出入口速度，改为松键并继续验证入口，不能强塞固定一帧前进。上升和下降消费共同出口，但保持原有限模板及首次合法选择，不在本轮同时扩成六十四项全量排名。

先做必要条件排除和廉价推演，再按确定次序完成原严格验证。只有完整验证的结果可执行。计算量达到上限时保留已有合法结果的真实质量状态，或报告预算耗尽；不能称已取得全局最优，也不能把计算未完成当成不支持。

候选排序和最大计算量冻结后再做配对比较。原 12 个基础候选上限仍计入前缀／模板变化，不把入口、落点和按键分别枚举后相乘。完整证明和复杂复核继续在已有 worker 中运行。

### 11.5 逐项处理地面近似

普通地面转弯先比较满足后续方向和停止安全的候选，不由固定距离阈值直接决定全部松键。合法墙面接触使用已有物理计算器的碰撞后状态继续查支撑与停止尾迹；危险、未知和未支持接触仍拒绝。

这些控制修改分别验收。它们不与首次扩大跨隙出口同时修改，不重写物理计算器，也不由技能层另做恢复。

### 11.6 入口复核与结束后的支撑收尾

后台复核期间，已应用的视角输入可能改变当前朝向。复核结果要求补身体条件且当前朝向确实未对齐时，协调器可以消耗原重试额度重新对齐。不能将所有 `NEEDS_STATE` 都作为重试许可，也不能通过原因文案判断。

路线结束后，业务结果不再授予新的前进动作。原执行器仍负责释放前的安全：中性输入的停止尾迹未通过原支撑门槛时，可使用已有计算器证明一帧潜行退回。每帧重新读取当前身体和地形；普通步行绑定当帧视角时，退回也按同一获胜朝向计算。监督者仍按原停止、输入归属和支撑条件决定释放。缺当前锚点、空中或无法证明的退回不会获得这项输入许可。依据见 D054，验证边界见 R28 验收第 13 节。

## 12. 动作入口朝向和预计入口作废的责任

2026-10-09：本节已按 D092 实现并通过独立入口交接验收。

`SegmentEntryWindow.required_yaw_radians` 是入口条件。当前 `ActionRouteExecutor` 消费它，在接近下一入口时提出视角；当前地面控制器按同一帧最终有效朝向计算按键。下一能力不要求前段识别自己的具体类型。只有当前真实观察满足原 yaw 及其他入口条件，才允许启动严格动作。

视角请求可能被战斗或安全视角压下。请求被提出或预计能转到，不等于朝向已满足。当前路线继续负责可安全的接近／停止，使用既有等待上限；不放宽原角度公差，不创建第二套转头恢复或等待状态。

`MotionRouteCoordinator` 对 upcoming action 的过期否定结果只作废原工作。它不证明当前动作失败，不购买本地真实失败额度。结果分类来自 typed 状态和依据变化事实，reason 只作报告。当前入口重新核对得到的真实否定结果，以及动作已开始后的失败，继续沿用原三次与身体收尾规则。

作废、等待、重新提交都沿用原作业身份和退场入口。每个连接只允许一个活动工作；前段停滞和准备等待有原上界。不计过期预测失败不能获得无限重算权限。

## 13. 入口刹车和终结原因

D093 将“已经可以交接”与“停下来就能交接”分开。后者只授予既有刹车路径，仍检查当前完成区域、着地支撑和完整停止尾迹。真实身体满足原入口后才交接。

最后严格动作因输入失联安全落地，但目标仍未满足时，执行器保持原 `FAILED` 终态。`ActionRouteDecision.failure_cause` 使用已有 `StopCause.INPUT_LOST`，`NavigationSessionReport.failure_cause` 将它传给任务层。原因字段用于报告，不触发新的入口恢复、等待或重试。普通目标不满足的分类不受影响。

## 14. 失联安全落地后的剩余目标

2026-10-10，D094 在 D093 分类之后增加限定恢复。末次严格动作实际失联、已确认安全落地、当前着地且目标尚未满足时，执行器给出已有 NEEDS_REPLAN，并携带 StopCause.INPUT_LOST。Session 用原任务额度重规划，不由执行器生成后续 Walk。正常终态不满足和空中失联仍使用原结果。

恢复原因归原 NavigationHandoffCoordinator。身体交出之后，原因继续保留到替代路线成功接纳；因此后台规划失败、预算耗尽不会丢失 INPUT_LOST。替代路线接纳、清除目标或新任务结束这次原因，之后的无关失败不会继承它。Session 报告先读取尚未解决的恢复原因，再读取当前执行器原因。

同面 local direct 允许已观察到着地的低支撑起点向内走。起点读取 FixedRouteConfig 的执行下限，当前为 0.15；达到规划支撑 0.5 前只能保持或增加支撑，之后保持原门槛，终点仍至少为 0.5。默认查询保持严格规则。例外的下限随 StandableConnectionQueryArgs 写入不可变配方，接纳和复核使用同一个查询，不另维护复核算法。
