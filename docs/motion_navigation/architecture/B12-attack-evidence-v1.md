# B12 攻击证据与重试 V1

日期：2026-09-26
状态：已实现并通过 Fabric 1.21 验收

## 1. 要解决的问题

现有移动近战把客户端门禁拒绝和命中确认超时放进同一个计数。一次早期失败会一直留到整场战斗结束，后续即使已经成功命中，另一类失败仍可能过早耗尽任务额度。

命中判断也过于宽松。攻击提交后，只要目标生命下降，就可能被记为机器人命中。着火、药水、环境伤害和其他实体造成的伤害也可能满足这个条件。

B12-A 先修正这两类基础语义。B12-B 再使用这里形成的结果处理部分观察和战斗运动。

## 2. 当前边界

B12-A 只读取正式 Minecraft 1.21 客户端已经收到的 `damage_event` 包，不增加服务端特权观察。Observation V3 保存包内的伤害类型、受伤目标、造成伤害的实体和直接来源实体。它们是客户端收到的协议事实，不是战斗策略。

系统区分三层结论：

- 目标确实受到伤害或已经死亡；
- 受伤变化在时序上与本次攻击命令关联；
- `damage_event` 明确说明造成伤害的实体或直接来源实体是机器人玩家。

第二层称为“命令关联命中”，第三层称为“来源确认命中”。来源确认更强，但仍只表示客户端收到的原版协议事实，不冒充服务器侧完整战斗日志。

## 3. 一次攻击尝试

每次攻击都有独立编号。编号在一次移动近战任务内递增，并绑定：

- 世界会话；
- 任务代次；
- 目标身份和目标修订；
- 攻击意图和请求编号；
- 提交前观察序号；
- 客户端回执；
- 确认期限；
- 后续观察和最终结果。

`MovingMeleeDriver` 分配攻击编号并保存任务级统计。`MeleeStrikeDriver` 拥有当前攻击尝试的详细状态。Runtime 继续拥有仲裁、后端推进和动作回执。观察契约继续拥有目标生命、死亡和受伤动画事实。

攻击尝试完成后成为不可变记录。后续重试创建新编号，不能改写旧结果。

## 4. 状态与结果

攻击尝试至少经过下面的阶段：

```text
准备
  → 提案等待仲裁
  → 客户端门禁检查
  → 已提交，等待确认
  → 终态
```

终态使用有类型结果：

| 结果 | 含义 | 是否消耗攻击失败额度 |
|---|---|---:|
| `DEFERRED_BY_ARBITRATION` | 攻击没有赢得本帧仲裁，命令没有执行 | 否 |
| `GATE_REJECTED` | 客户端拒绝目标、距离或其他攻击门禁 | 是，只计门禁拒绝 |
| `INPUT_FAILED` | Runtime、后端或动作回执未能证明命令已提交 | 是，只计输入失败 |
| `CONFIRMATION_TIMEOUT` | 命令已提交，但期限内没有得到命令关联命中 | 是，只计确认超时 |
| `OBSERVATION_INTERRUPTED` | 命令已提交，确认所需观察中断 | 不与超时混计；交给任务决定重看或结束 |
| `COMMAND_CORRELATED_HIT` | 本次命令和后续新受伤事实满足关联条件 | 否 |
| `SOURCE_CONFIRMED_HIT` | 本次命令生效后，目标收到明确指向机器人玩家的伤害事件 | 否 |
| `TARGET_DEAD_UNATTRIBUTED` | 目标已死亡，但证据不能归到本次命令 | 否；任务可以结束，但不增加机器人命中 |
| `TARGET_REVISED` | 目标身份相同但任务采用了新修订 | 否 |
| `CANCELLED` | 任务取消；已提交命令仍记录真实后果 | 否 |

“已提交，等待确认”是过程状态，不是确认成功。来源未确认的目标受伤也是当前尝试附带的证据事实，不是终态。它们不能混入终态失败计数。

## 5. 命中证据

同时满足以下条件时，可以形成 `COMMAND_CORRELATED_HIT`：

1. 攻击意图赢得本帧仲裁；
2. 客户端针对同一目标返回 `pending_confirmation`；
3. 提交前目标不处于已有受伤动画中；
4. 更晚的正式观察中，同一目标出现新的受伤动画；
5. 观察位于本次确认期限内；
6. 世界会话、任务代次、目标身份和目标修订没有变化。

目标生命下降和死亡是补充事实，不能单独把结果提升为机器人命中。若只观察到生命下降，当前尝试继续等待新的关联证据；期限结束后返回确认超时，并在记录中附带“目标受伤，来源未确认”。若目标已经死亡，战斗任务可以完成，但不能因此增加确认命中次数或建立新的报复交战许可。

攻击提交后发生目标修订时，旧尝试立即以 `TARGET_REVISED` 结束。任务取消或世界会话准备替换时，调用方先取消旧尝试，再替换 Runtime。取消这一帧如果已经出现命令关联命中，仍保存真实命中；否则以 `CANCELLED` 结束。目标修订和取消都写独立原始事件，离线重放不能借用在线终态字符串。

在上述窗口内，若新的 `damage_event` 同时满足“受伤目标一致”以及“造成伤害实体或直接来源实体是机器人玩家”，结果提升为 `SOURCE_CONFIRMED_HIT`，证据等级为 `SOURCE_CONFIRMED`。若事件明确指向其他实体或环境，受伤动画不能再把同一次变化提升为机器人命中。

伤害事件缓冲固定为 64 条。满载时丢弃最旧事件并累计丢弃数，不能在游戏线程抛异常。换世界时清空。攻击尝试只消费基线序号之后、确认期限之内的新事件，不能借用旧伤害。非玩家目标若没有正式追踪编号，当前观察协议无法表达其身份，采样时直接移除该事件；这类移除不计入缓冲溢出数，避免常驻运行把无关事件误报成证据丢失。

着火、药水、环境伤害、队友攻击和未知来源造成的生命变化遵守同一规则。缺少来源事件时仍可保留命令关联等级；一旦事件明确指出其他来源，就以明确来源为准。

## 6. 重试和任务结果

任务级记录分成两类：

- 历史总数：门禁拒绝、输入失败、攻击提交、确认超时、来源未确认伤害和确认命中各自累计，只用于记录和分析；
- 当前连续失败：按失败类别分别维护，只决定是否还能重试。
- 自上次确认命中以来的失败总数：门禁拒绝、输入失败和确认超时无论怎样交替都会增加；用于避免分类计数相互清零后只能等待任务总超时。

一种失败不能消耗另一种失败的额度。攻击确认成功后，当前尝试结束，下一次攻击从新的连续失败序列开始；历史总数不清零。

某一类额度耗尽时，移动近战返回有类型的任务结果，例如“门禁重试耗尽”“输入失败重试耗尽”或“命中确认重试耗尽”。任务进入 `NEEDS_TASK_DECISION`。这属于任务结果，不得封存 Runtime。

首版总无进展上限为 6 次，等于三类现有上限之和。单类连续失败仍先返回原来的分类结果。确认命中会把总无进展计数清零，但保留历史总数。仲裁延后没有执行攻击，不进入该计数。

外力恢复、重新接近、目标观察缺口和攻击失败继续使用各自的额度，不能写入攻击确认计数。

## 7. 记录与离线重放

每次攻击尝试至少记录：

- 尝试编号、目标和任务身份；
- 提案、仲裁结果和客户端回执；
- 提交前后的观察序号；
- 生命、死亡、受伤动画和伤害来源事件；
- 使用的证据等级；
- 终态结果；
- 目标修订或取消的原始事件；
- 各类历史总数和当前连续失败数。

离线重放从这些原始事实重新运行证据分类，不能直接信任在线写下的结果字符串。

## 8. 与 B12-B 的接口

B12-B 只消费有类型的攻击尝试结果和交战许可事件。它不会通过生命下降自行推断机器人命中，也不会建立第二份攻击计数。

目标暂时不可见时，当前已经提交的攻击仍由原 `MeleeStrikeDriver` 负责确认、超时或取消。导航和战斗视角的组合不能改写攻击尝试的历史事实。

## 9. 不变量

1. 一次攻击尝试只有一个拥有者和一个终态。
2. 未赢得仲裁的攻击不算已提交。
3. `pending_confirmation` 不等于命中。
4. 生命下降和死亡不能单独证明机器人命中。
5. 不同失败类别不共用重试计数。
6. 任务预算耗尽不封存 Runtime。
7. 旧攻击结果不能因目标修订或后续观察被改写。
8. B12-A 不新增服务端特权观察，也不改变唯一输入出口。
9. 明确的其他来源不能被受伤动画覆盖成机器人命中。
10. 伤害事件缓冲满载只丢弃旧事件并报告，不得使客户端崩溃。
