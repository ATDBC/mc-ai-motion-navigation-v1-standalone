# 固定路线步行 V1

日期：2026-09-18

## 职责

`FixedRouteController` 接收调用方给出的不可变路线，根据当前身体状态和统一世界知识，每帧选择一次普通地面移动输入。它只负责跟踪、制动、取消和失败分类，不生成路线，不设置检查点，也不直接写游戏按键。

动作仲裁仍是唯一输入出口。Fabric 客户端的输入租约负责断流释放，控制器不能绕过这两层。

相机朝向不属于水平路线本身。控制器把期望的世界运动方向换算为当前视角下的前后、左右输入，因此调用方可以在直行时独立改变 yaw，也可以固定 yaw 跟踪曲线路线。视角命令仍须和移动命令一起经过正式动作仲裁，不能从测试脚本直接写入客户端。

## 输入和状态

输入包括固定路线、`NavigationFrame`、上一帧输入是否得到实际应用确认，以及可选取消请求。控制器自己保存：

- 当前路线和已通过的路段；
- 上一帧选择的移动输入；
- 正在制动、已经取消或已经失败等执行状态；
- 连续没有进展的帧数。

世界知识、身体状态和输入租约不归控制器所有。

## 每帧处理

1. 先检查世界会话、姿态、层高、速度、支撑材质和输入确认。超出普通地面模型的状态返回 `UNSUPPORTED`。
2. 把当前位置投影到当前路段；接近当前段末点后才允许进入下一段，不在自交路线中跳跃匹配。
3. 枚举普通地面的九种移动输入，用 B02 地面模型预测短时轨迹。
4. 用统一扫掠和支撑查询排除碰撞、支撑不足、未知、未支持形状和未校准地面。预测覆盖完整输入租约、松键后降到停止门槛的过程，以及停止门槛之后按校准保持率计算的剩余惯性尾段。墙体碰撞使用水平扩大 0.03 格的包围盒；坑边支撑仍按真实脚底计算，再扣除 0.03 格位置误差最多可能损失的支撑面积。扩大后的面积不能算作真实接触。
5. 在可行输入中综合路线进度、横向误差、终点制动、墙边余量和坑边支撑比例选一个输入。
6. 同时预查路线前方最多 2 格所需的空气事实。当前动作已安全时继续走，把缺失位置交给观察请求，不为等待远处信息停车。
7. 终点或取消时根据实际速度主动制动，停稳后才报告完成。

## 不变量

- 未知不能当作空气；缺失事实只能产生观察请求或明确失败。
- 中间路点表示路线几何进度，不要求逐点停稳。
- 取消接纳和取消完成是两个时刻；实际速度没有降到门槛前不能完成。
- 路线前查只准备信息，不授予当前动作权限。
- 墙边和坑边余量是候选代价，不修改碰撞与支撑真值。
- 碰撞误差和支撑误差方向不同：碰撞盒可以扩大，支撑面积只能保持或减少。硬支撑门槛不能依赖软评分碰巧避开危险动作。
- 输入确认丢失后锁定失败，并由正式动作出口提交中性输入，不能在后续帧自行恢复前进。
- 临时测试墙会让下方草地退化为泥土。验收夹具必须在清墙后恢复草地；控制器不能因此放宽已校准地面材质。
- 形状测试的理想直线和理想圆只用于评分与回放。控制器收到的仍是普通固定路线，不能读取评分误差来修正动作。

## 当前边界

V1 只支持站立、同高度、普通速度步行。跳跃、冲刺、潜行、液体、动态实体绕行和路线重接不在本接口中偷偷处理。后续能力应扩展能力判断与动作执行，后台寻路只需提供同一固定路线接口。
