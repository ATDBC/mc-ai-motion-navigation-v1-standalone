# 目标状态 v1

日期：2026-09-19
适用阶段：B06 起

## 要解决的问题

“到达一个坐标”不足以判断任务完成。同一个位置可能要求站在固体上、漂在水中、朝向某个方向、保持某种姿态，或者停到足够慢。

## 契约

`GoalState` 由目标管理创建，规划、路线接纳和执行完成判断读取同一份对象。当前字段包括：

| 字段 | 含义 |
|---|---|
| `region` | 身体参考点允许落入的三维区域 |
| `support` | 固体、流体、附着面或不限 |
| `allowed_modes` | 允许的运动模式 |
| `allowed_poses` | 允许的身体姿态 |
| `maximum_terminal_speed_blocks_per_second` | 完成时最大速度 |
| `minimum_resources` | 完成时仍须保有的已启用资源 |
| `required_yaw_radians` | 可选的终点朝向 |
| `maximum_yaw_error_radians` | 有朝向要求时允许的误差 |
| `risk_policy_id` | 本次目标采用的风险政策 |

没有提供的资源维度表示当前能力没有这类数据，不能解释成资源为零。依赖该资源的能力必须保持关闭。

## 当前接入范围

B06 已让 `PlanningRequest`、`RouteCandidate`、`ActiveRoute` 和最终 `ActionRoute` 保存同一份目标状态。规划请求只检查目标节点能静态证明的区域、支撑类型、模式和姿态，不伪造朝向或风险政策。已知图首版的目标节点仍只支持固体支撑、Walk 和站立。后续 Swim、Climb 和带速目标会扩展节点状态。

动作序列结束后，路线执行器用最新身体观测核对位置、支撑、姿态、速度和朝向；资源来自同一路线的规划结果，实际采用的风险政策由执行入口明确传入。接地 Walk 的终端速度采用水平速度，因为 Minecraft 在角色静止接地时仍会报告一个用于重力结算的向下速度。若只差朝向，执行器保持中立移动并补齐转头，满足后才报告完成。这个补转头阶段仍服从世界会话、取消和输入回执规则。B06 的现有安全动作没有风险标签，默认使用 `no_expected_damage`。后续阶段若允许其他风险政策，必须由上层明确声明。

## 不变量

- 路径到达目标格不代表目标完成；还要满足支撑、模式、姿态、速度、资源、朝向和风险政策。
- 规划器不能改写目标条件来制造可达路线。
- 路线更新可以改变怎么走，不能悄悄改变怎样才算完成。
- 活动路线必须先完成取消和安全交接，不能被新的路线直接覆盖。
