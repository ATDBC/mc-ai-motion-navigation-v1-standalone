# 终点接近与路线优化 V1

> 本文保存 2026-10-02 的历史设计。后台筛选已经撤回；现行设计先补通用非中心路线执行，再把终点接近作为首个用例，见[连续地面路线执行 V1](continuous-ground-route-execution-v1.md)。

日期：2026-10-02。状态：批次 5 的后台筛选接口已按 [D051](../decisions/0051-remove-terminal-screening-and-fix-contact-control.md) 撤回。本文第 2—4 节涉及筛选的接口只保留历史设计，不是正式实现要求。静态站位、末段直连、实际长度、依赖登记和在线闭环仍保留。原 v3 的实际表现见 R28 验收第 10.7 节。

## 1. 要达到的行为

机器人应到达 GoalState 规定的区域，并满足其速度、支撑、姿态等终态要求。图节点是搜索代表点，不是必须踩到的位置。不能因目标可静态站立就承诺当前控制器一定能走到，也不能因控制器暂不支持就宣布物理不可达。

成功判断仍消费原 GoalState。提前拒绝是失败分类改善，不算到达成功；跟随区域将来由目标管理产生，执行层不擅自扩大区域。

## 2. 职责与数据流

| 模块 | 负责什么 | 本批不承担什么 |
|---|---|---|
| `support_surfaces.py`／`geometry.py` | 目标内的站位、身体净空、沿途支撑、缺信息和完整依赖 | 控制器接近距离、停车策略、路线收益 |
| 普通地面移动能力 | 用已发布的选键、预测和停止尾迹判断终端接近的支持范围 | 新贴墙控制、完整路线寻优、重新实现物理 |
| `PlannerWorker`／表面规划 | 在既有快照中生成终端候选，执行有界能力筛选 | 控制线程中的长时模拟、第二份实时地图 |
| `RouteAdmitter` | 按最新目标、世界及身体条件复核并生成实际执行路线 | 将旧结果直接改标签、重新搜索一套控制 |
| `FixedRouteController` | 依据真实身体逐帧跟踪、制动和安全停止 | 把离线筛选改成逐 tick 命令回放 |

Session 只做廉价的目标几何必要条件检查，不再自行决定一个必须沿用的最终位置。最终位置随规划候选传递，接纳消费同一位置；变化使它失效时返回类型化结果。共享的是规则和候选身份，接纳时的最新事实复核仍须保留。

首版只声明普通 Walk 的终端接近条件。Sprint、Crouch、Crawl 和高度动作维持各自已发布范围并回归，不自动套用站立 Walk 的筛选，也不顺手扩大支持。

## 3. 终端候选的接口

`terminal_approach.py` 提供薄的查询，复用现有局部控制器与运动计算器；不增加求解框架。

```python
query_terminal_approach(
    world: WorldView,
    surface: SupportSurface,
    goal: GoalState,
    connection: FixedRoute,
    entry: SegmentEntryWindow | None,
    profile: GroundMotionProfile,
    config: FixedRouteConfig,
    *,
    deadline_ns: int,
    template: PhysicsState,
    trial_route: FixedRoute | None = None,
    mode_profile: GroundModeProfile | None = None,
) -> TerminalApproachResult
```

`entry` 描述这段接近实际声明支持的位置、速度、方向和姿态条件；它不是假造的正式观察，也不要求机器人额外停稳。未来入口没有依据时不能用一个任意静止状态冒充；返回 UNSUPPORTED，原因是入口适用域未验证。没有算完则返回 BUDGET_EXHAUSTED。查询可以使用临时模拟状态，但不能回写 WorldKnowledge、输入账本或观察。

正式选择器传入 `entry=None`，由真实 `template` 生成参考入口。调用者显式提供入口时，必须与身体和 Profile 匹配；不能把另一位置或速度范围写进结果却没有检查。

一个不可变结果保存下列内容，作为表面候选的附加字段；Session 不保存第二份权威副本：

| 字段 | 用途 |
|---|---|
| `status` | FEASIBLE、BLOCKED、NEEDS_INFORMATION、UNSUPPORTED、BUDGET_EXHAUSTED 五种终端查询结果 |
| `position`／`stop_region` | 同一具体终点及目标内部可以停车的范围；失败时不返回可执行终点 |
| `entry_window` | 本次条件化结论的适用入口，不自动代表完整路线可达 |
| `dependencies`／`missing_cells` | 检查连接和终点实际读取的格子，以及缺失事实 |
| `reason` | 有类型的依据，区分几何阻塞、停止范围不足、接近未支持及未算完 |
| `profile_id`／规则版本 | 标明筛选沿用的控制与物理条件 |

外围候选继续绑定世界会话、请求、目标 ID／修订及工作身份，不另复制一套生命周期。预算值与场景参数只维护在验收和清单中。

### 3.1 先选择目标内部的位置

先求支撑范围、目标范围与已知净空的交集。优先目标中心，再选交集内部点；不把交集四角作为默认后备。停止范围须完全位于原目标内，并为现有停止阈值对应的漂移、已声明的位置误差留出余量。

不能把 0.05 格当成所有目标的统一门槛。由目标范围与既有控制误差得到可用停止范围；范围不足时明确报告停止精度未支持。也不能只因目标中心嵌入障碍而否定整个区域，区域内部仍可能有可用站位。

### 3.2 再筛选当前控制器支持的接近

复用普通地面已有候选选键、预测、碰撞、支撑和停止尾迹检查，按该接近的方向、速度域、身体条件和 Profile 核对。完整检查完成前不能给 FEASIBLE。没有候选通过，只表示当前已声明的接近方法未支持；未穷尽预算时不能推断物理不可达。

墙边软代价与硬碰撞分开。0.40／0.20 等扫描距离保留为场景证据，不建按场景名分支的接近表。本批不改变软代价、预测误差、支撑阈值或选键规则。

不从静态站位直接生成新的执行许可。接纳复核候选身份、事实依赖、实际连接与当前控制条件；在线仍逐帧闭环。筛选不是普通步行的新严格动作证明。

## 4. 普通步行末段直连

优先检查末段前一个实际路线点到已选终点的同高连接。通过身体扫掠、沿途支撑及终端接近检查后，替换末段代表点；不能在这一步偷偷换成另一个终点。直连不成立时，只有原格心连接也通过相同条件才能保留它。

已有地面证明的轨迹保持不变。需要非格心尾段时继续生成独立普通 Walk；空中入口、落点和动作边界不删除。

实际路线生成后，路径长度、当前走廊、局部进度、末端容差和全部新增依赖都按执行路线更新。规划搜索代价与优化后的执行长度分别报告，不伪造未经重算的预计时间。接纳和执行不得各自重新选终点。

## 5. 恢复期间的身体归属

现有 `RouteControl` 包含执行器与路线协调器。协调器接手输入丢失后的地面入口恢复时，仍由这个路线控制对象负责；不因执行器处于 INPUT_LOST 就把它从诊断中消失。

拟增加只读 `BodyControlActivity`，由现有控制者输出、监督者汇总。字段为世界会话、观察序号、owner ID、路线 ID／修订、动作索引、`phase` 和本帧输入责任。阶段首版为 TRACKING、ACQUISITION、STRICT_PREPARATION、STRICT_EXECUTION、ENTRY_RECOVERY、STOPPING；取证 owner 仍独立登记。

这份报告从当前控制对象和本次决定生成，不新增权限状态或第二份恢复计数。已选择的非中性输入必须能关联到仍负责其尾迹的 owner。纯潜行、中性落地和停止尾迹也可能承担身体责任，不能只检查 forward／strafe。

本帧提案的 owner 与观察中已应用输入的 owner 分别记录，使用 control_sequence 和 movement_tick 关联输入账本。控制者在两者之间已经交接时，不能拿当前列表直接解释上一 tick 的输入，或因此误报无人控制。

历史 `last_handoff` 仍保留，但不能当作当前帧可释放证据；当前交接判断继续由监督者按真实身体和输入账本作出。任务业务终态后必要收尾仍合法。Runtime 的获胜意图与实际应用记录标明来源，不把落选提案算实际控制。

诊断更正先单独验收：身体、输入、许可及释放时刻不改变。若发现实际控制权规则也需修改，停止将其归为只读更正，按 R28-1 的行为修改单独推进。

## 6. 后续整条路线优化与性能

完整路线优化未列入批次 5。后续可在普通地面连续段内尝试任意角度连接，删除无必要拐点；搜索仍可以使用离散支撑节点。机器人使用合法按键和现有视角规则跟踪，不以路线任意角度为由新增模拟输入权限。

只在新路线或相关依赖变化时处理，在既有后台预算内限制直连距离、候选数量和查询总量。不做所有点两两比较，不每帧平滑整条路线。复用既有查询缓存，不增加新进程或长期缓存。

优化完成的部分使用新依赖和路线修订；预算耗尽时保留仍有效的已验证原路线。相关地形已经使原路线失效时，先按现有规则保持身体安全，不能借“性能后备”继续执行。已有动作证明只能整段保留或由原能力重新验证，不裁剪证明冒充已验证。

优化必须同时比较路径长度、几何查询次数、后台 P95/P99、首条可用路线延迟和控制帧耗时。阈值在独立步骤首次候选运行前冻结；不能用更短的路交换原地等待。

## 7. 实施核对后的入口与预算

查询从规划请求中的真实身体状态开始，沿同一条普通路线调用现有控制器，再用 1.21 计算器推进。不能用未来格心和任意入口速度作出拒绝结论。临时帧只供计算，不写观察和记忆。查询缓存只在同一次筛选内使用，并核对事实版本。

一次目标查询最多检查六个内部位置，共用 50 ms 截止时间；每次推演最多 64 tick。用尽预算仍报告 BUDGET_EXHAUSTED。原普通连接满足既有几何和内部停止余量时，可继续交给原闭环控制，但不得把该后备标成筛选通过。明确阻塞或缺事实时不采用后备。严格动作不走这条规则。
