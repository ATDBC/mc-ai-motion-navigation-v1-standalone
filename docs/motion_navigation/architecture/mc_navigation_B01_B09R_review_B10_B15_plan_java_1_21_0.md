## 0. 核心决定

**保留 B09-R 的计算器边界；将尚未实施的可达性查询、输入求解和在线接入明确放入 B10。**

当前系统已经有两类成果：一类是 B01–B09 建立的实际导航、有限动作与执行闭环；另一类是 B09-R 建立的离线／只读逐 tick 运动计算能力。二者尚未完全连接。下一步不是重写计算器，也不是仅仅取消动作间的停稳，而是建立“可筛选、可求解、可接纳、可及时执行”的连接。[R01][R12][R14]

推荐顺序：

```text
B01–B09 已有闭环 + B09-R 基础计算支持域
  → B10-A：补齐在线前提和相关差分证据
  → B10-B：动作可达性查询、单动作求解与验证
  → B10-C：规划接纳、连续接续与实时执行
  → B11：特殊接触与材质组合
  → B12：攀爬与进出模式
  → B13：流体、呼吸与自然 Crawl 入口
  → B14：混合能力选路与效率
  → B15：分层验收和有限范围发布
```

本方案不要求推翻 B09 或 B09-R 历史验收。新证据、新控制器、新规则适用域分别记录。B10 可以先交付单动作自动求解的中间结果，但只有连续闭环门槛通过后才宣布 B10 完成。

### 1.2 B09-R 的实机证据如何理解

| 数据组 | tick 数 | 开环段数 | 记录的最大开环位置误差 |
|---|---:|---:|---:|
| Walk／Sprint／Crouch 稳态 | 1,298 | 81 | 约 6.02×10^-7 格 |
| 合法 Crawl 稳态 | 602 | 23 | 约 2.38×10^-7 格 |
| B09 空中转换 | 1,948 | 115 | 约 5.44×10^-7 格 |

当前差分门槛是每轴位置 0.001 格、速度 0.0001 格／tick，并要求相关离散状态一致。记录中的精度明显小于门槛，但结论只适用于对应规则、输入相位和样本。[R11]

219 段来自两份主要 sidecar 的连续性切分，不是 219 个新实机场景。Crouch/Crawl 的姿态变化若发生在上一 post_state 与下一 pre_state 之间，就在边界切段；这些片段证明稳态计算，不能证明全链路姿态切换连续预测。验收文档还说明两份 sidecar 没有水平碰撞事件样本，专项形状差分、潜行防跌落、落地同 tick 跨步、单独释放冲刺等仍需补采。[R11]

B06 普通材质的新补采在观察支撑阶段失败，未进入物理差分，不能计入 B09-R 新成绩。这不取消早先 B06 的有限控制器验收，但也不能用旧成绩冒充新计算器的材质验证。[R07][R11]

### 1.3 实现不等于已取得同等证据

以后所有能力清单至少分列：已登记、代码实现、组件验证、指定输入实机差分、在线控制实测、组合实测。一个布尔 `supported` 不足以表达这些区别。

B09-R 当前可确认的架构成果包括：完整状态构造时显式处理缺失／冲突；碰撞是正常计算事件；未知世界与未支持规则有独立结果；rollout 在完整 tick 边界终止；分支及恢复不修改共享状态；资源完整性能够沿整段演算保留。[R12][R15][R16][R18]

### 1.4 文档同步项

`reports/current-performance-and-limitations.md` 仍停在本地来源 `5d6a0de` 和 B01–B09，而 README 与 B09-R 专项文档已更新。总计划中还有“顺序执行器只识别 Walk/JumpUp”等历史表述。应更新当前状态说明与消费者清单，不能据此重新实现已经完成的 Step、其他地面模式、空中动作或活动走廊变化跟踪。[R01][R08][R20][R21]

## 2. B10 前必须承认的六个真实接入边界

### 2.1 计算器输入不是上层按键命令

`TickInput` 表示已经采样并交给运动规则的轴值、按键标记与运动 yaw。后续求解器不能任意优化这些值后直接写玩家输入；必须证明它们能由现有正式命令链路产生，包含姿态缩放、朝向、冲刺、租约与更新相位。[R12][R15]

最小完整路径是：

```text
合法命令序列
  → 输入采样／模式边界投影
  → TickInput + 运动前状态
  → B09-R step / rollout
  → 预测后果
```

如果模型边界之前或两个运动 tick 之间还存在会改变后续的状态处理，应补充同相位转换适配并验证，不能用每 tick 真值重注入掩盖遗漏。保留计算器输入 schema，不静默把其含义改成原始按键。[R11][R12][E1]

### 2.2 完整诊断状态不等于正式 actor 能取得的状态

`ClientPhysicsTickDiagnostics` 是 opt-in 诊断。线上状态构造必须来自正式观察、固定配置和有依据的估计，不能直接读取未来 sidecar。当前 `build_physics_state` 仍要求显式给出跳跃冷却和四项运动属性；并把新构造状态的局部 movement_tick_id 初始化为 0。[R12][R16]

因此需要一个线上状态锚点：正式观察序号、玩家运动 tick、当前已应用输入和在途输入之间的映射。局部 rollout 步数不能冒充真实客户端 tick。调用者写了 `explicit_assumption` 只意味着假设被记录，不意味着线上安全已被证明。

### 2.3 计算器与导航层的单位不同

计算器内部使用格／tick，既有导航契约使用格／秒。新求解器、动作状态、成本和回执必须通过单一边界转换，测试速度、预算和目标阈值的单位，不能直接复用同名数值。[R12][R15][R19]

### 2.4 资源结果仍是条件化的

当前单步能报告已知跳跃消耗贡献，`ResourceUpdate` 标记 `CONDITIONAL`；下一食物水平和饱和度并未通过完整服务端 HungerManager 时钟推进。[R12][R17]

固定食物条件下的多步轨迹可以是条件化预测，但不能拿它证明长路线始终可冲刺。B10 至少要有经验证的资格保持范围和路线消耗界；完整资源同步与恢复语义需在依赖它的功能发布前补齐，不能用事后检查替代搜索期间的必要状态。

### 2.5 当前性能不支持逐帧大枚举

仓库记录：单 tick P50 0.387 ms；20 tick 单分支 P50 8.393 ms；60 tick P50 25.967 ms；32×20 tick P50 267.474 ms；128×20 tick P50 1066.838 ms。[R11]

这些是特定机器与基准上的 P50，不是实时最坏保证。新方案不能在每个控制帧枚举几十条完整轨迹，也不能为了达标把预测截到落地之前。

重计算优先放入已有后台体系；快路径负责有限检查与执行已接纳的短期控制。优化先减少重复工作、复用前缀和只读查询，必要时再优化实现。任何优化均须保留相同规则与差分结果。[R14]

### 2.6 一个具体解不是整个入口区间的通行证

目前 `MovementStateClass` 只有模式、姿态和速度大小区间；必须补充对后续确实有影响的位置区域、方向和内部状态。具体连续状态与规划用有限类别分开，不能把位置、速度、方向各自宽区间的笛卡尔积都视为可执行。[R19]

## 3. 后续统一结构：职责不变，连接补齐

```text
目标 / 风险 / 资源 / 可用能力
  → 既有目标与规划请求
  → 后台拓扑与动作图搜索
       ↔ 动作可达性查询：快速筛选、查找已有通过依据
       ↔ 有界局部求解：生成合法控制序列
              ↔ 输入边界投影
              ↔ B09-R 计算器及后续规则扩展
       → 经验证的动作候选
  → RouteAdmitter：最新世界、身体、时序、资源核验
  → 已接纳的动作序列与有限执行走廊
  → 局部有界修正 + 既有动作阶段
  → 唯一 MotorGateway / Fabric 输入出口
  → 实际反馈与状态更新
```

计算器继续只算结果。动作验证器判断某条给定轨迹是否满足空间、终态、资源与恢复条件；可达性模块判断哪些连接值得考虑、哪些已有可执行依据；求解器产生输入；规划器连接兼容动作。不要新增第二张地图、第二份真实身体状态或第二个输入写入者。[R14][E2]

可达性结果至少区分：

| 含义 | 处理 |
|---|---|
| 已知约束能明确排除的连接 | 排除，并注明能力／模型／已知范围 |
| 条件可能成立、尚无控制依据 | 候选，进入求解或待计算 |
| 存在已验证输入及适用条件 | 可生成动作边，仍不是即时执行许可 |
| 缺世界、缺身体条件或机制未支持 | 分别返回，不伪装几何阻塞 |
| 搜索预算用尽 | 保留未完成语义，不宣称现实绝对不可达 |

“高度差小于最大值”和“距离差小于最大值”不能独立组合成充分条件。范围必须联合考虑入口速度／方向、落地区域、途中净空、终态和资源。稀疏成功样本只能形成有限适用依据；空表项不能证明物理不可能。

动作边建议携带：规则／模型身份、有效入口、合法命令或参数化控制依据、相关轨迹／接触、出口及不确定范围、资源完整性、预计时间、恢复条件和世界依赖。复用 `MovementTransition`，按实际需要扩展，不另外定义一个与路线执行互不认识的总协议。

## 4. B10：从计算器到可达性、单动作求解和连续执行

B10 是本次变化最大的交付包，应分成 A/B/C 三个可独立验收的子里程碑。基础混合动作与必要模式转换在 B10 实现；B14 再扩展全能力自动选择和全局效率，不能把让 B10 成立的正确性推迟到 B14。

### B10.0 补齐将被在线使用的预测边界

**范围：** 真正发生的水平碰撞／碰顶、普通材质替换、半砖／直角和转角楼梯／地毯／已支持雪层、潜行防跌落、落地同 tick 跨步、单独释放冲刺、Crouch/Crawl 连续切换。

沿用 sidecar、差分与只读回放。姿态转换必须有未靠真值重注入消除的连续序列。外部传送、真实世界修改等合法事件仍可切段，但必须记录原因，不能把正常模式转换统一切掉后宣称转换通过。

**落点：** `physics_validation.py`、已有差分脚本与完整工程 `ClientPhysicsTickDiagnostics`；仅在出现反例时修对应规则。

**验收：** 各专项有固定输入实机证据和组件对照；原阈值与离散事件要求保持。补采失败单列，不计成功；不要求为了补一个边界重新跑全部无关大量场景。

### B10.1 建立正式状态与命令到 TickInput 的可验证投影

**交付：** `NavigationFrame` 与完整模拟初始状态的正式映射、状态有效 tick、在途输入；合法命令经过采样／模式边界处理得到 `TickInput`。

支持输入相位、方向符号、实际 yaw、姿态缩放与释放语义。有限采样轴值必须可由实际输入产生，不能让求解器选择未实现的模拟器专有连续推力。

**建议新增：** `motion_input_projection.py`；扩展 `physics_adapter.py`、正式动作／观察契约。真实 Fabric 修改路径从完整工程定位，本文不猜测未公开路径。

**反例：** 同一观测重复使用；相同位置速度但冷却不同；采样后 Crouch 轴值被重复缩放；迟到输入；同速度不同 yaw；属性缺失；诊断开启／关闭得到不同正式行为。

**验收：** 新输入的运动前状态可以在事前构造并与实机对齐；诊断数据不进入 actor；新计划不能从收到时刻无条件重新起算。仅具声明、缺少依据的假设不能取得执行许可。

### B10.2 先确定实时计算安排与预算

重搜索复用独立后台进程或明确隔离的有界工作队列；控制侧不等待完整求解。已有固定路线控制继续工作，直到对应新能力通过在线验收。候选键包含规则、输入投影、状态类别、相关世界、目标终态和资源条件。

先优化重复前缀、稳定几何查询、对象复制和输出模式。摘要模式不能跳过碰撞或事件；预算检查发生在 tick 边界，因此还要测单次 step／几何查询最坏耗时。不能用“有 wall-time budget”冒充硬可抢占的实时上界。

**验收：** 固定 1／20／60 tick、1／小批量／32 分支基准，分开 P50/P95/P99 与最大值；记录带完整检查的整帧预算。候选数由结果反推，不预填一个无证据的每帧枚举数。

没有可行实时配置时，只发布离线求解结果，不宣布连续在线完成。缩短预测范围不得截去已承诺动作的落地和恢复；可离线预先验证完整后果，在线用经过验证的剩余方案和有界检查维持。

**B10-A 完成：** 预测证据、输入边界和预算足以支持至少一个限定在线能力；尚不声明自动导航求解已经实现。

### B10.3 动作可达性查询与候选生成

从既有支撑面和动作能力查询出发，筛选局部连接。先处理现有三类空中动作和已支持普通地面／Step；不对地图中所有位置两两求解。

建立有限、条件化的能力索引：相对几何、合法接近空间、入口姿态／方向／速度、目标区域与出口条件。旧 Profile 可作为种子；条件不匹配时不缩放轨迹强行套用。

**建议新增：** `motion_feasibility.py`；现有 `query_air_motion`、JumpUp/Step 查询保留责任，逐步消费统一结果。

**反例：** 高度和距离单独在限值内但组合无解；有端点无途中净空；落点可到但恢复区不足；表中无样本却有其他控制可过；需要先加速而非从当前速度直接跳。

**验收：** 候选与已验证边不混淆；不支持和预算耗尽不写成绝对无路；预计算库记录证据域，不把若干扰动测试写成连续集合证明。

### B10.4 单动作输入求解与独立轨迹验证

求解器在有限起跳／释放／转向／制动参数上搜索合法命令，经输入投影调用同一个计算器。先用旧标准场景验证，再冻结新入口偏移、速度、方向、起落区域；至少一组不再需要逐场景手调松键阈值。

验证对象是整段实际运动、模式变化、支撑／净空、资源资格、目标出口和必要恢复。`CalculationStatus.OK` 只说明算完，允许包含不符合导航要求的碰墙或错误落地，不能直接映射为可通行。[R12][E2]

**建议新增：** `motion_solver.py`、`motion_validation.py`。不为每个动作复制重力和碰撞；物理规则仍由计算器提供。

**输出：** 一个具体控制依据、适用入口、完整预测、出口、成本、资源完整性、依赖和恢复条件。有限搜索未找到与已知硬冲突分别报告。

**验收：** 指定任务的自动输入在独立 Fabric 验证中完成；输入不能依赖后验轨迹；验证组冻结后不逐场景调参；旧安全反例全部保留。

**B10-B 完成：** 在冻结范围内可自动产生一次动作的真实可执行输入，但还未通过全路线连续执行门槛。

### B10.5 接入规划、接纳和状态／资源条件

扩展现有 `MovementStateClass`，只纳入会改变后续可达性的有限类别：位置区域、速度方向与范围、姿态／模式、接触和必要内部条件。连续状态仍用于实际计算，有限类别仅用于搜索组织。[R19]

前一动作的实际可实现出口必须满足后一入口，不仅仅是两个粗区间存在交集。不能将“同站位、相同速度大小”视为等价。先针对小图保留必要状态和资源标签，再控制规模。

B10 至少实现基础 Walk/Sprint/Step/空中动作的自动选择与必要切换，保留原 B08 单模式请求路径作对照；这是一项新增能力，不冒称已存在。更广的混合模式全局优化留给 B14。[R09]

资源方面：建立客户端资格与服务端资源变化的明确适配。近期若用保守界，必须有依据并记录范围；若不确定性会改变可达性，返回条件不足／需要更新。不能让每条边读取相同 food_points 就宣称整条路线资源安全。状态相关资源变化、每段准备和恢复耗时按顺序累计。

**落点：** `movement_transition.py`、`known_map_planner.py`、`planner_worker.py`、`route_admission.py`、`action_route.py`；按需要新增 `resource_projection.py`，不修改纯物理结果为任务评分。

**验收：** 同图同状态代价与独立参考一致；另有必须跨隙、必须带速、必须调整出口的独立可达场景。状态被合并后漏解的反例必须保留。新动作加入图时立即检查启发式，必要时先用零启发式。

### B10.6 有限窗口接续与已存在走廊的扩展

先联合求解“接近—一次动作—离开／转弯”，再扩展相邻多动作。根据下段选择本段落地位置和速度，不先固定平台中心再现场补救。停稳是合法选项，不是默认强制动作。

复用已经存在的路线身份、进度、世界依赖和表面路线活动走廊，不重建它们。新增的是带速度／模式／控制时序及恢复条件的连续执行范围。逻辑折点移除不能删除仍需验证的依赖。[R05][R08]

**验收：** Sprint→Jump→Walk、落地转弯、连续台阶、连续高差、连续跨隙、低姿态退出；必须同时有可连续组合和确实需要制动的组合。每个声明可连续组合都不能靠无谓停稳通过。

### B10.7 实时执行、延迟和异常

控制出口按明确玩家运动 tick 或有效状态窗口执行短期方案；重计算提前进行，迟到候选复核而非整体静默顺延。必要时在现有 Fabric 唯一输入出口增加有界队列和护栏；不引入第二输入写入者。

区分：求解迟到、观测过时、回执丢失但通信正常、真正断流。真正断流只能依赖实际已下发租约和经验证的本地回退，不承诺不存在的后续控制。服务器纠正或未模拟状态跳变会终止原自由预测。

同一观测的逻辑交接有次数上限，不重复推进物理或资源，不多次写入按键。整帧统计涵盖交接两边、输入投影、验证与序列化，不能只返回最后一个控制器的计时。

**验收：** 人为延迟、抖动、重复观测、连续漏帧、旧会话、交接取消、空中目标替换、后台 500 ms 阻塞分别测试；能继续的安全前段不被清空；没有安全后续时按模式恢复。

### B10.8 双轨验证与有限能力发布

上线分为：离线候选 → 只读影子 → 固定场景新控制 → 混合路线。每阶段只有一个真实控制器；影子输出不改变世界与输入。

为新能力发布独立规则／投影／求解器／执行契约身份。旧 Profile 保留回归，不在新求解失败时静默退回一个不再适用的旧控制器。已完成动作与资源状态不能因后端切换被重置。

**B10-C／B10 总验收：** 冻结普通支持域内的目标可以由规划生成、求解落实、正式接纳并连续执行；至少一组自动选择不同入口与时机而无中间强制停稳；失败分类和时序门槛通过。多格、对角、极限落差只在新增支持域单独验证后开放，不由计算器精度推导授权。

## 5. B11：特殊地面与接触——扩展规则，而非堆固定轨迹

沿用原计划的四组范围，但加入“旧目录—计算器支持域一致性”任务。当前计算器有有限 `_ORDINARY_MATERIALS` 列表，而系统已有 `BlockMotionCatalog`；二者需要一个明确的共享分类来源与验证状态，不能今后一边增加普通材质、一边仍被另一层拒绝，更不能直接把注册表全部放行。[R07][R17]

| 子任务 | 交付 | 强制场景 |
|---|---|---|
| B11.0 分类一致性 | 几何、运动机制和证据级别分开；规则目录映射到计算支持域 | 普通等价替换、异常几何、已知但未支持接触 |
| B11.1 滑移／减速 | 逐 tick 接触参数和真实查询位置、进入／退出、制动模型 | 普通↔冰类、减速↔普通、混合脚下支撑 |
| B11.2 体积／侧面效果 | 非空气空碰撞体仍保留机制；接触顺序可验证 | 蜘蛛网、蜂蜜类进入、内部、退出及侧面接触 |
| B11.3 落地响应 | 落地后的再次离地、抑制条件和恢复；接地不是全部终态 | 弹性落地、落地后转向与可停／不可停的目标 |
| B11.4 条件支撑／危险 | 装备和实际状态、伤害／世界变化策略；接触形状按模拟状态查询 | 细雪代表条件、危险与非危险状态、条件缺失、运动诱发变化 |

每个子任务执行：规则对照 → 单步／开环差分 → 可达关系／求解 → 控制 → 与已有动作接续。首次接触特殊材质的那个 tick 也要验证，不能直到下一个 tick 才更新规则。

新增状态依赖形状时，`PhysicsWorldView.shapes` 应能接受必要预测上下文；当前简单静态接口不够时只扩展这一边界，不复制世界。抽象上的多处理器不是任意排序，必须遵守固定版本行为。

危险识别与绕行不计为穿越能力。默认无预计伤害、无主动世界修改；会引发未授权踩踏或设施变化的动作仍拒绝。未做复杂动态世界模拟，不承诺相关设施可通行。

**主要落点：** `block_motion_traits.py`、`world_model.py`、`physics_adapter.py`、`physics_1_21.py`；按实际独立职责新增接触规则文件。求解器通过统一接口使用新规则，不散布方块名特判。

## 6. B12：攀爬及模式转换

### B12.0 观察与状态

补充正式可取得的附着面、邻域／方向及模式条件，区分地面、空中和攀爬。有效附着不是脚下地面支撑，不给攀爬伪造支撑节点。

### B12.1 指定输入规则与差分

梯子、已登记可攀爬藤蔓族、脚手架逐类验证上、下、保持和离开，使用同一基础重力／碰撞／时钟。标签相同不能代替进入和控制规则验证。

### B12.2 进出模式的动作边

地面接近→进入攀爬→上下→顶端或侧向退出→地面/已支持空中动作，全部进入能力查询、求解和图。不能只在专用测试中把角色预置到梯子上，就宣布可自动攀爬到目标。

### B12.3 取消与失联

终态可以是已验证的稳定附着，或安全退出。需要持续按键才能维持时，应记录对本地执行与通信的依赖；不承诺长时间断网安全。

**验收：** 三维目标、不同进入方向、顶部净空不足、附着丢失、有限中断、进出接续。加边即检查启发式与资源，不等 B14。

**主要落点：** 现有观察／世界／物理规则与模式接口；按需增加 `climb.py` 和 `physics_climb_1_21.py`。两者分别持有动作语义和计算规则，不重复地图和执行调度。

## 7. B13：流体、资源时钟和 Crawl 自然入口

### B13.0 流体与固体共存

布尔 `fluid` 不能表达本阶段所需的高度、方向和含水形状。补充合法观察的流体状态和邻域条件，必要信息不足时不猜流向。固体碰撞与流体体积独立，含水方块不整体空气化。

### B13.1 指定输入规则与运动模式

逐项验证静水、水面／水下、上浮／下潜、声明范围内流水和气泡柱。输入 pitch、yaw 与移动关系重新核验，不直接使用地面水平模型。极端动态水体不在声明范围内时明确拒绝。

### B13.2 呼吸与资源状态

区分当前量、容量、变化速率和可靠恢复事件。不能把任务开始时的低呼吸量当作永远不可超过的容量上限；不能把原始 exhaustion 当作“越大越有能力”的标签。

资源时钟和正式同步需有独立证据。规划状态必须保留影响能否到达下一可靠呼吸点的差异；不能仅在路线结束时检查一次余额。恢复阶段按规则需要时间，并保留实际反馈。

### B13.3 出入水与低通道

地面→入水→Swim→可靠上岸区域；水中低姿态→合法 Crawl→低通道→退出，作为显式转换求解和验收。不会直接写姿态，也不以未授权开合活板门制造入口。熔岩只做风险识别和禁入，不计为本批游泳范围。[R20]

### B13.4 取消与失联

取消到可维持的呼吸状态或合法出水终态。输入丢失只承诺有限、已经实现的本地回退。没有相应通信／本地执行保证时，不承诺持续控制上浮。

**主要落点：** 世界／正式观察／资源投影、`physics_adapter.py`、流体规则、动作查询和既有图。水中节点不以地面支撑为前提，但也不必无差别搜索全部空气体素。

**验收：** 含水形状、流动与出口、呼吸不足、低呼吸出发后恢复、模式切换、Crawl 自然入口和失败；所有模式新边及时验证代价与启发式。

## 8. B14：全能力混合选路与真实效率

B10 已完成基础求解和必要混合选择，B11–B13 已完成各自真实接入。本阶段不是第一次把它们连起来，而是在这些正确边之上扩大组合和改善效率。

### B14.1 成本、目标和资源

统一起步、加速、姿态变化、离地、落地、恢复与接续时间，不重复计费。时间／资源偏好由任务给出；安全与禁止机制是硬条件。物理结果不随任务名称改变。

图搜索的状态相关代价和资源支配规则必须一致。更快但无法保持后续资源或方向的前缀不能覆盖较慢可行前缀；不确定性存在时返回条件范围，不捏造精确余量。

### B14.2 多能力自动选路

在地面多模式、Step、三类空中、特殊接触、Climb/Swim 转换间选择，覆盖不同起终模式、不同最终速度与资源政策。保留受限能力配置，未启用能力不进入图。

### B14.3 连续连接和简化

有限支撑区域／拓扑节点组织全局搜索，局部实际位置和速度保持连续。对可简化片段重新验证逐 tick／tick 内接触、终态和恢复；不能切穿拐角、跳过模式转换或丢依赖。

### B14.4 缓存和算力

优先复用有效控制余段、候选初值、共同输入前缀和稳定世界查询。缓存键包含规则、输入投影、状态、资源、形状／材质、能力和策略条件；某一精确状态的解不能直接借给一整个未验证区间。

按实测热点决定是否对计算器采用原生优化或批量实现；任何替代后端必须对同一金标准做差分。状态采样和近似剪枝若影响完备性，要标明不完整结果，不承诺无损优化。

### B14.5 效率证据

同能力、同地图、同起终状态和风险约束比较真实耗时、无谓停车、资源、重试和规划延迟。不同能力前后的完成时间不当作算法纯提速。继续独立验证“搜索最优”与“图没有漏掉目标场景中的已支持连接”。

D* Lite、完整 NavMesh、GPU 或机器学习不是本阶段必需项。[R20]

## 9. B15：发布前分层证据、规模和跨机器验收

### 9.1 冻结发布清单

每一行至少列出：动作／模式、材质与形状族、身体／装备条件、规则与输入投影身份、入口与出口范围、资源完整性、取消／断流能力、组件／差分／在线／组合证据。未通过不能临时移出清单后继续沿用原发布声明。

### 9.2 继续沿用的门槛

以下是未来验收要求，不是已达到成绩。沿用原计划 [R20]，计算器部分采用 B09-R 已冻结要求 [R11]。

| 项目 | 要求 |
|---|---|
| 规则差分 | 支持场景的单步及开环误差满足预先冻结阈值，相关离散事件一致；转换不靠真值重注入过关 |
| 强制可达场景 | 全部完成；必要减速与不可连续例外在运行前定义 |
| 每个独立运动模型／控制能力范围 | 正式 Fabric 有效／边界闭环至少 200 次；相同模型材质别名不逐名凑数 |
| 不可执行反例 | 另列正确拒绝率；不用于抬高到达成功率 |
| 可避免安全违规 | 0，包括未知放行、未授权伤害、错误完成及输入多写 |
| 控制进程完整本帧 | P95 ≤8 ms，P99 ≤15 ms，名义最大 <30 ms；50 ms 提交硬期限另记 |
| 搜索基准 | 至少 1,000 个有限图／动作图与独立参考比较；代价误差不超过 1e-6×max(1,参考代价) |
| 组合随机导航 | 至少 1,000 次可复现分层闭环，成功率 ≥99%；不要求全部在 Fabric 重复，实机／模拟分开统计 |
| 后台阻塞 | 500 ms 注入；足够安全前段可继续时不新增无谓停车 |
| 规模 | 远处静态地图扩大 10 倍时，本地控制 P95 增量不超过 max(2 ms, 原P95×20%)；初次载入另计 |
| 持续 | 30 分钟，任务、缓存、日志和结果队列有界 |

单条参考控制“在计算器中成功”不是独立闭环证据。统一模拟器可扩大覆盖，但控制器和计算器共享规则会有共同错误，所以核心模式、组合和边界必须保留独立 Fabric 验证。

### 9.3 跨机器和时序

同一输入／状态／世界快照按逻辑 tick 比较计算结果，不比较同一现实毫秒的位置。执行另测采样年龄、输入延迟、抖动、尾部超时、连续丢帧、客户端／服务器不同更新节奏以及进程崩溃。

需要两种结论：物理规则一致性，以及当前机器是否满足在线执行时序。如果尚无第二台实际设备，只能报告延迟注入与本机结果，不能宣称已验证跨硬件部署。

物理身份与执行时序配置分开。不能因慢机器迟到而改重力、摩擦或逻辑 tick 参数，也不能无条件把旧候选开始时间顺延。

### 9.4 加速数据生成

现有无等待 rollout、分支和预算可用于离线能力种子生成与测试扩充；不是已经建成的同步 Minecraft 训练环境。不把 `/tick rate` 当作完整玩家高倍速步进后端。官方 tick 命令对玩家与世界的处理并不简单同比，因此完整游戏加速另立工具链任务并验证。[E3]

### 9.5 证据与清理

保留唯一失败／边界样本、原始输入、环境身份、种子、分段原因、耗时口径和复现元数据。重复网页和中间截图可按事前规则重建或清理，不能删除引用中的唯一证据。公开摘要缺原始轨迹时明确“文档记录”，不要诱导外部审阅者认为能从该快照直接重现实机。

## 11. 开始执行时的前三项具体任务

**任务一：补一条完整命令到状态的连续证据链。** 使用现有 B08/B09 测试入口，保留一次姿态／冲刺切换及相应输入采样，不靠切段真值重注入；确认原始命令、实际采样输入、运动前后状态和之间的更新能对应。先定位缺口，不同时改规划和物理。

**任务二：交付正式状态／输入投影并做只读比较。** 从 actor 合法信息和有依据的状态推算构造初始值，与诊断仅作对照；验证重复观测、单位、轴向和冷却，现有控制器仍独占输入。

**任务三：测量带完整检查的小候选闭环预算。** 选择现有一格上跳或跨隙，用预先给定的少量合法候选序列比较，验证后台提交、返回与过期核验。此时还不宣称求解器完成。只有该数据链与预算通过，才开始 B10.3 的能力筛选和 B10.4 自动输入搜索。

最终判断：B09-R 已经给系统增加可复核的物理计算基础；B10 要把它连接成真实可执行的规划与控制能力，B11–B13 扩大机制覆盖，B14 提高混合选路效率，B15 证明整个冻结范围能够可靠发布。
