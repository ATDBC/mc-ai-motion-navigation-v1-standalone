# B12-B 部分观察与战斗移动 V1

日期：2026-09-26
状态：已实施并通过正式验收

## 1. 要解决的问题

现有移动近战已经能在目标暂时不可见时使用交战记忆，也能让攻击和直线接近在同一帧发生。普通步行其实已经会根据当前身体朝向自动选择前进、横移或后退，通常不要求路线视角。缺少的是另一项约束：这组按键是依据哪一帧朝向算出来的，以及同一帧还能允许战斗视角转动多少。

这会造成两个结果：机器人已经面向目标并能用横移或后退沿路线走，导航也算出了安全输入，但移动仍被取消；目标被遮挡后，已有的交战记忆、继续接近和原地补看也缺少一组统一验收。

## 2. 首版范围

B12-B 首版只处理：

- 单个已经直接看见过的交战目标；
- 正式按需实体查询能够继续提供新鲜位置；
- 已知普通地面上的 `WalkSegment`；
- 前进、左右横移和后退输入；
- 目标暂时离开视野、被墙遮挡或单帧观察不连续；
- 当前攻击仍要求目标直接可见、准星命中、距离和作用路径合法。

首版不把自由视角权限扩展到台阶、上升、跨隙、下落、冲刺起步或低净空姿态。它们继续要求各自动作证明声明的视角。

## 3. 复用现有状态

| 状态 | 唯一拥有者 | B12-B 怎样使用 |
|---|---|---|
| 目标身份、修订和任务终态 | `MovingMeleeDriver` | 变化时使旧站位、瞄准和攻击失效 |
| 直接看见历史和交战许可 | `EngagementStateV1` | 决定隐藏目标位置能否用于导航 |
| 当前目标位置和生命 | 正式实体观察 | 只查询已登记的当前目标 |
| 路线和局部安全输入 | `NavigationSession` 及路线执行器 | 继续决定身体该往哪里走 |
| 最终视角和操作 | 战斗技能与仲裁器 | 瞄准目标并决定是否攻击 |
| 实际输入和回执 | Runtime 唯一输入出口 | 记录哪组移动、视角和攻击真正生效 |

B12-B 不增加第二份目标记忆、局部地图或战斗专用寻路器。

## 4. 部分观察处理

目标信息分为四种情况：

1. **当前直接可见。** 可以导航、瞄准，并在其他攻击门禁满足时攻击。
2. **当前不可见，但交战许可和按需位置都有效。** 可以朝目标位置继续导航；进入攻击距离后先补看，不能直接攻击。
3. **观察序号出现短暂缺口。** 已经接纳且仍有效的身体动作继续由原执行器负责。新攻击和新目标修订等待下一份连续观察。
4. **从未建立交战许可、实体卸载、信息过期、身份变化或世界会话变化。** 隐藏位置没有使用权限，任务返回明确结果或取消旧动作。

墙后目标的位置只说明“目标在哪里”。武器不能穿过当前阻挡时，攻击门禁仍会拒绝。以后若加入能穿墙的能力，是否可攻击由那项能力自己的作用路径规则决定。

补看不是不可退出的状态。机器人开始补看后，如果新观察表明隐藏目标已经离开攻击距离，应立即释放补看视角并恢复导航。目标再次进入攻击距离后，仍要先取得直接视野，才能重新攻击。

## 5. 普通地面的战斗视角

`FixedRouteController` 每帧对九种离散地面输入做短期预测。它能自动选择前进、横移、后退或松键，并检查支撑、墙面、路线偏差和停止距离。

B12-B 不另写战斗移动控制器。战斗技能先给出本帧候选视角；正式导航驱动再把“当前观察朝向＋该视角增量”交给普通 `WalkSegment`，重新计算本帧移动。移动意图保存它依赖的视角意图 ID。仲裁器只有在这份视角实际胜出时才采用移动。

这项顺序也适用于接近阶段。只要当前观察仍有目标几何，移动近战驱动就持续提交一帧目标视角，导航按这份视角继续追击。这样机器人不会只靠横移接近斜前方目标，直到目标走出视野后才开始转头。目标几何缺失时不猜测视角，仍进入原有的观察缺口或补看流程。

例如，机器人原本朝北，路线要继续向东，战斗瞄准本帧向右转 15°。路线控制器直接按转动后的朝向选择前进与横移组合，并重新检查预测轨迹。它不会拿旧朝向算出的左移按键去执行新朝向下的运动。

若绑定视角没有胜出，本帧移动被明确压下，Runtime 保持可用。没有提供最终视角条件的旧调用仍可使用 5° 保守上限；该上限只是兼容路径，不再承担持续瞄准移动。

普通步行授权仍只有一 tick。下一帧依据新的正式观察和新的获胜视角重新计算。B12 审查整改后的持续追击与 C1-B 实机回归均未发现由此造成的断续。B03 实机脚本只直接验证底层地面控制器，不作为 `NavigationSession` 单帧授权的证据。

## 6. 权限边界

只有当前动作确实是普通 `WalkSegment`，且地面模式为 `WALK` 时，导航才声明这项单帧约束。空中动作、台阶动作、冲刺、潜行、爬行和其他没有声明的动作保持原规则。

仲裁器只核对移动依赖的视角是否胜出，不自行判断地形，也不修改移动键。路线执行器仍是移动安全性的唯一生产者。战斗技能只提交目标视角和攻击，不取得路线控制权。

## 7. 失败和记录

每个组合帧至少记录：

- 导航移动意图、所依据的观察序号和身体朝向；
- 战斗视角和攻击意图；
- 移动依赖的视角意图 ID，或兼容路径声明的水平转角上限；
- 被选中的移动、视角和操作；
- 移动被压下时的原因；
- 目标位置来源、观察连续性和交战许可；
- 后续输入回执与身体轨迹。

`NavigationSession` 还要逐帧记录执行器状态、动作序号、移动输入、是否提交以及 `reason_code`。回放中出现中性输入时，应能区分转弯速度控制、等待输入生效、结束制动和路线完成，不能只显示“导航没有移动”。

绑定视角落选只取消这一帧的移动，不封存 Runtime，也不把攻击自动算成失败。路线下一帧重新计算。目标信息失去使用权限时，旧攻击和路线按原有身份与取消规则结束。

## 8. 不变量

1. 未经路线控制器验证的移动不会因战斗需要而获得执行权限。
2. 大幅转头时按获胜视角重新计算地面移动，不复用旧朝向候选。
3. 空中和跨高度动作不会继承普通地面的自由视角权限。
4. 隐藏目标位置可以指导导航，不能单独授权攻击。
5. 单帧观察缺口不使仍有效的身体动作失去负责人。
6. 世界、目标身份、目标修订和任务取消继续使旧授权失效。
