# Minecraft 1.21 玩家运动计算器

日期：2026-09-20
状态：B09-R 已实现的稳定架构

## 1. 作用

运动计算器回答一个限定问题：给定完整身体状态、这个 tick 已实际生效的输入，以及只读世界几何，下一个 tick 会发生什么。

它不选择按键，不判断路线是否值得走，也不向游戏写输入。目标管理、搜索、路线接纳和控制器可以调用它比较候选，但不能把这些职责塞进计算器。

## 2. 组成

| 位置 | 职责 |
|---|---|
| `physics_types.py` | 保存规则身份、完整状态、tick 输入、结果和失败类型 |
| `physics_adapter.py` | 把正式观察和明确假设组装成完整状态；提供只读碰撞形状查询 |
| `physics_1_21.py` | 执行一个 50 ms Minecraft 逻辑 tick |
| `physics_rollout.py` | 对调用者给定的输入序列连续演算，并处理预算、取消和外部事件边界 |
| `physics_validation.py` | 把计算结果与独立 Fabric tick 记录对齐和比较 |

真实客户端中的 `ClientPhysicsTickDiagnostics` 只在明确开启诊断时记录同一 `movement_tick_id` 的运动前状态、采样后输入、运动采用的 yaw、运动后状态和接触事件。它不进入正式 actor 数据，也不改变输入。

## 3. 数据和单位

- 位置单位为格，速度单位为格／tick，角度单位为弧度。
- 一个逻辑 tick 固定为 0.05 秒。
- 规则身份为 `minecraft-java-1_21-player-motion-r1`。
- 数值语义为按 Java 1.21 调用顺序执行的 Python `float64` 实现。跨实现比较使用预先冻结的误差，不声称逐位一致。
- `TickInput` 保存输入采样后真正交给运动规则的前后、侧向、跳跃、潜行、冲刺和运动 yaw。它不是上层的按键意图。
- `PhysicsState` 保存运动分支需要的身体、姿态、接触、属性、资源资格和模式状态。位置与速度相同而冷却、姿态或实际冲刺不同的状态不能合并。

## 4. 状态构造

正式观察提供真实身体事实。客户端没有正式提供的字段必须由调用者明确声明；首版包括跳跃冷却、移动速度属性、跨步高度、重力和跳跃强度。

构造结果分为：

- `READY`：字段完整且没有冲突，可以进入计算器；
- `NEEDS_STATE`：缺少会影响当前分支的状态；
- `INVALID_INPUT`：同一字段来源冲突，或调用者传入未声明字段。

明确假设不能覆盖正式观察。世界会话、规则身份和状态 schema 不一致时，计算器拒绝运行。

## 5. 单步与碰撞

当前规则覆盖普通地面和普通空中运动、输入缩放、冲刺资格与释放、起跳、重力、阻力、分轴碰撞、潜行防跌落、落地、碰顶、撞墙、普通跨步，以及已知碰撞盒表示的半砖、楼梯、地毯和积雪层。

碰撞查询只读取动作扫掠需要的格子。必要格未知时返回 `NEEDS_WORLD`，不会产生一半更新过的状态。流体、未知碰撞形状或尚未支持的运动模式返回 `UNSUPPORTED`。数据或身份错误返回 `INVALID_INPUT`。

接触是正常计算结果。撞墙、落地或碰顶不会被误报为计算失败。若本 tick 首次碰到尚未建模的特殊材质，计算在产生后继状态前返回 `UNSUPPORTED`，不能套用普通方块规则。

## 6. 姿态和资源

首版覆盖 Walk、Sprint、Crouch，以及已经合法处于 Crawl 姿态时的保持和退出。它不负责主动进入 Crawl。

冲刺按当前饥饿、向前输入、碰撞、失明、使用物品和飞行状态判断实际是否成立。使用物品的输入减速尚未建模，因此该状态明确返回 `UNSUPPORTED`。

客户端可以准确给出本 tick 的跳跃消耗贡献，但完整饥饿变化还依赖服务端 HungerManager 时钟。因此资源结果标记为 `CONDITIONAL`，不能伪造下一帧食物值。

## 7. 多步演算

`rollout` 只计算调用者已经给出的输入序列。它支持完整轨迹或摘要、保存后恢复、从同一状态独立分支、tick 预算、几何依赖预算、外部时间预算、取消检查和外部事件边界。两种输出都保留带 tick 位置的关键事件和累计资源完整性；完整输出另保留每个单步结果。

预算、取消和外部事件只在完整 tick 边界停止。缺世界或遇到未支持规则时，只返回此前已经完成的前缀。计算器没有隐藏缓存、全局“已计算”标志或真实时钟等待。

## 8. 不变量

1. 相同规则、状态、输入和世界快照产生相同结果。
2. 计算器不读取目标，不生成候选，不选择输入，不写玩家控制。
3. 未知空间不当作空气；测试夹具只能从独立验证入口提供。
4. 失败类型保持分开，不能把缺信息、未支持和预算耗尽都写成阻塞。
5. 世界和状态只读；一个分支不能修改另一个分支。
6. 旧控制器仍拥有在线行为。B09-R 默认离线或只读比较，尚未获得动作许可权。

## 9. 当前边界

尚未覆盖水中运动、攀爬、飞行、鞘翅、特殊接触材料、药水／附魔造成的运动变化、使用物品减速和完整服务端资源时钟。当前性能基线约为每秒 2500 个普通静态世界 tick；这足以做离线验证和小批量候选比较，不能据此承诺未来控制帧可展开任意数量分支。
