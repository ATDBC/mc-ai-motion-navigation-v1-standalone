# 可靠稀疏运动证明 v1

状态：契约保持有效。T1-A0、T1-A1、T1-A2 已通过；T1-A3 因 Windows 性能门槛失败而停止。方案 B 和正式 worker 迁移均未实施。决定见 [D105](../decisions/0105-restart-sound-proof-slimming-and-decouple-tracks.md)，结果见[验收记录](../acceptance/sound-motion-proof-and-independent-tracks.md)。

## 1. 证明回答什么

证明回答两件事：一条输入流在哪些边界仍可安全放弃，以及越过最后可放弃边界后由谁负责让身体恢复到可安全停车的状态。

v1 保留逐 tick 主轨迹。主轨迹用于执行时的廉价比较；风险区间用于表示“不能随意停止”的连续范围；安全尾迹用于真正停止或恢复。没有实际计算过的尾迹不能产生安全结论。

## 2. 方案 A 的逐边界规则

每条按时或整体晚一 tick 的时序分支只回放一次主轨迹。随后按边界从小到大处理，状态只有“风险关闭”和“风险打开”。

风险关闭时：

1. 按旧扫描器规则计算当前边界的停车尾迹；
2. 尾迹安全时保持风险关闭；
3. 尾迹不安全时，以当前边界打开风险，并保留前一个可安全放弃边界。

风险打开时：

1. 当前边界明确在空中，即 `on_ground == false`，不计算该边界的假想停车尾迹，风险继续保持打开；
2. 当前边界着地时，先按旧规则计算停车尾迹；
3. 只有尾迹为 `SAFE_STOP` 且旧 `_risks` 原本会核对当前支撑时，才执行同一支撑查询；
4. 尾迹安全且当前支撑安全时关闭风险；否则风险继续打开。

着地边界不能提前查询支撑。首轮也不能因为当前支撑已知不安全而跳过停车尾迹。该顺序是方案 A 的一部分，因为 UNKNOWN、依赖集合和有类型失败都可能受查询顺序影响。

风险关闭后，后续边界可以再次打开新的风险。输出按顺序保留所有风险区间，不把多个区间合并，也不把第二个区间归为不支持。

## 3. 可以省略什么

方案 A 只省略风险已打开时的空中假想停车尾迹。原因来自现有 `_risks` 的关闭条件：空中边界不能成为恢复边界。无论该假想尾迹最终落地还是失败，它都不能在这个边界关闭已经打开的风险。

被省略的尾迹不写入证明，不计为安全，不提供恢复输入，也不参与运行时回退。方案 A 仍逐边界读取主轨迹的真实 `on_ground` 状态；不能从动作名称、固定 tick、输入变化或相邻采样点猜测空中范围。

“当前着地但支撑已知不安全”不在 v1 的省略范围。以后若要加入，必须先证明它不会改变旧查询顺序、UNKNOWN、依赖收集、风险关闭和可执行尾迹。

## 4. 等价边界

v1 要证明的是风险开闭等价：在支持范围内，方案 A 与旧扫描器对每条时序分支产生相同数量、相同顺序和相同边界的风险区间。最后可放弃、承诺和恢复边界必须逐项一致。

v1 不承诺完整结果等价。旧扫描器会让风险区间内部、空中边界上的假想尾迹否决候选。方案 A 有意取消这部分否决权，因为这些尾迹既不能关闭风险，也不会被执行。验收必须单列因此产生的状态差异，不能把它们描述为旧结果完全一致。

## 5. UNKNOWN、UNSUPPORTED 和依赖

主轨迹、着地边界尾迹、恢复尾迹或实际支撑查询遇到 UNKNOWN 时，结果仍为需要世界信息或拒绝，不能把缺失格当空气。不能为了保持样本通过而少收依赖或改变查询顺序。

规则、材料、状态类型或物理分支不在当前能力范围时，返回有类型的 `UNSUPPORTED`。它与 UNKNOWN、预算耗尽、候选不安全和普通未找到分开记录。

方案 A 跳过的空中假想尾迹没有查询，也不产生依赖。文档和结果必须明确这是主动缩小假想尾迹的否决范围，不能声称这些未查询位置已经安全。

## 6. 证明内容和执行

每条时序分支至少保存：

- 输入和主轨迹摘要；
- 全部风险区间；
- 入口、最后可放弃、恢复和终点所需的可执行安全尾迹；
- 每条尾迹的输入、起点、终点、伤害、依赖和最大 tick；
- generation、owner、窗口、规则和世界会话身份；
- 物理步、尾迹步、查询和拒绝原因计数。

实际使用安全尾迹前，执行器仍从当前真实状态做有界回放，并核对身份、窗口、伤害余额和依赖。跳过尾迹的空中边界不能伪造为安全尾迹节点。

输入流第一条回执只选择按时或整体晚一 tick 的一个分支。中段单条晚到、丢失或内容改变属于偏离，不能重新选择时序分支。

## 7. 方案 B 的预留边界

方案 B 不属于 v1 的实施范围。只有方案 A 已通过完整性和安全门槛、Windows M0 又仅因性能不足而失败，才可以另立决定。

未来方案 B 只能用代码等价关系或保守物理上界单向证明一段边界为 `SAFE`。证明不适用时必须回退方案 A。它还必须生成可以实际执行的安全尾迹；只有 SAFE 标签、没有输入和回放依据的结果不能进入正式链。

## 8. 与 T2、T3 的接口

T1 的证明格式稳定前，T2 不删除完整 bundle、规范 bytes、lease 或 registry 中的旧载荷。格式稳定后，receiver 可以只核对消息边界和父侧权威事实，但 candidate、executing、safe-tail 三种责任用途保持不变。

T3 只记录客户端 tick 顺序，不读取风险算法的通过状态。T1、T2、T3 全部通过前，不建立连续两跳或零等待交接。
