# 按风险连续运动架构 v1

日期：2026-10-11。状态：设计冻结；尚未实现。依据 [D099](../decisions/0099-adopt-game-first-risk-graded-short-open-loop-control.md) 与 [D100](../decisions/0100-use-risk-aware-continuous-deviation-recovery.md)。

## 1. 目标

这份架构规定偏离发生后由谁判断、由谁继续控制身体，以及何时可以停车、局部接回或重新规划。

默认行为是：安全区域内保持运动。系统不为回到格心、精确落点或理想入口而停车。连续跳跃、跨隙和高度变化允许真实落点存在偏差；只要当前位置仍安全，并且能在运动中接入后续路线，就继续前进。

安全仍是硬边界。接近坑、伤害区、未知落点或已越过承诺点时，必须保留相应证据和身体责任。流畅不能用来放宽 UNKNOWN、伤害额度或控制权规则。

## 2. 长期不变量

1. Runtime 和既有输入出口仍是唯一真实输入出口。
2. `ExecutionSupervisor` 仍是身体控制权与交接的唯一权威。
3. 观察和输入账本记录真实状态；预测状态不能冒充观察。
4. 规划节点和格心不是必须经过的物理目标。
5. 下一动作声明可接受入口；前一动作不判断下一动作的具体类型。
6. 偏离原因只用于诊断。继续、接回、规避或收尾由当前风险决定。
7. 安全落地与任务完成分开。
8. 局部接回失败后才进入完整重规划。
9. 普通安全 tick 不做完整搜索和整段物理重证。
10. 已承担的空中或在途严格动作责任必须完成收尾，不能因目标变化或旧计算失效而消失。

## 3. 复用的正式数据

连续运动不建立第二份路线、世界或身体状态。执行时从现有正式数据读取需要的范围：

| 数据 | 用途 |
|---|---|
| `GroundTraversalPlan.corridor` | 当前地面段允许的身体区域 |
| 路线几何与进度 | 选择前方接回位置，判断后段是否仍可复用 |
| `SegmentEntryWindow` | 下一动作可接受的位置、速度、方向、姿态和模式 |
| `MotionContinuationRequirement` | 正常入口、恢复入口和后续路线身份 |
| `VerifiedMotionResult` | 严格动作输入、轨迹、落地区、依赖和时间窗口 |
| `ActiveRouteTracker` | 相关世界变化、有效依赖和当前动作进度 |
| 输入账本 | 实际发送、应用、晚到和缺失事实 |
| 正式观察与状态锚点 | 当前真实身体、支撑、姿态和接触 |
| 外力事件与运动残差 | 识别输入无法解释的位移 |

短开环输入包只是这些正式数据的执行视图。它不能成为新的权威状态。

## 4. 短开环输入包

一个输入包覆盖有限的未来 tick。它至少引用：

- owner、路线、动作和计算身份；
- 绝对 tick 与输入序列；
- 当前允许的身体范围；
- 相关地形和物理依赖；
- 最后可放弃点和承诺点；
- 允许落地区域；
- 下一入口或安全恢复范围；
- 当前仍可能成立的输入时序分支。

输入包不能只在唯一位置、唯一 tick 或容差边缘成立。包长和余量由后续 Windows 量尺决定。

候选输入时序沿用 D099：整包按时开始，或整体晚一 tick 开始。第一条实际回执到达后，只保留真实分支。包中间单条命令晚到、缺失或内容不同属于偏离，不能继续沿用旧证明。

## 5. 逐 tick 监视

每个客户端 tick 只做有界、便宜的检查：

- owner 和 tick 是否连续；
- 实际输入是否属于当前包及真实时序分支；
- 身体是否仍位于允许范围；
- 当前支撑和姿态是否满足最小条件；
- 实际相关依赖是否发生变化；
- 是否收到伤害、爆炸、活塞、流体或属性变化等直接事件；
- 输入无法解释的残差是否超过门槛；
- 是否到达关键节点。

稳态检查以数值范围、集合相交、身份和版本比较为主。它不每 tick 搜索新动作，也不重新计算全部停车尾迹。

监视必须和仍然存活的允许范围比较。只比较“上一观察加实际输入”的一步预测没有意义，因为确定性模拟器中两者天然一致，无法发现身体已经离开原安全范围。

## 6. 偏离判断

偏离判断是一个纯判断过程。它不发送输入，不拥有身体，也不改变任务状态。

### 6.1 判断依据

每次只检查三项：

1. 当前身体是否处于已知安全区域；
2. 原路线后段是否仍有效且能从当前状态接入；
3. 当前是否处于可放弃阶段，还是已经承诺。

### 6.2 结果

| 结果 | 含义 | 后续处理 |
|---|---|---|
| `CONTINUE` | 仍在当前允许范围 | 当前控制器继续输入包 |
| `RECONNECT` | 地面安全，能够接回原路线 | 当前地面控制器消费短期接回目标 |
| `REPLAN_AHEAD` | 当前安全，原后段不能继续 | 保留安全前段，后台规划替代路线 |
| `EVADE_HAZARD` | 当前运动趋势正在接近危险 | 当前地面控制器消费远离危险的短期目标 |
| `COMMITTED_RECOVERY` | 已承诺或处于空中 | 原严格动作 owner 负责安全落地或收尾 |
| `HAND_TO_TASK` | 现有能力无法证明安全处理 | 身体安全释放后交任务层选择其他办法 |

这些名称描述处理方式，不代表需要在 `NavigationSession` 中增加六个状态。实现可以使用一次性有类型结果，通过现有控制器和监督者推进。

## 7. 安全区域内的局部接回

局部接回从原路线前方选择一个仍可到达的位置或入口范围。选择时按以下顺序：

1. 跳过身体已经越过的路线点；
2. 保留整体前进方向；
3. 优先选择不要求降到静止的入口；
4. 检查从当前身体到接回位置的已知支撑、净空和可停车性；
5. 使用现有有限地面候选产生下一帧输入。

接回目标只包含短期需要：区域、方向、速度范围、期限和依赖。它不拥有身体，也不替代正式路线。身体重新进入原路线允许范围后，接回目标立即结束。

可用的原路线后段继续复用。只有局部接回无法在有界时间内完成，或后段已经失效时，才请求完整重规划。

宽阔安全区域内，接回不得默认发中性输入、回到偏离点或回到格子中心。必要的小幅横移、转向、加速和减速应在前进中完成。

## 8. 危险规避

危险规避针对“身体仍可控制，但当前速度正在把身体带向危险”的情况。典型例子是被实体推向坑边。

规避目标首先要求短期风险降低：

- 预计支撑比例增加，或离危险边界更远；
- 不进入 UNKNOWN、伤害区或不支持的碰撞环境；
- 尽量保留任务的大方向和已有速度；
- 能重新进入原路线时直接接回。

原地松键只有在其完整尾迹已知安全时才可使用。不能因为“停车比较保守”就在惯性会继续把身体带向坑时松开输入。

规避目标仍交给现有地面控制器。没有单独的避险输入写入者。无法找到安全候选时，按已有严格收尾或任务层决策处理。

## 9. 世界变化和外力

### 9.1 世界变化

`changed_cells` 先与当前路线、输入包和严格动作依赖求交集：

- 无关变化直接忽略；
- 后续路线受影响但当前身体安全时，继续安全前段并后台重规划；
- 即将经过的支撑、净空、边缘或落地区变化时，作废受影响部分；
- 当前脚下或停止尾迹出现危险时，进入危险规避或严格收尾。

路线后段是否有效按实际受影响范围判断，不因世界全局修订就清空整条路线。

### 9.2 外力

伤害、爆炸、活塞和其他明确事件优先触发检查。没有直接事件，但输入账本无法解释观察位移时，使用运动残差补漏。

外力本身不决定处理结果：

- 在宽平台上被侧推，通常局部接回；
- 被推向坑边，先危险规避；
- 被推到空中，原 owner 或现有身体恢复链负责落地；
- 落地后仍安全，再接回或重新规划。

## 10. 关键节点和承诺后恢复

以下节点保留严格检查：

- 进入动作入口；
- 最后可安全放弃点；
- 起跳、离边或下落提交前；
- 承诺输入实际生效后；
- 进入落地区；
- 着地确认；
- 向下一动作交接。

承诺前缺证据时，不提交不可撤销输入。承诺后发生偏离时，原 owner 继续负责身体。

恢复的第一目标是进入安全、可交接的身体状态。它可以落在任务目标之外，也可以不满足下一动作的理想入口。落地后再按当前真实状态选择局部接回或任务重规划。

## 11. 连续跳跃和跨隙

连续动作使用安全落地区域和下一动作入口范围，不使用唯一落点。

第一跳落到宽平台但位置偏离时：

1. 若仍满足第二跳入口，直接继续；
2. 若可在运动中进入入口，生成局部接回目标并保持速度；
3. 若平台安全但第二跳暂时不可用，继续安全地面控制并后台准备；
4. 若落点接近危险，先规避危险；
5. 只有入口明确要求低速或没有安全接续时，才停车。

前一动作只读取下一入口范围，不增加 JumpGap→JumpGap、JumpGap→JumpUp 等组合判断。新增动作也必须通过同一入口和责任契约接入。

## 12. 模块职责

| 模块 | 新设计中的职责 | 不能承担的职责 |
|---|---|---|
| 地面控制器 | 执行原路线、局部接回和危险规避的短期目标 | 不拥有任务重试，不判断动作组合 |
| 严格动作控制器 | 执行已验证输入和承诺后安全收尾 | 不把安全落地当成任务完成 |
| 动作执行器／协调器 | 管理动作顺序、准备、入口和同路线交接 | 不另建偏离状态机 |
| 路线复核 | 判断相关变化影响了哪一部分 | 不因无关变化停止整条路线 |
| 执行监督者 | 保持唯一身体 owner，处理正式交接 | 不生成地面按键或局部路线 |
| Session | 处理完整重规划、任务目标和最终结果 | 不增加动作组合或偏离原因专用分支 |
| Runtime／输入出口 | 仲裁、发送并记录真实应用 | 不替代控制器选择恢复目标 |

## 13. 性能边界

稳态 tick 的目标是常数时间判断：不做全局规划，不枚举动作序列，不完整重放整段轨迹。

局部接回和危险规避只比较现有有限地面候选。复杂规划和严格重证进入现有后台工作。后台结果未及时到达时，当前 owner 继续已有安全前段或已证明收尾，不能把未完成结果当成输入许可。

正式性能以 Windows 为准。后续计划必须分别记录：

- 稳态监视；
- 局部接回；
- 危险规避；
- 关键节点检查；
- 后台重算和交付延迟；
- 完整控制路径。

平均成本不能掩盖关键 tick 的长尾。具体数值由实施计划在基线测量后冻结。

## 14. 验收原则

### 14.1 安全不变量

- 无 owner 输入为零；
- UNKNOWN 当可通行为零；
- 任务伤害额度超出为零；
- 承诺后直接释放身体为零；
- 相关变化后继续使用失效严格依据为零；
- 输入包中间出现未允许晚到时继续冒充旧时序为零。

### 14.2 连续性

- 宽阔安全区域中的位置、速度和落点偏差不会引起非必要完整停车；
- 可局部接回时，不返回偏离点或格子中心；
- 连续动作落地到下一段有效输入的空档有明确上限；
- 下一入口允许带速时，交接不得强制降到静止；
- 没有任务需要的反向输入、折返和等待应计为质量失败。

### 14.3 代表场景

验收至少覆盖：

- 宽平台横向偏离；
- 宽平台非理想落点；
- 无关与相关世界变化；
- 前方突然出现坑；
- 宽平台侧推和坑边侧推；
- 空中目标修订和输入缺失；
- 两次连续跨隙；
- 跨隙后转向或进入下一高度动作；
- 高危窄路由任务层拒绝或改道。

场景按规则代表性选择，不把原因、阶段和动作做无界全排列。发现缺陷时先判断它是否违反共同规则；不得只为单个案例增加专用分支。

## 15. 当前边界

这份架构只冻结方向和职责。它没有实现短输入包、偏离判断、局部接回或危险规避，没有修改正式 Runtime，也没有运行 Fabric。

D098 的 P3 仍然失败，原数字和证据不改写。后续实施必须另写阶段计划和验收文档，先在 Windows 正式量尺中验证共同规则，再决定正式链接入顺序。
