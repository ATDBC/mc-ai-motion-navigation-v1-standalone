# B02 世界知识与几何核心

日期：2026-09-18
状态：B02 已验收

## 格子知识

每个位置只有下面三种对导航有效的状态：

| 状态 | 怎样产生 | 含义 |
|---|---|---|
| 未知 | 没有合法事实 | 不能当作空气或障碍 |
| 已知空气 | 按需空气确认返回正例，或角色身体碰撞盒实际占据该格 | 该格没有方块碰撞体，也不提供支撑 |
| 已知方块 | `pre-floating-7ab0b35f` 的合法可见方块事实 | 使用实际碰撞形状和介质属性 |

没有看见方块不等于空气。空气查询没有返回某个位置时，该位置继续未知。

角色能直接感知身体所在空间和脚下支撑。Fabric 客户端因此把身体碰撞盒实际占据的格子，以及身体周围 0.05 格容差内真正接触的方块或流体，统一标记为 `body_contact`。身体所在格即使是空气也会导出；更深的地下格和附近未接触格不会因此暴露。

## 时间与世界会话

- 长度使用格，连续时间使用秒，控制进程时间戳使用纳秒，角度使用弧度。
- 世界 tick、控制进程单调时间和客户端采样时间分开保存。
- 只有同一世界会话、同一时钟的时间才能相减。
- 世界重置、重连或明确重锚定产生新的世界会话。旧事实不能写入新会话。

`NavigationObservationAdapter` 是正式观察进入运动系统的唯一 B02 入口。它接收 Observation V3，并输出同一种 `NavigationFrame`。世界会话由后端、episode 和客户端 JVM 时钟共同确定。新会话出现时，旧会话立即退休；旧帧不能再次写回。

B02 的 Observation V3 还没有维度标识。进入下界、末地等新维度前，运行时必须先开启新 episode，不能在同一会话里继续写事实。以后若要支持不中断的跨维度任务，应先把维度加入正式观察契约，再改变这条规则。

身体位置使用格，速度在适配时从 Minecraft 的“格/tick”换算为“格/秒”，角度从度换算为弧度。身体包围盒由位置和姿态统一生成。独立 Fabric 已完成实机验收；CraftGround 目前只通过同一契约和适配器测试，不属于 B02 实机门槛。

## 按需空气确认

几何查询先返回缺失信息的位置集合。调用方去重后，通过 Observation V3 一次提交整组位置。协议每次最多接受 512 格且整个请求不能超过 16 KiB；当前运行适配器默认每帧提交 128 格，其余位置延后。客户端只返回 32 格范围内确认为空气的正例。固体不会从这个接口泄露；没有返回的位置仍然未知。

正例写入当前世界会话后，后续几何查询不会再把它报告为缺失信息。调用方因此无需重复查询。方块观察或更新更晚的空气事实可以替换旧事实；世界会话变化会整体隔离旧缓存。

未知位置查询失败后，运行适配器至少等待 5 个世界 tick 才允许重试，避免控制器逐帧提交同一个未知格。后续合法方块或空气事实到达时会清除该位置的重试记录。当前 Observation V3 没有提供视野外世界变化通知，因此机器人不会凭隐藏变化主动清除历史；真正观察到变化后，较新的事实会按顺序替换旧事实。

## 统一几何结果

支撑与扫掠统一使用四种结果：

- `FEASIBLE`：现有事实足以确认；
- `BLOCKED`：已知几何明确阻挡或没有支撑；
- `NEEDS_INFORMATION`：缺少相关格子的事实；
- `UNSUPPORTED`：碰撞形状或运动模式尚未支持。

扫掠检查整段连续运动，不只检查起点和终点。支撑查询返回实际接触面积和比例；是否额外要求安全余量，由后续能力配置决定。

墙边和坑边的“弹性缓冲”不属于几何真值。B02 只报告第一次碰撞位置、实际支撑面积、支撑比例和缺失信息。B03 的局部跟踪器再根据速度、制动距离和风险设置缓冲，避免规划、几何和控制各自维护一套余量。

## 普通地面预测

地面预测使用显式配置的控制周期、加速度、每 tick 速度保留率、最高速度和已经验证的支撑材质。模型只处理普通步行，不覆盖疾跑、潜行、跳跃、碰撞、液体、空中运动或未校准地面。接受的参数保存在 `config/motion-navigation/ordinary-ground-v1.json`。

模型同时提供相机相对输入与世界 X/Z 方向的双向换算。水平行走只依赖 yaw，不受 pitch 影响。因此 B03 可以在任意俯仰视角下沿同一条世界路线直行，而不必复制不同视角的控制逻辑。
