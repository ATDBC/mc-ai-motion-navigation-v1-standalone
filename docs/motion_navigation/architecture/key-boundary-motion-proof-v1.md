# 关键边界运动证明 v1

> 2026-10-13 后注：本设计对应的 D104 实现已在 K1 停止。新的可靠稀疏规则见[可靠稀疏运动证明 v1](sound-sparse-motion-proof-v1.md)。

状态：设计冻结，尚未完成正式验收。决定见 [D104](../decisions/0104-slim-motion-proofs-before-continuity.md)。

## 1. 证明回答什么

证明只回答两件事：当前输入是否仍在已验证范围内，以及身体在不能随时停车的阶段由谁负责。它不负责重新搜索路线，也不把每个 tick 都变成一份完整停车证明。

每条时序分支包含一串确定输入、一条用于逐 tick 廉价比较的主轨迹、动态关键节点、关键节点上的安全尾迹，以及风险区间、伤害和世界依赖。

## 2. 动态关键节点

设主轨迹边界为 `0..N`。实现先按输入回放主轨迹，再用正式支撑查询和安全尾迹求关键节点。

单个风险区间记录：

- `last_abandon_boundary`：最后一个还能执行安全尾迹并留在安全支撑上的边界；
- `commitment_boundary`：下一条命令开始不可随意放弃；
- `recovered_boundary`：重新进入安全支撑且重新具备安全停车能力的第一个边界。

比较节点为入口、最后可放弃、承诺、恢复和终点。安全尾迹节点为入口、最后可放弃、恢复和终点。索引去重后必须严格递增。

没有风险区间时，只保留入口和终点。v1 遇到多个风险区间时返回有类型的不支持结果，不把两个区间合并。

## 3. 输入流时序

输入流开始时可以有“按时”与“整体晚一 tick”两个分支。首条实际应用回执到达后，执行器立即选择唯一分支并丢弃另一个分支。

后续命令单独晚到、丢失或内容改变都算偏离。执行器不能把每个短包重新解释成一条新的 0／1 tick 输入流。

## 4. 执行与偏离

正常执行每 tick 比较 generation、owner、输入流身份、状态范围、世界依赖和时序分支。这些操作以字段比较、版本比较和范围判断为主。

承诺前偏离时，停止提交新的不可撤回输入，并执行仍覆盖当前真实状态的安全尾迹。承诺后偏离时，原 owner 继续承担责任，优先完成已证明的落地／恢复段。恢复后再从真实状态重规划。

## 5. 安全尾迹

安全尾迹保存输入、起点状态、终点状态、伤害、依赖和自己的长度上限。它不保存全部中间状态。

执行前必须核对真实状态、generation、owner、窗口、伤害余额和依赖，并在声明的最大 tick 内有界回放，最后核对安全支撑和伤害条件。长度不能硬编码为 9 tick。

## 6. 连续动作

下一个动作可以在当前动作运行时后台准备。若落地后存在安全停车点，监督者可以在交接窗口内选择继续或停车。

若两个动作之间没有安全停车点，两个动作合成一个承诺段。后一个动作通过入口契约声明是否需要落地即起跳。它的输入必须提前准备；落地观察只做事后核对。核对失败后仍由原 owner 负责恢复。

## 7. receiver 与快照

worker 是受信任的本地进程。receiver 只核对消息边界、父侧身份、当前权威事实和依赖版本。完整物理等价、依赖收集完整性和对象不可变性由构造端测试、属性测试和离线审计验证。

局部快照是 detached 值。边界由动作模板最大包络决定，超界查询返回 `NEEDS_WORLD`。登记对象只保留紧凑输入、主轨迹、关键节点、尾迹输入和依赖版本。

candidate、executing、safe-tail 三种身体责任用途保持不变。简化快照生命周期不能删除执行责任。

## 8. 性能边界

控制线程禁止无界搜索、整份证明、整图快照和完整对象图复核。允许有物理步数上限的短预测和尾迹回放。

Windows 完整决定继续要求 P95≤8 ms、P99≤15 ms、最大值<30 ms。每 tick 物理步上限先测量再冻结，不能从 Linux 折算，也不能先写一个方便通过的常数。
