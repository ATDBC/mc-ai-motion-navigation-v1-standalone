# 连续动作控制器、离线表与增量证明验收

日期：2026-10-10。状态：M0 未通过，M1—M4 未开始。

## 1. 证据分层

| 证据 | 能说明什么 | 不能说明什么 |
|---|---|---|
| M0 成本探针 | Windows 上继续原型是否经济 | 增量证明已经实现 |
| M1 离线表 | 参数覆盖和入口／出口关系 | 当前真实命令安全 |
| M2 组件与变异 | 增量证明安全语义和性能 | 正式链能连续执行 |
| M3 闭环 | 正式调用链中的连续性和恢复 | Fabric 与真实服务端一致 |
| M4 Fabric | 冻结实机场景结果 | 未声明动作和任意地形能力 |

## 2. M0 冻结矩阵

正例沿用 R2 的 22 项，并增加混合动作元反例。至少包含：平地 Walk、疾跑、90° 转向、直线上一格、转弯后上一格、一至三格跨隙、转弯后连续出口和跨隙连续出口。

负例至少包含：A3 无法完成三格跨隙、1／12 支撑、未知落点、条件资源、碰撞和极小预算。极小预算只检查计数器分类，不计入无解成本。

M0 报告有模板高度限制和无该限制两份结果。前者只能用于模板可行性，不能冒充一般安全剪枝；后者用于暴露真实负例成本。

## 3. M1 抽样

每个入口分箱保存样本总数、完成数、失败分类、最坏伤害、出口状态分布和证明哈希。训练与验证种子分开冻结。

99%门槛的分母包括所有预先登记的有效入口。运行后失败不能改分箱或移出分母。表外入口单列为未支持。

## 4. M2 必须为零的违规

- UNKNOWN 被当成可通行；
- 只证明一个时序分支；
- 提交与许可不一致的输入；
- 承诺后更换未证明输入或释放身体；
- 过期锚点、目标、依赖或版本仍被接纳；
- 超过任务伤害额度；
- 表项扩大原目标、入口或出口；
- 预算耗尽被写成不可达。

## 5. 完整扫描对照

冻结计划上逐项比较：结果类型、最后可放弃边界、首个承诺边界、恢复边界、风险区间、两支退出状态、必要依赖、预计伤害和目标／出口判断。

增量方法可以少算未执行边界，但不能得到比完整扫描更宽的执行许可。

## 6. 性能

M0 只保存可行性数字。M2 才形成正式性能结论。

| 指标 | M0参考 | M2／M3正式门槛 |
|---|---:|---:|
| 单次增量证明 P95 | 预计≤10 ms | 单列报告，并使完整控制P95≤8 ms |
| 动作开始 rollout P95 | 预计≤15 ms | 不阻塞完整控制路径 |
| 完整控制 P95／P99／最大值 | 不签署 | ≤8／15／30 ms |

墙钟不进入行为决定。每个分位数写明样本对象、样本数和计算方法，不平均各批次的 P99。

## 7. M0 Windows 正式结果

仓库内量尺没有从三方 `reviews/` 导入代码。正式判断关闭模板高度截断，并且只允许两支时序都着地时起跳；带高度截断版本只作诊断。每个场景预热 3 轮、正式运行 20 轮。墙钟只写入报告，不参与控制器输入、枚举或结果分类。

冻结集合包含 22 个原正例、6 个负例和 1 个混合动作元反例。两次正式采集的分类、输入哈希和 physics step 都确定；`PYTHONHASHSEED=1／77／991` 结果一致。

| 门槛 | 第一次 | 第二次 | 最终模块入口复跑 | 结论 |
|---|---:|---:|---:|---|
| 正例和负例分类 | 全部符合 | 全部符合 | 全部符合 | 通过 |
| 正例最大耗时≤400 ms | 587.9058 ms | 591.1611 ms | 736.8842 ms | **未通过** |
| 有意义负例最大耗时≤800 ms | 593.8242 ms | 745.7609 ms | 744.7585 ms | 通过 |
| lazy 单次证明估算 P95≤10 ms | 2.2131 ms | 2.7462 ms | 2.7390 ms | 通过，仅为估算 |
| 已知输入 rollout P95≤15 ms | 4.6591 ms | 5.7815 ms | 5.7393 ms | 通过 |
| 哈希种子不改变结果 | 一致 | 一致 | 一致 | 通过 |

超限项不是单次调度尖峰。三轮中该反例都固定使用 10,056 次 physics step。最终模块入口复跑的 P50／P95／最大值为 733.5156／735.3165／736.8842 ms；即使取机器较快时的第一轮，最大值仍为 587.9058 ms。第二轮中，除该新增反例外的 22 个原正例最慢为 `flat_sprint` 的 256.3196 ms。失败说明这个精确混合入口仍需要昂贵的参数枚举；不能用原矩阵通过来签署 M0。

`controller_ms` 包含每次调用重新构造冻结夹具和世界快照的时间。独立复核测得这部分约为 26—31 ms；缓存夹具后，混合动作元反例仍约为 556—695 ms，继续明显超过 400 ms。M0 原始 JSON 不扣除这段成本，因为正式量尺冻结的是完整探针调用；即使单列夹具构造，停止结论也不变。

已知输入的完整扫描成本为 161—843 physics step。拆出的单边界停车尾迹为 16—38 step，承诺恢复为 0—16 step。后两项仍是从完整证明拆出的估算，没有实现 M2 增量证明，也没有授予任何执行许可。

`tiny_budget` 在 M0 探针里是直接分类：发现冻结请求的 physics step 上限为 1 后，直接返回 `BUDGET_EXHAUSTED`。它只保护“极小预算不进入无解成本统计”的口径，没有在 M0 中重新执行 `CountedPhysics` 的真实 `PHYSICS_STEP_BUDGET` 耗尽路径。该计数器路径继续由旧 TP 94 项冻结回归覆盖，不能把 M0 的这一行写成新的独立计数器证据。

因此 M0 未通过，D097 停止于 M0。M1 控制器与离线表、M2 增量证明、M3 正式链适配和 M4 Fabric 均未开始。`mc2p` 没有修改。
