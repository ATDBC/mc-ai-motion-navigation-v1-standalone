# B10-A 验收结果：在线状态、输入投影与计算预算

日期：2026-09-21
结论：通过，可以开始 B10-B 的限定单动作求解

## 验收范围

本轮只验收状态锚点、真实输入应用账本、命令投影、固定输入物理对照和计算预算。没有启用自动求解，也没有让新链路取得真实输入控制权。

实机产物位于：

`artifacts/fabric-deployment/20260921T092838990780Z-a17b670a`

该产物运行的是 B09 已发布控制器。B10-A 只增加逐 tick 输入应用证据，因此可以核对现有命令、真实采样输入和物理结果是否属于同一次执行。

## 输入链结果

`scripts/validate_b10_input_chain.py` 对实机轨迹进行了三方核对：

| 项目 | 结果 |
|---|---:|
| 正式命令 | 1511 条 |
| 真实输入应用 | 1555 个玩家运动 tick |
| 物理 tick 记录 | 1555 个 |
| 命令、输入、物理或归属不一致 | 0 |
| 命令到首次应用的 tick 延迟 P50／P95／P99 | 1／1／1 tick |
| 最大延迟 | 7 tick |

最大值出现在场景切换或长间隔处，不代表所有候选都可继续执行。以后接纳候选时仍须检查自己的执行窗口，不能用总体 P99 替代逐候选判断。

部署轨迹共有 1510 个正式运行步骤。修正验收器的 V3 回执兼容后，动作关联、观察连续性、零图像和独立客户端检查全部通过。最初实机命令返回失败，是旧验收器只读取 V2 回执造成的；动作场景本身、清理和物理证据没有失败。该问题由 V3 回归测试覆盖。

## 固定输入物理对照

同一实机产物包含 80 次空中动作试验，其中同高一格跨隙四方向各 10 次，受控下降四方向各 10 次。全部完成，没有水平碰撞或错误落层。

将 1555 个实机物理 tick 交给 B09-R 重新计算，结果如下：

| 项目 | 结果 |
|---|---:|
| 单 tick 完整记录 | 1555／1555 |
| 单 tick 事件不一致 | 0 |
| 单 tick 最大位置误差 | 1.32×10⁻⁸ 格 |
| 连续序列 | 115 段 |
| 连续序列问题／发散 | 0／0 |
| 连续预测最大位置误差 | 5.45×10⁻⁷ 格 |

这证明固定命令经过真实输入采样后，可以由当前 B09-R 规则连续复算。它不证明自动求解器已经能找到这些命令。

## 计算预算

基准在当前 Windows 机器上运行 50 次。每个 tick 都包含命令投影和完整 B09-R `step`：

| 范围 | 稳态墙钟 P50 | P95 | P99／最大值 |
|---|---:|---:|---:|
| 1 tick，1 个候选 | 0.063 ms | 0.066 ms | 0.069 ms |
| 20 tick，1 个候选 | 1.342 ms | 1.357 ms | 1.402 ms |
| 60 tick，1 个候选 | 4.033 ms | 4.066 ms | 4.129 ms |
| 20 tick，8 个候选 | 10.609 ms | 10.631 ms | 10.631 ms |
| 20 tick，32 个候选 | 42.515 ms | 42.758 ms | 42.758 ms |

首次 20 tick 计算耗时 1.549 ms。Windows 的当前线程 CPU 计时分辨率约为 15.625 ms，因此小样本 CPU 数值只用于判断量级，墙钟结果作为本轮预算依据。

结论是：单候选和 60 tick 预测足够便宜；32 个候选不能塞进控制帧。B10-B 必须在后台按明确预算分批搜索，并让控制循环继续执行已有安全前段。

现有 B09 控制器在这轮实机中的计算耗时为 P95 4.081 ms、P99 4.673 ms、最大 4.800 ms，仍满足现有控制帧门槛。
