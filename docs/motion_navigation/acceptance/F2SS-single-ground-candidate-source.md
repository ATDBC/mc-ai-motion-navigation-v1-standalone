# F2-SS 普通地面候选单一事实源验收

日期：2026-10-08。状态：已运行到 v8；发现三项历史成功退步后按 fail-fast 暂停，阶段尚未通过。

本验收回答五个问题：十八项候选是否只有一份物理结果，质量层是否停止自行推演，预算不完整时是否拒绝选择，正式接线是否满足控制期限，以及统一后能否恢复 F2-WR 的历史行为。

## 2. 十八项逐项 oracle

每个正式输入帧的报告必须恰好包含：

- 九种 `(forward, strafe)`；
- 每种一 tick和两 tick许可；
- 合计十八个不同身份；
- 顺序固定为 `CLOSED_GROUND_MOVEMENTS`，每个方向内先一 tick、再两 tick。

逐项比较正式 1.21 oracle：

1. typed 状态；
2. `tracking_end`；
3. `stopped_end`；
4. 前缀轨迹；
5. 中性停止轨迹；
6. 最低支撑与姿态／模式；
7. 世界依赖和缺失事实；
8. 验证路径。

数值容差沿用运动计算器现行差分门槛。候选输入顺序打乱、字典插入顺序改变或评分改变后，按候选身份比较的结果必须一致。

错误副本至少覆盖：漏掉一个许可长度、交换两个终点、漏掉尾迹依赖、只保存最终位置、按完成先后输出。每个错误副本都必须使检查失败。

## 3. 唯一调用与旧入口退出

对每个实际进入普通 `STANDING + WALK` 候选决策的正式帧断言：

- `GroundCandidateVerifier` 调用次数等于 `1`；
- family 报告数量等于 `1`；
- 报告包含十八项；
- `GroundTrackingPolicy` 的物理 step 和世界查询次数等于 `0`；
- 普通 Walk 旧 rollout、evaluate、safe-tail 和 replay 入口次数等于 `0`；
- `FixedRoute` 不在报告外重新计算 `tracking_end`、`stopped_end` 或依赖。

不进入普通候选决策的帧可以是 `0` 次。严格动作不能为了满足计数而绕进普通验证器。

下面两个错误副本必须被调用计数发现：同帧分别验证普通行走和制动；新报告不完整时退回旧简化候选。

## 4. 报告完整性与预算

family 只有两种可供调用方解释的整体状态：

- `COMPLETE`：十八项都有 typed 终态；
- `BUDGET_EXHAUSTED`：至少一项尚未得出结论。

`BUDGET_EXHAUSTED` 时：

- `eligible_candidates` 必须为空；
- 已完成的方向候选不能参与质量排序；
- 不能发送一个“目前看来最好”的方向输入；
- 中性输入只有在它自己的完整停止轨迹已经证明安全时才可沿现有规则使用；
- 调用方有界退出，不新建等待或重试。

分别在第 `1`、`9`、`17` 和 `18` 项后耗尽预算，结果都必须满足同一规则。墙钟速度不能改变已公开候选集合。

## 5. `tracking_end`、`stopped_end` 与依赖

对一 tick、两 tick、晚到和部分生效分别断言：

- 名义路线只推进到 `tracking_end`；
- completion 和路线质量读取报告字段，不重新 rollout；
- `stopped_end` 不冒充现实身体或下一帧起点；
- 获胜项的前缀和尾迹依赖在 D084 的证明时域内持有；
- 相关变化使旧资格失效，无关变化不影响资格；
- 新正式观察与实际输入账本重新锚定。

交换两个终点、只登记前缀依赖、许可结束就提前释放尾迹依赖的错误副本必须失败。

## 6. 质量层职责

给定同一份完整报告，`GroundTrackingPolicy` 只能改变：

- `control_prefix_inside`；
- `neutral_tail_inside`；
- 进展、偏差和 completion 距离；
- 现有质量排序；
- typed 获胜候选或无候选结果。

它不能改变候选的世界安全状态、轨迹、终点和依赖。

改变 corridor、completion 或评分时，世界安全集合必须逐项不变。改变世界事实时，必须先由验证器生成新报告；质量层不能自己补查格子或重新推演。

任一层失败即停。失败必须保留，不把有界失败、预算耗尽或拒绝改记成完成。

## 8. Windows 性能门槛

Windows 是正式平台。正式接线后先运行代表最坏普通地面场景，分别报告：

- 验证器总耗时；
- 公共前缀、普通内核和正式计算器回退；
- 路线／completion 质量计算；
- 依赖合并；
- 完整生产控制帧。

门槛为：

- 生产控制 P95 `≤8 ms`；
- P99 `≤15 ms`；
- 最大值 `<30 ms`；
- deadline miss `0`；
- 正式普通候选帧的验证器调用数恒为 `1`。

首次失败后最多做一轮语义不变的低风险优化。优化后仍失败，本阶段立即停止，不运行 remaining42、大集合、D061 或 Fabric。

D061 另保持完整夹具最大值 `<50 ms`。模拟后端时间与生产时间分开报告，不用相减得到生产耗时。

## 9. 严格动作负对照

Sprint、Sneak／探边、Crawl、Swim、Climb、JumpGap、JumpUp、ControlledDrop、离地和连续高度严格入口继续使用原证明链。

至少断言：

- 严格动作不会生成十八项普通候选；
- 普通验证报告不能授权跳跃、下落或姿态转换；
- 严格动作的生效窗口、落地责任和伤害额度不变；
- 普通 Walk 的旧入口退出不会删除严格动作仍需的函数。

## 10. A* 边界

F2-SS 验收不运行“每个 A* 节点十八项候选”的实现。测试要证明当前大图搜索没有新增验证器调用。

后续 terminal rollout 若复用核心，必须单独统计调用点和节点数。它只允许作用于少量终点状态，不得让全图展开成本随十八项候选成倍增长。

## 11. Fabric 正式证据

Fabric 证据必须来自正式调用链，并能逐帧对应：

- 唯一验证器报告；
- 十八项候选身份和 typed 结果；
- 获胜候选的 `tracking_end` 与 `stopped_end`；
- 路线质量、completion 距离和依赖窗口；
- 命令提交、实际生效 tick、重锚定和身体 owner。

场景至少覆盖开阔地、拐弯、墙边、坑边、支撑边缘、危险材质、UNKNOWN、terminal 修正、晚到、丢失、目标／路线修订和一个严格动作负对照。

## 12. 关闭判定

只有第 2—11 节全部通过，F2-SS 才能关闭。

通过表示普通地面候选的物理状态和世界依赖只有一个正式来源。它不自动关闭 F2-WR、F2-CV、F2-SC、F2-GP、F2-SG、F2-S 或路线优化器。F2-WR 的旧失败仍保留在原验收和证据目录中。

## 16. 三项退步的根因边界

三项失败的共同点是 completion 很窄。正式物理报告判定十八项候选的世界安全均成立，但当前身体或完整停止点略微越过 completion：

| 场景 | 最终坐标 | completion 对应边界 | 超出距离 |
|---|---:|---:|---:|
| `0.1/7/22/product` | `x=2.007312` | `max_x=2.0` | `0.007312` |
| `0.2/1/18/product` | `x=-0.022946` | `min_x=0.0` | `0.022946` |
| `0.2/8/22/product` | `x=-3.006081` | `min_x=-3.0` | `0.006081` |

第一项还证明了另一个限制：身体在区域内时速度约为 `0.1127` 格／秒；一 tick反向输入可把速度降到约 `0.0616` 格／秒，但位置已经越出约 `0.0042` 格。完全停稳后，一 tick离散按键又会移动约 `0.098` 格，远大于需要修正的距离。

这说明旧简化模型记录的成功可能是假阳性。它没有证明正式 1.21 物理下的身体最终停在 completion 内。本轮尝试过“速度或停车距离改善即可继续”的测试先行试验；三项只延后失败，没有恢复完成，因此试验和对应测试都已撤销。

该问题超出 D085 的授权范围。继续修正会涉及 completion 语义、控制分辨率或规划目标选择。当前不能扩大区域、调权重、增加候选，也不能恢复第二套简化模型。

## 17. fail-fast 停止范围

## 18. F2-TS 交接边界

三个退步已经作为 [F2-TS 验收](F2TS-bounded-ground-terminal-sequences.md)的正式 oracle 冻结。新阶段必须先通过与三例分开的 holdout、删除模板变异和 Windows 性能门槛，之后才可运行这三例。

F2-TS 若通过，只能说明窄 completion 有了正式 1.21 物理下的多 tick解。F2-SS 仍要继续完成本文件第 17 节没有运行的集合，才能单独签署。任何后续结果都不能改写本节保存的 `0/3` 当前结果和 fail-fast 停止位置。
