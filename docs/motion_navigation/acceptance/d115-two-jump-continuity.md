- 同位姿迟到传送不能提前结束等待；

- 组件与 Fabric 的 trial builder、summary 和等待帧定义相同；
- 场景帧数上限不能计作安全终态。

### 2.2 交付估计

- 新 SOLVE 重建当前动作估计；
- 当前动作的 REVALIDATE 只上调；
- 无效、重复或过期结果不改变估计；
- D113 180 项抖动不退步；
- 多动作路线的后续动作不继承旧动作的额外等待。

### 2.3 连续两跳

- 第一跳空中提交第二跳准备；
- 准备及时且入口匹配时，第一跳落地 `L` 到第二跳首条实际输入不超过 1 tick；
- 两跳之间无完整停车、无 owner 空档、route 不变化；
- 迟到、失联、依赖变化和取消都不盲目启动第二跳；
- 全部场景零伤害、零 UNKNOWN 放行、零旧 generation 应用、零来源泄漏；
- 控制准备与交接 tick 满足 P95≤8 ms、P99≤15 ms、最大值<30 ms；

### 3.3 连续两跳停止结果

正式代表链生成 `WalkSegment -> JumpGapSegment -> JumpGapSegment`，零伤害。第二跳没有开始，最终状态为 `executing/prepared_action_boundary`。

关键事实：

| movement tick | 事实 |
|---:|---|
| 8 | 第一跳输入实际应用 |
| 12 | 第二跳证明登记；请求窗口 21—22 |
| 19 | 第一跳着地 |
| 20 | 真实身体与准备入口精确相同，但本控制循环尚未发布动作边界 |
| 21 | 边界已经可见，身体却已继续前移，入口比较为 `ENTRY_MISMATCH` |
| 22 | 准备证明过期 |

根因是同一控制循环的顺序：Session 先请求交接批准，执行器随后才发布 `boundary_reached`。修复必须改变 Session／监督者／执行器之间的同帧协议，超出本轮允许的协调器局部改动。按止损规则，自动准备生产代码和活动 RED 已撤回。

紧凑证据为 `evidence/motion_navigation/d115-two-jump-v1/stop.json`。该文件明确记录：未改生产交接协议、未运行扩大矩阵、未运行 Fabric。
