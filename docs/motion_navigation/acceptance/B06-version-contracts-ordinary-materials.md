## 验收判定

### 环境和证据边界

- 环境文件使用冻结 SHA-256。任何版本或配置内容变化都必须先产生新环境身份，不能继续加载 B06 Profile。
- 组件夹具可以建立有限完整世界；Fabric 正式运行只使用合法观察；测试真值只负责写场景、传送复位和评分，不能向规划器提供隐藏路线。
- B03/B05 的旧 Profile 保留。B06 新 Profile 使用新 ID，并显式绑定环境和地面模型。

### 方块分类

- 普通类必须同时满足已登记注册名、完整碰撞、非流体和当前身体条件。
- 相同普通注册名若出现非完整几何，返回未支持。
- 冰、蜂蜜块、灵魂沙、蛛网、流体、攀爬方块、危险和条件支撑只登记效果，不在 B06 获得执行能力。
- 未登记原版状态和非固定注册表方块返回未支持，不能默认普通化。
- B06 Profile 把方块目录带入 Walk 和 JumpUp。规划扫掠、支撑查询和直接控制检查同一批已知方块，分类结果不再停留在独立测试中。

### 目标、动作和资源

- 目标完成同时检查三维区域、支撑、模式、姿态、终端速度、资源、可选朝向和风险政策。
- 使用 Fabric 静止接地观测中的真实竖直速度 `-1.568 格/秒` 做回放，确认它不会被误判为角色仍在移动。终点补转头期间，取消、输入失联和世界会话变化都会终止旧路线，终态不会随后变回完成。
- 动作路线执行器拒绝用新路线覆盖仍在执行的路线，因此空中的 JumpUp 不会因创建新控制器而丢失落地保护。
- Walk 和 JumpUp 从规划边到路线接纳、动作段都携带同一份 `MovementTransition`。
- 动作转换引用版本化轨迹 Profile，保存世界依赖、资源变化、风险标签、取消和输入失联终态。
- 搜索按时间和相关资源做支配判断。恢复不能超过请求声明的初始容量；剩余资源不能小于零；资源维度缺失时，不能把它当成零值继续执行依赖该资源的动作。
- 带非零资源变化的相邻 Walk 边不合并。路线接纳保留变化顺序，避免容量截断和中途不足被总和掩盖。

## 证据边界

这次实测证明五种完整、非特殊方块可以在固定环境和普通身体条件下共用现有步行与低速一格上升参数。每种材质各运行一次正式步行和一次正式 JumpUp；它不是每种材质的长期统计，也不证明所有完整方块都自动等价。

注册表快照固定的是原版方块身份集合。实际方块状态仍以正式观察提供的几何和状态为准；B06 没有声称穷举 Minecraft 每个属性组合。非完整形状、特殊接触、状态效果、装备条件和资源恢复规则分别留给后续阶段。
