## 4. 统一遮挡规则与实体可见性

正式观察现在声明 `visibility_rules_id=surface_visibility_1_21_v1`。启动记录和每一帧 perception 都会携带这个标识，Python 接收端拒绝缺少标识或标识不一致的 profile 4 观察。

规则门禁覆盖玻璃、染色玻璃、玻璃板、植物、蜘蛛网、铁栏杆、栅栏、活板门、浮冰、蓝冰、树叶、水、熔岩、含水半砖、含水楼梯和隐藏方块。隐藏方块在视觉上按空气处理；身体接触仍能取得其实际事实。

实体按距离使用两种明确写入元数据的判定：

- 16 格内使用 `surface_bbox_exact_16`。实体包围盒与本帧方块共用表面投影，只要有一部分轮廓没有被更近的遮挡面盖住，就算可见。
- 16～32 格使用 `surface_rules_five_point_16_32`。它仍是五点近似，但沿途玻璃、水、熔岩等方块统一按同一张规则表判断。

原生门禁覆盖完整墙后、只露出一部分、玻璃后和超出 16 格四种包围盒。离线 Minecraft 1.21 Java 门禁补充了玻璃、完整石块和熔岩对远距离五点检查的影响。原生 JNI、Fabric Java 构建和 80 项相关 Python／Java 检查均通过。活动实体的最终结果仍要随 B12 实机重跑补证据。

## 5. 单帧视觉空气

正式实现把最多 128 个候选格与方块表面放进同一次原生调用。候选格的中心和八个内缩角点只用于快速拒绝；最终结果仍由完整立方体的投影轮廓与本帧不透明表面作多边形差集决定。目标格只要有一部分在视野外、超过 16 格或被遮挡，就不返回空气。

原生门禁覆盖 500 个固定种子的随机世界，并补充完整方块、半砖、楼梯、多外形盒、栅栏、透明方块、流体、视野边缘和相机贴面。随机对照把候选完整块加入世界，用现有表面深度参考计算它的完整投影面积，再与新接口逐格比较，结果零误判。

## 6. 传输与导航写入

正式发送端不再把 `ClientObservationCollector` 刚生成的 JSON 字节解析成 Gson 对象后再次序列化。新的封装器只序列化会话、回执和诊断字段，并把由同一进程内正式收集器生成的观察对象字节作为一个完整 JSON 值嵌入。独立 Java 门禁验证了引号转义、原始观察字节保持不变，以及非对象载荷被拒绝。

导航适配器为当前世界会话维护最多 4096 种“方块标识、流体状态和碰撞形状”组合。相同组合复用不可变的 `BlockGeometry`，世界切换时清空。每次重看仍刷新 `ObservationStamp` 和证据修订。方块或空气语义变化仍进入 `changed_cells`。变化位置在写入前直接比较，不再在写入完成后逐格重读一次世界。

## 7. 信息视角、动作交接与正式门禁

导航会话只在三个条件同时成立时给出信息视角：会话正在等待缺失格；至少一个缺失格位于当前 120° 视野外；当前帧没有战斗视角。信息视角使用 `BEHAVIOR` 优先级，单帧最多转 36°。缺失格已经在视野内时，系统把它视为当前站位受遮挡，不在原地重复转头。本阶段仍不包含观察站位搜索。

D034 的三个控制边界已经补齐：普通步行在同一帧切换为台阶或空中动作时，撤回已经准备好的战斗视角；目标更新期间跨过追击期限时安全交给任务层；有路线动作记录时，回放使用动作原因，不再用外层会话原因覆盖。B10 的滑行阶段现在读取客户端实际输入；若本应自由下落时出现非中性输入，执行器转入局部恢复并继续负责落地。

公开导出清单不再单独携带已退役、且缺少整套旧依赖的目标驱动和跟随可视化入口。仍在现行包内的回放工具改用当前证据接口，并同时支持包内导入和脚本启动。门禁会在临时导出目录中逐个导入 `mc2p`、`scripts` 和 `tools` 下的 Python 模块。

当前组件证据：

- 信息视角 3 项：视野外缺失格会触发，视野内遮挡不会触发，战斗视角会压下信息视角；
- 滑行输入 2 项：正常中性自由下落保持不变，非中性实际输入进入保持落地责任的恢复；
- D034 5 项：同帧动作交接、期限竞态、历史期限路径、非步行动作视角和追击视角；
- 表面 Java／协议 14 项和原生核心 10 项全部通过；后者包含 220 个随机世界的容量剔除等价、实体遮挡、固定边界和 500 个随机世界的空气零误判；
- 公开包第一方模块导入检查通过。

这些组件和离线门禁不能替代实机证据。B10 的实机结果见下一节；后续阶段仍需单独重跑。
