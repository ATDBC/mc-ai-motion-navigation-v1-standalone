# B12-A 验收计划：攻击证据与重试

日期：2026-09-26
状态：已完成

## 1. 组件检查

至少覆盖：

1. 攻击未赢得仲裁时不算已提交，也不消耗失败额度；
2. 客户端门禁拒绝只增加门禁拒绝计数；
3. Runtime 或回执失败只增加输入失败计数；
4. 已提交攻击在确认期限内保持等待状态；
5. 单独生命下降不会确认机器人命中；
6. 单独死亡可以结束消灭目标任务，但不会增加确认命中或授予交战许可；
7. 同一命令后的新受伤动画在身份和时间均有效时形成命令关联命中；
8. 目标修订、换世界和观察中断不能复用旧命中证据；
9. 门禁拒绝、输入失败和确认超时分别耗尽各自额度；
10. 一次确认命中后，后续攻击不会继承此前的连续失败状态；历史总数仍保留；
11. 额度耗尽返回有类型的 `NEEDS_TASK_DECISION`，Runtime 保持 `READY`；
12. 离线重放能够从原始命令、回执和观察恢复同一结果。
13. 门禁拒绝、输入失败和确认超时交替出现时，总无进展计数仍会在冻结上限内返回任务层。

## 2. 固定场景

首轮 Fabric 场景继续使用单玩家、单只普通成年僵尸和固定种子。僵尸放在不会自然燃烧的环境中，使命令关联命中先验证最小闭环。

正例至少覆盖：

| 场景 | 次数 | 要证明什么 |
|---|---:|---|
| 固定目标单次攻击 | 20 | 每次攻击只产生一个尝试记录和一个命令关联命中 |
| 移动目标连续近战 | 20 | 多次攻击编号连续，成功后不携带旧失败状态 |

边界和反例各运行 2 次：门禁拒绝、攻击意图被其他操作延后、输入失败、确认超时、仅生命下降、未归因死亡、提交后目标修订、提交后观察中断、世界会话变化，以及门禁拒绝、输入失败和确认超时三类额度耗尽。共 12 类、24 次。

根据 D030，依赖游戏事实的门禁拒绝、确认超时、仅生命下降、未归因死亡和提交后目标修订使用 Fabric。仲裁延后、输入失败、提交后观察中断、世界会话切换和三类额度耗尽使用确定性 Runtime 注入。40 个正例仍全部使用 Fabric。两类反例共用同一份冻结清单和有类型结果。能够形成单次攻击记录的试次还要核对在线结论与离线重放；三类额度耗尽则核对两次有类型失败和对应的额度归并结果。结果分别报告，不能把确定性注入写成实机试次。

场景清单使用世界种子 `21001`。固定目标和移动目标正例各按东、南、西、北四个方向运行 5 次。移动目标的生物种子固定为 `31001` 至 `31005`。完整清单由 `scripts/b12_attack_evidence_runtime.py` 生成；首次正式运行后不得按结果删除或改组试次。

人为注入的来源未确认伤害与失败用例单独统计，不进入有效可达正例成功率。有效正例超时仍保留在分母中。

## 3. 证据要求

每次运行保存：

- 世界、任务、目标和种子；
- 每次攻击尝试编号；
- 正式观察流；
- 攻击意图、仲裁和客户端回执；
- 生命、死亡和受伤动画变化；
- 有类型的尝试结果和任务结果；
- Runtime 状态；
- 各类历史总数和连续失败数。

在线结论与离线重放逐次一致。任何缺少命令、回执或关键观察的运行都不能作为命中确认正例。

世界会话变化用旧会话结束顺序验收：先向仍存活的攻击拥有者发出取消，保存 `combat_cancel` 和旧尝试终态，再替换 Runtime。它的预期结果是 `CANCELLED`，不是把旧尝试留成缺观察。若会话已经异常消失而来不及取消，必须保留为观察中断或运行故障，不能伪造取消记录。

## 4. 回归

提交前至少运行：

- 运动／导航专项检查；
- 固定近战、移动近战和外力恢复检查；
- Runtime、仲裁和客户端动作门禁检查；
- 公开证据读取与重放检查；
- Java 独立门禁。

C1-A、C1-B 和 C1-C 的历史记录不改写。若新分类使旧记录得到更保守的结论，应作为新重放结果单独报告。
