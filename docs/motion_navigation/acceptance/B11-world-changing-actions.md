# B11 验收计划：放置方块与有限搭桥

日期：2026-09-25
状态：B11 冻结范围与复审整改通过

## 1. 组件检查

至少覆盖：

1. 放置请求拒绝非法坐标、面、目标偏移、物品和方块身份；
2. 当前准星、支撑格、目标空气、主手物品或身体位置不满足时不提交；
3. `pending_confirmation` 不完成事务；
4. 只有更晚的正式观察显示预期方块，且生存库存减少一件时才成功；
5. 错误方块、观察缺失、目标修订、世界会话变化和确认超时分别得到明确结果；
6. 同一原因最多重试两次，不能无限点击；
7. 未确认方块不会写入正式世界知识或进入路线；
8. `RequiredInteraction` 绑定规划请求、目标修订、世界依赖和安全站位；
9. 交互确认后旧路线失效，并从真实观察重算；
10. 未授权世界修改时，原场景仍返回无路。

Python、Java 解码和客户端门禁都要覆盖新增正式契约。只用合成后端通过不能代替 Fabric 结果。

## 2. 固定 Fabric 场景

### 正例

| 场景 | 次数 | 要证明什么 |
|---|---:|---|
| 固定站位单块放置 | 20 | 一次操作、一次库存消耗、正式观察确认 |
| 一格缺口后继续到目标 | 20 | `RequiredInteraction` 与重新规划闭环 |
| 两格直桥 | 10 | 逐块确认，不提前采用第二块 |
| 三格直桥 | 10 | 连续上限、路线和库存一致 |

有效任务失败或超时仍保留在分母中。60 个正例必须全部完成，才能声明冻结范围通过。

### 反例

每类至少 2 次：没有放置授权、主手不是泥土、数量少于所需桥长、准星错误、目标格不再是空气、提交前取消、一次确认后取消、结果观察超时、世界会话或目标修订变化，以及桥位被其他方块抢先占用。目标修订另外覆盖两个时机：身体已潜行到边缘但尚未点击，以及点击后仍在等待正式确认。

反例在运行前登记，单独统计，不进入正例成功率。

## 3. 安全与时序

- 放置时身体停在已知安全支撑上，目标格与身体碰撞箱不相交；
- 未确认前不会踏入目标格上方；
- 一次操作只发一次原版使用脉冲；
- 观察年龄、控制处理时间、动作提交到实际应用继续沿用 B10 的计时口径；
- 世界变化后，下一条移动路线引用新的几何修订；
- 取消、失联和失败后不会继续放置剩余方块。

## 4. 证据

每次保留运行清单、版本、种子、初始库存、每帧正式观察、规划结果、`RequiredInteraction`、动作意图、仲裁结果、客户端回执、库存变化、世界事实修订和任务终态。组件证据、合成后端证据和 Fabric 证据分别报告。

## 5. 回归

提交前至少运行运动／导航专项测试、动作协议 Java 门禁和 B11 专项检查。正式验收后再增加一组 B10 跨隙、C1 移动近战与 C1 外力恢复实机回归，确认新的交互执行器没有取得它们的输入所有权。

## 7. 复审整改与重新验收

三方复审确认首轮 B11 放置结果成立，同时发现跨阶段和生命周期边界。整改内容如下：

- B10 探针改读 Runtime 已维护的世界，不再重复写入约 290 个格子；整轮复用同一组后台 worker；中性落地帧不再因没有动作证明编号而被探针误判；
- 搭桥额度归一次任务会话所有，目标修订不补充额度；
- 放置前改目标会撤销旧站位，放置后改目标会等待旧操作确认，并只保留最新修订；
- 走位和瞄准最多等待 120 次新观察，操作仲裁最多等待 20 次新观察；
- 受击后缺世界格不会再把后续位移记成无来源外力。
