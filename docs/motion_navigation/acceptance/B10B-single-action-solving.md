# B10-B 验收结果：单动作命令求解

日期：2026-09-21

## 结论

B10-B 已在冻结的首版范围内通过。机器人可以从正式状态锚点出发，自动搜索可发送的按键序列，预测同高一格跨隙的完整轨迹，并在受控 Fabric 会话中执行同一份结果。

> 2026-09-26 证据边界：这里的 Fabric 结果使用已退出正式主线的 profile 3。求解与验证组件仍然成立；profile 4 下的当前端到端 B10 验收已经重新打开，不能用本页历史成功率代替。详见 [D035](../decisions/0035-formal-surface-depth-only.md)。

本结论只覆盖草方块、低速且对正入口、四个正方向和同高一格空隙。它不授权普通规划使用新求解器，也不覆盖斜向、多格跨越、途中转向或高速入口。

## 实现范围

- 求解对象是正式 `MovementV1` 命令，不是模拟器专用的任意连续输入。
- 每个 tick 都根据预测状态重新投影输入，再调用 B09-R。
- 命令、投影输入、入口、轨迹、接触事件、出口、世界依赖和执行窗口保存在同一份不可变结果中。
- 独立验证器检查离地、落地、水平碰撞、上升阶段顶撞、目标区域、终端速度和恢复余量。
- 有限搜索最多检查 12 个候选，每个候选最多预测 20 tick。
- 受控入口串行独占正式 Runtime 和 Fabric 输入出口；旧 B09 控制器没有作为失败回退。

## 保留的失败证据

正式通过前保留了三类失败：

1. 第一轮场景请求了超过正式接口上限的空气格，场景准备被正确拒绝。测试范围随后缩小到仍覆盖完整身体扫掠的 7×6×7 区域。
2. 第二轮动作样本全部完成，但诊断关闭恰好发生在运动 tick 中间，旧代码抛异常。现在只丢弃尚未形成完整证据的尾部半个 tick，已经封存的记录不变，并有 Java 回归测试。
3. 第三轮动作样本再次全部完成，但 Python 离线整理大报告时没有及时关闭控制会话，客户端 64 条未读取输入记录达到上限并按设计失败。现在场景结束后先发送最终中性输入并关闭唯一控制会话，再离线生成报告。

前两次完成动作的运行仍按整轮失败保留，没有并入正式通过结果。只有最后一次重新运行全部门槛后，才形成 40／40 的正式结果。
