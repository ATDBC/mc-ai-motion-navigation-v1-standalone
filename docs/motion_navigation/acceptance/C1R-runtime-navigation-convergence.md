# C1-R：公共控制与导航收敛验收计划

日期：2026-09-24
状态：已完成；R0 至 R5 均已通过

## 1. 判定原则

C1-R 修复公共边界，不通过增加容易场景来证明成功。旧阶段的适用正例、反例和失败证据继续保留。新的验收结果不能覆盖旧失败，也不能把超时、预算耗尽或基础设施错误从预先冻结的可达任务分母中删除。

每个子阶段先通过组件和离线集成检查，再进入 Fabric。某一子阶段失败时停止后续正式运行，保留失败产物并修复该层。

## 2. R0：瞄准和文档事实

### 结果（2026-09-24）

R0 通过组件与回归验收。证据范围如下：

- 新增的纯函数测试覆盖站立、潜行、同高、高一格、低一格和非法几何；
- 固定目标驱动测试证明它读取正式观察中的实际眼高，不再写死 `1.62`；
- 移动目标测试证明重新找回目标使用同一个瞄准函数和被跟踪实体的碰撞箱；
- 决策和驱动测试证明 C1 会等目标受伤动画归零后再提交下一击；上一击可由生命下降、明确死亡或攻击后的新受伤变化确认；
- C1、观察契约及部署来源相关的 120 项测试通过；
- `tests/motion_nav` 的 345 项测试通过；
- `tests.test_deployment_project.DeploymentProjectTests.test_real_offline_build_contains_shared_client_only_classes_and_provenance` 通过，实际编译并检查了本轮修改的 Java 观察代码。

本轮没有重新运行游戏内 C1 场景，因此不能用上述结果替代 C1-A、C1-B、C1-C 已冻结的 Fabric 统计，也不新增实机性能结论。

### 组件门槛

- 同高普通成年僵尸：站立和潜行都瞄准碰撞箱中心附近；
- 目标脚点分别高、低 1 格：pitch 符号和角度正确；
- 重新找回目标与正式攻击使用同一角度函数；
- 目标受伤动画仍在持续时不提交无效攻击；动画来源不用于冒充本次命中归因；
- 攻击许可与上一击命中确认分别绑定自己的条件和命令身份；
- 世界会话、目标修订和实体身份变化仍拒绝旧攻击；
- C1 文档明确区分共享 Runtime 链和新运动导航链。

### 回归

- C1-A、C1-B、C1-C 现有单元与重放全部通过；
- 不因修正瞄准而放宽准星、距离和合法视野门禁。

组件和回归证据如下：

- 123 项 R1、近战、外部运动恢复、证据重放和包边界检查通过；
- 138 项扩大后的 Runtime、观察请求、Fabric 后端和部署检查通过；
- 独立 Fabric 客户端使用锁定的 Minecraft 1.21、Fabric Loader 0.15.11 和 Fabric API 0.100.6+1.21 完成离线编译、打包和来源校验；
- 实机运行检查确认 40 次攻击都只有一条 `attack_dispatched`，且能找到同请求、同 `client_ticks`、输入值完全一致的 `input_consumed`；
- 客户端在实际输入采样前再次执行攻击门禁。世界、界面、玩家死亡和期限等整帧条件失败时拒绝完整动作；准星、距离、目标身份和冷却等攻击专属门禁失败时返回 `operation_rejected`，同帧已经接纳的移动继续执行并进入输入账本；
- 传输层在组合操作真正进入输入采样前不会返回成功回执，后续请求不能提前覆盖待执行攻击。

第一次实机调试曾暴露两个问题：场景在攻击冷却未满时先启动前进，机器人会在等待期间走近目标；攻击也曾在请求到达时执行，而移动到下一运动 tick 才采样。最终场景改为先等待满冷却，客户端则把攻击移到输入采样前，并用真实同 tick 诊断验收。失败记录没有改写为成功样本。

### 组件门槛

- 一帧有导航移动、战斗转头和攻击意图时，只产生一个动作快照；
- `attack_entity` 与移动、转头可以共存；
- C1 声明的满冷却门槛继续生效；把门槛降到已验证值时，通用客户端不会因为“未满冷却”固定拒绝；
- 打开界面、容器和不兼容操作仍被明确拒绝；
- 技能注册顺序改变不改变同优先级规则下的确定结果；
- 当前空中责任方不会被一次攻击意图替换；
- 每个正式运动 tick 最多调用一次后端 step。

### Fabric 专项

固定目标场景至少覆盖前进、后退、左右横移四种移动。每种方向运行 10 次，共 40 次：

- 40 次都取得包含实际移动应用和攻击分发的同 tick 证据；
- 40 次都命中指定 `track_id`；
- 误攻其他实体为 0；
- 重复提交同一次攻击为 0；
- 可避免的输入所有权违规为 0。

离线重放重新运行伤害归因、事件去重、责任交接和恢复状态机。它使用日志中保存的预测残差，不独立重演服务器击退物理；B09-R 计算器和 Fabric 正式运行仍是物理与时序结论的来源。

### 分类矩阵

| 场景 | 预期结果 |
|---|---|
| 普通行走、冲刺、转弯、跳跃 | 不产生外力事件 |
| 僵尸真实攻击并产生运动残差 | `DAMAGE_KNOCKBACK` |
| 吸收心承担伤害并产生运动残差 | `DAMAGE_KNOCKBACK`，不得因生命未下降漏检 |
| 伤害成立，但当前材质、姿态或状态不受物理计算器支持 | `DAMAGE_WITH_UNVERIFIED_MOTION`，进入保守恢复，不宣称已证明击退 |
| 着火或中毒且无运动残差 | 只有伤害事实，不启动位移恢复 |
| 摔伤且运动符合预测 | 只有伤害事实 |
| 人工注入预测外的位移、无来源证据 | `UNATTRIBUTED_EXTERNAL_MOTION` |
| 已知安全走廊内、仍落在能力入口范围的外力偏移 | 从新锚点续行，不机械刹到静止 |
| 外力后处于空中或路线已不安全 | 原责任方安全落地或有界制动，再重新规划 |
| 异步日志线程失败 | 控制继续，证据标为不完整，正式成功判定拒绝 |
| 输入采样缺口 | 当前责任继续安全收尾，随后重新锚定 |
| 世界会话倒退或输入所有权冲突 | 封存当前会话 |

上表定义预期行为，不表示每一行都已经取得 Fabric 证据。公开的 C1-C 通过批次包含 33 次真实受击，全部因为原版击退把接地玩家抬离地面而进入落地和制动恢复。该批次没有触发“已知安全走廊内直接续行”。恢复完成后的 `parent_reanchored` 只能证明刹停后交回导航，不能当作不刹停续行的实机证据。直接续行目前只有组件测试，等以后加入不抬离地面的活塞推动或实体挤压场景再补实测。

公开批次还发现一次伤害与击退相差一个运动 tick。旧版本把它拆成“有伤害、无位移”和“无来源外力”两条记录。D024 将伤害归因保留到紧接着的一个运动 tick；历史归档保持不变，新的组件回归使用同一组观察序号和运动 tick 验证修正。

### 容量与持续运行

- 30 分钟常驻场景覆盖静止、移动、目标更新和远处地图变化；
- 已知格、区段、输入账本、后台请求和日志队列都有可检查上限；
- 达到世界知识上限时，活动路线依赖不被静默删除；
- 远处无关区段更新不让当前路线或全部视图失效；
- 日志消费者阻塞 5 秒不阻塞控制帧。
- 控制帧不再同步投影整份观察；日志队列饱和时有丢弃计数，运行证据降级但客户端保持可控。

## 6. R4：带速度跨隙

三个入口速度带和四个正方向形成 12 个固定类别。每类至少完成：

- 20 个确定性计算器／求解器样本；
- 5 个中断时刻样本，验证释放输入后落到已知安全支撑；
- 5 次 Fabric 正例；
- 2 个明确拒绝反例，包括入口方向不符和落地空间不足。

共计至少 240 个计算样本、60 个中断样本、60 次实机正例和 24 个反例。正式正例必须全部完成。求解超时保留在正例分母中。

性能沿用 B10：后台规划／求解不阻塞控制；控制帧 P95 ≤ 8 ms、P99 ≤ 15 ms；输入必须在候选执行窗口内真实生效。

输入证据逐条绑定请求和客户端运动 tick。首条命令允许在两个相邻 tick 中生效，但两个分支都经过完整验证。晚一 tick 的分支包含此前的一次空输入，因此不会把变化后的入口状态套入旧轨迹。动作开始后，后续命令仍要求连续 tick 回执。

正式运行还证明后台等待不会冻结状态锚点。等待时会话只请求新观察，不提交中性移动去覆盖现有输入；求解结果到达后，从最新正式观察重新接纳。恢复和终止释放不会登记成证明中的新命令。

以下失败记录保留为边界证据：

- `20260924T184028642222Z-82a2c0f0`：首条命令晚一 tick 生效，旧实现没有证明此前的空输入，实际出口与证明不一致；
- `20260924T185411232963Z-40f45007`：后台等待时状态锚点停在旧 tick，且恢复释放被登记成在途证明命令；
- 其余调试运行分别暴露输入账本、观察时效、旧意图容量、材质许可、查询范围和大型诊断文件导出问题。所有问题都先由失败证据定位，再修正对应层。

该结果只授权已冻结的一格同高跨隙、三个入口速度带、四个正方向和当前普通支撑材质。它不代表任意宽度缺口、带速上台阶或所有动作都已支持带速衔接。
