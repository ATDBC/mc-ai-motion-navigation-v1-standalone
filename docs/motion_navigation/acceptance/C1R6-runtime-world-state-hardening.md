# C1-R6：运行时失败处置与世界知识验收

日期：2026-09-25
状态：组件与 Runtime 集成验收通过；未新增 Fabric 结果

## 1. 失败处置场景

1. 异步证据写入失败：Runtime 保持 `READY`，后端不关闭，决定明确标记证据不完整；
2. 可重试任务期限失败：前两次返回有界重试，旧输入来源失效，下一帧为中性输入；
3. 同原因第三次失败：返回任务取消，不继续增加重试；Runtime 仍可接受新任务；
4. 后端输入状态不确定：进入 `FAILED`，后端只关闭一次；
5. 不可恢复的连接或世界结束：进入 `ENDED`，不能继续提交动作；
6. 同步正式 trace 写入失败：不能按“异步证据降级”继续控制。

## 2. 世界知识场景

1. V3 reset 返回后，Runtime 的适配器已经包含 reset 观察；
2. 后续 step 返回前，新增或变化的方块已经写入相同适配器；
3. 没有启动导航任务时，世界知识仍会随观察更新；
4. 结束第一个导航任务并新建第二个任务后，第二个任务读取此前地图，不重新得到空地图；
5. 正式导航驱动会把会话绑定到 Runtime 的适配器；已经消费私有地图的会话不能中途换拥有者；
6. 换世界或换 episode 后建立新会话，旧会话事实不混入新世界。

## 5. 公开证据复核补充

三方从公开原始试次重新统计了 C1-B 通过批次、C1-B 失败批次和 C1-C 通过批次，结果与验收文档一致。C1-B 失败批次仍为 19／20，唯一失败是已经记录的单帧目标观察缺口。

C1-C 通过批次的 33 次真实受击中，有一次扣血和击退相差一个运动 tick。旧版本把同一次受击拆成两种来源。D024 采用一个 tick 的相邻归因窗口，并用该真实时序增加回归测试。修正没有改写公开历史归档，也没有新增 Fabric 结论。

B11 复审又补出一个相邻边界：伤害出现后，如果下一段残差因为缺世界格而无法计算，更晚的偏差不能被改记成无来源外力。现在检测器保留伤害事实；补齐相邻证据时正常归因，证据窗口已经跨过或等待到期时产生 `DAMAGE_WITH_UNVERIFIED_MOTION` 并进入保守恢复。评审方提供的复现现在依次得到 `damage_motion_grace`、`motion_residual_unavailable` 和 `damage_motion_unverified_gap`。

该批次的 33 次真实受击全部进入落地和制动恢复，没有一次触发已知安全走廊内的直接续行。该分支目前只有组件测试证据，后续需要用不抬离地面的外力单独验收。

上面的 415 项等数量是 C1-R6 当时的冻结结果。B11 复审整改后的最新检查数量和公开仓库验证写入 B11 验收记录与 D026，不用新结果改写旧批次。
