# D101：澄清短开环时序、证明范围和生命周期

日期：2026-10-11。状态：决定有效；只补齐 D099／D100 的协议规则，尚未授权实现、实施计划、正式链接入或新 Fabric。

## 为什么需要澄清

三方在提交 `a01474d` 后复核 D099／D100，指出几处仍可能被实现成两种不同语义：

- “整体按时或晚一 tick”可能被误读成每条命令都可以各自晚一 tick；
- 正常回执可以批量上报，但第一条回执如果也延迟，上层无法及时删掉错误时序分支；
- “关键节点严格检查”可能被实现成到达每个节点都重新计算完整证明；
- 证明是否仍有效与外力归因可能共用同一套容差；
- 余量可能被实现成事后扩大证明范围；
- 宽阔普通地面可能再增加一套短输入包控制器；
- 取消、替换和输入欠载时，旧输入流由谁收尾还没有写全。

这些问题如果留到实现时决定，会重新产生平行状态、重复控制器和逐案例补分支。现在先冻结共同协议。

## 决定

### 1. 0／1 tick 只属于输入流起点

“按时或整体晚一 tick”只描述一条新输入流的首条命令何时开始生效。

- 输入流开始前，同时保留起始偏移 0 和 1 tick 两个候选分支；
- 第一条命令的实际应用回执到达后，立即确定真实分支；
- 后续命令按照该分支对应的绝对 movement tick 执行；
- 中间任何一条命令单独晚到、缺失或内容不同，都属于偏离；
- 不能为后续每条命令重新选择 0／1 tick，也不能把多个单独晚到解释成输入流整体平移。

第一条应用回执必须立即上报，不能等整个输入包结束后批量发送。稳定分支内的普通连续回执仍可压缩或批量传输；异常、关键节点和流结束继续立即上报。

### 2. 不提前冻结“必须预排程”

当前还没有用 Fabric 实测客户端 tick 内的观察、Python 决定、命令到达、输入读取和应用顺序。因此本决定不要求所有短输入包必须在动作开始前一次性预排程。

后续最小试验必须记录真实 tick 顺序，并回答：

- 同一客户端 tick 收到的命令能否赶上本 tick 输入读取；
- 最迟何时提交才会在指定 movement tick 生效；
- 连续命令是逐 tick 发送更稳定，还是有限预排程更稳定；
- 撤销或替换已经排入客户端的未来命令时，客户端能否给出逐条终态。

最终实现可以选择有限预排程、逐 tick 发送或两者组合，但必须满足同一输入流时序和生命周期规则。行为不能依赖未经验证的 tick 顺序假设。

### 3. 一致时只比较，不重复证明

关键节点的“严格”表示越过节点前必须持有仍然有效的证据，不表示每次到达节点都重新运行完整求解或完整轨迹扫描。

当以下条件全部一致时，只做字段、范围、身份和版本比较：

- 当前 generation、owner、路线和动作身份一致；
- 第一条回执已经确定时序分支；
- 身体仍在证明的有效范围内；
- 相关世界与物理依赖没有变化；
- 伤害额度、姿态和动作前提仍成立。

只有比较不一致、相关事件发生或证据尚未覆盖当前状态时，才重算受影响部分。

### 4. 证明有效范围与外力归因阈值分开

证明有效范围回答“当前输入是否仍有执行资格”。它由候选、走廊、入口、落地区和安全收尾决定。

外力归因阈值回答“这次偏移是否可归因于伤害、爆炸、活塞、实体挤压或其他外力”。它只用于诊断和选择恢复原因。

两者不能互相代替：

- 身体离开证明范围时，即使没有识别出外力，也必须按偏离处理；
- 已识别出外力时，如果身体仍在安全范围，可以继续或局部接回；
- 调大外力归因阈值不能扩大证明范围；
- 调整证明范围也不能改变伤害或外力来源结论。

### 5. 余量放在控制目标和承诺点重定时

安全余量在生成输入时使用：控制器瞄准可接受区域的内部，不以边界为目标；速度、横向位置和落点也保留明确余量。

到达最后可放弃点前，系统可以根据真实观察和已确定的时序分支，重新选择承诺 tick、入口或安全落地区。这个过程必须重新绑定 generation 和依赖。

余量不能通过以下方式实现：

- 事后扩大旧证明的允许范围；
- 将超出范围的真实状态强行夹回范围内；
- 把外力归因容差当作位置余量；
- 在越过承诺点后重写原候选的承诺时刻。

### 6. 宽阔普通地面只使用现有地面控制器

宽阔、已知、可恢复的普通地面继续由 `FixedRouteController` 逐帧选择有限候选。它现有的输入租约和安全检查是地面控制的唯一正式路径。

短开环输入流主要约束需要明确时序和承诺点的动作及其衔接。不能为了统一接口，再为普通地面增加一个通用输入包执行器、第二条地面控制链或另一份进度状态。

地面发生安全偏离时，`FixedRouteController` 消费局部接回或危险规避目标。只有它无法有界处理时，才升级到完整重规划。

### 7. 下一动作要提前计算

当前动作仍在执行且身体责任仍由原 owner 持有时，后台可以根据当前观察、短期预测和下一入口提前计算下一动作。

提前结果只表示候选已经准备，不表示输入已获授权。真正交接前仍要核对：

- generation、目标和路线身份；
- 当前真实身体是否落在候选入口范围；
- 相关依赖是否未变；
- 输入流起点和许可窗口是否仍可满足；
- 原 owner 是否提供正式交接证据。

如果预测入口没有出现，候选自然失效；不能为了使用已算好的结果把身体停回预测点。

## 输入流生命周期

### 1. Generation

每条输入流绑定不可变 generation。generation 记录任务请求、计算时采用的目标修订、路线修订、动作位置、输入流序号和计算依据。

目标修订本身不会自动创建新 generation。系统先检查当前输入流是否仍满足新目标、依赖和身体责任；只有输入内容、入口、许可或安全后缀需要改变时，才创建新 generation。持续跟随因此可以保留仍然适用的安全前段，不会因为每 tick 更新目标而反复撤销输入。

同一 owner 在同一未来 tick 只能有一个 generation 提供执行资格。旧 generation 的结果可以保留作诊断，但不能继续授权尚未发送的命令。

### 2. 撤销

撤销针对尚未实际应用的未来命令，包括客户端已经接收并排队、但还没进入输入采样的命令。已经进入采样、可能正在应用或已经应用的命令不能抹去，必须保留事实记录，并由原 owner 完成身体收尾。

客户端要为已接收的未来命令报告明确终态：已应用、已撤销、来不及撤销或未执行。Python 不能只清空本地队列就假设客户端也已停止。

### 3. 替换

新的 generation 可以在旧输入流仍活动时提前准备，但不能直接覆盖旧 owner。

替换只有在以下条件满足时生效：

- 旧流已到可交接边界，或旧 owner 已给出安全释放证据；
- 新流的首条命令、入口和依赖仍有效；
- Runtime 仲裁明确选择新流；
- 旧流中相冲突的未来命令已有明确撤销终态。

替换失败时，旧 owner 继续执行已授权安全前段或收尾。不能留下无人负责的一帧。

### 4. 输入欠载收尾

“欠载”指客户端需要下一条已授权输入，但 Python、后台计算或传输没有及时提供。

每条严格输入流必须声明有界的欠载收尾：继续已授权的安全尾段、执行已证明的停止／落地尾迹，或明确保持到下一个关键边界。客户端只能执行事先授权的收尾，不能自行无限重复最后输入，也不能把缺输入解释成中性输入。

欠载收尾结束后仍没有继任输入时：

- 身体已安全着地且可释放，按正式交接退出；
- 身体仍在承诺阶段，原 owner 继续承担责任并立即报告未解决；
- 不能通过重开 generation、刷新任务或隐藏回执来补回期限。

普通宽地面仍由 `FixedRouteController` 的现有租约和回退逻辑处理，不另建输入流欠载状态机。

## 与既有决定的关系

D101 澄清 D099 的短开环时序和 D100 的连续偏离恢复，不改变两者的产品目标。D098 的 P3 失败、性能数据和原始证据继续保持不变。

本决定不授权实现、实施计划、正式 Runtime 修改或 Fabric。下一步只能先做最小、隔离的 tick 顺序与协议试验；试验结果出来前，不得把预排程写成正式要求。
