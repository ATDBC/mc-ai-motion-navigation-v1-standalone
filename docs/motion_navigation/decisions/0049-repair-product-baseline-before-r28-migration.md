# D049：先修产品基线，再迁移协调逻辑

日期：2026-10-01。依据三方 `54394f8` 的修正方案和本地复现。

原基线暴露了两个产品缺陷：目标解析只接受支撑面代表点；绕墙时横移没有被算作进入下一段的进展。停顿指标漏掉抖动，离散参数重复，迁移比较也没有覆盖足够的中断路径。

在 R28-1 前增加三个有明确范围的批次：

1. 批次 2 修量尺与清单。保留原零位移指标，增加 10 tick 净位移不足 0.1 格且持续至少 3 tick 的指标。按控制者和动作种类分开普通步行、严格动作准备和规划等待，不读取原因文案。新生成器随机化连续参数，正常与晚到使用相同身体入口。中断、随机序列和异步组合只用于配对回归，不进入产品成功率。
2. 批次 3 统一目标区域中的站位查询。查询返回位置、状态、缺信息和依赖；最终连接沿用现有几何检查。地面证明的前段保留，不能让旧证明覆盖新终点，也不能把改动后的路线冒充原证明。
3. 批次 4 修拐角进度。连续无进展后才允许使用紧邻下一段的投影，仍保留碰撞、支撑和停止尾迹检查。四向对照旋转整个入口。平局偏置只在取得依据后修，不同时引入自动转身。

每批保存自己的源码和检查结果。原 v1 归档不改写；新提取器输出独立报告。先用同一份 v2 参数保存修复前结果，再比较修复后结果，最后冻结 v2。200 对连续入口只签署本批固定集合的基线，不替代足量统计发布验收。

只修阻碍当前结果的共同规则。未涉及的细小问题记入缺陷台账，不能借此扩展感知、物理、游泳、跟随或协调状态迁移。普通步行朝向与疾跑能力限制留给后续局部跟踪阶段。

受影响的目标和绕墙场景需走正式 Runtime 导航链做 Fabric 对照。组件成功不计为实机成功。R28-1 至 5、长期跟随和持续任务预算仍未交付。
