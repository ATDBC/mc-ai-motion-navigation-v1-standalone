# D075：完成区域选择精确子矩形，潜行区间限期接入

日期：2026-10-07。状态：F2-R 已按冻结范围通过；后续支撑边缘收敛转入 D076／F2-S。

## 要解决的问题

F2 把终点从一个小点改成原 `GoalState` 内的安全矩形。目标旁只有正交墙时，这个表示足够；目标位于建筑外角、树干或对角柱旁时，障碍会从目标区域切掉一个角，剩余可站区域成为 L 形。当前实现因为不能把整个 L 形写成一个矩形，直接拒绝任务。

F2 还实现了按路线进度授权的潜行防坠，但正式规划和接纳没有生成能力区间。它目前只有组件证明，不能继续写成已经交付的产品能力。

## 决定

1. `GroundCompletionRegion` 继续只保存一个轴对齐矩形，不扩成多边形或矩形集合。
2. 可站区域由多个互不重叠的精确矩形组成时，首版选择面积最大的矩形。面积相同时按固定坐标顺序选择。
3. 选择的是原可站区域的子集，不能使用外接矩形，也不能扩大原 `GoalState`。
4. 支撑、净空、危险、未知、依赖和正式完成检查保持不变。区域重放必须得到同一矩形，否则原路线失效。
   UNKNOWN 不能当 AIR。查询按整格最坏障碍裁剪未知 owner；如果剩下的子区域及身体扩张包络完全已知且安全，则允许使用。未知 owner 不成为执行区域依赖。没有这样的子区域时仍为 `NEEDS_INFORMATION`。执行区域内的事实变未知，仍按原查询或依赖复核拒绝。
5. 本轮先冻结外角、对角柱、柱间目标、三种生产目标尺寸和杂乱地形，再修改代码。
6. `SNEAK_EDGE_GUARD` 改记为“执行器已有组件证明，正式路线尚无生产者”。F2-R 不为凑验收而让终点接纳强行生成区间。
7. 如果 F2-R 后立即实施路线优化器，路线优化器必须成为第一个正式区间生产者，并补必须潜行才能完成的 Fabric 场景；如果下一产品阶段不是路线优化器，删除当前不可达的潜行状态机。

## 没有采用的做法

- 不把 L 形的外接矩形当作安全区域；
- 不新增通用多边形完成区域；
- 不优先选择入射方向所在块，除非后续出现最大块导致可复现失败；
- 不让终点在松开潜行后会坠落的位置完成；
- 不用总体成功率掩盖某个新场景族全部失败。

## 影响

F2-R 会新增 v8 产品量尺。v7 的 2,000 项和 F2 的 528 项保持原记录。v8 逐场景族报告外角、柱子、多格目标、斜向接近和杂乱地形，不以一个汇总数字代替分类结果。

F2-R 还会补齐公开加固证据，报告 D061 被预热排除的最慢帧和动作分支数。换行治理不与本轮行为修复混合实施。

## 2026-10-08 实测补记

最小几何修复、当前 Windows 正逆各 1647 项、v8 固定 104 项及 Fabric 16 项均通过。原 v7 完成数和安全门槛保持，新杂乱正式链为 1715／1800，85 项失败原样保留，不记为能力已覆盖。UNKNOWN 继续按最坏障碍裁剪，完全已知的安全子区域可用；执行区域未知仍拒绝。

D061 初次和冷却后的正式复验超限，失败保留。同机交错与临时探针定位到共享模拟器视觉查询中的重复射线计算。只在 `tests/sim/backend.py` 做全字段等价短路，不改生产、输入或计时边界。RED／随机及边界对照／错误副本检查通过后，单次正式复验最大 40.1764 ms、deadline miss 为 0。它只是量尺夹具的性能修复，不是机器人能力提升，也不回写原 F2 的 captured 57.0863／retained 46.5423 ms。

潜行仍只有组件证明。下一产品阶段保持路线优化器设计与交付，必须成为首个正式区间生产者并补必须潜行的实机；如果更换下一阶段，先删除不可达状态机。独立公开快照 verify、专项 63 项和完整 motion_nav 1647 项通过，F2-R 按冻结范围关闭。最后签署仅修改文档与证据，新快照须验证并与已测试的 638 个代码、配置和夹具文件逐字节比较；原完整运行的来源提交不改写。
