# D027：动作生效窗口绑定到获胜移动意图

日期：2026-09-25
状态：已采用

## 要解决的问题

跨隙动作会证明首条命令允许在哪些玩家运动 tick 生效。B10 探针曾把这个窗口直接传给 Runtime，但战斗和 B11 使用的正式导航驱动只登记下一 tick。首条命令若在证明允许的第二个 tick 生效，账本会误判为窗口外输入并中断动作。

直接让父驱动传导航窗口也不可靠。同一控制帧以后可能同时包含导航、战斗和世界交互提案，最终移动未必来自导航。Runtime 只能采用实际赢得移动仲裁的那条约束。

## 决定

1. 已验证命令的最早和最晚生效 tick 绑定在对应移动意图上。
2. 仲裁结果带回获胜移动意图的窗口。Runtime 只登记该窗口；落选意图的窗口没有任何作用。
3. 带证明窗口的移动意图只仲裁一次。它不能像普通持续前进意图一样留到下一帧重复执行。
4. 导航驱动、战斗和 B11 不再理解动作证明细节。它们只提交提案并采用 Runtime 的统一结果。
5. 探针保留显式窗口参数，用于单来源诊断。若显式窗口与获胜意图的窗口不同，Runtime 按契约错误拒绝，不能任选一个。

## 验证范围

- 正式 `RuntimeNavigationDriver` 集成检查让跨隙首条命令在证明允许的最晚 tick 生效，输入账本仍判为 `APPLIED`。
- 仲裁检查证明窗口随移动赢家传递，并在一次仲裁后消失。
- 当前 Fabric B10 批次的 200 条已验证命令全部在最早 tick 生效，因此没有把这项组件证据写成新的实机成功率。以后出现真实晚一 tick 样本时，再补充正式路径证据。

## 影响

这个边界可直接复用于 B12-B 的同帧组合控制。以后其他意图级约束也应由自己的提案携带，并在仲裁后只采用赢家的约束；不能增加一个脱离意图身份的控制帧全局参数。
