# D056：按时间盒结束 R28，用正式跟随检验扩展边界

日期：2026-10-04

## 决定

R28 已使用全部十个正式工作批次。项目停止在 R28 内继续修改生产代码，也不执行原计划中的 R28-5。

R28 的状态记为“时间盒结束，部分交付通过”。不能写成整体完成：

- R28-1 和 R28-4 按冻结范围通过；
- R28-3 的计算世代、当前目标绑定、两项有界规划工作和新任务身份通过限定安全与功能验收；
- 协调代码净减少、产品统计非退步、五 tick 修订响应、正式跟随、室内终点接近和 R28-5 没有通过；
- 原失败、结构数字和未完成门槛继续保留，不能通过改写范围将它们变成通过。

R28 原来的“协调代码总量净减少”继续记录为未通过。它不再作为 R28-3／4 的追加整改理由。R28-3／4 新增了持续任务预算、计算世代和双规划工作，总代码变化混合了新能力与重复逻辑，不能单靠行数判断职责是否收敛。

下一阶段用正式跟随检验扩展边界。首版跟随层只做三件事：开始持续导航、提交同一目标的新修订、取消任务。它不能管理计算世代、取消后台工作、接纳结果、恢复预算或身体交接。

正式跟随完成后，再单独安排一次行为不变的结构整理。该整理不新增能力和权威状态，只删除死路径、重复身份判断和重复转发。它有独立时间盒，不能借“收尾 R28”继续扩张。

## 为什么这样处理

R28 计划规定最多十个工作批次，并且批次上限与日期先到者触发复核。此前已经折算为七批；R28-1、R28-4、R28-3 分别使用第八、第九和第十批。继续拆 R28-3 或把重构塞进 R28-5，都会成为新的正式批次。

现有证据已经证明共享导航接口具备继续发展的基础：`NavigationSession.propose()` 已成为薄路由；任务恢复、身体责任、计算身份和结果接纳都有正式拥有者。现在最有价值的验证，是新增一个真实调用方是否只需使用公共接口。

## 结构门槛

正式跟随阶段使用下面的硬门槛：

1. 跟随层只能调用导航的开始、目标修订和取消接口；
2. 跟随层不能保存规划、计算、路线、接纳、恢复或身体交接状态；
3. 十二个核心协调文件不得出现跟随专用状态、类型判断或 `reason` 文案分支；
4. 正式跟随原则上不修改核心协调文件。若发现缺少通用接口，先停止并单独记录决定；
5. 核心协调文件总量不净增作为警戒线，但不允许通过压缩代码、包装状态或移动文件制造通过。

跟随完成后的结构整理使用下面的门槛：

- 不新增产品行为、权威状态、恢复规则或兼容分支；
- 核心协调文件的总行数和决定分支都要下降；
- v7 两千项、协调一千四百四十八项和四个补充故障按统一签名逐项一致；
- 轨迹比较使用带版本的浮点取整规则，旧证据和旧哈希保持原字节。

## 影响

- R28 的批次计数恢复为 10／10；
- R28-5 记为未执行，不用现有完整回归结果冒充；
- `_wait_for_active_terminal` 当前只记为未覆盖候选，不能在证明公共入口不可达前删除；
- R28-4 的五个晚到下降结果改称“时序敏感变化”，不宣称产品能力提升；
- R28-3、R28-4 的精简证据要进入公开整理版；
- 正式跟随使用新的阶段与验收记录，不复用旧 `RuleFollower`／`PlaygroundFollower` 作为正式实现。
