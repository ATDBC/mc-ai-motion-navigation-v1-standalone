# D093：在入口范围内刹车，并保留输入失联原因

日期：2026-10-09。状态：限定实现已验证；新增 Fabric 门槛未签署，原始失败和证据保留。

## 要解决的问题

D092 的柱顶验收覆盖正常输入和首条严格命令晚一 tick。每条输入有 20% 概率晚一 tick 时，身体已经进入下一入口的位置范围，却因速度未降下来而继续左右平移。另一个旧缺陷是最后一次上跳失联后安全落地，但任务离目标还差半格，结果被误报为目标不满足。

## 决定

当前地面控制器分别判断“可以交接”和“停下来就能交接”。后一判断要求路线已经走完、身体着地、支撑满足原门槛，以及把水平速度设为零后满足完整入口条件。路线有完成区域时，还必须处于该区域内。它只允许进入既有刹车路径，不授予交接资格。

最后动作确实经 `INPUT_LOST` 路径确认安全落地时，执行器保存这个事实。最终目标仍未满足，执行终态仍为 `FAILED`，报告 `failure_cause=StopCause.INPUT_LOST`；正常动作结束后的目标不满足继续单独报告。补走最后半格留给后续方案，不在本批改变完成行为。

先冻结 Windows RED，修定向检查，再检查关键 tick 和固定随机种子。八种子用于稳定复现；一百种子用于报告完成分布。之后才跑旧基线、性能、完整正逆和四方向 Fabric。最多两轮限定修正。旧证据不改写。

没有修改入口公差、动作证明、任务额度、Session／规划器状态或运动能力。一次转过 180° 的观感、修订帧 8 ms 和 worker 资源债仍单独保留。
