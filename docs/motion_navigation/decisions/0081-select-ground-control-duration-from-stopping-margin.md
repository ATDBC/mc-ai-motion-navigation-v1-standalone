# D081：普通地面控制时长由停止距离和完成余量决定

日期：2026-10-08。状态：已实施一次并按止损规则停止；F2-PC 未通过。后续由 [D082](0082-separate-safe-tail-from-completion.md) 修订。

> D082 保留一／两 tick控制粒度、单一 `control_ticks`、逐玩家 tick重算和晚到压下。D082 撤销“每帧安全尾迹必须停进 completion”的要求，并把安全尾迹、完成判断和控制质量分开。本文保留为 F2-PC 的历史决定与失败证据，不能继续按原 completion 门槛实施。

## 要解决的问题

F2-GP 首轮把失败归因于“两 tick 输入租约与窄完成区域冲突”，这个表述不够准确。

正式普通 `Walk` 已经按玩家 tick 提交输入。执行链每收到一帧新观察，就可以重新计算下一帧。问题出在 `GroundTrackingPolicy` 的候选评分：它仍固定按“同一个输入持续两 tick，再完整松键停止”做预测。窄完成区域前，一 tick 前进可以安全进入并开始制动；固定两 tick 的模型却会把它判成越界。规划 rollout 因此拒绝一条正式执行原本有机会完成的路线。

这个偏差同时影响规划和执行。继续改候选分数，只会掩盖预测时长不一致的问题。

## 决定

### 1. 控制时长只允许 1 或 2 tick

普通地面策略为每个候选明确选择 `control_ticks`：

- 离完成区域和危险边界仍有足够余量时，保留历史两 tick 包络；
- 两 tick 会消耗过多完成余量，而一 tick 加完整停止尾迹仍安全时，改用一 tick；
- 两种时长都不安全时，候选不可用。

选择依据只能来自当前身体、路线进度、完成区域、扫掠结果、停止距离和安全余量。不能读取场景 ID、目标类别、动作名称或测试名称，也不能用“靠近终点”这样的固定距离特判代替物理判断。

### 2. 一 tick 仍验证完整停止尾迹

`control_ticks=1` 只缩短继续施加方向输入的时间，不缩短安全证明。

策略仍要从一 tick 后的预测状态继续模拟松键尾迹，直到达到现有停止条件或现有尾迹上限。整个扫掠体积都必须满足支撑、净空、碰撞、危险接触和 completion 约束。

因此，一 tick 是精细控制，不是降低安全门槛。

### 3. 一个决定只有一个 control_ticks

同一帧内，下列对象必须记录相同的 `control_ticks`：

- `GroundTrackingPolicy` 选中的候选；
- `FixedRouteDecision`；
- 提交给 Runtime 的移动意图和输入租约；
- 诊断记录与规划 rollout。

任何一层不得把一 tick 改回两 tick，也不得只缩短实际发送而继续用两 tick 结果解释安全性。规划 rollout 和正式执行都按相同规则选择时长。

### 4. 每个玩家 tick 都重新计算

普通地面控制不回放多帧脚本。每次取得新观察后，重新计算路线进度、停止距离、完成余量和 `control_ticks`。

两 tick 许可只说明当前候选在这段包络内安全。下一帧收到正式观察后，仍应重新判断；它不允许控制器忽略新观察继续沿用旧评分。

### 5. 精细输入不使用 D068 的晚启动余量

选择一 tick 表示当前安全余量只支持这一玩家 tick。它不能再取得 D068 的“首条输入可晚一 tick”窗口。

如果一 tick 精细输入没有在声明的 tick 生效：

1. Runtime 压下过期输入；
2. 输入账本记录实际结果；
3. 控制器从下一份正式观察重新锚定并重新计算。

不能把晚到的一 tick 输入延后执行，也不能把它扩成两 tick。远处的两 tick候选继续使用历史安全包络；D068 原白名单不因本决定扩大。

### 6. 适用范围

本决定只适用于同时满足以下条件的候选：

- 身体着地；
- 姿态为 `STANDING`；
- 地面模式为普通 `WALK`；
- 当前输入可以随时松开，并能由完整停止尾迹证明安全；
- 不处于起跳、主动离开支撑面、空中落地、探边或其他严格动作阶段。

Sprint、Sneak、Crawl、Swim、Climb、JumpGap、JumpUp、ControlledDrop 和连续高度严格证明不继承这个选择器。以后扩展必须另给证据。

## 为什么采用这个方案

远处用两 tick，可以保留现有推进效率和历史行为。接近窄完成区域时改用一 tick，可以在每个玩家 tick 重新看实际位置和速度。两种情况都由同一份停止尾迹检查保护。

例如，机器人离完成区域还有 0.25 格。继续前进两 tick再松键会越过区域，一 tick 后松键的完整尾迹仍落在区域内。策略应选择一 tick。若一 tick 的尾迹也会越过边缘，则两个候选都应拒绝。

## 与 D080、D068 的关系

本决定补充 [D080](0080-share-ground-tracking-policy-for-terminal-approach.md)：共享 `GroundTrackingPolicy` 的方向不变；首轮失败的直接根因改为“正式逐 tick 提交与固定两 tick 评分不一致”。

[D068](0068-bind-ordinary-walk-late-start-to-ledger-window.md) 继续约束原首动晚启动白名单。本决定新增的精细一 tick输入明确不在该白名单内。不能借 D068 扩大精细控制的生效窗口。

## 不做什么

- 不继续调候选评分权重；
- 不加入终点、场景或动作名特判；
- 不改变 completion region；
- 不压低入口速度；
- 不增加候选重试；
- 不修改通用 A*、Session 生命周期或严格动作证明；
- 不把一 tick 当成所有地面移动的新默认值。

## 止损

按本决定正确实现时长选择、完整尾迹、单一 `control_ticks` 和晚到压下后，先运行 F2S-C-04。

如果 F2S-C-04 仍不能关闭，立即停止 F2-PC。不得再调评分、增加候选或改完成阈值。保留可独立证明的改动，记录新的根因，再另写决定。

实施与验收分别见 [F2-PC 阶段](../stages/F2PC-ground-precision-control.md) 和 [F2-PC 验收](../acceptance/F2PC-ground-precision-control.md)。


## 实施结论

F2-PC 已按本决定完成一次实现尝试。组件场景证明了两个事实：

- 远离完成区域时，两 tick 包络可以保持；
- 在构造的窄区域前，一 tick 加完整中性停止尾迹可以安全落入区域，而两 tick 会越界。

实现还把同一个 `control_ticks` 贯通到 `FixedRouteDecision`，并为一 tick 意图生成不含晚启动余量的精确生效窗口。这些局部契约成立。

不过，F2S-C-04 没有关闭。第一次正式链运行以 `no_safe_ground_candidate` 结束，身体停在 `(1.15004, 64, -2.7)`，而完成区域的 `max_x` 是 `1.09115`。补齐“被简化模型拒绝的一 tick 候选必须用正式 1.21 计算器复核完整停止尾迹”这一接线后，结果改善为 `fixed_route_stalled`，身体停在 `(0.99, 64, -2.69)`，仍在完成区域外。

这次结果推翻了本决定中的一个前提：可恢复地面移动的每帧安全尾迹不必立即终止在最终 completion 内。停止尾迹首先证明身体仍留在安全支撑和路线走廊内。completion 用于判断任务是否完成。机器人仍在安全走廊内时，下一玩家 tick 可以根据新观察继续修正。把两者合成一个条件，会在窄区域前过早淘汰仍可由闭环控制修正的输入。

因此，未提交的生产实现已经撤销。没有继续修改评分、完成区域、候选数量或通用 A*。本决定保留为失败证据；后续若继续，必须另写决定，分别定义“安全可停”和“已经完成任务”两个条件。
