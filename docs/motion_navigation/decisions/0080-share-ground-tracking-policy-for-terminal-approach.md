# D080：普通地面末段共享同一份闭环跟踪策略

日期：2026-10-08。状态：方向保留；首轮实施在批次 3 止损，F2-GP 未通过。后续控制时长由 [D081](0081-select-ground-control-duration-from-stopping-margin.md) 修订。

## 要解决的问题

F2-ST 首轮把普通 `STANDING + WALK` 末段当成严格动作，要求一份输入计划同时覆盖整个 `SegmentEntryWindow`。这个要求超过了普通地面移动真正需要的安全强度。

普通地面末段可以随时松键、制动、重新锚定或重新规划。它与起跳、离开支撑面、受控下降等动作不同。后者一旦开始，身体可能无法安全停在原地，仍然需要严格的入口和轨迹证明。

首轮诊断也说明了这一点：约 `0.50..1.19` 格／秒的入口能完成剩余 9 项，但现有验证器只验证一个代表状态，不能证明整个窗口。正确修正不是继续扩大窗口证明，也不是把入口压到近乎停稳，而是让规划和执行使用同一份普通地面闭环策略。

## 决定

### 1. 按当前风险选择证据强度

普通 `STANDING + WALK` 终点接近属于可恢复地面移动。它不再要求一份离线输入序列覆盖连续入口区间。

以下动作继续使用严格证明：

- 起跳或跨隙；
- 主动离开支撑面的下降；
- 需要在空中承担落地责任的动作；
- 其他开始后不能靠普通制动安全退出的动作。

动作名称本身不决定风险。判断依据仍是当前身体状态、支撑、停止尾迹和动作开始后能否安全退出。

### 2. 只有一个 GroundTrackingPolicy

抽出唯一的纯 `GroundTrackingPolicy`。纯策略只根据显式输入计算结果，不读取或修改 Session、Runtime、worker、墙钟或全局状态。

它至少接收：

- 当前 `PhysicsState`；
- 直线或 L 形地面路线；
- `GroundCompletionRegion`；
- 身体、地面模式和规则版本；
- 当前世界查询视图；
- 本 tick 的输入资格和停止尾迹约束。

它返回类型化结果：下一步候选输入、预测状态、路线进度、安全依赖，以及完成、继续、需要重锚、需要重规划或不支持等结论。

规划阶段用这份策略做有限 rollout，估计路线是否可跟踪和预计 tick 成本。正式执行中的 `FixedRouteController` 也调用同一份策略逐 tick 选键。不能保留一套“规划器地面控制”和另一套“执行器地面控制”。

### 3. Terminal edge 保存可复核的计划信息

`SurfaceTerminalApproachEdge` 仍是真实搜索边，但不再宣称持有覆盖整个入口窗口的形式证明。它保存：

- 稳定的末段身份；
- terminal surface 和 completion region；
- 直线、X→Z 或 Z→X 路线；
- `GroundTrackingPolicy` 版本；
- rollout 得到的预计 tick 成本；
- 支撑、净空、碰撞、完成区域和规则依赖；
- 适用的姿态与地面模式。

搜索把预计 tick 成本计入 `g` 值。需要移动的末段必须使用正成本；已经满足完成条件的末段可以是零输入、零 tick。

搜索边保存的是路线和策略依据，不是未来逐 tick 输入脚本。执行阶段不会假装实际身体状态与 rollout 的代表状态完全相同。

### 4. 执行从真实身体状态接纳并重锚

RouteAdmitter 接纳末段时，使用最新正式观察检查：

- 身体仍为已声明的 `STANDING + WALK`；
- 当前支撑、净空和碰撞事实足以安全开始；
- completion region、规则版本和相关依赖仍有效；
- 当前身体可以映射到路线走廊中的一个确定进度。

满足条件后，从真实位置和速度重锚路线进度。接纳器不要求真实状态等于规划 rollout 的代表状态，也不重新选择另一条末段路线。

无法安全映射时返回类型化拒绝或请求重新规划。不能把入口改成零速，也不能现场扩大 completion region。

### 5. 每 tick 只接受当前可证明安全的输入

正式执行每 tick 都使用当前观察和统一几何查询检查下一步输入。至少包括：

- 当前身体与预计支撑关系；
- 下一步扫掠净空和碰撞；
- 路线走廊与完成区域；
- 输入租约；
- 松键后的停止尾迹；
- 进度与停滞。

只有在“当前输入有效期间及停止尾迹均安全”时，策略才允许发送非中性输入。没有安全输入时，控制器停止推进并返回类型化结果。连续无进展达到上限后，从当前观察有界重规划，不能无限等待或无限提交同一工作。

### 6. 候选与成本

首版只生成三类确定性末段路线：

1. 直线；
2. 先走 X、再走 Z；
3. 先走 Z、再走 X。

退化路线去重。每条路线都由 `GroundTrackingPolicy` rollout 得到预计 tick 成本，再由 A* 一次比较完整路线成本。

不使用完成区域面积阈值；不在 A* 外按候选重试；不修改通用 `_plain_search()` 或 `_resource_aware_search()` 循环；不按墙钟先后选择结果。

### 7. 与 D079 的关系

本决定修订 [D079](0079-model-terminal-approach-as-a-real-search-edge.md) 的以下要求：

- 普通 `STANDING + WALK` 末段不再要求证明整个 `SegmentEntryWindow`；
- `GroundTerminalApproach` 不再保存一份必须原样执行的正式输入计划；
- 搜索、接纳和执行共享的是路线、completion、策略版本、依赖和成本口径；
- 接纳和执行允许基于真实观测重锚，并由同一策略重新计算本 tick 输入。

D079 的这些结论继续有效：末段是搜索边；末段成本进入 A*；区域目标仍由一次后台 A* 处理；不用虚拟汇点；不用候选面外层重试；UNKNOWN 不能当安全事实；通用 A* 循环不改。

F2-ST 保留已经冻结的 9 项 RED、typed 出口要求、typed 正常否定、`SurfaceTerminalApproachEdge` 和 `terminal_approach_id` 数据契约。F2-ST 仍记为未通过，不回写历史结果。

## 边界

- 首版只支持普通 `STANDING + WALK`；
- 不加入 Sprint、Sneak、Crawl、Swim、Climb 或新的动作；
- 不做任意角度平滑，只支持直线和两种 L 形；
- 不新增 Session 状态、等待、重试或候选队列；
- 不降低支撑、净空、碰撞、UNKNOWN、伤害和输入期限门槛；
- 不把规划 rollout 当成正式安全证书；
- 不改变严格动作的入口、轨迹和落地证明。

## 后续

按 [F2-GP 阶段方案](../stages/F2GP-shared-ground-tracking-policy.md)实施。F2-GP 通过后，回到 F2-SG 的停止点完成原大集合、性能和 Fabric。它不会自动关闭 F2-SG、F2-S 或路线优化器。

## 首轮实施反馈

`61fefa78` 已完成本决定的第一部分：`FixedRoute` 和规划 rollout 可以复用同一个纯 `GroundTrackingPolicy`，直线和两种 L 形路线也有统一的有界 rollout。

本决定关于 terminal edge、A* 成本和真实状态重锚的部分尚未落地。F2S-C-04 暴露了一个更低层的问题。首轮把它概括成“两 tick 输入租约和松键尾迹冲突”，两轮局部评分修正均失败，未提交接线已撤销。

后续复核确认，正式普通 Walk 已按玩家 tick提交输入，真正的不一致在纯策略内部：候选仍固定按两 tick同向输入评分，再计算松键尾迹。窄完成区域前，一 tick可以安全进入并开始制动，固定两 tick模型却提前拒绝。

[D081](0081-select-ground-control-duration-from-stopping-margin.md) 因此决定：按停止距离和 completion 余量在一／两 tick之间选择；一 tick仍验证完整停止尾迹；policy、`FixedRouteDecision` 和移动意图使用同一个 `control_ticks`。精细一 tick输入不取得 D068 的晚启动余量。本决定继续作为共享策略的方向约束，但不能据此宣称 F2-GP 已实现。
