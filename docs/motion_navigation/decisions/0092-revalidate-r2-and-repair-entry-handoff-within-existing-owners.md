# D092：重新验证 R2，并限定修复动作入口交接

日期：2026-10-09。状态：已采用，依据用户对先完成四步工作的授权。

## 要解决的问题

R2 因修订帧 P95 超过 8 ms 停止，但 R0 的同类帧已经超过这个目标。两次测量的样本也不足以判断分位数。原停止不能证明候选退步。

柱顶 24 项另有两处交接缺陷：下一入口声明了朝向，前段却没有安排转头；接近期间的旧否定结果被当作真实失败计费。它们在 F2-R 中已经存在，继续按 D091 与区域几何分开验收。

## 决定和顺序

1. 修订 R2 门槛，恢复隔离候选，重新采集 Windows 证据并签署。
2. 完成 F2REC 的 R3 清理和 R4 恢复验收。
3. 单独实施动作入口交接修复。
4. 完成正式调用链、回归和 Fabric 验收，再讨论更广的连续运动优化。

前一步未通过，不启动后一步。方案分别见 [恢复阶段](../stages/F2REC-rebuild-from-f2r.md)和[入口交接阶段](../stages/action-entry-handoff-repair.md)。

## R2 的性能口径

在同一台 Windows 机器、同一 Python 环境下交错运行 R0 和 R2。固定场景、目标修订序列、预热规则和分位数计算方法，至少各取得 200 个有效修订帧。两个版本都从 Runtime 外壳开始计时，规划计算和模拟后端另列，不混入 production。

修订层要求 R2 的 P95、P99 均不高于交错重跑的 R0。8 ms 的修订帧目标按 D089 继续登记为性能债。整体 production 仍要求 P95 ≤ 8 ms、P99 ≤ 15 ms、最大值 < 30 ms；完整路径最大值 < 50 ms，deadline miss 为 0。不能用历史的 19 帧直接签署。

候选从 `archive/f2rec-r2-stopped-20261009` 按文件恢复。只恢复已审查的选面实现和必要检查，不将旧停止文档覆盖当前记录。旧失败、停止记录与原证据保持原字节。最终候选必须通过完整 Windows 正序和逆序。

这次重新验证来自门槛纠正，不授权第三轮选面或控制优化。新性能证据仍不通过时，停止并报告。

## 动作交接的边界

入口朝向由 `SegmentEntryWindow.required_yaw_radians` 声明。当前路线执行器负责在前段末尾提出视角，沿用本帧最终视角计算地面移动。只有真实观察满足入口要求，下一动作才可启动。不得按 JumpUp 名称写新的交接分支，也不得放宽原朝向、速度、支撑或证明条件。

下一动作尚未开始时，基于旧预计身体状态的否定结果只作废旧计算，不购买一次真实动作失败。这个判断使用有类型的结果或明确的布尔事实，不能比较 `motion_negative_basis_changed` 文案。当前入口的真实失败仍沿用三次上限。

每个连接最多一个活动作业；作废必须走现有工作退场入口。前段停滞、视角等待和准备耗时继续使用原有限预算。不能通过不计失败获得无限提交或无限等待。

## 与既有决定的关系

本决定只替换 D090 中 R2 单独的修订帧绝对门槛和对应性能止损解释。D090 的恢复清单、旧成功零退步、墙钟边界和公开全绿规则不变。

D091 的柱顶 RED 保留为恢复阶段事实；进入独立交接阶段后，将同一批 24 项作为待修正例，不回写历史结果。暂不实施状态格、通用 MPC、路线优化器、新动作或全面动作接口迁移。
