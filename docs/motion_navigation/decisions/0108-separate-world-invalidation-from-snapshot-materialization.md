# D108：把世界失效与快照物化分开，并修复有界验证工具

日期：2026-10-15。状态：**已实施；B10 不退步门槛未关闭。**

## 要解决什么问题

D107 已修复纯证据刷新造成的重复 section 重建，但重建成本仍集中在两条未被 F1 覆盖的路径：

- worker 借用小范围快照时，会在全局锁内物化所有待更新 section；
- 看到新地形、挖掉或放下方块时，观察线程会立即物化整个相关 section。

这两条路径会让 20 Hz 控制线程等待数十到数百毫秒。分片运行器也只终止直接子进程，模块留下孙进程时，名义上的超时不能保证命令按时返回。

## 决定

### 1. 观察线程只维护权威事实和安全失效

观察到变化时必须立即完成：

- 更新实时世界事实；
- 推进几何、证据和单格依赖版本；
- 使覆盖变化位置的已发布快照失效；
- 标记需要重新物化的 section。

观察线程不再构造 `ImmutableWorldSection`。这不改变 UNKNOWN、依赖检查或伤害规则。

### 2. 借用只物化请求范围

`borrow_snapshot_version()` 只物化本次 bounds 相交的待更新 section。范围外 section 保持待更新，后续相关借用再处理。

几何变化必须立即移除当前缓存引用，防止内部代码误读旧 section。已经借出的版本继续持有自己的不可变对象，不被原地修改。

section 被淘汰或最后一个事实被移除时，同时清理缓存和无须继续物化的脏标记。缓存与脏集合必须受实时世界容量约束。

首版仍允许在全局锁内物化相关 section。若真实 B10 bounds 或 Windows 量尺仍超过 8／15／30 ms，再单独决定是否采用“锁内复制事实、锁外构造、锁内核对版本”的两阶段实现，不提前增加复杂度。

### 3. 分片器必须终止整棵进程树

模块超时时，运行器按 PID 和创建时间登记并终止根进程及后代。清理、强杀和输出收尾都必须有期限。留下孙进程、管道不关闭或清理失败时，报告必须明确失败，不能继续无限等待。

发现 0 项测试的模块记为错误，不能算通过。

### 4. 确定性单测与生产时序证据分开

现有 `wait_for_receiver()` 屏障保留，用于表达确定性业务语义。另补不依赖该屏障的正式链时序矩阵，覆盖结果晚 0、1、2 movement tick，以及 SOLVE、REVALIDATE 和旧世代结果。

trace 同时报告整帧、后端、阻塞 I/O 和 `runtime_outside_backend_ns`。计算门槛使用 `runtime_outside_backend_ns`，不能把约 50 ms 的服务器 tick 周期当成 Python 计算耗时。

### 5. 平台边界

Windows 继续是正式门槛平台，默认单模块上限保持 300 秒。Linux 补充复核显式使用 600 秒。

POSIX Queue feeder 重复关闭文件描述符是真实资源问题，单独修复并保留 Windows 生命周期回归。公开文档并列报告：主项目 Windows 为 184 个模块、2264 项；公开快照不含 46 MiB 本地原始证据，对应 183 个模块、2240 项。

## 完成条件

- 无关脏 section 数量不再影响小范围借用时间；
- 语义变化观察不再构造不可变 section，依赖和旧快照仍立即失效；
- 快照缓存及脏集合保持有界；
- 3 秒超时的孙进程反例在固定收尾期限内结束，后代全部退出；
- 0 测试模块被拒绝；
- receiver 晚 0—2 tick 的正式链检查有界且分类正确；
- 修正后的 trace 使用正确字段；
- Windows 完整正序、逆序通过；
- 完成上述检查后，重新运行 B10 Fabric，并如实保留结果。

连续两跳、零等待交接、新动作和同步起始证明门槛仍不在 D108 范围内。

## 实施结果

观察热路径、按范围物化、分片进程树终止、receiver 晚到矩阵和正确 trace 字段都已落地。A5-R2 又把 B10 自身六类 JSONL、Runtime trace 和 F-TICK 从控制 tick 的同步写盘路径移走；收尾批写失败不会覆盖已经发生的主异常。A5-R3 让 receiver 去重集合只登记真正进入有界缓冲的记录，并把旧 A5 的含混 ready 字段改为 legacy 证据。现有协议只能测 receiver 观察、注册发布和控制消费，不能测 worker 实际完成时刻。最近一次完整结果仍是 A5-R2：Windows 主源码正序、逆序各 186／186 个模块、2307 项，独立公开快照正序、逆序各 185／185 个模块、2283 项。Linux 动态生命周期矩阵仍待三方复核。

B10 四方向时间线为 40／40 下一 movement tick。去掉同步文件 I/O 后，控制线程自身 P95 降到 0.8191 ms，批次仍在约 3200 个 50 ms 游戏 tick 后触发 `deadline_exceeded`。后续复核确认，D108 四次命令都遗漏了 `--timeout-seconds 600`，实际任务预算只有 215 秒；最近一次停止前已经完成 24 个 R4 试次。因此该失败应登记为探针总预算待复验，不能直接归因到 R4 运动逻辑。清理阶段又用 `formal Runtime must be ready` 覆盖原始失败。ordered source 显式注销失败，但会在 Runtime 最终关闭时由 `arbiter.clear()` 清除。D109 将先按当前 HEAD 重跑 600 秒诊断，再处理清理与生命周期边界。B10 不退步条件仍未关闭，不能据此恢复连续两跳或新动作。
