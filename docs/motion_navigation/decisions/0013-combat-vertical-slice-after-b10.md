# D013：B10 后先做战斗纵切片

日期：2026-09-23
状态：采用

## 要解决的问题

B10 已经把状态锚点、后台规划、动作求解、接纳、输入回执和局部执行接成一条完整链。若继续只增加运动种类，很多模块会各自变厚，却不能尽早证明这套边界能否服务第二类任务。

战斗同时需要目标管理、局部移动、朝向、动作时序、取消和世界变化。做一个很小的战斗纵切片，可以尽早检查这些公共接口是否真的能复用，而不是等所有移动能力完成后才发现架构仍只适合导航。

## 决定

1. B10 当前冻结范围收口后，下一项新能力是 C1 战斗纵切片。
2. C1 只取一个范围明确、观察完整、无需主动改变世界的试点。它复用现有状态、目标、规划、物理、输入和接纳链，不另建第二套逐 tick 控制体系。
3. 原 B11 改为放方块、搭桥等会改变世界的动作。
4. 原 B12 改为部分观察下的战斗，用来验证目标暂时消失、遮挡和信息不足时的行为。
5. 特殊地面、攀爬、流体和其余移动能力没有被取消。它们的具体编号在 C1 范围冻结时重新排定，不能为了沿用旧编号把职责混在一起。

## 影响

- 当前 B10-C 的完成结论不变。
- C1 不是完整战斗系统，也不引入学习；它只验证一条可验收的端到端能力链。
- B11、B12 开始前分别写清主动改世界和部分观察的权限、失败分类与验收边界。
