# D125：先验证三个必要事实能否在提交前观察

日期：2026-10-21。状态：**PARTIAL／STOPPED**。D125-0 已运行并命中预登记停止条件；D125-1／D125-2 未开始。

四方向结果一致。起点平台前缘的安全站位能在同一帧看见 parent-only 和 successor-only 两格；同时属于 parent 和 successor 的格子，从起点侧安全站位始终被中间平台遮挡，只能在第一跳后的中间平台看见。只缺该格时正式 proof 仍返回 `NEEDS_WORLD`。因此当前固定地形形成“先跳才能看见、先看见才能证明第一跳”的循环。本阶段没有修改生产代码，也没有启动 Minecraft、Fabric 或运动 trial。

依据：[D124 验收](../acceptance/d124-proof-dependency-projection.md)、[D123 验收](../acceptance/d123-proof-dependency-and-transport-loss.md)和[实施计划](../stages/d125-three-required-fact-observation-plan.md)。

## 要解决的问题

D124 已把每个方向的证明依赖从 67 格收窄到 58 格。原来 12 个未知下层格中，9 格已经证明不影响动作；另外 3 格仍会改变第一跳恢复证明或第二跳证明。它们未知时必须继续返回 `NEEDS_WORLD`。

下一步不能直接增加一个“观察动作”。必须先确认：机器人能否在第一跳承诺前，从安全站位真实看见这 3 格。如果看不见，增加状态机只会把任务从立即拒绝改成永久等待。

## 决定

先执行 D125-0，只做有界、只读的可见性和证明前置关系验证：

1. 使用 D124 冻结的 1-1-4 地形、58 格依赖和现有 Windows native 可见性核心。
2. 只检查仍与起点平台保持安全支撑的站位，以及中间平台上的对照站位。
3. 记录每个必要格属于 parent、successor 还是两者，以及它在第一跳提交前是否可见。
4. 不把 fixture 真值写入 WorldModel，不把 `UNKNOWN` 当成 `AIR`，不启动 Minecraft 或运动 trial。
5. 任一 parent 必要格只能在第一跳之后看见，就停止 D125。D125-1 和 D125-2 不自动开始。

只有 D125-0 证明所有 3 格都能在安全的提交前站位取得，才允许复用现有信息拥有者和身体监督者实现窄观察动作。届时仍不得新增 Session 状态或通用视点规划器。

## 为什么这样做

现有系统已经有多格观察请求、事实等待、身体所有者、停止请求、超时和安全释放。当前未知的是几何上是否存在可行站位。先验证这一点，可以把“缺少代码”与“任务本身不可行”分开。

`LandingEdgeProbe` 只服务单个直降落点。它的证据、站位和 grant 都绑定一个 `landing_cell`，不能用来冒充普通 proof facts 的通用观察动作。

## 范围

D125 可以修改只读脚本、检查、紧凑证据和四类文档。若 D125-0 通过，后续生产改动只能落在现有 observation／information acquisition／supervisor 边界。

本阶段不修改 Session、transport、Java、planner、动作求解、连续跳跃和证明安全语义，也不运行 Fabric。

D123-2 继续单独处理传输结果。D125 和 D123-2 都通过后，才允许进入 D123-3 Fabric smoke 和矩阵；随后再恢复连续两跳产品阶段。

## 停止条件

出现以下任一情况就保存证据并停止：

- 某个 parent 必要格只能在第一跳承诺后看见；
- 需要进入地下、穿墙、离开安全支撑或使用隐藏事实；
- 需要通用视点搜索、新 sensing、新 Session 状态或 Java／wire 修改；
- 只取得部分事实时必须放宽证明才能继续。

停止只说明当前固定地形与权限下不能完成提交前观察，不否定以后使用历史地图事实、改变路线／地形或重新设计第一跳安全尾段。

## D126 纠偏

2026-10-21，D125 保留为“如果只允许当前相机取证，会发生什么”的视觉诊断。当前阶段只验证已知地图运动，因此 D125 不再阻塞 D123-2 或后续运动验收，也不授权开发主动感知。

D125 的停止结论和原始证据不变。需要主动感知时再另立产品阶段，届时重新使用这些诊断结果。
