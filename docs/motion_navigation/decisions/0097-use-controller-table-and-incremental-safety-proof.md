# D097：用确定性控制器、离线参数表和增量安全证明继续连续运动

日期：2026-10-10。状态：M0 未通过，停止于 M0；M1—M4 未授权。

M0 在 Windows 上按冻结口径完成三次正式采集。22 个原正例、6 个负例和混合动作元反例的分类全部正确；已知输入 rollout、lazy step 估算和负例成本也满足参考线。但混合动作元反例的控制器参数探测最大耗时分别为 587.9 ms、591.2 ms 和 736.9 ms，稳定超过正例 400 ms 上限。按本决定第 7 节停止，不进入 M1，也不调整冻结反例、枚举顺序或门槛。结果见[验收](../acceptance/continuous-motion-incremental-proof.md)和 `evidence/motion_navigation/incremental-motion-m0-v1/`。

## 1. 要解决的问题

[D096](0096-repair-trajectory-proof-and-use-stable-motion-primitives.md) 已证明，分层穷举式在线搜索不适合继续承担连续短轨迹：修正地面、起跳和空中输入的独立组合后，三个冻结正例都耗尽 65,536 次物理计算预算；即使输入方案已知，执行前扫描整条候选的全部边界也要重复计算大量停车尾迹。

TP 保持结束。R2、R3 和 P0 的历史结论不改写。本决定开启一条新的限定路线，不延长 TP，也不把旧候选写成正式能力。

## 2. 决定

下一轮把连续运动拆成三个职责：

| 组件 | 回答什么 | 是否授予执行许可 |
|---|---|---|
| 确定性动作控制器 | 这个模板按什么规则产生逐 tick 输入 | 否 |
| 离线入口／出口表 | 当前入口优先选哪组离散参数，预计进入什么出口范围 | 否 |
| 增量安全证明 | 当前这一条命令现在能不能提交 | 是 |

停止当前“先穷尽低输入层，再进入高输入层”的在线搜索。原搜索和完整承诺扫描保留为离线对照、验收工具和历史复现入口。

本决定不永久禁止所有在线选择。承诺点之前可以在不超过三组离线参数中有界尝试；越过承诺点后只能执行已经证明的具体后缀，不能切换参数或控制者。

## 3. 控制器和表的合同

首版只处理 `JumpGap(1—3)`、`JumpUp` 和已知地面转向。普通 Walk、连续小高差和正式 B10 动作链仍由原 owner 负责，不建立第二套权威身体状态或输入出口。

控制器使用少量离散参数：步态、起跳触发距离、空中模式和落地模式。它根据名义分支生成输入；准时与晚一 tick 两支执行相同的输入值、顺序和提交序号。

每个离线表项必须保留完整关联：

```text
动作模板＋入口子域
→ 控制器参数
→ 候选承诺边界和恢复边界
→ 出口状态范围
→ 规则、计算器、Profile、生成器和世界模板身份
```

不得分别合并入口和出口后假设任意组合可互换。表项只推荐方案，不证明真实入口安全。查不到表项表示未求解或未支持，不表示物理不可达。

## 4. 增量安全证明

每次提交命令前，从当前不可变状态锚点和输入账本出发，检查按时与晚一 tick 两支。

- 下一条命令不会越过承诺点时：证明命令生效后的下一边界仍有安全停车尾迹。
- 下一条命令会越过承诺点时：生成并锁定一段具体输入后缀，证明两支从该边界到恢复支撑的轨迹、伤害、落地和停车尾迹。恢复安全支撑前只能执行这段后缀。
- 当前事实不再符合证明时：承诺前执行已经证明的停车尾迹；承诺后继续承担身体责任，并按现有动作链的失联和落地规则结束。

证明绑定状态锚点、在途和已应用输入、请求与目标代次、世界依赖、规则／计算器／Profile／表版本和任务伤害余额。UNKNOWN、身份过期、输入安排矛盾或依赖变化都不能取得新许可。

安全尾迹、风险区间、支撑判断和伤害计算复用现有扫描器的纯计算代码。正式链仍只有 Runtime 仲裁后的唯一输入出口。

## 5. 离线表的证据含义

入口分箱的抽样成功率只衡量表的可用性，不构成安全证明。M1 必须分别覆盖分箱中心、边界和角点，并保留独立验证集。每个实际入口仍要经过 M2 的在线证明。

离线表必须：

- 使用固定种子、确定性生成顺序和稳定序列化；
- 设最大表项数和字节上限；
- 保存生成命令、输入分布、规则身份和内容哈希；
- 规则、计算器、Profile 或生成器版本变化后拒绝旧表并重新生成；
- 报告不支持、缺信息和安全拒绝，不能把失败样本从分母删除。

## 6. 性能门槛

Windows 是正式平台。M0 的现有探针只判断方向是否值得继续，不能签署未实现的增量证明性能。

M2 实现后，至少预热三轮并采集不少于 200 个决定：

- 单次增量证明单独报告 P50、P95、P99 和最大值；
- 动作开始的双支 rollout 单独报告；
- 完整控制路径继续满足 P95≤8 ms、P99≤15 ms、最大值<30 ms；
- 增量证明不能用墙钟改变行为；超出控制期限时不提交新命令。

M0 的可行性参考线是：已知参数的单次安全决定预计 P95≤10 ms，动作开始 rollout 预计 P95≤15 ms。它们只决定是否进入 M1，不替代完整控制路径门槛。

## 7. 顺序和止损

| 阶段 | 交付 | 通过后进入 |
|---|---|---|
| M0 | Windows 只读成本与行为基线 | M1 |
| M1 | 纯函数控制器、带关联离线表和随机入口验证 | M2 |
| M2 | 真实增量证明、承诺后缀锁定、变异检查和正式性能 | M3 |
| M3 | 接入现有 B10 链的隔离闭环 | M4 |
| M4 | Fabric 验收 | 后续产品决定 |

任一阶段未通过即停止，不调整冻结场景或把允许失败重新分类。M1 最多允许一次分箱细化；M2 最多允许一次限定性能修正。M3 前不得修改正式 `mc2p` 动作链，M4 前不运行新的 Fabric 批次。

回退到旧 B10 求解只允许发生在尚未越过承诺点，或已经安全落地并重新锚定之后。空中和其他不可安全撤回阶段不能替换动作拥有者。

## 8. 不做什么

- 不把计算器迁到 Java 或原生代码；
- 不引入学习策略；
- 不建立通用状态格规划器；
- 不声明最优路径或完备搜索；
- 不自动把离线表生成的入口／出口兼容关系写成已验证接续能力；
- 不恢复已删除的潜行防坠状态机。
