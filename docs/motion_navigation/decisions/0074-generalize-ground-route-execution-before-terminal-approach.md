# D074：先让普通地面控制执行非中心路线，再交付终点接近

日期：2026-10-07。状态：已实施；冻结范围正式验收通过。

## 要解决的问题

终点贴墙、墙角、走廊尽头和平台边缘长期失败。直接为这些场景增加终点特判，可以改善当前产品结果，却不能支持未来的路线优化。路线优化会产生大量非中心中途路线，同样需要沿墙、靠边和连续跟踪。

现有控制器已经按连续折线计算进度。真正的缺口是安全判断过粗：预测碰墙就失败，靠边时不会使用经过证明的潜行，终点又被压成一个很小的点。

## 决定

1. 中心点搜索保持不变。搜索节点只用于找拓扑路线。
2. 普通地面控制器继续接收 `FixedRoute` 浮点折线，并正式声明支持非中心中途路线。
3. 开阔地保留快速预测。候选因已知碰撞或支撑边界失败时，最多对三个候选运行 1.21 计算器。
4. 已知无害墙面接触按碰撞后的真实结果判断。仍沿走廊前进可以接受；中途正面撞墙且没有进展仍然失败。
5. 潜行防坠由路线进度区间显式声明。实施后确认执行器只有组件证明，正式路线尚无区间生产者。下一产品阶段为路线优化器设计与交付，由它成为第一个正式生产者并补必须潜行的 Fabric；若该阶段被更换，先删除不可达状态机。
6. 终点只增加原 `GoalState` 内的完成区域和停止条件，不创建终点动作或另一套控制器。
7. 不降低未知、危险材质、支撑和严格动作门槛，不恢复后台终点筛选。

## 为什么这样做

需要删除的是“任何碰撞都危险”和“终点必须接近一个点”这类错误限制。安全性由计算器推演后的身体状态、支撑、路线进展和停止尾迹决定。

这使同一套控制可以处理：

- 偏离格心的直线和斜线；
- 沿墙切线及墙角路线；
- 从中心线进入非中心线；
- 终点贴墙自然停住；
- 契约明确允许的潜行边缘路线。

## 没有采用的做法

- 没有为贴墙、墙角和走廊分别增加控制分支；
- 没有新建通用插件系统或第二套路线类型；
- 没有让所有候选都运行完整物理计算；
- 没有把整条路线优化器提前塞入本阶段；
- 没有通过降低身体宽度、支撑比例或扩大目标来提高成功率。

## 代价和止损

靠近墙面或边缘的少数控制帧会增加完整物理计算。候选数固定为三个，并继续执行完整输入租约和停止尾迹。

如果实现要求修改 Session、ExecutionSupervisor 或 Runtime 生命周期，或者需要按场景名称分支，说明边界设计失败，应停止实施并修正方案。

架构见[连续地面路线执行 V1](../architecture/continuous-ground-route-execution-v1.md)，阶段见[F2 方案](../stages/F2-non-center-ground-route-execution.md)，验收见[F2 验收](../acceptance/F2-non-center-ground-route-execution.md)。

## 实施后的补充取舍

实机证明了多点折线的首条启动余量缺口。处理仍沿用原单 tick 命令和输入账本。只有首次静止入口的一 tick 中性前缀能由现有计算器证明、并与原入口状态等价时，才允许首条命令晚一 tick 开始。原候选的完整租约与停止尾迹证明继续有效。该取舍不按路线点数、场景或方向放宽，也不修改生命周期或空中动作证明。

连续高度与严格动作保持原证明。完成区域首版仍限于常高普通 Walk 的精确轴对齐矩形；F2-R 按 D075 选择障碍裁剪后的最大精确块。原目标内有普通安全点时优先使用，平台边缘用例不强制潜行，不作为潜行实机证据。正式路线尚无 `SNEAK_EDGE_GUARD` 生产者；本阶段没有新增优化器。

正式 Windows 组合结果、原目标证明、三类持续输入参照和新增实机失败分别保存。移动活塞的邻格碰撞盒超出当前观察表示范围时明确失败，不为外力验收扩展观察协议；无伤害外力改用原版实体碰撞，只签署实际有界安全结果。
