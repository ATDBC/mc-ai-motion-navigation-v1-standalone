# D043：为等待退场、规划期限和门禁口径重新打开 S5

日期：2026-09-30

## 决定

导航协调 S5 重新打开。连续高度 M3 的既有能力和 Fabric 结论保持关闭状态。

本轮不新增协调模块。继续使用现有 `RetryLedger`、`PlanningPipelineState`、`KnownMapSnapshotBuilder` 和正式模拟门禁，并补齐它们各自已经声明但尚未完整执行的职责：

- 会话和动作退场时结束其拥有的活动等待；
- 规划调用方为已提交请求设置结果等待期限；
- 快照复制后的未知格整理也服从分片预算；
- 随机门禁只接受运行前冻结的结果，并区分事件生成、派发和应用。

## 原因

第二十二轮随机序列已经包含会话退场后残留等待的触发条件，但监视器没有观察活动等待，因此错误地允许其通过。后继会话复用任务账本时会立刻发生内部契约失败。这说明 S5 的“终态后没有活动等待”并未真正关闭。

后台规划和快照完成帧还各有一个调用方无法约束的等待或计算峰值。它们不会推翻当前分层，但会在常驻运行和未知区域扩大后形成永久等待或控制帧超时。

## 影响

- 任务级重试与风险历史继续跨会话保留。
- 活动等待不能跨拥有者生命周期保留。
- worker 内部计算预算和调用方结果等待期限分别记录，不能互相替代。
- 有界失败仍是合法验收结果，但原因必须预先冻结。
- 在本决定的关闭条件满足前，不恢复新的运动、探索或战斗能力开发。

## 实施结果

上述四项职责已经补齐并通过第二十三轮门禁。S5 于 2026-09-30 重新关闭。

随机门禁的允许结果按场景写入固定清单。门禁同时记录事件是否真正作用到后端，不再用生成数量代替覆盖数量。该变更只加强协调和验收，不改变运动计算器、正式视觉、输入仲裁或连续高度的能力范围，因此没有新增 Fabric 批次。

后续复审发现“真正作用到后端”的判断仍把重复空操作算成应用，规划期限也没有覆盖结果恰好返回的帧。D043 的历史决定保留；现行补充规则见 [D044](0044-planning-work-ownership-and-truthful-perturbation-evidence.md)。
