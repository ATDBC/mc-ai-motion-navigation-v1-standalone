# D090：从 F2-R 重建主线，只恢复独立验证过的部分

日期：2026-10-08。状态：已采用，恢复阶段进行中。

## 要解决的问题

F2-S 原本只处理支撑边缘目标。后续为少量失败连续加入多终点搜索、共享地面策略、逐帧十八候选验证、末段 beam search 和后台地面作业。运动导航生产代码因此增加约 7,000 行，普通地面控制明显变慢，公开完整检查也从 F2-R 的 `1647/1647` 变成有失败和错误。

这些改动不能继续在当前链条上逐项修补。主线先恢复到可验证的 F2-R 结构，再移植已经独立证明有效的部分。

## 基线与历史

- 公开 F2-R 提交为 `1ee76b6`；对应主项目来源提交为 `886ae1fc`。
- F2-R 完整检查实际运行于 `cc28816`，结果为 `1647/1647`，零失败、零错误、零跳过。
- 最终签署比较了 638 个核心文件，确认测试后的代码和夹具没有变化。
- F2-S 至 F2-RH 链固定在本地分支 `archive/f2s-f2rh-20261008` 和标签 `archive-f2s-f2rh-20261008`。
- 公开仓库不 force-push。当前公开提交继续保留在历史中，最终恢复快照通过普通前向提交发布。

## 恢复范围

### 移植

1. 障碍、UNKNOWN 和支撑门槛共用的完成区域网格；
2. 只复核路线已经绑定的矩形；
3. 几何与支撑查询缓存；
4. Session 使用区域查询选面，并限制实际查询数量；
5. 规划尾段保留已经证明的终点面；
6. D061 的 production、backend、full 三段计时；
7. v9 支撑边缘输入、稳定失败 ID 和独立可达标签。

### 撤出主线

- D078 的默认多终点规划、终点接近搜索边和终点 witness；
- D080—D082 的共享地面跟踪策略和一／两 tick 控制时长；
- D083—D085 的逐帧十八候选验证、墙钟候选预算和单一候选事实源；
- D086—D088 中只服务后台地面 beam 作业的代码。

这些代码、文档和证据继续保存在归档引用中。历史文档只增加状态说明，正文不改写。

### 删除

删除没有正式生产者的潜行防坠状态机。保留完成区域和普通路线执行契约。以后有正式路线生产者时，再按实际需求增加潜行区间。

## F2S-C-04 的处理顺序

先保留 F2-R 的选面排序。新区域查询只排除确实不可站立的面，不主动改变偏好顺序。

如果这种做法仍不能解决 F2S-C-04，才在同一个规划作业内增加一次受限回退：

1. 先搜索偏好面；
2. 只有搜索队列耗尽并确认无路时，才搜索目标区域内其他可站立面；
3. 两次搜索共享节点展开上限、墙钟期限、取消状态和请求世代；
4. 第一次搜索因时间或展开预算耗尽时，直接返回原有 typed 结果，不启动回退；
5. 不增加 Session 状态、重试、候选游标或新作业类型。

这属于限定无路回退，不恢复 D078 的默认多终点规划。

## 墙钟边界

普通地面逐帧控制、候选安全判断和选面结果不能读取墙钟来决定行为。后台规划可以保留已有墙钟期限，用于中止计算；超时不能被解释为“已经证明无路”，也不能触发目标集合回退。

## 发布规则

- 恢复分支每个检查点提交前，完整 `tests/motion_nav` 必须零失败、零错误、零跳过。
- 不允许用预期失败保存已知红色中间状态。
- 冻结量尺中的旧成功退步必须为 0。
- 公开 `main` 只接收最终签署的恢复快照，并且快照自身的完整检查必须全绿。
- 开发过程中先跑定向检查。只有检查点准备提交时，才运行该检查点要求的完整门槛。
