# D045：为规划行为所有权重新打开 S5

日期：2026-09-30

## 决定

导航协调 S5 再次打开。本轮不新增运动能力，也不进行第二次大重构。先把规划相关行为迁移到一个有明确边界的 `PlanningCoordinator`，用它关闭第二十四轮后发现的两个 P1：

- 信息请求不能由任意未知格决定，必须来自规划搜索实际受阻的位置；
- 依赖变化后的重新规划必须经过任务级 `RetryLedger`，不能直接生成无限代请求。

`NavigationSession` 的公开接口保持不变。现有规划 worker、`RouteAdmitter`、`RetryLedger`、生命周期表和身体监督者继续使用。R25 只迁移已经存在的规划编排行为，不建立插件系统，不改运动计算器，也不同时重构 `ActionRouteExecutor`。

## 原因

第二十四轮修复了空转规划状态，但把“范围不完整的第一个证据”同时当成“下一步必须取得的信息”。路径外且难以观察的未知格因此可能挡住路径上的真正阻塞格。

第二十四轮还在依赖变化时直接重发请求。每一代请求都有期限，但这些失败没有进入任务级重试账本，地形反复变化时可以无限生成新请求。

两个问题都说明：`PlanningPipelineState` 已经拥有规划状态，规划的推进、失败和重试行为却仍散落在 `NavigationSession`。继续增加局部分支只能解决单个现象，不能保证其他规划出口遵守相同规则。

## 影响

- `KnownMapSnapshotBuilder` 只负责产生不可变世界快照和范围完整性，不再选择观察目标。区块段版本变化只是重新核对的信号，正常增加知识和范围外变化不能直接算作失败。
- 表面规划在端点解析和搜索过程中收集有界的阻塞事实，并只在没有已知路线时随候选返回。前一批事实不可获取时，必须能在固定期限内尝试后续批次。
- `PlanningCoordinator` 统一管理快照、规划尝试、一次性请求许可、调用方期限、候选消费、路线接纳和规划失败登记。
- 正常目标修订、取得阻塞事实、确认世界交互和安全重锚不是失败重试。它们各自产生只能使用一次的规划许可；内部失败只能使用 `RetryLedger` 返回且尚未消费的许可。
- `NavigationSession` 根据协调器返回的类型化结果更新任务状态，并继续通过 `ExecutionSupervisor` 处理安全交接。
- R25 关闭后，才开始运动段执行适配层和其余会话瘦身；这些工作另立阶段，不混入本轮验收。

profile 4 Fabric 代表批次 `20260930T070421228037Z-9393f4c4` 证明真实观察链先取得路径阻塞事实，再开始移动；路径外比较格没有遮蔽该事实。公开独立版导出和哈希校验也已通过。R25 的关闭条件全部满足，S5 重新关闭。
