# D020：补齐导航交接、受击兜底和攻击确认

日期：2026-09-25
状态：采用

## 要解决的问题

C1-R 首轮完成后，三方复审发现四个问题：

1. 战斗通过导航桥调用会话时，没有传入当前状态锚点和 Runtime 输入账本。平地能走，但跨隙动作会一直等待验证。
2. 更新目标或取消路线时，会话立即丢弃执行器。机器人若正在空中，后续落地便没有责任方。
3. 圆石、沙子、深板岩、进食和部分状态效果尚未进入 B09-R 的预测范围。计算器返回“不支持”后，真实受击也可能得不到恢复。
4. 目标处于原版受伤无敌时间时继续挥击，通常不会产生新的有效伤害。旧确认规则会把这种无效挥击当成整个战斗任务失败。

复审还指出，失败处置、短暂观察缺口、恢复次数耗尽和移动攻击组合仍有未闭合的分支。

## 决定

1. `RuntimeNavigationDriver` 每帧从正式观察和 Runtime 输入账本取得状态锚点，再把二者交给 `NavigationSession.propose()`。技能不得传空值绕过动作验证。
2. 目标修订只启动新规划，不立即撤销当前安全前段。新路线准备好之前，旧执行器继续照管身体。
3. 取消或替换发生在空中时，原执行器持续执行自己的取消和落地尾段。只有它到达终态，或把责任明确交给恢复控制器后，才能释放输入所有权。
4. 运动残差明确为 `DEVIATION` 时，结合伤害事实形成 `DAMAGE_KNOCKBACK`。若计算器因当前姿态、效果或材质返回 `UNSUPPORTED` 或 `INVALID_INPUT`，伤害事实形成 `DAMAGE_WITH_UNVERIFIED_MOTION`，触发保守恢复，但不宣称已证明击退。
5. 缺少世界格或输入回执时先等待必要证据，不使用上述兜底冒充完整残差。D021 后续补充了等待上限：超过八个运动 tick 后仍无法补齐残差，但真实伤害事实仍成立时，明确转为“运动未验证”的保守恢复事件。
6. 新攻击要等目标的受伤动画归零后再提交。上一击可以通过生命下降、明确死亡或新的受伤变化确认；确认不确定时只进行有界重试，随后返回任务策略。
7. 客户端若只拒绝攻击操作，已经接纳的同帧移动仍按原请求执行并记录，回执使用 `operation_rejected`。世界、界面、玩家死亡或期限过期等整帧条件失败时，仍拒绝完整动作。
8. 观察短暂缺口不自动撤销活动路线，也不因单次攻击无法取得目标视觉而终止整个战斗。当前攻击尝试结束后，有效交战记忆把控制交回重新观察流程。第五次外部运动事件先完成当前身体恢复，再把“需要任务决策”交给战斗层。
9. 固定地面行走允许在战斗视角与导航视角相差不超过 5° 时继续移动。台阶、跳跃、下降和其他依赖精确朝向的动作不使用这个容差。

## 为什么这样做

状态锚点和输入账本是动作证明的一部分。战斗调用导航时缺少它们，等于只接上了寻路结果，没有接上可执行性证明。

更新目标和取消命令只改变任务意图，不能抹掉身体已经处于空中的事实。让原执行器完成落地，能保持“任一时刻只有一个身体责任方”的不变量。

对尚未建模的材质和状态，当前阶段无法精确重演运动。真实伤害仍说明旧运动证明已经不可靠，因此先进入保守恢复更安全。事件名称保留“不曾验证运动”的事实，避免把安全兜底误写成准确归因。

原版无敌时间内重复攻击没有收益。等待动画结束能避免稳定地产生无效攻击，也给后续不同武器或穿透能力保留独立规则入口。

## 证据边界

- 圆石、沙子、深板岩和状态效果仍未获得完整运动模型。本决定只补齐受击时的安全兜底，不把这些条件声明为已精确预测。
- 5° 容差只服务普通地面跟踪。它不是空中动作的通用视角放宽。
- 正式 Fabric 回归继续使用已冻结的普通平地。未建模材质和状态的兜底由确定性契约测试验证，后续补充对应实机场景时再扩大证据范围。
