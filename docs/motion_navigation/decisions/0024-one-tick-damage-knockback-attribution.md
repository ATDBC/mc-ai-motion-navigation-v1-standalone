# D024：伤害与击退允许相差一个运动 tick

日期：2026-09-25
状态：采用

## 要解决的问题

公开的 C1-C 通过批次包含 33 次真实受击。其中一次先在运动 tick 448 记录扣血，但 447→448 的运动仍符合预测；击退到 448→449 才出现。旧检测器立即把前一条定为“有伤害、无位移”，随后又把击退记成“无来源外力”。恢复仍然成功，但来源被拆错了。

以后如果活塞、实体挤压和受击采用不同策略，这种拆分会让上层选择错误分支。

## 决定

1. 伤害所在 tick 已出现预测外运动时，立即形成 `DAMAGE_KNOCKBACK`，现有路径不变。
2. 伤害所在 tick 的运动符合预测时，暂不形成“只有伤害”的最终结论。检测器保存该伤害事实，再等紧接着的一个运动 tick。
3. 下一运动 tick 出现预测外运动时，把它与原伤害合并成一个 `DAMAGE_KNOCKBACK`。事件继续使用原伤害的观察序号、运动 tick 和生命变化。
4. 下一运动 tick 仍符合预测时，确认只有伤害，不启动位移恢复。
5. 偏差晚于这个相邻窗口才出现时，不得认领旧伤害。它仍按 `UNATTRIBUTED_EXTERNAL_MOTION` 或其他已证明来源处理。
6. 世界格或输入证据缺失时，继续沿用已有的有界等待和保守恢复规则。这个决定不扩大 8 tick 的证据补全上限。

## 为什么只等一个 tick

真实记录直接证明了一个 tick 的生效差。把窗口继续放大会增加错误合并：一次着火扣血后，稍晚发生的活塞推动可能被误认为伤害击退。一个相邻 tick 足以覆盖现有证据，同时保持来源之间的边界。

## 证据和边界

- 回归测试采用公开批次中的观察序号 445／446 和运动 tick 448／449，证明两条旧事件合并成一次受击击退。
- 另一个反例让偏差从 tick 22→23 才出现，证明超出相邻窗口的运动不会认领 tick 21 的伤害。
- 历史公开归档保持原字节和原判定。它用于说明旧版本当时如何运行，不能被修复后的结果覆盖。
- 本次没有重跑 Fabric。它修正归因逻辑，不增加新的游戏内成功率结论。
