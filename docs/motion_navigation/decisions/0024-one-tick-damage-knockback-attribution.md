# D024：伤害与击退允许相差一个运动 tick

日期：2026-09-25
状态：采用

## 要解决的问题

当前公开的 C1-C 通过批次 `20260925T124344500270Z-ac8d6347` 包含 33 次真实受击。其中一次先在观察序号 445 记录扣血，下一观察才出现预测外运动。修正后的同一试次已经把两条记录合并成一次受击击退。旧版本曾把同类时序拆成“有伤害、无位移”和“无来源外力”。恢复仍然成功，但来源标签错误。

以后如果活塞、实体挤压和受击采用不同策略，这种拆分会让上层选择错误分支。

## 决定

1. 紧邻伤害 tick 的单段完整残差已经证明出现预测外运动时，立即形成 `DAMAGE_KNOCKBACK`，现有路径不变。横跨多个 tick 的偏差不能据此定位到伤害 tick。
2. 伤害所在 tick 的运动符合预测时，暂不形成“只有伤害”的最终结论。检测器保存该伤害事实，再等紧接着的一个运动 tick。
3. 下一运动 tick 出现预测外运动时，把它与原伤害合并成一个 `DAMAGE_KNOCKBACK`。事件继续使用原伤害的观察序号、运动 tick 和生命变化。
4. 下一运动 tick 仍符合预测时，确认只有伤害，不启动位移恢复。
5. 若相邻 tick 的完整残差已经证明运动符合预测，之后才出现的偏差不得认领旧伤害。它仍按 `UNATTRIBUTED_EXTERNAL_MOTION` 或其他已证明来源处理。
6. 若相邻 tick 因世界格或输入缺失而无法计算残差，伤害事实继续挂起。跨多个 tick 的完整匹配残差可以证明这段时间没有预测外运动；跨多个 tick 的偏差残差无法证明偏差具体发生在哪个 tick，只能产生 `DAMAGE_WITH_UNVERIFIED_MOTION`，不能标成击退，也不能改记成“来源不明”。
7. 证据持续缺失时继续沿用 8 tick 上限。到期后同样进入保守恢复，不无限等待。

## 为什么只等一个 tick

真实记录直接证明了一个 tick 的生效差。把窗口继续放大会增加错误合并：一次着火扣血后，稍晚发生的活塞推动可能被误认为伤害击退。一个相邻 tick 足以覆盖现有证据，同时保持来源之间的边界。

## 证据和边界

- 回归测试覆盖观察序号 445／446 的相邻受击时序；当前公开批次在运动 tick 451／452 附近提供同类实机证据，并已合并成一次 `damage_knockback_confirmed`。
- 一个反例先用完整残差证明相邻 tick 没有位移，再让更晚的偏差出现，证明它不会认领旧伤害。
- 另一个反例让相邻残差因缺世界格不可用，之后才出现完整偏差，证明结果为“伤害存在、运动未验证”，而不是“无来源外力”。
- 旧批次 `97bc0db8` 只保留在旧公开提交中，不再冒充当前证据。当前决定以新批次的原始记录和冻结回归测试为依据。
- 当前 C1-C Fabric 批次为 20／20 正例、10／10 反例；其中 33 次真实受击均进入已声明的恢复流程。
