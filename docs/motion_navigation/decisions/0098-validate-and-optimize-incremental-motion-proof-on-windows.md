# D098：先在 Windows 复测，再优化连续动作证明

日期：2026-10-11。状态：停止于 P3。W0、P1、P2 已完成；P3 的有界性和实验输入溯源检查通过，身体责任、安全与 8／15 ms 延迟门槛未通过。P4 未授权。实施结果见阶段计划与验收。

## 1. 要解决什么问题

[D097](0097-use-controller-table-and-incremental-safety-proof.md) 已在项目 M0 停止。三方随后在隔离目录完成 D097-A 试做：确定性控制器、离线表和逐次证明在固定模板上能够工作，但 Linux 的 G10 决定延迟没有通过预登记门槛。

这份试做还说明，在线成本主要来自重复的停车尾迹：控制器先模拟主轨迹，证明器再模拟一次主轨迹，并在每个边界重新计算停止过程。F1 只把这些计算提前，没有减少总物理步数。真实状态偏离预测后，提前结果会失效；这部分尚未验证。

D097 的失败结论不改写。本决定另开一个项目自有的隔离实验，回答两个问题：

1. 同一份试做在正式 Windows 平台上是否仍卡在性能门槛；
2. 不改变安全语义时，能否去掉确定的重复计算，并在真实偏离下保持期限和安全。

## 2. 决定

按以下顺序推进。W0 的复现完整性未通过就停止；W0 的性能未通过只记录基线，仍允许进入本决定已经预登记的不改语义优化：

1. 原样复跑三方提交 `f5e43e7` 的 Windows 计时，不修改参数、候选集合或 F1 的 60 步预算；
2. 把通过审查的控制器、表和逐次证明改写成项目自有实验模块；
3. 依次实现增量伤害、可信主轨迹复用和固定步数分摊；
4. 只有前述优化仍不足时，才研究物理状态的内部快速构造；公共输入和公共输出继续完整校验；
5. 在模拟闭环中注入真实状态偏离，测量证明作废和重算；
6. 全部通过后，另写决定授权正式链适配和 Fabric。

本轮不修改 `mc2p` 的正式动作链，不运行新的 Fabric 批次，也不把三方 `reviews/` 目录作为运行时依赖。

## 3. 两类性能门槛

Windows 原样复测沿用 D097-A 的探索门槛：

- 普通逐 tick 决定 P95≤10 ms；
- 越过承诺点的决定 P95≤50 ms；
- 至少 1,000 个普通决定；
- T2 和 T3 都要通过。

它们只决定是否值得继续，不代表正式控制链通过。正式闭环仍使用：

- 完整控制路径 P95≤8 ms；
- P99≤15 ms；
- 最大值<30 ms；
- 输入必须在当前许可窗口内提交。

所有报告同时保存 P50、P95、P99、最大值、physics step 数和样本数。墙钟不能参与控制器选择、证明结果或许可判断。

## 4. 允许的性能修正

### 4.1 增量伤害

把“已经结算的伤害”和“当前尚未落地的最大下落距离”随轨迹前缀保存。尾迹每增加一个状态只更新一次，不再从轨迹开头重算。

新实现必须与现有 `_damage(states)` 对所有冻结轨迹逐项一致。不能改变伤害额度、保守取整或多次落地的累计方式。

### 4.2 可信主轨迹

控制器生成输入时，同时输出不可变的 `ControllerRolloutTrace`。该对象只能由共享 rollout 内核通过模块私有签发器构造；直接构造、复制后改字段，或篡改字段后重新计算公开哈希都必须被拒绝。它至少绑定：

- 请求、目标和锚点身份；
- 两个时序分支；
- 输入序列和逐 tick 状态；
- 世界、规则、计算器和状态 schema；
- 依赖格及其事实；
- 任务剩余伤害、输入时序和停止输入；
- 前缀伤害状态和轨迹哈希。

证明器先验证签发来源、身份和哈希，再复用主轨迹。任一字段不匹配时拒绝复用，并从当前锚点重算。轨迹只减少重复模拟，不能直接授予执行许可。

### 4.3 固定步数分摊

校准集合只使用 A＋C。依次测量 24、32、40、48、60 步五个固定预算，选择第一个同时满足普通决定 P95≤8 ms、承诺决定 P95≤45 ms 的预算。选择后冻结，在集合 D 上只运行一次正式验证。

如果没有预算满足校准线，则本轮停止，不根据集合 D 的结果重新选择。

45 ms 只是探索组件的筛选线，不是对正式 30 ms 最大值的余量承诺。集合 D 已经参与 W0，属于冻结回归集，不是未见验证集。若根据 D 的结果调整实现，原 D 结果只能算开发反馈，必须另冻新的验证集合。

### 4.4 内部状态构造

这不是默认工作。只有完成前三项后仍未达到正式闭环门槛，才允许单独立项。

公共 `PhysicsState` 构造、外部输入、计算器入口和输出继续完整校验。不得直接删除 `__post_init__()`。如需优化，只能把已经校验且每步不变的字段放入内部上下文，并继续检查本次变化的位置、速度、姿态和有限性。

## 5. 偏离和提前计算

F1 只能缓存已经成立的正面证明。提前看到未来缺信息或未来依赖变化时，不能直接把它升级为当前失败；当前命令仍按当前边界的安全证明判断。

首版状态匹配只接受位置、速度、朝向等连续量在 `1e-9` 绝对误差内一致，离散字段完全一致。这个误差只吸收序列化尾差，不扩大物理入口。超出范围就使旧许可失效。

每个动作最多连续重证 3 次。实验使用同步证明，不设置“先等几 tick 再补证明”的窗口：当前决定内拿不到覆盖真实状态的证明，就不能提交依赖该证明的新命令。同一 tick 内的查表、重证和许可构造作为一个完整决定计时，不能分别满足期限后再相加。该场景按阶段和身体责任有界失败。

模拟闭环要在承诺前、承诺边界和承诺后三种阶段分别注入，至少覆盖：

- 输入按时和晚一 tick；
- 横向位置偏差 0.01／0.03 格；
- 朝向偏差 2°／5°；
- 无关格变化、依赖格变化和未知事实；
- 目标修订；
- 动作连续接续。

每组报告预计算作废率、重算次数、重算 P95／P99／最大值、额外停车、期限失败、伤害和安全违规。

- 承诺前偏离：旧许可失效，不提交不可撤回命令；从真实观察重算，或者使用仍覆盖真实状态的已证明停车尾迹。
- 承诺边界偏离：只有新的证明能覆盖真实状态时才允许越过承诺点，否则保持原 owner 并返回有类型的证明失败。
- 承诺后偏离：旧锁定后缀不再自动有效。原 owner 继续承担身体责任，从真实状态重新证明恢复后缀；没有新证明时不能更换控制者，也不能把旧后缀冒充安全。

如果现有控制器无法在期限内为承诺后偏离给出恢复证明，P3 记为未通过。本轮不为通过门槛临时增加未经证明的“中性输入”。

## 6. 明确不做

- 不把 Linux 结果换算成 Windows 通过；
- 不把 10／50 ms 探索门槛写成正式 8／15／30 ms 门槛；
- 不直接合入三方试做目录；
- 不把查表结果当作安全许可；
- 不使用 minimal 模式或减少证明边界；
- 不以平均每 tick 耗时代替延迟分位数和最大值；
- 不在本轮把表键扩展为任意几何；
- 不迁移到 Java、原生代码或学习策略。
