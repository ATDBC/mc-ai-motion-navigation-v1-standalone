# D094：失联后安全落地，从当前观察补走到目标

日期：2026-10-10。状态：已实施并验收通过。

## 要解决的问题

末次严格动作因输入失联安全落地后，身体可能离目标还差半格。D093 保留了正确原因，但仍直接结束任务。现有恢复入口和任务额度已经能够承担剩余行走。

## 决定

只有末次严格动作实际经过 INPUT_LOST、已经确认安全落地、当前仍着地且目标为 NOT_SATISFIED 时，执行器返回已有 NEEDS_REPLAN，并携带 StopCause.INPUT_LOST。正常落地目标不满足、空中或缺支撑信息不获得这个许可。执行器不自行生成 Walk。

Session 通过现有恢复入口申请重规划。交接拥有者保留本次恢复的原因；后续规划或恢复额度耗尽时，报告同时表达最终失败和发起恢复的 INPUT_LOST。替代路线成功接纳后关闭这次原因；之后的无关失败不继承它。清除目标与新任务也清除该原因，不增加 Session 状态或并行原因账本。

仅同一支撑面的 local direct 可以消费已观察到着地的低支撑起点。起点不得低于 FixedRouteConfig 的正式执行下限（当前 0.15）。低于规划余量 0.5 时，沿途支撑只能保持或增加；达到 0.5 后恢复原门槛，终点仍至少为 0.5。该资格及下限写入不可变复核配方；默认查询和其他调用者保持严格门槛。未知、碰撞、材质与依赖检查继续执行。

Fabric 只对显式声明生效 tick／窗口的输入判定期限失败。普通 Walk 的未声明窗口迟到单独报告 tick 差、次数和身体结果，不宣称 late1 安全。四方向夹具以 typed 路线进度定位普通 Walk 注入；产品实机优先注入既有严格空中命令，核对安全落地、重规划、着地补走、无二次跳跃。

最多两轮限定生产修正。D093 证据和正文保持原字节。正常落地泛化、轨迹原型、性能债和新预算系统均不进入本批。

D093 原证据、验收结论与正文不回写。两项冻结旧 FAILED 行为的当前测试改验新契约：返回 NEEDS_REPLAN，恢复前轨迹相同，之后着地补走且不再次跳跃。测试随现行行为更新，不能借此改写历史结果。

显式取消、关闭、完成和目标修订覆盖之前的恢复原因。STALE、BUSY、DUPLICATE、ACTIVITY_REQUIRED 请求均不改拥有者原因。只有这次恢复直接引发的规划或额度失败继续保留 INPUT_LOST。

## 实施结果

六族各一百种子的配对结果中，两个落点族分别从 41／100、35／100 提高到 99／100、99／100；共恢复 122 项，旧成功退步为 0。其余三个未完成仍是原有的 `motion_unsolvable:needs_state`。

Windows 完整正序、逆序各 1705／1705。v7、F2 528、v8、v9 均无旧成功退步，D058／D061 通过原整体性能门槛。

Fabric 四方向 4／4 完成。四次严格空中命令都在允许窗口后一 tick 实际生效，账本状态均为 `applied_outside_window`，实际偏移均为 2 tick；四次都在安全落地后保留 `INPUT_LOST`，重新规划并补走到目标。零伤害、额外严格期限违规、来源泄漏和二次起跳。
