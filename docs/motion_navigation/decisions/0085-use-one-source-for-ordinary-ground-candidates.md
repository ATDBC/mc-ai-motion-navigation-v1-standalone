# D085：普通地面候选只保留一个物理事实源

日期：2026-10-08。状态：已采纳；核心接线已实施，v8 发现历史成功退步后暂停。

## 要解决的问题

F2-WR 已经把世界安全与路线适用性分开，但正式控制链仍然有两套候选计算：

- `GroundTrackingPolicy` 先用简化模型生成、推演和筛选候选；
- `GroundCandidateVerifier` 再用正式 1.21 规则验证完整的 `9 × 2` 候选族。

两套计算使用的精度和职责不同。它们先后运行，使正式控制帧 P95 达到约 `26—28 ms`。即使去掉一处重复的 `safe_tail`，P95 仍约为 `16 ms`。更重要的是，两套结果可能对同一个输入给出不同的入口、停止位置和依赖，后续只能继续补映射和例外。

F2-WR 因行为与性能门槛同时失败，保持未通过。下一步不再优化两套模型之间的衔接，而是让正式验证报告成为普通地面候选的唯一物理事实源。

## 决定

### 1. 每个正式普通地面决策帧只验证一次

当身体处于 `STANDING + WALK`，并且本帧进入普通 `FixedRoute` 决策时，只调用一次 `GroundCandidateVerifier`。

这次调用必须返回完整的十八项候选：九种方向键组合，各有一 tick和两 tick许可。候选身份由下面三项组成：

```text
(forward, strafe, control_ticks)
```

同一帧不能再由 `GroundTrackingPolicy`、`FixedRoute` 或其他普通 Walk 分支独立推演第二套候选。

### 2. 验证报告显式保存执行需要的物理结果

每项候选至少保存：

- 候选身份和 typed 验证状态；
- `tracking_end`：声明方向输入前缀结束时的身体状态；
- `stopped_end`：随后持续中性输入并安全停稳后的身体状态；
- 验证过的前缀与中性尾迹；
- 实际读取的世界依赖；
- 使用正式计算器、普通地面内核或混合路径的诊断信息。

`tracking_end` 用于推进名义路线和下一帧闭环控制。`stopped_end` 只用于停止安全、容错质量和依赖持有。两者不能再由调用方重新计算，也不能互相代替。

### 3. `GroundTrackingPolicy` 只判断路线质量并选择候选

`GroundTrackingPolicy` 读取完整验证报告，再计算：

- 控制前缀是否留在路线 corridor 内；
- 中性尾迹是否留在 corridor 内；
- 路线进展、completion 距离和停止质量；
- typed 选择结果以及稳定排序键。

它不再：

- 独立 rollout 身体状态；
- 计算 `safe_tail`；
- 查询碰撞、支撑、UNKNOWN、材质或伤害；
- 调用 1.21 计算器；
- 用简化模型覆盖正式验证报告。

世界安全事实只来自 `GroundCandidateVerifier`。路线和 completion 质量只来自 `GroundTrackingPolicy`。二者通过有类型的报告连接。

### 4. 不完整报告不能参与选择

只有十八项都取得终态后，报告才是 `COMPLETE`。`BUDGET_EXHAUSTED`、缺少某项结果或只完成部分候选时：

- 已完成的方向候选不能参与选择；
- 不能把当前最优项当成完整候选族的最优项；
- 只能沿用已经证明安全的中性输入处理，或由当前身体负责人有界退出；
- 不新增等待、重试或 Session 状态。

候选输出顺序固定为 `CLOSED_GROUND_MOVEMENTS` 的既有顺序，并在每个方向内依次排列一 tick、两 tick许可。墙钟快慢、便宜分数、历史胜者和调用方枚举顺序都不能改变报告顺序或候选安全集合。

### 5. 删除普通 Walk 的旧计算入口

正式接线通过后，删除或让普通 `STANDING + WALK` 无法进入这些旧路径：

- `GroundTrackingPolicy` 内独立的 rollout、evaluate 和 `safe_tail`；
- `FixedRoute` 内为普通 Walk 准备、评估和重放第二套候选的路径；
- 先用简化模型淘汰候选、再只复核部分候选的路径；
- 从旧 rollout 重新推导 `tracking_end`、停止终点或世界依赖的兼容分支。

仍被严格动作或独立组件使用的函数，必须改名或拆分出明确用途。不能保留一个普通 Walk 仍可误入的隐式后门。

### 6. 严格动作保持原证明链

Sprint、Sneak／探边、Crawl、Swim、Climb、JumpGap、JumpUp、ControlledDrop、离地和连续高度严格入口不进入 F2-SS 的十八项普通候选报告。

它们继续使用原动作证明、生效窗口、落地责任和伤害额度。F2-SS 不改变动作接口，也不扩大 `STANDING + WALK` 的适用范围。

### 7. A* 只在局部 terminal 计算中复用核心

F2-SS 先统一在线 `FixedRoute` 的候选事实。A* 不在大图的每个节点上完整验证十八项候选。

以后补 terminal 成本时，可以在已经缩小到少量终点状态的局部 rollout 中复用同一物理核心。该工作必须另行冻结状态输入、缓存和性能门槛。大图搜索继续使用有界图成本和启发函数，不能因为复用验证器而把在线控制成本乘到所有展开节点上。

## 实施顺序

1. 先冻结逐项 oracle、正式行为和每帧调用次数；
2. 建立包含 `tracking_end`、`stopped_end` 和依赖的完整报告；
3. 让 `GroundTrackingPolicy` 只消费报告并返回 typed 选择；
4. 接入 `FixedRoute`，删除普通 Walk 的旧 rollout／evaluate／replay 入口；
5. 先过 Windows 8／15／30 ms 性能门槛；
6. 性能通过后，再依次运行 F2-WR 历史退步、remaining9、remaining42、大集合、D061 和 Fabric。

如果正式接线首次超时，只允许一轮不改变语义的低风险优化，例如复用同帧查询、公共前缀或已经生成的轨迹。优化后仍超时，立即停止；不得缩短尾迹、减少候选或恢复第二套简化筛选。

## 不做什么

- 不改变 corridor、completion、候选数量、候选输入或评分权重；
- 不按墙钟选择先验证哪些候选；
- 不把部分验证结果交给质量层；
- 不增加 Session 状态、等待、重试、后台任务或长期缓存；
- 不修改 A*、目标区域、输入账本和严格动作证明；
- 不用场景 ID、reason 文案或历史胜者决定安全资格。

## 影响

本决定修订 D083 和 D084 的正式普通 Walk 接线方式。D083 的封闭候选、typed 预算、公共前缀和正式 1.21 回退继续有效；D084 的世界安全、路线适用性、真实偏离和短期依赖边界继续有效。

F2-WR 的失败结果不变。F2-SS 只有在唯一事实源、行为非退步、性能、分层回归和 Fabric 都通过后才能关闭。实施方案见 [F2-SS 阶段](../stages/F2SS-single-ground-candidate-source.md)，验收见 [F2-SS 验收](../acceptance/F2SS-single-ground-candidate-source.md)。

## 实施后记

单一事实源、十八项完整报告、每帧一次验证和质量层只读报告已经落地。短性能门槛通过，两个 F2-WR 历史退步、remaining9 和 remaining42 也达到本决定的分层要求。

v8 随后发现三项旧成功退步。正式 1.21 物理显示它们最终停在窄 completion 外 `0.0061—0.0229` 格；当前离散键盘候选无法作更小修正。旧简化模型的成功可能是假阳性，但原记录继续保留，不能据此回写。

这不推翻 D085 的单一事实源决定。它说明下一步已不属于“消除重复计算”，而属于 completion、控制分辨率或规划目标的设计问题。F2-SS 暂停但不最终关闭；v7、D061 和 Fabric 未运行。
