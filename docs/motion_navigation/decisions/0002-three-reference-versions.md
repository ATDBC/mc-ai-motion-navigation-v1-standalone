# D002：保留三版参照，不指定一个旧版作为新底座

日期：2026-09-18
状态：已接受

## 要解决的问题

三个旧版本分别证明了不同的事情。悬浮墙实验前版本能反映行走是否干脆；重叠空气识别版记录了空气、未知和悬浮结构的处理得失；当前分层版验证了后台规划未完成时，安全的局部动作可以继续执行。

如果只选一个版本作为“旧基线”，另外两版的重要反例会丢失。如果把三版代码拼在一起，又会把这次重构重新变成旧状态的叠加。

## 决定

保留三个独立参照：

| 参照 | 用途 |
|---|---|
| `pre-floating-7ab0b35f` | 比较普通行走、转弯、停止和整体流畅度 |
| `overlap-air-legacy` | 检查空气／未知语义，以及悬浮墙候选补看造成的退化 |
| `hierarchical-current` | 检查全局路线、局部走廊、逐帧控制和后台工作的寿命边界 |

每个参照都固定两层身份：GitHub 公开源码摘录及其提交，完整实机运行的源码树指纹。三版共享场景编号和证据格式，但不共享控制状态，也不自动成为新架构的起点。

## 为什么这样做

这能让后续模块按职责比较。局部跟踪可以和运动表现参照比较；知识与几何可以复用空气版的反例；后台规划可以和分层版比较。新架构不需要继承任何一版的全部内部结构。

## 边界

B01 只固定已有事实，不补跑完整横向矩阵。某个参照没有直接实测过的场景，要明确写成“无直接证据”。后续阶段需要公平性能比较时，再用相同地图、任务、权限和记录口径运行。
