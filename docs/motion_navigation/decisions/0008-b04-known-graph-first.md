# D008：B04 先实现完整已知图的四邻接 Walk A*

日期：2026-09-19
状态：已接受

## 要解决的问题

B04 需要证明规划、路线接纳和逐帧控制真正分开。如果同时加入未知探索、对角捷径、动态实体和增量搜索，失败时将无法判断是图语义、搜索、路线寿命还是执行控制出了问题。

## 决定

首版只在声明为完整的已知范围内生成四邻接普通地面 Walk 图。节点必须具有已确认支撑和身体净空；边必须通过连续扫掠和沿途支撑检查。A* 只优化非负预计步行时间，并用独立 Dijkstra 作正确性参考。

规划放入一个独立后台进程。控制进程只提交不可变快照、非阻塞读取最新结果并执行路线接纳。D* Lite、对角捷径和局部绕行等后续优化只能替换对应内部实现，不能改变候选不能直接写输入、未知不能当空气和控制线程不能等待后台这三项约束。

## 为什么这样做

四邻接不是最终运动自由度。它是最小的正确性基线，可以先验证墙、坑、悬浮净空和无路结论。B03 控制器仍会在连续空间内计算实际按键，并不会退化成角色只能沿八个方向移动。

独立进程在这一阶段是必要行为边界，不是性能装饰。只有真实阻塞和崩溃不会拖住控制帧，后续更换 A* 或增加增量修补才有稳定接口。

## 影响

B04 的路线可能不是连续空间中的最短曲线，实机时间也不用于评价最终路径质量。验收先关注图和隔离是否正确。路线平滑、对角边和增量修补要在基线通过后，用相同候选和接纳接口增加。
