# D042：动作拥有自己的未完成责任，停止后统一交接

日期：2026-09-30

状态：已实施并通过第二十二轮关闭门槛。

## 要解决的问题

第二十二轮评审发现三类重复缺陷：历史输入歧义没有出口；探边被替换时遗留等待记录；停止收尾期间普通规划分支仍能请求非法状态转换。

这些问题都来自同一个缺口：动作创建了输入责任、等待和停止承诺，但它们没有随动作统一结束。改目标、取消和重新规划分别在不同分支处理这些责任，导致循环等待、容量泄漏和非法转换。

## 决定

1. 输入账本继续如实保存 `AMBIGUOUS`，不能把未知历史改写成已执行或未执行。
2. 输入责任判断增加有界出口。动作窗口已经过去并取得更新的安全身体锚点时，可以从当前状态形成交接证据；期限用尽则返回有类型失败。
3. 等待记录绑定创建它的动作或恢复流程。动作正常完成、替换、取消、失败、超时或关闭时，统一结束该所有者的全部等待。
4. 固定容量的风险、等待、重试和提交记录都要有创建者、结束条件和满载行为。
5. 改目标、停止、交接和重新规划由一个长期所有者管理。普通规划与执行代码不能直接让 `STOPPING` 离开。
6. 从 `STOPPING` 恢复规划或执行必须使用当前帧交接证据。状态表继续负责最终准入。
7. 实施期间导航协调 S5 重新打开；第二十二轮门槛通过后重新关闭。连续高度 M3 始终保持关闭。

## 为什么这样做

只修三个复现点会继续遗漏取消、关闭或其他转换入口。共享规则必须直接表达“谁负责、什么时候结束、结束不了怎么办”。

状态表已经能拦住非法转换，但不能阻止业务代码反复走到错误入口。等待账本已经能限制容量，但不能知道创建等待的动作已经结束。输入账本能保留事实，但不能单独判断身体是否可以交接。因此三者需要由动作所有权和统一交接连接起来。

## 代价与边界

- 本轮需要修改输入责任、等待账本和导航交接的公共接口；所有生产者、消费者和测试必须一起更新。
- 历史输入事实仍可能保持未知。系统只证明当前身体可以安全交接，不声称已经还原过去发生了什么。
- 本轮只拆出目标修订与交接链，不重写整个导航会话，也不新增移动能力。

## 实施结果

输入责任、等待归属和停止交接已经分别落到 `online_motion.py`、`retry_ledger.py` 和 `navigation_handoff.py`。会话只调用这些公共契约。

扩大后的 1000 个固定随机序列没有不变量违规、永久等待或公开接口异常。固定 14 场、冻结 200 种子、192 个中断组合和 755 项运动导航测试均符合既定口径。因此导航协调 S5 重新关闭。

门禁额外确认了两条规则：判断静止释放时，必须同时检查当前身体速度与预测尾段；替换规划失败时，必须请求旧控制者停止，不能让旧安全前段无限运行。
