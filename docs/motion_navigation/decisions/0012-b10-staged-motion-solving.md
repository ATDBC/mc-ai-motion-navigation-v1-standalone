# D012：B10 按能力分三步接入动作求解

日期：2026-09-21
状态：已采用

## 决定

B10 分成三个独立门槛：

- B10-A 建立正式状态锚点、输入应用账本、合法命令到 `TickInput` 的投影和可用计算预算；
- B10-B 在冻结试点内自动求解一个动作，并通过固定测试入口完成独立 Fabric 验证；
- B10-C 才允许规划器生成、接纳和连续执行已发布的动作组合。

证据按能力和实际规则分支补齐。B10-A 不等待所有现有计算器边界完成补采，但一个分支只要被试点使用，就必须先取得对应证据。

首个试点使用草方块、同高一格空隙、低速直线入口和现有 B09 `JumpGap` 风险边界。开发链先使用 `+Z`，B10-B 发布前扩展到四个正方向。

## 状态决定

具体 `PhysicsState`、动作入口／出口范围和 `PlannerStateKey` 分开。规划状态键只保存搜索必须区分的有限信息，但不能无依据地省略会改变后续可达性的方向、速度、接触或内部状态。

动作入口、命令、轨迹和出口必须保持关联。不得把几个宽范围分别相交后，宣称其中任意入口都能到达任意出口。

## 输入和执行决定

求解器搜索真实命令和时序。输入投影根据每 tick 的预测状态生成采样后输入，再调用 B09-R。求解结果保留命令、投影输入和轨迹的同次不可变记录。

在线状态由状态锚点和有界输入账本建立。状态／预测有效范围与候选执行窗口分别表达。`RouteAdmitter` 可以复核旧解的当前适用性，但不在控制帧寻找新解。

可缓存的运动结果与本次任务的候选实例分开。后者必须绑定请求代次、目标 ID／修订、路线位置、候选修订和执行窗口。目标变化本身就足以让旧候选失效。

## 验收决定

B10-C 使用冻结接续矩阵。每个声明组合分别验证连续正例、边界行为和扰动／中断；不要求所有动作两两组合，也不强制每个负例都完全停稳。

统计口径、样本、种子、计时、恢复和容量上限在首次正式运行前冻结。外部重跑不覆盖失败；任务内部合法恢复单独统计。安全结论只覆盖冻结验收集合中的观察结果。

## 原因

B09-R 已经解决给定输入的逐 tick 计算。若 B10 同时扩大全部证据、状态类型、求解、规划和在线执行，失败将无法定位，控制线程也容易再次承担后台工作。

三步实施可以分别回答：

1. 当前状态和输入时间是否可信；
2. 是否能自动求出真实可执行的单动作；
3. 规划和执行能否连续使用它。

## 影响

- B09-R 的计算器边界和历史验收保持不变。
- B10-C 通过前，默认业务运行继续使用现有 B03–B09 控制器。B10-B 和 B10-C 的受控验收会话可以串行授权新命令生产者通过既有 `MotorGateway` 执行；同期只有一个有效命令来源。空中动作在落地或显式交接前不因会话切换而失去动作责任。
- B11–B13 复用同一求解和验证链，不为材质、攀爬或流体复制新地图和输入系统。
- 流体提供环境条件；姿态规则仍由统一运动计算体系拥有，水不成为第二个 Crawl 状态拥有者。
- 原 B06–B15 总计划中的 B10–B15 实施细节由新的阶段、架构和验收文档取代；旧文件保留为历史背景。
