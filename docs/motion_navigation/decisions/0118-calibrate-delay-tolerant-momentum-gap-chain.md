# D118：先校准带动量连续跨隙，再决定是否接入生产链

日期：2026-10-18。状态：**D118-0 FAILED／STOPPED；D118-1—D118-5 未授权。**

## 1. 要解决什么问题

D117 已经收口 prepared 后继交接，但它只证明组件链能正确交接。当前生产能力仍只有一格跨隙，也没有实机证据说明以下四件事：

1. 四格跨隙的计算器轨迹与 Fabric 一致；
2. 机器人能在落地后不停车，立即进入下一跳；
3. 走出平台边缘的最后一个着地 tick 仍能起跳；
4. 机器人高速落到一格平台后，潜行能及时成为安全收尾。

三方探索给出一个值得验证的产品判据：在冻结地形、输入模板、搜索分辨率和输入流起点 0／1 tick 契约内，没有找到能同时覆盖两种起点时序的停稳四格跳；带动量接续存在这样的候选。这只说明当前冻结策略中的能力差异，不能写成 Minecraft 中“停下绝对过不去”或“连续接续是唯一解”。

## 2. 本轮决定

先只实施 D118-0。D118-0 建立项目自己的计算器 RED、固定输入和 Windows Fabric 校准证据。它不修改生产动作配置、求解器、规划器、安全规则或 prepared 默认入口。

只有 D118-0 签署后，才可以另立决定授权后续步骤：

- D118-1：把“松开输入能安全结束”推广为“候选带有经过证明的 fallback 尾段”；
- D118-2：先求第二跳入口范围，再约束第一跳出口，并在第一跳空中准备第二跳；
- D118-3：规划器只为冻结形状发布短平台组合边，速度留在组合边内部；
- D118-4：运行组件矩阵；
- D118-5：运行 Fabric 产品验收。

这些步骤现在都没有实施授权。

## 2.1 实施结论

D118-0 已完成组件夹具和一次有效的 Windows 朝南 smoke。Fabric probe 本身通过，273／273 条命令的 Runtime receipt、physics 和 F-TICK 身份能够唯一对应。7 个 trial 中，6 个与项目计算器逐 tick 一致。

阶段在 `fallback-back-south-0` 停止。Fabric 从 movement tick 246 起仍按原版碰撞规则着地，项目计算器却选择了不同的碰撞结果。根因是计算器遗漏了原版会考虑的 0 高度 step 候选。这违反第 7 节的离散状态一致门槛，因此不能继续四方向矩阵，也不能用调输入、放宽容差或改验收文案绕过。

其余实机事实保留，但不能改变失败结论：

- `fallback-sneak-south-0` 的潜行在 `L+1` 生效，身体安全停在平台上；纵向余量只有 `0.000551` 格；
- 第二跳按时输入在 `L+1` 生效，late1 在 `L+2` 生效；
- 第二跳入口仍没有冻结的可证明包络，状态为 typed `unverified`。

四方向 full matrix、生产运动接入和 D118-1—D118-5 均未运行。若后续修正计算器，需要另写决定和新的校准阶段；本决定的失败结果不回写。

## 3. 三种时序必须分开

本阶段分别记录三种情况，不能统称“晚一 tick”：

1. **后台交付抖动**：worker 提交到控制线程首次可见的 `D／D+1`。D113 已验证的是这一类。
2. **输入流起点分支**：新输入流的第一条命令按时或晚一 tick 生效。第二跳是一条新输入流，属于这一类。
3. **输入流中段偏离**：动作已经开始后，某条命令晚到或缺失。它属于 D101 定义的偏离，不能拿起点分支的证明覆盖。

落地 tick `L` 定义为：身体从 `L-1` 的空中状态进入 `L` 的 authoritative post-state，并第一次报告 `on_ground=true`。`L+1` 是下一次 movement tick 的输入采样与应用机会。

D118-0 必须实际测出：

- 后继已提前获批时，第二跳的第一条输入能否在允许的 `L／L+1` 起点分支生效；
- 后继未获批时，默认潜行尾段能否最迟在 `L+1` 生效并安全停在平台；
- 如果 `L+1` 潜行与 `L+1` 跳跃冲突，批准截止必须放在 `L` 之前，不能同时保留两个互斥承诺。

## 4. 物理校准口径

Fabric 每个试次都从真实静止状态通过正式 Runtime 输入加速，不用传送伪造入口速度。固定输入在运行前写入清单并计算哈希，运行中不能根据结果临时调按键。

连续量沿用 B09-R 的校准上限：

- 每轴位置误差不超过 `0.001` 格；
- 每轴速度误差不超过 `0.0001` 格／tick；
- 着地、离地、碰撞、疾跑、潜行和姿态等离散状态逐项一致。

这些值只用于判断计算器和实机是否一致，不用于全局放宽 prepared 的 `1e-7` 数值等价规则。后续生产实现应在落地时用真实状态检查 proof 给出的入口范围。

## 5. 经过证明的 fallback

后续安全规则不再把 neutral input 当作唯一安全尾段。候选可以声明一种 fallback，但仍必须由运动计算器证明它在绑定的 generation、owner、绝对 tick、时序分支、身体范围、世界依赖和伤害额度内安全。

潜行只是短平台动量落地的第一个 fallback。它不恢复已经删除的通用 `SNEAK_EDGE_GUARD`，也不增加 Session 状态、第二个身体 owner、账本或输入出口。

## 6. D118-0 授权范围

D118-0 只允许：

- 决定、计划、验收和台账文档；
- 计算器事实测试和固定输入清单；
- 独立 Fabric 校准夹具；
- 复用现有 Runtime、物理 sidecar、F-TICK sidecar 和输入回执；
- 只读分析、证据封存和公开导出登记。

D118-0 禁止：

- 新增四格跨隙生产 profile；
- 修改求解器、规划器、接纳、安全分类或动作证明；
- 恢复 prepared 自动准备；
- 放宽 UNKNOWN、伤害、入口或全局浮点规则；
- 把探索数据写成正式产品能力。

## 7. 停止条件

出现任一情况，D118-0 立即停止，D118-1 不得开始：

- 任一方向超过 B09-R 连续量上限，或离散状态、movement tick 顺序不一致；
- Runtime receipt、物理 sidecar 和 F-TICK 不能用请求序号唯一对应；
- 未获批时，潜行不能最迟在 `L+1` 生效并安全留在平台；
- 实机误差吃掉第二跳入口或 fallback 的全部余量；
- 固定输入必须根据运行结果临时调整；
- 需要全局放宽容差、安全规则或 UNKNOWN 规则；
- 需要新增 Session 状态、第二个 owner、账本或输入出口；
- 两轮限定修正后仍出现范围外的跨层阻塞；
- 出现旧成功退步、安全违规、无界等待或无关行尾变化。
