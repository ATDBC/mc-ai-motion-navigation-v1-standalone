# D051：撤回终点筛选，直接修接近控制

日期：2026-10-02。状态：方案已确定，实施与结果分别见 R28 阶段和验收记录。

同日新增本地演示时，仅通过只读接口展示当前身体拥有者的已采用路线。没有恢复终点试算或为显示另算路线；人类旁观客户端与无头机器人分开。它不改变本决定的实施顺序或能力门槛，额外跨隙演示失败单独保留。

依据三方 `7a5a083` 的评审、本地代码检查和原 v3 归档审计。用户选择保留开阔地跟随探针，先修终点接近，不扩大原时间盒。

## 为什么改变

批次 5 的归属、量尺、迁移场景和末段直连保留。后台筛选没有让失败提前，也没有在正式基线中判定接近不支持。其完成与超时分支选择不同连接，使同一输入的行为受机器速度影响。末段执行失败又被按原因字符串改名，不能作为能力结论。

普通步行拒绝无害墙面接触是控制规则问题。提高筛选预算、增加候选或保留在线诊断试算都不能解决它，反而增加成本和分支。

## 决定

1. 移除正式筛选模块及规划、接纳、执行和模拟工具的接线。保留静态站位查询、目标内部停车范围、普通末段直连、实际长度和依赖。真实后台工作仍有计算期限，但不再用这个额外试算的墙钟分支选择终点连接。
2. 删除按失败文案改名的逻辑。执行结果如实表达当前控制失败；不把未算完或单次没有可用输入称为已证明不支持。
3. 原 v1、v2、v3 和全部失败保持原文件。另建 v4 确定性基线，不覆盖旧 v3，不把撤回后的结果回填旧记录。
4. R28-1 首先核对并关闭 R28-C-01 的证据。复现若混用了传感器地形和旧碰撞世界，先修测试输入，不为矛盾的模拟状态增加生产特例。真实支撑改变后的停止、重锚和接替由现有身体与交接拥有者处理；不通过强制释放、伪造锚点或独立场景开关结束等待。R28-C-02 同属共享工作退场范围。
5. 终点接近控制安排在跟随之前。无害墙面接触由现有材质和几何事实限制；局部预测要反映接触后的真实位置、速度和支撑，再评分，不能照搬原型中的 `break`。
6. 边缘接近复用已有潜行能力，执行层不能改变原目标的姿态和终态要求。没有合法潜行与站立收尾方案时保持明确失败，不宣称任意边缘目标均可达。

## 剩余顺序和范围

仍剩五个正式批次：R28-1、R28-4、R28-3、终点接近与开阔地跟随、R28-5。终点控制和跟随在同一批次中分步骤保存；先通过控制专项，再接入跟随，不同时修改协调规则和局部选键。正式候选及清单冻结后不合并不同版本的样本。

跟随先覆盖已知、支撑完整的开阔地，仍检查目标修订、持续任务预算、输入扰动和取消。室内、贴墙、边缘和疾跑跟随不在此探针的能力声明中。探针仍要核对技能层没有复制导航的停止和交接逻辑。

保留 2026-10-15 的初始复核日期和十批上限。到期未完成则按原决定冻结已通过的集成版本，记录未完成项，不自动延长或把有界失败改为成功。

## 怎样避免重复走偏

先检查是否真正减少对应失败、是否改变了不相关严格动作、是否引入机器负载分支。最小代表场景未满足目标就停止扩大验收。准备阶段、失败阶段和行为结果分开度量；代码量和检查通过不替代玩家到达表现。

原型、单机配对和 Fabric 各自报告范围。控制器原型的种子 187 退步、墙角、走廊尽头、危险材质和边缘均须先检查，不能直接复用其成功数字。
