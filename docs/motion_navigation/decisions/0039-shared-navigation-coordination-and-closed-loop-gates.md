# D039：先建立共享协调规则与正式路径闭环门禁

日期：2026-09-28

状态：部分执行。S0 至 S4 已完成；S4 经 [D040](0040-reopen-navigation-coordination-gates.md) 强化后重新关闭，S5 仍然打开。完整连续高度能力矩阵仍按原验收单独关闭。

## 为什么调整

连续高度移动的组件测试和代表性实机已经通过，但新复审在正式调用链中重现了探边超时、改目标后无主坠落、远处落点提前取证、交替原因绕过重试上限等问题。目标已经满足时还会产生规划内部错误。

这些问题反复落在控制者交接、任务计数和动作门槛上。原来依靠会话多个分支分别遵守约定，没有共同的执行入口；单帧测试又没有让身体继续运动，所以无法及时发现松键后的后果。

依据是第三方提交 [eae4419 的方案](https://github.com/ATDBC/mc-ai-motion-navigation-v1-standalone/blob/eae4419731fc7ae6cf4ae43e511b4117ecbd996f/reviews/2026-09-28-refactor-plan.md)及原因分析。原型已在本地 `df3e093` 复跑，14 项结果与公开 `8898cf9` 一致；这属于计算器模拟证据。

## 决定

1. 暂停新增运动、地形和战斗能力。先建立正式路径闭环工具，再迁移共享机制，最后拆分会话。
2. 按以下顺序交付：工具 S0 → 已满足目标 S0a → 身体控制权 S1 → 重试和风险账本 S2 → 动作前置条件 S3 → 会话拆分 S4 → 完整验收 S5。与第三方编号的对应关系见阶段计划。
3. S1 至 S3 顺序实施。它们共同修改会话，前置条件还依赖控制者和风险账本，不作为独立并行补丁集成。
4. 导航内部由一个执行监督者拥有当前身体控制者。取消、超时、目标变化都是停止请求；只有同帧交接检查成立后才释放。Runtime 仍是唯一全局仲裁和输入出口。
5. 正常路线替换可以带速接管，前提是下一控制者接受当前状态、相关证明仍有效、在途命令已得到解释。没有接替者时，旧控制者必须完成自己的安全收尾。不能把所有交接都改为停稳。
6. 路线接纳检查几何、证明、目标身份和当前额度；落点最新下部证据等即时门槛在对应动作开始前检查。被接纳的路线不能被当作每个未来动作已获得执行许可。
7. 重试次数、等待期限、伤害额度和方块库存分别按各自单位管理。共享规则和接口，避免用一个无类型计数器承担所有职责。
8. 每个缺陷必须增加同类场景、检查其他调用点，并绑定自动不变量。单个复现变绿不足以宣布该类缺陷关闭。

## 对原有决定的修订

- D038 的探边拥有权继续保留；“结束探边”改为请求收尾，不再允许直接丢弃控制者。远处落点不再在整条路线接纳时驱动身体去探边。
- 同原因重试最多两次保留为局部限制；新增跨原因总限制。目标修订、原因变化、无关几何更新不能补回次数。
- 下落离边占用额度继续保留；首条不可逆输入发出前增加额度保留，并以正式回执和离边事实转为已承诺，堵住在途命令期间的重复授权。
- D004、D035 的视觉权限和空气判定不变。测试里的简化遮挡模型仅用于模拟，不能成为正式传感器后备。
- 旧验收批次与失败记录保留。代表性实机通过不再解释为探边中断、多个下落及所有调用入口已经通过。

S2 落地时只用正式观察已有的生命值核对风险。伤害事件没有点数，不能从事件名称推算实测值。缺样本时保留承诺和已知损失下界；下界已超预计就停止新风险动作。这个实现边界不改变上述授权顺序或 2／6／12 重试门槛。

## 代价与边界

增加的小型协议和状态对象必须替换现有分支，不能形成第二套目标、世界、输入账本或物理规则。过渡期逐个调用点迁移，不引入通用状态机框架。

同步后台替身用于确定性验证；实际后台进程仍需单独测试延迟、乱序和死亡。计算器同时作为被测预测模型和模拟物理时，无法发现它与 Minecraft 的共同偏差，因此 Fabric 仍是独立门槛。

正式方案见 [架构](../architecture/navigation-coordination-v1.md)、[阶段计划](../stages/navigation-coordination-refactor-plan.md)和[验收](../acceptance/navigation-coordination-refactor.md)。

## 实施后的影响

动作边界门槛、执行监督者、重试账本和风险账本已经进入正式导航路径。探边不再由整条路线接纳提前触发；每道下降在自己的入口取得证据。会话状态已按目标、规划、取证、执行、风险和结果分开归属，任务生命周期由结构化事件推进。

固定矩阵、冻结扰动扫描和代表性 Fabric 回归证明这套协调规则可以同时服务普通导航、连续高度、战斗追击、放置和部分观察战斗。它没有把这些能力的策略合并，也没有建立新的全局控制器。Runtime 仍是唯一输入出口，各技能保留自己的任务状态。

本决定已经关闭共享协调结构缺口。可靠性和专项 Fabric 仍属于 S5：完整连续高度速度带、形状与随机迟到矩阵未因此自动通过；后续新增能力仍必须走正式闭环工具并补对应 Fabric 证据。
