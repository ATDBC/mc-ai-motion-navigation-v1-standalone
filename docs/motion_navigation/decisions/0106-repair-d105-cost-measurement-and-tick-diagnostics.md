# D106：先修 D105 的重复成本和量尺，再讨论连续两跳

日期：2026-10-14。状态：**部分完成并停止。**

本决定接续 [D105](0105-restart-sound-proof-slimming-and-decouple-tracks.md)。D105 的 T1、T2、T3 失败状态和原证据保持不变。本轮使用新的证据目录和验收记录，不把后续修正回填为 D105 当时已经通过。

## 要解决什么问题

D105 的三条轨道都按预登记门槛停止，但新证据表明，当前阻塞点包含三项附带成本：

1. T1 在同一次扫描中对同一个不可变证明计算两次完整摘要；
2. G2 用 `sys.setprofile` 同时计数和计时，控制帧耗时被放大；
3. T2-2 把“快照必须覆盖最大可达区域”当成安全前提，但快照外查询本来就会返回 UNKNOWN。

T3 的 22 个已运行试次全部在下一 movement tick 生效。批次随后因 B10 滑行阶段输入样本缺失而停止。现有本地归档还保留完整 trace，应先读现有证据，再决定是否启动新的 Fabric 对照。

## 决定

### 1. T1-R 只去掉重复摘要

证明内容、风险区间、可执行尾迹和摘要字节保持不变。

扫描器生成证明后只做结构检查，不再立即重算刚生成的完整摘要。公共验证入口仍执行“摘要检查＋结构检查”，用于载入、传输和篡改检测。规范化可以缓存 dataclass 类型对应的字段表，但输出字节和摘要必须逐字节一致。

本轮不实施方案 B，也不把摘要移出正式计时窗口。若只算一次摘要后仍未达到 Windows `8／15／30 ms` 门槛，T1-R 停止并保存结果。

### 2. G2 的调用计数和性能计时分开运行

调用计数批次允许使用 `sys.setprofile`，但不得报告为生产性能。性能批次禁用 profile，只使用显式时间段记录控制路径耗时。两批使用相同场景、种子和代码身份，并在证据中互相引用。

旧的含 profile 耗时不改写，只补充“包含量尺放大”的边界说明。

### 3. T2-2-R 使用保守失败保证安全

局部 detached 快照不再要求先证明所有动作模板的最大可达包络。安全条件改为：

- 快照外查询必须得到 UNKNOWN，并转成 `NEEDS_WORLD` 或 `MISSING_INFORMATION`；
- 被接受证明的全部实际依赖都在快照内；
- 父侧接纳和执行前继续核对正式世界依赖；
- UNKNOWN、UNSUPPORTED、伤害和身体责任规则不变。

快照大小、首次命中率、补取次数和准备时间属于效率指标。快照太小只能让任务重新取信息，不能产生假 SAFE。

T2-3 仍不运行。本轮不删除完整 bundle、规范 bytes、lease、返回队列、receiver 线程或 registry 载荷。

### 4. T3-R 先归因

先离线分析 D105 本地原始 trace，确定缺失的 movement tick 以及缺失发生在哪一段。如果旧证据不足，再在同一源码、同一场景和固定 seed 下关闭 sidecar，运行一次 B10 诊断批次。

无 sidecar 批次只用于归因，不计入 T3：

- 对照也失败时，先修 B10 正式输入／账本路径；
- 对照通过时，先把 sidecar 改成有界内存缓冲，收尾时写盘；
- 原因修复后，才重新运行四方向各 10 次的正式 T3。

来源注销仍是阻塞门槛。即使它是 B10 异常中止的连带结果，也不能从正式验收中删除。

### 5. 连续两跳继续关闭

本轮不实施连续两跳、零等待交接或新动作。T1-R、T2-2-R 和 T3-R 全部通过后，还要先拆分准备链的快照封存、worker 求解、规范化、序列化和 receiver 时间，再单独决定连续两跳。

## 证据与历史

新证据写入 `evidence/motion_navigation/sound-motion-proof-d106-v1/`。D105、D104、D103 和更早阶段的原文件、原分母与失败状态都不改写。

## 实施结果

- T1-R 保持功能、安全和摘要一致，但 Windows M0 的 P99 为 16.5732 ms，仍高于 15 ms，按门槛停止；方案 B 未实施。
- G2 量尺已经把调用计数和性能计时分开，配对业务结果一致。
- T2-2-R 证明现有 UNKNOWN 与正式依赖复核足以保证局部快照保守失败，不需要新增最大动作包络算法，也没有修改生产代码。
- T3 的账本边界已经统一到 Runtime；第二次正式批次取得 40／40 `NEXT_MOVEMENT_TICK`、来源正常注销、sidecar 零丢弃。随后 B10 的旧 R4 移动入口夹具没有在 80 tick 内进入 `(0.5, 1.0)` 速度带，仍触发 B10 回归门槛。失败发生在动作求解前，与账本修正无关；身体全程着地、满血，最后安全静止。两轮限定修正已经用完，R4 `FAILED／STOPPED`。

所以 D106 不能作为连续两跳的通过前置。连续两跳、零等待交接、方案 B 和 T2-3 继续关闭。
