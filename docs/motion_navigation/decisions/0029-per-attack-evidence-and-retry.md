# D029：按攻击尝试保存证据和重试状态

日期：2026-09-25
状态：已采用

## 要解决的问题

现有连续近战把攻击门禁拒绝和命中确认超时放进同一个跨战斗计数。生命下降也可以单独确认命中。这会造成两类错误：正常的短暂拒绝可能过早耗尽整个任务，外部伤害可能被记成机器人命中。

## 决定

1. 每次攻击建立独立、不可变的尝试记录，并绑定任务、目标、命令、回执和观察证据。
2. 攻击没有赢得仲裁时不算已提交，也不消耗攻击失败额度。
3. 门禁拒绝、输入失败和确认超时分别统计，并分别维护连续重试额度。
4. 生命下降和死亡只证明目标状态发生变化。只有同一攻击命令提交后出现满足身份、时序和受伤动画条件的新事实，才记录命令关联命中。
5. 来源未确认的目标死亡可以完成消灭目标任务，但不能增加机器人确认命中，也不能建立新的交战许可。
6. 一次确认命中结束当前失败序列。历史诊断总数继续保留，不参与下一次攻击的重试判断。
7. 某一类额度耗尽返回有类型的任务结果，Runtime 保持可用。

## 为什么这样处理

客户端能确认攻击命令发给了哪个实体，也能观察之后的受伤动画和生命变化，但不能稳定取得服务端伤害来源。因此系统必须如实区分“命令和受伤事实在当前证据下关联”与“服务端证明伤害由机器人造成”。

按攻击尝试保存状态后，失败归因和重试范围都能在一个局部生命周期内完成。移动近战只消费结果，不再根据字符串重新猜测失败含义。

## 影响

- C1 的历史验收范围保持不变；新代码会增加更细的证据分类和重放结果。
- B12-B 的部分观察逻辑只能消费有类型结果，不能从生命变化自行授予权限。
- 将来若服务器能够提供可靠伤害来源，可以增加更高证据等级，无需改变攻击尝试和重试结构。
