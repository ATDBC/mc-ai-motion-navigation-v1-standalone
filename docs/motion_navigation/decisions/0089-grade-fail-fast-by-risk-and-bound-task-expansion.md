# D089：按风险使用 fail-fast，并限制任务自动扩张

日期：2026-10-08。状态：决定有效，作为后续阶段解释 fail-fast 和止损的统一口径。

## 要解决的问题

项目原本用 fail-fast 避免带着已知错误继续跑大矩阵。这个原则仍然正确，但 2026-10-08 的 F2-S 系列工作暴露了另一个问题：每个小阶段都及时停止，整个任务却在发现新根因后自动开启下一阶段。

当天从 `08:04` 到 `19:41` 共形成 108 个提交。原任务从目标区域收敛继续扩展到多终点搜索、地面候选验证、末段序列搜索、后台 worker 和控制热路径。每一段都有单独的停止点，但任务整体没有停止边界。

这种做法会让低风险的性能余量和高风险的安全缺陷受到同样处理，也会把“发现问题”自动变成“立即扩展当前任务”。后续必须同时限制验证成本和任务范围。

## 决定

### 1. fail-fast 只决定当前验收怎么推进

fail-fast 的作用是先运行便宜、最能暴露问题的正式调用链检查。它不自动授权修复所有新发现的问题，也不自动开启新的阶段。

发现失败后，先判断它属于下面哪一类。

| 类别 | 典型情况 | 处理方式 |
|---|---|---|
| 硬停止 | 安全不变量违反、身体无人负责、旧结果获得执行资格、不可逆动作缺少证明、真实控制期限错过、无界等待或重试 | 立即停止当前实施和扩大验收。修复前不得签署相关能力 |
| 当前交付阻塞 | 冻结场景中的旧成功退步、当前任务目标没有完成、正式路径与声明不一致 | 当前能力不能签署，停止昂贵矩阵。最多进行两轮限定修正 |
| 性能或体验债 | 内部 P95／P99 余量未达，但没有真实期限失败、安全事件或冻结产品退步 | 保存数据并登记债务，不自动阻塞无关产品工作 |

动作名称不能决定风险等级。普通地面靠近坑边时也可能属于硬停止；后台计算慢但仍在执行窗口前交付时，可以只是性能债。

### 2. 同一任务最多进行两轮限定修正

第一轮修正解决已经确认的直接根因。第二轮只处理该修正造成的相邻回归或遗漏。

出现下面任一情况时，结束当前任务并报告：

- 需要改变新的公共契约或状态所有者；
- 需要换规划、求解或控制方法；
- 需要建立新的阶段、验收集合或长期决定；
- 第二轮后仍有未关闭的当前交付阻塞；
- 新问题与原冻结目标没有直接关系。

结束当前任务不等于删除有效改动。已经通过独立门槛的安全修复和结构修复可以保留，未完成能力继续记为未通过。超出范围后必须先向用户报告并结束当前任务；只有用户明确授权后，才能用新的决定重新冻结范围。新决定只记录授权和边界，不能自行产生授权。

### 3. 验证按成本逐级扩大

默认顺序为：

1. 最小复现或组件检查；
2. 少量代表性正式调用链；
3. 受影响的冻结集合；
4. 完整矩阵；
5. Fabric 实机。

前一层出现硬停止或当前交付阻塞时，不继续运行更昂贵的层。性能或体验债不会自动跳过后续产品验收，但必须在报告中单列，不能写成达标。

小范围诊断修改只复跑直接受影响的检查。没有代码、输入、环境或验收口径变化时，可以复用仍然有效的证据。

### 4. 性能门槛分成真实期限和容量目标

真实期限回答“输入是否还来得及生效”。容量目标回答“是否给未来负载留下足够余量”。两者必须分别记录。

下面的情况属于硬停止：

- 输入实际生效晚于动作允许窗口；
- 完整控制帧超过项目冻结的真实期限；
- 后台结果超过执行窗口仍获得资格；
- 性能退步使冻结产品任务失败或产生安全事件。

单独的内部 P95／P99 余量未达属于性能债。新增工作若继续占用同一热路径，必须先重新核对这项债务；不能假定剩余容量足够。

### 5. 历史记录不回写

旧阶段按当时冻结门槛停止的事实继续保留。不能把旧失败改成通过，也不能删除未运行项目、失败样本或性能数字。

新口径只决定后续如何排期：

- 安全和真实期限问题继续阻塞；
- 当前能力回归阻止该能力签署；
- 内部性能余量进入债务，不阻塞无关产品主线；
- 历史阶段不会因为风险重新分类而自动关闭。

## 对 F2-TP 和 F2-RH 的应用

F2-RH 已关闭 worker 生命周期方面的 P0／P1／P2。本批五个正式场景全部完成，安全事件和观察到的 deadline miss 为 0，full max 为 `45.3178 ms`，通过该批冻结的 50 ms 门槛。production max 为 `24.9818 ms`，原容量上限也通过。这些结果只适用于本批五个非 oracle 场景，不能外推成所有正式动作的真实期限已经证明。

production P95／P99 为 `10.2680／23.9535 ms`，没有达到原 `8／15 ms` 容量目标。这项结果继续保留为 RH5 历史失败，同时登记为性能债。它不再单独阻塞与该热路径无关的产品工作，也不授权继续现场叠加优化。

F2-TP 的 beam 上界、deadline、取消、旧世代作废和控制线程隔离仍是硬条件。TP4、oracle 和后续 F2-TS 工作没有自动获得授权；如要继续，必须先写明产品目标、受影响热路径和两轮修正上限，并说明用什么真实期限证据替代或继续执行原 `8/15 ms` 复合门槛。同一热路径的性能债必须重新核对。
