# D040：重新打开导航协调 S4 和 S5 门槛

日期：2026-09-28

状态：已决定。H1 至 H7 的结构整改和专项 Fabric 对照已实施，S4 已重新关闭；S5 因可靠性和完整矩阵缺口继续打开。

## 为什么改变

第十九轮评审在公开 `d34a674` 上复现了两次非法状态复活、五类 P1 缺陷和两类 P2 边界。本地在对应源码 `707e7b8` 上重跑后，状态复活、一格下降、风险容量、固定晚一帧、落点支撑移除和成功率分布均与评审结果一致。

原 S4 只把状态放入了新对象，并记录了事件。状态写入仍由会话分支自由完成，所以“显式状态转移”没有真正成立。原 S5 的 `14/14` 和 `200/200` 表示结果符合允许分类，不表示所有可达任务成功。

## 决定

1. S0 至 S3 保持完成，S4 和 S5 重新打开。
2. 暂停新增能力，先按 H1 至 H7 完成协调强化。
3. 任务状态只能由有类型的转移表改变。终态不可离开；`STOPPING` 离开时必须说明交接或最终结果。
4. 不用放大容差解决一格下降入口错位。动作在真实边界用当前锚点重新准备。
5. 风险容量限制未结算责任，不限制已释放的历史记录。账本仍保留必要汇总，不丢失审计结果。
6. 下落权限必须同时证明落脚空间和支撑仍有效。
7. 验收分开任务成功、有界安全失败和意外结果。不再用“符合允许结果”代替成功率。
8. 公开历史不重写。后续按可验收行为分开提交，每个提交附直接场景族结果。

## 证据边界

落点支撑移除已经完成正式 Fabric 对照。支撑在首条不可逆下落输入前被移除后，正式表面深度更新使动作以 `landing_support_missing` 拒绝；机器人留在上层且没有受伤。该结论只覆盖动作前的变化。输入已经生效后的世界变化仍按在途动作和落地责任处理。

实施细节和门槛见[导航协调强化计划](../stages/navigation-coordination-hardening-plan.md)。

新的统计也说明 S5 还不能关闭。固定 14 场中有 12 个任务成功和 2 个有界安全终止；方向性预测余量修正后的冻结种子扫描中有 192/200 个任务成功、8 个有界安全失败和 0 个意外结果。半砖路线在 20% 概率晚一帧时为 100/100，两格下降为 92/100。旧白名单外的 `no_safe_ground_candidate` 已消失；剩余结果是预先声明的 3 次取证超时和 5 次输入失联。安全失败证明系统会停在受控边界，不等于能力已经通过完整可靠性门槛。

专项 Fabric 批次 `20260928T135808548919Z-587c5904` 保留原代表矩阵 12/12，并新增三项门禁：助跑四格后下一整格并继续行走成功；动作前移除落点支撑安全拒绝；首条已验证输入由真实客户端回执确认晚一 tick，随后成功落地。三项均为零伤害。它们关闭专项证据缺口，但不替代 192/200 的冻结扰动结果和完整连续高度矩阵。
