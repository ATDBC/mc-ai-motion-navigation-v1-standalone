# D032：补齐持续瞄准移动和伤害来源证据

日期：2026-09-26
状态：已采用并完成验证

## 要解决的问题

B12-B 的实机正例证明了移动和攻击可以同帧执行，但目标使用 `NoAI`，玩家也已经面向目标。记录中没有出现“非零转头和移动同帧”。因此，这批结果不能证明持续瞄准下的移动已经成立。

当前普通步行按旧朝向算出按键，再允许战斗视角最多转 5°。近身横移时，保持准星所需的每帧转角可能超过 5°，移动便会隔帧被压下。固定放宽角度会使旧朝向按键偏离原路线，不能解决根因。

B12-A 还只使用受伤动画形成命令关联命中。Minecraft 1.21 客户端实际会收到带伤害类型、造成伤害实体和直接来源实体的伤害包，原先“客户端拿不到来源”的设计前提需要修正。

## 决定

1. 普通地面战斗移动改为先形成战斗视角，再由导航按该视角计算本帧移动；移动与具体视角意图绑定。
2. 仲裁器只有在绑定视角胜出时才采用移动。视角变化不会让导航失去路线和支撑检查的职责。
3. 台阶和空中动作不采用普通地面的视角条件。
4. 攻击任务增加跨失败类别的总无进展上限，分类连续计数继续保留。
5. Observation V3 增加有界的客户端伤害来源事件。来源事件是事实，不直接决定攻击或报复策略。
6. B12-B 在活动目标实机记录出现“同一动作请求内的非零转头与非空移动连续生效”前，不宣称持续瞄准移动已经实机通过。视角和移动位于不同客户端钩子时，以同一请求、同一时间事件序列和相邻执行相位判定，不能要求两个钩子的 tick 计数相等。
7. “未交战目标在墙后”同时保留两层证据：Fabric 证明真实遮挡观察，确定性注入证明权限消费者拒绝隐藏位置。

## 为什么这样做

Minecraft 的移动键相对玩家朝向生效。同一帧转头后继续使用旧朝向计算的按键，会改变实际世界方向。让导航看到最终视角后再选按键，可以继续复用现有支撑、墙面、停止和路线偏差检查，也不用建立战斗专用移动器。

伤害包提供了比受伤动画更直接的来源事实。保留命令关联等级可以兼容事件缺失或尚未覆盖的情况；一旦事件明确指出其他来源，就不能继续把同一受伤动画归给机器人。

## 影响

- B12 既有 24 个移动攻击正例继续有效，证明范围收窄为“移动与攻击同帧”；
- D031 的 5° 规则保留为未使用最终视角条件时的保守路径，不再作为持续瞄准移动的最终方案；
- B12-B 在审查整改完成前曾标为“既有范围通过，持续瞄准移动待补实机证据”；当前活动目标、真实墙体、C1-B、B03 和 B10 实机回归均已通过，可以关闭该缺口；
- Jev 的战术目标接口另行设计，本决定不提前加入绕圈、撤退或地形利用策略。

## 验证结果

- B12-A 伤害来源批次 `20260926T055043431485Z-e2dc4fff`：玩家近战得到 `minecraft:player_attack` 和 `SOURCE_CONFIRMED_HIT`；环境伤害得到 `minecraft:on_fire`，没有来源实体；8 个原有游戏事实反例继续通过。
- B12-B 批次 `20260926T063032338012Z-780e0386`：24 个固定正例、1 个活动目标专项和 8 个 Fabric 边界全部通过；活动目标有两个组合请求，真实墙后未交战目标两次均未移动、未攻击；控制计算 P95 4.4011 ms、P99 5.7083 ms。
- C1-B 批次 `20260926T063405450804Z-646f449c`：20／20 正例和 10／10 反例通过；控制 P95 6.5766 ms、P99 7.7832 ms。
- B03 批次 `20260926T063850514146Z-82a6a76d`：25 条路线通过，途中低速停滞为 0。
- B10 批次 `20260926T064258873497Z-780a4000`：静止跨隙 40／40、落地转向 40／40、带速跨隙 60／60、默认协调链 10／10 通过；输入没有晚于许可窗口。
