# D103：用共同窗口接口和有界可信构造完成 G2 最后一轮修正

日期：2026-10-13。状态：**设计冻结；实施前置条件已明确。**

本决定补充 [D102](0102-prepare-and-register-motion-proof-ahead-of-handoff.md)，处理 G2 在 `fast` 阶段暴露的两个问题。实施计划见[ G2-F2 修复计划](../stages/prepared-motion-proof-g2-f2-remediation-plan.md)，失败事实见[ D102 正式验收](../acceptance/prepared-motion-proof-pipeline-d102.md)。

## 要解决什么问题

G2 首轮因量尺只等待 receiver 跑过一次循环、没有等待本作业实际发布而止于 0／1。唯一一次已授权修正 G2-F1 关闭了这个夹具问题，但完整 `fast` 又在第 25 项停止：首段证明允许 tick 11／12 生效，量尺把运动转换成 Runtime intent 时没有携带该窗口，账本因此按 11／11 记录，tick 12 的真实应用被正确判为窗口外。第二跳没有得到授权，任务安全停止。

这不是正式导航链已经确认的同类缺陷。正式 `NavigationSession` 会把动作决定的两个 tick 端点写进获胜 intent，Driver 和 Runtime 继续保留它。问题在于量尺和正式链各自拼装窗口，量尺遗漏了一个字段。

即使补齐窗口，G2 仍不能通过。前 24 个成功项每项平均触发 31 次观察请求 JSON 容量校验和 49 次不可变对象图遍历。25 项合计有 750 次 serialization、1,178 次 recursive immutable graph 检查。失败项还在同一观察上重复九次终态安全回放，共 81 个相关调用。G2 的热路径门槛是这些调用为 0，不能只修 `fast-025`。

## 决定

### 1. 动作决定到 Runtime intent 只保留一个窗口转换入口

在动作决定的 owner 模块提供一个共同转换函数。只有 earliest 和 latest 两端都存在且满足现有 0／1 tick 契约时，才返回 `MovementTickWindowV1`。只缺一个端点、窗口过期或 verified command 缺窗口时明确拒绝。普通未验证地面输入继续使用 Runtime 的精确下一 tick 默认值，不能全局放宽成晚一 tick。

正式 Session 和隔离量尺共同调用该入口。测试必须使用 `fast-025` 的真实 11／12 窗口和 tick 12 应用事实，并验证另一 intent 胜出、过期窗口和中段单条晚到仍按现有规则拒绝。

### 2. 重复容量检查改为有界原生字段证明，不关闭公共校验

`ObservationRequestV3` 的公共入口继续校验 profile、实体身份、位置类型、排序去重、128 格上限、整数范围、冲突实体和 16 KiB 上限。默认请求与内容未变的合并结果可以复用已经验证的不可变值。

对固定的原生字段，容量用可复算的最坏情况上界证明，不在每个控制 tick 再执行 `json.dumps`。当前 128 个 signed-32-bit 三元组、最长合法实体身份、最长 profile 和固定 schema 的规范 JSON 上界必须小于 16,384 bytes。新增字段、扩大身份或改变编码格式时，上界测试必须先失败。真实 backend 发送时的实际编码不在本决定中删除或改名。

### 3. 本进程可信引用使用窄构造，外部和 receiver 仍做完整接纳

现有完整公共构造器、反序列化和 receiver 校验继续执行不可变对象图遍历。控制路径只对已经由本进程完整校验、且字段集合固定的原生事实使用窄构造：prepared dispatch、activation proposal、有限 `ReferenceResult` 和与精确 handle 绑定的候选退场小事实。

窄构造必须逐项校验原生类型、身份、窗口、movement、yaw、port 和 owner；不能接受任意对象、可变容器、外部反序列化值或调用者提供的 `skip_validation`。缓存与现有最多八个登记对象一起回收并计入 bytes，不建立第二套 registry。动态命令终态、身体退出和监督者释放事实不得缓存。

### 4. 失败驱动与安全收尾分开

量尺遇到明确 typed 失败后，结束该项的正常动作循环，不能在没有新观察时继续按旧 proof 的命令长度重复调用终态检查或申请第二跳。原 owner、账本和必要安全收尾仍保留，收尾决定单独计量。

受控晚交付和中段缺失必须先检查是否存在已登记、仍覆盖真实状态的安全尾迹。没有有效尾迹时不能临时现场 rollout 后把 Neutral 当作已证明输入。若修复需要为 legacy 首段建立新的恢复证明、补新的输入包 owner 或修改客户端欠载协议，本轮立即停止，不能在 G2-F2 中顺手扩能力。

### 5. G2-F2 是最后一次限定修正

G2-F1 已使用第一轮限定修正。本决定授权三个可回退代码批次共同构成唯一的第二轮 G2-F2：

1. 窗口转换和 typed 失败驱动；
2. 观察请求重复容量校验；
3. 本地激活、引用结果与候选退场事实的窄构造。

三个批次都必须先有真实 RED，再实现和独立审查。它们不是三次正式重跑机会。只有全部定向检查通过、正常和必要拒绝／收尾路径的禁止调用为 0、资源和安全门槛无回归，才允许在唯一新目录运行一次完整 F2 fast。任何阶段再次失败就停止 G2，不设 F3，也不进入 Task 10 或 Fabric。

## 证据和来源边界

原首轮 fast、G2-F1、失败指针及 124 份引用文件保持原字节。新候选必须把 `observation_request_v3.py` 及所有实际修改文件加入 source 索引。旧 G1 只证明旧源码；修改 G1 相关生产文件后，需要建立与新源码一致的新 predecessor 索引，不能只运行旧 G1 的只读 verifier 就宣称新候选已通过。

本决定不改变 D098 P3、D101 M0、G2 当前 FAILED／STOPPED 状态，也不授权 Task 10、G3、Fabric tick 试验或客户端预排程。
