# D019：先收敛控制帧和导航主线，再增加新能力

日期：2026-09-24
状态：已采用；R0 至 R5 已完成

## 要解决的问题

C1-A 至 C1-C 已经验证正式观察、动作仲裁、唯一输入出口、输入回执和战斗结果确认。但战斗接近与追击仍使用 `skills/` 下的旧平地导航，没有进入 B04–B10 建立的 `motion_nav` 规划、接纳和执行链。

同一时期，逐帧推进权分散在多个驱动器中。移动、视角和攻击因此被写成互斥操作。验收用的严格失败处理也直接关闭运行时，不适合以后常驻运行。继续增加盾牌、食物、跳劈、多敌人或复杂地形，会让这些问题扩散到更多模块。

## 决定

1. 在 B11 和新的战斗能力之前插入 C1-R“公共控制与导航收敛”阶段。
2. 保留 C1-A、C1-B、C1-C 的原始验收结果。文档明确这些结果验证了共享观察、仲裁、输入和回执链，没有验证战斗已经使用新的 `motion_nav` 导航主线。
3. Runtime 成为唯一逐帧推进者。技能每帧只提交有身份、有期限的意图和状态报告，不能自行调用后端推进一帧。
4. 仲裁按操作种类检查兼容关系。首批只开放移动、转头和 `attack_entity` 同帧；界面、容器、挖掘等操作继续使用各自的限制。
5. 建立正式 `NavigationSession`。它拥有目标生命周期、当前路线、接纳进度和导航报告；读取唯一世界知识和状态锚点；产生移动与视角意图；不写游戏输入，也不调用 Runtime 推进。
6. C1 的接近与追击迁移到 `NavigationSession`。旧 A–E 导航停止新增功能，保留为参照，待现行调用和冻结证据迁移完成后再移入 `legacy`。
7. 外部运动拆成“伤害事实”和“运动残差”。伤害、吸收心和受击动画说明角色受到了什么；实际身体状态与输入预测的差异说明身体是否受到外力。恢复控制器只根据真实身体状态、已知空间和恢复限制决定动作。
8. 单次恢复继续有界。任务级重复事件上限不再直接决定整个战斗失败，而是返回有类型结果，由任务策略决定继续、撤退或结束。
9. 运行时错误按后果分类。只有会话身份错乱、输入所有权破坏和无法安全收尾的契约错误关闭当前会话。日志缺口、可恢复的观察缺口和输入歧义分别降级证据、重新观察或重新锚定。
10. B09-R 计算器用于一个带速度动作试点。离散动作类型、入口、出口和安全证明继续保留；局部求解器负责寻找具体逐 tick 输入，不用无约束按键搜索替代整个动作图。
11. 正式本地验收全部通过后再更新独立 GitHub 仓库。公开快照必须在临时目录中证明内部导入闭合、声明的测试可运行、哈希清单一致，README 只陈述实际可复现的结论。

## 不在本轮完成

- 不新增食物、盾牌、拉弓、声音感知或完整 Jev 战术选择；
- 不实现所有动作的带速度入口；
- 不删除三版参照、旧验收证据或失败运行；
- 不把外部审查直接改写成阶段验收结论；
- 不引入学习模型、ROS、GPU 规划或新的通用插件框架。

## 原因

逐帧推进、导航会话和世界事实是后续能力共同依赖的边界。先修这三处，新增跟随主要改目标，新增战斗动作主要改技能和兼容规则，新增运动能力主要改动作边、求解和执行。若先继续堆战斗策略，之后每个策略都要再次迁移控制和导航。

局部求解器放在收敛工作之后，是为了先得到唯一状态和唯一输入来源。否则计算器即使给出正确轨迹，也无法可靠判断从哪个真实 tick 开始、实际应用了哪些输入，以及哪个技能仍拥有身体。
