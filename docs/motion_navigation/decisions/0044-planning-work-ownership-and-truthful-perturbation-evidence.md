# D044：规划状态必须拥有工作，扰动证据按实际效果记录

日期：2026-09-30

## 决定

导航会话处于 `PLANNING` 时，必须满足以下条件之一：

- 正在分片构建快照；
- 已提交一个仍在调用方期限内的后台请求。

路线因依赖变化被接纳器拒绝时，会话立即从当前身体状态创建新请求。它不能只把状态改回 `PLANNING`。后台结果即使已经返回，只要调用方期限已过，也不能再被接纳。

正式模拟新增逐帧不变量 I15，直接检查“规划状态有无工作所有者”。

随机扰动证据分为三步：

1. 事件按清单生成；
2. 扰动被派发到正式测试后端或仲裁器；
3. 扰动实际改变世界、输入、回执、速度或导航移动选择。

重复移除一个已经为空的方块只算派发，不算再次生效。仲裁事件只有真正压下导航提交的移动意图时才算生效。

快照仍把所有未观测位置保存为未知。`missing_cells` 不再复制整片未知区域，而是返回第一个确实会影响当前规划范围的稳定位置。取得该位置的信息后，下一轮快照可以继续给出下一个位置。

## 原因

第二十三轮已经给后台请求加了期限，也把未知格整理放进分片预算，但独立复审发现四个边界：

- 依赖变化拒绝候选后，会话处于 `PLANNING`，却没有快照构建器和后台作业；
- 结果恰好在期限之后返回时，会绕过只针对“没有结果”的超时检查；
- 重复世界编辑和没有导航移动可压制的仲裁被误记为实际覆盖；
- 找到一个相关未知格后仍继续检查其余未知格，完成结果还复制全部未知位置。

这些问题来自共享契约没有检查完整，不需要增加新的规划器、队列或协调层。

## 影响

- `reason` 仍只用于报告；规划能否继续由工作所有权决定。
- 后台算法可以替换，但每个已提交请求都必须有身份和期限。
- 信息获取可能分多轮取得未知格，不能把未返回在 `missing_cells` 中的位置当作已知。
- 验收报告中的“应用次数”只表示实际产生效果，不能由事件数量推断。
- 本决定不改变运动计算器、正式视觉、动作执行和输入权限，因此不新增 Fabric 能力声明。

## 后续修订

复审证明，“第一个会影响规划范围的未知格”不一定是当前搜索真正缺少的信息；依赖变化后的直接重发也没有经过共享重试账本。D044 保留已经验证的工作所有权、期限和扰动统计决定；未知信息选择及重试所有权由 [D045](0045-reopen-s5-for-planning-behavior-ownership.md) 和 R25 修订。
