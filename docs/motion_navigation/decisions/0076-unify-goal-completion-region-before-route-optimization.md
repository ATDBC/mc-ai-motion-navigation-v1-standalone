# D076：路线优化前统一目标完成区域

日期：2026-10-08。状态：已接受，待按 F2-S 方案实施。

## 要解决的问题

F2-R 修复了障碍物把目标切成 L 形时的原地拒绝。平台外角、桥头和柱顶仍有同类问题：目标内存在可站点，但完成区域的一个顶点支撑比例低于 `0.5`，整个区域因此被拒绝。

当前 Session 用点查询选择目标支撑面，规划尾段部分使用点查询，路线接纳使用区域查询。同一个问题有两套判定，才会反复出现“前面选中，后面拒绝”。

## 决定

1. `standable_region_in_goal()` 成为正式目标可用性的唯一真值。Session、需要真实终点的规划尾段和路线接纳使用同一查询。`surface_overlaps_region()` 只保留为便宜的必要条件，不代表可执行。
2. 先使用碰撞和净空把目标切成精确矩形块。对每个矩形建立支撑边界网格，寻找所有顶点支撑比例均不低于 `0.5` 的最大子矩形。最后在所有精确块中全局选择面积最大的一块，不能只检查障碍裁剪后的最大块。
3. 支撑比例在单个网格内是双线性函数。只有子网格全部顶点合格，才能证明整个矩形合格。不用离散采样代替证明，不降低支撑门槛。
4. 选定矩形后，重新收集该矩形的净空、支撑和边界依赖。放弃区域的支撑依赖不能进入执行契约；真正定义边界的障碍 owner 继续保留。
5. 完成区域仍是原 `GoalState` 内的正面积轴对齐矩形。目标完全落在一个支撑网格内，而门槛切面穿过该网格时，本阶段继续返回 `UNSUPPORTED`。不为尚未成功的任务引入二分求根或零余量站位。
6. 不采用“旧点查询可行，区域查询必须可行”作为无条件不变式。正式不变式是三个调用者得到同一区域结论；历史已成功且具有正面积余量的任务不得因为查询分裂而退步。
7. D061 分别报告生产控制耗时、模拟后端耗时和完整夹具耗时。生产准备 P95 `≤ 8 ms` 继续是产品门槛；完整夹具 `≤ 50 ms` 保留为测试健康门槛，不再描述为纯生产控制耗时。
8. F2-R 保持关闭，原 v8 和失败记录不回写。本决定通过新的 F2-S 小批次实施，完成后再开始路线优化器。

## 不修改的边界

- 不改 Session、ExecutionSupervisor、PlanningCoordinator 和 Runtime 的生命周期、责任交接或输入权限；
- 不改中心点搜索，不实施路线平滑，不启用正式潜行区间；
- 不改身体宽度、支撑比例、危险材质、UNKNOWN 或停止尾迹门槛；
- 不删除或重新解释 v8 的无路和执行失败；
- 动作接口继续冻结，路线优化器不作为新动作的扩展探针。

## 影响

F2-S 会新增支撑边缘量尺，并把 v8 中 `9` 项无前进控制、`5` 项停滞和 `41` 项无已知路线登记为路线优化阶段的参照。`41` 项无已知路线在优化器开工前补独立物理可达标签。

主项目继续保留旧 M0–M1 计划作为隔离历史。整理后的公开快照不再导出该计划；正式结论已经保存在四类文档中。行尾治理继续留给独立的纯格式提交。
