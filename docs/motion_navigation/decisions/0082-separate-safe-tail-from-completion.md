# D082：普通地面安全尾迹与任务完成分开判断

日期：2026-10-08。状态：决定已部分实施；F2-SC 在 remaining9 门槛止损，未通过。

## 要解决的问题

F2-PC 证明了一 tick和两 tick控制都可以存在，但它把两个不同问题写成了同一个门槛：

- 如果现在松开输入，身体是否仍留在已知安全支撑和路线走廊内；
- 身体是否已经满足最终 completion，可以结束任务。

F2S-C-04 中，机器人仍在安全走廊内，而且下一玩家 tick还能继续修正。旧门槛却要求当前候选的完整停止尾迹立即落入窄 completion，于是提前淘汰了安全输入。继续调候选分数不能修正这个职责错误。

## 决定

### 1. 硬安全只检查可能生效的前缀和中性尾迹

普通 `STANDING + WALK` 候选声明 `control_ticks=1|2`。验证器必须分别检查这个许可可能产生的每个前缀：

- 一 tick许可：`0` 或 `1` tick方向输入，随后保持中性输入；
- 两 tick许可：`0`、`1` 或 `2` tick方向输入，随后保持中性输入。

每个前缀及其完整中性尾迹都必须：

- 留在已知安全支撑和已接纳的路线走廊内；
- 保持净空，不穿过碰撞体；
- 不接触已知危险；
- 不进入未获授权的姿态、运动模式或伤害状态。

硬安全尾迹不要求停进最终 completion。`0` tick前缀用于覆盖输入被压下或没有生效；中间前缀用于覆盖部分生效、晚到或回执缺失。

### 2. completion 只承担三个职责

completion 只用于：

1. 判断任务是否已经完成；
2. 计算预测停止点到 completion 的距离，供制动和方向评分使用；
3. 在一 tick和两 tick都安全时选择 `control_ticks`。

它不再决定候选是否满足硬安全。

任务完成必须同时满足：

- 当前身体位置在 completion 内；
- 当前地面模式和姿态满足目标；
- 当前终速满足目标；
- 从当前状态施加中性输入得到的完整尾迹仍留在 completion 内。

只预测将来会停进 completion，不能提前报告完成。当前位置已经在 completion 内，但速度会把身体带出去，也不能报告完成。

### 3. rollout 每次只推进一个玩家 tick

规划和执行共用的地面 rollout 每次只推进一个玩家 tick，然后从预测或正式观察到的新状态重新求值。

`control_ticks` 表示本帧输入可以安全维持的许可长度。它不是动作成本，也不能让 rollout 一次跨过两 tick。A* 的预计 tick成本要累计每次实际推进的一 tick结果，不能把两 tick许可记成一次推进。

正式执行继续以每份玩家 tick观察为边界重新计算。两 tick许可不授权跳过下一份观察。

### 4. 一 tick和两 tick按停止点质量选择

先做硬安全验证，再比较候选质量：

- 两 tick的所有可能前缀都安全，且预测停止点更接近 completion、没有越过需要制动的位置时，可以选两 tick；
- 两 tick虽然安全，但预测停止点会明显越过 completion，或一 tick能得到更好的制动位置时，选一 tick；
- 只有一 tick的所有可能前缀安全时，只能选一 tick；
- 两者都不安全时，不提交方向输入；
- 身体已经满足完成条件时，提交中性决定并结束任务。

比较使用到 completion 的几何距离、沿末段方向的有符号误差、预计终速和停止余量。不能使用场景 ID、目标名称、测试名称或固定“离终点多少格”的特判。

### 5. 冲过目标后允许有界反向修正

身体冲过窄 completion 后，继续把“沿原方向前进”当作唯一进展会造成停滞。末段控制应根据沿路线的有符号误差选择方向：

- 位于 completion 前方时，允许向前接近；
- 已越过 completion 时，允许反向修正；
- 反向候选同样必须通过所有可能前缀和中性尾迹的硬安全验证；
- 不得因为“反向”而越过路线走廊、踏出支撑或绕开严格动作入口。

这只是普通地面末段的闭环修正，不是规划器新增一条反向动作边。

### 6. 末段进展按 completion 距离判断

普通路线中段继续按路线弧长判断进展。进入 terminal 段后，进展改为下面任一事实：

- 当前状态到 completion 的几何距离下降；
- 预计中性停止点到 completion 的距离下降；
- 身体速度按制动计划下降，并且没有远离 completion；
- 从超调一侧进行安全反向修正。

单帧制动或换向不要求位置距离立刻下降。监视器必须使用有限窗口，并设明确的最大无进展 tick。期限用尽后返回 typed 停滞结果，不能永久往返，也不能用 reason 字符串决定流程。

### 7. 晚到、丢失和严格动作边界不变

晚到或丢失输入先由输入账本给出实际生效前缀。控制器从下一份正式观察重新锚定。未证明的额外 tick不能补发，过期输入不能延后生效。

本决定只适用于着地、`STANDING`、普通 `WALK`、随时可用中性输入安全退出的地面段。Sprint、Sneak、Crawl、Swim、Climb、JumpGap、JumpUp、ControlledDrop、离地过程、探边和连续高度严格阶段继续使用原证明链。

## 与 D081 的关系

本决定修订 [D081](0081-select-ground-control-duration-from-stopping-margin.md)。D081 保留的结论是：

- 普通地面控制需要一 tick和两 tick两种精度；
- 同一决定中的 `control_ticks` 必须贯通策略、执行和账本；
- 每个玩家 tick都要重新计算；
- 精细输入不能借用未证明的晚启动余量。

D081 被撤销的要求是“每帧候选的完整停止尾迹必须落入 completion”。F2-PC 仍然记为未通过，原 RED 和两次失败记录不改写。

## 不做什么

- 不修改 completion region；
- 不调整候选权重来制造通过；
- 不增加目标候选、重试或 Session 状态；
- 不改变通用 A* 搜索循环；
- 不把两 tick许可当作两 tick rollout；
- 不放宽 UNKNOWN、支撑、净空、碰撞、危险接触或伤害规则；
- 不把普通地面规则扩散到严格动作。

## Fail-fast

先冻结错误副本，再实现最小正式链，并首先运行 F2S-C-04。

若安全尾迹、完成判断、逐 tick rollout、控制时长和停滞窗口都按本决定实现后，F2S-C-04 的 normal 主例仍失败，只允许检查：

- 完成谓词是否错误；
- terminal 进展或停滞谓词是否错误。

只有晚到或丢失负对照单独失败时，才检查实际生效前缀是否与账本记录一致。

不得继续调权重、完成区域、候选数量或固定距离阈值。查明仍是新职责缺口时，停止 F2-SC 并另写决定。

实施与验收见 [F2-SC 阶段](../stages/F2SC-safe-tail-and-completion.md) 和 [F2-SC 验收](../acceptance/F2SC-safe-tail-and-completion.md)。

## 实施后记

`safe_tail` 与 `completion` 的职责分离已经通过聚焦检查，并让 F2S-C-04 normal 主例完成。这个结果支持本决定的核心判断：安全尾迹不应被要求每帧立即停进 completion。

remaining9 的下一层门槛只完成 `4/9`。一项仍缺 terminal completion 进展资格；四项受现有完整物理复核的三候选上限约束。后者需要改变候选复核数量或顺序，属于本决定明确禁止在 F2-SC 内调整的内容。因此保留已验证的职责分离，F2-SC 仍不关闭，后续必须另行决定完整复核的预算和选择方法。

后续决定已由 [D083](0083-verify-the-closed-ground-candidate-family.md) 给出：普通地面使用封闭的 `9 × 2` 候选域，先完整判定安全资格，再比较质量；terminal 历史进展单独修复。D082 的职责边界保持不变。
