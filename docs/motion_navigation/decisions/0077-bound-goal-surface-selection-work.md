# D077：限制目标支撑面选择的同步工作

日期：2026-10-08。状态：已实施并通过。F2-S 可以返回任务 4；本决定不代表任务 4、v9 或 Fabric 已通过。

## 要解决的问题

F2-S 已经统一完成区域的选择和复核。新的阻塞来自跟随目标修订帧的同步工作量。

修正计时器后的 `77` 帧 Windows 诊断中，完整生产计算的 P95 为 `8.8566 ms`，超过 `8 ms` 门槛。同一批样本的主要片段如下：

| 片段 | P95 |
|---|---:|
| `_surface_for_goal` | `2.7117 ms` |
| 其中精确区域选择 | `1.1172 ms` |
| Navigation prepare | `5.0374 ms` |
| Follow update | `3.1117 ms` |
| Runtime 外壳，不含后端 | `0.6591 ms` |
| Navigation adopt | `0.1304 ms` |

`_surface_for_goal` 还包含多列支撑面发现，因此它比精确区域选择多出的约 `1.6 ms` 不是空闲时间。以上片段存在包含关系，不能相加。

当前目标选面先完整查询目标覆盖的所有列，再给所有支撑面排序。跟随每次修订目标时都会重复这项工作。已完成的 F2-S 区域选择本身满足 `4/6/<10 ms`，因此本轮先减少同一次选面里的重复查询和无关查询，不改安全规则，也不把工作移入新的生命周期。

## 决定

### 1. 同一次选面共用查询缓存

`query_support_surfaces()` 新增可选的 `WorldQueryCache`。传入缓存时，缓存必须属于同一个 `WorldView`；错误世界、错误类型或跨调用复用都要明确拒绝。

一次 `_surface_for_goal()` 从支撑面发现到 `standable_region_in_goal()` 精确查询，共用同一个缓存。缓存只复用世界事实和碰撞盒，不保存目标结论，也不跨 observation frame 保留。

### 2. 按几何下界惰性发现目标列

目标列先按“该列中任何可能支撑面到目标中心的最小几何距离”稳定排序。等距时使用列坐标固定顺序。

查询过的支撑面仍按现有正式键比较：

1. `surface.position` 到目标中心的实际距离；
2. `SurfaceNodeId`。

当前最佳候选的距离不大于所有未查询列的几何下界，并且没有未知列仍可能产生更优候选时，才允许提前结束。若下界相等，只有能够证明未查询列不可能凭 `SurfaceNodeId` 赢得等距比较时才能结束；否则继续查询。

这是一项分支定界优化。它只跳过已经证明不可能改变最终选择的列。它不能用墙钟、候选数上限、机器速度或运行顺序改变结果。

### 3. 收紧 D063 的 missing 范围

D063 原来要求目标面查询返回同一次完整枚举能够确定的全部 missing。F2-SP 后，完整性改为针对“仍可能改变当前目标面选择的列”：

- 可能优于当前最佳候选的未知列必须请求；
- 与当前最佳距离相等、仍可能凭节点 ID 胜出的未知列必须请求；
- 已由几何下界证明不可能改变选择的远列，不再进入本次 missing，也不再分页等待；
- 尚未找到可行候选时，必须查询所有列并汇总全部 missing；
- 所有相关未知事实仍保持 UNKNOWN，不能当作 AIR，也不能提前授权规划。

这是对 D063 查询范围的语义收紧。它需要独立回归，不能只按性能重构处理。

### 4. 先过短门槛，再运行一次正式 D061

实现先使用冻结诊断场景和至少 `77` 个连续目标修订帧。它必须满足：

- 正式选中的 `SurfaceNodeId` 与完整查询结果一致；
- missing 按上面的相关性规则确定且稳定；
- 完整生产计算 P95 `≤ 7.2 ms`，给 `8 ms` 正式门槛保留至少 `0.8 ms` 余量；
- 区域选择继续满足 P95 `≤ 4 ms`、P99 `≤ 6 ms`、最大值 `< 10 ms`。

短门槛失败时立即停止。不得引入同帧延期、后台作业、新状态或降低目标修订频率。

短门槛通过后，只运行一次修正版正式 D061 `4096` 帧。生产总体和目标修订分层都必须满足 P95 `≤ 8 ms`、P99 `≤ 15 ms`、最大值 `< 30 ms`；完整夹具最大值保持 `< 50 ms`。原行为、安全、身份、GC、trace、pacing、deadline 和最小余量门槛全部保留。

正式 D061 失败时，F2-S 继续停在任务 3，不运行任务 4。后台或跨帧方案必须另写决定。

## 必须覆盖的测试

- 缓存类型、世界身份、单次调用边界和跨列复用；
- 分支定界结果与完整查询逐项一致；
- 列乱序、等距离和 `SurfaceNodeId` 平手；
- 可能更优的 UNKNOWN 阻塞选择；
- 已证明无关的 UNKNOWN 不阻塞选择；
- 没有可行面时查询全部列并汇总 missing；
- 非完整支撑面、多个高度带和四个方向；
- 删除缓存复用、错误早停、按墙钟停止和忽略相关 UNKNOWN 的错误副本。

## 不修改的边界

- 不改 NavigationSession 生命周期、pending goal、PlanningCoordinator、A* 或动作执行；
- 不改输入责任、支撑门槛、UNKNOWN、危险材质、目标区域或完成区域；
- 不新增 Session 状态字段、等待、重试、线程或后台工作；
- 不通过降低目标修订频率、减少正式样本或放宽性能门槛过关；
- 不重写 F2-S 任务 0—3 的历史证据。

## 后续

正式 D061 通过后，回到 F2-S 任务 4，运行 v9、旧集合和 Fabric。若正式 D061 未通过，本决定结束，不在 F2-SP 内继续扩大性能改造。

## 实施结果

实现按 P0—P4 顺序完成。`query_support_surfaces()` 现在接受单次 `WorldQueryCache`。目标选面按列到目标中心的几何下界查询，并继续用实际距离和 `SurfaceNodeId` 决定结果。可能改变结果的 UNKNOWN 仍然阻塞；已经证明无法改变结果的远处 UNKNOWN 不再进入本次请求。

第一次短 Windows 门槛为 `7.6401 ms`，没有通过 `7.2 ms`。该失败已经原样保存。唯一允许的局部修正复用了精确区域首轮已经计算的中心净空和顶点支撑结果，没有改变选择、依赖或安全条件。修正后的 `77` 个目标修订帧生产 P95 为 `6.9638 ms`。目标列 P95 为 `25`，实际查询列 P95 为 `2`。

随后只运行了一次正式 D061。`4096` 个保留帧全部生产计算为 P95/P99/max `5.1705/5.3590/7.0193 ms`；目标修订帧为 `7.0193/7.0193/7.0193 ms`；完整夹具最大值为 `28.4577 ms`。全部正式门槛通过，deadline miss 为 `0`，最小余量为 `22.0093 ms`。

来源实现提交为 `40462948`，短门槛证据提交为 `dc6b3d64`，正式 D061 证据提交为 `6f4273dd`。F2-S 任务 4、v9、旧大集合和 Fabric 没有在本决定中运行。
