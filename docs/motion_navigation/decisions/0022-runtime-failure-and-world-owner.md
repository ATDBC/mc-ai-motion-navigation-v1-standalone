# D022：在 B11 前执行失败处置并固定 Runtime 世界拥有权

日期：2026-09-25  
状态：采用

## 要解决的问题

现有 Runtime 会计算 `FailureDispositionDecision`，但异常路径随后仍直接封存，分类没有真正决定生命周期动作。与此同时，Runtime 虽保存一个共享导航适配器，正式观察只有在导航会话调用 `ingest()` 时才进入世界知识。没有导航任务时，地图不会更新；构造会话时遗漏共享适配器还会产生第二份地图。

## 决定

1. 失败分类仍由 `FailureDispositionPolicy` 唯一负责，Runtime 负责执行结果；
2. 证据降级、任务重试、任务取消、Runtime 重建和世界结束采用不同动作，不能都用“记录后封存”代替；
3. 任务级处置只清理任务输入并安排下一帧中性释放，不在处置函数里推进后端；
4. 可能已经向客户端提交但无法确认的输入继续要求重建 Runtime；
5. Runtime 在正式 V3 reset 和 step 边界更新唯一 `NavigationObservationAdapter`；
6. 正式导航驱动负责把会话绑定到该适配器。导航会话拥有路线，不拥有第二份世界事实；
7. 离线组件可以显式拥有独立世界，但不能进入正式 Runtime 控制链冒充共享地图。

## 影响

- C1-R6 成为 B11 的进入条件；
- B11 的放置和搭桥可以依赖持续存在的世界知识和明确的局部失败处理；
- B12-A 仍负责攻击拒绝／未确认计数和多来源命中归因；
- B12-B 仍负责横移、后撤和部分观察下的战斗运动；
- 本决定不放宽输入回执、世界身份、空中责任或正式 trace 的安全门槛。
