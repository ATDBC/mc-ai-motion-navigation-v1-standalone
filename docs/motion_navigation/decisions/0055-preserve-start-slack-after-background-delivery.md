# D055：后台交付后仍保留已验证的启动余量

日期：2026-10-03。状态：P1—P4 已完成，本轮启动交付门槛按已声明范围关闭。依据[下降退步根因调查](../acceptance/r28-drop-failure-root-cause.md)。本决定补齐 D052 的交付条件，保留其后台复核、真实输入核对和身体责任规则。

## 要解决的问题

当前后台求解把启动窗口放在源观察后的两个 tick。结果到达时通常已过一个 tick，首条输入便没有迟到余量。恢复后又使用同样安排。六个新增下降失败已通过小范围对照定位；其他任务完成不能证明该余量仍存在。

旧版现场复核能重新提供余量，却把完整运动推演放回控制线程。直接恢复这条旧路径，会重新引入 D052 已测得的控制成本问题。只增加期限或重试次数，也没有证明身体在新时刻仍能安全启动。

## 决定

1. 准备输入、后台交付和首条输入生效使用同一条时间线。求解器预测实际准备过程，结果第一次获得执行资格时仍应保留本能力声明的一 tick 首条输入迟到范围。
2. 普通等待、提前接近和后台复核复用现有准备前缀、启动变体与输入账本。准备只由现有身体拥有者提出，经原仲裁出口发送；后台不控制身体。
3. 准备期间的姿态、视角、支撑、实际输入与预测不符，仍需重新求证。已发送或已启动的动作保持原证明和原收尾责任，不通过刷新窗口重置责任。
4. 后台变慢时先检查已声明的准备范围与现有期限。复用已观测到的往返时间安排有限准备，不建立无限变体、不每帧重搜、不为不同动作复制等待账本。
5. 此轮同时检查下降、跨隙和一格上升的共同入口。局部修复不得绕过落点证据、伤害余额、支撑、视角仲裁或停止尾迹。

数值和接口只维护在[动作衔接架构第 7.1 节](../architecture/action-continuity-v1.md#71-准备交付与首条输入的共同时间线)。实施顺序见[R28 阶段第 11 节](../stages/navigation-coordination-convergence-r28-plan.md#11-补齐后台交付后的启动余量)，验收见[R28 验收第 14 节](../acceptance/navigation-coordination-convergence.md#14-d055-启动交付修正的验收计划)。

## 范围和取舍

本轮交付是恢复已声明动作的启动容错，并保持连续性和在线性能。没有新增运动方式；全局路线、未知探索、室内贴墙、正式跟随和 R28 共享协调迁移的范围保持原计划。新增的非阻塞问题登记后排期。

不能以“六场不再报错”作为完成条件。先恢复共同启动条件，再用原固定清单检查完成、耗时和安全。严格动作中途输入丢失仍可能正确返回有界失败，不能为了完成率取消回执验证。

这是行为修正，不宣称逐帧等价。原 v4、v5 和所有失败保留，修正后的候选另存证据。R28 原时间盒和复核规则继续适用，本决定不自行延长阶段或把一次失败重新算作新批次。

实际结果与限制见验收第 14.5—14.7 节。下降实机在已知落点、持续向下观察的条件下通过；平视时信息获取打断准备的失败仍保留并登记，不能把本轮启动修正写成该问题也已解决。R28 整阶段仍打开。
