# D038：探边、重复重规划和下落额度由明确状态管理

日期：2026-09-28

## 要解决的问题

直接下落前的探边曾由一个原因值和一个布尔保持位驱动。目标变化后，这个保持位仍会覆盖新路线的移动输入。输入失联和停滞又会无限重新规划。伤害额度只在下落成功后记录，旧规划结果还可能使用已经消耗的余额。

这些问题来自同一个缺口：动作已经开始产生影响，但没有一个对象负责保存它处于哪一步、什么时候结束，以及已经承诺了什么风险。

## 决定

1. 探边由 `LandingEdgeProbe` 独立保存生命周期。会话负责创建、取消和读取结果，不再根据字符串原因或布尔位直接覆盖路线输入。探边依次经过接近斜侧观察位、保持潜行观察、横移到下落中心线、减速松开潜行、恢复原视角和交出证据。路线不能在观察位直接接管身体。
2. 普通落点证据要求 4.5 格内、足够新且下部可见。探边证据可以超过 4.5 格，但必须在到达边缘后取得、下部可见，并且只适用于探边绑定的落点格。
3. 输入失联在安全落地后结束会话。停滞等可恢复错误在同一支撑面和同一世界几何修订下最多重新规划两次。
4. 需要地面证明的 Walk 只允许出现在首个连续地面段。经过空中动作或 Step 后，规划器在同一次搜索中直接使用不依赖该证明的后备边。
5. 受伤下落离开起始支撑时就占用任务伤害额度。接纳新路线时必须按当前余额复核，不能信任请求发出时保存的旧余额。
6. 直接下落的计时分成两段。第一次面对未知落点时，单独记录探边取证用时；`ControlledDrop` 从首条已验证前进输入到确认落地，继续与持续前进参照比较。完整任务仍报告端到端用时，不能删掉取证成本。原来的“参照加 3 tick”门槛用于下落动作执行，不再把一次性的环境取证当成移动控制耗时。

## 为什么这样做

探边会直接控制身体，必须和跳跃、下落一样有明确所有者。重复重规划和伤害额度也属于会话的长期状态，不能由某一帧的原因字符串间接决定。

例如，机器人潜行到悬崖边后，目标转到平台另一侧。旧实现会继续只按潜行键，新路线无法横移。新实现会因目标修订结束探边，随后由新路线取得移动控制权。目标没有变化时，机器人会先从能看见落点下部的斜侧位置横移到下落中心线，不会从观察角直接斜着掉下去。

## 边界

- 本决定不增加新的下落高度，也不放宽伤害额度。
- 探边取得的证据不会变成永久通行许可。目标、落点格、相关世界事实或证据时效发生变化后，必须重新检查。
- 当前代表性批次中，2、3、5 格下落各用了 27 个控制帧取证。该数字只说明当前实现的成本，不是完整矩阵的正式上限。验收必须同时保留取证、动作执行和端到端三种时间。
- 首版仍不证明空中动作出口到后续小高差 Walk 的连续入口。规划器在该位置使用 Step 后备动作。
