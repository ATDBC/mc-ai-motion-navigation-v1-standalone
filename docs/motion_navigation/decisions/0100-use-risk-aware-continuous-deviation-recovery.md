# D100：按当前风险处理偏离，安全区域默认连续运动

日期：2026-10-11。状态：设计已冻结；尚未授权实现、正式链接入或新 Fabric 验收。

## 要解决什么问题

项目的目标一直是丝滑、连续的玩家式运动。机器人在宽阔安全区域内，不应为了回到格心、精确落点或某个理想入口而停住。连续跳跃和连续跨隙允许落点存在偏差；只要身体仍在安全区域，并且还能接上后续动作，就应在运动中完成转向、横移、加速或减速。

现行链已经具备带速入口、路线走廊、动作证明、输入账本和身体责任，但偏离后的处理仍不完整。普通地面离开既有走廊时，常会先结束当前控制，再进入完整重规划。相关世界变化也容易统一进入停止流程。这能保守退出，却不能满足连续运动的产品目标。

偏离的原因很多，例如输入晚到、外力、落点误差、目标变化或地形改变。如果分别为每种原因、每种动作组合建立恢复分支，组合数量会不断增长。真正决定怎样处理的，应是当前身体是否安全、原路线后段是否还能使用，以及动作是否已经越过难以撤销的承诺点。

## 决定

后续连续运动按当前风险处理偏离，不把“停止再重规划”作为统一默认动作。

### 1. 安全区域内默认继续

身体仍在已知、宽阔、可停车的安全区域时，位置和速度偏差优先在运动中消化：

- 仍处于当前输入包允许范围时，继续执行；
- 已离开理想轨迹但能接回原路线时，连接到前方安全位置；
- 原路线后段失效但当前前段仍安全时，继续可用前段并在后台重规划；
- 下一动作接受当前位置、速度和方向时，直接交接，不为进入参考点而停车。

格子中心、规划节点和候选参考点只用于搜索与计算。它们不自动成为身体必须经过或停住的物理目标。

### 2. 按三个事实选择处理方式

偏离判断只回答三个问题：

1. 当前身体是否仍在已知安全区域；
2. 原路线的安全后段是否仍有效且能够接回；
3. 身体是否已经越过起跳、离边、下落等承诺点。

偏离原因继续记录，用于诊断、归因和统计，但不各自拥有恢复状态机。

| 当前情况 | 处理方式 |
|---|---|
| 仍在当前安全范围 | 继续短输入包 |
| 地面安全，能够接回原路线 | 在运动中局部接回 |
| 地面安全，原后段失效 | 继续安全前段，同时后台重规划 |
| 正在逼近坑、伤害区或其他危险 | 先朝远离危险的方向移动，再恢复任务方向 |
| 已越过承诺点或处于空中 | 原 owner 负责安全落地或安全收尾 |
| 没有可证明的安全处理 | 交给任务层换路、等待、消除威胁、改变地形或结束任务 |

### 3. 局部接回不创建第二条控制链

局部接回只产生短期目标，例如可接受区域、优先方向、希望保留的速度和有效期限。现有地面控制器继续根据真实观察选择输入；它仍通过唯一输入出口执行。

局部接回目标不拥有身体，不保存第二份世界或路线，也不创建新的导航任务。接回失败时，才升级到现有完整重规划。

路线优化器以后可以提供非格心折线或平滑路线。局部接回依据路线几何、走廊和下一入口工作，不依赖八方向移动或格心节点，因此可以直接复用。

### 4. 危险规避先改变风险趋势

身体已被推向坑边或伤害区时，原地松键未必安全。系统应比较短期候选，让下一步预测远离危险，同时尽量保留任务的大方向。只有无法证明这种移动安全时，才采用已证明的停车、退回或有界失败。

危险规避只使用已知地形和现有运动能力。UNKNOWN 不能当作安全出口。高危任务是否值得继续，由后续任务和策略层决定；运动层不负责强行通过。

### 5. 承诺后先完成身体责任

起跳、离边或下落已经发生后，任务目标、理想落点和下一动作入口不能替代身体安全。当前 owner 先负责：

- 复用仍覆盖真实状态的安全后缀；
- 必要时改为安全落地区域或安全停止状态；
- 一直保留控制权，直到身体满足正式交接条件。

安全落地不等于任务成功。落地后再从真实位置局部接回或重新规划任务目标。

### 6. 连续动作使用范围，不使用精确点

下一动作通过 `SegmentEntryWindow` 等现有契约声明可接受的位置、速度、方向、姿态和支撑范围。前一动作只需把身体送入这个范围，不需要知道下一动作的具体类型。

连续跳跃或跨隙落到宽平台的其他安全位置时，应优先保持速度并调整到下一入口。只有下一入口确实要求低速、空间过窄、接近危险，或没有安全后缀时，才减速或停车。

### 7. 沿用 D099 的短开环执行方式

本决定不恢复 D098 的逐 tick 完整重证。后续仍采用 D099 的方向：

- 控制器发出有限的短开环输入包；
- 客户端逐 tick 记录输入和身体事实；
- 普通 tick 只比较输入、状态范围、依赖版本和直接事件；
- 只有相关变化、明显残差或关键节点才重算；
- 越过起跳、离边、下落等节点前保留严格检查。

短输入流的整体按时／整体晚一 tick 语义已由 D101 澄清；实际客户端 tick 顺序和发送方式仍须由后续最小试验确认。当前 Runtime 的正式许可窗口不因本决定改变。

[D101](0101-clarify-short-open-loop-timing-and-lifecycle.md) 已进一步冻结这句话的含义：0／1 tick 只属于输入流起点，第一条实际应用回执立即上报；之后的单条晚到或缺失属于偏离。是否必须预排程仍等待 Fabric tick 顺序试验，不能在设计阶段假定。

证明有效范围与外力归因阈值彼此独立。前者决定旧输入是否仍有资格，后者只说明偏移可能由什么造成。关键节点的身份、时序分支、身体范围和依赖都一致时，只比较已有证据，不重复运行完整证明。

安全余量由控制器瞄准区域内部、保留速度和落点余量，并在最后可放弃点前重定承诺时形成。不能通过事后扩大旧证明范围获得余量。

### 8. 输入流必须有 generation 和有界收尾

输入流绑定不可变 generation。目标修订只有在输入内容、许可或安全后缀确实需要改变时才换代，持续跟随不会因为每 tick 修订目标而反复撤销仍然有效的安全前段。取消可以阻止尚未实际应用的未来命令，包括客户端已经接收但尚未采样的命令；已经进入采样或已经应用的输入继续保留事实，并由原 owner 收尾。

新的 generation 可以提前准备，但只有旧流到达可交接边界、冲突的未来命令已有明确撤销终态、Runtime 选择新流以后，才能替换旧流。计算结果准备完成不等于控制权已经交接。

客户端欠缺下一条及时输入时，只能执行输入流声明的有界安全尾段。不能无限保持上一条输入，也不能把缺输入解释成中性输入。完整协议见 D101。

## 复用现有职责

- `FixedRouteController` 是宽阔普通地面的唯一控制路径，继续负责地面输入、路线进度、有限候选和刹车；局部接回应成为它消费的短期目标。
- `GroundTraversalPlan` 继续提供走廊、依赖、输入和出口，不复制第二份权威路线。
- `SegmentEntryWindow` 与 `MotionContinuationRequirement` 继续表达下一动作入口和恢复入口。
- `ActionRouteExecutor` 与 `MotionRouteCoordinator` 继续负责动作次序、严格动作和同一路线内部交接。
- `ExecutionSupervisor` 继续拥有身体控制权与交接。恢复不会创建另一个 owner。
- `ActiveRouteTracker` 继续按实际依赖过滤世界变化。
- 输入账本、直接外力事件和 `MotionResidualTracker` 继续提供事实。直接事件优先，残差用于补漏。
- `NavigationSession` 只接收局部处理无法完成后的正式重规划或任务结果，不增加动作组合专用状态。

下一动作由现有协调器在当前动作仍运行时提前计算。提前候选不拥有身体，也不授权输入；交接时继续核对真实入口、generation、依赖和原 owner 的释放证据。

## 禁止的实现方式

- 不为 Walk→Jump、Jump→Jump 等动作组合增加专用恢复分支；
- 不为晚到、外力、目标变化和方块变化各建一套状态机；
- 不把中性输入或停车当作所有偏离的默认安全动作；
- 不要求身体回到偏离点、格子中心或唯一落点后才能继续；
- 不因普通新观察每 tick 重算完整轨迹和所有停车尾迹；
- 不新增恢复控制器、第二输入出口或第二份身体状态；
- 不用墙钟决定搜索范围或行为结果；
- 不为尚未授权的极端风险继续扩充恢复矩阵。

## 验收原则

后续实施必须同时验证安全和运动质量。

安全门槛继续为零容忍：无人负责的输入、把 UNKNOWN 当可通行、超出任务伤害额度、承诺后直接释放身体、相关变化后继续使用失效严格依据，均不得发生。

产品门槛至少覆盖：

- 宽阔安全区域内的偏离不产生非必要完整停车；
- 能局部接回时不返回偏离点或格子中心；
- 连续动作落地到下一段有效输入的空档有明确上限；
- 运动用时、反向输入、速度保持和停顿相对计算器参考没有明显退步；
- 危险规避的首个恢复输入使预测风险降低；
- 局部接回失败能够有界升级为正式重规划。

性能继续在 Windows 正式环境测量。稳态监视不得执行完整搜索或整段物理重放；相关事件只复核实际依赖；严格计算不得阻塞约 20 Hz 控制线程。具体输入包长度、接回范围、性能数值和场景数量由下一阶段计划冻结。

## 与既有决定的关系

本决定细化 D048 的按风险恢复、D052／D053 的连续入口和安全落地分离，以及 D099 的游戏优先短开环方向。[D101](0101-clarify-short-open-loop-timing-and-lifecycle.md) 补齐输入时序、证明范围、提前计算和生命周期协议。它不降低 D089 的范围控制，也不改变 D094 已完成的失联后着地重规划能力。

D098 的 P3 失败、性能结果和原始证据保持不变。本决定不授权 P4，不修改 `mc2p`，不运行新的 Fabric，也不声明连续偏离恢复已经实现。下一阶段必须先写实施计划和验收文档，再决定是否进入生产代码。
