# D046：为异步工作生命周期重新打开 S5

日期：2026-09-30

后注：R26 的关闭记录保留。后续复审发现共同入口仍有缺口，现行整改范围与门槛以 [D047](0047-enforce-async-admission-and-test-formal-path.md) 为准。

## 决定

导航协调 S5 重新打开。暂停新增能力，先统一规划、动作求解和放置确认中重复出现的三条规则：

1. 工作从产生需求时开始拥有稳定身份和固定期限；
2. 所有异步结果先核对工作身份，再核对当前事实；
3. 工作所有者统一负责终结和完整退场。

本轮不进行第二次大重构。保留 Runtime 唯一输入出口、`ExecutionSupervisor` 身体责任、任务级 `RetryLedger`／`TaskRiskLedger`、不可变规划快照和现有领域结果类型。

实施范围和关闭条件见 [R26](../stages/navigation-async-work-lifecycle-r26-plan.md)。

## 原因

R25 已经把规划快照、worker 和候选收进 `PlanningCoordinator`，但期限仍从 worker 提交后才开始，旧信息和旧否定结论也没有在接纳时按当前世界复核。继续审计又发现同类问题出现在动作求解和放置确认：提交前背压没有期限、旧动作结果会终结新修订、部分放置证据会绕过确认超时。

这些问题说明缺少的是跨阶段规则，不是更多局部超时和 ID 比较。只修单个分支，会在下一种异步结果或新的中间状态中再次出现。

## 影响

- 规划尝试从开始构建快照时计时，快照重建不能延长期限；
- 规划计算和后续信息取得是两个关联但分别计时的工作；取得信息不能刷新旧规划期限或恢复任务总额度；
- 动作求解从执行器需要证明时计时，背压、提交和返回共用期限；
- 放置事务的部分确认不能绕过固定期限；
- 路线、信息需求、无路线、动作证明和交互确认都要经过身份与当前事实接纳；信息确定为阻塞也算取得事实，不等于路线可行；
- 共享 motion worker 的结果由唯一入口按完整身份分发；
- 取消、替换、终态和关闭使用工作所有者按 identity 完整退场的入口，不能由旧 identity 清理 owner 的新工作；
- R25 已有实现和历史证据继续保留，但不足以支持当前 S5 关闭结论。

## 不影响

- 不改变物理、几何、路径评分、视觉空气和输入权限；
- 不新增运动或探索能力；
- 不清空任务级失败和风险历史；
- 不把任务终结等同于身体责任终结。

## 实施结果

本决定要求的整改和验收现已完成，S5 重新关闭。重新打开的历史原因继续保留，不能从文档中删除。

R26 已按领域完成原子迁移：

- `PlanningCoordinator` 从快照需求开始建立固定窗口，并在接纳路线、信息需要和否定结论前复核当前事实；
- 补充信息使用独立 identity，只有协调器重新运行类型化查询后才能报告取得事实；
- motion 求解从首次缺少证明时开始计时，共享 worker 通过单一有界邮箱按完整 identity 分发；
- `BlockPlacementTransaction` 在交互提交时建立确认窗口，世界与库存证据无论先后都不能绕过期限；
- owner 的退场保持幂等，旧 identity 不能清理当前新工作；三类 owner 都保留有界接纳记录。

B11 的正式 Runtime 链还发现一个相邻问题：机器人在边缘准备放置时若被推离旧短路线，旧 `FixedRouteController` 会直接令事务失败。现在只有在当前观察确认身体仍着地时，才从当前位置重新建立短路线；原准备期限不刷新，潜行继续保护边缘。

这项修正只覆盖已经确认着地的位移。独立 B11 driver 没有接入 C1 的空中外力恢复，因此本轮不把“放置准备期间被推到空中”写成已验证能力，也没有复制第二套空中恢复控制器。以后组合 B11 与外力恢复时，仍由任务级控制组合把身体责任交给现有恢复链。
