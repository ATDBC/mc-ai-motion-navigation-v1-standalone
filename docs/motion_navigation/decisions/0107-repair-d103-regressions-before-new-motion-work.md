# D107：先修复 D103 回归，再恢复新的运动阶段

日期：2026-10-14。状态：**已完成。**

## 要解决什么问题

D106 的 R2、R3 结论成立，R1、R4 也按预登记规则停止。但 D103 发布后留下两类回归：

1. 旧的异步复核、重试、持续预算和重新锚定路径出现行为失败；
2. 重复观察只更新时间戳时，也会重建并深度校验整个世界 section，导致控制帧和完整测试变慢约一个数量级。

正式 Windows 抽查已经确认这两个问题。`test_r27_async_admission` 当前 25 项中有 15 个失败、1 个错误。F1 缩短场景 80 tick 用时 14.6 秒，约 182 ms/tick；其中 section 提交占 93%。

过去三轮停止了长时间没有进度的完整测试，但没有把它拆成可定位的模块运行。结果是“完整测试没有被宣称通过”，却也没有阻止新阶段继续。这不符合 fail-fast 的目的。

## 决定

### 1. 暂停新能力

在 D107 关闭前，不开始连续两跳、零等待交接、T2-3、新动作、R1 方案 B、B10 带速入口修正或同步起始证明门槛调整。

### 2. 先恢复观察摄取的增量成本

物理快照只因会影响运动计算或依赖身份的事实变化而重建。单纯刷新观察时间不能触发整个 section 的重新排序、构造和深度遍历。

修正必须保留以下事实：

- 最新观察仍更新正式世界知识和 evidence revision；
- 几何、碰撞形状、空气／方块身份变化仍使旧依赖失效；
- UNKNOWN 不能变成 AIR；
- worker 只能读取 owner 发布的不可变快照；
- 如果某个消费者确实需要最新观察时间，应从对应证据 owner 读取，不能假定物理快照保存每格最新时间戳。

不能为了性能跳过进程边界的必要校验。可以删除的是可信内部构造中重复的整图校验，以及没有运动语义变化时的整 section 重建。

### 3. 完整测试不能再以“长时间无输出”结束

新增 Windows 原生分片运行器。它逐个运行 `tests/motion_nav/test_*.py`，每个模块有独立期限，持续写出当前模块、用时、退出状态和结构化报告。

模块超时属于失败，不能当作未运行。正式阶段入口要求所有模块完成，且没有失败、错误或超时。平台例外必须提前登记，不能在运行后临时忽略。

### 4. 逐项处理 D103 后的失败

失败分为三类：

- 正式行为改变：修生产代码；
- 测试替身不再符合公开契约：先证明正式行为正确，再更新替身；
- 冻结指标或导出元数据过期：记录变化来源后更新。

不能只为了全绿改变预期结果。异步后继已有证明时应复核还是重求解、持续预算如何结束、旧结果如何退场，都必须按现行职责和原安全语义判断。

### 5. D106 的结论不回写

D106 的 R1—R4 原结果保持原样。D107 可以说明 D103 性能回归是否影响了 B10 控制帧，但不能把相关性写成已经证明的因果，也不能用 D107 结果覆盖 D106 的失败记录。

## 完成条件

- 重复的同语义观察不再重建整个不可变 section；
- F1 缩短场景在正式 Windows 上回到每 tick 不高于 40 ms，且没有安全结果变化；
- 已登记的 11 个失败模块全部通过；
- 完整 `tests/motion_nav` 通过分片运行器完成，失败、错误、超时均为 0；
- D106 的 78 项直接检查和公开导出检查保持通过；
- 用现有 trace 记录 D103 前后控制帧和 movement tick 间隔，给 B10 后续工作提供事实依据。

任一修正如果需要新增平行状态机、放宽 UNKNOWN 或伤害规则、改写旧失败证据，立即停止并重新评估。

## 实施结果

D107 已满足完成条件。F1 缩短场景从约 182 ms/tick 降到 14.57 ms/tick；计划列出的 11 个回归模块全部恢复。最终 Windows 正序、逆序分别运行 184 个独立模块、2264 项检查，均为零失败、错误、超时和跳过。公开导出校验通过。

本轮没有新增平行状态机，没有放宽 UNKNOWN、伤害或动作证明规则。D106 的停止结论和旧失败证据保持原样。B10 trace 缺少 D103 前的同口径原始记录，因此“观察性能回归是否造成 D106 跨 tick”仍无法判断。
