# D026：修正 B10／B11 回归，并保留移动与交互组合边界

日期：2026-09-25
状态：已采用

## 要解决的问题

B11 首轮通过后，三方复审发现五类边界：B10 探针重复写世界并反复启动后台进程；目标修订会补充搭桥额度；放置期间无法安全更新目标；走位和瞄准没有期限；受击后缺世界格可能把同一次事件拆成“伤害”和“无来源外力”。

这些问题不改变 B11 的放置确认原则，但会影响常驻运行、跟随任务和跨阶段回归。

## 决定

1. Runtime 继续是实时世界知识的唯一写入者。B10 实机探针直接读取 Runtime 已生成的导航帧，不再用第二个适配器重复写入。
2. 一个 B10 探针会话只启动一组长期存在的规划与动作求解 worker。单个试次借用它们，结束时不反复创建进程。
3. 中性落地责任可以没有“已验证命令编号”。探针仍发送并记录该帧，同时保存具体失败原因；只有实际动作命令才必须带完整许可窗口。
4. `NavigationSession` 的一次实例对应一个任务授权。搭桥额度在实例创建时确定，目标位置修订不会补充额度。新任务需要新建会话。
5. 放置操作尚未发出时，目标修订取消旧站位和旧交互，再恢复导航。操作已经发出时，继续等待正式观察确认或失败，并只保留最新目标修订。旧操作确认成功或报告世界依赖变化后再切换；其他终端失败仍按原失败结束，不能用新目标掩盖异常。
6. 放置准备最多等待 120 次新观察。操作连续 20 次新观察未赢得仲裁也会失败。确认阶段继续使用事务自己的 tick 期限和两次尝试上限。
7. 有伤害事实但残差因缺世界或缺输入而中断时，不产生“无来源外力”。能够补齐相邻证据就正常归因；跨过可归因区间或等待到期则进入 `DAMAGE_WITH_UNVERIFIED_MOTION`。

## 后续同帧移动与交互

B11 仍采用“停稳、交接、放置、确认、恢复导航”。以后要做战斗中筑墙、移动中放置或跳起垫块时，不复制第二套身体控制器：

- 当前移动执行器继续负责身体和落地；
- 世界交互能力只提出视角与操作通道；
- 仲裁器按明确兼容规则把移动、视角和放置合成同一控制帧；
- 一旦组合输入改变原动作的入口、中间状态或出口，重新验证受影响的轨迹与接续；
- 动作证明若计划在途中改变世界，必须预先写明发生变化的运动 tick、格子和预期结果。执行器只把这些声明过且按时得到观察确认的变化视为证明的一部分；其他变化仍使受影响的后续证明失效；
- 方块是否真正出现，仍由后续观察和库存变化确认。

这只是后续能力的接口边界，不表示 B11 已支持边走边放。

## 证据

- B10 完整 Fabric 回归：`20260925T103445684561Z-9a2d62d9`；固定跨隙 40／40、转弯出口 40／40、带速 60／60、默认协调 10／10，210 个协调控制帧没有晚于许可窗口。
- B11 完整 Fabric 回归：`20260925T104441670754Z-64a4005e`；60／60 正例、20／20 反例，90 次放置得到正式确认。
- 受击缺世界格的复现按“伤害存在、运动未验证”结束；没有再生成无来源外力事件。

## 二次复审补充

后续复审又发现四个边界，并按原职责修正：

- 当前路线起点按身体碰撞箱覆盖的支撑面确定。身体中心越过边缘，但碰撞箱仍压着原方块时，不再误报 `current_surface_unavailable`；
- B10 探针直接使用 Runtime 的输入账本，已验证命令的生效窗口也由 Runtime 在提交前登记；探针不再重复登记中性落地帧；
- 放置操作发出后停止消耗“准备阶段”期限，等待确认只受事务自己的确认期限约束；
- 完整的多 tick 匹配残差可以证明该区间没有预测外运动。多 tick 偏差不能定位偏差实际发生在哪个 tick，因此只形成“受伤后运动未验证”，不能标成击退；因缺世界或缺输入形成的区间空洞也不能跨过。

公开树校验忽略运行测试自然生成的 `__pycache__` 和 `.pyc`，但其他未登记文件仍会让校验失败。这样不会把缓存当成源码，也不会放宽公开清单边界。

最终回归没有放宽既有门槛。B10 在两次独立运行中暴露出形状查询重复计算，修正为一次求解内按不可变依赖复用碰撞形状；活世界视图在复用前批量核验分区修订。正式运行 `20260925T123521898324Z-5d0a66dc` 的 142 次求解最大值为 27.8626 ms，全部功能样本和 210 个协调控制帧通过。C1-C 正式运行 `20260925T124344500270Z-ac8d6347` 为 20／20 正例、10／10 反例。B11 正式运行 `20260925T120057978030Z-c17b889e` 为 60／60 正例、24／24 边界和反例。
