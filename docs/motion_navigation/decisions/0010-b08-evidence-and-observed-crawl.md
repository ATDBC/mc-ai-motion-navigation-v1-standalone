# D010：B08 使用实际姿态识别 Crawl，并按证据性质安排重复次数

日期：2026-09-19
状态：已采用

## 决定

低通道 Crawl 以正式观测中的 `pose=swimming` 且未浸没在水中为准，不要求 `isSwimming=true`。B08 只接受已经合法存在的 Crawl 状态，不实现入口动作。

连续运动的误差、制动和控制耗时会受真实 tick 与客户端状态影响，因此 Sprint、Crouch、Crawl 各运行 10 条实体路线。资源不足、输入失联和非法入口等纯契约分支使用明确的参数化反例；相同输入的机械重复不增加证据价值，不作为独立样本计数。

## 原因

Minecraft 1.21 实测中，一格高通道内的玩家姿态是 `swimming`，但 `isSwimming=false`。后者描述游泳标志，不能代表爬行。若同时要求两者，合法 Crawl 会被误判为入口无效。

运动轨迹需要重复测量波动。纯函数式失败分支对相同输入会得到完全相同结果，重复十次只会增加运行时间。验收仍要求每个分支有正例、反例和明确终态，但不把重复同一断言当作可靠性证据。

## 影响

- Crawl 的主动入口仍由 B13 提供。
- B08 验收文档分别报告实体重复路线和契约边界检查。
- 若后续失败分支引入时间、网络或服务端状态波动，应升级为多次实机试验。
