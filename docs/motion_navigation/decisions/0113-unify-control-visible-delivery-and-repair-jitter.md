# D113：统一控制可见延迟并修复交付抖动

日期：2026-10-16。状态：已决定，等待实施结果。

## 1. 要解决的问题

D112 如实记录为 FAILED／STOPPED，但两个阻断项混入了量尺偏差：

- 组件和 Fabric 对“延迟 N tick”的起止点不同；
- 控制准备统计把同步 B10 探针算进了生产控制帧。

同时存在两个真实行为问题：后台结果比上次晚一 tick 时，协调器仍沿用旧估计；jump-up 的纯中性准备会因惯性碰到台阶侧面并停稳，却被直接判成硬冲突。

D113 修正这些问题。D112 的历史结论和原始证据保持不变，D110-SOLVE-01 继续打开。

## 2. 延迟统一按控制线程首次可见计算

正式延迟定义为：

```text
first_control_visible_tick - worker_submit_tick
```

`first_control_visible_tick` 是控制线程第一次读取到对应 identity 结果的 movement tick。`peek()` 第一次返回结果时即算可见；真正从 inbox 取走结果的 tick 单独记录为 `result_take_tick`。

receiver 看见结果的 tick 继续记录，但不再用来命名“2 tick”或“5 tick”产品场景。旧 D112 的 `first_control_consume` 仍按当时的取走时刻解释，不改写旧记录。

中性准备上限保持 5 tick。产品要求写成：提交到控制线程首次可见不超过 5 tick时，冻结正例必须完成。6 tick 只要求安全有界，不把上限改成 6。

验收夹具必须记录请求值和实际值。实际首次可见不是目标 tick 时，该试次记为注入无效，不能冒充对应延迟场景。

## 3. 控制准备只统计生产协调器帧

生产控制准备继续使用完整区间：

```text
dispatched_monotonic_ns - decision_observation_received_ns
```

门槛保持 P95 ≤ 8 ms、P99 ≤ 15 ms、最大值 < 30 ms。统计范围只包含正式协调器帧，包含等待帧。

同步 B10 探针和其他夹具步骤分别报告，不参与生产控制门槛。`proposal_elapsed_ns + runtime_outside_backend_ns` 只作分段诊断，不能替代完整区间。

D112 原始 trace 的只读重算只作为 D113 基线，不把 D112 改写成通过。

## 4. 交付估计只允许保守上调

第一次完整 SOLVE 继续建立交付估计。后续 REVALIDATE 到达得更慢时，可以把估计调大；更快的复核不能缩短完整求解需要的准备长度。

上调只接受当前 scope、connection、revision 和 identity 的合法结果。过期、来源不明或属于旧任务的结果不能改变估计。结果是否解决动作问题与“这次交付用了几个 tick”分开记录，因此一个合法返回的否定结果也可以提供更保守的交付时间。

## 5. 纯中性准备允许安全停在台阶侧面

准备预测器只对下面这类侧碰继续计算：

- 整个准备前缀都是纯中性移动；
- 视角保持不变；
- 每一步世界信息完整、物理受支持并保持着地；
- 发生侧碰后水平速度归零；
- 资源、依赖、输入和完整准备轨迹照常记录；
- 从最终预测状态重新验证原动作命令，原有入口、UNKNOWN、伤害和落点门槛全部保留。

主动向墙移动、侧碰后仍滑动、离地、未知世界、物理不支持或视角改变仍拒绝。不得删除通用碰撞检查，也不得增加重试次数。

## 6. 失败原因和诊断

- worker 请求已经超时，而旧未完成请求占满 inbox 时，最终细分原因使用现有 `motion_solver_request_expired`。普通容量不足仍报告 `motion_inbox_capacity_exhausted`。未完成请求继续占槽，不能为了通过测试提前释放。
- 客户端失败保留 cause，并只输出异常类型及最深可定位原因中的项目源码 `文件名:行号`。不输出异常消息、完整路径、载荷、地址、token 或完整调用栈。
- D102 测试必须等待本次 prepare 产生的新 job，不能取作业列表最后一项来猜测。

## 7. 验收和停止边界

组件层新增 180 个固定种子的 `{D, D+1}` 抖动场景：gap、jump-up、controlled-drop × D∈{2,3,4} × 20 个种子。最大实际延迟为 5 tick，全部必须完成并保持零伤害。

先单独运行一个 5-tick Fabric 场景，确认实际首次可见为 5，并取得客户端失败位置。若注入不精确或异常仍无法定位，停止正式矩阵，先修夹具。

单场成立后，只运行一次正式批次。它必须覆盖 baseline、2／5／10 tick、never-return 和现有不支持记录。中途失败也要写出部分探针统计。

本阶段不优化求解器，不增加 Session 状态，不开始连续两跳、零等待交接或新动作。
