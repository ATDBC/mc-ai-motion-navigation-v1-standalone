# D006：后续实机开发只使用独立 Fabric

日期：2026-09-18
状态：已接受

## 要解决的问题

当前机器人直接运行在独立 Fabric 客户端，近期不使用 CraftGround 做训练或正式运行。若每个阶段都同时维护两套实机启动、部署和验收流程，会增加没有现实收益的工作，也会让后端环境问题干扰运动核心的判断。

## 决定

从 B03 开始，正式实现和实机验收只使用独立 Fabric。

公共观察、动作和运动核心继续使用后端无关的数据契约。现有 CraftGround 代码保留，不要求删除，也不作为后续阶段的完成条件。以后确实恢复 CraftGround 训练或运行时，再通过新的设计决定恢复对应接入和实机验收。

## 影响

- 固定路线、后台规划、跨高度动作和后续能力都先在 Fabric 上形成完整证据。
- 不为 CraftGround 单独复制地图、路线、控制或验收逻辑。
- 共享契约发生变化时，仍应检查现有 CraftGround 适配代码能否编译或通过已有自动测试；这不等于要求启动 CraftGround 游戏实例。
