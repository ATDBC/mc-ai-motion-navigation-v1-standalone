# D033：接近活动目标时持续瞄准并记录导航原因

日期：2026-09-26
状态：已采用并完成验证

## 要解决的问题

B12-B 已证明近身转头时可以同时移动，但原活动目标只有一次，而且夹具会把目标横移到侧前方。更长的真实追击暴露了缺口：导航能用横移接近斜前方目标，战斗层却要到准备攻击时才持续瞄准。活目标自行移动后会走出视野，任务最终返回 `target_unavailable`。

同时，回放只能看到中性移动，不能判断它来自转弯减速、等待输入还是结束制动。未登记目标的伤害事件还会长期留在 64 条缓冲里，使溢出计数逐渐失去含义。

## 决定

1. 当前观察有目标几何且移动近战正在接近时，战斗层提交一帧目标视角。
2. 导航继续负责身体移动，并按这份最终视角计算普通地面输入。视角没有胜出时，本帧移动仍由仲裁器压下。
3. 进入攻击、补看、取消、外力恢复或导航结束时，释放接近阶段的视角来源。
4. 导航每帧通过现有任务事件记录执行状态、动作序号、移动、是否提交和原因码。
5. 没有追踪编号的非玩家受伤目标无法进入正式观察，采样时从缓冲移除。它不算容量溢出。
6. B03 仍是底层地面控制器回归。`NavigationSession` 的连续步行证据来自正式持续追击和 C1-B。

## 为什么这样做

战斗层知道该看谁，导航层知道身体怎样安全前进。先确定视角，再计算移动，可以复用现有路线、支撑、停止和仲裁规则。若让导航自己选择战斗目标，或让战斗技能直接按键，会复制已有职责。

未登记实体没有可以跨帧引用的身份。把它留在缓冲里不会增加可用证据，只会挤掉能够归因的事件。

## 验证结果

- B12-B 批次 `20260926T074601049372Z-1e50bcb7`：34／34 场景完成。新增活目标没有被瞬移，追击 43 个控制帧、2.150 秒，目标自行移动 2.056 格；15 个转头帧中 9 帧同时移动。控制 P95 4.7440 ms、P99 6.4896 ms。
- 受控横移样本有 8 个转头帧，其中 7 帧同时移动。中性导航帧全部能归到 `corner_speed_control`、`cancel_braking` 或 `cancelled_after_stop`。
- C1-B 批次 `20260926T074903856184Z-9fa68417`：20／20 正例和 10／10 反例通过；离线重放一致。
- Java 回归连续注入 70 轮未登记目标伤害，正式自伤事实持续交付，容量溢出计数保持为 0。

远距离追击仍可能需要重新发现目标。本决定只补齐当前可见目标的持续瞄准，不提前实现未知区域搜索或观察站位协调。
