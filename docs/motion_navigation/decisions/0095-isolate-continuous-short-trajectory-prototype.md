# D095：隔离验证连续短轨迹搜索

日期：2026-10-10。

## 决定

先隔离验证连续短轨迹原型TP，不直接改正式导航链。本轮已实施到Task5A，现按独立审查和预设门槛停止；当前没有继续实施的授权。

原型把接近、转向、起跳、空中控制、落地和落地后的继续移动放进同一次有界搜索。它回答一个问题：在沿用现有 Minecraft 1.21 运动计算器和世界事实的前提下，连续搜索是否能减少动作交界处的停车与失败，同时守住现有安全门槛和控制期限。

原型放在 `experiments/motion_navigation/trajectory_proto/`。正式 actor、`NavigationSession`、`Runtime` 和现有路线执行器不得导入原型代码。公开快照允许包含原型源码、测试、方案与审查，供第三方复现；快照中的正式入口仍不得导入原型。原型通过测试脚本和独立驱动运行。

## 原型边界

原型首轮只覆盖：

- 普通 Walk、Sprint、有限转向；
- JumpUp；
- 同高一至三格 JumpGap；
- 半砖、楼梯和现有连续小高差；
- 一个已经证明安全的短落地补走族。

原型不覆盖多格受控下降、潜行、爬行、游泳、攀爬、鞘翅、未知世界探索、动态避障和战斗策略。`SNEAK_EDGE_GUARD` 已在 F2REC R3 从生产代码删除，本原型不恢复它。

## 承诺点

承诺点不等于起跳或离地的那一 tick。

每个候选都必须计算安全停车尾迹。轨迹可能多次经历“可安全停车、进入不可停止区、重新落地并恢复可停车”。因此承诺边界按风险区间记录，不能在整条轨迹里只找最后一个可停车状态。

对每个风险区间，最后一个仍能沿已验证停车尾迹留在安全支撑上的状态称为该区间的最后可放弃状态。越过该状态的下一条命令开始本次承诺。停车尾迹必须先应用已经提交、无法撤回的在途输入，再判断还能否停住。

越过每个承诺点前，候选必须已经验证该风险区间剩余的助跑、起跳、空中运动、落地和安全收尾。承诺点后，计划变化可以取消后续资格，但不能取消身体责任。落地后重新具备停车能力，只结束当前承诺区间，不改写此前越界时刻。

## 结果分类

原型只返回以下结果：

- `FOUND`：找到完整验证的轨迹；
- `NEEDS_INFORMATION`：关键世界事实未知；
- `BLOCKED`：已知必要条件已经证明整个请求不能通过；单个候选碰撞只淘汰该候选；
- `NO_TRAJECTORY_IN_BUDGET`：固定搜索预算内没有找到，不能解释为不可达；
- `STALE`：入口锚点、世界依赖、目标或输入账本已过期。

未知格不得归入 `BLOCKED`，也不得按空气处理。

## 实施约束

- 时间盒从 P0 第一笔原型代码提交开始计算两周；P4 的一次限定修正也包含在两周内，到期不顺延；原型代码约 2500 行上限，测试、场景和报告不计入；
- 第一版直接调用现有 1.21 运动计算器，并使用确定性缓存；只有测量证明计算器调用是主要瓶颈时，才讨论离线运动表；
- 输入仍在途或生效时间有歧义时，同时验证有限的按时／晚一 tick 分支，或返回 `NEEDS_INFORMATION` 等待新观察重锚；不得选择更有利的分支；分支预算耗尽返回 `NO_TRAJECTORY_IN_BUDGET`，不能写成 `STALE`；
- 所有时序分支必须共享同一条准备提交的输入前缀。不能让不同分支分别依靠不同命令获得安全，再只执行其中一支；
- 原型自己关闭 worker，并检查重复创建、取消和关闭；
- 原型期间主线只接受 P0／P1 安全修正；
- 不把原型结果写成正式能力，不修改旧验收结论。

## 止损

P0 如果不能在固定计算预算内给出明确的承诺边界、搜索规模和 Windows 性能数据，停止原型。P1 如果不能在冻结场景中达到对照完成率，或出现安全退步，停止原型。任何阶段出现越过伤害额度、无人负责身体、UNKNOWN 被当成 FREE、未验证输入被发送，都立即停止。
