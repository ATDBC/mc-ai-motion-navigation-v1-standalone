# D036：先修连续高度移动，再增加新的移动能力

日期：2026-09-27

状态：已接受并完成核心实施；完整验收矩阵尚未关闭

## 决定

B12 之后先完成连续高度地面移动整改，再推进特殊地面、攀爬和流体等新移动能力。

整改分四步：

1. 前一段按下一段的方向性入口条件收尾；
2. 0.6 格以内、已经验证形状上的自然迈步并入站立 Walk；
3. 规划使用经过物理验证的整数 tick 代价；
4. JumpUp、连续整格下降和直接多格下落接入带速求解与连续出口。

现有静止 Step、JumpUp 和 ControlledDrop 保留为后备。支撑、碰撞、未知和危险事实不因追求连续性而放宽。

## 原因

当前链路在每次高度变化前后都要求停稳。完全已知的闭环模拟已经复现 1.3 至 2.4 倍的用时差、重复停稳、输入晚一 tick 后失败，以及一格下降在无延迟时也因入口范围错配而失败。

这类问题会影响以后所有新地形和移动模式。若继续在旧接口上增加动作，动作越多，停稳点和接续矩阵也会越多。

现有 1.21 运动计算器已经实现原版自动迈步。B10 已经具备后台求解、轨迹验证、路线接纳和逐 tick 执行。当前缺少的是把这些能力用于连续地面段，而不是再建立一套规划系统。

## 未采用的方案

### 只调大旧动作参数

不采用。旧 Profile 的证据只覆盖静止、低速入口。直接扩大范围无法证明安全，也不能修复规划代价和方向性交接。

### 所有地形都交给通用轨迹优化器

不采用。当前问题可以通过现有计算器、局部求解和控制器解决。现在增加通用优化框架会扩大实现和验收范围。

### 先做八方向或任意角度平滑

不采用作为前置。它能减少平面转弯，但不能消除同一直线上的高度停稳。两项工作以后可以独立组合。

## 影响

- B07 的 Step 从默认小高差动作变为连续 Walk 验证失败时的后备。
- B09 的静止下降继续有效；新增带速下降不会修改旧 Profile。连续整格台阶下降不再要求每一级停稳，直接多格下落从离边到最终落点只算一次空中动作。
- B10 的入口、命令、轨迹和出口关联继续作为带速动作依据。
- 没有任务伤害额度时只接纳零伤害下落；允许伤害时仍须由计算器给出上界，并在接纳时核对生命、状态效果和落点条件。
- 伤害额度由规划请求的 `TaskDamageBudget` 入参提供，默认值为 0。额度变化属于任务权限变化，必须使旧候选失效。
- `MovementStateClass` 不承担连续坐标；具体入口由新的方向性窗口表达。
- 后续 Sprint、Crouch、Crawl、特殊地面、攀爬和流体分别补证据，不能自动继承站立 Walk。
- 旧成功和失败记录继续保留，作为整改前基线。

## 实施结果

四步核心链已按决定接入。代表性 Fabric 批次证明小高差可以保留为一个连续 Walk，连续整格下降不再要求每一级停稳，直接多格下落也不再按经过的高度拆段。任务伤害额度已经成为正式导航入参；额度变化会生成新的任务修订并使旧候选失效。

跨模块回归曾发现普通路线减速会穷举九种按键，并让 C1-B 控制 P95 稳定超过 8 ms。此次只优化候选验证顺序：安全候选成立后，跳过运动学下界已经不可能更优的候选；没有安全候选时仍检查全部候选。该变化不修改安全边界，也不把完整 1.21 计算塞进普通平地每一帧。修正后 C1-B、B11 和 B12-B 均通过现行实机门槛。

本决定没有因此扩大到 Sprint、Crouch、Crawl、任意角度或全部形状。完整授权仍以验收文档中的矩阵和回归为准。
