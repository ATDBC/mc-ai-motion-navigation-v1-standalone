# D017：受击、实体挤压和活塞推动共用外部运动恢复

日期：2026-09-24
状态：采用

## 要解决的问题

C1-C 最先遇到的是僵尸攻击造成的伤害和击退。机器人以后还会被生物挤压、活塞推动、爆炸或其他外力改变位置和速度。如果每种来源各写一套停止、落地、制动和路线恢复，身体责任、路线失效和输入权限会逐渐分裂。

现有 `unsupported_motion` 只表示未支持的姿态、介质、模式或材质。现有导航恢复处理路线拒绝和无进展。两者都不代表已经识别外部力量，也没有串联身体责任和重新锚定。

## 决定

1. 将“当前已应用输入无法单独解释的身体运动”作为共用问题处理。
2. 正式观察保存原始身体和来源事实；外部运动检测器形成有身份、可去重的事件。
3. 来源证据和恢复动作分开。来源决定能够宣称什么，恢复控制器根据真实身体状态和已知空间决定怎样落地、制动和重新锚定。
4. C1-C 首版只正式产生和实测 `DAMAGE_KNOCKBACK`。实体挤压和活塞推动以后补自己的证据与场景，不提前实现空壳生产者。
5. 没有明确受击证据的运动偏差不能记为僵尸击退。它可以阻止新动作授权，并以未归因偏差报告。
6. 外部事件只让受影响的动作、路线前段、执行窗口和旧锚点失效。任务目标、交战记忆和世界知识不因此清空。
7. 当前动作必须明确交出身体责任，恢复控制器才能接管。空中、制动和稳定确认期间始终只有一个移动责任方。
8. 已提交的一次性攻击继续收尾，不因受击重复提交。
9. 恢复完成后从最新正式状态重新锚定，并由当前任务决定继续、改路或结束。
10. 每次恢复和每项任务都有上限。无新证据不能无限重新锚定或重复恢复。

## 原因

运动恢复关心的是身体当前在哪里、速度如何、周围是否有足够空间，以及哪些旧承诺已经失效。它不需要知道攻击者是谁。把来源事实保留在事件上，又能让战斗、导航和将来的环境交互作出不同判断。

首版只实现已经有明确需求和实机验收的受击来源，符合项目不过度工程化的要求。共用事件边界和恢复责任则避免 C1-C 把战斗特例写进导航控制器。

## 影响

- C1-C 增加玩家自身受击观察、外部运动事件和共用恢复控制器；
- C1-B 的目标、交战记忆、单次攻击和死亡确认继续复用；
- 以后支持实体挤压和活塞推动时，主要增加事件证据和验收，不重写恢复流程；
- 坑边、悬崖和夹压需要自己的恢复包络，不能沿用 C1-C 平地结论。

## 当前实现状态

C1-R 的 R3 已补齐通用检测主线：Runtime 长期维护实际输入账本；`MotionResidualTracker` 使用状态锚点、账本、世界快照和 B09-R 计算实际运动与预测运动的差；伤害事实同时比较生命和吸收心。只有伤害事实与覆盖伤害 tick 的预测外运动同时成立，才形成 `DAMAGE_KNOCKBACK`。只有伤害不会启动位移恢复；没有伤害来源的预测外运动报告为 `UNATTRIBUTED_EXTERNAL_MOTION`。

当前正式实测仍只覆盖受控普通僵尸攻击和已知完整平地。着火、中毒、摔伤与吸收心已由确定性契约检查覆盖；实体挤压、活塞推动、爆炸、远程攻击和复杂地形仍需各自的来源证据及实机场景。D017 的共用恢复决定保持不变，新增来源不能复制第二套身体恢复控制器。后续收敛记录见 [C1-R](../stages/C1R-runtime-navigation-convergence.md)。
