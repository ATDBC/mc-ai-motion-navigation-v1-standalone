# D057：目标已满足时结束无用规划，移动中路线不得回到已越过的格心

日期：2026-10-04

## 发现的问题

F1 已知开阔地跟随的正式链模拟暴露了两个通用导航缺陷。

第一，持续任务的新目标已经满足时，Session 会保持中性输入，但规划 owner 仍保留这次目标修订创建的工作。该工作没有继续推进，却会按规划期限超时。连续三次后，任务以 `planning_timeout_retry_exhausted` 失败。

第二，机器人移动中收到新路线时，普通地面路线可能包含下面的前缀：

```text
当前身体位置 → 当前支撑格的代表点 → 前方支撑格
```

当身体已经越过当前格的代表点时，这个前缀会要求机器人先刹车、后退，再重新前进。现有 0.45 格投影边界使一 tick 的位置差足以决定是否回头。

这两项问题不只影响跟随。任何使用 `KEEP_ACTIVE_ON_REACH` 的持续目标，以及任何在普通地面移动中接纳新路线的任务，都可能遇到。

## 决定

在继续 F1 之前，单独完成两项通用修正。

### 1. 满足状态收口规划工作

当正式目标观察为 `SATISFIED`，且持续任务准备进入稳定待命时：

- PlanningCoordinator 结束当前及并存的规划工作；
- 已提交工作的真实回执身份和退场历史继续由现有 owner 保留；
- 不购买任务恢复，不记规划失败，不启动替代规划；
- 任务继续保持 active，目标再次离开满足区域时再为新修订规划。

实现必须复用 PlanningCoordinator 的正式退场入口。不能由跟随层清空规划状态，也不能删除未回执身份。

### 2. 删除已经越过的普通地面入口代表点

接纳普通 Walk 路线时，如果当前身体位置、起始支撑代表点和下一支撑代表点形成一个回头前缀，接纳器可以删除起始代表点，但必须同时满足：

- 只处理路线开头的普通地面 Walk；
- 身体已经沿第一条图边方向越过起始代表点；
- 从当前身体位置直接到下一代表点的扫掠、净空和支撑查询为 `FEASIBLE`；
- 新查询依赖加入路线依赖；
- 高度动作、空中动作、方向真正反转、缺信息和不可行连接保持原路线或明确拒绝。

这不是任意路线平滑，也不放宽 0.45 格的横向走廊。它只删除已经被身体实际通过、并由统一几何查询重新证明安全的第一个代表点。

## F1 调用方的对应规则

跟随目标管理仍应避免无意义修订：当前目标已经满足，而且真实玩家仍在冻结的保持距离内时，不因最长修订间隔单独提交新目标。玩家离开保持距离后立即提交修订。

这项调用方规则用于减少无用规划。通用 Session 修正仍必须存在，不能依赖每个未来调用方都正确节流。

## 实施与验收顺序

1. 用 F1 `straight_2_0` 的最小正式链复现“满足后规划超时”，修正满足状态的规划退场；
2. 用身体刚好位于格心投影边界两侧的成组场景复现回头，修正普通 Walk 入口前缀；
3. 复跑 F1 的 2.0、3.3、4.0、横向和停止后恢复场景；
4. 修正取消场景的指标分组，并让跟随层不提交保持范围内的定时修订；
5. 只有模拟固定清单稳定后，才进入 Fabric。

每项生产修正单独提交、单独审查。不得同时调整修订距离、保持距离、控制器速度、规划预算或 0.45 格横向阈值。

## 对 F1 结构门槛的影响

F1 第一次扩展探针已经证明现有核心接口不足，因此“十二个核心协调文件零修改”这项初始门槛没有通过。两项修正作为独立的通用前置工作记录，不能写成跟随层零改核心。

完成 D057 后重新冻结 F1 基线。正式跟随层本身仍不得增加跟随专用核心状态或分支；后续 F1 提交继续要求十二个核心协调文件零修改。
