# D096：TP 原型改用动作元搜索，并修订 P1 性能门槛（草稿）

日期：2026-10-10。状态：**草稿，由三方审查者起草，待项目方确认后再放入 `docs/motion_navigation/decisions/`**。依据见 [Task 5A 审查](../2026-10-10-tp-5a-review.md)。任务说明见 [Task 5A-R](task-5a-r-brief.md)。

## 决定

1. **授权一轮 Task 5A-R。** 范围事先冻结为三步：

   | 步骤 | 内容 |
   |---|---|
   | R1 | 修正证明 |
   | R2 | 搜索前端改为动作元枚举 |
   | R3 | 降低成本 |

   每步完成后都做独立审查，前一步通过才开始下一步。5A-R 只有这一轮，不再追加。

2. **P0 参考搜索由“逐 tick 贪心”改为“动作元有界枚举”。** 下列部分保留：

   - 承诺扫描器；
   - 合同和结果分类；
   - 两支时序；
   - 证明哈希；
   - 统一计数预算。

   原 `reference_search()` 的贪心循环由动作元枚举替换。动作元按步态定义，每个 tick 的朝向由转向规则选取（指向目标区域中心）。模板冻结为“地面段、可选起跳、空中段、刹车到停”四段，扩展模板需要新的决定。Task 5A 的候选实现、报告和数字照原样保留，不回写。

3. **修订 P1 后台搜索门槛。**

   | 口径 | 原值（D095／TP 阶段计划） | 新值 |
   |---|---|---|
   | 硬条件 | 结果在对应承诺点前至少 1 个 movement tick 可用 | 结果在对应承诺点前至少 3 个 movement tick 可用，由 P2 闭环验证 |
   | 后台搜索耗时 | Windows 稳态 P95 ≤ 50 ms、P99 ≤ 100 ms | Windows 稳态 P95 ≤ 150 ms、最大值 ≤ 400 ms |
   | 控制线程消费 | P95 ≤ 8 ms、P99 ≤ 15 ms、最大值 < 30 ms | 不变 |

   这次是放宽门槛，必须用本决定记录。原“P0 只能收紧、不能放宽”的规则对新门槛继续有效。

4. **退出规则。** 任一步出现下列情况，就结束 TP，不再加轮次：

   - 独立审查发现证明完整性问题，包括：
     - 证明遗漏已发生的承诺；
     - UNKNOWN 被当作 FREE；
     - 未验证的输入被授予证明；
     - 结果分类混淆；
   - R2 的稳健性矩阵不通过；
   - R3 的 Windows 计时集 P95 > 300 ms，或最大值 > 800 ms。

   R3 的 P95 在 150—300 ms 之间（最大值 ≤ 800 ms）时，算**有条件通过**：可以进入 5B，但 P1 必须达到第 3 条的门槛，P1 期间的性能优化最多一轮。300 ms 这条线沿用原型最初方案的止损线。

5. **时间盒不变。** 仍从 `7d997913` 的提交时刻起算，截止 `2026-10-24T11:52:53+08:00`。本决定不延长、不重置时间盒。

## 原因

Task 5A 的独立审查发现两项证明缺陷（P1、P2）和一项去重的覆盖边界，按预设门槛停止。这个停止是正确的。三方审查复现了这三项，并补充了以下事实：

- **P1 的根因是扫描器里有两套“安全停住”的判据。** 停车尾迹只要求着地静止；关闭风险区间和等待分支却要求公开支撑不低于 0.15；目标检查又接受任意正支撑。统一判据，再拒绝未关闭的风险区间，P1 就消失。
- **P2 的根因是 1.21 计算器每个 step 的资源结果都是 CONDITIONAL。** 因此非空资源下限永远证明不了，应当返回 `NEEDS_INFORMATION`。
- **逐 tick 贪心搜索不稳健。**
  - 2 格跨隙只要加入疾跑输入，原版用 20 万节点、142 万次 step 仍然找不到。
  - 原因是验证只在终点做，而从首条命令起就注定失败的子树一直排在前面。
  - 在 16 个可行的跨隙小矩阵上，各版本找到 10—14 项。
  - 它对输入集不单调：只用步行能找到的用例，加入疾跑后反而找不到。
- **同一组用例换成动作元枚举，结果稳定。**
  - 枚举形式是“助跑、可选起跳、空中、刹车到停”的固定模板。
  - 9 个可行的直线用例全部找到；不可行的用例把网格枚举完后，明确报告“网格内无解”。
  - 每个候选都通过同一个扫描器的两支时序验证。
  - 起草本决定时，又用“转向动作元”在完整的 5A-R 矩阵上复核：19 个正例全部找到，其中包括转弯后上跳。三方审查认定为不可行的那一项，枚举完网格后报告无解。
- **成本是主要的未知数。**
  - 按 Task 5A 报告的 Windows 数字折算，每次物理 step 约 0.11 ms，50 ms 只够约 440 次 step。
  - 已找到的跨隙用例最少也要 553 次 step。
  - 用转向动作元加“先不跳、再从最晚起跳点往前”的顺序，计时集 14 项需要 311—1968 次 step。按上面的折算，最贵几项在 Windows 上约 150—220 ms。
  - 降到 150 ms 以内还要大约 1.5 倍，有希望；降到 50 ms 以内要 4 倍以上，把握很小。
  - 原型最初方案（2026-10-09）采用的是 P95 ≤ 150 ms。滚动执行时，下一段的搜索可以和当前段的执行重叠，所以硬约束应当是“承诺点前可用”，而不是绝对毫秒数。

## 5A-R 的通过条件

细节见任务说明，这里只列门槛。

| 步骤 | 通过条件 |
|---|---|
| R1 | P1、P2 反例和新增 RED 全部转绿；原有检查只允许改写因统一判据而变化的前提，逐项说明；Task 5A 跨隙代表仍在真实落地处关闭风险区间 |
| R2 | 冻结的稳健性矩阵（见下）全部满足：<br>• 正例全部 FOUND；<br>• 标为不可行的用例返回有类型的搜索耗尽；<br>• 输入集变大不丢解；<br>• 反例分类正确；<br>• 相同请求结果和哈希逐项一致；<br>• 全部在 P0 计数预算内 |
| R3 | Windows 稳态下，计时集全部样本的 P95 ≤ 150 ms、最大值 ≤ 400 ms，且全部正例在 P0 预算内，即为通过；有条件通过和不通过的界线见“决定”第 4 条。同时报告冷启动、节点、物理 step、缓存命中，以及距承诺点的开环余量 |

冻结的稳健性矩阵包括：

- Task 5A 的三个代表；
- 三方审查的直线跨隙矩阵：
  - 两种起点（无助跑、3.5 格助跑）；
  - 宽 1—3 格；
  - 三种输入集；
  - 共 15 项，其中“助跑 3 格、仅步行”标为不可行；
- 新增 `flat_sprint`、`turn_90`、`jump_up_after_turn` 三项。

每一项的可行性已经在冻结前由不计成本的离线枚举确认，见任务说明附录。

R3 的计时集共 14 项：三个代表，直线跨隙中的 A3、A5 正例，加上新增的三项（同一请求只计一次）。A15 直线跨隙的 5 个正例只报告耗时，不计入门槛。原因是这 5 项的 3 个朝向里有 2 个对直线跨隙没有用，它们测的是“多余选项会不会破坏稳健性”，这件事已由 R2 把关。转弯两项使用 15 个输入，属于真实需要，计入门槛。

R3 的开环余量只用于报告，不作门槛。原因是开环从静止锚点出发，承诺点可能在第 2—3 tick 就到来。“承诺点前至少 3 tick 可用”由 P2 闭环验证。

## 不改变的内容

- D095 的原型边界、不覆盖的能力、承诺点定义、五类结果和全局门槛全部不变。
- 正式 actor、`NavigationSession`、`Runtime` 和脚本入口不导入原型。
- 原型期间，主线只接受 P0／P1 安全修正。
- 原型代码总量上限仍约 2500 行。
- Task 3／4／5A 的报告、审查、失败证据和原数字全部保留，新结果另行记录。

## 阶段计划的相应修订

- **P0：** 参考搜索 = 动作元有界枚举。5A-R 通过后进入 5B，即把完整 18 族冻结成可执行夹具，并补齐 runner。
- **P1：** 门槛内容不变，包括：
  - 冻结矩阵完成率不低于对照；
  - 短落地两族各不低于 99／100；
  - 所有严格候选同时通过准时与晚一 tick 两支；
  - 三类反例各自成立；
  - 性能单独报告。

  其中性能门槛按本决定第 3 条执行。搜索实现沿用 P0 的动作元前端和缓存，不另写第二套搜索。
- **P2—P4：** 不变。

## 未决事项

- 转弯动作元沿用正式输入契约：单 tick 朝向变化不超过 ±180°，不另加速率限制。如果正式链以后引入转身速率限制，转弯动作元随之修改，并重新冻结矩阵。
- 多格受控下降、潜行、爬行、游泳、攀爬，仍在原型范围之外。
