# D104 K1 止损审查：关键边界证明漏判短风险（`d984138`）

日期：2026-10-13。审查对象：`origin/main` `d984138`，包括 D104、关键边界阶段计划、验收、K1 失败索引、隐藏短风险复现和候选原型。脚本与输出在 [2026-10-13-d104-k1-review/](2026-10-13-d104-k1-review/)。

## 结论

**K1 止损是对的。但“缩小证明”这条路没有被否定：有一种不漏判的做法。在同样的样本和反例上，它与旧扫描器逐项一致，物理计算量也和失败的候选差不多。建议用它重做 K1，并把与证明算法无关的工作从这条串行链上拆出来。**

1. **止损正确。**
   - 候选只在“输入变化、不可撤回输入变化、支撑变化”附近计算停车尾迹，其余边界默认安全。这个默认没有任何覆盖论证。
   - 复现靠人为篡改 `_tail`，但它准确指出了缺口：未采样边界的安全是假定的，不是算出来的。这类缺口不能靠增加样本或补事件点关闭。
   - 我在 420 个随机变异世界里找到 130 处真实的“SAFE→UNSAFE→SAFE”短风险。候选的事件点规则一处也没漏，说明它在常见地形上基本可用，但这仍不是证明。
2. **上一轮我的建议对此有责任。**
   - 上一轮 E16 的关键边界取自旧扫描器的结果，等于用答案选题。
   - 我在脚本注释里写了“实际实现可从首个跳跃输入和着地直接得到”，并在第 6 节建议“尾迹只在关键边界证明”，但没有写出覆盖其余边界的条件。K1 候选正是沿这条思路失败的。E16 只能说明计时，不能作为算法依据。
3. **不漏判的做法：每个边界都有判定，但多数判定不需要推演。**
   - **A：等价跳过。**
     - 风险区间打开后，旧 `_risks` 只在“边界状态着地、支撑安全、尾迹 SAFE”时关闭区间，空中或支撑不安全的边界不影响结果。
     - A 只跳过这些边界，其余边界照常调用原 `_tail`。这是对旧判定的等价变换，没有启发式。
   - **B：A＋保守停车包络。**
     - 对着地边界，先用物理上界检查“松键后最多滑多远、滑过的地面是否全是普通整方块且头顶为空”；能证明就判 SAFE，证明不了再调用原 `_tail`。
4. **实测结果**（Linux，项目函数）：

   | 检查 | 结果 |
   |---|---|
   | 28 个冻结样本的风险区间 | A、B 都是 28／28 与旧扫描器一致 |
   | K1 原复现（`_tail` 在第 5 边界被改成 UNSAFE） | A 得到同样的区间 (4, 5, 6) |
   | 1,120 次随机翻转 `_tail` 结果 | A 与旧扫描器在接纳／拒绝和区间上全部一致 |
   | 420 次随机世界变异（挖洞、加障碍、删成 UNKNOWN） | B 的 4,920 个包络判定 0 误判；旧扫描器接纳的 346 个世界里，A、B 区间 346／346 一致 |
   | 物理步：K0 的 18 个样本 | 旧 11,072；A 9,750；B 5,115（失败候选为 5,263） |
   | 物理步：`jump_gap_1:A3` | 旧 451；A 151；B 119 |
   | M0 动作开始决定，Windows 估算 | A 约 7—10 ms，B 约 6—8 ms；门槛为 P99 15 ms |

5. **计划结构让一个算法失败拖停了三件不相关的事。**
   - D104 §6 已认定 F-TICK 不依赖证明管线。但实施顺序仍把它排在 K1—K5 之后，并规定“任一步未通过即停止”。
   - 结果 K1 一失败，F-TICK、receiver 信任边界简化和局部快照也全部停了，而它们都与证明算法无关。
   - 建议拆成三条各自止损的轨道（第 5 节）。

## 2. 为什么止损是对的

候选的 `_event_boundaries` 只把下列位置及其相邻边界作为种子：

- 入口和终点；
- 主输入变化处；
- 不可撤回输入变化处；
- 支撑布尔值变化处。

只有某个种子的尾迹为 UNSAFE 时，它才向两侧逐边界扩展。两个种子之间若有短暂的 UNSAFE，又在下一个种子前恢复，候选既没有算，也没有任何理由认为它安全。

这个缺口的性质：

- **是结构性的，不是样本不够。** 18 个冻结样本一致，只说明这些样本里风险恰好落在种子附近。
- **真实地形里不常见，但会出现。** E17 在 420 次世界变异中找到 130 处真实短风险，全部恰好碰到种子。所以这不是“已经会出事”的问题，而是“安全结论没有依据”的问题。按项目“安全不变量零容忍”的规则，停下是对的。
- **上一轮我给的思路有同样的缺口。** E16 用旧扫描器的风险区间选关键边界，计时结论成立，但“怎样不看完整扫描就找到这些边界”没有回答。候选的事件点规则正是在回答这个问题时引入了未证明的假设。

## 3. 不漏判的缩减办法

### 3.1 A：只跳过旧判定本来就不看的边界

旧 `_risks` 的逻辑（`commitment.py`）：

- 区间未打开时，遇到第一个 UNSAFE 尾迹就打开区间；
- 区间打开后，只有同时满足以下三条的边界才关闭区间：尾迹 SAFE、边界状态 `on_ground`、`_safe_support` 成立；
- 区间打开期间的 UNSAFE 尾迹，以及空中或支撑不安全边界上的 SAFE 尾迹，都不改变任何结果。

所以，**区间打开后，边界状态在空中、或支撑不安全时，它的尾迹算不算都一样。**

A 在这些边界只做一次支撑查询，不推演尾迹；其余边界（区间外的全部边界、区间内着地且支撑安全的边界、终点）一律调用原 `_tail`。

- **区间与旧扫描器一致，靠代码等价，不靠样本。** E18 用 K1 同类篡改验证：28 个样本各做 40 次，每次随机翻转 1—4 个边界的尾迹结果，共 1,120 次。A 与旧扫描器的接纳／拒绝和区间全部一致（942 次都接纳，178 次都拒绝）。
- **唯一差别：被跳过的尾迹不会再触发旧扫描器的整单拒绝。**
  - 例如空中某个假设的松键尾迹碰到 UNKNOWN 或没停稳，旧扫描器会整单拒绝，A 不会。这些尾迹在承诺区间内，本来就不承诺可停车，所以不影响安全。
  - 但这仍是接纳范围的变化，应写进契约。E17 的变异测试中这种情况出现 0 次。
- **省下的是空中段：** jump_gap_1 两条分支共跳过 24 个空中边界，451 → 151 物理步。没有风险区间的动作（平地、转弯、上台阶）A 不省任何计算。

### 3.2 B：着地边界先用保守停车包络

着地边界的停车尾迹是“执行一 tick 不可撤回输入，然后松键滑行到停”。B 在调用 `_tail` 之前检查下面的条件，全部满足就判 SAFE。

**前提条件：**

- 状态着地、站立；不在水中、不攀爬、不飞行、无状态效果；
- 脚底恰在整格高度，不低于 `min_y`，前缀伤害未超额；
- 不可撤回输入不含跳跃。

**滑行距离上界：**

- 计算器只接受滑度 0.6 的普通材料，其他表面一律返回 UNSUPPORTED。所以着地后每 tick 速度乘 0.6×0.91＝0.546。
- 第一 tick 加速度不超过 移动速度×1.3×输入幅度。
- 水平总位移上界为 D＝(|v|＋a)/(1−0.546)＋0.05。

**检查范围：**

- 身体盒向四周扩 D 覆盖的每一列，脚下一格必须是已知、普通材料、整方块，身体所在两格必须是已知 AIR。
- 这些格加入依赖，任何一格变化都会使结论失效。

满足时，身体不可能离开支撑、下落、碰撞或上台阶，最终支撑比例为 1，必然 SAFE。不满足就回退原 `_tail`，与旧扫描器相同。

**验证：**

| 检查 | 结果 |
|---|---|
| 28 个样本区间 | 28／28 一致 |
| 420 次世界变异（每次 1—4 处随机改动，作用于路径附近的地面、身体高度格或 UNKNOWN） | 4,920 个包络判 SAFE 的边界逐个再跑原 `_tail`，不 SAFE 的为 0 |
| 变异世界中旧扫描器接纳的 346 个 | A、B 区间 346／346 一致；旧扫描器拒绝而 A／B 接纳的为 0 |

**B 对 K1 原复现的结果与旧扫描器不同，这是预期的。**

- 那个复现在平地上把第 5 边界的 `_tail` 硬改成 UNSAFE，而世界本身没有任何危险。B 用几何证明第 5 边界安全，根本不调用被篡改的 `_tail`。
- 所以篡改 `_tail` 这种测试只对“跳过推演且没有理由”的方法有效。它适用于检验 A（A 跳过的边界有代码等价理由，E18 已通过），不适用于检验 B。
- 检验 B 必须改动世界本身，并检查包络前提是否被守住。
- B 的前提必须作为代码中的显式守卫。以后支持冰、灵魂沙、药水效果、实体推挤等，必须先让包络对这些情况返回“不适用”，再扩展。

### 3.3 计算量与时间

| 范围 | 旧扫描器 | A | B | 失败的 K1 候选 |
|---|---:|---:|---:|---:|
| 28 个样本物理步 | 15,808 | 13,040（82%） | 6,583（42%） | — |
| K0 的 18 个样本物理步 | 11,072 | 9,750 | 5,115 | 5,263（项目 Windows 实测） |
| `jump_gap_1:A3` 物理步 | 451 | 151 | 119 | 233（本机） |
| `jump_gap_1:A3` Linux 耗时占旧扫描器 | 100% | 约 20% | 约 15% | 约 50% |

**Windows 估算：**

- 失败候选在项目 Windows M0 中的 P99 为 18.25 ms（旧扫描器 48.61 ms），即旧扫描器的 37.5%；本机测得它是旧扫描器的约 50%。
- 用这组对应关系校准，再与直接按本机比例换算的结果一起给出区间：A 约 7—10 ms，B 约 6—8 ms，都低于 P99 15 ms。
- 正式结论仍要在 Windows 重跑原 M0。

**候选实现本身偏慢：**

- 它对每个主轨迹状态都做支撑查询，再按种子逐个推演；233 步却用了旧扫描器一半的时间。
- A 的步数比它少约 35%，耗时约为它的 40%。
- 所以 K2 诊断中 18.25 ms 的 P99，不能说明“缩证明不够”。

## 4. 重做 K1 的门禁建议

把“与旧扫描器比较风险区间”保留为必要条件，同时改成可以检查的完整性要求：

1. **每个边界都有判定。** 判定只能来自三类来源，结果中逐边界记录来源：
   - 原 `_tail` 推演；
   - 包络证明（B）；
   - “区间打开后、空中或支撑不安全”的等价跳过（A）。
   不允许“没算就默认安全”。
2. **篡改测试（针对跳过）。** 对任意边界随机翻转 `_tail` 结果，新旧扫描器的接纳／拒绝和区间必须一致。E18 的写法可以直接作为测试。
3. **世界变异测试（针对包络）。** 在路径附近随机挖洞、加障碍、删格、改材料。凡包络判 SAFE 的边界，原 `_tail` 必须 SAFE，违例为 0；同时统计新旧区间一致率。
4. **冻结样本一致。** K0 的 18 个样本仍逐项比较。
5. **接纳范围变化写进契约。** 被跳过的空中尾迹不再触发整单拒绝，需要在契约中说明，并在测试中计数。

D104 §1“第一次实现只支持一个风险区间”可以取消。A／B 按旧逻辑逐边界推进，天然支持多个区间。

先只做 A 也可以：它完全没有物理假设，估算已低于 15 ms。B 用来留余量，可以在 A 通过 K2 后再加。

## 5. 计划结构：拆成三条独立轨道

D104 的实施顺序是 K1→K2→…→K7，任何一步失败全部停止。但其中至少三件事互不依赖：

| 轨道 | 内容 | 依赖 | 自身止损条件 |
|---|---|---|---|
| T1 证明 | K1-R（A 或 A＋B）→ K2 重跑原 M0 → K3 迁入 worker | 无 | 完整性测试或 M0 门槛失败 |
| T2 接收与快照 | receiver 只做身份比对；局部 detached 快照；在 Windows 实测生产链“提交 → worker 完成 → 发布 → 首次消费”的耗时 | 不依赖证明格式（信任边界与快照大小与尾迹怎样算无关） | 身份变异未全部拒绝，或关闭／责任保留出现退步 |
| T3 F-TICK | B10 正式链上四方向各 10 次，只读记录首条命令的真实 tick | D104 §6 已认定独立 | 40／40 时间线不完整 |

- 只有“删除登记对象中的完整 bundle”需要等 T1 的紧凑证明，其余部分可以先做。
- 连续两跳和零等待交接仍等 T1、T2、T3 都通过后再开始。

这样一来，一个算法缺陷不会再连带停掉测量和简化工作。上一轮 G2 也是同样的情况：量尺问题挡住了与之无关的 F-TICK。

## 6. 其他意见

- **失败处理规范。** 候选从活动路径撤回，K2 诊断数据单独存放、明确标为无效，复现脚本和失败索引齐全。这些做法都对。
- **建议补一条通用规则：** 任何“少算”的优化，都要先说明被省掉的计算为什么不影响结论（代码等价或物理上界），再做性能测量。这条可以写进 D104 或 AGENTS.md 的工程要求。
- **依赖登记要注意：**
  - 包络检查的格必须进入依赖；E17 已加入。
  - 被跳过的空中尾迹原本会登记的格不再进入依赖。这些尾迹不承诺可停车，所以不影响安全，但会让“世界变化后是否作废”的范围变小，应在 K3 迁入时说明。

## 7. 证据边界

- **计时：** E17／E18 都在 Linux 上运行。Windows 数字由 D101 M0 的旧扫描器实测和 K2 诊断中候选的实测换算，只代表量级。
- **E17 的变异：**
  - 每次只在路径附近改 1—4 格，材料只有石头、空气和 UNKNOWN；
  - 没有覆盖台阶、半砖、其他普通材料组合，也没有覆盖实体和流体；
  - B 的包络对这些情况本来就返回“不适用”，回退原 `_tail`。
- **E18：** 只翻转 SAFE／UNSAFE，没有模拟 `_tail` 抛出 NEEDS_INFORMATION 等异常的情况；这类差别见 3.1 节。
- **适用范围：** A 的等价性依据当前 `_risks` 的实现。如果以后修改区间规则（例如允许空中边界关闭区间），A 的跳过条件必须同步修改，并重跑 E18 式测试。
- **未做的事：** 没有修改项目代码，没有运行 Windows 或 Fabric。
