# 空气确认：用表面深度判断“看得见的空”

日期：2026-09-26
背景：回应“中心连线会漏掉肉眼能确认的空气，多加射线又太慢，所以才用直接读取”的问题
基线：`origin/main` 提交 [`3e0c64b`][base]
性质：外部审查给出的设计建议。原型只用于论证，不是可直接合入的实现。

## 结论

1. **有更好的办法，而且不需要更多射线。**
   - **原理：** 一个空格子里没有东西，所以眼睛能看到它的哪一部分，只取决于它**前面**的东西。
   - **做法：** 格子的可见部分，等于它在屏幕上的投影减去更近的不透明面。表面深度每帧本来就把所有面投影好了，这个差集可以直接精确算出来。
2. **只需要两条规则：**
   - **(a)** 格子（或它的八分之一块）完整落在视野和 16 格内，并且投影完全处在可见区域里，才算“看见了”；
   - **(b)** 本帧传感器在这一格报告了可见方块时，这一格什么都不确认。
3. **正确性（原型，使用仓库原生源码，未改动）：**
   - 500 个随机世界，方块包括实心块、玻璃、半砖、中心柱、门状薄板：
     - 确认了 64,437 个八分块，没有一个与方块外形相交；
     - 单帧整格确认的 3,036 格全部是真的空气。
   - 去掉规则 (b)，同样的测试会出现 7,488 个错误确认。
4. **性能：** 先用“中心加 8 个内缩角点”做快速点测试，只有通过的格子才做精确多边形判定。结果与纯精确计算完全相同：

| 每帧 128 格 | 耗时 |
|---|---|
| 只回答整格 | 约 0.2 ms（纯精确 4.4 ms） |
| 同时给出八分块掩码 | 约 1.2 ms（纯精确 6.1 ms） |

5. **“连线被挡住、但真实视觉能确认”这种情况，在单帧里并不成立。** 被挡住的那部分，人眼这一帧也看不到。真实视觉的做法是在移动中不断补看，所以正确的补救是**跨帧累积**：
   - 柱子后面的格子，正前方看时 0/8 个八分块可见；眼睛左右各挪约 0.8 格之后，累计 8/8，可以确认为空气。
   - 中心连线反而**两个方向都会出错**：它拒绝了一个 71% 可见的格子，又接受了一个只有 52% 可见的格子。在随机世界里，它确认了 21,560 格，其中 29 格里其实有方块，都是门、梯子这类被挡住的薄板。

## 一、几种做法的比较

同一组随机世界，都启用规则 (b)：

| 做法 | 单帧确认的格子 | 错误确认 | 每帧 128 格耗时 | 能否证明不出错 |
|---|---|---|---|---|
| 直接读取（现状） | 全部 | 0，但属于越权 | 最低 | 不适用：违反合法观察 |
| 中心连线 | 21,560 | **29** | 很低 | 否 |
| 中心＋8 个内缩角点 | 3,854 | 0（仅限本测试的形状） | 0.04 ms | 否：比采样间距更小的形状可能漏掉 |
| **精确可见区域（九点预筛）** | **3,036 整格／64,437 八分块** | **0** | **0.2 ms（整格）／1.2 ms（八分块）** | **是** |

**射线的问题不在速度，而在只能抽样。**
- 抽样再密，也可能正好错过一块薄板或一根柱子。
- 中心连线之所以会漏，是因为门、梯子、活板门这类方块都贴在格子的一侧。
- 表面深度已经有每个面的精确投影，直接用它就能得到确定的答案，而且更快：大多数被挡住的格子在点测试阶段就被排除了。

## 二、为什么这样判定不会出错

1. **可见部分只取决于前面的东西。** 眼睛在空气里。若格子 C 是空的，C 里任意一点 p 能否被看见，只取决于眼睛到“视线进入 C 的那一点”之间有没有遮挡。所以，C 的可见体积 = C 的投影轮廓中，没有被更近遮挡面覆盖的区域 V。
2. **规则 (a)：** 盒子 B（整格或八分块）完整在视锥和范围内，并且 B 的轮廓完全在 V 里，那么 B 的每一点都被看见了。
3. **规则 (b) 处理“格子里其实有方块”的情况。** 设 C 里有方块 X：
   - X 若与某个“被看见”的盒子相交，X 在那里的表面前面就没有遮挡，所以本帧传感器必定报告 X 可见，这一格就会被规则 (b) 排除；
   - X 若只在没被看见的部分，那部分本来就不确认。
   - 因此，确认下来的部分一定是空的。
4. **九点预筛只会拒绝，不会误收。** 空格若整格可见，其中每一点都可见，这 9 个点自然也可见。
5. **与传感器规则保持一致：**
   - 玻璃这类不遮挡的方块，照样能看穿；
   - 屏障这类隐形方块，会被当作空气。这正是玩家本来会有的认识，撞上时再由身体接触纠正。
6. **合法性：** 所用几何与表面深度传感器相同，都来自客户端世界；输出的只是“看得见”能推出的事实，与传感器本身同属合法观察。

原型里的随机世界测试（[`air_probe_prototype.cpp`](2026-09-26-air-visibility-repro/air_probe_prototype.cpp)＋[`soundness.inc`](2026-09-26-air-visibility-repro/soundness.inc)），逐一核对了以上结论。

## 三、建议的实现

### 第一步：只回答整格，不改协议

| 位置 | 改动 |
|---|---|
| 原生核心 | 在 `center_frame_pose` 的同一次调用里（本帧的面已经投影好），增加“探测格”输入和结果输出；投影面按屏幕网格分桶；先九点预筛，再做精确判定 |
| JNI／`SurfaceSensor` | 把请求的空气位置传给原生核心，取回每格的结果 |
| `discoverRequestedAir` | 不再调用 `isAir()`。只有“整格可见”且本帧该格没有可见方块时，才照现有格式输出 `air_query` 记录 |
| Python | 不变：请求配额（每帧 ≤128）、已确认空气的缓存、重试间隔都沿用 D004 |

**同一判定还能撤销消失的方块：** 已知方块格若本帧整格可见，且没有报告方块，说明它已经消失，可以确认为空气。这样“看着方块被挖掉，世界知识却不更新”的问题也一并解决。

### 第二步：跨帧累积八分块（按需）

**什么时候做：** 包 0 的测量显示有较多格子长期处于“部分可见”时。

**改动：**
- 观察中新增部分结果字段：每格一个 8 位掩码。
- Python 只合并最近一小段时间内的结果（例如 2 秒），8 块齐了才 `confirm_air`。
- 这一格出现方块、或世界会话变化时，清空累积。
- 时间窗用来避免一种情况：前后两次观察之间，有人在没被看见的那一半放了方块。

### 与导航的配合

- 视野外、16 格外和被挡住的格子仍是未知。需要整改方案里 3b 的“信息视角”：导航等待信息时，转头去看缺的格子。
- 以后还可以把部分掩码用于“乐观规划、走到跟前再确认”：规划时把部分可见的格子当作高代价候选，执行到那里之前必须完成确认。这属于路线评分的改动，应该单独做。

## 四、其他可选方案

**深度图光栅化：** 把本帧的面光栅化成一张深度图（例如 256×256），再逐像素判断格子是否在可见表面之前。
- 优点：探测量大时更快，还能不经请求，直接把整片视野里的空气都推出来。
- 缺点：要新增一个光栅器，要选分辨率，还要用保守光栅化来保证不误判。
- 建议：只有探测量远超每帧 128 格时再考虑。

**继续直接读取：** 不推荐。它让机器人知道墙后的空间，违反合法观察；在表面深度之下也已经不再必要。

## 五、验收建议

- **门禁测试：** 把原型的随机世界正确性测试改写成原生测试，要求零误判；
- **感知场景：** 墙后、玻璃后、熔岩后、身后、柱子后（验证跨帧累积）、台阶边缘；
- **性能：** 每帧探测耗时 P95 ≤ 1.5 ms（128 格，含八分块），纳入包 0 的逐帧指标；
- **导航影响：** 对比改动前后，B03、B10、B12 中“等待信息”的帧数和首动时间。
