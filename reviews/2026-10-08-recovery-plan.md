## 2. 目标与不做的事

**目标：**

1. 公开 `main` 恢复为完整检查全绿、所有回归量尺都能运行的状态。
2. 保留 F2-S 的区域几何和 F2-SP 的有界选面，解决平台外角、桥头和柱顶目标的拒绝问题（F2S-C-01）。
3. 修复 F2S-C-04，确保 v8 中的旧成功全部恢复。
4. 普通地面控制的耗时回到 F2-SP 时的水平。
5. 把这一轮的取舍写成一条决定，并在旧阶段文档开头标注状态。

**不做：**

- 不在主线保留 F2-SG/ST 的终点搜索边、F2-GP/PC/SC 的共享跟踪策略、F2-CV/WR/SS 的帧内完整候选验证、F2-TS/TP 的 beam search 交付；
- 不实施路线优化器、正式潜行区间、疾跑路线或新动作；
- 不修改通用 A*、严格动作证明、空中动作语义和 Runtime 输入仲裁；
- 不删除、不改写任何历史失败、证据或阶段文档正文。

## 3. 分支与历史

1. 在主项目中，给当前链条的最后源码提交打一个不可移动的标签，并建立归档分支，例如 `archive/f2s-chain`。不 rebase，不 force-push。
2. 从 F2-R 的源码提交（对应公开 `1ee76b6`）开出恢复分支。所有 R 批次都在这个分支上提交。
3. 移植时以 `2bad9bf` 的代码作参考，但按本方案的接口重新落地，不整文件复制。每个移植项都要写明来源文件、来源决定和差异。
4. 公开 `main` 只接收 R5 签署后的快照。中间批次不发布。

## 6. 全局规则

1. **全绿**：每个批次结束时，M1 正序、逆序都必须零失败、零错误、零跳过。唯一例外是 R2 中登记的 F2S-C-04 预期失败，它必须在 R3 关闭。
2. **不退步**：M2—M4 的旧成功退步为 0，新安全事件为 0。
3. **确定性**：任何影响候选、选面、路线或完成判断的逻辑都不能读墙钟。需要上限时，用确定的计数，例如物理步数、候选数、查询数。墙钟只能用于计时报告。
4. **Session**：只允许修改 `_surface_for_goal` 及其调用点；不新增状态字段、等待、重试、候选队列或动作类型分支。用 `navigation_design_metrics.py` 核对：Session 方法数和字段数不增加，动作分支直接计数不超过 42。
5. **性能**：production P95 ≤ 8 ms、P99 ≤ 15 ms、最大值 < 30 ms；full 最大值 < 50 ms；M7 的中位数不超过 `1ee76b6` 的 1.2 倍。
6. **两轮上限**：遵循 D089。同一个批次最多两轮限定修正；如果需要改变公共契约、状态所有者或求解方法，就停止并报告，不自动开新阶段。
7. **fail-fast 顺序**：定向检查 → 少量正式链 → M8 → M3/M4 → M1 → M2 → M6 → Fabric。前一层出现硬停止或交付阻塞时，不继续运行后面更昂贵的层。

### R3：F2S-C-04——偏好面优先，无路时退回目标集合

**设计**

- 规划请求同时携带 Session 选出的偏好面，以及原 `GoalState`。
- 后台在同一个作业里先对偏好面运行现有 A*。
- 只有第一次搜索得出“已穷尽、无路线”时，才运行第二次 A*：`goal_test` 接受目标框内区域查询可行的任意支撑面，可行面在 worker 内用同一份快照和 `standable_region_in_goal` 计算。
- 第一次搜索因为预算用尽而停止时，不做回退，返回原有的 typed 预算结果。
- 结果携带实际到达的终点面；接纳只对这个面做区域查询，不重新挑面。
- 两次搜索共用原有的规划预算，总预算不增加。不新增作业类型，Session 不新增状态或重试，PlanningCoordinator 不新增候选游标。

**步骤**

1. 先写失败测试：F2S-C-04 主例；偏好面可达时，结果与只搜一次的结果完全相同（逐字段比较）；第一次搜索预算用尽时不回退。
2. 实现回退，加上计数诊断：第二次搜索的启用次数和用时。

**完成门槛：**

- F2S-C-04 完成；
- M2—M4 的旧成功退步为 0（包括 R2 登记的那一项）；
- 偏好面可达的任务，路线和行为签名逐项不变；
- 报告 39 项可达的“无已知路线”任务中有多少转为完成。这一项只作报告，不作门槛；
- 规划作业耗时的 P95 和最大值不超过 R0 基线的 1.5 倍，第二次搜索的启用率单独报告；
- M1 全绿。
