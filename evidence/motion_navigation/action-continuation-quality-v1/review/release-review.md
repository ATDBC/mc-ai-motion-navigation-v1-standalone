# 释放恢复修正限定复核

只复核最新 `_release_recovery_evidence` 和新增边缘反例，不扩大生产扫描或矩阵。

**结论：语义合理，没有发现需要阻止本次修正的具体遗漏。**

原 `recovery_horizon_ticks=R` 约束的是在 R tick 内达到着地、水平速度不超过 .01 格／tick 的既有可收尾条件。新检查要求再证明其后全部中性漂移安全，属于增强未来尾迹证据，不把“实际速度为零”重新定义为原 R 的恢复资格。

代码在 `recovery_tick >= R` 且尚未满足原稳定条件时退出，所以没有让 R 内仍不稳定的分支借后续计算取得资格。只有取得原资格的分支继续模拟，最终必须着地且水平速度达到实际零；总调用数仍不超过 2R。全过程复用原未知／未支持检查、支撑高度下界、预计伤害约束，并将每一步世界依赖加入同一结果。未改变正常命令长度、启动窗口或证明中原恢复期限字段。

此前边缘反例已成为正式失败检查。本分工单独运行 `test_low_velocity_edge_contact_is_not_a_complete_safe_stop`，1/1 通过，确认这条先低速着地、随后被动滑出支撑的尾迹现在会被拒绝。没有重跑其他矩阵。

一个非阻塞的表述细节：当前实现限制的是总计算量 2R。若较早取得稳定条件，稳定点之后剩余可用步数可能多于 R，并不是逐分支严格“额外尾迹最多 R”。这不扩大原资格期限，也不影响当前已支持普通材质的停止证明。若文档要严格使用后者表述，可以记录首次稳定 tick，再将尾迹限制到该 tick 加 R；无需新字段、配置或状态拥有者。直接写“总被动推演最多 2R，原稳定期限仍为 R”更贴合当前最小实现。
