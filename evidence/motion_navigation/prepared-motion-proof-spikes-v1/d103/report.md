# D103：真实快照传输与 20 Hz 连续两跳的 Windows 可丢弃试验

2026-10-12。在本批模拟闭环中，提前准备并在 receiver 线程完整注册第二跳，能及时接上第一跳。A 组无积压 120／120 完成两跳；热决定 P95／P99／最大为 0.2073／0.2350／0.3227 ms，达到沿用的 8／15／30 ms 门槛。每个 2／3／4 格平台与 ON_TIME／LATE_ONE 组合各 20 次，A 合计 120 次。第二段有效输入均在第一跳落地后 1 movement tick 应用，第二跳开始前完整停车为 0。

热决定指后台已完成证明和登记后，每个 tick 只核对已有依据并执行输入的一次控制。证明保存主轨迹、每个边界的停止办法和所依赖的世界事实；它包含可重放的状态，不只是一个“通过”标记。receiver 是父进程中接收并完整校验后台结果的独立线程；handle 是它登记后交给控制循环的证明引用。

B 组在第二跳作业前明确插入同尺寸的低优先级作业，FIFO 顺序会让第二跳等待它。B 的 120／120 也完成两跳，热决定 P95／P99／最大为 0.2032／0.2305／0.2850 ms。B 只观察这一项明确积压，不作为产品阶段通过或通用调度保证。A／B 安全违规、UNKNOWN 放行、伤害超额、无人负责推进均为 0；控制 deadline miss 分别为 0／0。

另外单独做六次 800 ms worker 延迟注入，覆盖三种平台与两个起点分支。六次都没有及时注册第二跳，全部拒绝跳跃，执行事先证明并登记的 Walk×1 前段，再用 Neutral 有界停住。六次最终都在中间平台安全着地且速度归零，未越过下一坑边；伤害与无人负责推进为 0。这些故障样本列为 OVERDUE，不混入 120 正例。

父进程构造朝南的两个一格坑，第一坑是 z=1，第二坑是 z=2+平台长度；中间平台是 z=2 到第二坑之前的完整方块。父侧每场新建 10,150 格 detached PhysicsWorldView，即与原世界独立的事实副本，并把映射冻结为 MappingProxyType。snapshot 的事实、会话、revision、ruleset 一起序列化。每个作业发送该实际快照的封存 bytes、完整 request、inputs 和第一跳实际依赖。worker 只恢复传入数据，不调用 fixture，也没有另一份全知世界。三种平台快照均为 165,780 bytes；作业请求为 167,679—167,707 bytes，完整结果为 292,470—393,156 bytes。

“真实快照”在这里指父侧这份具体模拟世界的实际格子数据，不是真实服务器采集。第一跳在同一份两坑快照中重新证明，随后第二跳 request 从该证明的预计着地状态生成。没有改写观察、移动身体到方便位置，也没有给 worker 传另一个世界。

快照只覆盖固定的 7×58×25 格窗口，BLOCK／AIR 共用两个不可变 CellFact 对象。pickle 会复用这些重复对象，因此 165,780 bytes 及本批构造／传输成本不能代表正式世界窗口、多种方块或更多观察 stamp 的成本。

第一跳使用冻结 jump_gap_1:A3 输入，hash 为 `8e1c73bf14b044c746c557b2e569198860ea9b25f00f646a17a370bc55af02ed`。它在 boundary 17 首次安全落地，z=2.3655134653，前向速度约 0.0406624 格／tick；后六条原停车命令尚未发送，交接记录将其退场。第二跳从这个完整 PhysicsState 开始，使用现有 A3 的三种 TickInput。预跑后冻结三份第二段输入：2 格平台为 Walk×4→Jump×1→Walk×7→Neutral×18；3 格为 Walk×10→Jump×1→Walk×4→Neutral×18；4 格为 Walk×13→Jump×1→Walk×7→Neutral×18。几何使用现有 Aabb；扫描、逐 tick 推进、支撑与伤害判断全部调用现有代码，没有复制物理公式。

第一跳实际起跳所在 tick 内，控制循环立即提交第二跳作业。请求及快照封装已在起跳前序列化，所以控制循环只执行 put_nowait 和读取已登记 handle。一个持久 Windows multiprocessing spawn worker 和一个独立 receiver 线程贯穿 A／B／故障矩阵。请求与结果队列容量均为 2，未消费的作业上限也是 2，满足“正在处理／已排队的低优先级作业＋第二跳”的实验边界。第三个作业明确拒绝，满队列不覆盖任何旧作业。

receiver 先核对消息 bytes 摘要，再反序列化；登记前要求返回的 bundle.inputs 精确等于父侧 make_job 保留的 expected_inputs，且 bundle.input_hash 等于父侧提交前计算的 expected_input_digest。只比较 bundle 与 proof 内部相同还不够。随后完整检查不可变对象图、重新序列化完整 proof 并计算 SHA-256、比较绑定与当前依赖，最后注册精确对象。proof.ruleset、bundle.ruleset、world.ruleset 必须相同。request／inputs／world session／revision／逐格 dependency／ledger／first sequence／generation／owner 都与预登记的父侧请求一致。控制循环只消费这个已注册对象，比较封存 bytes 的对象身份和已登记摘要字符串，没有重新计算完整摘要。可信来源仍是项目 scanner；pickle 只在自己的可信进程之间传递。

控制循环按绝对 50 ms 节拍 sleep，醒来推进一个 movement tick。它不等待 worker，不根据墙钟选择行为；交付可用与否只在 tick 边界非阻塞轮询。每次输入都绑定 owner、generation、实验账本、序号、实际 effect tick 和已有证明状态。第一条实际应用回执立即调用 D101 tracker，ON_TIME／LATE_ONE 从此只有一个生效分支；后续输入不再重新选晚一 tick。着地时只比较已登记入口与已有第一跳关键节点，匹配后同一 owner 交接。

已记录 12567 个真实节拍控制决定。控制线程的 scan／搜索／完整 proof hash／反序列化调用均为 0。包装器会在控制线程尝试这些调用时直接失败；完整校验与注册的线程名必须是 d103-receiver。决定计时包括 poll、已登记对象及依赖检查、账本、物理一步、实际回执、关键节点比较、伤害检查、交接和输入提交；sleep、证据 JSON 序列化与写盘在计时外。receiver 与控制线程在同一父进程中运行，实际争用 Python 一次只能给一个线程执行解释器代码的机会（GIL）；worker 同时使用 CPU。原始 wake_lateness 与 deadline_miss 单独保留，不把线程 wake 延迟当作控制决定耗时。

“提交至 worker 取到请求”包含实际队列传输和队列等待，因此 B 的这一分项会反映前序作业。结果队列传输从 worker 完成结果序列化与摘要后计到父侧 get 完成，包含结果跨进程传递。“提交至可信可用”由父侧提交前和 receiver 完整注册后的同一时钟测量，包含两个进程间的传递与完整注册。

ready_at 精确记录注册完成时间，取值略早于 receiver 把 handle 发布到字典；“提交至可信可用”的表中终点采用这一时刻。控制循环只使用实际发布后 poll 到的对象，不根据这个时间戳提前应用输入。两跳能否接续的结论来自实际逐 tick 应用；注册时刻到字典发布的短间隔没有单独计时。

快照／请求实际成本加提交至可信可用，是把快照构造、快照序列化及摘要、请求封装序列化及摘要和提交后交付成本相加；它不重复计入数据准备与运行之间的空档。另一个“开始构造快照至可信可用”保留真实墙钟全程，包含第一跳准备、fallback 证明与登记以及起跳前 6／7 tick 的运行，不能解释为 worker 独占耗时。队列分项使用本机 Python 3.11 的 Windows QueryPerformanceCounter；它在同机所有进程共享单调时钟，没有混用服务器时钟或不同机器的绝对时间。

五项可信边界反例重新执行：dependency 格变化、world revision 变化、已重新封存但 proof.ruleset 错配、stale generation，以及同 request 下换成另一条合法输入。最后一项让 worker 在原输入后追加一条合法 Neutral，再用原 scanner 重扫，得到 VERIFIED_CANDIDATE；request、generation、owner 和 world 保持同一身份。receiver 比较父侧预登记输入后以有类型的 INPUTS 拒绝，未登记，推进为 0。五项全部拒绝，推进为 0。正常结束、构造失败、在途父异常、worker 内部异常和满队列停止五条路径都结束了 worker 与 receiver；结束活子进程和 receiver 线程为 0。满队列停止可能使用有界 terminate，记录真实退出码，不宣称所有异常都是正常退出。
